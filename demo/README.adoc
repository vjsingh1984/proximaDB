== 🏃‍♂️ Quick Start (5 Minutes)

[.lead]
Get ProximaDB running in under 5 minutes with our streamlined setup process.

=== Option 1: Docker Compose (Recommended)

[source,bash]
----
# Navigate to demo directory
cd demo

# Start the complete demo environment
docker-compose up --build

# View demo logs in another terminal
docker-compose logs -f demo

# View ProximaDB logs
docker-compose logs -f proximadb

# Clean up when done
docker-compose down -v
----

[TIP]
====
🐳 **Docker Benefits**: Complete environment setup with monitoring, no dependency management needed
====

=== Option 2: Local Development

[source,bash]
----
# Install dependencies
pip install -r requirements.txt

# Install ProximaDB Python SDK
cd ../clients/python
pip install -e .
cd ../../demo

# Start ProximaDB server (in another terminal)
cd ..
cargo run --bin proximadb-server

# Run demo
python demo.py
----

[IMPORTANT]
====
📋 **Prerequisites**: Ensure Rust toolchain and Python 3.8+ are installed

=== Feature Demonstrations

==== 1. Vector Operations
- **Batch Upsert**: Efficiently insert large numbers of vectors
- **Similarity Search**: Find nearest neighbors using various distance metrics  
- **Vector Management**: Add, update, and delete vectors with ACID properties

==== 2. Advanced Indexing
- **HNSW Integration**: Hierarchical Navigable Small World indexing
- **AXIS Support**: Adaptive eXtensible Indexing System
- **Partitioned Indices**: Automatic partitioning for scalability

==== 3. Metadata Filtering  
- **Logical Operators**: AND, OR, NOT queries
- **Comparison Operators**: =, !=, <, >, <=, >=
- **Complex Queries**: Nested logical expressions

==== 4. Text Processing (RAG Applications)
- **6 Chunking Strategies**: Sentence, paragraph, sliding window, semantic, fixed-size, recursive
- **BERT Integration**: 384, 768, 1024-dimensional embeddings
- **Preprocessing Pipelines**: Text normalization and optimization

==== 5. Vector Quantization
- **Product Quantization**: Compressed vector representations
- **Configurable Compression**: Adjustable compression ratios (4x-32x)
- **Performance Optimization**: Memory usage vs. accuracy trade-offs

==== 6. Storage Engine Comparison
- **LSM Engine**: Optimized for frequent updates and mixed workloads
- **VIPER Engine**: Optimized for analytics and compression (4x storage reduction)
- **Performance Benchmarking**: Real server execution with tangible datasets

==== Docker Compose Configuration

The `docker-compose.yml` provides a complete demo environment:

[source,yaml]
----
version: '3.8'
services:
  proximadb:
    build: ..
    ports:
      - "5678:5678"  # REST API
      - "5679:5679"  # gRPC API
    volumes:
      - ./docker-config.toml:/app/config.toml
      - proximadb_data:/data
    environment:
      - RUST_LOG=info
  
  demo:
    build:
      context: .
      dockerfile: Dockerfile.demo
    depends_on:
      - proximadb
    environment:
      - PROXIMADB_SERVER_URL=http://proximadb:5678
      - PYTHONPATH=/app
  
  prometheus:
    image: prom/prometheus:latest
    ports:
      - "9091:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
----

==== ProximaDB Server Configuration

The `docker-config.toml` optimizes ProximaDB for demo scenarios:

[source,toml]
----
[server]
host = "0.0.0.0"
rest_port = 5678
grpc_port = 5679

[storage]
data_dir = "/data"
storage_engine = "viper"  # Optimized for demos

[storage.wal_config]
strategy_type = "Avro"
memtable_type = "BTree"
sync_mode = "PerBatch"    # Balanced performance
max_memory_mb = 512
max_entries = 50000

[storage.viper]
enable_compression = true
compression_type = "zstd"
enable_quantization = true

[api]
enable_rest = true
enable_grpc = true
cors_enabled = true

[monitoring]
enable_metrics = true
metrics_port = 9090
----

== 🔧 Troubleshooting Guide

=== Common Issues & Solutions

==== Connection Issues

===== "Connection refused" errors

[source,bash]
----
# Check if ProximaDB server is running
curl http://localhost:5678/health

# Expected response:
# {"status":"healthy","timestamp":"2025-01-07T..."}

# Check server logs
tail -f /var/log/proximadb.log

# For Docker:
docker-compose logs proximadb
----

**Solutions:**
1. **Server not started**: Run `cargo run --bin proximadb-server`
2. **Port conflicts**: Check with `netstat -tulpn | grep 5678`
3. **Firewall blocking**: Temporary disable firewall for testing
4. **Docker networking**: Use `proximadb:5678` in container-to-container communication

===== "Module not found" errors

[source,bash]
----
# Install ProximaDB SDK properly
cd clients/python
pip install -e .

# Verify installation
python -c "import proximadb; print('SDK installed successfully')"

# Check Python path
python -c "import sys; print('\n'.join(sys.path))"

# Set PYTHONPATH if needed
export PYTHONPATH="${PWD}:${PYTHONPATH}"
----

**Common causes:**
- SDK not installed in current virtual environment
- Wrong Python interpreter being used
- Missing PYTHONPATH configuration

=== Storage Engine Comparison

ProximaDB offers two high-performance storage engines optimized for different workloads:

==== LSM Engine - Mixed Workloads
[cols="2,3"]
|===
|**Optimized For** |Frequent updates, real-time processing, mixed read/write

|**Architecture** |Log-Structured Merge trees with SkipList memtables
|**ACID Support** |Full transactional guarantees
|**Performance** |25-50ms real-time updates, 42.1ms average search
|**Throughput** |1,847 vectors/sec sustained
|**Best Use Cases** |IoT sensors, real-time analytics, live dashboards
|===

==== VIPER Engine - Analytics Workloads  
[cols="2,3"]
|===
|**Optimized For** |Analytics, compression, read-heavy workloads

|**Architecture** |Parquet columnar storage with sorted rewrite optimization
|**Compression** |4.2x storage reduction with ZSTD
|**Performance** |3,205 vectors/sec bulk loading, 38.7ms analytical queries

==== BERT Integration Performance

[source,python]
----
# Optimized BERT embedding generation
class OptimizedBERTProcessor:
    def __init__(self, model="bert-base-uncased"):
        self.model = AutoModel.from_pretrained(model)
        self.tokenizer = AutoTokenizer.from_pretrained(model)
        
    def batch_embed(self, texts, batch_size=32):
        # Process in batches for optimal GPU utilization
        embeddings = []
        for i in range(0, len(texts), batch_size):
            batch = texts[i:i+batch_size]
            with torch.no_grad():
                encoded = self.tokenizer(batch, 
                                       padding=True, 
                                       truncation=True,
                                       return_tensors="pt")
                outputs = self.model(**encoded)
                batch_embeddings = outputs.last_hidden_state[:, 0, :]
                embeddings.extend(batch_embeddings.cpu().numpy())
        return embeddings
----
