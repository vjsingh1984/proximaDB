== 🔧 Troubleshooting Guide

=== Common Issues & Solutions

==== Connection Issues

===== "Connection refused" errors

[source,bash]
----
# Check if ProximaDB server is running
curl http://localhost:5678/health

# Expected response:
# {"status":"healthy","timestamp":"2025-01-07T..."}

# Check server logs
tail -f /var/log/proximadb.log

# For Docker:
docker-compose logs proximadb
----

**Solutions:**
1. **Server not started**: Run `cargo run --bin proximadb-server`
2. **Port conflicts**: Check with `netstat -tulpn | grep 5678`
3. **Firewall blocking**: Temporary disable firewall for testing
4. **Docker networking**: Use `proximadb:5678` in container-to-container communication

===== "Module not found" errors

[source,bash]
----
# Install ProximaDB SDK properly
cd clients/python
pip install -e .

# Verify installation
python -c "import proximadb; print('SDK installed successfully')"

# Check Python path
python -c "import sys; print('\n'.join(sys.path))"

# Set PYTHONPATH if needed
export PYTHONPATH="${PWD}:${PYTHONPATH}"
----

**Common causes:**
- SDK not installed in current virtual environment
- Wrong Python interpreter being used
- Missing PYTHONPATH configuration

==== Docker Issues

===== Docker build failures

[source,bash]
----
# Clean Docker cache
docker system prune -a

# Rebuild with no cache
docker-compose build --no-cache

# Check Docker memory allocation
docker system df

# Increase Docker memory (Docker Desktop):
# Settings > Resources > Memory > 4GB+
----

===== Container startup failures

[source,bash]
----
# Check container logs
docker-compose logs proximadb

# Check container status
docker-compose ps

# Restart specific service
docker-compose restart proximadb

# Full restart
docker-compose down && docker-compose up
----

==== Performance Issues

===== Slow demo execution

[source,bash]
----
# Reduce dataset size
export DEMO_NUM_VECTORS=100

# Disable debug logging
export RUST_LOG=warn

# Use SSD storage for Docker volumes
# Update docker-compose.yml volume configuration

# Check available memory
free -h

# Monitor resource usage during demo
htop  # or top on macOS
----

===== High memory usage

[source,bash]
----
# Adjust ProximaDB memory settings in config.toml:
[storage.wal_config]
max_memory_mb = 256  # Reduce from 512
max_entries = 25000  # Reduce from 50000

# Use quantization to reduce memory
[storage.viper]
enable_quantization = true
quantization_level = "pq8"  # Higher compression
----

=== Platform-Specific Issues

==== Windows Issues

[source,powershell]
----
# PowerShell execution policy
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# Windows Defender exclusion for faster builds
Add-MpPreference -ExclusionPath "C:\path\to\proximadb"

# WSL2 memory issues
# Edit .wslconfig in user directory:
[wsl2]
memory=4GB
processors=4
----

==== macOS Issues

[source,bash]
----
# Xcode command line tools
xcode-select --install

# Homebrew permissions
sudo chown -R $(whoami) $(brew --prefix)/*

# Apple Silicon Rust targets
rustup target add aarch64-apple-darwin

# Rosetta for Intel binaries (if needed)
softwareupdate --install-rosetta
----

==== Linux Issues

[source,bash]
----
# Docker permission issues
sudo usermod -aG docker $USER
# Then logout and login

# Shared memory issues
sudo sysctl -w kernel.shm_rmid_forced=1

# File descriptor limits
ulimit -n 65536

# Check systemd journal for errors
journalctl -u docker -f
----

=== Performance Troubleshooting

==== Memory Optimization

[source,toml]
----
# Optimize config.toml for limited memory:
[storage.wal_config]
max_memory_mb = 128
sync_mode = "PerBatch"
memtable_type = "HashMap"  # Lower memory overhead

[storage.viper]
enable_quantization = true
compression_type = "lz4"  # Faster than zstd
----

==== Disk I/O Optimization

[source,bash]
----
# Use tmpfs for temporary data (Linux)
sudo mount -t tmpfs -o size=2G tmpfs ./demo_data

# Monitor I/O
iostat -x 1

# Check disk space
df -h ./demo_data
----

==== Network Optimization

[source,bash]
----
# Increase network buffers for high throughput
echo 'net.core.rmem_max = 134217728' | sudo tee -a /etc/sysctl.conf
echo 'net.core.wmem_max = 134217728' | sudo tee -a /etc/sysctl.conf

# Apply changes
sudo sysctl -p
----

==== Reporting Issues

When reporting issues, include:

1. **System Information**: OS, version, hardware specs
2. **Software Versions**: Rust, Python, Docker versions
3. **Configuration**: config.toml and environment variables
4. **Error Logs**: Complete error messages and stack traces
5. **Reproduction Steps**: Exact commands that trigger the issue
