== 🗄️ Storage Engine Comparison

=== VIPER vs SST Engine Performance

[cols="2,3,3"]
|===
|Aspect |VIPER (Columnar) |SST (Row-based)

|**Best For**
|Analytics, metadata-heavy queries
|High-throughput ingestion, simple queries

|**Insert Performance**
|6,320 vec/s (REST), 18,024 vec/s (gRPC)
|6,346 vec/s (REST), 18,529 vec/s (gRPC)

|**Search Performance**
|1.9ms (REST), 1.5ms (gRPC)
|1.9ms (REST), 1.7ms (gRPC)

|**Metadata Filtering**
|60-90% I/O reduction via predicate pushdown
|Three-stage filtering (Bloom → Index → Row)

|**Storage Format**
|Parquet with ZSTD compression
|LSM-Tree with SSTables

|**Compression Ratio**
|3:1 typical, 5:1 with bloom filters
|2:1 typical, optimized for write speed
|===

    "analytics_data",
    dimension=768,

    FROM analytics_data
    WHERE metadata->>'published_date' > '2023-01-01'
      AND metadata->>'author' IN ('Smith', 'Johnson')  
      AND metadata->>'rating' > 4.0

""")

== 📊 SQL + Vector Similarity Engine

=== Advanced SQL Capabilities

ProximaDB's SQL engine combines familiar SQL syntax with powerful vector operations:

[source,sql]
----
-- Semantic search with complex metadata filtering
SELECT 
    id,
    metadata->>'title' as title,
    metadata->>'category' as category,
    VECTOR_SIMILARITY(vector, {query_vector}, 'cosine') as similarity
FROM knowledge_base
WHERE 
    metadata->>'language' = 'english'
    AND metadata->>'published' > '2023-01-01'
    AND VECTOR_SIMILARITY(vector, {query_vector}, 'cosine') > 0.75
ORDER BY similarity DESC
LIMIT 10;
----

== 🎯 Production Deployment Patterns

=== E-commerce Semantic Search

[source,python]
----
# Product recommendation system
collection = client.create_collection(
    "product_embeddings",
    dimension=384,  # BERT embeddings
    storage_engine="viper",  # Analytics-optimized
    indexing_algorithm="hnsw"  # High recall
)

# Semantic product search with filters
results = client.execute_sql("""
    SELECT 
        id,
        metadata->>'name' as product_name,
        metadata->>'price' as price,
        VECTOR_SIMILARITY(vector, {user_query_vector}, 'cosine') as relevance
    FROM product_embeddings
    WHERE 
        metadata->>'category' = 'electronics'
        AND CAST(metadata->>'price' AS FLOAT) BETWEEN 100 AND 500
        AND metadata->>'in_stock' = 'true'
        AND VECTOR_SIMILARITY(vector, {user_query_vector}, 'cosine') > 0.6
    ORDER BY relevance DESC
    LIMIT 20
""")
----

== 🎓 Best Practices Summary

=== Algorithm Selection Guide

[source,text]
----
✅ Choose HNSW when:
  • Recall is critical (>95% required)
  • Query latency can be 1-2ms
  • Memory usage is acceptable

✅ Choose PQ when:
  • Memory is severely constrained
  • 8x compression is needed
  • 85-90% recall is sufficient

✅ Choose ANNOY when:
  • Dataset is relatively static
  • Consistent performance is key
  • Simple deployment is preferred

✅ Choose LSH when:
  • Approximate similarity is sufficient
  • Ultra-high throughput required
  • Working with sparse vectors
----

=== Storage Engine Selection

[source,text]
----
✅ Choose VIPER when:
  • Complex metadata filtering is common
  • Analytical queries are frequent  
  • Storage efficiency is important
  • Update frequency is moderate

✅ Choose SST when:
  • High write throughput is critical
  • Simple similarity queries dominate
  • Real-time ingestion is required
  • Metadata filtering is basic
----
