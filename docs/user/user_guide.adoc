== Overview

ProximaDB: High-performance vector database for AI applications with rich metadata filtering.

**Topics**: Collections | Vector Operations | SQL Engine | Performance | Production

== Collections

**Create Collection:**
[source,python]
----
from proximadb import ProximaDBClient
from proximadb.models import CompressionConfig, CompressionAlgorithm

client = ProximaDBClient("http://localhost:5678")

# Basic collection
collection = client.create_collection(
    name="documents", dimension=384, distance_metric="cosine", engine="viper"
)

# With compression
compression = CompressionConfig(
    algorithm=CompressionAlgorithm.ZSTD, level=6, enable_quantization=True
)
collection = client.create_collection(
    name="enterprise", dimension=1536, compression=compression
)
----

**Manage Collections:**
[source,python]
----
collections = client.list_collections()  # List all
info = client.get_collection("documents")  # Get details
client.update_collection("documents", description="Updated")
client.delete_collection("documents")  # Delete
----

== Vector Operations

**Insert Vectors:**
[source,python]
----
# Single vector
vector_data = {
    "id": "doc_001",
    "vector": [0.1, 0.2, 0.3] * 128,
    "metadata": {"title": "ML Fundamentals", "category": "education"}
}
client.insert_vectors("documents", [vector_data])

# Batch insert (recommended)
vectors = [{"id": f"doc_{i}", "vector": vector_data[i], 
           "metadata": metadata[i]} for i in range(1000)]
results = client.insert_vectors("documents", vectors, batch_size=100)

# Upsert (insert or update)
client.upsert_vectors("documents", upsert_data)
----

**Search Vectors:**
[source,python]
----
# Basic search
results = client.search_vectors(
    collection_id="documents",
    query_vector=[0.1, 0.2, 0.3] * 128,
    top_k=10,
    include_metadata=True
)

# With metadata filtering
results = client.search_vectors(
    collection_id="documents",
    query_vector=query_vector,
    metadata_filter={
        "category": "research",
        "word_count": {">=": 1000}
    },
    distance_threshold=0.8
)

# Batch search
batch_results = client.batch_search_vectors(
    collection_id="documents",
    query_vectors=[query1, query2, query3],
    top_k=5
)
----

== SQL Engine

**Vector SQL Queries:**
[source,python]
----
# Basic vector similarity
results = client.execute_sql("""
    SELECT id, metadata->>'title', 
           VECTOR_SIMILARITY(vector, [...], 'cosine') as score
    FROM documents WHERE score > 0.8
    ORDER BY score DESC LIMIT 10
""")

# Complex filtering
results = client.execute_sql("""
    SELECT id, metadata->>'title'
    FROM documents 
    WHERE (metadata->>'category' = 'research' AND metadata->>'priority' = 'high')
      AND metadata->>'word_count' BETWEEN 1000 AND 5000
    ORDER BY VECTOR_SIMILARITY(vector, [...], 'cosine') DESC
""")
----

**Supported**: 13 distance metrics (cosine, euclidean, dot_product, etc.) | Full SQL operators (AND/OR/NOT, comparisons, JSON access)

== Performance

**Benchmarks**:
- **Insert**: gRPC 49K/sec, REST 20K/sec
- **Search**: VIPER ~1.5ms, SST ~1.8ms
- **SQL**: ~3ms average latency

**Engine Selection:**
[source,python]
----
# Write-heavy: SST engine
collection = client.create_collection(
    name="writes", engine="sst", index_config={"algorithm": "hnsw"}
)

# Analytics: VIPER engine  
collection = client.create_collection(
    name="analytics", engine="viper", dimension=384
)
----

**Optimization:**
- **Batch Sizes**: gRPC (500), REST (100), SQL (50)
- **Protocol**: Use gRPC for high throughput
- **Compression**: ZSTD level 6 for balanced performance
- **Caching**: Enable vector cache (512MB) and metadata cache (128MB)

== Production Deployment

**Hardware Configuration:**
[source,toml]
----
[hardware]
enable_gpu = true        # Auto-detect CUDA/ROCm/MPS
enable_simd = true       # Auto-detect AVX-512/AVX2/NEON
worker_threads = 8

[performance]
connection_pool_size = 100
query_cache_size_mb = 256
----

**Compression Algorithms:**
- **ZSTD**: Balanced speed/ratio (3-5x compression)
- **LZ4**: Maximum speed (2-3x compression)
- **Snappy**: Low latency (2x compression)
- **Brotli**: Maximum compression (4-6x compression)

**Best Practices:**
- Use VIPER for analytics, SST for write-heavy workloads
- Enable compression for storage savings (especially VIPER with quantization)
- Batch operations for optimal throughput
- Use appropriate distance metrics for your data
- Monitor performance with built-in metrics
