[abstract]
**Vectorized Intelligence Parquet Engine for Retrieval** - A production-ready columnar storage engine with 13,604 lines of implementation. Features predicate pushdown, progressive search pipeline, and unified infrastructure integration for 2.5-3x search performance improvement.

image::../assets/logos/viper-engine-logo.svg[VIPER Engine Logo, 200, align="center"]

== Overview

The VIPER engine leverages Apache Parquet's columnar format to provide exceptional compression ratios and analytical query performance. By storing vectors and metadata in columnar format with aggressive compression and quantization, VIPER achieves 5-10x storage reduction while maintaining excellent batch processing throughput.

=== Key Features

* **Shared Columnar Infrastructure**: Uses common columnar module for consistency
* **Progressive Search Pipeline**: 7-phase optimization (Bloom → Binary → INT8 → PQ → Hybrid → FP32 → Cache)
* **Predicate Pushdown**: Returns row indices without reading vectors (60-90% I/O savings)
* **Zero-Copy Serialization**: BinaryArray with bytemuck for optimal performance
* **EventLog Integration**: Async indexing with ~600 line queue system
* **Production Ready**: 2.5-3x search performance, -52% P50 latency

=== Key Components

==== Predicate Pushdown Optimization
* Returns qualifying row indices before reading vector data
* 60-90% I/O reduction for filtered queries
* Uses `VIPERColumnFilterEvaluator` for columnar filtering

==== Progressive Search Pipeline
1. **Bloom Filter Check**: O(1) existence check
2. **Binary Search**: 32x reduction
3. **INT8 Search**: 4x reduction
4. **PQ Refinement**: 2-4x reduction
5. **Hybrid Stage**: Combined strategies
6. **Full Precision**: Final candidates
7. **Cache Layer**: 60-90% hit rate

==== Vector Serialization
* Uses `BinaryArray` with bytemuck for zero-copy
* Better compression than standard Arrow arrays
* Direct proto support without conversions

=== Architecture Evolution

NOTE: VIPER has evolved from standalone implementation to shared infrastructure:
* ML Clustering moved to AXIS service
* Quantization uses unified compute module
* Search uses `IntegratedSearchOptimizer` from core
* Schema uses shared `ColumnarSchema`

== Quantization Strategies

=== Automatic Selection

The VIPER engine automatically selects optimal quantization based on:

1. **Vector Dimensions**: Higher dimensions → more aggressive quantization
2. **Data Distribution**: Uniform → binary/INT8, clustered → PQ
3. **Quality Requirements**: User-defined threshold (0.9-0.99)

== Best Practices

=== Data Preparation

1. **Batch Loading**: Always use batches ≥ 10K vectors
2. **Pre-sort Data**: Sort by timestamp or ID for better compression
3. **Normalize Vectors**: L2 normalization improves quantization
4. **Remove Duplicates**: Deduplication before insertion

=== Query Optimization

1. **Use Predicates**: Push down filters to Parquet level
2. **Column Projection**: Select only needed columns
3. **Partition Pruning**: Use time-based partitioning
4. **Cache Hot Data**: Keep frequently accessed columns in memory

=== Storage Management

1. **Compaction**: Regular compaction of small files
2. **Partitioning**: Time or category-based partitioning
3. **Retention**: Implement data lifecycle policies
4. **Backup**: Regular snapshots to object storage

== Advanced Features

=== Multi-Stage Quantization

[source,rust]
----
// Quantization pipeline
pub struct QuantizationPipeline {
    stages: Vec<QuantizationStage>,
}

impl QuantizationPipeline {
    pub fn execute(&self, vectors: &[f32]) -> QuantizedVectors {
        // Stage 1: Binary quantization for initial filtering
        let binary = self.binary_quantize(vectors);
        
        // Stage 2: INT8 for intermediate precision
        let int8 = self.int8_quantize(vectors);
        
        // Stage 3: Product Quantization for storage
        let pq = self.pq_quantize(vectors);
        
        QuantizedVectors {
            binary,
            int8,
            pq,
            original_sample: self.sample(vectors),
        }
    }
}
----

== Troubleshooting

=== Common Issues

==== Slow Batch Writes
**Symptom**: Batch insertion < 100K vec/s

**Causes**:
1. Small batch sizes
2. Excessive compression
3. Complex quantization

**Solutions**:
```toml
batch_size = 50000           # Larger batches
compression_level = 3        # Faster compression
quantization_level = "int8"  # Simpler quantization
```

==== High Storage Usage
**Symptom**: Storage > 1GB per million vectors

**Solutions**:
1. Enable quantization
2. Increase compression level
3. Run compaction

```toml
quantization_enabled = true
quantization_level = "pq8"
compression_level = 9
compaction_threshold = 0.2
```

==== Poor Query Performance
**Symptom**: P99 latency > 10ms

**Solutions**:
1. Enable statistics
2. Add bloom filters
3. Optimize row group size

```toml
enable_statistics = true
enable_bloom_filters = true
row_group_size = 50000  # Smaller for faster seeks
```

== Migration Guide

=== From SST to VIPER

[source,bash]
----
# 1. Export from SST
proximadb-cli export \
  --engine sst \
  --collection my_data \
  --format arrow \
  --output data.arrow

# 2. Configure VIPER
cat > viper_config.toml << EOF
[storage]
default_engine = "viper"

[engines.viper]
batch_size = 10000
quantization_level = "pq8"
compression = "mixed"
EOF

# 3. Import to VIPER
proximadb-cli import \
  --engine viper \
  --collection my_data_viper \
  --config viper_config.toml \
  --input data.arrow

# 4. Verify
proximadb-cli verify \
  --collection my_data_viper \
  --check-quality 0.95
----

== Integration Examples

=== Python Client

[source,python]
----
from proximadb import ViperClient

# Connect to VIPER engine
client = ViperClient(
    host="localhost",
    port=5678,
    engine="viper"
)

# Create collection with VIPER settings
client.create_collection(
    name="products",
    dimension=768,
    engine_config={
        "engine": "viper",
        "batch_size": 10000,
        "quantization_level": "pq8",
        "compression": "mixed"
    }
)

# Batch insert
vectors = np.random.rand(10000, 768)
metadata = [{"category": "electronics"} for _ in range(10000)]

client.insert_batch(
    collection="products",
    vectors=vectors,
    metadata=metadata
)

# Analytics query
results = client.query(
    collection="products",
    vector=query_vector,
    filter={"category": "electronics"},
    k=100,
    search_params={
        "progressive_search": True,
        "quantization_stages": ["binary", "int8", "pq8"]
    }
)
----
