== Production Engines (✅ Ready)

=== SST Engine
**Sorted String Table** - Zero-copy LSM with three-stage filtering

* **Implementation**: 26,488 lines of production code
* **Architecture**: Row-based LSM with WAL and MemTable integration
* **Optimization**: Three-stage filtering (Bloom → Quantized → Full), zero-copy compaction
* **Performance**: 200K vectors/sec write, <5ms P99 latency

link:sst.adoc[Full SST Documentation →]

=== VIPER Engine
**Vectorized Intelligence Parquet Engine for Retrieval** - Columnar analytics storage

* **Implementation**: 22,581 lines of production code
* **Architecture**: Apache Parquet-based columnar format
* **Optimization**: Advanced quantization pipeline, predicate pushdown, zone maps
* **Performance**: 500K vectors/sec batch write, 5-10x compression

link:viper.adoc[Full VIPER Documentation →]

=== HELIX Engine
**High-Efficiency Locality-Indexed eXecution** - Similarity-optimized storage

* **Implementation**: 7,783 lines of production code
* **Architecture**: Disk-only LSM with PCA+Hilbert clustering
* **Optimization**: FastLane blocks, liquid clustering, aggressive pruning
* **Performance**: 150K vectors/sec, 70-90% query pruning

link:helix.adoc[Full HELIX Documentation →]

== Production Engines (Continued)

=== RAPTOR Engine
**Row-Aligned Predicated Tensor Optimized Repository** - Graph-optimized storage

* **Implementation**: 18,191 lines of production code
* **Architecture**: Matrix Trinity navigation (P²+K²+P×K) replacing HNSW
* **Optimization**: Artus bloom filters (200x memory savings vs B-tree)
* **Performance**: 100K vec/s, O(1) centroid lookup, <10ms graph traversal

link:raptor.adoc[Full RAPTOR Documentation →]

== Configuration Examples

=== High Throughput (VIPER)
[source,toml]
----
[storage]
default_engine = "viper"

[engines.viper]
batch_size = 10000
compression = "zstd"
quantization = "pq8"
enable_statistics = true
----

=== Low Latency (SST)
[source,toml]
----
[storage]
default_engine = "sst"

[engines.sst]
memtable_size = "2GB"
bloom_filter_bits = 10
compression = "lz4"
level0_file_num_compaction_trigger = 4
----

== Migration Guide

=== Switching Engines
[source,bash]
----
# Export from current engine
proximadb-cli export --collection my_data --format parquet

# Update configuration
sed -i 's/default_engine = "sst"/default_engine = "helix"/' config.toml

# Restart and import
systemctl restart proximadb
proximadb-cli import --collection my_data --format parquet
----

=== Engine-Specific Optimizations

Each engine supports specific optimizations:

* **SST**: Tune compaction, bloom filters
* **VIPER**: Optimize batch size, compression
* **HELIX**: Configure PCA dimensions, parallelism
* **RAPTOR**: Adjust matrix parameters (future)
* **NOVA**: Set SuperBlock size (future)
* **SWIFT**: Configure hierarchy levels (future)
* **PRISM**: Tune memory pools (future)

== FAQ

**Q: Can I use multiple engines simultaneously?**
A: Yes, different collections can use different engines.

**Q: How do I migrate between engines?**
A: Use the export/import tools or streaming migration.

**Q: Which engine is fastest?**
A: Depends on workload - SST for updates, VIPER for batch, HELIX for similarity.

**Q: When will new engines be ready?**
A: RAPTOR and NOVA in Q1 2025, SWIFT and PRISM in Q2 2025.
