= SST Storage Engine
:toc: left
:toclevels: 3
:icons: font

[abstract]
**Sorted String Table** - A sophisticated LSM tree storage engine with zero-copy compaction, three-stage filtering pipeline, and hierarchical bloom filters. Optimized for real-time OLTP workloads with sub-5ms P99 latency.

image::../assets/logos/sst-engine-logo.svg[SST Engine Logo, 200, align="center"]

== Overview

The SST engine implements a classic Log-Structured Merge (LSM) tree architecture, providing excellent write performance and predictable read latencies. It's the ideal choice for real-time applications requiring frequent updates and consistent sub-5ms query response times.

=== Key Features

* **Zero-Copy Compaction**: 80% memory reduction, 3x faster than traditional
* **Three-Stage Filtering**: Bloom → Quantized → Full precision pipeline
* **Hierarchical Bloom Filters**: File-level, block-level, and composite filters
* **No Embedded MemTable**: Pure SSTable storage with external WAL handling
* **Unified Infrastructure**: Full integration with quantization and compression
* **Production Ready**: 47K+ lines of battle-tested code

== Configuration

=== Basic Configuration

[source,toml]
----
[storage]
default_engine = "sst"

[engines.sst]
# Block settings (256KB-16MB range)
block_size_kb = 2048              # 2MB default (cloud optimized)

# Compression (14 algorithms available)
compression = "mixed"             # Per-block optimal selection
compression_level = 6             # 1-22 for ZSTD

# Bloom filter configuration
bloom_filter_config = {
    enabled = true,
    bits_per_key = 10,
    hierarchical = true           # File + block level
}

# Compaction configuration
compaction_strategy = "unified"   # leveled, tiered, or unified
max_files_per_level = 10
level_size_multiplier = 10
max_levels = 7
background_thread_count = 4

# Cache configuration
decompression_cache_config = {
    size_mb = 512,
    policy = "lru",
    prefetch_enabled = true
}

# Write settings
write_buffer_size = 67108864  # 64MB
max_write_buffer_number = 3
min_write_buffer_number_to_merge = 2
----

==== Three-Stage Filter Pipeline
1. **Bloom Filter Stage**: 95% reduction in unnecessary reads
2. **Quantized Vector Stage**: INT8/PQ for fast approximate filtering
3. **Full Precision Stage**: Exact results with decompression cache

==== Zero-Copy Compaction
* Direct streaming between SST files without deserialization
* Preserves compressed blocks during compaction
* MVCC resolution for concurrent reads
* 80% memory reduction vs traditional compaction

=== Integration Points

==== EventLog System
* Synchronous flush acknowledgment
* Asynchronous AXIS indexing
* Queue-aware compaction

==== Unified Infrastructure
* **Quantization Engine**: `/src/compute/quantization/`
* **Distance Computation**: `/src/compute/distance_computation/`
* **Compression Module**: 14 algorithms with mixed strategy
* **Hardware Acceleration**: Automatic SIMD detection

== Best Practices

1. **Tune Compaction**: Balance between write amplification and space
2. **Size MemTables**: Larger for throughput, smaller for latency
3. **Enable Bloom Filters**: Essential for read performance
4. **Monitor Levels**: Keep L0 under control
5. **Batch Writes**: Improve throughput significantly
