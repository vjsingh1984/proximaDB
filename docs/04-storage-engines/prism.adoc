[abstract]
**Progressive Retrieval with In-memory Storage Management** - A memory-first storage engine optimized for ultra-low latency (<1ms) through progressive quantization, lock-free data structures, and NUMA-aware memory management.

image::../assets/logos/prism-engine-logo.svg[PRISM Engine Logo, 200, align="center"]

== Overview

The PRISM engine represents the pinnacle of low-latency vector search, designed for applications where every microsecond matters. By keeping all data in memory with progressive quantization levels and employing lock-free concurrent data structures, PRISM achieves sub-millisecond search latencies while maintaining high throughput.

=== Key Features

* **Memory-First Architecture**: All data resident in RAM
* **Progressive Quantization**: Multi-level precision for speed/accuracy trade-off
* **Lock-Free Operations**: Wait-free reads, minimal contention writes
* **NUMA Optimization**: CPU-local memory allocation
* **Zero-Copy Search**: Direct memory access without serialization
* **Microsecond Latency**: P99 < 1ms for most workloads

=== Lock-Free Data Structures

==== Vector Storage
[source,rust]
----
pub struct LockFreeVectorStore {
    // Epoch-based memory reclamation
    epoch: Arc<Epoch>,
    
    // Lock-free hash map for vectors
    vectors: Arc<LockFreeHashMap<VectorId, AtomicVector>>,
    
    // Progressive quantization levels
    fp32_vectors: Arc<MemoryPool<f32>>,
    fp16_vectors: Arc<MemoryPool<f16>>,
    int8_vectors: Arc<MemoryPool<i8>>,
    binary_vectors: Arc<BitVecPool>,
    
    // Access statistics (lock-free counters)
    access_counts: Arc<AtomicCounters>,
    
    // NUMA-aware allocators
    numa_allocators: Vec<NumaAllocator>,
}

impl AtomicVector {
    // Wait-free read
    pub fn read(&self) -> VectorData {
        let ptr = self.data.load(Ordering::Acquire);
        unsafe { &*ptr }.clone()
    }
    
    // Lock-free update with CAS
    pub fn update(&self, new_data: VectorData) -> bool {
        loop {
            let current = self.data.load(Ordering::Acquire);
            let new_ptr = Box::into_raw(Box::new(new_data));
            
            match self.data.compare_exchange(
                current,
                new_ptr,
                Ordering::Release,
                Ordering::Acquire
            ) {
                Ok(_) => {
                    self.epoch.defer(move || {
                        unsafe { Box::from_raw(current); }
                    });
                    return true;
                }
                Err(_) => {
                    unsafe { Box::from_raw(new_ptr); }
                }
            }
        }
    }
}

== Implementation Details

=== NUMA-Aware Allocation

[source,rust]
----
pub struct NumaAllocator {
    node_id: usize,
    local_memory: *mut u8,
    capacity: usize,
    used: AtomicUsize,
}

impl NumaAllocator {
    pub fn allocate_aligned(&self, size: usize, align: usize) 
        -> Result<*mut u8> {
        // Allocate from local NUMA node
        let ptr = unsafe {
            numa_alloc_onnode(
                size,
                self.node_id
            )
        };
        
        // Track usage
        self.used.fetch_add(size, Ordering::Relaxed);
        
        // Prefault pages for lower latency
        if self.prefault_enabled {
            self.prefault_pages(ptr, size);
        }
        
        Ok(ptr)
    }
    
    fn prefault_pages(&self, ptr: *mut u8, size: usize) {
        // Touch every page to prevent page faults
        let page_size = 4096;
        for offset in (0..size).step_by(page_size) {
            unsafe {
                ptr.add(offset).write(0);
            }
        }
    }
}

=== Lock-Free Search

[source,rust]
----
pub fn search_lock_free(
    &self,
    query: &[f32],
    k: usize
) -> Vec<SearchResult> {
    // Start epoch for safe memory access
    let guard = self.epoch.pin();
    
    // Phase 1: Binary search (coarse)
    let binary_candidates = self.search_binary_tier(
        query, 
        k * 100
    );
    
    // Phase 2: INT8 refinement
    let int8_candidates = self.refine_int8(
        query,
        binary_candidates,
        k * 10
    );
    
    // Phase 3: FP32 final ranking
    let final_results = self.rank_fp32(
        query,
        int8_candidates,
        k
    );
    
    // Update access statistics (lock-free)
    for result in &final_results {
        self.access_counts.increment(result.id);
    }
    
    final_results
}

=== Automatic Promotion/Demotion

[source,rust]
----
impl TierManager {
    pub fn run_background_optimization(&self) {
        loop {
            sleep(Duration::from_millis(1000));
            
            // Check for vectors to promote
            for (id, count) in self.access_counts.iter() {
                let current_tier = self.get_tier(id);
                let new_tier = self.compute_optimal_tier(count);
                
                if new_tier > current_tier {
                    self.promote_vector(id, new_tier);
                } else if new_tier < current_tier {
                    self.demote_vector(id, new_tier);
                }
            }
            
            // Rebalance memory if needed
            if self.memory_pressure() > 0.9 {
                self.evict_coldest_vectors();
            }
        }
    }
}

== Troubleshooting

=== Common Issues

==== High Latency Spikes
**Symptom**: P99 > 1ms occasionally

**Causes**:
1. Page faults
2. NUMA remote access
3. GC or memory pressure

**Solutions**:
```toml
memory_locked = true      # No page faults
numa_bind = true         # Single NUMA node
huge_pages = true        # Reduce TLB misses
```

==== Memory Fragmentation
**Symptom**: Cannot allocate despite free memory

**Solutions**:
1. Use memory pools
2. Enable huge pages
3. Periodic defragmentation

```toml
use_memory_pools = true
huge_pages = true
defrag_interval_hours = 24
```

==== Accuracy Degradation
**Symptom**: Search quality decreases over time

**Solutions**:
1. Adjust tier thresholds
2. Increase FP32 percentage
3. Retrain quantization

```toml
fp32_percentage = 20
hot_threshold = 50
reQuantize_interval_days = 7
```

== Best Practices

=== Hardware Configuration
1. **Disable CPU Frequency Scaling**: Consistent performance
2. **Isolate CPUs**: Dedicate cores to PRISM
3. **Configure NUMA**: Interleave or bind appropriately
4. **Tune Network**: Kernel bypass for networking

=== Data Management
1. **Pre-warm Cache**: Load hot data at startup
2. **Batch Operations**: Amortize overhead
3. **Monitor Access Patterns**: Adjust tiers accordingly
4. **Regular Rebalancing**: Maintain optimal layout

=== Production Deployment
1. **Redundancy**: Multiple PRISM instances
2. **Health Checks**: Sub-millisecond response required
3. **Gradual Rollout**: Test with subset first
4. **Monitoring**: Detailed latency percentiles
