=== Real-time Workloads (≪10ms latency requirement)

[TIP]
====
**Recommended Strategy**: `GroupedFieldEncoded`

Ultra-low latency queries with frequent random access patterns.
====

Latency Requirement:: ≪10ms response time

Batch Size:: Small operations (1-100 vectors)

=== WORM Workloads (Write Once, Read Many)

*Recommended Strategy: GroupedFieldEncoded*

.Characteristics
* Large batch ingestion
* Infrequent updates
* Optimized for storage efficiency
* Read-heavy access patterns

.Configuration
[source,toml]
----
[storage.encoding]
strategy = "GroupedFieldEncoded"
compression_algorithm = "Zstd"     # Better compression ratio
compression_level = 3              # Balanced compression
compression_threshold = 1024       # Compress larger blocks
group_size = 32
----

.Performance Profile
* *Encode*: 384ms for 1000 vectors (1536D)
* *Decode*: 270ms for 1000 vectors (1536D)
* *Compression*: 2.10x (52% space savings)
* *Storage Cost*: Minimal (best compression)

=== Streaming Writes Workloads

*Recommended Strategy: GroupedBlockCompressed*

.Characteristics
* Continuous data ingestion
* Time-series patterns
* Append-only operations
* Fast decode for recent data

.Configuration
[source,toml]
----
[storage.encoding]
strategy = "GroupedBlockCompressed"
compression_algorithm = "Lz4"      # Fastest compression
compression_level = 1              # Speed over ratio
compression_threshold = 512        # Small block compression
group_size = 32
----

.Performance Profile
* *Encode*: 224-448ms for 1000 vectors
* *Decode*: 42-158ms for 1000 vectors (fastest decode!)
* *Compression*: 1.28x (22% space savings)
* *Streaming*: Optimized for append operations

=== Balanced Workloads

*Recommended Strategy: TransposeBlockCompressed*

.Characteristics
* Mixed read/write patterns
* Moderate latency requirements
* Batch and single operations
* Cost-performance balance

* *Decode*: 130-260ms for 1000 vectors
* *Compression*: 2.06x (51% space savings)
* *Flexibility*: Good for all operations

== Storage Engine Integration

=== SST Engine (Row-based)
* Use `GroupedFieldEncoded` for best compression with row access
* 32D groups align with SST's segment structure
* Ideal for: Real-time queries, frequent updates

=== VIPER Engine (Columnar)
* Use `TransposeBlockCompressed` for columnar efficiency
* Transpose layout matches Parquet's column organization
* Ideal for: Analytics, batch processing

=== SWIFT Engine (Speed-optimized)
* Use `GroupedBlockCompressed` for fastest decode
* Block compression minimizes decompression overhead
* Ideal for: Streaming, time-series

=== RAPTOR Engine (Adaptive)
* Use `GroupedFieldEncoded` as default
* Switch to `TransposeBlockCompressed` for large batches
* Ideal for: Dynamic workloads

== Performance Optimization Tips

=== Cache Optimization
[NOTE]
====
GroupedFieldEncoded's 32-dimension groups (32 × 4 bytes = 128 bytes) fit perfectly in modern CPU cache lines, providing:

* 2-3x faster SIMD operations
* Reduced memory bandwidth usage
* Better prefetcher efficiency
====

=== Compression Thresholds
[cols="2,2,3", options="header"]
|===
|Data Size |Threshold |Rationale

|< 256 bytes
|Don't compress
|Overhead exceeds benefit

|256-1024 bytes
|Selective
|Compress if >10% savings

|> 1024 bytes
|Always compress
|Significant savings

== Implementation Example

[source,rust]
----
use proximadb::storage::engines::core::formats::fastlanes_blocks::{
    BlockCompressionConfig, VectorEncodingLayout
};
use proximadb::core::compression::CompressionAlgorithm;

// Real-time configuration
fn configure_realtime() -> BlockCompressionConfig {
    BlockCompressionConfig {
        vector_layout: VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector,
        algorithm: CompressionAlgorithm::Snappy,
        compression_level: 1,
        enable_vector_compression: true,
        enable_metadata_compression: false,
        compression_threshold_bytes: 0,
        dictionary_compression: false,
        metadata_algorithm: None,
    }
}

// WORM configuration
fn configure_worm() -> BlockCompressionConfig {
    BlockCompressionConfig {
        vector_layout: VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector,
        algorithm: CompressionAlgorithm::Zstd,
        compression_level: 3,
        enable_vector_compression: true,
        enable_metadata_compression: true,
        compression_threshold_bytes: 1024,
        dictionary_compression: true,
        metadata_algorithm: Some(CompressionAlgorithm::Zstd),
    }
}
----

== Monitoring and Tuning

=== Key Metrics to Monitor
1. **Compression Ratio**: Target > 2.0x for WORM, > 1.5x for real-time
2. **Encode Latency**: < 200ms for real-time, < 500ms for batch
3. **Decode Latency**: < 100ms for real-time, < 300ms for batch
4. **Memory Usage**: Monitor buffer allocations during encoding

== Conclusion

The benchmarks demonstrate that **GroupedFieldEncoded** provides the best overall balance of:
- **Compression**: 2.08-2.10x ratio (52% space savings)
- **Performance**: Fastest encode/decode for most workloads
- **Flexibility**: Works well across all dimension sizes

For specialized workloads:
- **Streaming**: Use GroupedBlockCompressed for fastest decode (42ms)
- **Large batches**: Use TransposeBlockCompressed for parallelization
- **Storage-critical**: Use GroupedFieldEncoded with Zstd compression

The realistic data patterns (mixed sparse, gaussian, quantized, sinusoidal) show significantly better compression (2.08x) compared to pure random data (1.1x), validating the importance of using representative test data.
