== 📖 Usage Guidelines

=== By Documentation Need
[cols="2,2", options="header"]
|===
| Documentation Need | Recommended Diagrams

| **Quick Start**
| Abstract diagrams: business, technical architecture

| **Architecture Understanding** 
| Abstract → Detail-modular progression

| **Component Development**
| Detail-modular diagrams for specific components

| **System Troubleshooting**
| Combination of abstract + relevant detail-modular diagrams
|===

=== By Audience
[cols="1,2", options="header"] 
|===
| Audience | Recommended Level

| **Business/Executive**
| Abstract diagrams only

| **New Developers**
| Abstract → Detail-modular progression

| **Experienced Developers**
| Detail-modular + Detail-monolithic as needed

| **System Architects**
| All levels with focus on Detail-monolithic
|===

== 🛠️ Technical Reference

=== File Locations
* **Source Files**: `./*.mmd` (62 MermaidJS files)
* **Generated Images**: `./images/*.svg` (62 SVG files) 
* **Mapping Reference**: `FINAL_MAPPING_REFINED.txt`

=== Adding New Diagrams
1. Determine abstraction level (abstract/detail-modular/detail-monolithic)
2. Follow naming convention: `[component]-[type]-[abstraction-level].mmd`
3. Create focused, single-responsibility content
4. Generate SVG: `npx mmdc -i diagram.mmd -o images/diagram.svg`
5. Update appropriate documentation sections
