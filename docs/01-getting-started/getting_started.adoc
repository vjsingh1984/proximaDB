== Installation

=== Option 1: Build from Source (Recommended)

**Why build from source?** Full control, latest features, optimized for your CPU.

[source,bash]
----
# 1. Install Rust (if needed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env

# 2. Clone ProximaDB
git clone https://github.com/vjsingh1984/proximaDB
cd proximaDB

# 3. Build (initial build ~3-5 minutes, then incremental)
cargo build --release

# 4. Start server
cargo run --bin proximadb-server
----

=== Step 2: Insert Vectors

Using the **Python SDK** (production-ready with 89% test coverage):

[source,bash]
----
# Install Python SDK
export PYTHONPATH=/path/to/proximaDB/clients/python/src
pip install numpy
----

[source,python]
----
from proximadb import ProximaDBClient, VectorRecord
import numpy as np

# Connect to server
client = ProximaDBClient(url="http://localhost:5678", protocol="rest")

# Generate sample paper embeddings (128D)
papers = []
for i in range(10):
    # Normalize to unit vector (best practice)
    vector = np.random.randn(128).astype(np.float32)
    vector = vector / np.linalg.norm(vector)

    papers.append(VectorRecord(
        id=f"paper_{i}",
        vector=vector.tolist(),
        metadata={
            "title": f"Research Paper {i}",
            "year": 2024,
            "category": "AI"
        }
    ))

# Batch insert (real metric: 5,193 papers/sec for 100 papers)
result = client.insert_vectors("research_papers", records=papers)
print(f"✅ Inserted {result.metrics.successful_count} papers")
----

=== Step 3: Search Vectors

[source,python]
----
# Create query vector
query = np.random.randn(128).astype(np.float32)
query = query / np.linalg.norm(query)

# Semantic search (real metric: 1.37ms for 100 papers)
results = client.search(
    collection_id="research_papers",
    vector=query.tolist(),
    top_k=5,
    include_metadata=True
)

# Explore results
for i, result in enumerate(results, 1):
    print(f"{i}. {result.metadata['title']}")
    print(f"   Similarity: {result.score:.4f}")
    print(f"   Year: {result.metadata['year']}")
----

**Performance reality check:**

```
✅ Search completed in 1.37ms (100 papers)
   Top-5 results returned with metadata
   No indexing needed for small datasets
```

# Direct graph API access (Python SDK graph methods coming in v0.2.0)

=== Step 5: Hybrid Query (Vector + Graph)

[source,python]
----
# 1. Find most similar paper by semantics (1.37ms)
search_results = client.search(
    collection_id="research_papers",
    vector=query.tolist(),
    top_k=1
)

most_similar = search_results[0]
print(f"Most similar: {most_similar.metadata['title']}")

# 2. Traverse citation network from that paper (0.48ms)
edges_response = graph_client.get(
    f"/api/v1/graphs/default/nodes/{most_similar.id}/edges"
)
citations = edges_response.json()

# ✅ Hybrid query total: 2.14ms (vector + graph)
print(f"Found {len(citations)} citations")
----

== Configuration & Tuning

=== Storage Engine Selection

ProximaDB auto-selects engines, but you can override:

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/collections \
  -H "Content-Type: application/json" \
  -d '{
    "name": "optimized_collection",
    "dimension": 384,
    "storage_engine": "sst",  # Explicit engine selection
    "config": {
      "sst": {
        "block_size_kb": 1024,     # 1MB (34% faster than 2MB)
        "compression": "lz4"         # 7% faster + 50% storage savings
      }
    }
  }'
----

**Engine selection guide:**

[cols="2,3,2", options="header"]
|===
| Workload | Recommended Engine | Why

| **Real-time search**
| SST (default)
| 5.32ms @10K vectors, balanced

| **High throughput**
| HELIX
| 13.2ms @10K, best for 1K scale

| **Low latency writes**
| SWIFT
| 28ms flush, write-optimized

| **Analytics/OLAP**
| VIPER
| 89.5ms @10K, columnar compression

| **Mixed workloads**
| NOVA
| Progressive search, adaptive
|===

=== Performance Tuning

**Compression (validated benchmarks):**

[source,toml]
----
# config/config.toml
[storage.sst_config]
block_size_kb = 1024    # 1MB - 34% faster than 2MB
compression = "lz4"      # 7% faster than no compression!
compression_level = 3    # Balance speed vs ratio
----

**Why LZ4 is faster:**
- Cache-friendly: Compressed blocks fit in CPU cache
- Lower memory bandwidth: Less data movement
- SIMD-optimized: Vectorized decompression

== Known Limitations (v0.1.4)

**Be aware of current constraints:**

⚠️ **Entity Store Durability**: Data does NOT persist across server restarts

- **What this means**: If you restart the server, vectors and graph data are lost
- **Why**: WAL (Write-Ahead Log) infrastructure exists but is disabled by default
- **Workaround**: Re-insert data on startup (suitable for development/testing)
- **Fix coming**: v0.2.0 will enable persistence by default

⚠️ **Graph Persistence**: Collection metadata persists, but graph nodes/edges are volatile

- **What persists**: Collection configuration, schema
- **What doesn't**: Graph nodes, edges, vector data
- **Workaround**: Store graph structure externally or re-create on startup

**Example persistence test:**

[source,bash]
----
# Test durability yourself
python3 /tmp/test_durability.py

# Result: ✗ Data did NOT persist after restart
# (Expected behavior in v0.1.4)
----

== Troubleshooting

=== Common Issues

**Issue: "Connection refused" error**

```bash
# Check if server is running
ps aux | grep proximadb-server

# Check port availability
lsof -i :5678

# Restart server with debug logging
RUST_LOG=debug cargo run --bin proximadb-server
```

**Issue: "ModuleNotFoundError: No module named 'proximadb'"**

```bash
# Set Python path correctly
export PYTHONPATH=/path/to/proximaDB/clients/python/src

# Or install SDK (development mode)
cd clients/python && pip install -e .
```

**Issue: Slow performance**

- **Small datasets (<1,000 vectors)**: No indexing needed, should be fast
- **Large datasets (>10,000 vectors)**: Consider adding HNSW index (planned for v0.2.0)
- **Check engine selection**: Use `HELIX` for best performance at 1K scale
