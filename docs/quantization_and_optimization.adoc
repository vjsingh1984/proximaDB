== Quantization Methods

ProximaDB supports multiple quantization techniques optimized for different use cases:

=== Product Quantization (PQ)

Product Quantization divides high-dimensional vectors into subvectors, quantizing each independently using learned codebooks.

==== How PQ Works

. **Vector Division**: Split d-dimensional vector into m subvectors
. **Codebook Training**: Learn k centroids for each subvector space
. **Encoding**: Replace each subvector with nearest centroid index
. **Storage**: Store m indices instead of d floats

[source,python]
----
quantization_config = QuantizationConfig(
enabled=True,
type=QuantizationType.PRODUCT,
bits_per_subvector=8, # 256 codes per subvector
num_subvectors=96, # For 768-dim: 768/8 = 96
adaptive_subvectors=True, # Auto-adjust based on dimension
compression_ratio_target=8.0, # Target 8x compression
accuracy_threshold=0.95 # Maintain 95% recall
)
----

=== Binary Quantization

Binary quantization provides maximum compression using 1 bit per dimension:

==== Binary Methods

. **Sign-based**: `b = 1 if x > 0 else 0`
. **Threshold-based**: `b = 1 if x > threshold else 0`
. **Learned thresholds**: Optimize per-dimension thresholds

[source,python]
----
quantization_config = QuantizationConfig(
enabled=True,
type=QuantizationType.BINARY,
threshold=0.0, # Sign-based by default
sign_based=True,
compression_ratio_target=32.0 # 32x compression
)
----

== Two-Stage Search Algorithm

ProximaDB's two-stage search leverages quantization for fast candidate selection followed by precise reranking:

[mermaid]
----
include::diagrams/two-stage-search.mmd[]
----

[source,python]
----
def two_stage_search(query, k, candidate_multiplier=3.0):
# Stage 1: Fast quantized search
candidates = quantized_search(
query,
k * candidate_multiplier,
use_quantized_vectors=True
)

# Stage 2: Precise reranking
results = precise_rerank(
query,
candidates,
k,
use_full_precision=True
)

return results
----

== Clustering Systems

ProximaDB employs two distinct clustering approaches:

=== Quantization Clustering (Compression)

* **Purpose**: Generate codebooks for Product Quantization (PQ)
* **Algorithm**: K-means clustering on vector subspaces
* **Output**: Centroids used as quantization codes
* **Benefit**: 4-32x compression ratios
* **Scope**: Applied universally across all storage engines

=== VIPER ML Clustering (Organization)

* **Purpose**: Group similar vectors for efficient storage and retrieval
* **Algorithm**: K-means++ on full vectors (not subvectors)
* **Output**: Cluster assignments for Parquet file organization
* **Benefit**: 3-5x search performance improvement
* **Scope**: VIPER engine only, for collections >1M vectors

[width="100%",cols="2,3,3",options="header"]
|===
|Aspect |Quantization Clustering |VIPER ML Clustering

|Primary Goal
|Reduce memory/storage size
|Optimize data layout for search

|Clustering Target
|Subvector spaces (e.g., 8-dim)
|Full vector space (e.g., 768-dim)

|Output
|Codebooks for encoding
|File organization strategy

|Storage Impact
|Smaller data footprint
|Better locality and cache usage

|Search Impact
|Enables fast Stage 1 search
|Reduces I/O through pruning

|Activation Threshold
|Always available

== Best Practices

=== Collection Design

[IMPORTANT]
====
. Start with conservative settings (INT8 or PQ8)
. Enable progressive quantization for flexibility
. Monitor accuracy metrics continuously
. Use dimensions divisible by 8 or 16 for PQ
====

=== Search Optimization

[TIP]
====
. Begin with `candidate_multiplier=3.0`
. Set reasonable min/max candidate bounds
. Enable parallel search on multi-core systems
. Use clustering for collections >10M vectors
====

=== Production Deployment

. **Benchmark**: Test with realistic data distributions
. **Monitor**: Track resource usage and latency
. **Scale**: Progressive quantization handles growth
. **Retrain**: Update codebooks periodically

|Enable progressive quantization
