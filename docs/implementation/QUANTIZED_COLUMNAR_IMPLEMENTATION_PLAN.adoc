**Implementation plan for file-level quantized vector storage with direct columnar access across all storage engines**

== 🎯 Executive Summary

=== **Architectural Approach: Direct Columnar Quantization**

**Problem Solved**: Eliminate quantization section map overhead and enable direct columnar pruning for optimal performance.

**Solution**: Individual optional columns (`q_binary`, `q_int8`, `q_pq4`, etc.) instead of nested quantization sections.

**Benefits**:
- **Direct Columnar Pruning**: Skip entire columns if quantization level not needed
- **Consistent Schema**: Identical column names across ProximaBlocks and Parquet
- **Zero Map Overhead**: No key lookups or nested structure traversal
- **File-Level Quantization**: Optimal for LSM compaction patterns

== 📊 Column Schema Design

=== **Unified Column Naming Convention (Using Constants)**

**Column names are defined in `src/storage/engines/core/formats/columnar/constants.rs` to ensure consistency across the entire codebase.**

[cols="3,2,2,3", options="header"]
|===
| Column Type | Column Name (Constant) | Storage Type | Pruning Capability

| **Vector Data** | | |
| Original vectors | `FIELD_VECTOR_FP32` ("vector_fp32") | `LIST<FLOAT>` | Always loaded
| Binary quantized | `FIELD_Q_BINARY` ("q_binary") | `BINARY` | Skip if not needed
| INT8 quantized | `FIELD_Q_INT8` ("q_int8") | `LIST<INT8>` | Column-level statistics
| PQ4 quantized | `FIELD_Q_PQ4` ("q_pq4") | `BINARY` | Skip for higher precision
| PQ8 quantized | `FIELD_Q_PQ8` ("q_pq8") | `BINARY` | Most common quantization
| PQ16 quantized | `FIELD_Q_PQ16` ("q_pq16") | `BINARY` | Higher precision
| PQ32 quantized | `FIELD_Q_PQ32` ("q_pq32") | `BINARY` | Highest precision

| **Codebooks** | | |
| PQ4 codebooks | `FIELD_CB_PQ4` ("cb_pq4") | `LIST<LIST<FLOAT>>` | Load independently
| PQ8 codebooks | `FIELD_CB_PQ8` ("cb_pq8") | `LIST<LIST<FLOAT>>` | Most common codebook
| PQ16 codebooks | `FIELD_CB_PQ16` ("cb_pq16") | `LIST<LIST<FLOAT>>` | Higher precision
| PQ32 codebooks | `FIELD_CB_PQ32` ("cb_pq32") | `LIST<LIST<FLOAT>>` | Highest precision

| **Parameters** | | |
| Binary threshold | `FIELD_QP_BINARY_THRESHOLD` ("qp_binary_threshold") | `FLOAT` | Constant per file
| INT8 min value | `FIELD_QP_INT8_MIN` ("qp_int8_min") | `FLOAT` | Constant per file
| INT8 max value | `FIELD_QP_INT8_MAX` ("qp_int8_max") | `FLOAT` | Constant per file
| INT8 scale factor | `FIELD_QP_INT8_SCALE` ("qp_int8_scale") | `FLOAT` | Constant per file
| PQ subquantizers | `FIELD_QP_PQ_SUBQUANTIZERS` ("qp_pq_subquantizers") | `UINT32` | Constant per file
| PQ centroids | `FIELD_QP_PQ_CENTROIDS` ("qp_pq_centroids") | `UINT32` | Constant per file
|===

**Constants Groups Available:**
- `QUANTIZED_VECTOR_COLUMNS`: All quantized vector columns
- `CODEBOOK_COLUMNS`: All codebook columns
- `QUANTIZATION_PARAMETER_COLUMNS`: All parameter columns
- `QUANTIZATION_COLUMNS`: Complete set of all quantization columns

=== **Column Pruning Strategies**

**Query-Specific Pruning**:
```rust
pub struct ColumnPruningStrategy {
    pub required_precision: f32,           // 0.95 = need q_int8+
    pub candidate_limit: usize,            // 1000 = can use q_binary
    pub reranking_enabled: bool,           // true = use progressive search
}

impl ColumnPruningStrategy {
    pub fn select_columns(&self, available_columns: &[String]) -> Vec<String> {
        // Select optimal columns based on query requirements
        match (self.required_precision, self.candidate_limit) {
            (p, _) if p > 0.98 => vec!["vector_fp32".to_string()],
            (p, c) if p > 0.90 && c < 10000 => vec!["q_pq8".to_string(), "vector_fp32".to_string()],
            (_, c) if c > 100000 => vec!["q_binary".to_string(), "q_int8".to_string(), "vector_fp32".to_string()],
            _ => vec!["q_int8".to_string(), "vector_fp32".to_string()],
        }
    }
}
```
