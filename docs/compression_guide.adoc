== Overview

image::compression-flow.svg[Unified Compression Architecture, width=900, align=center]

ProximaDB implements a unified compression module supporting 13 algorithms across all storage contexts, achieving 50-80% storage reduction with minimal performance impact.

== Quick Start

=== Enable Compression

```python
from proximadb import ProximaDBClient
from proximadb.models import CompressionConfig

client = ProximaDBClient("http://localhost:5678")

# Create collection with compression
collection = client.create_collection(
    name="compressed_data",
    dimension=1536,
    storage_engine="viper",
    compression=CompressionConfig(
        algorithm="zstd",
        level=6,
        enable_quantization=True,
        quantization_type="pq8"
    )
)
```

== Compression Algorithms

[cols="1,1,1,2", options="header"]
|===
| Algorithm | Ratio | Speed | Best For

| LZ4 | 2-3x | Fastest | Real-time, low latency
| Snappy | 2-3x | Very fast | Balanced performance
| ZSTD | 3-5x | Moderate | Best ratio/speed balance
| Gzip | 3-4x | Slow | Compatibility
| Brotli | 4-6x | Slow | Maximum compression
| None | 1x | No overhead | Testing/debugging
|===

Additional algorithms: Bzip2, Deflate, XZ, Zlib, LZO, LZ4HC, LZMA

== Two-Tier Architecture

=== Protocol Level (Transport)
* **Purpose**: Network bandwidth reduction
* **Default**: Disabled (for debugging)
* **Configuration**: Server-wide

```toml
[api]
rest_compression = false  # Keep disabled for debugging
grpc_compression = true   # Enable for production
```

=== Collection Level (Storage)
* **Purpose**: Storage optimization
* **Default**: Per-collection configuration
* **Configuration**: SDK-driven

```python
compression = CompressionConfig(
    algorithm="zstd",
    level=6,  # 1-9, higher = better compression
    enable_quantization=True
)
```

== Quantization Options

=== Vector Quantization Types

[cols="1,1,1,2", options="header"]
|===
| Type | Compression | Accuracy | Use Case

| INT8 | 4x | 99.5% | High accuracy required
| PQ8 | 8-32x | 95-99% | Balanced
| PQ4 | 16-64x | 90-95% | Maximum compression
| Binary | 32x | 85-95% | Extreme scale
|===

=== Engine Recommendations

**VIPER Engine**: ✅ Quantization recommended
* Columnar format benefits from uniform types
* Better compression ratios
* Faster SIMD operations

**SST Engine**: ❌ Quantization not recommended
* Row format doesn't benefit
* Added complexity without gains
* Use native FP32

== Context-Aware Compression

The unified compression module automatically optimizes for different contexts:

=== SST Blocks
* Algorithm: LZ4 or ZSTD
* Block-level compression
* Preserves random access

=== Vector Serialization
* Algorithm: Any supported
* Header with checksums
* Streaming support

=== Parquet Columns
* Algorithm: 7 supported (ZSTD, LZ4, Snappy, Gzip, Brotli, LZO, None)
* Column-level compression
* Predicate pushdown preserved

== Monitoring & Metrics

=== Compression Metrics
```bash
curl http://localhost:5678/metrics | grep compression

# Key metrics
proximadb_compression_ratio         # Current compression ratio
proximadb_compression_bytes_saved   # Total bytes saved
proximadb_compression_time_ms       # Compression overhead
```

=== Performance Tuning

**Low compression ratio (<30%)**
* Switch to ZSTD from LZ4
* Increase compression level
* Enable quantization

**High latency impact (>20%)**
* Switch to LZ4 from ZSTD
* Reduce compression level
* Disable quantization

**Memory pressure**
* Enable compression for all collections
* Use higher compression levels
* Enable tiering for cold data

== Best Practices

1. **Start with defaults** (ZSTD level 6)
2. **Measure impact** before optimization
3. **Test with your data** - compression varies by content
4. **Consider workload** - read vs write patterns
5. **Monitor metrics** - track ratio and performance
