= Performance Metrics
:toc: left

Performance benchmarks and optimization guidelines for ProximaDB.

== Benchmark Results

**Insert Performance**: gRPC achieves 49K vectors/sec (batch 500), 10K vectors/sec (batch 100). REST achieves 20K vectors/sec (batch 100), 2K vectors/sec (batch 10).

**Search Latency**: SST P50: 1.8ms, P95: 4.5ms, P99: 9.2ms. VIPER P50: 1.5ms, P95: 3.8ms, P99: 7.5ms. SQL queries: P50: 3.2ms, P95: 12ms, P99: 28ms.

**Resource Usage**: Base memory 100MB, 1M vectors require 2.1-3.5GB. CPU usage: 0.5% idle, up to 85% under search load. Disk I/O: 50-180MB/s write throughput.

== Optimization Guidelines

**Hardware Acceleration**: Enable SIMD (AVX-512/NEON) and GPU (CUDA/ROCm) for distance computations with CPU fallback.

**Memory Optimization**: Configure vector pool (512MB), cache (256MB), and bloom filter memory (128MB).

**Storage Optimization**: SST uses 8MB blocks, 1% bloom filter FPR, ZSTD level 3. VIPER uses 50K row groups, statistics enabled, ZSTD level 6.

== Workload-Specific Tuning

**Write-Heavy**: Use SST engine, increase write buffer (256MB), reduce compaction frequency (600s), enable batch commits.

**Read-Heavy**: Use VIPER engine, increase cache (1024MB), enable bloom filters, optimize with HNSW indexes.

**Mixed**: Use dual-engine setup, route by collection, balance resources, monitor metrics.

== Performance Tips

**Batch Operations**: Insert 100-500 vectors per batch, use gRPC for maximum throughput, enable async processing.

**Query Optimization**: Use metadata filters, enable query plan caching, leverage SQL for complex queries.

**Resource Management**: Monitor with Prometheus, set appropriate limits, use connection pooling.

== Monitoring

Key Prometheus metrics: vector insert rate, P99 search latency, memory usage, compaction frequency.

== Capacity Planning

**Storage**: 1M vectors (128-dim) require 512MB raw / 250MB compressed. 100M vectors (768-dim) require 300GB raw / 120GB compressed.

**Memory**: Base 100MB + ~2GB per million vectors + 20% for indexes. Configure cache based on working set.
