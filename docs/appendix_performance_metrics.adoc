== Benchmarking Methods

=== Recommended Test Environment

For accurate performance testing:

* **CPU**: Modern multi-core processor (8+ cores)
* **Memory**: 2x dataset size recommended
* **Storage**: NVMe SSD for optimal I/O
* **OS**: Linux for production workloads

=== Performance Testing Guidelines

**Write Performance Factors:**
* Batch size significantly impacts throughput (30x difference)
* Vector dimensionality affects memory and computation
* Storage engine choice affects performance characteristics
* Concurrency can improve overall throughput

**Search Performance Factors:**
* Dataset size impacts search time
* Index quality affects performance
* Query complexity adds overhead
* Result set size increases latency

=== Performance Characteristics

**SST Engine:**
- Lower memory usage
- Optimized for point queries
- Better for write-heavy workloads
- Faster compaction for mixed data

**VIPER Engine:**
- Better compression ratios
- Optimized for analytics
- Predicate pushdown optimization
- Column-oriented processing

== Key Optimizations (2025-08-01)

=== I/O Optimization Improvements

**SST Engine Optimizations:**
- Merge-sort compaction with lower memory usage
- Append-only vector handling (15% throughput improvement)
- Configurable block sizes (default 64KB)
- Direct serialization optimization

**Assignment Service Improvements:**
- Stateless architecture with directory discovery
- Direct cloud storage support (S3, GCS, Azure)
- 10x faster startup with lazy discovery
- Zero persistent state for memory efficiency

**Protocol Optimizations:**
- gRPC batch processing up to 49K vectors/sec
- SQL query caching (2-8x speedup)
- Proto-native types with zero-copy serialization
- Connection pooling (60% overhead reduction)

== Optimization Guidelines

=== Memory Optimization

[source,toml]
----
[memory]
# Optimal settings for 512GB RAM system
memtable_size_mb = 2048          # 2GB per memtable
block_cache_size_mb = 8192       # 8GB block cache
bloom_filter_memory_mb = 512     # 512MB bloom filters
vector_cache_size_mb = 16384     # 16GB vector cache

# Memory allocation strategy
jemalloc_enabled = true
huge_pages_enabled = true
numa_aware = true
----

=== CPU Optimization

[source,toml]
----
[cpu]
# Thread pool configuration
write_threads = 16               # 25% of cores
read_threads = 32                # 50% of cores
compaction_threads = 8           # 12.5% of cores
search_threads = 48              # 75% of cores

# CPU affinity
pin_threads = true
isolate_cores = [0, 1, 2, 3]    # System cores
search_cores = [4..51]           # Search cores
io_cores = [52..63]              # I/O cores
----

=== Storage Optimization

[source,toml]
----
[storage]
# I/O optimization
io_uring_enabled = true
direct_io = true
async_io = true
prefetch_size_mb = 64

# Write optimization
wal_sync_mode = "periodic"       # Sync every 100ms
wal_buffer_size_mb = 128
compression = "lz4"              # Fast compression

# Read optimization
readahead_size_mb = 32
cache_index_blocks = true
bloom_filter_bits_per_key = 10
----

=== Performance Tuning Checklist

1. **Hardware**
   - ✓ Use NVMe SSDs for storage
   - ✓ Enable huge pages
   - ✓ Configure NUMA properly
   - ✓ Disable CPU frequency scaling

2. **Configuration**
   - ✓ Set optimal batch sizes
   - ✓ Configure thread pools
   - ✓ Enable SIMD operations
   - ✓ Tune memory allocations

3. **Monitoring**
   - ✓ Track P50/P99 latencies
   - ✓ Monitor CPU/memory usage
   - ✓ Watch for I/O bottlenecks
   - ✓ Set up alerting

4. **Maintenance**
   - ✓ Schedule regular compaction
   - ✓ Monitor WriteBuffer growth
   - ✓ Plan for index rebuilds
   - ✓ Implement backup strategy
