This appendix provides performance testing guidelines and optimization recommendations for ProximaDB.

== Performance Testing Guidelines

=== Recommended Test Environment

For accurate performance testing, use:

* **CPU**: Modern multi-core processor (8+ cores recommended)
* **Memory**: Sufficient RAM for dataset (2x dataset size recommended)
* **Storage**: NVMe SSD for optimal I/O performance
* **OS**: Linux recommended for production workloads

== Performance Characteristics

=== Write Performance Factors

* **Batch Size**: Larger batches improve throughput but increase latency
* **Vector Dimensionality**: Higher dimensions require more memory and computation
* **Storage Engine**: SST optimized for writes, VIPER for analytics
* **Concurrency**: Multiple writers can improve throughput

=== Search Performance Factors

* **Dataset Size**: Larger datasets increase search time
* **Index Quality**: Well-maintained indexes improve performance
* **Query Complexity**: Metadata filters add overhead
* **Result Set Size**: Returning more results increases latency

== Large-Scale Performance

=== Scalability Considerations

* **Linear Scaling**: Insert time and storage generally scale linearly with dataset size
* **Memory Requirements**: Plan for ~2x dataset size for optimal performance
* **Search Scaling**: Search latency increases sub-linearly with proper indexing
* **Hardware Limits**: Consider distributed deployment for datasets exceeding single-node capacity

== Optimization Guidelines

=== Memory Optimization

[source,toml]
----
[memory]
# Optimal settings for 512GB RAM system
memtable_size_mb = 2048          # 2GB per memtable
block_cache_size_mb = 8192       # 8GB block cache
bloom_filter_memory_mb = 512     # 512MB bloom filters
vector_cache_size_mb = 16384     # 16GB vector cache

# Memory allocation strategy
jemalloc_enabled = true
huge_pages_enabled = true
numa_aware = true
----

=== CPU Optimization

[source,toml]
----
[cpu]
# Thread pool configuration
write_threads = 16               # 25% of cores
read_threads = 32                # 50% of cores
compaction_threads = 8           # 12.5% of cores
search_threads = 48              # 75% of cores

# CPU affinity
pin_threads = true
isolate_cores = [0, 1, 2, 3]    # System cores
search_cores = [4..51]           # Search cores
io_cores = [52..63]              # I/O cores
----

=== Storage Optimization

[source,toml]
----
[storage]
# I/O optimization
io_uring_enabled = true
direct_io = true
async_io = true
prefetch_size_mb = 64

# Write optimization
wal_sync_mode = "periodic"       # Sync every 100ms
wal_buffer_size_mb = 128
compression = "lz4"              # Fast compression

# Read optimization
readahead_size_mb = 32
cache_index_blocks = true
bloom_filter_bits_per_key = 10
----

=== Performance Tuning Checklist

1. **Hardware**
   - ✓ Use NVMe SSDs for storage
   - ✓ Enable huge pages
   - ✓ Configure NUMA properly
   - ✓ Disable CPU frequency scaling

2. **Configuration**
   - ✓ Set optimal batch sizes
   - ✓ Configure thread pools
   - ✓ Enable SIMD operations
   - ✓ Tune memory allocations

3. **Monitoring**
   - ✓ Track P50/P99 latencies
   - ✓ Monitor CPU/memory usage
   - ✓ Watch for I/O bottlenecks
   - ✓ Set up alerting

4. **Maintenance**
   - ✓ Schedule regular compaction
   - ✓ Monitor WriteBuffer growth
   - ✓ Plan for index rebuilds
   - ✓ Implement backup strategy
