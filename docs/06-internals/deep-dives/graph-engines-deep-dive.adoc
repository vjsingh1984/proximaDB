= ORION Graph Runtime Deep Dive
:toc: left
:icons: font

== Summary

ORION is ProximaDB's graph runtime. It maintains graph topology projections over
canonical records and provides fast traversal, graph query, and graph RAG
execution. It is not a separate durable authority.

== Authority Model

[source,text]
----
xCatalog + canonical records + WAL/log/manifest + policy/RLS
        |
canonical node/edge facts
        |
      ORION
        |
CSR / adjacency / graph RAG projections
----

ORION projections can be rebuilt from canonical state. Projection WAL and
snapshot files are compatibility recovery buffers, not the durable source of
truth.

== Distributed Scale

ORION does not own cluster coordination. Graph scale-out depends on the
relational distributed substrate:

* partitioning and placement,
* route planning,
* fanout/fanin execution,
* isolation and policy enforcement,
* rebalance and recovery,
* distributed `EXPLAIN` metadata.

Former PULSAR coordinator and sharding concepts are tracked as requirements for
that substrate.

== Projection Tiering

ORION does not own cold-tier storage. Hot/cold behavior is cataloged storage
policy over canonical records:

* projection freshness,
* retention tier,
* access heat,
* rebuild source,
* policy boundary.

Former QUASAR access-tracking and tiering concepts are tracked as requirements
for xCatalog/storage projection policy.

== Operational Guidance

Use ORION for graph workloads. Do not configure PULSAR or QUASAR; those engine
names are retired and rejected by runtime compatibility checks.
