== Overview

ProximaDB provides both gRPC and REST APIs for vector operations. The gRPC API offers better performance (2.1x throughput) while REST provides broader compatibility.

== Connection

=== gRPC

[source,python]
----
import grpc
from proximadb import proximadb_pb2_grpc

channel = grpc.insecure_channel('localhost:5679')
stub = proximadb_pb2_grpc.VectorServiceStub(channel)
----

=== REST

[source,python]
----
import requests

base_url = "http://localhost:5678/api/v1"
headers = {"Content-Type": "application/json"}
----

== Collections

=== Create Collection

.gRPC Example
[source,python]
----
request = CreateCollectionRequest(
    collection=Collection(
        name="embeddings",
        dimension=1536,
        distance_metric=DistanceMetric.COSINE,
        storage_engine=StorageEngine.VIPER,
        indexing_algorithm=IndexingAlgorithm.HNSW
    )
)
response = stub.CreateCollection(request)
----

.REST Example
[source,bash]
----
POST /api/v1/collections
{
    "name": "embeddings",
    "dimension": 1536,
    "distance_metric": "cosine",
    "storage_engine": "VIPER",
    "indexing_algorithm": "HNSW"
}
----

== Vector Operations

=== Insert Vectors

.gRPC Example
[source,python]
----
vectors = [
    VectorRecord(
        id="vec_001",
        vector=[0.1, 0.2, ...],  # 1536 dimensions
        metadata=[
            MetadataItem(key="category", value="product"),
            MetadataItem(key="price", value="29.99")
        ]
    )
]
request = VectorBatchRequest(
    collection_name="embeddings",
    vectors=vectors
)
response = stub.BatchUpsert(request)
----

.REST Example
[source,json]
----
POST /api/v1/collections/embeddings/vectors
{
    "vectors": [
        {
            "id": "vec_001",
            "vector": [0.1, 0.2, ...],
            "metadata": {
                "category": "product",
                "price": 29.99
            }
        }
    ]
}
----

=== Search Vectors

.gRPC Example
[source,python]
----
request = SearchRequest(
    collection_name="embeddings",
    query=SearchQuery(
        vector=[0.15, 0.25, ...],
        k=10,
        distance_metric=DistanceMetric.COSINE,
        params=SearchParams(
            ef_search=200,  # HNSW parameter
            nprobe=10       # IVF parameter
        )
    )
)
response = stub.Search(request)
----

.REST Example
[source,json]
----
POST /api/v1/collections/embeddings/search
{
    "vector": [0.15, 0.25, ...],
    "k": 10,
    "distance_metric": "cosine",
    "params": {
        "ef_search": 200,
        "nprobe": 10
    }
}
----

== Advanced Features

=== Filtered Search

[source,python]
----
# Search with metadata filters
request = SearchRequest(
    collection_name="embeddings",
    query=SearchQuery(
        vector=[...],
        k=10,
        filter={
            "category": "product",
            "price": {"$gte": 20, "$lte": 100}
        }
    )
)
----

=== Batch Operations

[source,python]
----
# Batch search
requests = [
    SearchQuery(vector=[...], k=5),
    SearchQuery(vector=[...], k=5)
]
response = stub.BatchSearch(BatchSearchRequest(
    collection_name="embeddings",
    queries=requests
))

# Batch delete
stub.BatchDelete(BatchDeleteRequest(
    collection_name="embeddings",
    ids=["vec_001", "vec_002", "vec_003"]
))
----

=== Quantization Control

[source,python]
----
# Configure quantization for a collection
config = QuantizationConfig(
    enabled=True,
    type="PQ",  # Product Quantization
    parameters={
        "num_subvectors": 64,
        "bits_per_code": 8
    }
)
----

=== Index Configuration

.HNSW Configuration
[source,python]
----
index_config = {
    "type": "HNSW",
    "parameters": {
        "M": 16,              # Number of connections
        "ef_construction": 200,  # Construction parameter
        "ef_search": 100      # Search parameter
    }
}
----

.IVF Configuration
[source,python]
----
index_config = {
    "type": "IVF",
    "parameters": {
        "nlist": 100,    # Number of clusters
        "nprobe": 10     # Clusters to search
    }
}
----

== Distance Metrics

[cols="1,2,1,2", options="header"]
|===
| Metric | Description | Range | Use Case

| `COSINE`
| Cosine similarity
| [0, 2]
| Text embeddings

| `EUCLIDEAN`
| L2 distance
| [0, ∞)
| General purpose

| `DOT_PRODUCT`
| Inner product
| (-∞, ∞)
| Normalized vectors

| `MANHATTAN`
| L1 distance
| [0, ∞)
| Sparse vectors

| `HAMMING`
| Bit differences
| [0, n]
| Binary vectors
|===

== Storage Engines

[cols="1,2,2", options="header"]
|===
| Engine | Description | Best For

| `VIPER`
| Columnar storage
| Analytics, batch operations

| `SST`
| LSM-tree based
| High write throughput

| `RAPTOR`
| HNSW integrated
| Graph-based search

| `NOVA`
| Zone maps
| Range queries

| `SWIFT`
| Adaptive blocks
| Mixed workloads

| `PRISM`
| Progressive search
| Large-scale search
|===

== Error Codes

[cols="1,2,2", options="header"]
|===
| Code | Description | Resolution

| `INVALID_ARGUMENT`
| Invalid parameters
| Check request format

| `NOT_FOUND`
| Collection/vector not found
| Verify resource exists

| `ALREADY_EXISTS`
| Duplicate resource
| Use update instead

| `RESOURCE_EXHAUSTED`
| Out of memory/disk
| Scale resources

| `INTERNAL`
| Server error
| Check server logs
|===

== Performance Tips

. *Use gRPC* for 2.1x better throughput
. *Batch operations* for better efficiency
. *Configure indexes* based on your dataset size
. *Enable quantization* for memory savings
. *Choose the right storage engine* for your workload
