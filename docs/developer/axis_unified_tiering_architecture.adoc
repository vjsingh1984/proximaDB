== Implementation Design

=== Core Components

[source,rust]
----
/// AXIS Tiering Integration - Lightweight orchestration layer
pub struct AxisTieringManager {
    /// Existing infrastructure references
    access_tracker: Arc<AccessPatternTracker>,
    global_tier_manager: Arc<GlobalTierManager>,
    adaptive_store: Arc<AdaptiveStore>,
    
    /// AXIS-specific enhancements
    index_preferences: AxisIndexPreferences,
    collection_constraints: CollectionConstraints,
}

/// Index-specific tier preferences
pub struct AxisIndexPreferences {
    preferences: HashMap<AxisIndexType, TierPreference>,
}

/// Collection-level constraints
pub struct CollectionConstraints {
    memory_pinned: HashSet<String>,      // Never evict from memory
    no_cloud: HashSet<String>,           // Keep on-premise
    max_tier: HashMap<String, TierLevel>, // Tier limits
}
----

=== Integration Flow

**1. Access Tracking**
```rust
// Uses existing AccessPatternTracker
self.access_tracker.track_access_async(
    collection_id,
    CacheType::IndexStructure
);
```

**2. Pattern Analysis**
```rust
// Leverages existing heat scoring
let is_hot = self.access_tracker
    .is_frequently_accessed(collection_id, threshold)
    .await;
```

**3. Tier Recommendation**
```rust
// Uses GlobalTierManager policies
let tier = self.global_tier_manager
    .recommend_tier(&workload_pattern, frequency, age);
    
// Apply AXIS-specific preferences
let final_tier = self.apply_index_preferences(tier, index_type);
```

== Policy Engine

=== Auto-Tiering Rules

[cols="2,1,1,1", options="header"]
|===
| Condition | Action | Tier Change | Priority

| Access > 100/min | Promote | → Memory | High
| Access < 10/min for 1hr | Demote | → NVMe | Medium
| No access for 24hr | Demote | → HDD | Low
| No access for 7d | Archive | → Cloud | Low
| Memory pressure > 70% | Emergency demote | → Next tier | Critical
|===

=== Index Type Preferences

[cols="1,2,2", options="header"]
|===
| Index Type | Preferred Tiers | Reason

| HNSW
| Memory > NVMe
| Graph traversal needs low latency

| IVF
| NVMe > Memory/HDD
| Balanced access patterns

| PQ
| Any tier
| Compression makes it tier-agnostic

| LSH
| HDD/Cloud acceptable
| Hash-based, tolerates latency

| FLAT
| Memory only
| Brute force needs speed
|===

== Migration Process

=== Tier Promotion

1. **Detection**: Access rate exceeds threshold
2. **Preparation**: Allocate space in target tier
3. **Migration**: Stream data with progress tracking
4. **Validation**: Verify data integrity
5. **Activation**: Update routing tables
6. **Cleanup**: Remove from source tier

=== Tier Demotion

1. **Detection**: Access rate below threshold
2. **Format Conversion**: Apply tier-specific compression
3. **Migration**: Background transfer
4. **Validation**: Checksum verification
5. **Activation**: Update metadata
6. **Monitoring**: Track for re-promotion
