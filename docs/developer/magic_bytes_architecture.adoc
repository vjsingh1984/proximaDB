**File format identification and validation using magic bytes.**

== Overview

ProximaDB uses magic bytes for format validation across its dual storage engines, ensuring data integrity and preventing format confusion.

== Magic Bytes Specification

=== SST Engine
[cols="1,1,2,2", options="header"]
|===
| Magic | Hex | Component | Purpose

| SST1 | 0x53535431 | SSTable Header | Main file identifier
| BF01 | 0x42463031 | Bloom Filter | Bloom data validation
| BLK1 | 0x424C4B31 | Data Block | Block marker
| IDX1 | 0x49445831 | Index Block | Index validation
|===

**SST File Structure:**
```
┌────────────────────────────┐
│ SST1 (4 bytes)             │
├────────────────────────────┤
│ Header Length + Data       │
├────────────────────────────┤
│ BF01 + Bloom Filter        │
├────────────────────────────┤
│ IDX1 + Index Data          │
├────────────────────────────┤
│ BLK1 + Data Blocks         │
└────────────────────────────┘
```

=== VIPER Engine
[cols="1,1,2,2", options="header"]
|===
| Format | Magic | Location | Standard

| Parquet | PAR1 | File footer | Apache Parquet
| Arrow | ARROW1 | File header | Apache Arrow
|===

== Implementation

=== SST Validation
```rust
const SST_MAGIC: &[u8; 4] = b"SST1";

pub fn validate_format(data: &[u8]) -> Result<()> {
    if data.len() < 8 {
        return Err("File too small");
    }
    if &data[0..4] != b"SST1" {
        return Err("Invalid SSTable format");
    }
    Ok(())
}
```

=== File Extension Routing
```rust
pub fn determine_engine(path: &str) -> StorageEngine {
    match extension {
        "sst" | "lsm" => StorageEngine::SST,
        "parquet" | "vpr" => StorageEngine::VIPER,
        "avro" | "proto" => StorageEngine::WAL,
        _ => StorageEngine::SST
    }
}
```

== Error Handling

=== Error Types
```rust
pub enum MagicByteError {
    InvalidSST { found: [u8; 4], path: String },
    InvalidBloom { found: [u8; 4], offset: u64 },
    InvalidParquet { path: String },
    FileTooSmall { size: usize, minimum: usize },
}
```

=== Recovery Actions
1. **Descriptive Errors**: Clear indication of expected vs found
2. **No Fallback**: No automatic format conversion
3. **Logging**: Error details for debugging
4. **Recovery**: Suggest re-export or conversion

== Performance

=== Overhead
* **SST**: Single 4-byte read (negligible)
* **Parquet**: Header + footer reads (minimal)
* **Caching**: Magic bytes cached after validation
* **Parallel**: Multiple files validated concurrently

=== Optimization
1. **Lazy Validation**: Only on first access
2. **Batch Processing**: Parallel validation
3. **Memory Mapping**: For large files
4. **Skip Option**: For trusted sources

== Security
