== Hardware Capabilities

=== Initialization
[source,rust]
----
use proximadb::core::hardware_capabilities::*;

// Required at startup
initialize_hardware_capabilities_default()?;

// Access globally
let caps = get_hardware_capabilities();
----

=== Capability Checks
[source,rust]
----
caps.has_avx512()      // AVX-512 available
caps.has_gpu()         // GPU acceleration
caps.has_simd()        // Any SIMD available

// Hardware-aware decisions
if caps.should_use_gpu_distance(vector_size) {
    // Use GPU for large vectors
}
----

[source,toml]
----

== Search Architecture

=== Two-Stage Search Strategy

image::two-stage-search.svg[Two-Stage Search, width=900]
_Coarse-to-fine search strategy with quantized first stage and FP32 reranking_

The two-stage approach provides optimal performance:
1. **Stage 1 (Coarse)**: Use quantized vectors or indexes to get 10-100x candidates
2. **Stage 2 (Fine)**: Rerank with full precision FP32 vectors

=== Search Orchestration Layers

ProximaDB implements a clear separation of concerns in its search architecture:

==== Orchestration Layer (VectorOperationsService)
Handles high-level coordination and result merging:

* **Stateless orchestration**: No engine-specific logic
* **Parallel execution**: Concurrent WAL, index, and storage searches
* **Smart deduplication**: Handles duplicates across sources
* **Collection awareness**: Routes to appropriate engines based on metadata

==== Engine Layer (SST/VIPER)
Implements engine-specific optimizations:

* **SST Engine**: Three-stage filter pipeline for row-based data
* **VIPER Engine**: Columnar optimizations and predicate pushdown
* **Index Manager**: AXIS index routing and management
* **WAL Search**: Bloom filter optimization for unflushed data

== SQL Interface

[source,sql]
----
-- Create collection
CREATE COLLECTION vectors (dimension=384, engine='viper');

-- Insert
INSERT INTO vectors (id, vector, metadata) 
VALUES ('vec1', [0.1, ...], '{"key": "value"}');

-- Search
SELECT id, similarity(vector, [0.1, ...]) as score
FROM vectors
ORDER BY score DESC
LIMIT 10;
----

== Index Types

[cols="1,2,1,1", options="header"]
|===
| Type | Best For | Memory | Search

| HNSW | High recall | O(M×N) | O(log N)
| IVF | Large datasets | O(N) | O(nprobe×N/K)
| LSH | Approximate | O(L×N) | O(L)

|===

== Error Codes

* **COLLECTION_NOT_FOUND**: Collection doesn't exist
* **DIMENSION_MISMATCH**: Vector dimension incorrect
* **INVALID_METADATA**: JSON parsing failed
* **STORAGE_ERROR**: Disk/permission issue
* **TIMEOUT**: Operation exceeded time limit
