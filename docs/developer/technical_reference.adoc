== Hardware Capabilities API

=== Centralized Hardware Detection

[source,rust]
----
use proximadb::core::hardware_capabilities::{
    get_hardware_capabilities, initialize_hardware_capabilities_default
};

// Initialize at server startup (required)
initialize_hardware_capabilities_default()?;

// Access capabilities globally
let caps = get_hardware_capabilities();
println!("CPU: {} cores, GPU: {}", caps.cpu.logical_cores, caps.gpu.backend);
----

=== Hardware Capability Queries

[source,rust]
----
// Check specific capabilities
caps.has_avx512()           // AVX-512 available and enabled
caps.has_gpu()              // GPU acceleration available
caps.has_gpu_parsing()      // GPU SQL parsing enabled
caps.has_simd()             // Any SIMD acceleration available

// Hardware-aware decisions
if caps.should_use_gpu_distance(vector_size) {
    // Use GPU for large vectors
}

// Get optimal backend
let backend = caps.preferred_backend(); // Returns best available hardware
----

=== MVCC Resolution API

[source,rust]
----
use proximadb::core::search::mvcc_resolution::MvccResolver;

// Create resolver with current timestamp
let resolver = MvccResolver::new();

// Create resolver with custom timestamp (testing)
let resolver = MvccResolver::with_timestamp(1234567890);

// Resolve vector records according to MVCC rules
let resolved = resolver.resolve_batch(records);
----

**MVCC Resolution Features**:
- **Expiry Management**: Automatic exclusion of expired records
- **Version Control**: Highest version without gaps wins
- **Timestamp Resolution**: Earliest timestamp for same version
- **Append-Only Support**: Empty ID bypass for high-throughput
- **Global Deletion**: ID-based expiry affects all versions

== SQL Acceleration APIs

=== GPU-Accelerated SQL Parser

[source,rust]
----
use proximadb::query::sql_engine::gpu_parser::{GpuSqlParser, parse_sql_gpu};

// Global parser (recommended)
let query = parse_sql_gpu(sql)?;

// Direct parser instance
let mut parser = GpuSqlParser::new()?;
let query = parser.parse(sql)?;

// Performance statistics
let stats = parser.get_stats();
println!("GPU: {}, CPU: {}", stats.gpu_accelerated_count, stats.cpu_fallback_count);
----

== API Reference

=== REST API

==== Collections

[source,http]
----
# Create collection
POST /collections
{
  "name": "my_collection",
  "dimension": 384,
  "engine": "viper"
}

# Get collection
GET /collections/{name}

# Delete collection
DELETE /collections/{name}

# List collections
GET /collections
----

==== Vectors

[source,http]
----
# Insert vectors
POST /collections/{name}/vectors
{
  "vectors": [
    {
      "id": "vec1",
      "vector": [0.1, 0.2, ...],
      "metadata": {"key": "value"}
    }
  ]
}

# Search vectors
POST /collections/{name}/search
{
  "vector": [0.1, 0.2, ...],
  "top_k": 10,
  "metadata_filter": {"key": "value"}
}

# Get vector
GET /collections/{name}/vectors/{id}

# Delete vector
DELETE /collections/{name}/vectors/{id}
----

=== SQL Interface

[source,sql]
----
-- Create collection
CREATE COLLECTION my_collection (dimension=384, engine='viper');

-- Insert vectors
INSERT INTO my_collection (id, vector, metadata) 
VALUES ('vec1', [0.1, 0.2, ...], '{"key": "value"}');

-- Search vectors
SELECT id, metadata, similarity(vector, [0.1, 0.2, ...]) as score
FROM my_collection
WHERE metadata->>'key' = 'value'
ORDER BY score DESC
LIMIT 10;

-- Delete vectors
DELETE FROM my_collection WHERE id = 'vec1';
----

== Configuration Reference

=== Server Configuration

**Ports**: REST port 5678, gRPC port 5679, configurable worker threads and connections

**Storage**: Dual engine (SST + VIPER), configurable data directory, write buffer settings

**Cloud Storage**: AWS S3, Azure Blob, Google Cloud Storage support with native authentication

=== Compression Configuration

==== Network Compression Defaults
* **REST API**: Compression OFF by default
  - Reason: Better debugging and troubleshooting
  - Supports: gzip, deflate, zstd, brotli
* **gRPC**: Compression ON by default  
  - Reason: Better performance
  - Supports: gzip (tonic limitation)

==== Configuration Hierarchy
1. **Defaults**: REST off, gRPC on
2. **TOML config**: Overrides defaults via `enable_compression` in `[rest]` and `[grpc]` sections
3. **Runtime**: Can be overridden programmatically

==== TOML Configuration
[source,toml]
----
[rest]
enable_compression = false  # Default: false
max_request_size_mb = 64

[grpc]
enable_compression = true   # Default: true
max_frame_size_mb = 16
----

==== Storage Compression
[source,toml]
----
[storage.sst_config]
compression = "zstd"
compression_enabled = true   # Default: true
compression_level = 3        # 1-22 for ZSTD

[storage.viper_config]
compression = "zstd"  
compression_enabled = true   # Default: true
compression_level = 3        # 1-22 for ZSTD
----

== Distance Metrics

* **cosine**: Cosine similarity [0, 2]
* **euclidean**: L2 distance [0, ∞)  
* **dot_product**: Inner product (-∞, ∞)
* **manhattan**: L1 distance [0, ∞)
* **hamming**: Bit differences [0, n]
* **jaccard**: Set similarity [0, 1]

== Index Types

=== HNSW (Hierarchical Navigable Small World)
* Best for: High recall requirements
* Memory: O(M × N) where M is connections
* Build time: O(N log N)
* Search time: O(log N)

=== IVF (Inverted File)
* Best for: Large datasets
* Memory: O(N) + centroids
* Build time: O(N × K) clustering
* Search time: O(nprobe × N/K)

=== LSH (Locality Sensitive Hashing)
* Best for: Approximate matching
* Memory: O(L × N) where L is tables
* Build time: O(L × N)
* Search time: O(L)

=== Annoy (Approximate Nearest Neighbors)
* Best for: Memory-constrained
* Memory: O(N × n_trees)
* Build time: O(N × n_trees × log N)
* Search time: O(n_trees × log N)

== Error Codes

* **COLLECTION_NOT_FOUND**: Collection does not exist - Create collection first
* **DIMENSION_MISMATCH**: Vector dimension incorrect - Check collection dimension  
* **INVALID_METADATA**: Metadata parsing failed - Validate JSON format
* **STORAGE_ERROR**: Storage operation failed - Check disk space/permissions
* **TIMEOUT**: Operation timed out - Retry with backoff
