**Technical architecture and deployment patterns for ProximaDB**

== Architecture Overview

image::deployment-architecture-cloud.svg[Cloud Deployment Architecture, width=1000]

ProximaDB employs a revolutionary single-server architecture that leverages cloud-native storage for resilience while eliminating the complexity of distributed systems.

=== Core Design Principles

1. **Single Server Simplicity**: One process, no coordination overhead
2. **Cloud-Native Storage**: Leverage S3/Blob/GCS for durability
3. **Stateless by Default**: Compute and storage separation
4. **Container-First**: Docker/Kubernetes native
5. **Zero-Downtime Operations**: Rolling updates, instant failover

== Resilience Architecture

image::deployment-resilience-flow.svg[Resilience Flow Diagram, width=1000]

=== Failure Scenarios

==== Pod Failure
* **Detection**: Kubernetes liveness probe (10s)
* **Recovery**: Automatic restart (30s)
* **Data Loss**: None (storage backend persists)
* **Client Impact**: Retry with exponential backoff

==== Node Failure
* **Detection**: Kubernetes node controller (40s)
* **Recovery**: Pod rescheduled to healthy node (60s)
* **Data Loss**: None (stateless design)
* **Client Impact**: Transparent with client retry

==== Zone Failure
* **Detection**: Cloud provider health checks
* **Recovery**: Pod scheduled to different zone
* **Data Loss**: None (cross-zone storage replication)
* **Client Impact**: <1 minute downtime

==== Region Failure
* **Detection**: External monitoring
* **Recovery**: Deploy in DR region
* **Data Loss**: <1 minute (replication lag)
* **Client Impact**: 15 minute RTO

=== Data Durability

==== Object Storage Durability
* **S3**: 99.999999999% (11 9's)
* **Azure Blob**: 99.99999999999% (12 9's) with LRS
* **GCS**: 99.999999999% (11 9's)

== Cost Optimization

=== Elastic Scaling with Spot/Preemptible Instances

==== Spot Instance Strategy for Stateless Deployments

ProximaDB's stateless architecture is perfectly suited for spot instance elasticity:

```yaml
# Mixed instance deployment for cost-optimized elasticity
apiVersion: apps/v1
kind: Deployment
metadata:
  name: proximadb-elastic
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
  template:
    spec:
      # Spot instance tolerance
      tolerations:
      - key: "node.kubernetes.io/spot"
        operator: "Equal"
        value: "true"
        effect: "NoSchedule"
      - key: "kubernetes.io/lifecycle"
        operator: "Equal"
        value: "spot"
        effect: "NoSchedule"
      
      # Node affinity for spot instances
      affinity:
        nodeAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            preference:
              matchExpressions:
              - key: "node.kubernetes.io/instance-lifecycle"
                operator: "In"
                values: ["spot"]
          - weight: 50
            preference:
              matchExpressions:
              - key: "node.kubernetes.io/instance-lifecycle"
                operator: "In"
                values: ["on-demand"]
      
      # Graceful termination handling
      terminationGracePeriodSeconds: 30
      
      containers:
      - name: proximadb
        image: proximadb/server:latest
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 15"]
```

==== Spot Instance Interruption Handling

```bash
#!/bin/bash
# Graceful shutdown script for spot termination

# AWS spot termination notice (2 minutes warning)
if curl -s http://169.254.169.254/latest/meta-data/spot/termination-time; then
    echo "Spot instance termination notice received"
    # Signal ProximaDB to stop accepting new connections
    curl -X POST http://localhost:5678/admin/drain
    # Wait for in-flight requests to complete
    sleep 30
    # Graceful shutdown
    kill -TERM $(pidof proximadb-server)
fi

# Azure spot eviction (30 seconds warning)
if curl -s -H Metadata:true "http://169.254.169.254/metadata/scheduledevents?api-version=2019-08-01" | grep -q "Preempt"; then
    echo "Azure spot eviction notice received"
    curl -X POST http://localhost:5678/admin/drain
    sleep 15
    kill -TERM $(pidof proximadb-server)
fi

# GCP preemptible termination (30 seconds warning)
if curl -s -H "Metadata-Flavor: Google" "http://metadata.google.internal/computeMetadata/v1/instance/preempted" | grep -q "TRUE"; then
    echo "GCP preemptible termination notice received"
    curl -X POST http://localhost:5678/admin/drain
    sleep 15
    kill -TERM $(pidof proximadb-server)
fi
```

==== Elastic Scaling Best Practices

1. **Stateless is Key**: ProximaDB's stateless design enables instant recovery
2. **Mix Instance Types**: Diversify to increase spot availability
3. **Set Price Limits**: Use maximum price for critical workloads
4. **Monitor Interruptions**: Track patterns and adjust strategy
5. **Implement Retries**: Client-side exponential backoff
6. **Use Multiple Zones**: Spread across AZs for better availability
7. **Maintain Base Capacity**: Keep 20-30% on-demand for stability
