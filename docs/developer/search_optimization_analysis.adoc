== Index Eviction & Search Fidelity

=== Current Implementation

ProximaDB guarantees 100% search fidelity through a multi-layered fallback strategy that ensures no data is ever missed, even when indexes are evicted from memory.

==== Fidelity Guarantee Architecture
[source]
----
VectorOperationsService.search():
├── WAL.search()        → Always executed (unflushed data)
├── Index.search()      → Conditional (if in memory)
├── Storage.search()    → Always executed (fallback)
└── Merge & Dedupe     → Combines all results
----

==== Key Mechanisms
1. **Persistent Bloom Filters**: Survive index eviction, provide 95% scan reduction
2. **Fallback to Raw Storage**: Automatic when indexes unavailable
3. **Statistics-Based Pruning**: Min/max metadata in SST index blocks
4. **Smart Caching**: IndexNodeCache keeps hot nodes in memory

=== Memory Pressure Handling

When memory pressure occurs:

[cols="1,2,2", options="header"]
|===
| Component | Eviction Behavior | Fidelity Impact

| HNSW Graph
| Evicts cold nodes first
| Falls back to IVF or brute force

| IVF Posting Lists
| Evicts by LRU
| Falls back to centroid scan

| Bloom Filters
| Never evicted (tiny size)
| No impact - always available

| Query Cache
| Evicts by TTL/LRU
| No impact - regenerates
|===

== Filtering Strategy Analysis

=== Distance vs Metadata Filtering Tradeoffs

[cols="2,3,3", options="header"]
|===
| Metric | Distance-Based (Indexes) | Metadata-Based (Filters)

| **Time Complexity**
| O(log N) for HNSW, O(√N) for IVF
| O(1) for bloom, O(log B) for index

| **Space Complexity**
| O(M×N) graph storage
| O(N/8) bloom filter

| **Accuracy**
| 95-99% recall (approximate)
| 100% precision (exact)

| **I/O Pattern**
| Random access (bad for HDD)
| Sequential scan (good for HDD)

| **Cache Efficiency**
| Poor - large working set
| Excellent - compact filters

| **Parallelization**
| Limited by graph structure
| Embarrassingly parallel
|===

=== Optimal Filtering Order

==== Recommendation: Metadata-First Strategy

[source]
----
Optimized Pipeline:
1. Metadata Filtering (Bloom + Statistics)
   └── Reduces search space by 95%
2. Distance-Based Search (on reduced set)
   └── 10-20x faster on smaller dataset
3. Fine-grained Reranking (top-k only)
   └── High precision on final candidates
----

==== Rationale

1. **Cost Efficiency**: Metadata filtering is 100-1000x cheaper than distance computation
2. **Cache Optimization**: Smaller working set after filtering improves cache hits
3. **I/O Reduction**: Eliminates majority of disk reads before expensive operations
4. **Parallelizable**: Metadata filters can process files independently

=== Performance Impact Analysis

[source]
----
Baseline (Distance-First):
├── Load 1M vectors into index: 10GB memory
├── Search 1M vectors: 100ms
├── Filter by metadata: 50ms
└── Total: 150ms, 10GB memory

Optimized (Metadata-First):
├── Apply bloom filter: 1ms
├── Load 50K filtered vectors: 500MB memory

== Design Patterns

=== Fallback Chain Pattern
[source,rust]
----
async fn search_with_fallback(&self, query: Query) -> Result<Vec<SearchResult>> {
    // Try index first (fast path)
    if let Some(index) = self.index_cache.get(&query.collection) {
        if let Ok(results) = index.search(&query).await {
            return Ok(results);
        }
    }
    
    // Fallback to filtered scan (medium path)
    if let Some(bloom) = self.bloom_cache.get(&query.collection) {
        let candidates = bloom.filter_candidates(&query.metadata_filter)?;
        return self.storage.search_filtered(candidates, &query).await;
    }
    
    // Final fallback to full scan (slow path)
    self.storage.search_full(&query).await
}
----

=== Adaptive Filtering Pattern
[source,rust]
----
async fn optimize_filter_order(&self, query: Query) -> FilterPlan {
    let metadata_selectivity = self.estimate_metadata_selectivity(&query);
    let distance_selectivity = self.estimate_distance_selectivity(&query);
    
    if metadata_selectivity < 0.1 {  // Very selective metadata
        FilterPlan::MetadataFirst
    } else if distance_selectivity < 0.01 {  // Very selective distance
        FilterPlan::DistanceFirst  
    } else {
        FilterPlan::Hybrid  // Interleave both
    }
}
----
