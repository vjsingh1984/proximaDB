* **Hardware acceleration**: Auto GPU/SIMD detection
* **Dual storage**: VIPER (columnar) + SST (row-based)
* **SDK-driven**: Client-controlled compression
* **Magic byte validation**: Auto format detection

== System Initialization

image::initialization-sequence.svg[Initialization Sequence, width=900]
_Complete startup sequence showing service creation, dependency injection, and recovery phases_

The initialization follows a careful sequence to avoid circular dependencies:
1. **Core Services Creation**: MetricsCollector and SharedServices
2. **Storage Engine Setup**: Created without CollectionService, then injected
3. **Network Layer**: REST and gRPC servers with unified handlers
4. **Recovery**: Collections from metadata, then vectors from WAL

=== Tiered Storage
```
Memory (bincode) → NVMe (SST/VIPER) → HDD → S3/Cloud
```

* **Memory**: Bincode serialization, <1ms
* **NVMe**: Native formats, bloom filters
* **Cloud**: S3 Express/Standard/Archive
* **Smart promotion**: Only to faster tiers

== Compression System

image::compression-architecture-consolidated.svg[Compression Architecture, width=800]

[NOTE]
====
ProximaDB implements a **two-tier compression architecture** separating transport and storage concerns for optimal performance and flexibility.
====

=== Two-Tier Compression Model

==== Tier 1: Protocol-Level Compression (Transport)
* **Scope**: REST/gRPC transport compression
* **Configuration**: Server-level TOML configuration
* **Default**: Disabled for performance testing and troubleshooting
* **Purpose**: Network bandwidth reduction (when enabled)

```toml
[rest]
enable_compression = false  # Disabled for pure performance

[grpc]
enable_compression = false  # Disabled for troubleshooting
```

==== Tier 2: Collection-Level Compression (Storage)
* **Scope**: Vector data and metadata compression
* **Configuration**: SDK-driven per collection
* **Default**: SDK-specified algorithms and levels
* **Purpose**: Storage efficiency and two-stage search optimization

```python
from proximadb.models import CompressionConfig

config = CompressionConfig(
    algorithm="zstd",              # Storage compression: zstd/lz4/snappy
    level=3,                       # Compression level 1-22 for zstd
    enable_quantization=True,      # Vector quantization for VIPER
    quantization_type="int8"       # int8/pq8/pq4 quantization
)

# Applied per collection
client.create_collection("analytics", compression=config)
```

=== Compression Decision Tree

image::compression-decision-tree.svg[Compression Decision Tree, width=900]
_Decision flow for selecting optimal compression settings based on workload_

=== Two-Stage Search with Compression Integration

1. **Index-Based** (AXIS): Quantized index → FP32 rerank
2. **Column-Based** (VIPER): Quantized column → FP32 column  
3. **Block-Based** (SST): Bloom filter → Decompression cache → Search

[TIP]
====
**Performance Optimization**: The decompression cache eliminates repeated decompression overhead, while protocol compression remains disabled to avoid transport-layer CPU overhead during benchmarking.
====

== Search Optimization

=== Query Planning
1. Retrieve collection metadata
2. Search WAL/memtable (always first)
3. Execute index or scan strategy
4. Merge and deduplicate results

=== Performance Features
* **Bloom filters**: 95% metadata scan reduction
* **Parallel reading**: 3-5x multi-file speedup
* **Early termination**: Stop at k results
* **Query caching**: LRU repeated queries
* **Predicate pushdown**: 60-90% I/O reduction

== Cache System

image::technical-cache-architecture.svg[Cache Architecture, width=900]
_Unified cache architecture with engine integration_

=== Unified Cache Integration
The cache system has been unified across storage engines to eliminate duplication and improve performance:

* **SST Engine**: Uses VectorStore for compressed blocks, IndexNodeCache for indices, BitmapFilterCache for bloom filters
* **VIPER Engine**: Uses MetadataStore for Parquet schemas and column statistics
* **Smart Optimizations**: Bloom filters skipped for cached data, applied only for disk reads
* **Compression-aware**: Caches compressed blocks to reduce memory usage

[cols="1,2,1,1", options="header"]
|===
| Cache | Purpose | Hit Target | Memory

| VectorStore | Vector data, SSTable blocks | >80% | 40%
| QueryCache | Search results | >70% | 25%
| BitmapFilterCache | Bloom filters, bitmaps | >85% | 15%
| IndexNodeCache | Index nodes, SSTable indices | >90% | 15%
| MetadataStore | Parquet schemas, column stats | >95% | 5%
|===
