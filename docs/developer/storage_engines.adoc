| Analytics, batch processing, high compression needs

== SST Engine

=== Hierarchical Architecture

image::sst-format-detail-modular.svg[SST Format, width=900]

The SST engine implements a sophisticated three-stage filtering system:

**Stage 1: File-Level Filtering**
* Global bloom filter (2KB): 85% file skip rate
* Min/max keys and timestamp ranges
* SST1 magic bytes: `0x535354310A1A0A0D`

**Stage 2: Block-Level Filtering**
* Per-block bloom filters (256B): 95% block skip rate
* Metadata statistics for predicate pushdown
* Compression metadata for adaptive decompression

**Stage 3: Record-Level Access**
* Zero-copy deserialization via bytemuck
* Memory-mapped I/O for hot blocks
* MVCC resolution at read time

=== Zero-Copy Compaction

[source,rust]
----
// Direct SST operations without VectorRecord conversion
pub struct SstCompactor {
    pub async fn compact_with_streaming(
        &self,
        input_files: Vec<String>,
        target_level: u8,
    ) -> Result<ZeroCopyCompactionStats> {
        // Phase 1: Create streaming iterators
        let iterators = self.create_sst_direct_readers(input_files).await?;
        
        // Phase 2: K-way merge with MVCC
        let merged = self.k_way_merge_streaming(iterators).await?;
        
        // Phase 3: Direct write with hierarchical blooms
        writer.write_streaming_sst_records(merged).await
    }
}
----

**Performance Benefits:**
* Eliminates double copying for 2000+ vectors per block
* 60% reduction in memory pressure
* 40-60% faster than traditional compaction

== VIPER Engine

=== Columnar Architecture

VIPER leverages Apache Parquet for columnar storage:

* **Compression**: 50-80% storage reduction
* **Predicate Pushdown**: Filter at storage layer
* **Quantization**: Optional INT8/PQ compression
* **Batch Processing**: Optimized for large scans

=== Quantization Strategy

[cols="1,2,2", options="header"]
|===
| Engine | Quantization | Reason

| **VIPER**
| ✅ Recommended
| Columnar format benefits from uniform types

| **SST**
| ❌ Not Recommended
| Row format doesn't benefit, adds complexity
|===

=== Configuration Examples

**SST for Real-time:**
[source,python]
----
config = CollectionConfig(
    name="realtime_stream",
    dimension=768,
    storage_engine="sst",
    compression=CompressionConfig(
        algorithm="lz4",          # Fast
        level=1,                  # Minimal overhead
        enable_quantization=False # Not for SST
    )
)
----

**VIPER for Analytics:**
[source,python]
----
config = CollectionConfig(
    name="analytics_warehouse",
    dimension=1536,
    storage_engine="viper",
    compression=CompressionConfig(
        algorithm="zstd",         # High compression
        level=6,
        enable_quantization=True,
        quantization_type="pq8"   # Product quantization
    )
)
----
