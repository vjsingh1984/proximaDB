== Zero-Copy Operations

=== Streaming Compaction Pipeline

[source,rust]
----
impl SstCompactor {
    /// Zero-copy compaction with hierarchical bloom updates
    pub async fn compact_with_streaming(
        &self,
        input_files: Vec<String>,
        target_level: u8,
    ) -> Result<ZeroCopyCompactionStats> {
        
        // Phase 1: Stream records directly (no VectorRecord conversion)
        let streaming_iterators = self.create_sst_direct_readers(input_files).await?;
        
        // Phase 2: K-way merge with MVCC resolution (SstRecord → SstRecord)
        let merged_records = self.k_way_merge_streaming(streaming_iterators).await?;
        
        // Phase 3: Write with hierarchical blooms and format analysis
        let writer = SstableWriter::new()
            .with_hierarchical_blooms(HierarchicalBloomConfig::for_level(target_level))
            .with_vector_format_analysis(true);
            
        writer.write_streaming_sst_records(merged_records).await
    }
}
----

== ✅ Compression Streaming Architecture (COMPLETE)

ProximaDB's hierarchical SST implementation features a **complete compression streaming pipeline** that provides SDK-driven compression configuration with self-describing block markers for automatic decompression.

=== Compression Flow: Collection Metadata → Block Serialization

The compression configuration flows through multiple layers from collection-level settings to individual block compression:

[source,text]
----
SDK Collection Config → FlushParameters → SST Engine → SstableWriter → DataBlockCompressionConfig → Block Serialization

1. Collection.config.compression (SDK-driven)
   ↓
2. FlushParameters.collection_config.compression 
   ↓
3. SST Engine extracts compression_config
   ↓
4. SstableWriter.with_compression(compression_config)
   ↓
5. DataBlockCompressionConfig creation
   ↓
6. DataBlock.serialize_with_config(&config)
   ↓
7. Self-describing compressed blocks with markers
----

=== Self-Describing Compression Markers

Each compressed block starts with a **compression marker** for automatic decompression detection:

[source,text]
----
Block Format: [MARKER:1][COMPRESSED_DATA:N]

Compression Markers:
• 0x00: MARKER_UNCOMPRESSED (no compression)
• 0x01: MARKER_ZSTD (Zstandard compression)
• 0x02: MARKER_LZ4 (LZ4 compression)
• 0x03: MARKER_SNAPPY (Snappy compression)
• 0x04: MARKER_GZIP (Gzip compression)
• 0x05: MARKER_BROTLI (Brotli compression)
• 0x06: MARKER_BZIP2 (Bzip2 compression)
• 0x07: MARKER_DEFLATE (Deflate compression)
• 0x08: MARKER_XZ (XZ compression)
• 0x09: MARKER_ZLIB (Zlib compression)
• 0x0A: MARKER_LZ4HC (LZ4 High Compression)
• 0x0B: MARKER_LZMA (LZMA compression)
----
