==== Overview

The SDK provides a modular chunking and embedding system with complete separation of concerns. Text chunking and embedding generation are independent operations that can be composed as needed.

NOTE: The SDK is transitioning from the old mixed implementation to the new separated architecture. Currently:
- `chunking.py` - Legacy implementation (being phased out)
- `chunking_refactored.py` - Clean implementation with separation of concerns (use for new code)
- `chunking_strategies/` - Strategy pattern implementation (recommended approach)
The `_refactored` suffix will be removed in the next major release.

==== Architecture

**Three-Step Process:**

[source,python]
----
from proximadb.chunking_refactored import (
    TextChunker, ChunkingConfig, ChunkingStrategy, create_vector_records
)
from proximadb.embedding_providers import get_embedding_provider

# 1. Chunk text (no embeddings involved)
chunker = TextChunker(ChunkingConfig(
    strategy=ChunkingStrategy.SEMANTIC,
    chunk_size=1000,
    chunk_overlap=100
))
chunks = chunker.chunk_text(text, source_id)

# 2. Generate embeddings (no chunking involved) 
provider = get_embedding_provider("fastembed")
embeddings = provider.embed_texts([chunk.text for chunk in chunks])

# 3. Create vector records (combine results)
records = create_vector_records(
    chunks=chunks,
    embeddings=embeddings,
    collection_metadata={"doc_type": "manual"},
    filterable_fields=["doc_type", "source_id"]
)
----

==== Chunking Strategies

Each strategy is in its own module (`proximadb.chunking_strategies`):

[cols="2,3,2"]
|===
|**Strategy** |**Description** |**Best Use Case**

|`sliding_window`
|Fixed-size overlapping chunks
|General text, logs, code

|`sentence`
|Respects sentence boundaries
|Articles, documentation

|`paragraph`
|Preserves paragraph structure
|Books, formatted documents

|`semantic`
|Topic-aware chunking (text analysis)
|Technical docs with sections

|`recursive`
|Tries paragraph → sentence → sliding
|Unknown or mixed content
|===

**Using Strategies:**
[source,python]
----
# Via factory
from proximadb.chunking_strategies import get_chunking_strategy

strategy = get_chunking_strategy(
    "semantic",
    chunk_size=1000,
    preserve_code_blocks=True
)
chunks = strategy.chunk(text, source_id)

# Via TextChunker
chunker = TextChunker(ChunkingConfig(
    strategy=ChunkingStrategy.PARAGRAPH,
    chunk_size=500,
    min_chunk_size=100
))
----

The SDK implements a sophisticated metadata layering system that separates different types of metadata for optimal performance and flexibility.

**Metadata Layers:**

1. **Core Chunking Metadata** (Automatically generated by chunking strategies):
   - `chunk_id`: Unique identifier for the chunk
   - `chunk_index`: Position within the source document
   - `start_pos` / `end_pos`: Character positions in original text
   - `chunk_length`: Size of the chunk in characters
   - `chunking_strategy`: Strategy used (sliding_window, semantic, etc.)
   - `source_id`: Reference to the source document
   - `text_preview`: First 100 characters of chunk text

2. **User Metadata** (Provided by developers):
   - Any custom fields like `category`, `author`, `date`, `tags`
   - Business-specific attributes
   - External references and IDs

3. **System Metadata** (Added during processing):
   - `embedding_dimension`: Size of the embedding vector
   - Processing timestamps
   - Version information

**Filterable vs Non-Filterable Separation:**

[source,python]
----
# The SDK automatically separates metadata for optimal storage
records = create_vector_records(
    chunks=chunks,
    embeddings=embeddings,
    collection_metadata={
        "category": "documentation",  # Will be filterable
        "author": "John Doe",         # Will be filterable
        "internal_notes": {...},      # Complex object - non-filterable
        "processing_stats": {...}     # Complex object - non-filterable
    },
    filterable_fields=["category", "author", "date", "source_id"]
)

# Result in each VectorRecord:
{
    "id": "doc_123_chunk_0",
    "vector": [...],
    "metadata": {
        # Filterable fields (high-cardinality, simple types)
        "source_id": "doc_123",
        "chunk_index": 0,
        "category": "documentation",
        "author": "John Doe",
        
        # Non-filterable fields grouped together
        "additional_metadata": {
            "internal_notes": {...},
            "processing_stats": {...},
            "text_preview": "ProximaDB is a high-performance..."
        }
    }
}
----

**Adding Custom Metadata:**

[source,python]
----
# Method 1: During chunking (applies to all chunks)
chunks = chunker.chunk_text(
    text=document,
    source_id="doc_123",
    base_metadata={
        "department": "engineering",
        "confidentiality": "public",
        "version": "2.0"
    }
)

# Method 2: During record creation (more control)
records = []
for i, (chunk, embedding) in enumerate(zip(chunks, embeddings)):
    # Add chunk-specific metadata
    custom_metadata = {
        "section": detect_section(chunk.text),
        "has_code": contains_code(chunk.text),
        "language": detect_language(chunk.text)
    }
    
    record = VectorRecord(
        id=f"{source_id}_chunk_{i}",
        vector=embedding,
        metadata={
            **chunk.metadata,      # Core metadata
            **custom_metadata,     # Your metadata
            **global_metadata      # Collection-wide metadata
        }
    )
    records.append(record)

# Method 3: Using the convenience function
records = chunk_and_embed_text(
    text=document,
    source_id="doc_123",
    embedding_provider=provider,
    metadata={
        "project": "proximadb-docs",
        "last_updated": "2025-08-05",
        "tags": ["vector-db", "tutorial"]
    },
    filterable_fields=["project", "last_updated", "tags"]
)
----

**Best Practices for Metadata Design:**

1. **High-Cardinality Fields**: Make filterable (>10% unique values)
   - Good: `user_id`, `document_id`, `timestamp`
   - Bad: `is_active`, `status` (if only 2-3 values)

2. **Complex Objects**: Store as non-filterable
   - Nested dictionaries, lists, JSON objects
   - Large text fields, descriptions
   - Computed statistics

3. **Performance Optimization**:
   - Limit filterable fields to what you'll actually filter on
   - Use simple types (str, int, float, bool) for filterable fields
   - Consider field cardinality before making filterable

4. **Metadata Inheritance**:
   - Collection-level defaults
   - Document-level metadata (all chunks inherit)
   - Chunk-specific overrides

[source,python]
----
# Example: Hierarchical metadata
collection_defaults = {"environment": "production"}
document_metadata = {"source": "user_manual", "version": "2.0"}
chunk_metadata = {"page": 42, "section": "API Reference"}

# Final metadata combines all levels with proper precedence
final_metadata = {
    **collection_defaults,
    **document_metadata,
    **chunk_metadata,
    **auto_generated_metadata  # Core chunking metadata
}
----

==== Performance Best Practices

**1. Cardinality Analysis**

[source,python]
----
# Analyze before designing schema
def analyze_field_cardinality(data, field):
    unique_values = len(set(item[field] for item in data))
    total_items = len(data)
    cardinality_ratio = unique_values / total_items
    
    if cardinality_ratio > 0.1:  # >10% unique
        return "FILTERABLE"
    else:
        return "EXTRA_METADATA"
----

**2. Batch Processing**

[source,python]
----
# Process multiple documents efficiently
async def batch_ingest(documents, batch_size=100):
    for i in range(0, len(documents), batch_size):
        batch = documents[i:i + batch_size]
        
        # Prepare all texts
        texts = [doc["content"] for doc in batch]
        
        # Single embedding call
        embeddings = await embed_batch(texts)
        
        # Process with metadata
        for doc, embedding in zip(batch, embeddings):
            records = prepare_vector_records(...)
            await client.insert_vectors(collection, records)
----

**3. Query Optimization**

[source,python]
----
# Use specific filters to reduce search space
# Good: Reduces to 5% of data
filter = {
    "category": "electronics",
    "brand": "Apple",
    "price": {"$gte": 500, "$lte": 1500}
}

# Avoid: Doesn't reduce search space
filter = {"in_stock": True}  # If 99% are in stock
----

**2. Time-series with Vectors:**

[source,python]
----
# Time-based partitioning
def get_collection(timestamp):
    return f"events_{timestamp.strftime('%Y_%m')}"

# Query across time range
results = []
for month in date_range(start, end):
    collection = get_collection(month)
    partial = client.search(
        collection,
        query_vector,
        filter={"timestamp": {"$gte": start, "$lte": end}}
    )
    results.extend(partial)
----

class HybridSearch:
    def search(self, query, alpha=0.7):
        # Vector search
