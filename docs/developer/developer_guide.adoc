==== Overview

The SDK provides a powerful chunking and metadata system designed for optimal performance across VIPER (columnar) and SST (row-based) storage engines.

==== Design Principles

**1. Metadata Separation**

[cols="2,3,2"]
|===
|**Type** |**Description** |**Examples**

|**Filterable**
|High cardinality fields that users query on
|`product_id`, `user_id`, `category`, `price`

|**Extra**  
|Low cardinality or rarely queried fields
|`currency`, `api_version`, `source_system`
|===

**2. Performance Impact**

* VIPER: Only filterable fields are indexed (60-90% I/O reduction)
* SST: All fields queryable but separation ensures portability

==== Using prepare_vector_records()

The `prepare_vector_records` function is the core of the SDK's chunking system:

[source,python]
----
from proximadb.chunking import prepare_vector_records

# Define custom enrichment
def enrich_chunk(chunk, index):
    """Add derived metadata to each chunk"""
    text = chunk["text"].lower()
    return {
        "has_code": "```" in chunk["text"],
        "section": "intro" if index == 0 else "body",
        "complexity": assess_complexity(text)
    }

# Convert chunks to optimized vector records
vector_records = prepare_vector_records(
    embedding_response,
    source_id="DOC123",
    source_type="manual",
    source_metadata={
        # Document-level metadata
        "author": "John Doe",
        "version": "2.0",
        "language": "en"  # Low cardinality → extra_metadata
    },
    chunk_metadata_fn=enrich_chunk,
    filterable_fields=["author", "section", "has_code"]
)
----

==== Performance Best Practices

**1. Cardinality Analysis**

[source,python]
----
# Analyze before designing schema
def analyze_field_cardinality(data, field):
    unique_values = len(set(item[field] for item in data))
    total_items = len(data)
    cardinality_ratio = unique_values / total_items
    
    if cardinality_ratio > 0.1:  # >10% unique
        return "FILTERABLE"
    else:
        return "EXTRA_METADATA"
----

**2. Batch Processing**

[source,python]
----
# Process multiple documents efficiently
async def batch_ingest(documents, batch_size=100):
    for i in range(0, len(documents), batch_size):
        batch = documents[i:i + batch_size]
        
        # Prepare all texts
        texts = [doc["content"] for doc in batch]
        
        # Single embedding call
        embeddings = await embed_batch(texts)
        
        # Process with metadata
        for doc, embedding in zip(batch, embeddings):
            records = prepare_vector_records(...)
            await client.insert_vectors(collection, records)
----

**3. Query Optimization**

[source,python]
----
# Use specific filters to reduce search space
# Good: Reduces to 5% of data
filter = {
    "category": "electronics",
    "brand": "Apple",
    "price": {"$gte": 500, "$lte": 1500}
}

# Avoid: Doesn't reduce search space
filter = {"in_stock": True}  # If 99% are in stock
----

**1. Multi-tenant SaaS:**

# Tenant isolation pattern
filterable_fields = [

    "resource_type",
    "access_level"

# Always include tenant filter
results = client.search(

----

**2. Time-series with Vectors:**

[source,python]
----
# Time-based partitioning
def get_collection(timestamp):
    return f"events_{timestamp.strftime('%Y_%m')}"

# Query across time range
results = []
for month in date_range(start, end):
    collection = get_collection(month)
    partial = client.search(
        collection,
        query_vector,
        filter={"timestamp": {"$gte": start, "$lte": end}}
    )
    results.extend(partial)
----
