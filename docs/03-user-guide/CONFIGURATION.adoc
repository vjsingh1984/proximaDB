== Overview

ProximaDB uses TOML configuration files. Example configs are in `config/` (e.g., `config/config.toml`, `config/simple-config.toml`). The server binds REST on port 5678 by default; gRPC listens on 5679 (multi-server).

== Top-Level Structure (maps to src/core/config.rs)

[source,toml]
----
[server]         # ServerConfig
[storage]        # StorageConfig
[consensus]      # ConsensusConfig (reserved)
[api]            # ApiConfig
[monitoring]     # MonitoringConfig
# Optional blocks
[network]        # NetworkConfig
[tls]            # TlsConfig
[hardware]       # HardwareConfig
----

== Server

[source,toml]
----
[server]
node_id = "node-1"
bind_address = "127.0.0.1"   # REST bind address
port = 5678                  # REST port (gRPC fixed at 5679)
data_dir = "./data"
grpc_port = 5679             # Optional convenience; ApiConfig takes precedence
----

TLS (same REST port, optional):

[source,toml]
----
[tls]
enabled = false
cert_file = "/path/to/cert.pem"
key_file  = "/path/to/key.pem"
bind_interface = "0.0.0.0"   # optional
----

== Storage

[source,toml]
----
[storage]
mmap_enabled = true
metadata_url = "file://./metadata"
cache_size_mb = <cache_size_mb>

[[storage.storage_locations]]
url = "file://./data"   # or s3://bucket/path
weight = 1
tags = ["local"]

# Write-ahead log and engine configs (selected fields)
# See code for full fields: SstConfig, ViperConfig, CompactionConfig, FilesystemOptimizationConfig
sst_config = { block_size_kb = <block_size_kb>, compression = "zstd", data_directory = "./data/sst" }
viper_config = { row_group_size = <row_group_size>, compression = "zstd", data_directory = "./data/viper" }
----

== Environment Overrides

All keys can be overridden via environment variables using your loader. Common examples:

[source,bash]
----
export PROXIMADB_SERVER_PORT=8080
export PROXIMADB_STORAGE_METADATA_URL=file:///var/lib/proximadb/meta
export PROXIMADB_TLS_ENABLED=true
----

== Notes
- REST port is `server.port`; gRPC is started by the multi-server on 5679.
- Index-specific tuning (HNSW/IVF/etc.) is configured per engine or service layer, not in this file.
- For concrete examples, see `config/config.toml` and `config/simple-config.toml`.

== Hardware-Specific Configuration

=== CPU-Only Systems

[source,toml]
----
[performance]
enable_gpu = false
enable_simd = true
num_search_threads = 0  # Use all cores
----

=== GPU-Accelerated Systems

[source,toml]
----
[performance]
enable_gpu = true
gpu_memory_fraction = 0.9
# Larger batches for GPU
prefetch_size = 256
----

=== ARM/NEON Systems

[source,toml]
----
[performance]
enable_simd = true  # Will use NEON
enable_gpu = false
----

== Collection-Specific Configuration

Configure individual collections via API:

[source,python]
----
client.create_collection(
    name="custom_collection",
    dimension=<dimension>,
    config={
        "storage_engine": "VIPER",
        "compression": "zstd",
        "quantization": {
            "enabled": True,
            "type": "PQ",
            "bits": <bits>
        },
        "index": {
            "type": "HNSW",
            "M": <M>,
            "ef_construction": <ef_construction>
        },
        "cache": {
            "enabled": True,
            "size_mb": <size_mb>
        }
    }
)
----

== Docker Configuration

.Dockerfile environment variables
[source,dockerfile]
----
ENV PROXIMADB_SERVER_REST_PORT=5678
ENV PROXIMADB_STORAGE_DATA_DIR=/data
ENV PROXIMADB_PERFORMANCE_ENABLE_GPU=true
----

.docker-compose.yml
[source,yaml]
----
version: '3.8'
services:
  proximadb:
    image: proximadb/proximadb:latest
    ports:
      - "5678:5678"
      - "5679:5679"
    volumes:
      - ./config:/config
      - ./data:/data
    environment:
      - PROXIMADB_CONFIG=/config/server.toml
      - PROXIMADB_PERFORMANCE_ENABLE_GPU=false
----

== Kubernetes Configuration

[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: proximadb-config
data:
  server.toml: |
    [server]
    rest_port = 5678
    grpc_port = 5679
    
    [storage]
    data_dir = "/data"
    
    [performance]
    enable_simd = true
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: proximadb
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: proximadb
        image: proximadb/proximadb:latest
        volumeMounts:
        - name: config
          mountPath: /config
        - name: data
          mountPath: /data
      volumes:
      - name: config
        configMap:
          name: proximadb-config
----

== Validation

Validate configuration before starting:

[source,bash]
----
./proximadb-server --config config/server.toml --validate

# Output:
# ✓ Configuration valid
# ✓ Data directory accessible
# ✓ Ports available
# ✓ Memory requirements met
----

== Best Practices

. *Start with defaults* - ProximaDB has sensible defaults
. *Monitor and adjust* - Use metrics to guide configuration
. *Test changes* - Benchmark before and after changes
. *Version control* - Keep configurations in git
. *Document changes* - Note why each setting was changed
