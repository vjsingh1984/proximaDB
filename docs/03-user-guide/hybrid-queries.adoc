== Hybrid (SKS) Queries
:toc:
:icons: font

Hybrid queries combine vector similarity with graph traversal to assemble richer context.

=== Current Paths

- Two‑step composition (recommended today):
  1) Perform a vector search (REST `/api/v1/search` or gRPC `VectorSearch`).
  2) Use result IDs as starting points for a graph traversal (REST `/api/v1/graph/traverse` or gRPC `TraverseGraph`).

=== gRPC Proto

- `proximadb.v1.GraphService/ExecuteHybridQuery` exists in the proto with `HybridSearchRequest/Response`.
- Server handler is staged; end‑to‑end examples will be added when enabled.

=== Example (Two‑Step Composition)

1) Vector search (REST):
----
curl -X POST http://localhost:5678/api/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"collection_id":"docs","queries":[{"vector":[0.1,0.2,...]}],"top_k":10}'
----

2) Graph traversal (use a top result id as start):
----
curl -X POST http://localhost:5678/api/v1/graph/traverse \
  -H 'Content-Type: application/json' \
  -d '{"start_node_id":"doc_123","max_depth":2,"algorithm":"BFS"}'
----

=== EXPLAIN

- `POST /api/v1/sql/explain` returns orchestration‑level plans with vector/graph hints.
