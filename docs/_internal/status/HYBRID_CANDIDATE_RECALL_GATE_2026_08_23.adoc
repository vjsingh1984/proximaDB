= Hybrid candidate-recall gate — 2026-08-23

== Decision

The candidate-generation hypothesis passes, but the selection policy fails. Keep held-out test
sealed and keep the current retrieval/reranking defaults unchanged.

On NFCorpus development, the complete union of canonical natural-language BM25 top 100 and exact
BGE-base-v1.5 dense top 100 raises candidate-pool recall from dense Recall@100 `0.347232` to union
Recall@<=200 `0.373375`. The paired delta is `+0.026143` (`+7.53%`, 95% interval `+0.021154` to
`+0.031727`), with 121 query wins, no losses and 203 ties.

That larger ceiling does not become final quality when the pinned MiniLM cross-encoder globally
orders the union. Final Recall@100 falls to `0.313560`, a delta of `-0.033672` versus dense
(`-9.70%`, interval `-0.045557` to `-0.022022`). NDCG@100 falls from `0.322261` to `0.301350`, a
delta of `-0.020912` (`-6.49%`, interval `-0.031913` to `-0.010064`). Both regressions are
statistically resolved. The model therefore remains an opt-in precision reranker for the measured
BM25-prefix policy; it is not promoted to a global hybrid-candidate selector.

== Working-backwards protocol

Only the 324-query development split was used. Held-out was not opened after the development
promotion criteria failed.

* The lexical leg is the sealed production-equivalent canonical natural-language BM25 source run,
  complete at 100 sources/query.
* The dense leg is the sealed exact normalized-float32 BGE-base-v1.5 source-direct run, complete at
  100 sources/query.
* Equal-weight RRF with the production default `k=60` provides deterministic, score-scale-independent
  ordering. With output depth 200 it retains every unique member of both legs; RRF score is not used
  as a calibrated relevance claim.
* Every input run is checked against an explicit manifest: path, SHA-256, row count, query count,
  optional source granularity and advertised depth must match before output is written.
* The same pinned `cross-encoder/ms-marco-MiniLM-L6-v2` revision from the prior gate scores every
  unique union source. Query-aware title-propagated body windows are max-reduced per source.
* Comparisons use 10,000 paired query bootstraps at seed 17. Cross-depth candidate-pool comparison
  records baseline `k=100` and candidate `k=200` explicitly instead of relabeling either metric.

The complete union's full-pool Recall@<=200 is `0.373375`. The table's union Recall@100 describes
the first 100 RRF-ordered members, not the full membership ceiling. Global reranking preserves the
full pool exactly: Recall@<=200 remains `0.373375`; its failure is choosing the final top 100.

A development-only BM25-weight grid against dense weight 1.0 also rejected a forced 100-source
fusion claim. Weight 0.5 reached Recall@100 `0.349198`, but its paired interval versus dense
`[-0.001692, +0.005722]` includes zero and its NDCG means were lower. Prefix-cascade depths
10/20/50 were explored from the cached scores; the best non-regressing mean was dense+r10 NDCG@10
`0.346133`, but its interval `[-0.004688, +0.010786]` also includes zero. These arms did not unlock
held-out and did not justify a new product seam.

== Zero-truncation and work

The complete development union contains 57,306 query-source pairs. Source splitting produced
64,744 actual model windows and 22,210,265 input tokens. Maximum actual pair length is exactly 512
tokens and the score manifest asserts zero truncation. PyTorch selected MPS. The host was running
concurrent Rust compilation, so elapsed time is provenance only and no latency, throughput or cost
claim is made.

== Architectural finding

Candidate generation and candidate selection are separate contracts. The union proves lexical and
dense retrieval are complementary, but a larger candidate set has customer value only if a bounded
selector can preserve that added relevance in the requested output depth. A passage reranker that
improves a BM25 prefix cannot be assumed to calibrate globally against dense and lexical candidates.

Possible causes such as training-domain mismatch, maximum-window length bias and heterogeneous
candidate calibration are hypotheses, not findings. The next selector must beat the strongest
available dense control on development NDCG and Recall with paired intervals before held-out,
ONNX export, catalog registration or default-on work. Returning up to 200 candidates is a separate
product/economics policy and must charge its downstream reranker and generator token work.

== Harness changes

* `fuse_source_runs.py` validates optional input manifests, reports candidate-depth percentiles and
  can require exact `top_k` coverage before atomically writing output.
* `rerank_source_candidates.py` supports scoring and materializing every candidate in variable-depth
  query pools while preserving identity and zero-truncation checks.
* `compare_retrieval_runs.py` supports explicit `baseline_k` and `candidate_k`; same-depth `k`
  remains backward compatible.
* TDD covers sealed-run mismatch, incomplete-depth failure, deterministic depth reporting,
  variable-depth full reranking and cross-depth paired comparison.
