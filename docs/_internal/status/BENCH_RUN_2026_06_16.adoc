== Results and bench→claim mapping

=== object_economy_e2e_latency — MEASURED (promoted)

`cargo bench --bench bench_vector_object_economy_e2e` (10000 vectors, dim 128, top_k 10):

* Cold query latency (fresh engine): min 20.64 ms, mean 20.86 ms, p50 20.83 ms, p99 21.12 ms
* Warm query latency (same engine): min 19.59 ms, mean 19.94 ms, p50 19.97 ms, p99 20.44 ms; effective QPS 50
* Setup: insert 9 ms, flush 117 ms, on-disk 3.37 MB

This genuinely measures the object-economy route's end-to-end cold/warm query
latency, so the ledger entry is promoted to `measured`.

=== vector_search_latency / qps_throughput — stays UNVERIFIED

`cargo bench --bench bench_04_storage_unified` measures per-engine search latency
at **128 vectors** (e.g. SST pure search ~1.44 ms, filtered ~1.42 ms), not the
"~8 ms p99 over 10M-vector HNSW" / "100K+ QPS" claims. Scale and engine differ;
no QPS-at-scale measurement. A real 10M-scale HNSW recall/latency/QPS bench is
needed.

=== ingest_throughput — stays UNVERIFIED

`cargo bench --bench bench_08_quantization_sst` measures the quantization-speed
kernel (dim 128 ~1.02 ms … dim 1536 ~10.74 ms) and progressive-search latency
(1024 → ~6.6 µs), not an end-to-end "~125K vectors/sec" ingest throughput.

=== hybrid_search_latency — stays UNVERIFIED

`cargo bench --bench bench_21_hybrid_search_fusion` measures the RRF
fusion-merge kernel (k=10 → 1.77 µs, k=50 → 8.46 µs, k=100 → 17.27 µs), not the
"~8 ms" end-to-end vector+BM25 hybrid search latency.

=== recall_at_10 — stays UNVERIFIED

`bench_23_recall_at_k` was an orphan file (no `[[bench]]` entry); it is now
registered and runnable. But it benchmarks the recall *computation* utility over
synthetic vectors + simulated approximate results — it does **not** measure the
ANN engine's actual Recall@10. A real index-vs-ground-truth recall bench is needed.

== Takeaway

The run substantiated one claim (object-economy e2e latency) and revealed that the
remaining headline claims (search latency, ingest, hybrid, recall@10, QPS) lack a
benchmark that measures the *claimed* end-to-end metric at the *claimed* scale.
The ledger notes are corrected accordingly; building those e2e benches is the
follow-up to move them to `measured`.
