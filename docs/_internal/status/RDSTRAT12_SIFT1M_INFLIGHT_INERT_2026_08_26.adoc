= TD-RDSTRAT-12 §3: PROXIMADB_READ_RANGES_INFLIGHT is INERT for SIFT1M IVF probe workload

**Status:**Measured null result — hypothesis falsified by evidence

**Date:**2026-08-26

**Claim:**Raising `PROXIMADB_READ_RANGES_INFLIGHT` from 0→32 improves SIFT1M cold-read p50 latency by ≥2× while keeping GET count and bytes read equal between baseline and treatment.

**Actual Result:**NO MEASURABLE EFFECT — p50 latencies are essentially identical (49.02ms baseline vs 49.11ms treatment), GET counts identical (13.80 vs 13.80), bytes identical (46.18MB vs 46.18MB), fetch rounds identical (4.61 vs 4.61).

== Acceptance Criteria

* [ ] PASS: cold p50 improves ≥2× at equal GET count and bytes read
* [x] FAIL: No measurable difference between baseline and treatment

== Root Cause Analysis

The `PROXIMADB_READ_RANGES_INFLIGHT` env gate is **inert** for the SIFT1M IVF probe workload because:

1. **The IVF probe path does not use `read_ranges_prefetch()`** — The env gate only exists in `proximadb-storage-filesystem-types/src/lib.rs:795` inside the `read_ranges_prefetch()` function
2. **The IVF probe has its own fetch mechanism** — `src/storage/engines/sst/segment_format.rs:coarse_probe_survivors()` (lines 2487-2701) issues sequential `fs.read_range()` calls in a for loop (lines 2619-2669)
3. **Zero production callers** — `grep` confirmed `read_ranges_prefetch()` has zero production callers outside its own test file (`read_ranges_prefetch_tests`)
