== 1. Metering — the blocker, its root cause, and the fix

=== What the bake originally found (blocker)

A canonical document write + `force_flush` + search moved all four per-tenant consumption families
by *0* — on BOTH the `/metrics/prometheus` endpoint AND the in-process default registry where the
counters live. Two compounding gaps:

. *Export gap.* `/metrics/prometheus` (`src/network/metrics_service.rs`) assembled the
  `MetricsCollector` system metrics + the precision/rank/wal-scan sub-registries, but never gathered
  prometheus's *default global registry* — where `src/metrics/consumption_metrics.rs` registers the
  per-tenant families via `register_*_vec!`. They were registered-but-never-scraped.
. *Write-path instrumentation gap.* The vector memtable→object-store flush recorded no per-tenant
  write op/bytes (only the warehouse *parquet* write and PAX *reads* were instrumented). Compounding
  this, `force_flush_collection` is a no-op for materialization (the flush coordinator owns it), so
  the segment write — and thus any metering — never happened during the original test window.

=== The fix (two OSS-side, neutral-telemetry changes)

. *Close the export gap* — `prometheus_metrics_endpoint` now appends `prometheus::gather()` (the
  default registry) to the scrape output. Sub-registries use their own `Registry`, so nothing is
  double-counted; the system exporter's `proximadb_storage_bytes` does not collide with the
  consumption `proximadb_storage_bytes_seconds`. This also surfaces ~15 other previously-invisible
  neutral families (http requests, route metrics, …) — a strict observability improvement.
. *Close the write-path gap* — `materialize_collection` (`src/storage/flush_materializer.rs`), the
  single tenant-aware flush funnel through which *every* engine's (`SST`/`HELIX`/`NOVA`/`VIPER`)
  memtable→object-store segment write passes, now emits
  `record_object_store_op(tenant, "flush_write")` +
  `record_object_store_write_bytes_by_tier(tenant, "hot", bytes)` after `engine.flush()`. Metering at
  this ONE funnel (rather than at each per-engine PAX write site) is DRY and engine-neutral, mirrors
  the read side's `fetch_pax` metering, and attributes to the flush plan's *catalog-resolved* owning
  tenant (`proximadb_tenant::tenant_id_of`) — per-tenant-correct by construction, not a hardcoded id.

*Co-design / OSS-boundary posture.* Both changes emit NEUTRAL usage telemetry only — byte/op counts
attributed by `tenant_id`, no pricing, no $/unit weights, no cloud-cost constants. Applying policy
weights to these dimensions is the commercial *anvaiops* control plane's concern, never OSS code
(the OSS/commercial boundary held; `check_workspace_boundaries.py` + `check-layering.sh` pass). The
metering sits at the I/O (flush) boundary carrying `TenantContext`, moving the KIU/KSU write-side
dimensional cost term from invisible to observable.

=== Re-measured evidence

----
metering.registry.object_store_ops_delta=1
metering.registry.write_bytes_by_tier_delta=64828
metering.endpoint.object_store_ops_delta=1
metering.endpoint.write_bytes_by_tier_delta=64828
metering.per_tenant_delta_observable_in_registry=true
metering.per_tenant_delta_observable_on_endpoint=true
----

The test drives a real materialization via the shutdown flush (`StorageEngine::stop` →
`flush_memtable_to_storage` → `materialize_collection`) inside `restart()`; the default registry is
process-global, so the counters survive the in-process restart and are read back after it. The
≈64 KB write bytes come from materializing the 200 vector-bearing REST documents (dim 8). The
gRPC arm of the test creates *vectorless* (metadata-only) documents, which correctly produce no
vector segment (0 write bytes) — so the write-billing equivalence claim is demonstrated on the
vector-bearing path; a vectorless document legitimately bills no KSU segment write.

== 2. ANN recall + vectorless exclusion (PASS)

----
recall.mean_at_10=1.0000
recall.n_embedded=300 n_queries=20 dim=32 ratchet=0.9
recall.empty_results=0
recall.vectorless_leaks_into_ann=0 (n_vectorless=30)
recall.vectorless_gettable_by_id=true
----

Documents ingested via REST v2 `/documents` with SDK vectors on a *canonical-routed* collection are
ANN-searchable through the shared store at mean recall@10 = 1.000 vs the in-test brute-force f32
cosine baseline (ratchet floor 0.90). 30 metadata-only documents created via gRPC converge on the
store, are excluded from ANN (0 leaks), and remain gettable by id. Criterion 2 satisfied.

== 3. Single-store / no double GB-month (PASS, with caveat)

----
single_store.total_data_dir_bytes=91260
single_store.document_wal_bytes_total=0
single_store.document_wal_nonempty_files=0
----

A canonical-routed collection (200 docs, dim 8) wrote *0* bytes into any `document_wal` path; all
91,260 bytes are under the shared vector store. The converged body is stored *once*.

CAUTION: *Legacy-contrast caveat.* The gate-OFF gRPC `CreateDocument` writes produced 0 on-disk
`document_wal` bytes too, so the on-disk contrast "legacy uses document_wal, canonical does not" is
*inconclusive* on this path — `DocumentService` appears to run WAL-less (in-memory `DashMap`) in the
default in-process config. The canonical single-store fact (0 `document_wal` bytes) still stands.

== Cutover recommendation

*All four bake criteria pass; proceed with the phased rollout.* Enable per-collection on a real
workload, watch metering / recall / GB-month in production telemetry, widen to `all`, then flip
`doc_canonical_vector_enabled` default-ON behind a kill-switch (keep the legacy read-fallback until
every collection is migrated). Remaining follow-ups (NOT cutover blockers):

. *Tenant attribution audit before widening.* The write meter attributes to
  `proximadb_tenant::tenant_id_of(catalog_meta)`; confirm production catalogs carry the real owning
  tenant for canonical document collections (unset ⇒ "default").
. *100k-scale projection-cost test* against `CANONICAL_DOC_SCAN_LIMIT` (criterion 4 at real scale).
. *Access tier* is billed as `hot` (the write-time default); when tiered flush/compaction lands,
  thread the real `ObjectAccessTier` into the meter instead of the literal.
. *KOU/read-side billing* for document reads is unchanged here (reads served from memtable/cache in
  these tests emit no `fetch_pax`); covered where the object-store read path is exercised.
