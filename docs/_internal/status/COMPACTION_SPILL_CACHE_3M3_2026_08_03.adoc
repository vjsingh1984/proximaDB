= Deterministic spill + disk-cache promotion — BIGANN 3.3M (2026-08-03)

== Purpose

Validate the default-OFF local-spill executor and its write-time persistent-
cache promotion on the production Azure filesystem path over Azurite. The run
must consolidate a morsel rejected by the 5 GiB in-memory ceiling, preserve the
0.98 recall ratchet, and avoid paying object GETs for Region A/B immediately
after publication and after a process restart.

== Compaction and resource result

The qualifying spill merged four L1 inputs into one L2 output:

[cols="1,1"]
|===
|Input |690,242,135 bytes / 2,580,000 rows
|Output |710,652,519 bytes / 2,580,000 rows
|Wall time |74.198 seconds
|Largest ranged input read |1,806,336 bytes
|Live scratch peak delta |5,171,175,625 bytes = **7.492x input**
|Scratch reservation |6,902,421,350 bytes = 10x input
|===

The final measured geometry contained two layout-v3 L2 segments: 2.58M and
720K rows, each with 100 non-empty IVF cells. Total bytes were 903,573,016 and
the WAL reported zero unflushed bytes.

The whole process started at 3,415,212,032 bytes RSS and peaked at
11,927,437,312 bytes, a delta of 8,512,225,280 bytes. This is deliberately
reported as a process observation, **not** attributed to the 512 MiB spill
working set: ingest-era flushes, in-memory L0/L1 compactions, WAL state, caches,
allocator retention, and a later admitted spill overlap the sampling window.
TD-COMPACT-11 therefore remains open for an isolated per-task/cross-collection
memory proof.

The completed spill logged `seeded_to_disk=true include_survivors=true` after
publication. Region A and B object bytes were zero in both cached phases. The
scratch tree returned to a 4 KiB owner/lease skeleton after shutdown, including
cancellation of a later admitted consolidation. Final Azurite inventory had
only the two authoritative PAX segments, warm manifest, and WAL manifests; no
`__compact` or intermediate-run object remained.

|===

At Azure Hot's $0.005/10K read-operation assumption, the operation-only COGS
are $2.49/M queries after write, $0.585/M for disk-warm queries, and $24.345/M
when deliberately object-cold. At a $50/M KRU price those correspond to 95.0%,
98.8%, and 51.3% operation-only gross margins before compute, disk, and other
COGS. The result supports the cache-promotion mechanism; it does not by itself
set a commercial rate card.

== Interpretation and remaining gates

* The D1/D2/D6 GET targets pass: first-after-write is at most 5 and disk-warm
  is at most 10, with recall above 0.98 in every phase.
* `nprobe=15` is a measured two-segment point, not a replacement for the
  checked-in four-scale single-segment power law. A query-only 100-query control
  on the prior two-segment corpus measured recall 0.990 and 48.50 GET/query.
* The original 50 ms latency aspiration is not met: disk-warm p50 is 58.56 ms
  and object-cold Azurite p50 is 345.07 ms. Azurite latency is local-emulator
  evidence, never an Azure WAN claim.
* A second whole-level spill was admitted while the harness observed a stable
  two-segment layout and was cancelled by the phase restart. Cleanup succeeded,
  but its admission explains why the sampled terminal reservation gauges show
  512 MiB RAM and 9,035,730,160 scratch bytes after the qualifying spill had
  already completed.
* The log contains pre-existing non-fatal Azurite missing-staging-prefix cleanup
  warnings and catalog precision-resolver misses for `default.1`; neither
  changed row count, recall, or final object geometry, but they are not erased
  from the evidence.
* ENOSPC, checksum-corruption, publication-failure, and deterministic-output
  matrix completion still gate ADR-088 promotion and TD-COMPACT-11 closure.
