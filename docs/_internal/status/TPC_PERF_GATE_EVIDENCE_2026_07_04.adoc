= TPC perf-ledger gate evidence — 2026-07-04 (scale 0.01, local-tempdir)

First dated artifact from the TD-OLAP-4 harness (`tests/tpc_perf_ledger_e2e.rs`),
run to decide the TD-OLAP-3 gate promotions. Three passes, identical data

Native route (unchanged across runs): TPC-H 4/22, TPC-DS 5/16 pass — and
**Q21 takes 316.8 s** on the row-wise Volcano vs the DataFusion route's ~4.5 s
median for the full suite. This is the ADR-052 "retire Volcano-for-OLAP"
premise as a measured number.

== Findings

. **Both gates are stability-neutral**: 38/38 DataFusion-route queries pass
  under every configuration; wall-clock deltas are within run noise (±2%);
  no stack incidents with 16 MiB stacks. Safe for experimental use.
. **Skip ratio is 0% in every configuration — a DATA property, not a
  mechanism failure.** The harness's synthetic generator draws dates and keys
  uniformly at random per row, so every row group's min/max spans nearly the
  full domain and zone-map pruning provably cannot exclude anything. Real
  TPC dbgen data (and real workloads) are time-clustered; min/max pruning is
  only meaningful over clustered data.
. **Promotion decision: both gates stay default-OFF** (mandate: promote only
  where the measured trace moves the dominant cost term — this trace shows
  no movement). Promotion prerequisite recorded in TD-OLAP-3: re-run the
  evidence over CLUSTERED data — either sort the generator's fact tables by
  date/key within row groups, or land faithful dbgen/dsdgen datagen
  (TD-OLAP-4 remaining scope) — at scale >= 0.01.
