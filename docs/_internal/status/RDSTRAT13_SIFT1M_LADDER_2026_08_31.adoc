== Finding 1 — the compaction L3/L2 retirement race is the dominant cold-latency term (3x)

The degree-1 control differs from the adaptive arm ONLY in the rank worker count, yet p50 is
**2977 ms vs 9029 ms** — because the two arms' query-time live sets differ: the control served
the **clean L3-only** state (11 cells, 370k rows, 58.5 MB, 21.95 GETs) while the adaptive arm
served **L2+L2+L3 overlap** (27 cells = 8+8+11, 882k rows, 125.5 MB, 50.57 GETs). Same code,
same bed bytes at settle (2×L2, 245,647,274 B) — the L3-publication/L2-retirement sequence is
**racy**: sometimes the superseded L2s remain live and serving, doubling rows, bytes, GETs and
re-ranking the same rows through overlapping levels. Recall and result-identity stay correct
(MVCC dedups at emit) but the compute, bytes and GETs are paid twice. When retirement wins:
**2977 ms @100 ms RTT** — within 3.4x of turbopuffer's 874 ms on a dev-box bed; when it loses:
9029 ms. The retirement race alone is a **3.03x p50 and 2.1x bytes** swing at identical code —
filed as the follow-up defect (compaction input retirement), the highest-value cold-query lever
this campaign measured.

== Finding 2 — the "0.9 s compute" premise was a mis-inference; measured rank is 34–43 ms

The az ladder inferred "~0.9 s single-threaded rank" from latency subtraction, and this TD's
Phase A premise inherited it. The C1 instrument now measures it directly: sequential rank
(degree-1 control) = **42.9 ms** at 370k probed rows; morsel-parallel = **33.7 ms** at 882k rows
(`PROXIMADB_SEARCH_MORSEL_DEGREE` adaptive, width 8). The rank was never the dominant cold term
at this geometry — the residual was transfer all along. C2 ships anyway (correct, deterministic,
oracle-proven, and the only always-on parallelism on the probe path), but the lever's measured
size is tens of ms, not ~1 s. The az-ladder record (`rdstrat12_sift1m_rtt_ladder_crossover`)
carries the same mis-inference and needs this correction on file.

== Finding 3 — the toxiproxy@RTT bed is transfer-dominated; waves/rank cannot move it

With the overlap doubling bytes, object_cold moves 125.5 MB/query at ~14 MB/s effective through
the window-limited 100 ms-RTT proxy ≈ 8.9 s of the 9.0 s p50 (~98% transfer). Raising RTT
50→150 ms moved b0's p50 only 9099→9575 ms (+5%) — RTT is a minor term next to throughput
degradation. On this bed the PR's round/compute levers are structurally capped (~1.0–1.3x), and
they measured exactly there at GET/byte parity (delta +0.00%, recall and result-identity
IDENTICAL in every same-geometry pair).
