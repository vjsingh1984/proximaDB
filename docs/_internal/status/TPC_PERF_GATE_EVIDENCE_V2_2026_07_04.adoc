= TPC gate evidence v2 — full pruning-chain root cause (2026-07-04)

Follow-up to `TPC_PERF_GATE_EVIDENCE_2026_07_04.adoc`. The v1 hypothesis
("uniform datagen defeats zone maps") was necessary but NOT sufficient: after
clustering the generator's fact tables by date, the skip ratio stayed 0%.
Link-by-link diagnosis found and fixed two more blockers and root-caused a
fourth:

|===
| # | Blocker | Status

| 1 | Static WHERE predicates never reached `scan()` (`supports_filters_pushdown` missing)
| fixed in #671 (slice A)

| 2 | `DATE`/timestamp literals never translated into pruning predicates — TPC-H's
    filters are almost all date-ranged, so no date predicate could ever prune
| fixed (temporal arms in `physical_filter_translate::df_scalar_value`;
  Date32 days compare numerically against the footer's Int32 stats)

| 3 | The materializer wrote ONE row group per table (Arrow default 1,048,576
    rows) — one split, whole-domain min/max, structurally unprunable
| fixed (`warehouse_writer_properties`: default 65,536 rows,
  `PROXIMADB_MATERIALIZE_ROW_GROUP_ROWS` override; blueprint §2 geometry)

| 4 | The materialize snapshot scan does not preserve/impose row order: with
    4,096-row groups over 20,000 strictly date-ordered inserts, ALL five row
    groups span the full date domain (footer diagnostic: min=8766 max=9066
    in every group)
| **open — filed as TD-OLAP-6 (sort-on-materialize by cluster key)**
|===

== Evidence runs (scale 0.01, clustered generator, local-tempdir, debug)

Clustered inserts alone (before fixes 2–3): skip 0/85 TPC-H, 0/40 TPC-DS in
baseline AND runtime-filter configurations; stability and latency identical
to the uniform v1 runs (all 38 DF-route queries pass in every pass; six
total passes across v1+v2).

Footer diagnostic (`diagnose_materialized_footer_bounds`,
`tests/tpc_perf_ledger_e2e.rs`): the geometry fix produces the expected
multi-row-group files (5 groups @ 4,096 rows for a 19,616-row table), proving
blocker 3's fix; the identical per-group bounds prove blocker 4.

== Decision

Gates remain **default-off** (mandate: promote on a measured win). The
promotion path is now precise: land TD-OLAP-6 sort-on-materialize, then
re-run this evidence — static date pruning (Q1/Q6-class) and the join runtime
filter should both show non-zero skip on the first sorted run.

== Provenance

Harness + fixes @ branch `perf/olap-clustered-datagen` (develop `e857b29`
base). Hardware/profile identical to v1 (WSL2, 32 cores / 78 GB, local NVMe
tempdir, debug). Reproduction: the three commands in v1 plus
`PROXIMADB_MATERIALIZE_ROW_GROUP_ROWS=4096` for granularity at small scale.
