= TPC gate evidence v6 — runtime-filter gate promoted to default-ON (2026-07-06)

Executes the promotion v5 (`TPC_PERF_GATE_EVIDENCE_V5_2026_07_06.adoc`, #696)
found evidence-supported and recommended for "a dedicated, correctness-ratcheted
PR". v5 proved Slice B (runtime join filter) prunes the fact table where Slice A
(static pushdown) structurally cannot, and deferred the default flip pending three
caveats. This PR flips the default and clears all three.

== The three v5 caveats, addressed

1. **Larger-scale confirmation.** v5 measured at scale 0.02; this PR reproduces
   the win at 0.01 (full 38-query suite) AND confirms it holds at 0.05 (2.5×
   v5's scale). See both tables below — the star-join reduction is stable across
   scales.
2. **`wait_complete()` stall-safety.** The full 38-query conformance suite runs
   with the gate ON with no 10 s fallback stalls: TPC-DS repeat walls median
   ~0.75 s, TPC-H ~4.5 s (both routes), all 38 pass. No plan shape left an
   absorbed filter unresolved. (The stream head awaits each filter's completion,
   0 ms when resolved; the 10 s bound is the safety net, not the common path.)
3. **`splits_*` double-count.** Fixed in this PR: the per-split `record_splits`
   at `execute` now adds only the *dynamic* skip to `splits_pruned`. The provider
   `scan()` already records every candidate in `splits_total`, so the prior
   `record_splits(1, …)` double-counted survivors (v5 saw `splits_total` 17→33).
   Now `splits_total` is stable across gates and reads the true candidate count.

== Result B — larger-scale confirmation, scale 0.05 (TPC-DS star queries)

At 2.5× v5's scale the fact table carries 38 row groups (vs 10 at 0.01). The
win holds and **grows** — the footer-prefetch fixed cost amortizes, so a larger
fraction of the query is prunable fact-scan. Controls (q98, cube — no
dimension-only date filter) are unchanged. All result sets identical.

Direction and magnitude are consistent with 0.01 (−44% there, −57% here) and
with v5's 0.02 (−47%) — the reduction is real and scale-stable, not a
small-scale artifact.

== Decision

* **`PROXIMADB_DF_RUNTIME_FILTER_PRUNE` promoted to default-ON** (opt out with
  `=0`). All three v5 caveats cleared; the star-join `bytes_read` reduction is
  measured, correctness-neutral (identical result sets; the hash join applies
  exact semantics), and stable across 0.01 and 0.05. Slice A (static) and Slice B
  (runtime) are complementary and both default-ON.
* Follow-ups unchanged: bloom for high-NDV, partition-level DPP, faithful-scale
  datagen (TD-OLAP-4).
