= Embedding retrieval next gate — 2026-08-21
:toc:

== Decision

Keep BGE base v1.5 at 480 tokens / 72 overlap as the NFCorpus control. Make propagated
document context available as an explicit chunking policy, but do not make title propagation a
quality default from this dataset. Repeating the title in every child chunk changed held-out
Recall@100 from `0.338022` to `0.338231`; the paired 95% query-bootstrap interval
`[-0.001082, +0.001385]` includes zero. NDCG@100 changed by `-0.000290`, also with an interval
that includes zero. The corpus grew by only 5 vectors (`+0.12%`), so this is a safe correctness
capability rather than a demonstrated NFCorpus quality improvement.

The source-aware depth defect is closed. Exact dense scoring now retains the best score for every
source over the complete chunk corpus before selecting 100 distinct sources. All dev and test
queries in every arm have exactly 100 candidates. The corrected held-out control Recall@100 is
`0.338022`; the historical `0.333068` value was a lower bound from collapsing only 100 chunks.

The lexical run exposed an architectural seam. ProximaDB's document `FullTextIndex` is an actual
Tantivy 0.22.1 projection with default BM25, but it is not the custom in-memory full-text index
used by the canonical hybrid endpoint. Its strict `QueryParser` rejected 13/324 dev queries and
9/323 held-out queries containing natural-language punctuation. The evidence runner defaults to
fail; this study explicitly used `zero_pad`, recorded every error, and padded deterministic
zero-score candidates so Recall@100 stayed complete. Do not call this a canonical hybrid-path or
natural-query quality result.

== Working-backwards protocol

The customer outcome is a complete, attributable source candidate pool under a bounded vector
budget. The protocol therefore fixed the corpus and model before examining held-out results:

* official NFCorpus corpus with separate `title` and `body` fields;
* 324 development queries for the promotion decision, followed once by 323 held-out test queries;
* `BAAI/bge-base-en-v1.5` revision
  `a5beb1e3e68b9ab74eb54cfd186867f64f240e1a`, 768 dimensions, role-correct query rendering,
  normalized float32 embeddings and exact inner product;
* recursive chunks at target 480 / overlap 72, split overflow, `deduplicate=none`;
* title arm rendered `{context}\n\n{text}` for every child while preserving `chunk.text` and
  source offsets exactly for citations;
* source-direct ranking by maximum child score across the complete corpus, deterministic
  source-ID tie breaking and a hard `--require-complete-k 100` evaluator gate;
* 10,000-sample paired query bootstrap, seed 17, with no parameter tuning on held-out test.

No timing is claimed. Embedding used PyTorch/MPS, but the host had concurrent compilation.

The runner indexes title and body as separate Tantivy fields, commits and reopens the persistent
index, calls `proximadb::storage::document::indexes::fulltext::FullTextIndex::search`, and records
Tantivy's default BM25 scores. Strict parser failures are production component behavior; only the
benchmark's explicit `zero_pad` policy converts them into complete diagnostic rows. The next
lexical product decision must first define distinct natural-text and query-syntax contracts, then
measure the canonical hybrid implementation or deliberately converge the two full-text engines.

== Code contracts closed

* `ChunkContextRenderer` renders optional metadata context into the exact model input. Blank
  context is a no-op; unknown template fields and templates without exactly one context/text slot
  fail closed.
* `TextChunk.text` and offsets remain source-exact. `TextChunk.input_text` is the content sent to
  the tokenizer/embedder, making citation and model-input faces explicit.
* The BEIR importer preserves separate title/body fields while retaining the prior combined
  `text` field for compatibility.
* The exact scorer has an explicit `source` candidate mode bound to the occurrence-sidecar hash.
* The Tantivy runner uses the production document component, emits a sealed manifest, fails on
  query errors by default, and makes diagnostic zero padding explicit and auditable.
