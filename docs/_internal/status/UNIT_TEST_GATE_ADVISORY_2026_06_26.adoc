= `Rust Tests (unit)` Gate Made Temporarily Advisory — Develop-Wide Unit-Test Rot (2026-06-26)
:toc: macro
:icons: font

[NOTE]
====
**RESOLVED (2026-06-26).** All clusters below are fixed and `rust-test` has been **re-added to
`ci-success.needs`** in `.github/workflows/ci.yml` — the `Rust Tests (unit)` gate is required again.
Root causes + fixes are recorded in <<resolution>>. This doc is retained as the historical record.
====

Records a **deliberate, temporary** CI-policy change: `rust-test` (the `Rust Tests (unit)` + `doc`
matrix) is removed from the `ci-success` gate (`.github/workflows/ci.yml`) so correct PRs can ship
while a batch of **develop-wide, PR-unrelated** unit-test failures is triaged. This is a tracked
backstop, not a silent disable — the job still runs and is visible on every PR.

[#resolution]
== Resolution (2026-06-26)
[cols="2,3", options="header"]
|===
| Cluster | Root cause + fix
| `query::semantic_analysis` (28 tests, both the `analyzer::tests` and `tests` modules)
| **Stale test fixture.** `setup_analyzer_with_mock` created a `TempDir`-backed system catalog but
  returned only the `Analyzer`, dropping the `TempDir` at setup return. Since #208 made xCatalog the
  sole store (read-through to its on-disk dir), the deleted dir made every `get_collection` miss
  ("Table not found"). Pre-#208 the in-RAM metadata backend masked it. **Fix:** bundle the `TempDir`
  with the `Analyzer` in a `TestAnalyzer` guard (`Deref<Target=Analyzer>`) so the catalog dir
  outlives the queries — call sites unchanged.
| `embedded::tests` (`…_lowers_agentic_ddl_to_catalog` — "Collection agent_store not found")
| **Real product bug** in `upsert_collection_catalog_asset`'s adopt-existing-table branch: when an
  existing non-collection table (an `agentic_mixed` DDL table) gains vector capability it set
  `asset.capability.vector=true` + `collection.id/name` + `vector.dimension` but **not**
  `asset.kind="collection"`, while the reader `collection_from_catalog_schema` gated strictly on
  `asset.kind == "collection"` → the adopted collection was invisible to `get_collection`, so DML
  INSERT into an agentic-DDL table failed. **Fix:** the reader now also accepts a table marked
  `asset.capability.vector == "true"` (honouring the writer's intent; `collection.id` still gates).
| `index::axis…dual_store_ivf` (`compact_id_search_returns_correct_external_ids` — "Vector dimension mismatch")
| **Under-specified test.** Config left `dimension` at the `0` default; the fp32 vector store is
  built from `config.dimension` (`CollectionConfig::fp32`), so `add_vector` rejected the 3-dim
  vectors. **Fix:** set `dimension: 3` in the test config to match the data.
| `metrics…integration_tests` (`test_flushcoordinator_metrics_integration`)
| **Stale test.** Post-D1-convergence the trait `flush()` wrapper is authoritative for timing and
  overwrites `duration_ms` with the real elapsed wall clock; the instant mock yielded `0`, failing
  `last_flush_duration_ms > 0`. **Fix:** the mock's `do_flush` now sleeps 2ms so the recorded
  duration is non-zero (its hardcoded `Some(100)` was always discarded by the wrapper).
| `network::auth::jwt` | **RESOLVED earlier** (jsonwebtoken v10 `aws_lc_rs` provider — see `JWT_CRYPTO_PROVIDER_REGRESSION_2026_06_26.adoc`).
|===

== Why
The `Rust Tests (unit)` job runs all ~8,386 unit tests and fails the `CI Success` aggregator if any
fail. As of 2026-06-26 several tests fail on **clean develop** (reproduced with no PR changes), so
**no PR can pass the gate** regardless of its own correctness — blocking all shipping. Rather than
let every PR carry unrelated red, the gate is made advisory until the suite is green again.

== What changed
`.github/workflows/ci.yml` — `rust-test` commented out of `ci-success.needs` (the existing advisory
pattern; cf. the line-230 "Advisory (not in `ci-success` needs)" note). The job is unchanged and
still runs; it just no longer blocks the merge gate.

== Re-promotion criteria (undo this)
Restore `- rust-test` to `ci-success.needs` once `cargo nextest run` (unit) is green on develop,
i.e. each cluster above is fixed (or quarantined with a tracked reason). Until then, **reviewers
must eyeball the advisory `Rust Tests (unit)` result manually** — advisory ≠ ignored.

== Follow-ups (separate, focused PRs)
* Triage + fix the `query::semantic_analysis::analyzer` cluster (largest; likely a real regression).
* Triage `embedded` (agent_store fixture), `dual_store_ivf` (dimension mismatch), `flushcoordinator`.
* File a TD to track re-requiring the gate (this doc is the interim record).
