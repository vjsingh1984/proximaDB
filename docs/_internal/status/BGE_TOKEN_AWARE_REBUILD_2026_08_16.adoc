= BGE Token-Aware Corpus Rebuild Evidence
:toc:

Status: complete

== Scope

Rebuild the shared BGE small/base corpus from the legacy 17-root source inventory using exact
480-token document inputs, 72 source-token overlap, split overflow, retained short tails, and exact
deduplication. This evidence is for realistic corpus quality, PCA spectrum, and lifecycle economics;
it does not reopen the completed TD-IVF-3 index-geometry conclusions.

== Source transport

* Source documents: 90,302
* Source JSONL SHA-256: `8143f3982cfda621c00723bbd15dcaa909c266e3e650fe1bb0f7c3c53b6e2bbd`
* Unreadable sources explicitly dropped and recorded: 17 encoding/malformed-input fixtures
* Oversized valid source policy: split; none implicitly dropped

== Pressure-test finding

The first full run exposed redundant reuse of a previous structural boundary when configured
overlap was close to a short structural span. A 15,550-character VS Code fixture produced 248
chunks with p50 56 tokens. PR #1659 added the missing forward-progress invariant and packing
diagnostics; the same pinned BGE contracts then produced 17 chunks, p50/max 480, minimum new
content 37 tokens, and exact `0..15,550` character coverage.

== Embedding evidence

The 384-d control is complete over all 765,406 shared texts. The final manifest is
`bge384/bge384.embedding.manifest.json`, SHA-256
`15c9cc441de5b120fa48c2db7b3842898acc448537944f7e4284d1f3b4a08211`. It binds the
sealed corpus SHA-256 and small-model contract fingerprint above to pinned model revision
`5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`, dimension 384, normalized embeddings, backend
`torch`, resolved device `mps:0`, compute/artifact dtype `float32`, and 20,000-row resumable
shards. The 1,000-row query split is explicitly a `geometry_probe`, not qrels-bearing retrieval
quality evidence. Quantization clipped zero query values at either bound.

The complete-corpus PCA spectrum is:

* `T=.70 -> 104`
* `T=.79 -> 148`
* `T=.85 -> 187`
* `T=.90 -> 229`
* `T=.95 -> 286`

The comparable legacy truncated-corpus values were `T=.70 -> 103` and `T=.79 -> 147`. The
token-aware rebuild therefore moved each reported threshold by only one component. That is not a
material diversity shift for the 384-d control, so this result does not support the hypothesis that
legacy truncation substantially suppressed its full-corpus PCA diversity. It does not answer
absolute retrieval quality because this geometry probe has no qrels.

Wall-clock shard durations are operational telemetry only. Other repository builds repeatedly
contended for CPU and unified memory during embedding, while shard identity, vectors and PCA are
contention-invariant. No throughput comparison is derived from those durations.

The paired 768-d control is also complete over all 765,406 shared texts. The final manifest is
`bge768/bge768.embedding.manifest.json`, SHA-256
`59fd7158536d260df02653f1c17046226f22d7e34d95475377d201a691d83c88`. It binds the
same sealed corpus SHA-256 and base-model contract fingerprint above to pinned model revision
`a5beb1e3e68b9ab74eb54cfd186867f64f240e1a`, dimension 768, normalized embeddings, backend
`torch`, resolved device `mps:0`, compute/artifact dtype `float32`, and 20,000-row resumable
shards. The 1,000-row query split is again a `geometry_probe`; quantization clipped zero query
values at either bound.

The complete 768-d corpus PCA spectrum is:

* `T=.70 -> 113`
* `T=.79 -> 164`
* `T=.85 -> 213`
* `T=.90 -> 270`
* `T=.95 -> 359`

The comparable legacy truncated-corpus values were `T=.70 -> 112` and `T=.79 -> 163`. As for the
384-d control, the token-aware corpus moved both legacy comparison thresholds by only one
component. The paired result therefore does not support a material full-corpus PCA-diversity shift
from removing truncation. It does not establish retrieval-quality equivalence: both outputs remain
qrels-free geometry probes.

Host contention exposed an MPS execution-stability seam during the long 768-d pass. The first 12
canonical shards used provider batch size 64. Offsets 240,000 through 580,000 used batch size 16,
and offsets 600,000 through 760,000 used the same batch size with fresh-process, 1,000-row micro
checkpoints before atomic assembly into the canonical 20,000-row shards. Every path used the same
pinned model revision, document role, contract fingerprint, normalization, `torch`/`mps:0`
runtime and float32 artifact dtype. The authoritative transport subsequently revalidated all 39
canonical shard shapes and dtypes before emitting the final binaries, manifest and spectrum.

This execution change was pressure-tested rather than assumed. Across identical 512-text batches,
batch sizes 16, 32 and 64 had maximum elementwise drift `2.1141022443771362e-07`, minimum cosine
`0.9999998807907104`, and mean cosine `1.0`. Re-embedding the actual offset-220,000 shard sample
at batch size 16 and comparing it with its stored batch-64 output found maximum absolute drift
`1.564621925354004e-07`, mean absolute drift `1.980869912543426e-10`, minimum cosine
`0.9999998807907104`, and mean cosine `1.0`. These are numerically equivalent float32 execution
partitions for the present geometry evidence; they are not byte-identical outputs.

The canonical shard identity currently records model, revision, contract, role, runtime, dtype and
transport but not execution batch size or process partitioning. That omission did not change this
result because equivalence was measured, but it is an operational-provenance follow-up: future
transports should record execution parameters separately from semantic artifact identity. Timing
remains excluded because the host was not quiet.

Multi-gigabyte vector binaries and resumable `.npy` shards remain in benchmark storage. Git records
their reproducible contracts, hashes and findings rather than copying generated vectors into the
source repository.

== Interpretation and bounded follow-up

BGE v1.5 remains the forensic control for closing the truncation incident; it is not a product
default recommendation. Model context is a ceiling rather than a target, and context and output
dimension are independent economic levers. The next controlled experiment will first sweep
tokenizer-only row, packing and update economics across the curated open-model catalog. A
qrels-bearing shortlist will then compare the lightweight 8K Matryoshka anchor (Nomic Embed
v1.5), the 32K Granite R2 97M/311M economic anchors, and the instruction-aware 32K Qwen3 0.6B
upper envelope. Full-corpus embedding is reserved for Pareto winners plus BGE v1.5 as the control.

The repository audit also found a legacy, provider-shaped `EmbedRoute` enum whose latent tier
defaults select BGE variants. The functions have no non-test production callers, while the newer
xCatalog model-contract authority is provider-neutral. Data-plane follow-up must resolve an
immutable xCatalog model version plus approved deployment binding instead of turning a model
family into tier policy. Workload-specific champion aliases may change only after quality and
lifecycle-cost bake evidence.

== Embedding runtime preflight

Tokenization, boundary packing, JSON transport, deduplication and hashing remain CPU work. Neural
embedding uses an explicit accelerator route. A two-text smoke of the pinned BGE small revision in
the approved unsandboxed execution context produced shape `[2, 384]` with backend `torch`, resolved
device `mps:0` and compute dtype `float32`. The restricted execution sandbox intermittently hid the
MPS device and is not a valid accelerator oracle. Full-corpus embedding must fail fast unless the
same-process model preflight succeeds, and its shard/final manifests must record backend, resolved
device, compute dtype and stored artifact dtype.
