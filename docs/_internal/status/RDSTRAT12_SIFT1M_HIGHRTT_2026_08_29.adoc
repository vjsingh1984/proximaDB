== Bed

Dedicated Azurite 3.36.0 (`127.0.0.1:11000`) behind Toxiproxy 2.12.0
(`127.0.0.1:11001`), symmetric 25+25 ms latency toxics (50 ms RTT, jitter 0).
Server env: `PROXIMADB_AZURE_EMULATOR=1`, `AZURITE_BLOB_STORAGE_URL` → proxy,
`PROXIMADB_WAL_LOCAL_DIR` per arm (ADR-069 local-WAL tiering; durable WAL
PUTs through the proxy hit a 30 s object_store send-timeout stall —

production architecture and removes it from the measured path). SIFT1M,
100 queries, top-k 100, 2 settled segments, harness `--azurite
--storage-url az://rdstrat12highttt/{baseline,treatment}`.

== Why the batched wave did not show (evidence-ranked)

. **The bulk of cold-RTT budget is OUTSIDE §3's batch scope.** Region-B
   (SQ8 rerank, 38.4 MB/q — 84% of cold bytes) is fetched through the
   survivor-cache `get_or_fetch` per-range path (segment_format.rs
   Region-B/survivor fetch sites), NOT through the probe cold tail §3
   batched. The probe's Region-A tail is ~5 planned fetches and 0.91 MB/q.
. ~~Azure coalesce policy collapses the probe tail inside the batch.~~
   **CORRECTED (round 4): DISPROVEN.** `AzureBlobFileSystem` overrides only
   single `read_range`; the trait-default `range_coalesce_policy()` is
   `None` ⇒ the re-plan is IDENTITY and the probe tail waved with real
   width. The actual mask is (a): the bed's overlapping queries RAM-hit most
   probe-tail ranges, leaving a tiny truly-cold population per query.
. **Box load 15–25 during both arms** (other sessions' builds) adds
   shared compute noise; both arms are equally affected, but small deltas
   (<150 ms) are not resolvable.

The azure wrapper overrides only single `read_range` — `read_ranges` /
`read_ranges_prefetch` / INFLIGHT gate are the trait defaults (verified in
azure_blob.rs), so the gate is reachable on this backend; the positive
control (merged in #1742) proves the wave fires when the plan has >1
physical GET.
