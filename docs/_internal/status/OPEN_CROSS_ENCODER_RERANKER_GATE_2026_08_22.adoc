= Open Cross-Encoder Reranker Gate — 2026-08-22

== Decision

Keep cross-encoder reranking opt-in. The development-first NFCorpus gate demonstrates a material
ordering improvement from a small open model at a 50-source rerank depth, but it does not improve
the Recall@100 candidate ceiling and does not measure citation-span precision, generated-answer
quality or production ONNX latency.

The selected development policy is:

* `cross-encoder/ms-marco-MiniLM-L6-v2`, Apache-2.0, 22.7M parameters, pinned revision
  `4bebbd56fc380a66525f95b03d4ec1a4b41a4f1e`;
* canonical natural-language BM25's top 100 sources as the fixed candidate set;
* rerank the first 50 sources, sort that prefix by cross-encoder score, then append the untouched
  tail; raw BM25 and cross-encoder scores are never compared across scales;
* propagate the source title to every query-aware body window, split oversized bodies with 32
  tokens of overlap, score every window, and use the maximum window score for the source;
* fail instead of dropping text when a query or title leaves no body-token capacity.

The upstream model card describes this model as an MS MARCO passage reranker and reports 22.7M
parameters. See https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2[the authoritative model
card]. A small English reranker is the first economics gate; the evidence does not establish it as
the best model for multilingual or domain-specific workloads.

== Protocol

The fixed inputs are the official NFCorpus 3,633-source corpus, 324 development queries and 323
held-out test queries already sealed by the lexical-contract gate. Each query starts from exactly
100 sources emitted by the production-equivalent canonical natural-language BM25 path. Source qrels
are evaluated at 10 and 100, with 10,000-sample paired query bootstraps at seed 17.

Model scoring is cached per query. One cache pass can materialize several prefix depths without
repeating inference. Every cache record is bound to the producer hash, model ID and revision,
token budget, overlap, maximum candidate depth and all input hashes; a mismatch fails instead of
mixing evidence.

The pair tokenizer owns the 512-token limit. It reserves the query and pair-special-token budget,
propagates title context, splits the body to fit the remainder, and verifies every actual pair with
truncation disabled. Oversized spans are split, not dropped.

Depth 50 versus baseline improves NDCG@10 by `+0.016666` (`+5.76%`, paired 95% interval

and `+0.000564` Recall@10 (interval `-0.000972` to `+0.002497`) while doubling candidate,
window and token work. Both intervals include zero, so depth 50 is the smallest measured Pareto
policy taken to held-out test.

Held-out NDCG@10 improves by `+0.024192` (`+7.50%`, paired 95% interval `+0.012902` to
`+0.036205`) and NDCG@100 by `+0.016111` (`+5.95%`, interval `+0.009516` to `+0.023546`).
Recall@10 changes by `+0.002674` (`+1.72%`, interval `-0.003252` to `+0.008254`), which is not
statistically resolved. Recall@100 is bit-identical: delta `0.0`, 323/323 ties. Reranking can
reorder a candidate set; it cannot recover relevant sources missing from that set.

The held-out policy scored 16,150 sources as 18,090 windows and 5,959,057 input tokens. The longest
actual model input was exactly 512 tokens; zero inputs exceeded the model limit. PyTorch selected
MPS on local Apple Silicon. Recorded elapsed time is execution provenance only: the machine was not
an isolated latency bed and the serving implementation is ONNX, so this gate makes no latency or
throughput claim.

== Product seam corrected by TDD

The rank pipeline previously globally sorted rescored cross-encoder logits together with untouched
first-stage scores. Those values have unrelated scales, so an untouched BM25 tail could move above
the reranked prefix for accidental numeric reasons. The pipeline now sorts the rescored prefix
independently, appends the untouched tail, and verifies that a scorer preserves candidate count and
identity.

The BERT-pair ONNX extractor also no longer turns missing query/document text into empty strings or
silently accepts tokenizer overflow. Missing hydration and overlength pairs fail closed with an
actionable error. Long-document splitting and source max-reduction remain an orchestration
responsibility; the current one-row-per-document ONNX adapter does not yet implement the benchmark's
multi-window reduction. This is why the quality finding does not ratchet reranking default-on.

== Limits and next gates

NFCorpus has document qrels, not citation-span labels. The winning window is retained for future
attribution diagnostics, but citation precision cannot honestly be computed from this dataset.
Generator answer quality is likewise outside a ranking-only evaluation. Maximum-over-window source
reduction also gives longer documents more scoring opportunities; its length bias needs a labeled
span corpus before choosing among max, top-n aggregation or learned pooling.

The first follow-up is closed in `HYBRID_CANDIDATE_RECALL_GATE_2026_08_23.adoc`: the complete BM25
and dense union materially raises the candidate-pool ceiling, but global MiniLM selection
significantly regresses final Recall@100 and NDCG@100 versus dense. Held-out therefore remained
sealed.

The next evidence order is:

. find a stronger open selector or calibrated cascade that beats the dense control on development
  quality under explicit candidate/window/token budgets, then evaluate held-out once;
. add a span-labeled citation and downstream answer-quality suite;
. export only the promoted selector to ONNX and prove framework rank parity, zero-truncation window
  reduction, accelerator-provider selection and quiet-machine latency/cost;
. only then register a deployable reranker capability in the model catalog. Its contract must carry
  task type, tokenizer/model revision, maximum pair length, title/window/reducer policy, tensor
  signature and score semantics. Retrieval pipelines should reference that model capability rather
  than duplicate it in a second catalog.
