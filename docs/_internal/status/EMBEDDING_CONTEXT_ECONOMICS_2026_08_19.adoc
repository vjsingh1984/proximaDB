= Embedding Context Economics Evidence
:toc:

Status: in progress

== Decision question

Does a larger embedding context reduce canonical vector rows and lifecycle bytes enough to justify
its ingestion-work, update, citation and retrieval-quality costs on the same 90,302-source corpus?
The experiment seeks a Pareto frontier; it does not assume that the model's maximum context is the
right chunk size.

Context and dimension are independent variables. Each scenario therefore reports canonical rows,
source occurrences, rendered tokens, an explicitly labelled quadratic attention-work proxy,
source-update amplification, and vector payload at multiple dimensions/dtypes. Wall time is not
evidence because the host is contended. Absolute quality remains blocked until role-correct queries
and source/span qrels are projected and evaluated for each corpus.

== Controlled inputs and gates

* Source JSONL: 90,302 documents, SHA-256
  `8143f3982cfda621c00723bbd15dcaa909c266e3e650fe1bb0f7c3c53b6e2bbd`.
* Every corpus must be `complete_source`, use `overflow_policy=split`, retain short tails, record
  exact deduplication, and assert zero truncation.
* Token budget, overlap, tokenizer/model revision, role renderer, structural strategy and character
  ceiling are manifest identity. Long-context runs use a 1,048,576-character ceiling so the token
  budget, rather than a legacy structural cap, is the intended binding constraint even for
  pathological source spans.
* Schema-v2 corpora record every source-span occurrence separately from canonical deduplicated
  chunks. This preserves update, ACL, citation and qrels lineage.
* `sum(rendered_tokens^2)` is a full-attention work proxy, not measured compute time. Vector byte
  estimates exclude ANN/index overhead except an explicit caller-supplied fixed bytes/row term.

Pinned tokenizer-only planning contracts cover Nomic Embed v1.5, Granite R2 97M/311M and Qwen3
Embedding 0.6B. They are not embedding evidence: a later neural run must resolve the exact runtime
contract and record backend/device/dtype provenance.

== BGE 480-token baseline

The sealed token-aware BGE corpus has 765,406 canonical rows. Across the 90,302 declared sources,
88,983 have a retained canonical occurrence in the legacy schema-v1 chunk file. Canonical
chunks/source are min 1, p50 3, p90 18, p99 83 and max 18,268. Exact deduplication removed 19,270
chunks, but schema v1 did not retain their source aliases, so update amplification is explicitly
undercounted for this baseline.

133,120,200,095. Canonical vector payload is:

Within one pinned Nomic tokenizer/model contract, 480 -> 2,048 tokens reduces canonical rows by
192 (5.1%) and rendered tokens by 1.3%, while increasing the attention proxy by 5.9%. Increasing
2,048 -> 7,936 changes no row, token or byte metric because NFCorpus' maximum rendered document is
1,852 tokens. Maximum model context is therefore not an economically justified chunk target for
this workload.

At the same one-chunk-per-source floor, tokenizer efficiency still differs: relative to Nomic,
Granite emits 10.6% more rendered tokens and a 22.9% larger attention proxy; Qwen emits 16.1% more
tokens and a 36.7% larger proxy. These are ingestion-work proxies only, not model-quality or
latency rankings. The 256-d Nomic/Qwen payload equality demonstrates that dimension fixes vector
bytes once row count is equal, independent of context ceiling.

The official 12,334 document relations project to 14,031 BGE chunks, 12,876 Nomic-480 chunks and
12,288 chunks for each one-chunk-per-source corpus after exact-dedup pair collapse. Those counts
are deliberately not compared as NDCG/Recall: document-level BEIR quality must collapse retrieval
scores back to source IDs before applying the original qrels. Exact-dedup aliases make document
credit ambiguous, so comparable neural quality corpora will be rebuilt with `deduplicate=none`;
alias expansion is retained only as an explicitly labelled diagnostic.

== Co-design findings implemented before the sweep

. Exact deduplication previously discarded duplicate source provenance. The builder now emits
  `chunk_occurrences.jsonl`, mapping every source span to its canonical `corpus_id` and identifying
  deduplicated aliases without duplicating vectors.
. The structural character ceiling could silently dominate a large token target but was absent
  from provenance. Schema v2 records `boundary_char_size` and source field mappings.
. `embedding_context_economics.py` fails closed on incomplete/truncated corpora and digest drift,
  then separates canonical storage rows from source occurrences and update amplification.
. `project_span_qrels.py` projects tokenizer-independent source/span judgments through occurrence
  lineage. Invalid/unmatched spans fail closed; repeated query/corpus pairs keep maximum relevance.
. `import_beir_dataset.py` verifies published archive provenance and emits deterministic,
  dependency-free documents, queries and document-level source qrels without inventing license
  rights.
. `evaluate_source_retrieval.py` computes document metrics only after maximum-score source
  collapse, binds every input digest, covers every qrels query, and rejects exact-dedup aliases by
  default. Metric definitions and deterministic tie breaking are persisted in the output.
. Schema-v2 embedding manifests bind both role-specific shard identities;
  `score_embedding_shards.py` validates exact row lineage and emits deterministic normalized
  float32 inner-product runs before ANN or quantization is introduced.

The new contracts are covered by offline smoke builds. Builder, economics, BEIR-import, qrels and
source-evaluation tests currently pass 30/30 together with the existing corpus/embedding transport
suite when `PYTHONPATH=clients/python/src` binds the isolated worktree SDK.

== Full-source long-context upper bound

The Nomic v1.5 7,936-token / 1,190-token-overlap corpus atomically finalized over the same
90,302-source input as the realistic BGE rebuild (`input_sha256`
`8143f3982cfda621c00723bbd15dcaa909c266e3e650fe1bb0f7c3c53b6e2bbd`). It records complete-source
scope, zero truncation, 100,875 canonical rows, 101,203 source occurrences and 328 exact-dedup
aliases. Its corpus manifest SHA-256 is
`82c3b846bccf732a8b78affe45c7f872244367b35810fe8fd7e936530e55c087`; the recorded builder digest
was verified byte-for-byte before branch rebase. The economics report uses producer
`b97753bcea1ee0bfbda76690a7ba2d0060adeda27a2e84a5c1f27a10b7167035`.

Compared with BGE-480 on that identical input:

[cols="2,1,1,1",options="header"]
|===
|Metric |BGE-480 / 768-d |Nomic-7,936 / 256-d |Nomic delta
|Canonical rows |765,406 |100,875 |-86.8%
|Rendered tokens |311,961,937 |221,826,070 |-28.9%
|Float32 vector payload |2,351,327,232 B |103,296,000 B |-95.6%
|Quadratic attention proxy |133,120,200,095 |1,155,353,002,868 |+767.9% (8.68x)
|===

This falsifies either one-dimensional conclusion. Longer context can greatly reduce row and vector
storage cost, especially together with a smaller Matryoshka output, but filling that context can
increase naive full-attention ingestion work by almost an order of magnitude. The proxy is not
measured MPS/CUDA latency, and neither corpus proves retrieval quality. Runtime-resolved,
`deduplicate=none` NFCorpus comparisons are the next gate.

== NFCorpus neural quality gate

The official NFCorpus test split (3,633 documents, 323 queries and 12,334 positive document
relations) was rebuilt with `deduplicate=none`. Every corpus is complete-source and asserts zero
truncation. Passages and role-correct queries were embedded serially with pinned weights on
PyTorch/MPS (`device=mps:0`, float32 shards), then scored by exact normalized float32 inner
product. Metrics are macro source-collapsed document metrics over every qrels query; ANN and uint8
transport effects are excluded.

[cols="2,1,1,1,1,1",options="header"]
|===
|Candidate |Rows |f32 vector payload |NDCG@10 |Recall@10 |MRR@10
|BGE base v1.5, 480/72, 768-d |4,145 |12,733,440 B |0.3757 |0.1778 |0.5758
|Nomic v1.5, 480/72, 256-d |4,180 |4,280,320 B |0.3260 |0.1527 |0.5207
|Nomic v1.5, 2,048/307, 256-d |3,647 |3,734,528 B |0.3239 |0.1488 |0.5150
|===

Nomic-480 saves 66.4% of raw vector payload versus BGE but is 13.2% lower in NDCG@10 and
14.1% lower in Recall@10. Increasing Nomic to 2,048 tokens removes 12.8% of its rows but slightly
reduces every reported @10 quality metric. Its maximum rendered document is 1,259 tokens, so 2,048
already reaches the one-document-per-source floor; a 7,936-token NFCorpus neural run is redundant.
The evidence rejects a default switch to Nomic-256 and rejects context capacity as a chunk target.
Nomic remains a storage-oriented candidate where workload-specific qrels meet the quality gate.

== Quality and adoption gate

No model or chunk size becomes a default from row economics alone. Candidates advance only if a
shared source/span qrels set demonstrates acceptable Recall@k/NDCG, citation span precision,
generator input payload and policy granularity. The first full neural embeddings are reserved for
the Pareto shortlist plus BGE as the forensic control. xCatalog approval should bind the immutable
model/runtime contract, corpus/evaluation hashes and measured lifecycle envelope; it should not
encode a mutable model-family default in data-plane code.
