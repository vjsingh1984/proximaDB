== Release Scope Decision

MVP is shippable only as a **narrow single-node release**:

* Supported: canonical REST/gRPC v2 record CRUD, vector search, typed filters, schema-aware records,
  core WAL-backed write path, compatibility v1 adapters where they lower into the canonical path.
* Beta: hybrid retrieval, document/graph/observability, pgwire/federated SQL, object-economy vector
  route, filtered ANN routing, security runtime, time-series/event foundations.
* Experimental/defer: distributed cluster execution, PULSAR/QUASAR production claims, full SQL
  parity, external-table execution, Arrow/gRPC multiplexing, conditional/filter writes.

Do not cut the release with docs or dashboards claiming broader production readiness than
`docs/SUPPORTED_SURFACE.adoc`.

== Architecture Grounding

[source,text]
----
Client APIs
  |
  +-- REST/gRPC v2 records --------------+
  |                                      |
  +-- v1 compatibility adapters ---------+--> ProximaRecord + xCatalog + canonical WAL
  |                                      |              |
  +-- pgwire / federated SQL (Beta) -----+              v
                                                storage layouts / projections
                                                SST, VIPER, HELIX, NOVA, HNSW,
                                                object-economy directory, graph/doc/obs

Release rule:
  canonical authority can be Supported;
  projections are Supported only when freshness, recovery, EXPLAIN, and tests are wired;
  otherwise they remain Beta or Experimental.
----

== Code Evidence Snapshot

[cols="2,2,3", options="header"]
|===
| Area | Evidence | Release interpretation

| Route health
| `src/network/rest/v2/collections.rs` reports filtered ANN, writes, freshness, object economy,
  recall probe, pinning, and degraded reasons.
| Good MVP diagnostic surface. Keep `stability: experimental` unless the schema is frozen.

| Writes
| `WriteContractHealth` marks insert/upsert/update/delete true and conditional/filter/patch false.
| MVP can ship CRUD, but conditional writes and update/delete-by-filter must be deferred or hidden.

| Freshness
| `VectorFreshnessMode` supports Strong/BoundedStale/StaleOk and search can merge WAL delta based on
  directory watermarks.
| Per-request freshness is usable; collection-default freshness is not catalog-wired.

| Filtered ANN
| `AxisManager::query_hnsw_with_predicate` evaluates ID filters and record metadata during HNSW
  traversal, then residual-verifies and records shortfall.
| Correctness is better than post-filter-only. Still no default metadata pushdown candidate set or
  published recall envelope.

| Object economy
| SST object-economy directory sidecar, cache, route hints, budget checks, and WAL delta merge are
  present.
| Opt-in Beta. Route needs cataloged selection, bytes/read metrics, and cold-object benchmarks for
  production positioning.

| Recall probe
| `RecallProbeGate` exists and REST debug explain can read gate state.
| Gate consultation is not on the main search route selection path; keep as diagnostic/Beta.

| SQL/federated
| Multiple code paths return explicit "not yet supported"/"not wired" errors for relational,
  external table, subquery vector source, distributed remote, and advanced SQL features.
| Beta only. MVP release notes must name supported SQL subset.

| Test gaps
| Live-server parity and several benchmark/recall tests are ignored/manual; v2 insert/search index
  E2E still has an ignored pre-existing gap.
| Need a release smoke suite that runs without a pre-existing server plus one manual/live suite.
|===

== MVP Blockers

[cols="1,3,3", options="header"]
|===
| Priority | Blocker | Required before release cut

| P0
| Public docs still contain stale or overbroad MVP/production claims.
| Update `SUPPORTED_SURFACE`, `MASTER_FEATURE_DASHBOARD`, roadmap README, and release notes so they
  all describe the same supported/beta/experimental scope.

| P0
| Release gate is not explicit.
| Add a single `make release-check` or documented command list covering `cargo fmt`, focused unit
  suites, proto compatibility, REST/gRPC v2 record smoke, route-health smoke, and packaging build.

| P0
| v2 record insert/search contract has an ignored E2E noting insert does not feed v2 search index.
| Either unignore/fix the E2E or document the exact path that is supported for insert-then-search.
  This is a customer-facing vector MVP risk.

| P1
| Route-health exposes unsupported write modes but APIs/protos contain optimistic version fields.
| Release notes and API docs must explicitly say optimistic version/conditional/filter writes are
  not supported in MVP.

| P1
| Filtered ANN has no differential recall gate.
| Add deterministic exact-vs-ANN tests for low/medium/high selectivity and keep ADR-011 Beta until
  those pass.

| P1
| Object-economy route lacks cold/warm benchmark evidence.
| Add a small benchmark/report that records estimated GETs, actual range reads, bytes, cache state,
  latency, and recall for SST object-economy route.

| P1
| Collection-level freshness defaults are not catalog-wired.
| Either implement catalog default freshness mode or document that freshness is per request only.

| P2
| Recall probe gate is diagnostic, not route-enforcing.
| Wire the gate into quantized-route selection before claiming automated recall guardrails.

| P2
| Broad SQL, graph, document, observability, distributed, and external-table gaps remain.
| Keep them Beta/Experimental and create scoped post-MVP tickets rather than expanding release scope.
|===

== Recommended Release-Cut Checklist

1. Freeze product scope to `docs/SUPPORTED_SURFACE.adoc`.
2. Fix or quarantine stale docs listed above.
3. Run:
   * `cargo fmt`
   * `cargo test --lib route_health`
   * `cargo test --lib query_optimizer`
   * `cargo test --lib vector_hints_from_search_plan_hints_preserves_ann_reason`
   * `cargo test --lib object_economy_directory`
   * `cargo test --lib graph::merge`
   * `cargo test --test graph_branch_merge_integration_test`
   * `cargo test --test grpc_hybrid_integration_test`
   * `make proto-check`
   * one release build of `proximadb-server`
4. Add one non-ignored REST/gRPC v2 record smoke that creates a collection, inserts records, searches,
   reads route-health, and deletes/tombstones a record.
5. Publish release notes with the supported/beta/experimental split and known limitations.
