= Restart-under-load verification (2026-07-24) — production-resilience package
:toc:

Dated artifact for the feat/restart-resilience package (TD-CACHE-1 S1+S2
restart warming, TD-CACHE-3 S1 tenant threading + admission floors,
TD-LIFECYCLE-1 bounded runtime teardown). Harness:
`scripts/bench/restart_under_load_verify.py`. Bed: SIFT 100k (128d,
Euclidean), local macOS arm64, release build, REST e2e on 5678,
`PROXIMADB_PAX_COALESCED_RABITQ=1 PROXIMADB_PAX_VECTOR_QUANT=rabitq`,
config `/tmp/restart-bed.toml` (file://, `flush_interval_secs=10`,
`flush_floor_predicted_mb=1` so the bed materializes segments). Indicative
dev-machine run, not an SLA.

== Protocol and results

1. Ingest 100k (streaming, 1000/batch) → timer flush → L0+L1 `.pax` segments.
2. Steady state, c=8 closed-loop 30 s: **3,701 QPS, p50 1.9 ms, p95 3.7 ms**
   (111,039 queries, 0 errors).
3. SIGTERM under load: clean shutdown sequence, **warm manifest persisted
   (tenant=default, 579 entries)** at
   `sst/data/default/manifests/warm_cache.json` (DrPathBuilder tenant-system
   prefix).
4. Relaunch + immediate c=8 load: **recovery in window 0** — first-second p95
   3.2 ms ≤ 2× steady-state p95 (target: within 10 s); 0 errors across the
   25 s post-restart sweep. Boot log: `restart cache warming complete
   tenants=1 ranges=579` (all manifest entries replayed inside the tenant's
   `io_trace` scope). A follow-up boot on the same bed replayed 1,092 ranges
   and prefilled `segments=1` control-invariants set (the earlier
   `segments=0` was the benign already-warmed-by-recovery race, now
   distinguished in logs at debug level).
5. Second SIGTERM: **clean process exit** (TD-LIFECYCLE-1 `shutdown_timeout`
   mitigation) and a fresh 1,092-entry manifest for the next boot.

== Caveats

* Local-SSD bed: cold-vs-warm latency is indistinguishable at file:// speeds,
  so this run verifies the warming *mechanics* (manifest emit → replay →
  prefill, tenant-scoped keys/metering, clean exit), not the object-store
  latency win. The GET-avoidance claim at object-store latencies rides on the
  measured per-range GET counts: 579–1,092 replayed ranges ≈ the manifest
  budget, versus an unbounded cold herd re-paying the full chain per query.
* Found and filed during this verification: TD-LIFECYCLE-1 (leaked shutdown
  senders block process exit; `sample` evidence in the TD), and the warm-tier
  cache multi-instance bug (9 armings = 9 disjoint budget pools; fixed in
  this package by process-global singleton caches — the shutdown emitter had
  been reading an instance no query ever touched).
