= TD-RDSTRAT-8 SIFT IVF2 coarse-probe gate (2026-07-22)

== Purpose
The TD-RDSTRAT-8 PR-B acceptance evidence: at SIFT scale, the two-level IVF
coarse probe (default-OFF, `PROXIMADB_IVF2_PROBE`) holds recall and engages
correctly on a v3 segment built by the **production compaction trigger**. Also
records whether default-on is justified at this scale.

== Method
N=100,000 SIFT vectors (first 100k of `sift_base.fvecs`), 100 queries, top-10,
Euclidean, in-test brute-force ground truth. The v3 segment is built by the
production compaction trigger — `workload_profile:append` + `l0_threshold:2`
⇒ compaction runs inline on the 2nd flush under `PROXIMADB_IVF2=1`,
`PROXIMADB_IVF_K=64` (the same path `sst_ivf2_compaction_route_proof_test`
proves). Baseline (probe OFF, whole-region scan) vs probe (ON, nprobe=16/64)
search the SAME v3 segment; each phase is wrapped in an `io_trace` scope.

Reproduce:
----
PROXIMADB_SIFT_DATASET_DIR=$HOME/sift1m PROXIMADB_SIFT_N=100000 \
PROXIMADB_SIFT_QUERIES=100 cargo test --release --test sift_pax_recall_ratchet_test \
  sift_ivf2_coarse_probe_recall_ratchet -- --ignored --nocapture
----

== Result
[cols="1,4,4,4", options="header"]
|===
| phase | recall@10 | range_gets/q | bytes/q
| baseline (probe OFF) | 0.9820 | 13 | 6,258,456
| probe (ON)           | 0.9800 | 22 | 3,820,034
|===

Probe engagement: Σcells_total=6400, Σcells_probed=1600 (nprobe=16 of 64),
Σfetch_rounds=799 over 100 queries — the probe ranked the coarse cells in RAM
and ranged only the 16 nearest cells' Region-A extents.

== Findings

1. **Recall held** (0.9820 → 0.9800, drop 0.002): reading only nprobe=16 of 64
   cells loses essentially nothing at this config. The probe is not lossy.
2. **Bytes cut 39%** (6.26 MB → 3.82 MB/q): the probe reads a strict subset of
   Region-A — the bandwidth / GB-month win.
3. **GETs increased** (13 → 22/q): the probe *fragments* Region-A into more,
   smaller ranged reads. The coalesced whole-region baseline is already
   GET-optimal at this scale (single-file, ~13 GETs). GET round-trips are the
   dominant cloud cost term (CLAUDE.md co-design mandate), so the probe does
   **not** improve GETs at N=100k.

== Default-on decision

**NOT justified at N=100k** — GETs (the dominant cost) went *up*. The probe's
GET win is expected only at larger N, where the baseline GET count (≈51 at 1M,
per `coalesced_rabitq_noivf_decisive_sift1m`) is high enough that probing a
subset outweighs the fragmentation. A 1M-scale GET-cut gate is the follow-up
before any default-on flip; the probe stays default-OFF.

This is the "trace before you tune" discipline paying off: the gate measured
that the probe — while recall-neutral and bytes-positive — is GET-negative at
this scale, preventing a premature default-on flip.

Indicative dev-machine run (macOS arm64), not an SLA. Governed by the
`BENCHMARK_EVIDENCE.toml` claim `rdstrat8_sift_ivf2_coarse_probe`.
