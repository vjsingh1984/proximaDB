= TD-SEARCH-2 S2 morsel-rank cold sweeps (2026-07-25)
:toc:

Dated artifact for the S2 multi-core Stage-A rank. Harness:
`scripts/bench/morsel_cold_sweep.py` (A/B via `PROXIMADB_SEARCH_MORSEL_DEGREE`).
Bed: SIFT 1M, production flush floor (3 L0 `.pax` segments), local macOS arm64
(10-core Apple Silicon, 64 GB), release build, REST e2e on 5678, coalesced
RaBitQ ON. Cold = never-repeated query slices per concurrency level; each mode
is a fresh server launch. Indicative dev-machine runs, not an SLA.

== Runs

Three sweep sessions (machine variance is the story — see conclusions):

|===
| run | mode | c=1 QPS/mean | c=4 QPS | c=8 QPS | c=16 QPS | recall@10

| 1 | degree=1 (baseline) | 5.8 / 174 ms | 21.0 | 29.7 | 35.5 | 0.9880
| 1 | adaptive (cores/inflight) | 10.4 / 96 ms | 35.0 | 34.3 | 32.3 | 0.9880
| 2 | adaptive (cores/(inflight+1)) | 7.5 / 132 ms | 19.8 | 20.4 | 21.5 | 0.9860
| 3 (paired) | degree=1 (baseline) | 5.9 / 168 ms | 23.3 | 26.4 | 24.1 | 0.9880
| 3 (paired) | adaptive (cores/(inflight+1)) | 10.7 / 93 ms | 21.4 | 19.9 | 18.3 | 0.9860
| 4 (shipped posture) | adaptive (lone-query only) | 9.7 / 103 ms | 18.1 | 26.8 | 22.1 | 0.9880
|===

Run 4 is the shipped default (`inflight == 1 → all cores, else sequential`):
the c=1 win holds (~1.8×), c=8/c=16 sit at baseline parity inside the noise
band (26.8 vs 26.4–29.7; 22.1 vs 24.1–35.5), recall identical to baseline.

== Conclusions (what the data actually supports)

1. **The lone-query win is stable and reproducible**: c=1 cold 5.8–5.9 →
   10.4–10.7 QPS, mean 174/168 → 96/93 ms, p95 254/193 → 116/110 ms — ~1.8×
   in every session, regardless of formula. This is the S2 deliverable: the
   interactive cold-latency floor the 2-segment flush-floor layout ceded.
2. **Concurrency-sharing formulas are unresolvable on this box**: baseline
   itself swung 35.5 → 24.1 QPS at c=16 across sessions (±30%), larger than
   any formula's effect; matched pairs showed regressions both with and
   without arrival-headroom bias. Shipped posture: morsels ONLY when the scan
   is alone in flight; any concurrency runs the sequential baseline path —
   zero throughput risk, all upside retained where it is provable.
3. **Recall**: 0.9880 vs 0.9860 (Δ = 1 hit in 500) — tie-score reordering at
   the survivor-pool boundary when chunks merge (the equivalence proof is
   exact for distinct scores; ties are order-dependent in both paths). Both
   clear the 0.984 ratchet.
4. Correctness is pinned by `chunked_rank_range_scored_matches_full_rank`
   (block-format): per-chunk top-pool merge ≡ sequential rank, degrees
   {2,3,7} × {L2, Cosine}.
