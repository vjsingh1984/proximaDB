= Graph API Canonical Schema Specification
:toc: left
:toclevels: 3
:icons: font

== Overview

This document defines the canonical schema for Graph API responses to ensure consistency between REST and gRPC protocols. All implementations should conform to these specifications.

== Design Principles

1. **Protocol Agnosticism**: Schema definitions should be implementable in both REST (JSON) and gRPC (protobuf)
2. **Timestamp Standardization**: Use ISO 8601 strings for human readability in REST, with millisecond precision
3. **Consistent Wrapping**: All responses include success indicator and optional error information
4. **Type Safety**: Properties use well-defined types with explicit null handling

== Canonical Response Wrapper

All API responses MUST use a consistent wrapper structure:

[source,json]
----
{
  "success": true,
  "data": { ... },
  "error": null,
  "metadata": {
    "request_id": "uuid",
    "execution_time_ms": 42
  }
}
----

.Response Wrapper Fields
|===
| Field | Type | Required | Description

| `success`
| boolean
| Yes
| Whether the operation succeeded

| `data`
| object/array
| No
| Response payload (null on error)

| `error`
| ErrorInfo
| No
| Error details (null on success)

| `metadata`
| ResponseMetadata
| No
| Optional execution metadata
|===

== Node Schema

=== Canonical Node Structure

[source,json]
----
{
  "id": "node_123",
  "labels": ["Person", "Employee"],
  "properties": {
    "name": "Alice",
    "age": 30,
    "active": true
  },
  "embedding": {
    "version": 1,
    "vector": [0.1, 0.2, 0.3]
  },
  "created_at": "2025-01-02T12:34:56.789Z",
  "updated_at": "2025-01-02T12:34:56.789Z"
}
----

.Node Fields
|===
| Field | Type | Required | Description

| `id`
| string
| Yes
| Unique node identifier

| `labels`
| string[]
| No
| Node labels/types (default: empty array)

| `properties`
| object
| No
| Key-value properties (default: empty object)

| `embedding`
| EmbeddingVersion
| No
| Optional vector embedding

| `created_at`
| string (ISO 8601)
| Yes
| Creation timestamp

| `updated_at`
| string (ISO 8601)
| Yes
| Last update timestamp
|===

=== Property Value Types

Properties MUST use these JSON types:

[source,json]
----
{
  "string_property": "value",
  "integer_property": 42,
  "float_property": 3.14,
  "boolean_property": true,
  "null_property": null,
  "array_property": [1, 2, 3],
  "object_property": {"nested": "value"},
  "vector_property": [0.1, 0.2, 0.3]
}
----

== Edge Schema

== Operation Responses

=== Single Entity Operations

For create, get, update, delete operations on a single node/edge:

[source,json]
----
{
  "success": true,
  "data": {
    "id": "node_123",
    "labels": ["Person"],
    "properties": {"name": "Alice"},
    "created_at": "2025-01-02T12:34:56.789Z",
    "updated_at": "2025-01-02T12:34:56.789Z"
  },
  "error": null
}
----

=== Batch Operations

For batch create, update, delete operations:

[source,json]
----
{
  "success": true,
  "data": {
    "created_count": 10,
    "updated_count": 0,
    "failed_count": 2,
    "results": [
      {"id": "node_1", "labels": ["Person"], ...},
      {"id": "node_2", "labels": ["Person"], ...}
    ],
    "errors": [
      {"id": "node_failed", "error": "Duplicate ID", "code": "DUPLICATE_ID"}
    ]
  },
  "error": null
}
----

.Batch Response Fields
|===
| Field | Type | Required | Description

| `created_count`
| integer
| Yes
| Number of entities created

| `updated_count`
| integer
| Yes
| Number of entities updated

| `failed_count`
| integer
| Yes
| Number of failed operations

| `results`
| Node[]/Edge[]
| Yes
| Successfully created/updated entities

| `errors`
| BatchError[]
| Yes
| Details of failed operations
|===

=== Query Operations

For node/edge queries with pagination:

[source,json]
----
{
  "success": true,
  "data": {
    "items": [
      {"id": "node_1", ...},
      {"id": "node_2", ...}
    ],
    "total_count": 100,
    "has_more": true,
    "next_token": "offset:10"
  },
  "error": null
}
----

.Query Response Fields
|===
| Field | Type | Required | Description

| `items`
| Node[]/Edge[]
| Yes
| Query results

| `total_count`
| integer
| No
| Total matching entities (if available)

| `has_more`
| boolean
| Yes
| Whether more results exist

| `next_token`
| string
| No
| Continuation token for pagination
|===

== Traversal Response

[source,json]
----
{
  "success": true,
  "data": {
    "nodes": [...],
    "edges": [...],
    "paths": [
      {
        "node_ids": ["a", "b", "c"],
        "edge_ids": ["e1", "e2"]
      }
    ],
    "stats": {
      "nodes_visited": 100,
      "edges_traversed": 250,
      "max_depth_reached": 3,
      "execution_time_ms": 42
    }
  },
  "error": null
}
----

.Traversal Response Fields
|===
| Field | Type | Required | Description

| `nodes`
| Node[]
| Yes
| Visited nodes

| `edges`
| Edge[]
| Yes
| Traversed edges

| `paths`
| Path[]
| No
| Discovered paths (if requested)

| `stats`
| TraversalStats
| No
| Execution statistics
|===

=== Path Structure

[source,json]
----
{
  "node_ids": ["node_1", "node_2", "node_3"],
  "edge_ids": ["edge_1", "edge_2"]
}
----

== Shortest Path Response

[source,json]
----
{
  "success": true,
  "data": {
    "path": ["node_1", "node_2", "node_3"],
    "total_weight": 2.5,
    "found": true
  },
  "error": null
}
----

.Shortest Path Fields
|===
| Field | Type | Required | Description

| `path`
| string[]
| Yes
| Node IDs in order (empty if not found)

| `total_weight`
| number
| No
| Sum of edge weights

| `found`
| boolean
| Yes
| Whether a path was found
|===

== Error Response

[source,json]
----
{
  "success": false,
  "data": null,
  "error": {
    "code": "NOT_FOUND",
    "message": "Node 'xyz' not found",
    "details": {
      "entity_type": "node",
      "entity_id": "xyz"
    }
  }
}
----

=== Standard Error Codes

|===
| Code | HTTP Status | Description

| `NOT_FOUND`
| 404
| Entity not found

| `ALREADY_EXISTS`
| 409
| Entity already exists (duplicate)

| `INVALID_ARGUMENT`
| 400
| Invalid request parameters

| `CONSTRAINT_VIOLATION`
| 409
| Violates unique constraint

| `INTERNAL_ERROR`
| 500
| Internal server error

| `TIMEOUT`
| 504
| Operation timed out

| `PERMISSION_DENIED`
| 403
| Insufficient permissions
|===

== Timestamp Handling

=== Format Specification

All timestamps MUST use ISO 8601 format with millisecond precision:

[source]
----
YYYY-MM-DDTHH:mm:ss.sssZ
----

Example: `2025-01-02T12:34:56.789Z`

=== Conversion Rules

|===
| Source | Target | Conversion

| Unix timestamp (ms)
| ISO 8601 string
| `DateTime::from_timestamp_millis(ms).format("%Y-%m-%dT%H:%M:%S%.3fZ")`

| ISO 8601 string
| Unix timestamp (ms)
| `DateTime::parse_from_rfc3339(s).timestamp_millis()`
|===

== Implementation Checklist

=== REST API Changes

* [ ] Update node/edge handlers to use canonical wrapper
* [ ] Standardize timestamp format in all responses
* [ ] Use `items` field for query results (not `data` array directly)
* [ ] Add `has_more` and `next_token` to query responses
* [ ] Use `path` field for shortest path (not `node_ids`)
* [ ] Include `stats` in traversal responses

=== gRPC API Changes

* [ ] Add response wrapper messages to proto
* [ ] Convert timestamps to ISO 8601 in service layer
* [ ] Align field names with REST (e.g., `path` not `node_ids`)
* [ ] Include `success` flag in all responses
* [ ] Add standard error codes to proto

=== Shared Type Definitions

Create shared Rust types that can be used by both REST and gRPC:

[source,rust]
----
/// Canonical node representation
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CanonicalNode {
    pub id: String,
    pub labels: Vec<String>,
    pub properties: HashMap<String, serde_json::Value>,
    pub embedding: Option<EmbeddingVersion>,
    pub created_at: String,  // ISO 8601
    pub updated_at: String,  // ISO 8601
}

/// Canonical response wrapper
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct GraphResponse<T> {
    pub success: bool,
    pub data: Option<T>,
    pub error: Option<GraphError>,
    pub metadata: Option<ResponseMetadata>,
}
----

== Migration Strategy

1. **Phase 1**: Add canonical types alongside existing types
2. **Phase 2**: Update REST handlers to use canonical types
3. **Phase 3**: Update gRPC service layer to convert to canonical
4. **Phase 4**: Deprecate old response formats
5. **Phase 5**: Remove deprecated code
