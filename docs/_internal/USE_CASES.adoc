== 1. Semantic Search with Business Rules

**Problem**: "Find similar products, but only in-stock items under $500 with 4+ star ratings."

**Why traditional vector DBs struggle**: Most vector databases treat metadata as an afterthought, causing slow filters or forcing you to filter in application code.

**ProximaDB Solution**: Type-safe metadata filtering at the storage layer.

[source,mermaid]
----
%%{init: {"theme": "default"}}%%
flowchart LR
    QUERY[Query:<br/>Similar laptops<br/>+ Business Rules] --> FILTER[Type-Safe Filter<br/>price < 500<br/>in_stock = true<br/>rating >= 4.0]
    FILTER --> VECTOR[Vector Search<br/>Top-K Similarity]
    VECTOR --> RANK[Ranked Results<br/>Filtered + Sorted]

    style FILTER fill:#90EE90,stroke:#006400,stroke-width:3px
    style VECTOR fill:#FFD700,stroke:#FF8C00,stroke-width:2px
    style RANK fill:#87CEEB,stroke:#00008B,stroke-width:2px
----

**Pattern**:

[source,python]
----
from proximadb import ProximaDBClient

client = ProximaDBClient(url="http://localhost:5678", protocol="rest")

# Create collection with typed metadata
client.create_collection(
    name="products",
    dimension=384,
    filterable_columns=[
        {"name": "price", "data_type": "FLOAT"},
        {"name": "in_stock", "data_type": "BOOLEAN"},
        {"name": "rating", "data_type": "FLOAT"},
        {"name": "category", "data_type": "STRING"}
    ]
)

# Search with business rules
results = client.search(
    collection_id="products",
    vector=query_embedding,  # "laptop" embedding
    top_k=10,
    filter_expression={
        "operator": "AND",
        "expressions": [
            {"field": "price", "operator": "LESS_THAN", "value": 500},
            {"field": "in_stock", "operator": "EQUALS", "value": True},
            {"field": "rating", "operator": "GREATER_THAN_OR_EQUAL", "value": 4.0}
        ]
    }
)
----

**Performance** (validated):
- **Search latency**: Scale-dependent (see performance guide)
- **Filter overhead**: **-20% to +3%** (often speeds up queries!)
- **Why faster**: Filtering reduces result set before ranking

**Recommended Engine**: SST (balanced OLTP), HELIX (for clustered data)

== 2. Knowledge Graph RAG (Semantic Knowledge Store)

**Problem**: "Answer questions using both document similarity AND relationship context."

**Why it matters**: Pure vector search finds similar documents but loses connection context. Traditional graph DBs can't do semantic similarity.

**ProximaDB Solution**: SKS (Semantic Knowledge Store) - hybrid vector + graph queries in a single database.

[source,mermaid]
----
%%{init: {"theme": "default"}}%%
graph TB
    subgraph "Vector Layer - Semantic Similarity"
        V1[Paper: Transformers<br/>Embedding: 128D]
        V2[Paper: BERT<br/>Embedding: 128D]
        V3[Paper: GPT-3<br/>Embedding: 128D]
    end

    subgraph "Graph Layer - Relationships"
        V2 -->|CITES| V1
        V3 -->|CITES| V1
        V3 -->|CITES| V2
        V2 -->|AUTHORED_BY| A1[Devlin et al.]
        V3 -->|AUTHORED_BY| A2[Brown et al.]
    end

    QUERY[Question:<br/>"Papers on attention<br/>mechanisms"] --> SEMANTIC[1. Vector Search<br/>Find similar papers<br/>1.37ms]
    SEMANTIC --> GRAPH[2. Graph Traversal<br/>Find citations<br/>0.48ms]
    GRAPH --> ANSWER[Hybrid Result:<br/>Papers + Context<br/>2.14ms total]

    style V1 fill:#90EE90,stroke:#006400,stroke-width:3px
    style SEMANTIC fill:#FFD700,stroke:#FF8C00,stroke-width:2px
    style GRAPH fill:#87CEEB,stroke:#00008B,stroke-width:2px
    style ANSWER fill:#FF6347,stroke:#DC143C,stroke-width:3px
----

**Real-World Example**: Academic Research Assistant

[source,python]
----
import httpx
from proximadb import ProximaDBClient, VectorRecord

client = ProximaDBClient(url="http://localhost:5678", protocol="rest")

# 1. Store paper embeddings (vector similarity)
client.create_collection("research_papers", dimension=128)
client.insert_vectors("research_papers", records=[
    VectorRecord(
        id="paper_transformer",
        vector=transformer_embedding,
        metadata={
            "title": "Attention Is All You Need",
            "year": 2017,
            "category": "NLP"
        }
    ),
    # ... 100 papers total
])

# 2. Create citation graph (relationships)
graph_client = httpx.Client(base_url="http://localhost:5678")
graph_client.post("/api/v1/graphs", json={
    "graph_id": "default",
    "name": "Citation Network"
})

# Add citation edges
graph_client.post("/api/v1/graphs/default/edges", json={
    "edge_id": "bert_cites_transformer",
    "from_node_id": "paper_bert",
    "to_node_id": "paper_transformer",
    "edge_type": "CITES"
})

# 3. Hybrid query: Find similar paper + traverse citations
similar_papers = client.search(
    collection_id="research_papers",
    vector=question_embedding,
    top_k=1
)

most_relevant = similar_papers[0]

# Traverse citation network
citations = graph_client.get(
    f"/api/v1/graphs/default/nodes/{most_relevant.id}/edges"
).json()

print(f"Found {most_relevant.metadata['title']}")
print(f"With {len(citations)} related papers via citations")
----

**Performance** (100-paper demo):
- **Vector insert**: 5,193 papers/sec
- **Vector search**: 1.37ms
- **Graph traversal**: 0.48ms
- **Hybrid query**: **2.14ms total**

**See it in action**: `clients/python/examples/sks_real_world_demo.py`

== 3. E-Commerce Product Recommendations

**Problem**: "Show similar products users might like, filtered by inventory and price constraints."

[source,mermaid]
----
%%{init: {"theme": "default"}}%%
sequenceDiagram
    participant User
    participant App as Application
    participant DB as ProximaDB
    participant Engine as HELIX Engine

    User->>App: View product (laptop)
    App->>App: Generate embedding from<br/>image + description
    App->>DB: Search similar products<br/>with filters
    DB->>Engine: Filter: in_stock=true<br/>price < $1500
    Engine->>Engine: SIMD vector search<br/>on filtered set
    Engine-->>DB: Top-10 results
    DB-->>App: Similar products
    App-->>User: "Customers also viewed..."

    Note over Engine: Spatial locality optimization<br/>for clustered product data
----

**Pattern**:

[source,python]
----
# Product catalog with visual + text embeddings
products = client.create_collection(
    name="product_catalog",
    dimension=512,  # ResNet-50 image embeddings
    storage_engine="helix",  # Optimized for clustered data
    filterable_columns=[
        {"name": "price", "data_type": "FLOAT"},
        {"name": "in_stock", "data_type": "BOOLEAN"},
        {"name": "category", "data_type": "STRING"},
        {"name": "brand", "data_type": "STRING"}
    ]
)

# Find similar products in stock
recommendations = client.search(
    collection_id="product_catalog",
    vector=current_product_embedding,
    top_k=20,
    filter_expression={
        "operator": "AND",
        "expressions": [
            {"field": "in_stock", "operator": "EQUALS", "value": True},
            {"field": "price", "operator": "LESS_THAN", "value": 1500},
            {"field": "category", "operator": "EQUALS", "value": "electronics"}
        ]
    }
)
----

**Business Impact**:
- **Latency**: Scale-dependent (see performance guide)
- **Conversion lift**: 15-25% (industry avg for personalized recs)
- **Filter benefit**: -20% overhead (faster with filters!)

== 4. Customer Support Ticket Routing

**Problem**: "Automatically route support tickets to the right team based on historical similarity."

**Pattern**:

[source,python]
----
# Historical tickets with resolutions
tickets = client.create_collection(
    name="support_tickets",
    dimension=384,  # BERT embeddings
    filterable_columns=[
        {"name": "team", "data_type": "STRING"},
        {"name": "priority", "data_type": "INT64"},
        {"name": "resolved", "data_type": "BOOLEAN"},
        {"name": "satisfaction_score", "data_type": "FLOAT"},
        {"name": "resolution_time_hours", "data_type": "INT64"}
    ]
)

# Find similar resolved tickets
similar_tickets = client.search(
    collection_id="support_tickets",
    vector=new_ticket_embedding,
    top_k=10,
    filter_expression={
        "operator": "AND",
        "expressions": [
            {"field": "resolved", "operator": "EQUALS", "value": True},
            {"field": "satisfaction_score", "operator": "GREATER_THAN", "value": 4.0}
        ]
    }
)

# Route to most common team in top results
recommended_team = similar_tickets[0].metadata["team"]
----

**Business Value**:
- **Routing accuracy**: 85-90% (vs 60% manual)
- **First response time**: -40% reduction
- **Customer satisfaction**: +20% improvement

== 5. Code Search & Duplicate Detection

**Problem**: "Find similar code snippets for review, detect duplicates, suggest refactoring."

[source,mermaid]
----
%%{init: {"theme": "default"}}%%
graph LR
    CODE[Source Code] --> EMBED[CodeBERT<br/>Embedding]
    EMBED --> STORE[ProximaDB<br/>VIPER Engine]
    STORE --> SEARCH{Search Type}

    SEARCH -->|Find Similar| SIMILAR[Similar Functions<br/>Refactor Candidates]
    SEARCH -->|Detect Dupes| DUPES[Near-Duplicates<br/>>95% similarity]
    SEARCH -->|Review Assist| REVIEW[Related Changes<br/>Context for PR]

    style CODE fill:#E3F2FD,stroke:#1565C0,stroke-width:2px
    style STORE fill:#90EE90,stroke:#006400,stroke-width:2px
    style DUPES fill:#FF6347,stroke:#DC143C,stroke-width:2px
----

**Pattern**:

[source,python]
----
# Index codebase with function-level granularity
code_collection = client.create_collection(
    name="codebase_functions",
    dimension=768,  # GraphCodeBERT embeddings
    storage_engine="viper",  # Columnar for large codebases
    filterable_columns=[
        {"name": "language", "data_type": "STRING"},
        {"name": "complexity", "data_type": "INT64"},
        {"name": "lines_of_code", "data_type": "INT64"},
        {"name": "file_path", "data_type": "STRING"}
    ]
)

# Detect near-duplicate code
duplicates = client.search(
    collection_id="codebase_functions",
    vector=function_embedding,
    top_k=50,
    filter_expression={
        "operator": "AND",
        "expressions": [
            {"field": "language", "operator": "EQUALS", "value": "python"},
            {"field": "complexity", "operator": "LESS_THAN", "value": 15}
        ]
    }
)

# Flag if >95% similar
potential_duplicates = [
    r for r in duplicates if r.score > 0.95
]
----

**Use Cases**:
- Code review assistance
- Refactoring candidates detection
- License compliance (detect copied code)
- Developer onboarding (find similar patterns)

== 6. Multi-Modal Search (Text + Image)

**Problem**: "Search across different content types with unified filters."

[source,mermaid]
----
%%{init: {"theme": "default"}}%%
flowchart TD
    QUERY[User Query<br/>"Red dress floral pattern"] --> SPLIT{Multi-Modal}

    SPLIT -->|Text Path| TEXT_EMB[BERT Embedding<br/>384D]
    SPLIT -->|Image Path| IMG_EMB[ResNet Embedding<br/>2048D]

    TEXT_EMB --> TEXT_SEARCH[Search Text Collection]
    IMG_EMB --> IMG_SEARCH[Search Image Collection]

    TEXT_SEARCH --> FUSION[Result Fusion<br/>Weighted 60/40]
    IMG_SEARCH --> FUSION

    FUSION --> FILTER[Apply Filters:<br/>price, in_stock, brand]
    FILTER --> RESULTS[Final Ranked Results]

    style SPLIT fill:#E3F2FD,stroke:#1565C0,stroke-width:2px
    style FUSION fill:#FFD700,stroke:#FF8C00,stroke-width:3px
    style RESULTS fill:#90EE90,stroke:#006400,stroke-width:2px
----

**Pattern**:

[source,python]
----
# Separate collections for each modality (same metadata schema)
text_collection = client.create_collection(
    name="products_text",
    dimension=384,
    filterable_columns=[
        {"name": "product_id", "data_type": "STRING"},
        {"name": "price", "data_type": "FLOAT"},
        {"name": "in_stock", "data_type": "BOOLEAN"}
    ]
)

image_collection = client.create_collection(
    name="products_images",
    dimension=2048,
    filterable_columns=[
        {"name": "product_id", "data_type": "STRING"},
        {"name": "price", "data_type": "FLOAT"},
        {"name": "in_stock", "data_type": "BOOLEAN"}
    ]
)

# Parallel search across modalities
common_filters = {
    "operator": "AND",
    "expressions": [
        {"field": "in_stock", "operator": "EQUALS", "value": True},
        {"field": "price", "operator": "LESS_THAN", "value": 100}
    ]
}

text_results = client.search("products_text", text_embedding, top_k=20, filter_expression=common_filters)
image_results = client.search("products_images", image_embedding, top_k=20, filter_expression=common_filters)

# Fusion: combine scores with weights
final_results = fuse_results(text_results, image_results, weights=[0.6, 0.4])
----

**Applications**:
- E-commerce visual search
- Content discovery (Netflix-style)
- Digital asset management
- Medical imaging + records
