= Feature Flags

ProximaDB is a highly modular system that uses feature flags to enable or disable functionality at compile time. This allows you to create a binary that is tailored to your specific needs, including only the features you require.

== Building with Features

You can enable features by using the `--features` flag when building with Cargo:

[source,bash]
----
cargo build --release --features "<feature1>,<feature2>"
----

== Available Features

=== Hardware Acceleration

* `gpu`: Enables GPU acceleration. This is a meta-feature that enables the appropriate backend for your platform.
* `metal`: Enables Metal GPU acceleration for Apple Silicon (macOS).
* `simd`: Enables SIMD acceleration for CPU-based vector computations.

Example:
[source,bash]
----
# Build with GPU and SIMD acceleration
cargo build --release --features "gpu,simd"
----

=== Storage Backends

* `rocksdb`: Enables RocksDB as a metadata backend.

Example:
[source,bash]
----
cargo build --release --features "rocksdb"
----

=== Cloud Storage

* `aws`: Enables support for AWS S3.
* `azure`: Enables support for Azure Blob Storage.
* `gcp`: Enables support for Google Cloud Storage.
* `cloud-full`: Enables all cloud storage providers.

Example:
[source,bash]
----
# Build with support for all cloud providers
cargo build --release --features "cloud-full"
----

=== Other Features

* `sql_frontend`: Enables the SQL query frontend. This is enabled by default.
* `distributed`: Enables features for distributed mode.
* `standalone`: Enables features for standalone mode.
