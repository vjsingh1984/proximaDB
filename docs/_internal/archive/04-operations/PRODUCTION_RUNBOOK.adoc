== Quick Start

=== Minimum Production Requirements

[cols="2,3"]
|===
|Resource |Specification

|**CPU**
|4 cores minimum (8+ recommended)

|**Memory**
|8GB minimum (16GB+ recommended)

|**Storage**
|100GB+ SSD/NVMe for data, 50GB for cache

|**Network**
|1Gbps minimum

|**OS**
|Linux (Ubuntu 20.04+, RHEL 8+) or macOS
|===

=== Deployment Options

==== Docker (Recommended)

[source,bash]
----
# Pull and run latest version
docker run -d \
  --name proximadb \
  -p 5678:5678 \
  -p 5679:5679 \
  -v /data/proximadb:/data \
  proximadb/proximadb:latest

# Verify running
curl http://localhost:5678/health
----

==== Kubernetes

[source,bash]
----
# Deploy with Helm
helm repo add proximadb https://charts.proximadb.com
helm install proximadb proximadb/proximadb \
  --set replicas=3 \
  --set storage.size=100Gi

# Check deployment status
kubectl get pods -l app=proximadb
----

==== Binary Deployment

[source,bash]
----
# Download and extract
wget https://releases.proximadb.com/latest/proximadb-linux-x64.tar.gz
tar xzf proximadb-linux-x64.tar.gz

# Run with config
./proximadb-server --config /etc/proximadb/config.toml
----

== Configuration

=== Production Configuration File

Create `/etc/proximadb/config.toml`:

[source,toml]
----
[server]
bind_address = "0.0.0.0"
port = 5678
data_dir = "/data/proximadb"
log_level = "info"

[storage]
metadata_url = "file:///data/proximadb/metadata"

[[storage.storage_locations]]
url = "file:///data/proximadb/d1"
weight = 1

[[storage.storage_locations]]
url = "file:///data/proximadb/d2"
weight = 1

[storage.wal_config]
global_manifest_url = "file:///data/proximadb/manifest"
enable_wal = true
memory_flush_size_bytes = 16777216      # 16MB per-collection
global_flush_threshold = 4294967296     # 4GB total

[api]
grpc_port = 5679
rest_port = 5678

[security]
auth_enabled = true
tls_enabled = true
tls_cert_file = "/etc/proximadb/certs/server.crt"
tls_key_file = "/etc/proximadb/certs/server.key"
----

== Troubleshooting

=== Common Issues

==== Server Won't Start

[source,bash]
----
# Check port availability
lsof -i :5678
lsof -i :5679

# Kill conflicting process
kill -9 $(lsof -t -i :5678)

# Check data directory permissions
ls -la /data/proximadb
chown -R proximadb:proximadb /data/proximadb

# Enable debug logging
export RUST_LOG=debug
./proximadb-server --config /etc/proximadb/config.toml
----

==== High Memory Usage

[source,bash]
----
# Check current memory usage
curl http://localhost:5678/metrics | grep memory

# Reduce cache size in config.toml
[storage]
cache_size_mb = 2048  # Reduce from default 4096

# Restart server
systemctl restart proximadb
----

==== Slow Queries

[source,bash]
----
# Check query performance metrics
curl http://localhost:5678/metrics | grep query_latency

# Enable query logging
export RUST_LOG=proximadb::core::search=debug

# Check cache hit rate
curl http://localhost:5678/metrics | grep cache_hit_rate

# If cache hit rate is low, increase cache size
----

==== WAL Recovery Issues

[source,bash]
----
# View WAL manifest
cat /data/proximadb/manifest/manifest_*.jsonl | jq .

# Check WAL segments
find /data/proximadb -name "*.wal" -ls

# Enable WAL debug logging
export RUST_LOG=proximadb::storage::persistence::write_ahead_log=debug
./proximadb-server --config /etc/proximadb/config.toml
----

==== Disk Space Full

[source,bash]
----
# Check disk usage
df -h /data/proximadb

# Find largest directories
du -sh /data/proximadb/* | sort -hr | head -10

# Clean old backups (if applicable)
find /data/proximadb/backups -type f -mtime +30 -delete

# Compact storage (future feature)
# curl -X POST http://localhost:5678/v1/admin/compact
----

=== Performance Tuning

==== Optimize for Write-Heavy Workloads

[source,toml]
----
[storage]
# Use SST engine for OLTP
default_engine = "sst"

# Increase WAL buffer
[storage.wal_config]
memory_flush_size_bytes = 33554432  # 32MB

# Enable LZ4 compression
[storage.sst_config]
compression = "lz4"
----

==== Optimize for Read-Heavy Workloads

[source,toml]
----
[storage]
# Use VIPER for analytics
default_engine = "viper"

# Increase cache size
cache_size_mb = 8192

# Enable query result caching
enable_query_cache = true
----

==== Optimize for Mixed Workloads

[source,toml]
----
[storage]
# Use NOVA for balanced workloads
default_engine = "nova"

# Configure memory pools
[storage.memory_pool]
pool_size_mb = 2048
vector_pool_size = 1000
----

== Backup and Recovery

=== Manual Backup

[source,bash]
----
# Stop writes (optional, for consistency)
curl -X POST http://localhost:5678/v1/admin/readonly

# Backup data directory
tar czf proximadb-backup-$(date +%Y%m%d).tar.gz /data/proximadb

# Resume writes
curl -X POST http://localhost:5678/v1/admin/readwrite
----

=== Automated Backup with Cron

[source,bash]
----
# Add to crontab
0 2 * * * /usr/local/bin/backup-proximadb.sh

# /usr/local/bin/backup-proximadb.sh
#!/bin/bash
BACKUP_DIR=/backups/proximadb
DATE=$(date +%Y%m%d-%H%M%S)
tar czf $BACKUP_DIR/proximadb-$DATE.tar.gz /data/proximadb
find $BACKUP_DIR -type f -mtime +30 -delete
----

=== Cloud Backup (S3)

[source,bash]
----
# Sync to S3
aws s3 sync /data/proximadb s3://my-backups/proximadb/

# Restore from S3
aws s3 sync s3://my-backups/proximadb/ /data/proximadb/
----

=== Recovery Procedure

[source,bash]
----
# Stop ProximaDB
systemctl stop proximadb

# Restore from backup
tar xzf proximadb-backup-20251217.tar.gz -C /

# Verify data directory
ls -la /data/proximadb

# Start ProximaDB (WAL recovery will run automatically)
systemctl start proximadb

# Monitor logs for recovery progress
tail -f /var/log/proximadb/proximadb.log | grep "WAL recovery"

# Verify collections
curl http://localhost:5678/v1/collections
----

== Security Operations

=== TLS Certificate Management

[source,bash]
----
# Generate self-signed certificate (testing only)
openssl req -x509 -newkey rsa:4096 \
  -keyout /etc/proximadb/certs/server.key \
  -out /etc/proximadb/certs/server.crt \
  -days 365 -nodes

# Install Let's Encrypt certificate (production)
certbot certonly --standalone -d db.example.com
ln -s /etc/letsencrypt/live/db.example.com/fullchain.pem /etc/proximadb/certs/server.crt
ln -s /etc/letsencrypt/live/db.example.com/privkey.pem /etc/proximadb/certs/server.key

# Restart server to load new certificate
systemctl restart proximadb
----

== Incident Response

=== High Latency Alert

[source,bash]
----
1. Check current query latency:
   curl http://localhost:5678/metrics | grep latency

2. Check cache hit rate:
   curl http://localhost:5678/metrics | grep cache_hit

3. If cache hit rate is low:
   - Increase cache size in config
   - Restart server

4. Check resource usage:
   top -p $(pgrep proximadb)

5. If CPU/memory high:
   - Scale vertically
   - Optimize queries
----

=== Service Down Alert

[source,bash]
----
1. Check if process is running:
   systemctl status proximadb

2. If not running, check logs:
   journalctl -u proximadb -n 100

3. Attempt restart:
   systemctl restart proximadb

4. If restart fails, check:
   - Port conflicts: lsof -i :5678
   - Disk space: df -h
   - Permissions: ls -la /data/proximadb

5. If still failing, start in debug mode:
   RUST_LOG=debug /usr/local/bin/proximadb-server --config /etc/proximadb/config.toml
----

=== Data Corruption Alert

[source,bash]
----
1. Stop server immediately:
   systemctl stop proximadb

2. Backup current state:
   cp -r /data/proximadb /data/proximadb-backup-corrupted

3. Check WAL integrity:
   cat /data/proximadb/manifest/manifest_*.jsonl

4. Attempt recovery from last backup:
   systemctl stop proximadb
   rm -rf /data/proximadb
   tar xzf /backups/proximadb-latest.tar.gz -C /
   systemctl start proximadb

5. If recovery successful, verify data:
   curl http://localhost:5678/v1/collections
----

=== Upgrading ProximaDB

[source,bash]
----
# Check current version
curl http://localhost:5678/health | jq .version

# Download new version
wget https://releases.proximadb.com/v0.2.0/proximadb-linux-x64.tar.gz

# Backup current installation
cp /usr/local/bin/proximadb-server /usr/local/bin/proximadb-server.backup

# Stop server
systemctl stop proximadb

# Extract new version
tar xzf proximadb-linux-x64.tar.gz
cp proximadb-server /usr/local/bin/

# Start server (reads existing data, runs migrations if needed)
systemctl start proximadb

# Verify version
curl http://localhost:5678/health | jq .version

# Monitor logs for migration messages
tail -f /var/log/proximadb/proximadb.log
----
