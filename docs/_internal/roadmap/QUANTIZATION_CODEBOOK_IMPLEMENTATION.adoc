== Overview

This document describes the implementation of file-level codebook metadata storage for quantized vectors in ProximaDB. The architecture separates codebook storage from per-row data, optimizing for LSM compaction and reducing redundancy.

== Architecture Design

=== Core Principle

Codebooks are stored as *file-level metadata* rather than per-row columns, providing:

* Efficient LSM compaction without recomputing codebooks
* Reduced storage overhead (one codebook per file vs. per row)
* Better cache efficiency
* Simplified schema management

== Integration Points

=== 1. Flush Operations

During flush, codebooks are extracted from the quantization engine:

[source,rust]
----
// During flush
let codebook_metadata = serializer
    .extract_from_engine(&quantization_engine, collection_id)
    .await?;

// ProximaBlock engines: embed in footer
let file_data = manager
    .write_with_codebook(blocks, index, Some(codebook_metadata))
    .await?;

// Parquet engines: write sidecar
manager.write_sidecar(&parquet_path, &codebook_metadata).await?;
----

=== 2. Search Operations

During search, codebooks are loaded once per file:

[source,rust]
----
// Load codebook for file
let codebook = if let Some(metadata) = manager.read_codebook(&file)? {
    cache.get_or_load(metadata)
} else {
    // Fallback to runtime quantization
    None
};

// Use for all vectors in file
for vector in file.vectors() {
    let distance = compute_with_codebook(query, vector, &codebook);
}
----

=== 3. Compaction

During compaction, codebooks are preserved:

[source,rust]
----
// Merge codebooks from source files
let merged_codebook = manager
    .migrate_during_compaction(&source_files, &target_file, &engine)
    .await?;
----

== Column Schema Updates

=== Before (Per-Row Codebooks)
[source]
----
Columns:
- id (string)
- vector_fp32 (binary)
- q_binary (binary)
- q_int8 (binary)
- q_pq8 (binary)
- cb_pq8 (binary)  ← Removed (redundant per-row storage)
----

=== After (File-Level Codebooks)
[source]
----
Columns:
- id (string)
- vector_fp32 (binary)
- q_binary (binary)
- q_int8 (binary)
- q_pq8 (binary)

File Metadata:
- codebook.pq8 (stored once in footer/sidecar)
----

== Performance Benefits

=== Storage Efficiency
* **Before**: 100MB codebook × 1M vectors = 100TB redundant storage
* **After**: 100MB codebook × 1000 files = 100GB total storage
* **Savings**: 99.9% reduction in codebook storage

=== LSM Compaction
* **Before**: Recompute codebooks during each compaction
* **After**: Copy existing codebooks, no recomputation needed
* **Speedup**: 10-100x faster compaction

=== Memory Usage
* **Before**: Load codebook with every vector
* **After**: Load once per file, share across vectors
* **Reduction**: 1000x less memory for codebooks

== Configuration

Add to `config/config.toml`:

[source,toml]
----
[compute.quantization.codebook]
# Storage strategy
storage_strategy = "file_level"  # file_level or per_row (deprecated)

# ProximaBlock settings
proximablock.placement = "footer"  # footer or header
proximablock.compression = "lz4"   # none, lz4, zstd

# Parquet settings
parquet.sidecar_format = "json"    # json or binary
parquet.sidecar_compression = "none"  # none, gzip

# Cache settings
cache.enabled = true
cache.max_codebooks = 1000
cache.ttl_seconds = 3600
----
