== 1. Cost-Based Query Planner with Runtime Feedback

=== Implemented Components

==== 1.1 Runtime Statistics Collector

Location: `src/query/federated/optimizer/mod.rs:651-777`

**Key Features:**
- `RuntimeStatisticsCollector` - Thread-safe EMA-based feedback accumulator
- `ExecutionFeedback` - Records cardinality, latency, CPU/IO/memory metrics
- Adaptive cost model tuning via exponential moving averages (α=0.2)
- Plan regression detection (invalidates when actual > 3x estimated)

**Statistics Tracked:**
| Metric | Collection Method | Update Strategy |
|--------|------------------|------------------|
| Cardinality ratios | estimated vs actual | EMA α=0.3 (fast adaptation) |
| Latency observations | ms per operation | EMA α=0.2 with P95 tracking |
| Selectivity | rows_scanned / returned | EMA α=0.25 |
| Cost-to-latency ratio | actual_ms / estimated_cost | Used for regression detection |

==== 1.2 Adaptive Cost Model

Location: `src/query/federated/optimizer/mod.rs:443-647`

**Auto-Tuning Parameters:**
- `cpu_cycles_per_distance` - Calibrated from observed hardware
- `io_cost_per_page` - Learned from I/O measurements
- `memory_access_cost` - Adapted from cache behavior

**Calibration Formula:**
[source,rust]
----
new_param = old_param * (1 - α) + observed_value * α
----

==== 1.3 Plan Cache Integration

Location: `src/query/federated/optimizer/mod.rs:1283-1262`

**Enhancements:**
- `PlanCacheKey` now includes extension collection targets (not just query.targets)
- `record_execution_time()` tracks EMA of execution latency
- Automatic invalidation on performance regression

**Example:**
[source,sql]
----
SELECT * FROM VECTOR_SEARCH('products', '[0.1]', 5)
----
Cache key now includes: `"products"` + normalized_sql + query_type

   - Node counts: 1K, 10K, 100K
