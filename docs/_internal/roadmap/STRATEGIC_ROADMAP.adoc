== Vision Alignment

This roadmap implements the three-phase approach from link:../../concepts/vision.adoc[Vision Document]:

* **Phase 1**: Format and Catalog Contract (Foundation)
* **Phase 2**: Cross-Model Query and Indexing (Differentiation)
* **Phase 2.5**: Foundational Performance Alignment (Execution Layer) -- _added March 2026_
* Phase 3: Deployment and Ecosystem Integration (Scale)
* Phase 4: Context Database Evolution (Time-Series, Event Sourcing, Hybrid Search)
* Phase 5: Agentic Intelligence & Research Frontier (2026 Strategy)

== Phase 2.5: Foundational Performance Alignment [📅 NEW]

[.lead]
_Performance Credibility: Align the execution layer between storage and API with single-node analytical system patterns (DuckDB, Polars). Without this, columnar analytics and cross-model query performance claims are not substantiable._

[IMPORTANT]
====
Added March 21, 2026 based on architectural review (`ARCHITECTURAL_REVIEW_2026_03_21.adoc`).
The storage layer (ProximaCodec, Parquet integration, WAL) is production-grade.
The gap is in the *query execution layer above storage* -- the layer that turns columnar storage into fast analytical queries and eliminates format conversion at model boundaries.
====

=== Vectorized Execution Engine [📅 Phase 2.5 -- CRITICAL]

|===
| Feature | Status | Priority | Notes

| DataChunk-based physical operators
| 📅 Phase 2.5
| P0
| 2048-value chunks fitting L2 cache. Pull-based pipeline with `next_chunk()`. Selection vector (bitmap) pattern instead of row copying. (TD-031)

| Selection vector filtering
| 📅 Phase 2.5
| P0
| Evaluate predicates on entire arrays (SIMD auto-vectorizable). Maintain bitmap through pipeline. Late materialization -- read column values only after filtering.

| Pipeline-based execution
| 📅 Phase 2.5
| P0
| Decompose query plan into pipelines separated by breakers (sort, aggregate, hash-build). Each pipeline processes morsels through full operator chain.

| Re-enable adaptive filter executor
| 📅 Phase 2.5
| P1
| `adaptive_filter_executor.rs` disabled due to API changes. Re-implement against current Arrow/Parquet API.
|===

=== Row Group Statistics Pruning [📅 Phase 2.5 -- HIGH]

|===
| Feature | Status | Priority | Notes

| Numeric statistics pruning
| 📅 Phase 2.5
| P0
| Use Parquet typed statistics API (`Statistics::Int64`, `Statistics::Float`, etc.) for proper comparison. Currently returns `true` for all row groups on numeric filters. (TD-033)

| Page-level statistics
| 📅 Phase 2.5
| P1
| Within pruned row groups, skip individual data pages using page-level statistics (Parquet v2).

| Bloom filter predicate resolution
| 📅 Phase 2.5
| P2
| For dictionary-encoded columns, resolve predicates against dictionary before decoding data.
|===
