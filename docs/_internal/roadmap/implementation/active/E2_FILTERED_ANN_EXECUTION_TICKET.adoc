== Problem Statement

The current vector path has multiple gaps between filter intent and live index execution:

* v1 search requests can build a `FilterExpression`, but that intent is not consistently carried into AXIS query objects
* `HybridQuery` is still created with empty `metadata_filters` and `id_filters` on key live paths
* AXIS owns a metadata index and filter-capable types, but filtered execution is not coherently used end-to-end
* benchmark and regression coverage for filtered ANN correctness is still incomplete

== Goals

* Normalize filter intent exactly once and lower it to candidate-set semantics.
* Ensure the canonical AXIS path receives metadata and ID constraints when the request contains them.
* Establish a retrieval pipeline that is both correct and benchmarkable:
** filter normalization
** candidate generation
** ANN search
** exact rerank
** MVCC and metadata verification
* Add exact-baseline comparisons and recall gates for approximate search.

== Non-Goals

* cross-model physical indexes
* learned retrieval policies
* new ANN algorithms outside what AXIS already supports

== Milestones

=== M1: Filter Normalization and Query Builder

Scope:

* define `NormalizedFilter` and `CandidateSet`
* lower `FilterExpression` into AXIS `MetadataFilter` and ID predicates
* centralize `HybridQuery` construction

Exit criteria:

* canonical vector lookups no longer construct filtered queries with empty filter fields when filters are present

=== M2: Candidate Pipeline Through AXIS

Scope:

* combine metadata index, bloom, and exact-ID restrictions into a candidate-set stage
* apply candidate restrictions intentionally in HNSW and IVF execution paths
* expose diagnostics for candidate counts and index choice

Exit criteria:

* AXIS filtered search is materially distinct from unfiltered ANN plus late full-scan filtering

=== M3: Differential Correctness and Benchmarks

Scope:

* exact-baseline comparison suite
* recall thresholds for filtered ANN
* selective-filter benchmark harness

Exit criteria:

* correctness and performance claims for filtered ANN are backed by repeatable artifacts

== Implementation Tasks

1. Add `NormalizedFilter`, `CandidateSet`, and a shared `HybridQueryBuilder`.
2. Convert `FilterExpression` into AXIS metadata and ID filters on the canonical vector path.
3. Update AXIS manager to perform candidate generation before ANN search where supported.
4. Implement post-filter verification and exact rerank contracts consistently across ANN backends.
5. Replace placeholder filtered-search tests with differential exact-baseline tests.
6. Add filtered ANN benchmark suites and record expected target envelopes.

== Test Plan

=== Unit Tests

* `FilterExpression` to `NormalizedFilter` lowering
* normalized filter to AXIS `MetadataFilter` lowering
* candidate-set composition across metadata index, bloom, and exact IDs
* HNSW and IVF filtered-search behavior on small deterministic datasets

=== Integration Tests

* v1 REST vector search with metadata filters produces only matching results
* unified-handler and facade-driven vector search preserve filter intent
* graph-first entity search respects metadata filters on the live path

=== Differential Correctness Tests

* filtered ANN results compared against exact scan baseline
* approximate filtered search measured for recall at multiple selectivity bands
* unsupported operators explicitly fail capability validation rather than degrade silently

=== Benchmarks

* exact filtered scan vs AXIS filtered ANN at low, medium, and high selectivity
* top-k latency and throughput on representative collection sizes
* candidate count, rerank count, and final recall included in benchmark output

== Acceptance Criteria

* The canonical vector path never drops filter intent when building `HybridQuery`.
* Filtered search through AXIS returns only matching results for supported operators.
* Approximate filtered search meets documented recall targets against exact baselines.
* Benchmark artifacts demonstrate a measurable win for filtered ANN on selective queries.

== Risks and Open Questions

* ANN backends may need different candidate-handling strategies; forcing one mechanism too early could add complexity.
* Some filters may remain storage-only initially; these need explicit capability gating.
* Benchmark corpora need to be representative enough to prevent misleading win claims.

== Definition of Done

* M1 through M3 are complete.
* AXIS filtered ANN is correct on the canonical path.
* Differential test and benchmark suites are committed and wired into CI or gated benchmark workflows.
* E3 can rely on one canonical filtered vector operator contract.
