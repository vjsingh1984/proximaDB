== Purpose

This plan is the active bridge between:

* link:../../STRATEGIC_ROADMAP.adoc[Strategic Roadmap]
* link:../../BEST_IN_CLASS_EXECUTION_TRACKER.adoc[Best-in-Class Foundation Execution Tracker]
* Current architecture/code review findings from March 2026

Primary rule:

*Correctness before capability claims; canonical execution paths before new surfaces; foundational semantics before scale work.*

== Problem Statement

The codebase now contains meaningful vector, document, graph, and observability subsystems, but the user-visible product still has foundational coherence gaps:

* Public vector paths can drop metadata filters before execution.
* Document query execution is not complete on the main service path.
* Federated correlated joins and distributed query routing are still partially scaffolded.
* Several roadmap and implementation documents overstate production completeness.

This plan tracks the work needed to close those gaps in a way that survives across sessions.

== March 2026 Active Tranche

=== Tranche A: Foundational Correctness

Status: In Progress

Objectives:

* Preserve vector filters end-to-end on canonical request paths.
* Stop dropping parsed document filters in the facade path.
* Make document queries execute against in-memory/WAL-backed state instead of returning empty results.
* Add unit/regression coverage for those semantics.

Primary files in this tranche:

* `src/query/facade/mod.rs`
* `src/query/facade/adapter.rs`
* `src/query/facade/strategies/vector.rs`
* `src/query/facade/strategies/document.rs`
* `src/services/operations/vectors.rs`
* `src/api_handlers/unified_handlers.rs`
* `src/storage/document/query/mod.rs`
* `src/storage/document/service.rs`

Exit criteria:

* A `VectorSearchRequest` with v1 filters reaches unified search as a non-empty predicate.
* The canonical facade path preserves vector filters from adapter input.
* `DocumentService::query_documents()` returns filtered rows from stored documents.
* Document sorting by JSON path produces deterministic output for supported scalar types.
* New regression tests cover both vector predicate propagation and document query execution.

=== Tranche B: Query Completeness

Status: In Progress

Objectives:

* Implement correlated `LATERAL`/nested-loop join execution for federated plans.
* Replace distributed query facade scaffolding with real parsing/planning and live local execution.
* Tighten graph query executor parity with ORION service capabilities.

Primary files in this tranche:

* `src/query/facade/strategies/distributed.rs`
* `src/query/distributed/coordinator.rs`
* `src/network/multi_server.rs`
* `src/query/federated/*`

Exit criteria:

* The forced distributed facade path is registered in the live `UnifiedQueryFacade`.
* Distributed execution parses federated extension SQL into executable local multi-model components.
* Local distributed subqueries execute through the unified executor instead of returning empty placeholders.
* Function-backed correlated `LATERAL` joins execute through `NestedLoopJoin`.
* Remote distributed execution uses registered handlers instead of returning silent empty placeholders.
* Remaining explicit gaps are the relational scan backend and true node-to-node transport.

== Design Rules

* Add one canonical request model per capability, not multiple partially equivalent ones.
* Do not mark a feature complete if the public path still bypasses it.
* Prefer fixing propagation/wiring bugs before adding new engines or query syntax.
* Keep experimental subsystems behind explicit messaging and opt-in paths.
