**Technical specification for real-time vector streaming in ProximaDB**

== Overview

This specification defines the architecture and implementation plan for real-time streaming capabilities in ProximaDB, enabling continuous vector ingestion and live query updates.

=== Goals

[source,text]
----
Primary Goals:
├── Sub-second ingestion-to-searchability latency
├── Continuous vector streaming via multiple protocols
├── Live query subscriptions with push notifications
├── Backpressure handling for high-volume streams
└── Exactly-once semantics for critical workloads
----

=== Non-Goals

* Batch processing optimization (covered by existing engines)
* Historical replay (covered by CDC specification)
* Cross-region streaming (covered by distributed operations)

== Protocol Definitions

=== gRPC Streaming API

[source,protobuf]
----
syntax = "proto3";

package proximadb.streaming.v1;

service StreamingService {
    // Bidirectional streaming for vector ingestion
    rpc StreamInsert(stream StreamInsertRequest) returns (stream StreamInsertResponse);

    // Server streaming for live query results
    rpc SubscribeQuery(SubscribeRequest) returns (stream QueryUpdate);

    // Client streaming for batch with streaming acks
    rpc BatchStream(stream VectorBatch) returns (BatchStreamResponse);
}

message StreamInsertRequest {
    string collection = 1;
    repeated VectorRecord vectors = 2;
    // Sequence number for ordering
    uint64 sequence = 3;
    // Partition key for ordered delivery
    string partition_key = 4;
}

message StreamInsertResponse {
    // Acknowledged sequence numbers
    repeated uint64 acked_sequences = 1;
    // Backpressure signal
    BackpressureSignal backpressure = 2;
    // Server timestamp
    uint64 server_timestamp = 3;
}

message BackpressureSignal {
    enum Level {
        NONE = 0;
        LOW = 1;
        MEDIUM = 2;
        HIGH = 3;
        CRITICAL = 4;
    }
    Level level = 1;
    // Suggested delay in milliseconds
    uint32 suggested_delay_ms = 2;
    // Current buffer utilization (0-100)
    uint32 buffer_percent = 3;
}

message SubscribeRequest {
    string collection = 1;
    // Query vector for similarity subscription
    repeated float vector = 2;
    uint32 top_k = 3;
    // Minimum score change to trigger update
    float score_threshold = 4;
    // Metadata filter
    Filter filter = 5;
    // Initial snapshot
    bool include_initial = 6;
}

message QueryUpdate {
    enum UpdateType {
        INITIAL = 0;    // Initial snapshot
        INSERT = 1;     // New result entered top-k
        REMOVE = 2;     // Result left top-k
        UPDATE = 3;     // Score changed significantly
    }
    UpdateType type = 1;
    // Full current top-k (for INITIAL)
    repeated SearchResult results = 2;
    // Changed result (for INSERT/REMOVE/UPDATE)
    SearchResult changed = 3;
    // Position in result set
    uint32 position = 4;
    // Server timestamp
    uint64 timestamp = 5;
}

=== Kafka Integration

[source,rust]
----
/// Kafka consumer for vector streaming
pub struct KafkaVectorConsumer {
    consumer: StreamConsumer<DefaultConsumerContext>,
    collection_mapping: HashMap<String, String>,
    processor: Arc<StreamProcessor>,
    config: KafkaConfig,
}

pub struct KafkaConfig {
    /// Kafka bootstrap servers
    pub bootstrap_servers: String,
    /// Consumer group ID
    pub group_id: String,
    /// Topics to consume
    pub topics: Vec<String>,
    /// Topic to collection mapping
    pub topic_collection_map: HashMap<String, String>,
    /// Commit strategy
    pub commit_strategy: CommitStrategy,
    /// Deserialization format
    pub format: MessageFormat,
}

#[derive(Clone)]
pub enum MessageFormat {
    Json,
    Avro { schema_registry: String },
    Protobuf,
    MessagePack,
}

#[derive(Clone)]
pub enum CommitStrategy {
    /// Commit after each batch
    PerBatch,
    /// Commit after successful index
    AfterIndex,
    /// Manual commit control
    Manual,
}

impl KafkaVectorConsumer {
    pub async fn run(&self) -> Result<(), StreamError> {
        loop {
            match self.consumer.recv().await {
                Ok(message) => {
                    let record = self.deserialize(&message)?;
                    let collection = self.get_collection(&message)?;

                    // Process through stream pipeline
                    self.processor.process(collection, record).await?;

                    // Commit based on strategy
                    if matches!(self.config.commit_strategy, CommitStrategy::PerBatch) {
                        self.consumer.commit_message(&message, CommitMode::Async)?;
                    }
                }
                Err(e) => {
                    tracing::error!("Kafka consume error: {}", e);
                    tokio::time::sleep(Duration::from_millis(100)).await;
                }
            }
        }
    }
}

== Summary

This specification provides the foundation for real-time streaming in ProximaDB, enabling:

1. **High-throughput ingestion** via gRPC, WebSocket, and Kafka
2. **Live query subscriptions** with push notifications
3. **Backpressure handling** for reliable operation under load
4. **Flexible delivery semantics** from at-most-once to exactly-once

Implementation follows a phased approach, with core infrastructure first, followed by live queries and external integrations.
