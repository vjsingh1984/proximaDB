== Executive Summary

This document specifies a native compute engine for ProximaDB optimized for internal storage formats (ProximaBlocks, Parquet-based engines) while maintaining compatibility with Arrow, Hadoop, and external compute engines. The design addresses identified bottlenecks in existing compute engines and leverages ProximaDB's unique multi-model architecture.

==== Identified Gaps in Header Structure

1. **Missing ProximaHeaderCache Integration**: Header doesn't store pre-computed rowgroup metadata for sub-millisecond pruning
2. **No Centroid Caching**: Block centroids not embedded in header for vector search pruning
3. **Bloom Filter Scatter**: Per-block bloom filters stored separately, not consolidated for batch checking
4. **Missing Spatial Index Summary**: Hilbert/Z-order range summaries not in header

==== Current Pruning Flow

1. Query arrives with predicate
2. Load header from cache (or fetch once)
3. Apply scalar predicate to `column_stats` -> skip rowgroups
4. Apply spatial predicate to `spatial_range` -> skip blocks
5. Issue selective S3 Range requests

==== Optimization Opportunities

* **Batch Bloom Filter**: Consolidated bloom for entire file (reduce round trips)
* **Centroid Index**: Pre-computed centroid tree in header (O(log n) pruning)
* **Learned Spatial Partitioning**: RL-based block clustering optimization

==== Encoding Bottlenecks

1. **High-Bit Flag Overhead**: `marker & 0x80` for every encoded group
2. **No Vectorized Decode**: BitPacked decode is scalar
3. **Separate Quantization Decode**: Binary/INT8/PQ decoded in separate passes

=== DataFusion

**Strengths:**

* Native Rust (zero-copy with ProximaDB)
* Arrow-native columnar execution
* Fastest single-node Parquet performance
* Extensible optimizer rules

**Shortcomings:**

* No native vector search operators
* No graph traversal support
* Limited distributed capabilities
* No learned optimization (RL)

**ProximaDB Integration Status:**

* `src/datafusion/table_provider.rs`: TableProvider implementation

**Strengths:**

* Mature distributed execution
* Rich ecosystem (MLlib, GraphX)
* DataSource V2 pushdown protocol
* Enterprise adoption

**Shortcomings:**

* JVM overhead (GC pauses)

**ProximaDB Connector:**

* `src/connectors/spark.rs`: JNI bridge

=== Legacy Compute Engines Analysis

Understanding historical SQL-on-Hadoop engines provides valuable lessons for ProximaDB's native engine design.

==== Apache Hive

**Architecture:** MapReduce/Tez/Spark execution, HiveQL language, shared metastore

**Strengths:**

* **Batch ETL Excellence**: Optimized for large-scale ETL with fault tolerance
* **Ecosystem Integration**: Works with Spark, Pig, entire Hadoop ecosystem
* **ACID Transactions**: Full support for inserts, updates, deletes
* **File Format Flexibility**: ORCFile, Parquet, Avro, text, JSON
* **Fault Tolerance**: MapReduce restart for failed tasks
* **Schema Evolution**: Metastore-based schema management

**Weaknesses:**

* **High Latency**: MapReduce overhead, not interactive (seconds to minutes)
* **Schema Rigidity**: Requires predefined schemas, no dynamic discovery
* **Resource Heavy**: JVM overhead, high memory footprint
* **Cold Start**: Job initialization takes seconds

**Lessons for ProximaDB:**

* Adopt Hive Metastore compatibility for ecosystem integration
* Support ORC/Parquet for Hive interoperability
* Avoid MapReduce-style job boundaries for interactive queries

==== Apache Impala

**Architecture:** MPP engine, C++ implementation, bypasses MapReduce

**Strengths:**

* **Low Latency**: Sub-second queries (6-69x faster than Hive)
* **C++ Implementation**: No JVM overhead, efficient memory management
* **Parquet Optimization**: Native Parquet support with predicate pushdown
* **Concurrent Users**: Elastic scalability in multi-tenant environments
* **Real-Time Analytics**: Ideal for BI dashboards

**Weaknesses:**

* **Memory Intensive**: Requires significant RAM per node
* **Limited Fault Tolerance**: Long queries may fail without restart
* **SQL Coverage**: Missing some advanced SQL features (ROLLUP, etc.)
* **Cloudera-Centric**: Primarily Cloudera distribution focused

**Lessons for ProximaDB:**

* C++ (or Rust) for performance-critical paths (already using Rust)
* MPP architecture for distributed queries
* Parquet-first optimization (VIPER/NOVA/RAPTOR)
* Balance memory usage vs query performance

==== Apache Drill

**Architecture:** Schema-free SQL, inspired by Google Dremel, distributed

**Strengths:**

* **Schema-Free Queries**: Query JSON/Parquet without predefined schemas
* **Dynamic Schema Discovery**: Compile-on-the-fly based on data
* **Multi-Source Joins**: Query across HDFS, S3, MongoDB, HBase
* **Nested Data Support**: Hierarchical columnar representation
* **Low Latency**: Designed for interactive exploration

**Weaknesses:**

* **Memory Management**: Complex memory allocation for nested data
* **Limited Ecosystem**: Smaller community than Hive/Spark
* **Optimization Complexity**: Dynamic compilation overhead

**Lessons for ProximaDB:**

* Schema-free query support for document collections
* Multi-source federation (vectors + graphs + documents)
* Hierarchical data model for nested JSON/metadata

==== Apache Pig

**Architecture:** Pig Latin language, compiles to MapReduce

**Strengths:**

* **Data Flow Language**: Natural for ETL pipelines
* **Extensibility**: User-defined functions (UDFs)
* **Optimization**: Automatic query optimization

**Weaknesses:**

* **Declining Relevance**: Superseded by Spark/SQL interfaces
* **Learning Curve**: Non-SQL syntax
* **MapReduce Limitations**: Same latency issues as Hive

**Lessons for ProximaDB:**

* SQL-first interface (already implemented)
* Avoid proprietary query languages
* Support UDFs for extensibility

==== Pruning Algorithm Enhancement

[source,rust]
----
impl EnhancedCachedHeader {
    /// O(log n) vector search pruning using centroid tree
    pub fn prune_by_vector_search(
        &self,
        query: &[f32],
        max_distance: f32,
        top_k: usize,
    ) -> PruningResult {
        let mut candidates = Vec::new();
        let mut skipped = 0;

        // Phase 1: Tree-based coarse pruning
        if let Some(ref tree) = self.centroid_index {
            self.tree_prune(&tree.root, query, max_distance, &mut candidates);
        }

        // Phase 2: Quantized centroid refinement
        for rg in &self.rowgroups {
            if let Some(ref qc) = rg.quantized_centroid {
                let approx_dist = self.quantized_distance(query, qc);
                if approx_dist > max_distance * 1.2 {  // 20% margin
                    skipped += 1;
                    continue;
                }
                candidates.push(rg.index);
            }
        }

        PruningResult {
            matching_rowgroups: candidates,
            rowgroups_skipped: skipped,
            estimated_io_savings: self.estimate_savings(skipped),
        }
    }

    /// Batch bloom filter check (single I/O)
    pub fn check_ids_exist(&self, ids: &[&str]) -> BloomCheckResult {
        if let Some(ref bloom) = self.global_bloom_filter {
            let mut definitely_absent = Vec::new();
            let mut possibly_present = Vec::new();

            for id in ids {
                if !bloom.may_contain(id) {
                    definitely_absent.push(*id);
                } else {
                    possibly_present.push(*id);
                }
            }

            BloomCheckResult { definitely_absent, possibly_present }
        } else {
            // No global bloom, all possibly present
            BloomCheckResult {
                definitely_absent: vec![],
                possibly_present: ids.to_vec(),
            }
        }
    }
}

impl RewardCalculator {
    pub fn calculate_extended(
        &self,
        latency_ms: f64,
        recall: f32,
        io_bytes_saved: u64,
        simd_utilization: f32,
        cache_hit_rate: f32,

        let simd_bonus = simd_utilization * 0.1;

        base_reward + io_bonus + simd_bonus + cache_bonus
    }

/// Smart I/O layer with header-driven range optimization
pub struct SmartIoLayer {
    /// Underlying filesystem (S3, Azure, GCS, local)
    filesystem: Arc<dyn FileSystem>,

    /// Header cache for pruning decisions
    header_cache: Arc<ProximaHeaderCache>,

    /// Range optimizer with access pattern learning
    range_optimizer: Arc<RangeOptimizer>,

    /// Prefetch engine
    prefetch_engine: Arc<PrefetchEngine>,

    /// Metrics collector
    metrics: Arc<IoMetrics>,
}

impl SmartIoLayer {
    /// Execute query with minimal I/O
    pub async fn execute_with_minimal_io(
        &self,
        query: &QueryPlan,
        files: &[String],
    ) -> Result<Vec<RecordBatch>> {
        let mut total_io_bytes = 0u64;
        let mut skipped_bytes = 0u64;

        for file in files {
            // Step 1: Load header (cached after first access)
            let header = self.header_cache.get_or_load(file).await?;

            // Step 2: Apply all pruning strategies
            let matching_rowgroups = self.prune_rowgroups(&header, query)?;

            // Step 3: Calculate optimal ranges
            let ranges = self.calculate_optimal_ranges(&header, &matching_rowgroups);

            // Step 4: Coalesce nearby ranges
            let coalesced = self.range_optimizer.coalesce_ranges(ranges);

            // Step 5: Execute range reads with parallelism
            let data = self.parallel_range_read(file, &coalesced).await?;

            // Track metrics
            skipped_bytes += header.total_data_size() - coalesced.total_bytes();
        }

        self.metrics.record_io_savings(skipped_bytes, total_io_bytes);

        // ... decode and return
    }

    /// Calculate optimal byte ranges for reading
    fn calculate_optimal_ranges(
        &self,
        header: &EnhancedCachedHeader,
        rowgroups: &[usize],
    ) -> Vec<ByteRange> {
        let mut ranges = Vec::new();

        for &rg_idx in rowgroups {
            let rg = &header.rowgroups[rg_idx];
            ranges.push(ByteRange {
                start: rg.offset,
                end: rg.offset + rg.length,
            });
        }

        // Sort and merge adjacent ranges
        ranges.sort_by_key(|r| r.start);
        self.merge_adjacent_ranges(&mut ranges, self.config.merge_threshold);

        ranges
    }
}

==== Range Coalescing Algorithm

[source,rust]
----
impl RangeOptimizer {
    /// Coalesce ranges to reduce HTTP requests
    pub fn coalesce_ranges(&self, ranges: Vec<ByteRange>) -> Vec<ByteRange> {
        if ranges.is_empty() {
            return vec![];
        }

        let mut result = Vec::new();
        let mut current = ranges[0].clone();

        for range in ranges.into_iter().skip(1) {
            // Merge if gap is smaller than threshold
            if range.start <= current.end + self.merge_threshold as u64 {
                current.end = current.end.max(range.end);
            } else {
                result.push(current);
                current = range;
            }
        }
        result.push(current);

        // Calculate efficiency
        let original_bytes: u64 = result.iter().map(|r| r.end - r.start).sum();
        let request_count = result.len();

        tracing::debug!(
            "Coalesced {} ranges into {} requests ({} bytes)",
            ranges.len(),
            request_count,
            original_bytes
        );

        result
    }
}

/// Universal adapter bridging external engines to internal formats
pub struct ProximaDBAdapter {
    /// Storage format registry
    format_registry: Arc<FormatRegistry>,

    /// Header cache
    header_cache: Arc<ProximaHeaderCache>,

    /// Smart I/O layer
    io_layer: Arc<SmartIoLayer>,

    /// Native operator library
    operators: Arc<NativeOperatorRegistry>,
}

impl ProximaDBAdapter {
    /// Create TableProvider for DataFusion
    pub fn to_datafusion_provider(
        &self,
        collection: &str,
    ) -> Arc<dyn datafusion::datasource::TableProvider> {
        Arc::new(ProximaDBTableProvider::new(
            collection.to_string(),
            self.get_schema(collection),
            self.format_registry.clone(),
            self.io_layer.base_path(collection),
        ))
    }

    /// Create Spark DataSource
    pub fn to_spark_datasource(
        &self,
        collection: &str,
    ) -> SparkDataSourceConfig {
        SparkDataSourceConfig {
            class_name: "com.proximadb.spark.ProximaDBDataSource",
            options: self.spark_options(collection),
        }
    }

    /// Create Trino connector config
    pub fn to_trino_connector(
        &self,
        collection: &str,
    ) -> TrinoConnectorConfig {
        TrinoConnectorConfig {
            name: "proximadb",
            properties: self.trino_properties(collection),
        }
    }

    /// Create DuckDB table function
    pub fn to_duckdb_function(
        &self,
        collection: &str,
    ) -> DuckDBTableFunction {
        DuckDBTableFunction {
            name: format!("proximadb_scan_{}", collection),
            bind_func: self.duckdb_bind_func(collection),
            scan_func: self.duckdb_scan_func(collection),
        }
    }

    /// Native query execution (bypass external engines)
    pub async fn execute_native(
        &self,
        query: &str,
    ) -> Result<RecordBatchStream> {
        // Parse -> Optimize -> Plan -> Execute
        let ast = self.parser.parse(query)?;
        let optimized = self.optimizer.optimize(ast).await?;
        let plan = self.planner.plan(optimized)?;
        self.executor.execute(plan).await
    }
}
