== Overview

ProximaDB's Unified Quantization Engine provides hardware-accelerated vector compression with automatic codec selection based on your workload requirements.

=== Quantization Types

|===
| Type | Compression | Memory/Vector | Recall | Use Case

| Binary | 32x | 1 bit/dim | 85-92% | Maximum compression
| INT8 (Scalar) | 4x | 1 byte/dim | 97-99% | Balanced
| PQ4 | 8x | 0.5 bytes/dim | 90-95% | High compression

== Quick Start

=== Enable Quantization at Collection Creation

[source,python]
----
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient(url="http://localhost:5678")

# Binary quantization (maximum compression)
client.create_collection(
    name="binary_collection",
    dimension=1536,
    quantization={"type": "binary"}
)

# INT8 scalar quantization (recommended default)
client.create_collection(
    name="int8_collection",
    dimension=1536,
    quantization={"type": "int8"}
)

# Product quantization with 8 bits
client.create_collection(
    name="pq8_collection",
    dimension=1536,
    quantization={
        "type": "pq",
        "bits": 8,
        "num_subvectors": 48  # dimension / 32
    }
)
----

=== Configuration via TOML

[source,toml]
----
[storage.quantization]
default_type = "int8"           # binary | int8 | pq
pq_bits = 8                     # 4, 8, 16, or 32
pq_subvectors = 48              # Auto-calculated if not set
training_samples = 10000        # For PQ codebook training
enable_reranking = true         # Full precision rerank
rerank_multiplier = 5           # Fetch 5x candidates for rerank
----

== Binary Quantization

=== How It Works

Binary quantization converts each float dimension to a single bit based on whether it's above or below the mean.

[source,text]
----
Original:    [0.1, -0.3, 0.5, 0.2, -0.1, 0.4, -0.2, 0.3]
Mean:        0.1125
Binary:      [0,    0,    1,   1,    0,    1,    0,    1]  = 0b01101011
----

=== Configuration

[source,python]
----
client.create_collection(
    name="binary_optimized",
    dimension=1536,
    quantization={
        "type": "binary",
        "threshold": "mean",      # mean | zero | median
        "enable_rerank": True,    # Rerank with FP32
        "rerank_k": 100           # Rerank top 100
    }
)
----

== INT8 Scalar Quantization

=== How It Works

INT8 quantization maps float values to 8-bit integers using min/max scaling.

[source,text]
----
Original:    [-1.0, 0.0, 0.5, 1.0]
Scale:       (max - min) / 255 = 2.0 / 255
Quantized:   [0, 127, 191, 255]
----

=== Configuration

[source,python]
----
client.create_collection(
    name="int8_collection",
    dimension=1536,
    quantization={
        "type": "int8",
        "calibration": "minmax",   # minmax | percentile | symmetric
        "percentile": 99.9,        # For percentile calibration
        "symmetric": False         # Force symmetric range
    }
)
----

=== Calibration Methods

[cols="2,4", options="header"]
|===
| Method | Description
| `minmax` | Use actual min/max values (default)
| `percentile` | Use 99.9th percentile (handles outliers)
| `symmetric` | Symmetric around zero (for centered data)
|===

=== Performance Characteristics

[cols="2,3", options="header"]
|===
| Metric | Value
| Memory reduction | 4x
| Search speedup | 2-4x

== Product Quantization (PQ)

=== How It Works

PQ divides vectors into subvectors and quantizes each using learned codebooks.

[source,text]
----
Original vector (1536 dims):
├── Subvector 1 (32 dims) → Codebook 1 → Code: 42
├── Subvector 2 (32 dims) → Codebook 2 → Code: 17
├── ...
└── Subvector 48 (32 dims) → Codebook 48 → Code: 203

Compressed: [42, 17, ..., 203] = 48 bytes (vs 6144 bytes original)
----

=== Configuration

[source,python]
----
client.create_collection(
    name="pq_collection",
    dimension=1536,
    quantization={
        "type": "pq",
        "bits": 8,                    # 4, 8, 16, or 32
        "num_subvectors": 48,         # dimension / 32 recommended
        "training_samples": 50000,    # More = better codebook
        "num_iterations": 25,         # K-means iterations
        "codebook_init": "kmeans++"   # Initialization method
    }
)
----

== Reranking Strategy

=== Two-Stage Search

1. **Stage 1**: Fast search with quantized vectors
2. **Stage 2**: Rerank top candidates with full precision

[source,python]
----
# Configure reranking
results = client.search(
    collection="binary_collection",
    vector=query_vector,
    top_k=10,
    search_params={
        "rerank": True,
        "rerank_k": 100,           # Fetch 100 candidates
        "rerank_metric": "cosine"  # Full precision rerank
    }
)
----

=== Automatic Reranking

[source,toml]
----
[storage.quantization]
enable_reranking = true
rerank_multiplier = 10     # For top_k=10, fetch 100 candidates
rerank_threshold = 0.9     # Only rerank if initial score < 0.9
----

== Memory Calculator

=== Formula

[source,text]
----
Memory per vector = (dimension * bytes_per_dim) + overhead

Binary:  1536 dims = 1536 / 8 = 192 bytes
INT8:    1536 dims = 1536 * 1 = 1,536 bytes
PQ8:     1536 dims = 48 subvectors * 1 byte = 48 bytes
FP32:    1536 dims = 1536 * 4 = 6,144 bytes
----

== Choosing the Right Quantization

=== Decision Tree

[source,text]
----
Start
├── Memory is critical constraint?
│   ├── Yes → Binary (32x compression)
│   └── No → Continue
├── Need 99%+ recall?
│   ├── Yes → INT8 or PQ16/32
│   └── No → Continue
├── Dataset > 100M vectors?
│   ├── Yes → PQ8 or Binary + rerank
│   └── No → INT8 (best balance)
└── Maximum search speed?
    ├── Yes → Binary (Hamming distance)
    └── No → INT8 or PQ8
----

=== Recommendations by Use Case

[cols="2,3,2", options="header"]
|===
| Use Case | Recommended | Why
| RAG / Semantic Search | INT8 | High recall, good compression
| Image Search | PQ8 | Good balance for high-dim
| Recommendation | Binary + rerank | Fast candidate generation
| Deduplication | Binary | Speed > precision
| Research / ML | None or INT8 | Maximum accuracy
| Mobile / Edge | Binary | Minimal memory
| Production API | INT8 or PQ8 | Predictable latency
|===

== Progressive Cascade Search

ProximaDB supports multi-stage quantization cascade:

[source,python]
----
# Configure cascade
results = client.progressive_search(
    collection="my_collection",
    vector=query_vector,
    top_k=10,
    stages=[
        {"type": "binary", "k": 1000},    # Fast filter
        {"type": "int8", "k": 100},       # Refine
        {"type": "full", "k": 10}         # Final precision
    ]
)
----

=== Cascade Configuration

[source,toml]
----
[search.progressive]
enabled = true
stages = [
    { type = "binary", multiplier = 100 },
    { type = "int8", multiplier = 10 },
    { type = "full", multiplier = 1 }
]
early_termination = true
confidence_threshold = 0.95
----

=== Quality Validation

[source,python]
----
# Compare quantized vs full precision
def validate_quantization(collection, test_vectors, k=10):
    recalls = []

    for vector in test_vectors:
        # Full precision search
        full_results = client.search(
            collection=collection,
            vector=vector,
            top_k=k,
            search_params={"quantized": False}
        )
        full_ids = set(r.id for r in full_results)

        # Quantized search
        quant_results = client.search(
            collection=collection,
            vector=vector,
            top_k=k,
            search_params={"quantized": True}
        )
        quant_ids = set(r.id for r in quant_results)

        recall = len(full_ids & quant_ids) / k
        recalls.append(recall)

    avg_recall = sum(recalls) / len(recalls)
    print(f"Average Recall@{k}: {avg_recall:.2%}")
    return avg_recall

validate_quantization("my_collection", test_vectors)
----
