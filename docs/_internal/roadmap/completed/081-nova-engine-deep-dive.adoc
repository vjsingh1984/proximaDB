== Overview

NOVA is ProximaDB's **progressive analytics engine** combining columnar storage with hierarchical statistics. It excels at mixed workloads requiring both point queries and analytical aggregations.

=== Key Characteristics

[cols="2,3", options="header"]
|===
| Metric | Value
| Query Latency | ~101.6ms (mixed workloads)
| Progressive Refinement | Yes (early termination)
| Statistics Levels | 4 (file, block, page, record)
| Memory Efficiency | Adaptive based on access patterns
| Best For | Mixed OLTP/OLAP, progressive queries
|===

    └── Individual vectors

== Progressive Query Execution

=== Stage 1: File-Level Pruning

[source,rust]
----
pub fn file_level_prune(&self, query: &Query) -> Vec<FileCandidate> {
    self.files.iter()
        .filter(|file| {
            // Check global centroid distance
            let centroid_dist = distance(&query.vector, &file.stats.centroid);
            centroid_dist <= query.threshold * file.stats.expansion_factor
        })
        .filter(|file| {
            // Check bounding box overlap
            file.stats.bounds.may_contain(&query.vector, query.threshold)
        })
        .collect()
}
----

== Write Path

=== Flush Process

[source,rust]
----
impl NovaEngine {
    pub async fn flush(&self, vectors: Vec<VectorRecord>) -> Result<()> {
        // 1. Compute hierarchical statistics
        let file_stats = self.compute_file_statistics(&vectors);

        // 2. Partition into blocks
        let blocks = self.partition_into_blocks(vectors);

        // 3. Compute block-level statistics
        for block in &blocks {
            let block_stats = self.compute_block_statistics(block);
            self.stats.block_stats.push(block_stats);
        }

        // 4. Write with statistics interleaved
        self.write_nova_file(blocks, file_stats).await
    }
}
----

== Performance Optimizations

=== Progressive Execution

* Early termination when confidence threshold met
* Streaming results during query execution
* Adaptive scanning order based on statistics

=== Statistics Caching

* Hot statistics kept in memory
* LRU eviction for cold statistics
* Prefetching for sequential patterns

=== Adaptive Compression

* Hot blocks: Fast compression (LZ4)
* Cold blocks: High compression (ZSTD)
* Statistics: No compression (fast access)

== Use Cases

=== Optimal For

* Interactive analytics (progressive results)
* Mixed OLTP/OLAP workloads
* Exploratory data analysis
* Dashboard queries with timeout constraints

=== Not Optimal For

* Pure real-time OLTP (<5ms latency)
* Pure batch analytics (VIPER better)
* Very small datasets (<10K vectors)
