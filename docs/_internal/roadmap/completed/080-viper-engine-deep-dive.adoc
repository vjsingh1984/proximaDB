== Overview

VIPER is ProximaDB's **analytics-optimized storage engine** using Apache Parquet columnar format with vector-specific optimizations. It's designed for batch analytics, OLAP workloads, and scenarios requiring high compression ratios.

=== Key Characteristics

[cols="2,3", options="header"]
|===
| Metric | Value
| Read Throughput | 100K+ vectors/sec (batch)
| Query Latency | ~89.5ms (analytical queries)
| Compression Ratio | 5-10x (Parquet + vector-specific)
| Memory Efficiency | Excellent for large datasets
| Best For | Analytics, batch processing, data warehousing
|===

== Search Pipeline

=== Stage 1: Row Group Pruning

* Statistics-based elimination
* Centroid distance thresholding
* Bloom filter checks for ID queries
* **70-90% row group elimination**

=== Stage 2: Column Projection

* Lazy column loading (only needed columns)
* Predicate pushdown to Parquet reader
* Arrow IPC for zero-copy transfers

=== Stage 3: Vector Search

* Batch-optimized SIMD operations
* Arrow-native distance computation
* Result aggregation across row groups

== Write Path

=== Flush Process

[source,rust]
----
impl ViperEngine {
    pub async fn flush(&self, vectors: Vec<VectorRecord>) -> Result<()> {
        // 1. Sort by clustering key (if configured)
        let sorted = self.sort_by_cluster_key(vectors);

        // 2. Create row groups
        let row_groups = sorted.chunks(self.config.row_group_size);

        // 3. Compute statistics for each row group
        for group in row_groups {
            let stats = self.compute_statistics(group);

            // 4. Write Parquet file with statistics
            self.write_parquet_file(group, stats).await?;
        }

        // 5. Update file manifest
        self.update_manifest().await
    }
}
----

=== Compaction Strategy

* **Minor Compaction**: Merge small row groups
* **Major Compaction**: Rewrite entire files with optimal clustering
* **Z-Order Sorting**: Multi-dimensional clustering for range queries
* **Automatic Triggers**: Based on file count and size ratios

== Performance Optimizations

=== Parquet-Specific

* Dictionary encoding for low-cardinality metadata
* Delta encoding for sequential IDs
* RLE for repeated values
* Page-level statistics for fine-grained pruning

=== Vector-Specific

* Centroid-based row group ordering
* PCA dimension reduction (optional)
* Quantized statistics for memory efficiency
* SIMD-accelerated batch operations

=== I/O Optimization

* Parallel row group reading
* Column projection pushdown
* Memory-mapped file access
* Prefetching for sequential scans

// Zero-copy Arrow integration
pub fn to_arrow_batch(&self, row_group: &RowGroup) -> RecordBatch {

// Arrow Flight export
pub fn export_to_flight(&self, query: &Query) -> FlightStream {
    self.search(query)
        .map(|batch| batch.to_flight_data())
        .into_stream()
}

=== Not Optimal For

* Real-time queries (<10ms latency)
* High write throughput
* Small datasets (<100K vectors)
* Point lookups by ID
