== Getting Started

=== Prerequisites

[source,bash]
----
# Required
- Rust 1.88+ (rustup install stable)
- Git
- Python 3.10+ (for SDK development)

# Recommended
- Docker (for integration tests)
- cargo-flamegraph (for profiling)
- cargo-watch (for development)
----

=== Setting Up Development Environment

[source,bash]
----
# Clone repository
git clone https://github.com/proximadb/proximadb.git
cd proximadb

# Build
cargo build

# Run tests
cargo test

# Start development server
cargo run --bin proximadb-server

# Format and lint
cargo fmt && cargo clippy -- -D warnings
----

|===

=== Contribution Workflow

[source,text]
----
1. Find/Create Issue
   ├── Check existing issues
   ├── Create new issue if needed
   └── Get issue assigned

2. Development
   ├── Create feature branch
   ├── Write code
   ├── Write tests
   └── Update documentation

3. Pull Request
   ├── Push branch
   ├── Open PR
   ├── Address review feedback
   └── Get approval

4. Merge
   ├── Squash and merge
   └── Delete branch
----

=== Branch Naming

[source,text]
----
Format: <type>/<issue-number>-<short-description>

Types:
- feature/   New functionality
- fix/       Bug fixes
- docs/      Documentation
- refactor/  Code refactoring
- perf/      Performance improvements
- test/      Test additions

Examples:
- feature/123-streaming-insert
- fix/456-search-timeout
- docs/789-api-reference
----

=== Commit Messages

[source,text]
----
Format:
<type>(<scope>): <subject>

<body>

<footer>

Types:
- feat:     New feature
- fix:      Bug fix
- docs:     Documentation
- style:    Formatting
- refactor: Code refactoring
- perf:     Performance improvement
- test:     Test additions
- chore:    Maintenance

Examples:
feat(search): add streaming search API

Implement gRPC streaming for large result sets.
- Add StreamSearch RPC method
- Implement server-side pagination
- Update Python SDK

Closes #123

fix(storage): handle corrupted WAL segment

Check segment checksum before replay.
Recover from corruption by skipping invalid entries.

Fixes #456
----

=== Testing Guidelines

[source,rust]
----
// Unit tests in the same file
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_insert_single_vector() {
        let engine = SstEngine::new(Config::default());
        let record = VectorRecord {
            id: "test_1".to_string(),
            vector: vec![0.1, 0.2, 0.3],
            metadata: None,
        };

        let result = engine.insert("test_collection", vec![record]);

        assert!(result.is_ok());
        assert_eq!(result.unwrap().inserted_count, 1);
    }

    #[test]
    fn test_search_returns_top_k() {
        // Arrange
        let engine = create_engine_with_data(100);

        // Act
        let results = engine.search("collection", &query, 10).unwrap();

        // Assert
        assert_eq!(results.len(), 10);
        assert!(results.windows(2).all(|w| w[0].score >= w[1].score));
    }

    #[test]
    fn test_error_on_invalid_dimension() {
        let engine = SstEngine::new(Config::default());
        engine.create_collection("test", 128).unwrap();

        let record = VectorRecord {
            id: "test_1".to_string(),
            vector: vec![0.1; 64], // Wrong dimension
            metadata: None,
        };

        let result = engine.insert("test", vec![record]);

        assert!(result.is_err());
        assert!(matches!(result.unwrap_err(), Error::DimensionMismatch { .. }));
    }
}
----

== Pull Request Process

=== Before Opening PR

[source,text]
----
Checklist:
[ ] Code compiles without warnings
[ ] All tests pass (cargo test)
[ ] Code is formatted (cargo fmt)
[ ] Lints pass (cargo clippy -- -D warnings)
[ ] Documentation updated (if applicable)
[ ] CHANGELOG.md updated (if applicable)
[ ] New tests added for new functionality
[ ] Benchmarks run (if performance-related)
----

=== PR Template

[source,markdown]
----
## Description

Brief description of changes.

## Related Issue

Fixes #123

## Type of Change

- [ ] Bug fix (non-breaking change that fixes an issue)
- [ ] New feature (non-breaking change that adds functionality)
- [ ] Breaking change (fix or feature that would cause existing functionality to not work as expected)
- [ ] Documentation update

## How Has This Been Tested?

Describe the tests you ran.

## Checklist

- [ ] My code follows the project's style guidelines
- [ ] I have performed a self-review of my code
- [ ] I have commented my code, particularly in hard-to-understand areas
- [ ] I have made corresponding changes to the documentation
- [ ] My changes generate no new warnings
- [ ] I have added tests that prove my fix is effective or my feature works
- [ ] New and existing unit tests pass locally with my changes
----

=== Review Process

[source,text]
----
Review Stages:
1. Automated checks (CI)
   ├── Build
   ├── Tests
   ├── Linting
   └── Coverage

2. Code review
   ├── Correctness
   ├── Design
   ├── Performance
   └── Documentation

3. Approval
   ├── At least 1 maintainer approval
   ├── All CI checks passing
   └── No unresolved comments

4. Merge
   ├── Squash and merge
   └── Delete branch
----
