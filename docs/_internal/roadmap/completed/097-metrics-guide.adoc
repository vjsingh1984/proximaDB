**Comprehensive guide to ProximaDB metrics for monitoring, alerting, and performance optimization**

== Overview

ProximaDB exposes metrics via Prometheus format on the `/metrics` endpoint, providing deep visibility into system health, performance, and resource utilization.

=== Metrics Architecture

[source,text]
----
Metrics Collection:
├── Application Metrics (business logic)
│   ├── Query metrics
│   ├── Insert/Update/Delete metrics
│   └── Collection metrics
├── System Metrics (infrastructure)
│   ├── CPU, Memory, Disk
│   ├── Network I/O
│   └── Thread pools
├── Storage Engine Metrics
│   ├── SST, VIPER, NOVA, etc.
│   ├── Compaction stats
│   └── Cache hit rates
└── Index Metrics
    ├── HNSW, IVF, LSH
    ├── Build progress
    └── Search efficiency
----

== Enabling Metrics

=== Configuration

[source,toml]
----
# config.toml
[monitoring]
prometheus_enabled = true
prometheus_port = 9090
prometheus_path = "/metrics"

# Metric collection settings
collection_interval_ms = 1000
histogram_buckets = [0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0]

# Export settings
include_labels = ["collection", "engine", "operation"]
exclude_metrics = []  # Regex patterns to exclude
----

=== Accessing Metrics

[source,bash]
----
# Direct access
curl http://localhost:9090/metrics

# With authentication
curl -H "X-API-Key: your-key" http://localhost:9090/metrics

# Prometheus scrape config
- job_name: 'proximadb'
  static_configs:
    - targets: ['localhost:9090']
  metrics_path: /metrics
  scrape_interval: 15s
----

== Prometheus Queries

=== Common PromQL Queries

[source,promql]
----
# Query rate (QPS)
rate(proximadb_query_total[5m])

# Query latency P99
histogram_quantile(0.99, rate(proximadb_query_duration_seconds_bucket[5m]))

# Query latency P50
histogram_quantile(0.50, rate(proximadb_query_duration_seconds_bucket[5m]))

# Error rate
rate(proximadb_query_total{status="error"}[5m]) / rate(proximadb_query_total[5m])

# Cache hit ratio
rate(proximadb_cache_hit_total[5m]) / (rate(proximadb_cache_hit_total[5m]) + rate(proximadb_cache_miss_total[5m]))

# Memory usage percentage
proximadb_memory_used_bytes / proximadb_memory_allocated_bytes * 100

# Disk usage percentage
proximadb_disk_used_bytes / (proximadb_disk_used_bytes + proximadb_disk_available_bytes) * 100

# Insert throughput (vectors/sec)
rate(proximadb_insert_vectors_total[5m])

# Compaction rate
rate(proximadb_sst_compaction_bytes_written[5m])

# Active queries by collection
sum by (collection) (proximadb_active_queries)
----

=== Aggregation Queries

[source,promql]
----
# Total queries across all collections
sum(rate(proximadb_query_total[5m]))

# Top 5 collections by query volume
topk(5, sum by (collection) (rate(proximadb_query_total[5m])))

# Average latency by engine
avg by (engine) (rate(proximadb_query_duration_seconds_sum[5m]) / rate(proximadb_query_duration_seconds_count[5m]))

# Storage usage by engine
sum by (engine) (proximadb_storage_size_bytes)
----

== Alert Rules

=== Critical Alerts

[source,yaml]
----
# alerts.yml
groups:
  - name: proximadb-critical
    rules:
      - alert: ProximaDBDown
        expr: up{job="proximadb"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "ProximaDB instance is down"

      - alert: ProximaDBHighErrorRate
        expr: rate(proximadb_query_total{status="error"}[5m]) / rate(proximadb_query_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Error rate above 5%"

      - alert: ProximaDBDiskFull
        expr: proximadb_disk_available_bytes / (proximadb_disk_used_bytes + proximadb_disk_available_bytes) < 0.1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Disk usage above 90%"
----

=== Warning Alerts

[source,yaml]
----
  - name: proximadb-warning
    rules:
      - alert: ProximaDBHighLatency
        expr: histogram_quantile(0.99, rate(proximadb_query_duration_seconds_bucket[5m])) > 1
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "P99 latency above 1 second"

      - alert: ProximaDBHighMemory
        expr: proximadb_memory_used_bytes / proximadb_memory_allocated_bytes > 0.85
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "Memory usage above 85%"

      - alert: ProximaDBLowCacheHitRate
        expr: rate(proximadb_cache_hit_total[5m]) / (rate(proximadb_cache_hit_total[5m]) + rate(proximadb_cache_miss_total[5m])) < 0.8
        for: 15m
        labels:
          severity: warning
        annotations:
          summary: "Cache hit rate below 80%"

      - alert: ProximaDBCompactionLag
        expr: proximadb_sst_sstable_count{level="0"} > 10
        for: 30m
        labels:
          severity: warning
        annotations:
          summary: "Too many L0 SSTables, compaction may be lagging"
----

== Custom Metrics

=== Application-Level Metrics

[source,python]
----
from proximadb_sdk import ProximaDBClient
import time

client = ProximaDBClient(url="http://localhost:5678")

# Get metrics
metrics = client.get_metrics()

# Parse specific metrics
for metric in metrics:
    if metric.name == "proximadb_query_duration_seconds":
        print(f"Query P99: {metric.quantile(0.99)}s")
        print(f"Query P50: {metric.quantile(0.50)}s")
        print(f"Query rate: {metric.rate(window='5m')}/s")

# Custom metric recording
start = time.time()
results = client.search("my_collection", vector=query, top_k=10)
duration = time.time() - start

# Log for custom dashboards
print(f"search_duration_seconds{{collection=\"my_collection\"}} {duration}")
----
