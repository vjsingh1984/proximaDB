== Overview

This guide covers backup strategies, recovery procedures, and disaster recovery planning for ProximaDB.

=== Backup Architecture

[source,text]
----
Backup Components:
├── Data Files
│   ├── Vector data (SST, Parquet files)
│   ├── Index files (HNSW graphs, IVF centroids)
│   └── Metadata (collection configs, schemas)
├── WAL (Write-Ahead Log)
│   ├── Segment files
│   └── Manifest
├── Configuration
│   ├── config.toml
│   └── Secrets (encrypted)
└── Optional
    ├── Codebooks (quantization)
    └── Graph data
----

== Backup Types

=== Full Backup

Complete snapshot of all data at a point in time.

[source,bash]
----
# Using proximadb-cli
proximadb-cli backup create \
  --type full \
  --output /backup/full-$(date +%Y%m%d) \
  --compress

# Using REST API
curl -X POST http://localhost:5678/api/v1/admin/backup \
  -H "X-API-Key: your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "full",
    "destination": "s3://my-bucket/backups/full-20241228",
    "compress": true
  }'
----

[source,python]
----
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient(url="http://localhost:5678", api_key="your-key")

# Create full backup
backup = client.create_backup(
    backup_type="full",
    destination="/backup/full-20241228",
    compress=True,
    include_wal=True
)

print(f"Backup ID: {backup.id}")
print(f"Size: {backup.size_bytes / 1e9:.2f} GB")
print(f"Duration: {backup.duration_seconds}s")
----

=== Incremental Backup

Only changes since last backup.

[source,bash]
----
# Create incremental backup
proximadb-cli backup create \
  --type incremental \
  --base-backup /backup/full-20241228 \
  --output /backup/incr-$(date +%Y%m%d-%H%M) \
  --compress
----

[source,python]
----
# Incremental backup
backup = client.create_backup(
    backup_type="incremental",
    base_backup_id="backup_20241228_full",
    destination="/backup/incr-20241228-1200",
    compress=True
)
----

=== Differential Backup

All changes since last full backup.

[source,bash]
----
# Create differential backup
proximadb-cli backup create \
  --type differential \
  --base-backup /backup/full-20241228 \
  --output /backup/diff-$(date +%Y%m%d) \
  --compress
----

=== Comparison

[cols="2,2,2,2,2", options="header"]
|===
| Type | Size | Speed | Restore Time | Complexity
| Full | Large | Slow | Fast | Low
| Incremental | Small | Fast | Slow | High
| Differential | Medium | Medium | Medium | Medium
|===

== Backup Scheduling

=== Cron-based Scheduling

[source,bash]
----
# /etc/cron.d/proximadb-backup

# Full backup every Sunday at 2 AM
0 2 * * 0 proximadb proximadb-cli backup create --type full --output /backup/full-$(date +\%Y\%m\%d) --compress

# Incremental backup every day at 2 AM (except Sunday)
0 2 * * 1-6 proximadb proximadb-cli backup create --type incremental --base-backup /backup/full-$(date -d 'last sunday' +\%Y\%m\%d) --output /backup/incr-$(date +\%Y\%m\%d)

# WAL backup every hour
0 * * * * proximadb proximadb-cli backup wal --output /backup/wal/$(date +\%Y\%m\%d-\%H)
----

=== Python Scheduled Backup

[source,python]
----
import schedule
import time
from datetime import datetime
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient(url="http://localhost:5678", api_key="your-key")

def full_backup():
    """Weekly full backup"""
    backup = client.create_backup(
        backup_type="full",
        destination=f"s3://my-bucket/backups/full-{datetime.now():%Y%m%d}",
        compress=True
    )
    print(f"Full backup completed: {backup.id}")

def incremental_backup():
    """Daily incremental backup"""
    latest_full = client.get_latest_backup(backup_type="full")
    backup = client.create_backup(
        backup_type="incremental",
        base_backup_id=latest_full.id,
        destination=f"s3://my-bucket/backups/incr-{datetime.now():%Y%m%d-%H%M}",
        compress=True
    )
    print(f"Incremental backup completed: {backup.id}")

def wal_backup():
    """Hourly WAL backup"""
    client.backup_wal(
        destination=f"s3://my-bucket/backups/wal/{datetime.now():%Y%m%d-%H}"
    )
    print("WAL backup completed")

# Schedule backups
schedule.every().sunday.at("02:00").do(full_backup)
schedule.every().day.at("02:00").do(incremental_backup)
schedule.every().hour.do(wal_backup)

while True:
    schedule.run_pending()
    time.sleep(60)
----

== Recovery Procedures

=== Full Restore

[source,bash]
----
# Stop ProximaDB
systemctl stop proximadb

# Restore from backup
proximadb-cli backup restore \
  --source /backup/full-20241228 \
  --target /data/proximadb \
  --overwrite

# Start ProximaDB
systemctl start proximadb

# Verify
proximadb-cli health check
----

=== Point-in-Time Recovery

[source,bash]
----
# Restore full backup
proximadb-cli backup restore \
  --source /backup/full-20241228 \
  --target /data/proximadb

# Apply incremental backups up to specific time
proximadb-cli backup restore \
  --source /backup/incr-20241229 \
  --target /data/proximadb \
  --apply-incrementals

# Replay WAL to specific point
proximadb-cli wal replay \
  --source /backup/wal \
  --target /data/proximadb \
  --until "2024-12-29T10:30:00Z"
----

[source,python]
----
# Point-in-time recovery
client.restore_backup(
    backup_id="backup_20241228_full",
    apply_incrementals=True,
    point_in_time="2024-12-29T10:30:00Z",
    target_dir="/data/proximadb"
)
----

== Disaster Recovery

=== DR Architecture

[source,text]
----
Disaster Recovery Tiers:
├── Tier 1: Hot Standby (RTO < 1 min, RPO < 1 min)
│   └── Synchronous replication to secondary site
├── Tier 2: Warm Standby (RTO < 15 min, RPO < 5 min)
│   └── Asynchronous replication + WAL shipping
├── Tier 3: Cold Standby (RTO < 1 hour, RPO < 1 hour)
│   └── Regular backups to secondary site
└── Tier 4: Archive (RTO < 24 hours, RPO < 24 hours)
    └── Daily backups to cold storage
----

=== Hot Standby Configuration

[source,toml]
----
# Primary config.toml
[replication]
mode = "primary"
standby_hosts = ["standby1.example.com:5679", "standby2.example.com:5679"]
sync_mode = "synchronous"  # synchronous, asynchronous
commit_wait = "all"        # all, any, none
----

[source,toml]
----

[replication]

recovery_mode = "streaming"
hot_standby = true  # Allow read queries
----

=== Warm Standby with WAL Shipping

[source,bash]
----
#!/bin/bash
# wal-ship.sh - Ship WAL segments to standby

WAL_DIR=/data/proximadb/wal
STANDBY_HOST=standby.example.com
STANDBY_WAL_DIR=/data/proximadb/wal

# Archive WAL segments
inotifywait -m -e close_write "$WAL_DIR" |
while read dir action file; do
    if [[ "$file" == *.wal ]]; then
        rsync -avz "$WAL_DIR/$file" "$STANDBY_HOST:$STANDBY_WAL_DIR/"
        echo "Shipped: $file"
    fi
done
----

=== Failover Procedure

[source,bash]
----
#!/bin/bash
# failover.sh - Promote standby to primary

# 1. Stop receiving WAL from primary
proximadb-cli replication stop-recovery

# 2. Promote standby
proximadb-cli replication promote

# 3. Update DNS/Load balancer
aws route53 change-resource-record-sets \
  --hosted-zone-id Z123456 \
  --change-batch '{
    "Changes": [{
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "proximadb.example.com",
        "Type": "A",
        "TTL": 60,
        "ResourceRecords": [{"Value": "10.0.2.100"}]
      }
    }]
  }'

# 4. Verify new primary
proximadb-cli health check
----

=== Failback Procedure

[source,bash]
----
#!/bin/bash
# failback.sh - Restore original primary

# 1. Stop new primary
proximadb-cli replication stop

# 2. Sync data from new primary to original
proximadb-cli backup sync \
  --source new-primary.example.com \
  --target /data/proximadb

# 3. Configure original as new standby
proximadb-cli replication configure-standby \
  --primary new-primary.example.com:5679

# 4. Start as standby
systemctl start proximadb

# 5. (Later) Switchover when ready
proximadb-cli replication switchover
----

=== Cleanup Script

[source,bash]
----
#!/bin/bash
# backup-cleanup.sh

BACKUP_DIR=/backup
FULL_RETENTION_DAYS=90
INCR_RETENTION_DAYS=14
WAL_RETENTION_DAYS=7

# Delete old full backups (keep minimum 4)
full_count=$(find $BACKUP_DIR -name "full-*" -type d | wc -l)
if [ $full_count -gt 4 ]; then
    find $BACKUP_DIR -name "full-*" -type d -mtime +$FULL_RETENTION_DAYS -exec rm -rf {} \;
fi

# Delete old incremental backups
find $BACKUP_DIR -name "incr-*" -type d -mtime +$INCR_RETENTION_DAYS -exec rm -rf {} \;

# Delete old WAL backups
find $BACKUP_DIR/wal -type d -mtime +$WAL_RETENTION_DAYS -exec rm -rf {} \;

echo "Cleanup completed"
----

=== Alerting

[source,yaml]
----
# backup-alerts.yml
groups:
  - name: proximadb-backup
    rules:
      - alert: BackupFailed
        expr: proximadb_backup_last_failure_timestamp > proximadb_backup_last_success_timestamp
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "ProximaDB backup failed"

      - alert: BackupStale
        expr: time() - proximadb_backup_last_success_timestamp > 86400
        for: 1h
        labels:
          severity: warning
        annotations:
          summary: "No successful backup in 24 hours"

      - alert: BackupSizeAnomaly
        expr: |
          abs(proximadb_backup_size_bytes -
              avg_over_time(proximadb_backup_size_bytes[7d])) >
          stddev_over_time(proximadb_backup_size_bytes[7d]) * 3
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Backup size anomaly detected"

== Summary

=== Backup Strategy Recommendations

[cols="2,3,3", options="header"]
|===
| Scenario | Strategy | Schedule
| Small (< 10GB) | Full daily | Daily full + hourly WAL
| Medium (10-100GB) | Full weekly + daily incremental | Weekly full + daily incr + hourly WAL
| Large (> 100GB) | Full monthly + daily incremental | Monthly full + daily incr + continuous WAL
| Critical | Continuous replication | Hot standby + hourly snapshots
|===
