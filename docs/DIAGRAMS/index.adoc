=== Color Scheme Guidelines

[cols="2,1,2", options="header"]
|===
| Component Type | Color | Usage

| **API/External** | Blue (`#4A90E2`) | Client interfaces, external services
| **Core Services** | Green (`#5CB85C`) | Internal services, business logic  
| **Storage** | Purple (`#7B1FA2`) | Storage engines, persistence layer
| **Performance** | Orange (`#F5A623`) | Optimization, caching, acceleration
| **Flows** | Gray (`#64748b`) | Data flows, connections, processes
|===

== 🛠️ Contributing Diagrams

=== Creating New Diagrams

1. **Identify Need**: Gap in visual documentation, user feedback, new features
2. **Choose Format**: Mermaid (preferred), SVG (complex), or PNG (external tools)
3. **Follow Standards**: Use standard theme, colors, and naming conventions
4. **Get Review**: Technical accuracy and visual clarity review
5. **Add Navigation**: Update this index and relevant audience guides

=== Updating Existing Diagrams

1. **Track Changes**: Use git to track all diagram modifications
2. **Maintain Compatibility**: Ensure updates don't break existing links
3. **Version Control**: Major changes get new filenames, minor updates in-place
4. **Update References**: Check and update all documentation references

=== Diagram Tools

**Recommended Tools:**
- **Mermaid**: Primary tool for most diagrams (code-based, version controllable)
- **Draw.io**: Complex diagrams requiring precise positioning  
- **Figma**: High-fidelity mockups and user interface diagrams
- **PlantUML**: Sequence diagrams and UML modeling

**Export Guidelines:**
- **SVG**: Preferred for scalable vector graphics
- **PNG**: High DPI (300 DPI minimum) for raster images
- **PDF**: Documentation embedding and print-friendly versions
