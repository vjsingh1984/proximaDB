= TD-OLAP-2: Wire the statistics substrate into the planner (real CBO + cardinality/selectivity)

[cols="1,3", options="header"]
|===
| Field | Value
| Status | Open — ADR-050 D2 is the first slice (ColumnStatistics for DataFusion); this TD generalizes it to the native planner + cardinality estimation
| Severity | High — without stats the planner is blind; runtime filters (TD-OLAP-3) and cost routing (ADR-050) both depend on it
| Component | `src/core/statistics/{summary,sketches,registry}`, `src/datafusion/schema_inference.rs`, `src/query/query_optimizer.rs`, `src/query/federated/optimizer/`
| Governs | link:../../12-design/adr/ADR-052-analytics-execution-competitiveness-codesign.adoc[ADR-052] (invariant 3); closes the ADR-037/038 designed-only gap
| Relates to | ADR-037 (statistics substrate), ADR-038 (freshness coherence), ADR-050 D2 (DataFusion ColumnStatistics), ADR-042 (mergeable SegmentStatistics), TD-174/175
|===

== Why

ADR-037/038 specify a mergeable statistics envelope; `src/core/statistics/{summary,sketches}`
already implement min/max, NDV (HyperLogLog), TDigest quantiles, null-count, and a registry.
But none of it reaches the planner: `schema_inference.rs` returns
`ColumnStatistics::new_unknown()`, so the DataFusion/native planners plan blind. Snowflake's
signature posture is *"all statistics used for optimization are automatically maintained"* and
a no-indices Cascades CBO; Spark AQE/DPP depend on runtime stats. A competitive engine cannot
ship a statistics-blind planner.

== Rollout

. **Close ADR-050 D2:** project the ADR-042 `SegmentStatistics` (min/max/distinct/null) into
  DataFusion `ColumnStatistics` in `schema_inference.rs` (replace `new_unknown()`) — zero new
  scan; the stats substrate's second consumer.
. **Persist + freshness:** stamp per-segment stats with the ADR-038 freshness watermark; merge
  up the segment→row-group→table hierarchy; invalidate on compaction / DV application.
. **Cardinality estimation:** feed NDV + TDigest histograms into the federated optimizer's
  selectivity/cardinality code (`src/query/federated/optimizer/`) so join ordering and filter
  costing use real distributions, not defaults.
. **Histograms for joins:** add equi-depth/equi-width histograms for join-column selectivity
  (today only TDigest quantiles exist).
. **Calibration:** wire the TD-158 observed-cost trace back as a cardinality correction ratio
  (infrastructure exists in the federated optimizer; tune it).

== Verification

* A plan-explain diff shows non-`unknown` cardinality on TPC-DS tables.
* Join-order changes measurably on skew-sensitive TPC-DS queries (Q72/Q95-class) once stats
  land, with conformance ratchets unchanged.
* Freshness: a write advances the watermark; a stale-stat query is flagged in EXPLAIN.
