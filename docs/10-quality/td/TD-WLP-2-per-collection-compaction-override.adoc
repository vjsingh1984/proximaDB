== Why

Compaction re-clusters (it re-runs `write_pax_segment_full`), but it is global and default-OFF, so
no collection ever re-clusters today. ADR-061 D5 makes compaction arm-able per-collection so
`AppendBulk` collections can get re-clustering while the global default and `Churn` stay OFF.

== Scope

* Add a per-collection compaction override (arm + optional L0 threshold), resolved through the
  TD-WLP-1 cascade (e.g. a `compaction:on` / `l0_threshold:N` tag, or profile-implied for
  `AppendBulk`), mirroring `CollectionWalConfig` / `effective_config_for_collection`.
* Wire it into `should_trigger_compaction`: fire if (global env armed) OR (per-collection opt-in) —
  and if globally disabled AND no per-collection opt-in → OFF. The global env remains the master
  kill-switch (globally-off can never be overridden to on... i.e. a global *hard* disable wins;
  choose the precedence in the ADR-consistent direction: per-collection opt-in arms only when the
  global switch is not a hard-disable).
* Add per-collection resolution to `OrchestratorCompactionConfig`.

== TDD gate

Integration test `tests/storage_wlp_compaction_gate.rs` (storage-integration CI job — `*storage*`):

* `test_append_collection_arms_compaction_while_global_off`: with the global env unset, a collection
  tagged `workload_profile:append` + compaction opt-in reaching L0 ≥ threshold → compaction fires;
  an untagged collection under the same global-off does NOT.

== Gating

Default path unchanged (no tag → global gate governs, still OFF). Requires an explicit
per-collection opt-in tag to arm.
