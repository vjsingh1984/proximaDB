== Why

This TD closed the original mechanism gap: collection tags/profile can arm the existing compactor
while a process-wide hard-disable remains authoritative. The later arm-default amendment made
untagged `AppendBulk` armed and retained `Churn` off.

Do **not** extend this resolved TD with another threshold heuristic. A fixed count cannot decide
whether rewrite cost repays measured GET/byte/cache savings across dimensions, providers, and
query/write ratios. TD-RDSTRAT-9 owns that collection-level policy and reuses this actuation seam.

== Scope

* Add a per-collection compaction override (arm + optional L0 threshold), resolved through the
  TD-WLP-1 cascade (e.g. a `compaction:on` / `l0_threshold:N` tag, or profile-implied for
  `AppendBulk`), mirroring `CollectionWalConfig` / `effective_config_for_collection`.
* Wire it into `should_trigger_compaction`: fire if (global env armed) OR (per-collection opt-in) —
  and if globally disabled AND no per-collection opt-in → OFF. The global env remains the master
  kill-switch (globally-off can never be overridden to on... i.e. a global *hard* disable wins;
  choose the precedence in the ADR-consistent direction: per-collection opt-in arms only when the
  global switch is not a hard-disable).
* Add per-collection resolution to `OrchestratorCompactionConfig`.

== TDD gate

Integration test `tests/storage_wlp_compaction_gate.rs` (storage-integration CI job — `*storage*`):

* `test_append_collection_arms_compaction_while_global_off`: with the global env unset, an
  `AppendBulk` collection reaching L0 ≥ threshold compacts; `Churn` and the hard-disable do not.

== Gating

Current default: untagged resolves to armed `AppendBulk`; `compaction:off` opts out and an
explicitly falsy global env disables every collection. TD-RDSTRAT-9 adaptive actuation remains
default-OFF until its observe/recommend evidence passes.
