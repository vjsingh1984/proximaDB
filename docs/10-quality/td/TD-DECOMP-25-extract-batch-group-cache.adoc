== Why

`src/query/cache/batch_group.rs` (**12 tests**) is the batch-group cache tier for stream-based RAG
(LLD 6.3, CALL arXiv 2509.18670): it groups batched queries by cluster-access pattern to emit prefetch
hints at group transitions (`BatchGroupCache`, `GroupKey`, `GroupEntry`, `BatchGroupConfig`,
`BatchGroupStats`). It is a truly self-contained leaf — zero `crate::` climb-out, zero real `super::`,
**`tokio`-only** dep — so it moves to a new tiny query-tier crate (no existing query-cache crate fits).

== What moved (behavior-neutral)

* `src/query/cache/batch_group.rs` → `crates/query/proximadb-batch-group-cache/src/batch_group.rs`.
* Root `src/query/cache/mod.rs`: `pub mod batch_group;` →
  `pub use proximadb_batch_group_cache::batch_group;` (the consumer `invalidation_coordinator.rs`,
  which uses `crate::query::cache::batch_group::{BatchGroupCache, GroupEntry, GroupKey}`, resolves
  unchanged via the shim).
* New query-tier crate, dep `tokio` (workspace). No `CAPABILITY_MATRIX.toml` pointer.

== Follow-ups

* **Running total once merged: ~884 tests out of root** (872 + 12).
* Standalone crate `--all-targets` compiled in ~10s with `RUSTC_WRAPPER=sccache` (the efficiency win
  from TD-DECOMP-24 — reused cached tokio artifacts vs a ~cold compile).
