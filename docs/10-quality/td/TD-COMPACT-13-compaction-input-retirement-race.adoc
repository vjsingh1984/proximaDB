= TD-COMPACT-13: Compaction input retirement race — superseded levels stay live and serving (3.03x p50, 2.1x bytes)

:status: Open
:owner: storage
:created: 2026-08-31
:discovered_by: TD-RDSTRAT-13 S3/MinIO + disk campaigns (evidence:
`docs/_internal/status/RDSTRAT13_SIFT1M_LADDER_2026_08_31.adoc`, ledger
`rdstrat13_l3l2_retirement_race`)

== Problem statement

The training-compaction chain publishes a higher level (e.g. an L3 covering the full 1M rows)
but the superseded inputs (the two L2s it merged) **remain live in the serving set** — often
indefinitely. Queries then read every row through BOTH the old and new levels: compute, bytes
and GETs are paid twice (MVCC dedup keeps *results* correct — recall and result-identity hashes
are unaffected — but the cost is not).

Measured (SIFT1M, identical code, beds that settled byte-identically at 2×L2/245,647,274 B):

|===
|Query-time live set |cells probed |rows ranked |bytes/q |GETs/q |object_cold p50 @100 ms RTT
|clean L3-only (retirement won) |11 |370,182 |58.5 MB |21.95 |**2977 ms**
|L2+L2+L3 overlap (retirement lost) |27 (= 8+8+11) |882,178 |125.5 MB |50.57 |**9029 ms**
|===

**3.03x p50 and 2.1x bytes at identical code** — the largest cold-query lever measured in the
TD-RDSTRAT-13 campaign, and the direct blocker for honest absolute cold-latency numbers (the
overlapping bed also doubles the *billed* bytes any bytes-scanned pricing model would see — a
COGS defect for query-priced SKUs).

== Reproduction

Deterministic-settle SIFT1M campaign arms (MinIO + toxiproxy 100 ms RTT; reproduced on 3 of 4
object-store beds and observed timing-dependent, not deterministic): the settle gate certifies
the 2×L2 intermediate (stable window, WAL quiescent), the chain then publishes the 1M-row L3,
and the L2s persist in the live set through every subsequent phase and restart. Reproduces on
MinIO (S3-shaped) beds; the disk (file://) campaign's beds settled clean and stayed clean in the
same window — the race window is the remote-publication/input-deletion path.

== Root-cause hypotheses (to confirm in code)

1. Input deletion after publication fails and is not retried (publish-before-delete contract,
   `--help` text of the settle gate: "Compaction publishes its output before deleting inputs") —
   with the deletion failure swallowed (logged at debug/warn, never re-driven).
2. The manifest/catalog retires inputs only on a later compaction trigger that never fires when
   the live set is already below the trigger thresholds (2 live segments < 5-file L0 rule) —
   the retirement work has no driver once the chain completes.
3. A commit-ordering race: the L3 commit lands in the manifest without an atomic
   retire-inputs step, and no reconciliation pass re-derives liveness from level coverage.

== Fix shape (whatever the mechanism confirms)

* Publication and input retirement must be one atomic manifest step, or
* a reconciliation pass must re-derive live-set coverage (a level fully covered by a higher
  level's row ranges is dead) and retire it — self-healing on boot and after each compaction,
* plus a test: after compaction quiesces, the live set contains no level whose rows are fully
  covered by a higher level (`settle`-gate equivalent as a unit test), and
* the harness settle gate may then drop its workaround once the engine guarantees it.

== Deployment guidance measured alongside (ADR-073 companion data)

The disk device profile measured on the campaign box (PERC H710P RAID10, 10K SAS): sequential
768 MiB/s; **random 1 MiB 99.8 MiB/s; random 128 KiB 16.9 MiB/s; 626 random-4k IOPS** —
HDD-class random behavior. Confirms ADR-073's posture: `PROXIMADB_DISK_CLASS=hdd` (CLOUD
coalescing profile) is mandatory on SAS/HDD RAID; the LOCAL (uncoalesced) profile measured
16.9 MiB/s on this class. AWS mapping for this device class: st1 ≥8 TB is the sequential proxy
(806 MB/s local > st1's 500 MB/s max); **gp3 for anything query-serving** (random IOPS this
device lacks); sc1 is a downgrade and never query-serving.

== Acceptance

* Reproduction test: post-compaction live set has no covered level (fails on current code).
* Campaign re-run: every arm's query-time live set is single-level; object_cold p50 variance
  between arms of the same pair collapses; the clean-bed reference (2977 ms @100 ms proxy,
  356 ms disk) becomes the stable recorded number.
* Ledger: re-measure `rdstrat13_l3l2_retirement_race` to `fixed` with the retirement commit.
