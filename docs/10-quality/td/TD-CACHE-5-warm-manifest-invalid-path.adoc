= TD-CACHE-5: The restart warm-cache manifest is written to a structurally invalid path — TD-CACHE-1 S2 has never warmed anything on object storage
:status: Open
:dim: D3
:pillar: PERF

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open.** Root cause identified by code reading (2026-07-26); one call site, one-line class of fix, plus a type-level fix that closes the class.
| Priority | **P2** — silent, non-fatal, but TD-CACHE-1 S2 (the whole restart-warming slice, shipped 2026-07-24) is inert on any object-store backend that validates paths. The cold-herd it was built to defuse is undefused.
| Component | `src/storage/engines/sst/warming.rs:44-49` (`manifest_url`); `src/storage/trait_components/path_resolver.rs:883-912` (`DrPathBuilder::build_tenant_system`).
| Evidence | Azurite SIFT-1M bench log: `Read failed from az://{bucket}/data/default///manifests/warm_cache.json: Invalid path: not an azure path`. Reproduced by inspection — see mechanism below.
|===

== Mechanism

`manifest_url` resolves the manifest location as:

[source,rust]
----
let resolved = DrPathBuilder::build_tenant_system(None, tenant_id)?;
let prefix = resolved.manifests_subprefix();
Ok(format!("{base}/{prefix}warm_cache.json"))
----

`build_tenant_system` is the *tenant-scoped* helper: it validates only
`account_id` + `tenant_id` and deliberately leaves `namespace_id` and
`collection_id` empty, because the objects it addresses (`_metering/`,
`_trace/`) hang off the tenant root and belong to no namespace or collection.
Its doc contract states this outright (`path_resolver.rs:891`):

____
Only `tenant_root()` / `metering_subprefix()` / `trace_subprefix()` are
meaningful on the result; `root_prefix()` and the collection-scoped subprefixes
are not.
____

`manifests_subprefix()` is a collection-scoped subprefix — it routes through
`root_prefix()`, which renders `format!("data/{}/{}/{}/", tenant_id, "", "")`
⇒ `data/default///`, then appends `manifests/warm_cache.json`. That is the
logged string character-for-character, including the `manifests` segment.

Both directions are best-effort, which is why it has been silent: the write
side only `warn!`s (`warming.rs:91`) and `replay_tenant` returns `(0, 0)` on
read failure (`warming.rs:114-115`, "no manifest = tenant wasn't hot = nothing
to warm"). On a local filesystem backend the triple slash collapses and the
manifest round-trips, which is why the unit/bench coverage passes; the Azure
path parser rejects it, so on the deployment target that TD-CACHE-1 was
written for, warming has never once replayed.

== Not the cause of the ingest stall

This error is logged adjacent to a separate, unresolved SIFT-1M ingest failure
(BACKPRESSURE, `record_count` stuck at 0, `Failed to commit atomic flush
operation`) and was initially attributed as its root cause. It is not, and it
cannot be: both sides are best-effort and neither can block catalog init,
flush, or writes. See link:TD-FLUSH-6-atomic-flush-commit-fails-clean-container.adoc[TD-FLUSH-6]
for the real blocker.

Related mis-attribution to retire: the same log line was read as evidence that
`namespace_id` is unpopulated in the identity flow. It is not — `DrPathBuilder`
is fail-closed on an empty namespace (`validate_id`, `path_resolver.rs:922`;
`build()` returns `MissingNamespaceId`), so a genuinely missing namespace
produces an *error*, never a malformed path. The namespace-identity gap is real
but separate, and is governed by ADR-074.

== Fix

1. **Point fix.** Give the warm manifest a tenant-system subprefix of its own —
   `_cache/`, alongside the existing `_metering/` and `_trace/` — and have
   `manifest_url` call that. Do *not* "make `manifests_subprefix()` valid on a
   tenant-system path": that would mean fabricating a namespace segment for an
   object that legitimately has none, and would corrupt the `_metering/` /
   `_trace/` contract as collateral.
2. **Class fix (recommended, small).** Split `DrResolvedPath` by meaning —
   `DrCollectionPath` (exposes `root_prefix`, `manifests_subprefix`,
   `segments_subprefix`, …) and `DrTenantSystemPath` (exposes `tenant_root`,
   `metering_subprefix`, `trace_subprefix`, `cache_subprefix`). Today one struct
   carries two meanings and which methods are valid depends on which constructor
   ran, enforced only by a doc comment — this defect is that gap being exercised.
   After the split it fails to compile.

Audit result: `build_tenant_system` has exactly **two** callers —
`src/metrics/metering_writer.rs:99` (correct, uses `metering_subprefix()`) and
`warming.rs:45` (this defect). There is no third seam to hunt.

== Verification

* Unit: assert `manifest_url` contains no `//` after the scheme and that the
  rendered prefix hangs off `tenant_root()`.
* Live: object-store (Azurite) run — graceful shutdown emits a manifest that a
  subsequent boot reads back, with `segment_invariants_cache_hits_total` and
  survivor-cache hits advancing on the first post-restart queries (the metric
  pair from TD-CACHE-4 that made TD-CACHE-1's arming observable in the first
  place).
* Regression guard: a test that constructs a tenant-system path and asserts the
  collection-scoped accessors are unavailable (post-split) or rejected.
