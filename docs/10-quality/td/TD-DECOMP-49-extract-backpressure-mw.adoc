= TD-DECOMP-49: Move backpressure middleware into existing proximadb-network-middleware crate

[cols="1,3", options="header"]
|===
| Field | Value
| Status | Landing
| Severity | Low — behavior-neutral re-export (+1 crate-local dep)
| Component | `crates/platform/proximadb-network-middleware`; root `src/network/middleware/mod.rs`
|===

== What moved
`src/network/middleware/backpressure.rs` (5 tests: `BackpressureConfig` +
`create_concurrency_limit_layer` tower `ConcurrencyLimit` wrapper) → the EXISTING platform crate
`proximadb-network-middleware`, joining `cors` + `rate_limit` + `timeout` (TD-DECOMP-22/48). Root
`network/middleware/mod.rs` re-exports it (`pub use proximadb_network_middleware::backpressure;`),
so the existing `pub use backpressure::{BackpressureConfig, create_concurrency_limit_layer};`
resolves unchanged.

== Why into an existing crate
backpressure.rs needs only `serde` + `tower` — `serde` was already declared by the crate; `tower`
is added crate-locally (`tower = { workspace = true }`, inheriting the workspace `limit` feature).
NO new crate, NO root `Cargo.toml` workspace-member/dependency wiring → no stacked-PR Cargo.toml
conflict. Verified: standalone + clippy -D warnings + root lib all pass. SIFT recall ratchet SKIPS
(network/** is not storage_changes).
