= TD-CACHE-6: survivor cache records ZERO hits on the probe-armed read path (identical repeat queries)
:status: RESOLVED (fix landed in #1227; this doc = the original filing + evidence)
:filed: 2026-07-26
:priority: P1 (the default read path since #1210 may bypass the warm tier)

== Evidence (two-tenant Azurite bed, 2026-07-26)

Tenant A repeated an IDENTICAL 50-query slice 4+ rounds against its trained
100k collection (probe default-ON): survivor cache recorded **12,554 misses,
0 hits** — every admission, never a serve — while its pinned floor filled to
98.7% of entitlement (pinning itself works; TD-CACHE-3 gauges correct).
Tenant B (churner) recorded 108 hits, so hits are possible. Identical
queries produce identical survivor sets and identical coalesced ranges, so
repeat rounds MUST hit if the read path consults the cache.

== Hypothesis

The coarse-probe branch (default-ON since #1210) fetches its probed-cell /
Region-B ranges without the `survivor_cache.get_or_fetch` seam the
whole-region branch uses — i.e. the warm tier serves only the fallback
path. If confirmed, the survivor cache (and its tier floors/pinning
economics) are dark on the DEFAULT path. Verify by tracing
`coarse_probe_survivors` + the probed SQ8 fetch for `get_or_fetch` usage,
then wire the probe fetches through the same seam (tenant-keyed, metered).

== Also observed (separate bug)

Warm-manifest replay fails on object storage: `Read failed from
azure://…/data/default///manifests/warm_cache.json: Invalid path: not an
azure path` — the manifest URL builder emits a path the azure backend
rejects (triple slash / scheme handling). Restart warming (TD-CACHE-1) is
therefore local-disk-only today. Fix the URL join in `warming.rs`
manifest_url for scheme-prefixed bases.

== Resolution

Fixed in #1227 (merged 2026-07-26): the probed-cell Region-A fetches and the
whole-Region-B fallback now flow through `survivor_cache.get_or_fetch`
(tenant-keyed, metered, floors apply); pinned by
`probe_path_hot_repeat_served_from_cache_seam`. This doc is retained as the
original two-tenant-bed filing + evidence that surfaced it. A follow-up
(TD-CACHE-8, #1233) showed the deeper hot-tier reuse limit for DIVERSE
queries — separate from this seam bug.
