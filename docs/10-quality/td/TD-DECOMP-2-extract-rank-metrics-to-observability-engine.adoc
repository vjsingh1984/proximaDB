== Why

The root `proximadb` crate is an 850K-LOC monolith whose lib test binary bundles **9,538
inline `#[cfg(test)]` tests** in one rustc process — the thing that OOMs the 16 GB CI runner
and forces `CARGO_BUILD_JOBS=1` (confirmed by the build/CI-acceleration effort, PR #1360: the
remaining bottleneck is this single-rustc root compile, not jobs or cache). The only structural
fix is decomposition — move `src/<mod>/` modules into their target crates; inline tests leave
with the code and the lib binary shrinks proportionally.

`src/observability` is the documented "Slice 2" (`proximadb-observability-engine/Cargo.toml`
calls it out), but research (3 Explore agents) showed it is **mostly structurally blocked**: the
WAL-backed `storage/` slice (`crate::storage::persistence::write_ahead_log`) and the axum/tonic
`ingestion/adapters/*` cannot move to a *modality*-tier crate (layering forbids modality→root/
platform/integration). The **one clean, unblocked, modality-legal leaf** is `rank_metrics` —
deps only `prometheus` (+ fully-qualified `proximadb_rank_*` trait impls), 4 callers, zero
`crate::` climb-out paths. This slice extracts it as the **first application of the TD-DECOMP-1
recipe to a whole module**, proving the pattern for the larger observability/storage/query/
network decompositions and moving 14 tests out of the monolith binary.

== What moved (behavior-neutral)

* `src/observability/rank_metrics.rs` → `crates/modalities/proximadb-observability-engine/src/rank_metrics.rs`
  — moved verbatim. The file has **no `crate::` climb-out paths** (only `use prometheus::{…}` +
  `use std::sync::{Arc, OnceLock}`; the rank trait impls `proximadb_rank_onnx::ModelCacheObserver`
  and `proximadb_rank_core::RankMetricsSink` are fully-qualified). No content edits.
* `proximadb-observability-engine/Cargo.toml` gained `proximadb-rank-core` +
  `proximadb-rank-onnx` (both **modality-tier** → the new edges are modality→modality, legal under
  `scripts/check_workspace_boundaries.py`). `prometheus` was already a dep.
* `proximadb-observability-engine/src/lib.rs` declares `pub mod rank_metrics;` (alphabetical) +
  a Slice-2a note in the extraction-status doc block.
* Root `src/observability/mod.rs` replaces `pub mod rank_metrics;` with
  `pub use proximadb_observability_engine::rank_metrics;` — so all 4 callers
  (`network/metrics_service.rs`, `network/shared_services.rs`, `network/rest/canonical/rank.rs`,
  `tests/rank_services_e2e_test.rs`) and the `/metrics/prometheus` scrape of the moved `OnceLock`
  `REGISTRY`/`METRICS` statics resolve **unchanged**.

Behavior-neutrality is structural: the public path `crate::observability::rank_metrics::*`
(resp. `proximadb::observability::rank_metrics::*`) resolves to the same items via the re-export;
the engine crate gains **no** dependency on the root (verified by `check_workspace_boundaries.py`),
so no cycle is possible.

== Verification

* `cargo check -p proximadb-observability-engine` green (moved module + new rank deps compile).
* `cargo check -p proximadb` green (root compiles through the re-export shim).
* `cargo nextest run -p proximadb-observability-engine --lib` — the 14 `rank_metrics` tests now
  run in the engine's own binary.
* `cargo nextest run -p proximadb --lib` green — root lib still compiles; the root lib test binary
  no longer includes the 14 `rank_metrics` tests (they left with the module). The 4 root callers
  compile through the shim.
* `python3 scripts/check_workspace_boundaries.py` + `scripts/check-layering.sh` green — engine→
  rank_core/rank_onnx is modality→modality (allowed); engine→root stays 0 (no upward edge).
* `cargo build -p proximadb-server` + `cargo clippy --lib --bins -- -D warnings` +
  `cargo fmt --check` + `make work-commit-check` green.
