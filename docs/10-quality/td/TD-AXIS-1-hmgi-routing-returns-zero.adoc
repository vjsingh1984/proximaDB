== Symptom

A search via `search_with_mode("approximate")` routes through `AxisManager::query`, which **skips the
HMGI/HNSW path** (where the index was built during insert) and falls to the IVF path (which has **no
data** for this collection). Stage 2 returns **0 results**. Every approximate query falls back to the
Stage-3 SST/memtable scan — defeating the entire purpose of the ANN index.

Trace evidence (RUST_LOG on the search stages):
```
Stage 2 complete: 0 AXIS HNSW results
query routed through IVF route=query_ivf collection_id=getcount_sst
```

== Root cause

The routing gate at `manager.rs:1439`:
```rust
if self.is_hmgi_enabled(collection_id).await && hmgi_query_safe {
    search_hmgi()  // ← the HNSW path (where the index IS)
} else {
    // falls through to IVF → returns 0 (no data)
}
```

`is_hmgi_enabled(collection_id)` returns **false** at query time despite HMGI being enabled at insert
time. The `hmgi_enabled_collections` set was populated with the collection's **UUID** during insert
(trace: "HMGI enabled for collection 'ec9af1b2-...'"), but the query checks it with a **different
identifier** (the resolved collection name or the partition key `oid:.../var:.../mod:...`). The
`HashSet::contains()` mismatch → HMGI skipped → IVF fallback → 0.

`is_hmgi_routable_query` (`:4688`) passes (the query IS `VectorQuery::Dense`, no filters) — so the
failure is specifically in `is_hmgi_enabled`.

== Fix approach

1. **Diagnostic** (first): add a log in `AxisManager::query` printing the `collection_id` +
   `is_hmgi_enabled` result + the contents of `hmgi_enabled_collections` to confirm the ID mismatch.
2. **Fix**: resolve `collection_id` to the canonical `object_id` (ADR-031) **consistently** at insert
   and query time. OR — add a fallback: if HMGI is not enabled for this ID, route to the legacy HNSW
   path (`query_hnsw`) instead of IVF (which has no data for single-modality collections).
3. **Test**: extend `bench_25` to assert Stage 2 returns > 0 results (AXIS serving) after the fix.

== Dependencies

- **Unblocks**: TD-HELIX-1 (the block-targeting flow requires AXIS to return matching IDs);
  TD-IOTRACE-1 (warm-path measurement is meaningful only after the ANN index serves).
- This is the **highest-priority TD** — without it, the entire index→ID→block-targeting chain is broken.
