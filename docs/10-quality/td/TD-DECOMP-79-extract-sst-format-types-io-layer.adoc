== What moved (Phase 5 PR C, ~3.6K LOC total)
1. **SST on-disk format types** → engine-core `sst_format_types.rs`: SST_MAGIC,
   `SstableHeader` (+ `VectorFormat` carry-along), `IndexEntry` + its 360-line custom
   serialization impl (JSON-safe serde via `proximadb-search-types::json_value_serde`),
   `BPlusTreeIndex`/`BPlusLeaf`, `SstableIndex` + impl, `SstMetadataStats`, and
   `SstableReadingStrategy` (from `sst_query_engine.rs:107`). Root `sst/mod.rs` re-exports
   everything — zero consumer-path changes across the SST engine dir.
2. **`proximablocks/arrow_reader.rs`** (731 LOC, 7 tests) — its only root ref
   (`sst::{SstableHeader, SstableIndex}`) became intra-crate.
3. **`coalesce_strategy.rs`** (132 LOC, pure fns) — carry-along for sst_io_layer.
4. **`proximablocks/sst_io_layer.rs`** (1,240 LOC, 1 test) — both reader+writer fields
   converted: `Arc<FilesystemFactory>` → `Arc<dyn FilesystemPort>`,
   `Arc<UnifiedCachingFilesystem>` → `Arc<dyn FileSystem>` (only trait methods used:
   supports_mmap/get_mmap/read — the caching fs implements the trait). Root callers coerce.

== Block-surgery lesson (recorded)
The three struct/impl blocks in `sst/mod.rs` were NOT contiguous with their derives/impls
(the impl IndexEntry sat 300 lines below the struct; VectorFormat sat between the two cut
ranges; the ReadingStrategy cut split the enum from its closing brace and derive). Each
required a follow-up fix caught by compile/clippy — the TD-71 "resolve what refs point at"
method works, but line-range extraction of interleaved blocks demands a post-extract
derive/impl audit: `grep -B2 'pub struct\|pub enum' <extracted>` + compile.
