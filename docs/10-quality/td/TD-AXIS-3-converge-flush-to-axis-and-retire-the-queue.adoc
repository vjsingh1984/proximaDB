== 1. Problem

Flush→AXIS had two implementations split by engine, and compaction→AXIS had a
working path plus a broken duplicate. See ADR-078 §Context for the full evidence;
the load-bearing facts:

* SST indexed **directly** from the in-memory `ProximaRecord`s on
  `FlushParameters.vector_records`. VIPER/HELIX/NOVA published a metadata event
  to the queue whose consumer **re-read the same vectors back from storage**.
* Those three engines took the queue route only because their `axis_manager`
  field is constructed `None` and **nothing ever set it** — not a design choice.
* The queue's compaction leg (`rebuild_indexes_after_compaction`) receives
  **swapped arguments** (`(file_paths, &[])` into `(old_files, new_files)`), so
  its nested loop never executes; it then increments `successful_migrations`.
* `EventType::Delete` is never emitted; `can_compact` fails open; queue state is
  PUT in full per event and is semantically stale after a restart.

**Explicitly not doing:** repairing `rebuild_indexes_after_compaction`. Fixing the
swapped arguments would resurrect a second compaction-indexing path beside the
working `update_indexes_after_compaction` and create a genuine double-index
hazard that does not exist today (ADR-078 D2).

== 3. Verification

Compile is not evidence here — this changes the indexing path.

**Done for S1 (convergence).** The AXIS indexing logic itself
(`handle_flushed_vectors`) is unchanged by S1 — it only changes how records
*reach* it (in-memory vs queue re-read). The verification chain:

* **Each engine populates `params.vector_records` as the flush input** (the
  load-bearing fact): VIPER (`engine.rs` derives `vector_records_v1` from it),
  HELIX (`mod.rs` derives `sorted_records` from it), NOVA (`engine.rs` consumes
  it). Code-verified; the hook reads the same source the old queue re-read from
  disk.
* Unit tests on the shared guard: absent config ⇒ no AXIS (ADR-070), empty
  `index_configs` without the `pax_vector_format:off` tag ⇒ no AXIS, tag match
  trimmed + case-insensitive, missing manager ⇒ quiet no-op.
* A recording-`IndexEngine` spy pins the dispatch: the guard, once passed,
  delivers the exact records + files to `handle_flushed_vectors` (explicit handle)
  *and* via the boot-registered global fallback (the path VIPER/HELIX/NOVA take,
  since their `axis_manager` field is `None`).

**Still owed (moves to the S2 follow-up, mandate #10/#11):**

* **Recall ratchet for all four engines** against the f32 baseline — SST is
  covered by `tests/td112_postflush_recall_e2e.rs`; the harness for VIPER/HELIX/
  NOVA over the AXIS path runs in the qa-gate.
* `cargo build -p proximadb-server` (and the SWIFT `experimental-engines`
  feature) — deleted queue types may have `#[cfg(test)]` or feature-gated callers
  that `--lib` misses.

== 4. Residual

A segment flushed but not indexed before an **unclean** restart is still never
re-indexed. That gap predates this TD and the queue never addressed it either;
tracked as **TD-AXIS-4**.
