== Status & relationship to ADR-062

This is the implementation spec for link:../../12-design/adr/ADR-062-coalesced-rabitq-header-self-describing-footer-pax-layout.adoc[ADR-062].
The ADR carries the *why* (the measured GET ceiling, first principles, alternatives rejected);
this TD carries the *what/how* (byte layout, writer/reader changes, read path, sizing,
compaction, stats, phasing, verification). Read the ADR first.

== The layout (byte-level)

Same segment magic/version as today; in-place writer + readability-preserving reader (see
<<_readability_preservation>>). One self-contained logical object per file:

```
 offset
 0      HEADER-PREFIX (~32 B, fixed):
          [SEGMENT_MAGIC][version:u8][rabitq_off:u64][rabitq_len:u64]
          [footer_off:u64][footer_len:u64]
 32      RaBitQ region [rabitq_off, rabitq_off+rabitq_len):
          [RaBitQ col header: centroid(dim·f32) + subspace meta, ONCE]
          per row: [code: ceil(dim/8) B][side: dist_to_centroid f32 + inv_factor f32 = 8 B]
          rows in CLUSTER order (IVF cell ▸ Hilbert/PC1 within cell — cluster_order_pca_ivf)
 …      Block0 [PBLK hdr | OID | tenant | ts | props | labels | text | SQ8 | fp32 | footer]
        Block1 … BlockK                              ◄ UNCHANGED PaxBlock decoder (RaBitQ stripe REMOVED)
 …      FOOTER-INDEX [footer_off, footer_off+footer_len):
          [schema snapshot: field-ids, types, column order]
          [block table: per block { off, len, row_count, stats[] }]
          [per-stripe ENCODING MAP: RaBitQ/SQ8/fp32/raw + compression, per column]
          [rabitq_off/len mirror][row_count]
        [footer_len: u64]
        [SEGMENT_MAGIC]
```

* **HEADER-PREFIX @0** — fixed ~32 B; the RaBitQ scan GET reads `[0, rabitq_len]` in one
  ranged GET (prefix + region coalesce). Zero metadata dependency for the hot scan.
* **RaBitQ region** — the *index* (≈ `dim/8 + 8 B`/row → 24 MB for 1 M×128d; 200 MB for
  1536d). Cluster-ordered so survivors are contiguous (rerank coalescing).
* **Blocks** — the *data*; `PaxBlockWriter`/reader reused verbatim for SQ8/fp32/metadata/text.
* **FOOTER-INDEX @tail** — the metadata hub (Parquet-style): schema snapshot, block table,
  per-stripe encoding map, per-block stats. Read via a tail GET (`[size-footer_len, size]`),
  cached per-file.

== Writer changes (in-place)

`write_pax_segment_ordered` / `PaxSegmentWriter::finish()` (`segment_format.rs`) becomes:

1. Buffer the flush batch (already done — flush accumulates a `BATCH_SIZE` batch in RAM).
2. Compute the RaBitQ centroid + per-row codes (needs the whole batch → buffered, no streaming break).
3. Emit: HEADER-PREFIX → RaBitQ region → blocks (SQ8/fp32/metadata/text, existing writer,
   RaBitQ stripe omitted) → FOOTER-INDEX → footer_len → SEGMENT_MAGIC.
4. `SegmentMeta` gains `rabitq_off/rabitq_len`; `pax_write_outcome` (`flush/mod.rs:970`) threads
   them into the VOE `IndexEntry`/footer so the read path finds the region.

Same magic/version. Default-ON for new writes (ADR-061 pre-GA amendment: write-time internals
replace predecessors).

== Reader changes — scan-then-rerank

`try_pax_cascade` (`search/mod.rs`) becomes:

1. **Scan:** `fs.read_range(path, 0, rabitq_len)` — one GET/file (LRU-cached). Rank all codes
   (keep=100%) → approximate distance for every vector.
2. **Select top-M survivors** (M = adaptive GET-budget; expand until the next survivor crosses a
   block boundary — see <<_self_derived_geometry>>).
3. **Rerank:** survivors are cluster-adjacent → they fall in few adjacent blocks → reuse
   `plan_selected_block_ranges` (`sst_query_engine.rs:733`) + `ObjectRangeCoalescePolicy` +
   `FileSystem::read_ranges` (batched multi-range) to fetch their SQ8(+metadata) stripes in a
   few coalesced GETs. Decode with the UNCHANGED block decoder.
4. **Finalize** top-k with fp32 (fetch fp32 stripe for finalists only).
5. **OID recovery** unchanged (`segment_format.rs:737-755`).

Net: ~1 RaBitQ GET/file (cached) + a few coalesced survivor GETs, vs today's ~4-5 × every
selected block.

== Footer-index detail

* **Schema snapshot** — the catalog schema at write time (field-ids, types, column order). The
  reader decodes from the footer schema (self-describing). Catalog stays the *write* authority.
  (Full schema-*evolution* reconciliation is the follow-on, TD-TBL-4/ADR-047.)
* **Per-stripe ENCODING MAP** — which stripe is RaBitQ/SQ8/fp32/raw + which compression, per
  column. This is the encoding control plane (Parquet-style); magic stays format-family-only.
  Future clustered-SQ8/fp32 compression registers here, no magic bump.
* **Per-block per-column STATS** — optional, tagged, extensible:
+
```
stats: [ per-column: { col_id, stats_kind: StatsKind, payload } ]
enum StatsKind { None, BloomOid, MinMax, BloomOid_MinMax, … }   // add kinds, no format change
```
v1: `BloomOid` (per-block OID bloom, no false negatives → `vector_by_id`/edge-by-oid skips to the
one positive block — the point-lookup index). `MinMax` pushdown + bloom on other columns deferred
(forward-compatible; unknown kinds skipped).

== Self-derived geometry

Block geometry emerges from dim × tier-composition × backend IOPS (replaces static
`SST_DEFAULT_VECTORS_PER_BLOCK`/`PROXIMADB_PAX_BLOCK_SIZE`):

```
 per_row_survivor_bytes = sq8(if present)·dim + fp32(if present)·4·dim + fixed_metadata   (RaBitQ excluded — it's in the header)
 block_bytes_target     = storage_profile.iops_target ∈ [iops_min, iops_max]              (backend-derived)
 rows_per_block         = clamp( iops_target / per_row_bytes, ceil(iops_min/per_row), floor(iops_max/per_row) )
```

`iops_min ≈ 512 KB`, `iops_target ≈ 2 MB`, `iops_max ≈ 8 MB` (S3/ABFS → 4 MB; MinIO/local →
512 KB-1 MB). The RaBitQ header region is sized separately (one GET = N × rabitq_bytes, cached);
this governs only the survivor-fetch block. Adaptive survivor M expands until the next survivor
would cross into a new block (a new GET), then stops — clustering makes this elasticity cheap.

== GET-budget compaction (file-count = GET-count knob)

A collection accumulates files LSM-style (flush → one self-contained file). Compaction triggers
on a **query GET-budget**: projected RaBitQ-GETs/query (= file count) exceeds target, or
file-count > threshold (3-5). Merge N→1: read each file's RaBitQ (cheap), re-cluster the union
(`cluster_order_pca_ivf`), rewrite one file. Double duty: fewer files (fewer GETs) AND tighter
survivor locality. Atomicity: single-object conditional replace (S3 `If-None-Match` / ABFS
`If-None-Match`). This is the WLP-7 compaction-scheduler seam reframed as the vector-query
GET-cost lever.

== Readability preservation

Per the ADR-061 pre-GA amendment, on-disk *readability* of already-written segments is preserved
even as write-time internals replace predecessors. Mechanism: the reader keys off the
FOOTER-INDEX / header-prefix `rabitq_off` — **present → scan-then-rerank; absent → legacy
in-block RaBitQ path**. So the reader supports both layouts (mixed-read) via a cheap
presence-field, while the writer changes in-place (same magic/version). No full dual-format
versioning machinery pre-GA; the presence-field is the serde-default/version-marker the
amendment sanctions.

== Phased implementation (one coherent PR at a time)

* **PR1 — layout + scan-then-rerank foundation (the GET win):** header-prefix + RaBitQ-head +
  footer-index (block table + encoding map + schema snapshot) + scan-then-rerank read path
  (reuse `plan_selected_block_ranges`/`read_ranges` + unchanged block decoder) + self-derived
  geometry + in-place writer/reader + round-trip/detection tests + SIFT recall + GET measurement.
  Indivisible core.
* **PR2 — cost control:** GET-budget compaction trigger (WLP-7 seam) + per-file RaBitQ/footer
  LRU cache (engine `DashMap` vs mmap residency).
* **PR3 — point-lookup index:** per-block OID bloom (`StatsKind::BloomOid`) + `vector_by_id` fast path.
* **Deferred (foundation anticipates):** schema-evolution semantics (TD-TBL-4/ADR-047); `MinMax`
  pushdown; clustered SQ8/fp32 compression; within-cell Hilbert; text-as-variable-fetch; coarse
  VOE prune for monster collections; per-collection RaBitQ sidecar only if file-merging proves
  insufficient at extreme scale.
