== Problem

A systematic sweep for inefficient data-structure use (container choice and
accumulation strategy imposing unnecessary time/memory complexity) found the
same two defect families that `tests/graph_ingest_asymptotic_integration_test.rs`
was filed to block, across the GA hot paths:

* **A. Per-item work ∝ store size** — deep-clone the container per access, or
  scan the whole table per item.
* **B. Unbounded accumulate → full sort → truncate; Vec membership in loops;
  clone churn per item.**

Every one of these passed all existing tests: fixed-size tests cannot see
asymptotics (the graph ratchet's founding observation).

== Fixed (top tier, one PR)

[cols="2,3,3", options="header"]

| Site | Defect | Fix

| IVF `find_nearest_centroids` | full sort of all centroids for top-n | bounded heap, stable tie order preserved

| AXIS `execute_exact_filtered_query` | deep-cloned every record in the collection per filtered query (ADR-011 PreFilter default route) | borrow under the read guard (taken after the awaits), one `Utc::now` per query, bounded top-k

TD-CAT-5 is closed by this work (options 2+3): DashMap lock shape + bounded
ring-sampled eviction; victim choice relaxes exact→insert-recency-biased
sampled LRU (an ancient cold entry can squat until TTL expires it).

== Shared utility

`TopKHeap<E: Ord>` (generic bounded top-k) added to
`crates/foundation/proximadb-search-types/src/bounded_queue.rs` beside the
existing `BoundedPriorityQueue` (untouched). A 10k-item seeded differential
test proves it reproduces stable `sort_by`+`truncate` exactly (tie-break by
explicit sequence key in the entry's `Ord`). Root re-export:
`crate::core::search::bounded_queue::TopKHeap`.

== Ratchets (shape, not wall-clock)

* `tests/ivf_ingest_asymptotic_test.rs` — equal ingest batches, last/first
  median ratio ≤ 4.0 (same self-normalizing shape as the graph ingest ratchet).
* Graph hybrid in-module — 500 vs 4000 nodes at fixed degree, full-traversal
  time ratio ≤ 20 (linear ≈8×, the blocked quadratic ≈64×); brute-force
  differential tests for BFS/Dijkstra/path.
* HNSW — permissive-predicate parity with `search_layer` + sparse-predicate
  drain guard (protects the skip-through recall mechanism against a future
  beam-cap "optimization").

== Rejected alternatives (recorded so they are not re-litigated)

* **HNSW hard beam cap** on `search_layer_predicate` — contradicts the
  documented sparse-predicate full-drain recall mechanism (the 1.3
  investigation note above `oversample_k`); the prune is provably identical.
* **Arc-valued CatalogCache entries** — all consumers return owned values
  through the `Catalog` trait, so Arc just moves the clone to the call site.
* **`lru`-crate O(1) LRU for CatalogCache** — `LruCache::get` takes `&mut`
  (write-shaped), reintroducing the whole-map write lock per lookup.
* **Reusing `AdjacencyProjectionState` for hybrid traversal** — it indexes
  oid-keyed canonical `ProximaRecord` edges, a different domain from the
  pool's `Edge` table.
* **`AdaptiveStore::mutate` as an async trait method taking a boxed closure**
  — `#[async_trait]` rewrites elided object lifetimes in argument position,
  tying the closure to caller lifetimes (E0521/E0597); the sync
  `try_mutate_sync(&mut (dyn FnMut(..) + '_))` form with an explicit
  async-backend `None` fallback is object-safe and compiles.

== Deferred inventory (open)

Experimental engines (feature-gated, no production traffic):

* raptor `writer.rs:1064` — O(E×N) cluster-membership lookup per edge
  (`find_cluster_for_node_static` scans all clusters' member Vecs per edge);
  a one-pass node→cluster array is O(N+E).
* raptor `writer.rs:227` — `BloomFilterBuilder::add_id` O(R²) `contains` on a
  `Vec<String>` per row-group build; a bloom filter is duplicate-insensitive —
  the dedup is semantically unnecessary.
* raptor `lib.rs:389` — `read_row_groups_selective` re-reads the WHOLE file
  (plus metadata) per selected row group; one read + slices is O(filesize).
* raptor `writer.rs:5110` (also `matrix_builder.rs:585`, `lib.rs:1717`) —
  full sort per node for top-M edges in kNN graph build;
  `select_nth_unstable_by` (precedent: `coalesced_rabitq.rs:466`) is O(n).
* swift `engine.rs:1333` — compaction merge clones every record version
  (locator map + survivor materialization is the fix shape, TD-188 pattern).
