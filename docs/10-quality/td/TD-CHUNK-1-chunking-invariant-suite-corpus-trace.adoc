== Why this is first

The audited suite has **426 passing tests and caught none of the defects**, because it asserts execution
rather than invariants — no test compares `text[start_pos:end_pos]` against `chunk.text`, none checks
coverage, and `test_unicode_text` asserts only `len(chunks) > 0` and `end_pos > start_pos`, both of which
hold for the single unsplit 41 KB chunk the CJK bug produces. Writing implementation first reproduces
exactly that. A fix that no test can see is indistinguishable from no fix.

== Deliverable 1 — the invariant suite

Parameterised over every boundary-source set × corpus entry. Each property maps to an ADR-091 axiom and
each is expected to FAIL somewhere on today's code; record which, in this TD, as the baseline.

. **Totality** — every non-whitespace byte of the input is covered by ≥1 chunk. *(Fails: `SEMANTIC`
  loses 29% on prose and 100% on header-dense Markdown; `sentence`/`paragraph` drop interior groups.)*
. **Exactness** — `source[span] == chunk.text` under the declared basis, non-ASCII included.
  *(Fails: 6/7 strategies; 4 unrecoverably.)*
. **Cap** — `tokens(chunk) <= budget` under the collection's tokenizer. *(Fails: 1 chunk of 100,000
  chars against a 2,048 cap on boundary-free input.)*
. **Non-empty** — non-empty input yields ≥1 chunk; a sub-minimum document is emitted short or rejected
  loudly, never dropped. *(Fails: `fixed_size`/`semantic` return `[]` under 100 chars; victor-rag drops
  everything under 200 while still incrementing `total_documents`.)*
. **No containment** — no span strictly inside another outside declared overlap.
. **Batch/stream equivalence** under **randomised** piece sizes. *(Fails: 303 mismatches in a 1,200-case
  fuzz on `sentence`, invisible to the existing fixture because it always places a period before a
  capital — the same blind spot my own first pass had.)*
. **Config safety** — no configuration hangs. *(victor-rag `_chunk_text` infinite-loops whenever
  `min_chunk_size < chunk_overlap`; ProximaDB's `__post_init__` normalisation makes it unreachable.
  Encode the property so neither can regress.)*
. **Idempotence** — re-chunking a chunk at the same budget is a fixed point.

== Deliverable 2 — the shared corpus

Ships as a fixture package that **every** consumer runs (ProximaDB, victor-rag, anvaiops). No
implementation brings its own flattering inputs — that practice is why each suite was green while broken.
Every entry earns its place by having caught a real defect:

[cols="2,3",options="header"]
|===
| Entry | Defect it caught
| prose, ~1 MB | 29% `SEMANTIC` loss; quadratic `sentence` accumulator
| header-dense Markdown | **zero chunks** — 100% loss, in *both* implementations independently
| CJK + emoji | sentence regex requires an ASCII capital, so `。！？` never fire despite shipping in the default config
| boundary-free 100 KB | `max_chunk_size` never enforced — 48× overrun
| whitespace-heavy | quadratic blowup: 518 KB → 17.5 s (0.03 MB/s vs a 13.5 MB/s baseline)
| sub-minimum documents | silent total drop
| table-heavy Markdown | `preserve_tables` is a flag no strategy honours
| code-fenced Markdown | `_preserve_special_blocks` splices at stale offsets and destroys content
| HTML, JSON | victor-rag's fabricated offsets (a synthetic cursor over re-serialised text)
|===

== Deliverable 3 — the cost trace

Per-document, `TenantContext`-tagged: `bytes_in`, `bytes_covered`, `bytes_duplicated`, `spans_dropped`,
`chunk_count`, `tokens_out`, and a `boundary_source` histogram.

Every defect above would have been a trace field: `bytes_covered < bytes_in` **is** the loss bug;
`spans_dropped > 0` **is** the min-size drop. A chunker that cannot report its own coverage is
unauditable, and today none of the nine can. The trace is also the pre-embedding KEU/KSU estimate, so
ingest cost becomes predictable before the spend rather than reconcilable after it.

== Acceptance

Suite + corpus + trace merged, wired into the **feat→develop** lane (which runs no chunking suite
today), with every failure recorded here as the measured baseline. Explicitly **not** in scope: fixing
any of them. That is TD-CHUNK-2 onward.
