= TD-RATE-1: REST request rate limiting is inert — a config field nothing reads, certified by a test
:icons: font

**Status:** Filed 2026-08-24. **Option 1 (mount, default-off) SHIPPED
2026-08-25** via `PROXIMADB_REST_RATE_LIMIT_RPM` — see "Resolution" below.
**Origin:** TD-TENANT-4 (PR #1705) surfaced `rate_limit_middleware` as unmounted
dead code and explicitly scoped it out as a non-goal. This TD records the full
inventory so the mount-vs-retire decision is made on evidence, not impression.

== The inventory (verified 2026-08-24)

Rate limiting in this repo is three separate things with three different
liveness states. Conflating them is the mistake this TD exists to prevent.

[cols="3,3,1,3", options="header"]
|===
| Capability | Mechanism | State | Keyed on

| pgwire *request* limiting
| `RateLimitState` built from `PROXIMADB_PGWIRE_RATE_LIMIT_RPM`
  (`multi_server.rs:918-953`), checked at `postgres/protocol.rs:1375`
| **LIVE**, env-gated, default off
| `self.peer_ip` — the real socket peer

| Auth *failed-attempt* budget
| `security::advanced_features::RateLimitingService`, called at
  `auth_service.rs:287` (`record_failed_auth`) in the authenticate path
| **LIVE**, per-principal
| attempted principal id

| REST *request* limiting
| `rate_limit_middleware` (`proximadb-network-middleware/src/rate_limit.rs:285`)
  + `RateLimitLayer` + `NetworkConfig.rate_limit`
| **DEAD** — zero non-test references to the middleware and the layer
| would be `get_client_ip` (now observation-based, TD-TENANT-4)
|===

== The defect is not "dead code" — it is *certified* dead code

Three properties stack, and the third is the one that matters:

. **A config section that parses into nothing.** `[network.rate_limit]` is
  documented in the module doc (`network/mod.rs:120`), deserialized into
  `NetworkConfig.rate_limit` (`core/config.rs:23` — the config tree IS live),
  and read by no code. An operator who sets it gets silent no-op. This is the
  chunking-census finding again — *a config field read by nobody is
  indistinguishable from one left unset* — now in the network tier.
. **A "secure by default" default that isn't.** `RateLimitConfig::default()`
  carries `enabled: true`, and `network/mod.rs:480` asserts it with the comment
  *"ENABLED by default (secure by default)"*. The test passes. Nothing is
  enabled — the field feeds no consumer. A green test certifying a security
  property that does not exist is the exact false-assurance pattern ADR-090
  documented (*five controls that existed and never fired*).
. **The middleware's own doc example implies use.**
  `middleware/mod.rs:33-38` shows constructing `RateLimitConfig::default()` as
  a working recipe ("Enabled by default").

TD-CAT-8's lesson applies in both directions: config-reachable surface must not
be deleted as if dead (it is a compatibility contract), but it also must not be
*presented* as live when it is inert. This TD restores the second half;
the first half is the pending decision.

== Why mounting is now sound (it was not before TD-TENANT-4)

Before #1705, `get_client_ip` returned a client-controlled header value. A
mounted per-IP limiter keyed on that would have been trivially evadable
(rotate `X-Forwarded-For`) **and** weaponizable (spam one victim's address
into the header to exhaust *their* bucket — a rate-limit DoS).

After #1705 the address is the observed transport peer (or a trusted-proxy
assertion under `PROXIMADB_TRUSTED_PROXY_CIDRS`), so per-IP keying is sound.
The dead middleware's dependency was the blocker; TD-TENANT-4 removed it
incidentally.

== Options

. **Mount, default-off** *(recommended)* — wire `NetworkConfig.rate_limit`
  (and/or an env gate mirroring `PROXIMADB_PGWIRE_RATE_LIMIT_RPM`) into the
  REST router's layer stack, reusing the tested `RateLimitState` the pgwire
  path already builds. Default off preserves single-node/embedded behavior
  (the default deployment must not start 429ing); a multi-tenant operator
  turns it on. Blast radius: a new layer on the hot path; needs the
  health-endpoint exemption verified (`is_health_endpoint` exists, untested
  against the real router).
. **Retire** — delete the middleware, layer, and config field in one breaking
  config change. Cheapest to maintain, loses tested infrastructure the pgwire
  path shares, and breaks anyone whose config already carries the section
  (parse would fail if the field is removed without `#[serde(default)]`).
. **Keep as-is** — rejected. That is the state this TD filed against.

== Shipped with this TD (the non-decision half)

* TD annotations at the three deception points — the config field, the
  "secure by default" test, and the doc-example — each pointing here, so a
  reader meets the truth where the lie was.

== Resolution (2026-08-25)

Option 1 shipped: the REST router (both build paths) layers
`rate_limit_middleware` from `rest_rate_limit_state_from_env()` —
`PROXIMADB_REST_RATE_LIMIT_RPM`, unset => **no layer at all** (zero hot-path
cost, default deployment unchanged). Mounted beside the v1-sunset layer, i.e.
inside auth/tenant, so accounting aligns with the authenticated principal.
Same `production(rpm, rpm)` shape as the pgwire gate (per-IP rpm/60s,
process-global 10x ceiling). Keyed on the TD-TENANT-4 observed client address.
Four new tests drive the REAL middleware through a router (429 envelope,
`/health` exemption, per-IP isolation, gate truth table); the health exemption
was negative-controlled (`if false &&` sabotage => `left: 429, right: 200`).

Not shipped, deliberately: wiring the `[network.rate_limit]` TOML section — its
parent `NetworkConfig` is itself unread by the boot path, so resurrecting that
plumbing is a separate decomposition question, and an env gate mirrors the
pgwire surface exactly. The section keeps its truth annotation. Also noted:
`RateLimitLayer` implements no tower `Layer` trait at all — a constructible
stub, the fourth artifact of the same false-assurance class; retiring it is a
follow-up cleanup recorded here rather than silently left.

== Non-goals

* The auth failed-attempt budget (live, correct, untouched).
* The pgwire limiter (live, env-gated, untouched).
* Any change to `get_client_ip` / client-address provenance (TD-TENANT-4,
  shipped).
