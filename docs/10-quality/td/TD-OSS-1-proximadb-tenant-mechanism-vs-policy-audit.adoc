== Findings (audited against origin/develop, 2026-07-12)

1. **`tenant_tier_types` — CLEAN (already neutralized).** The `Tier` enum is `Tier1`..`Tier5` (positional/neutral). Its own doc (`tenant_tier_types.rs:236`) records the prior commercial names (`FreeTrial`/`Team`/`Pro`/`Business`/`Enterprise`) were removed; commercial names survive only as serde aliases for back-compat. No remediation needed.
2. **`UnifiedPermission` variants — CLEAN (neutral capability names).** Sampled variants are `TenantAdmin`, `TenantRead`, `TenantWrite`, `DomainCreate`, `CollectionCreate`, `ListCollections`, … A keyword grep for commercial surface terms (`enterprise|business|premium|dedicated|paid|pro|team|starter|free|trial|sku|commercial|sale|license`) across all 40 variants returned **empty** — no commercial tier/SKU leak. These are authZ *capability* names (mechanism), correctly OSS.
3. **`TenantContext` / `UnifiedUserContext` / `RbacTenantContext` — OSS mechanism** (authN identity). Correctly OSS per the boundary spec §2 ("Security mechanism: authN/authZ ports").
4. **The ports (`LimitsResolver`, `set_tier_multiplier_resolver`, `TierPolicy` parser) — OSS mechanism** with default-inert adapters. The commercial *values/policy* are supplied by the commercial Rust crate (ADR-060), not encoded here.

== Verdict

`proximadb-tenant` is **mechanism + neutral-named** — it is correctly OSS and **PR #901 (RBAC identity → this crate) is boundary-correct** (authN/authZ identity is mechanism, not commercial policy). No type needs to move to `anvaiops`/commercial. The commercial **policy** (multipliers, quota caps, RBAC policy, billing compute) is a new commercial Rust crate per ADR-060 Option A — it *depends on* these OSS types; it does not own them.

== Adjacent follow-up (NOT in the tenant crate)

`StoragePoolClass::{Business,Enterprise,EnterpriseDedicated}` — commercial tier names in a **catalog** enum (`crates/control/proximadb-catalog/src/lib.rs:54`) — is the remaining tenant-adjacent leak, already P0-flagged in `OSS_ENTERPRISE_BOUNDARY` §3 (rename neutral `Pooled/Standard/Premium/Dedicated` + serde aliases). Tracked there; out of scope for this audit.
