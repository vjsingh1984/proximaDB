== Why

Agent-driven code-RAG is update-heavy and freshness-critical. The code review found the unflushed
delta is already hard-bounded (about 2 MiB by default), so a Strong brute-force delta merge is the
smallest correct mechanism. A second mutable index would add insert/evict/flush/replay coherence for
a large-delta condition the bound excludes.

== Shipped scope

* `Churn` resolves requests to Strong freshness and merges the bounded unflushed delta.
* Canonical durability stays WAL/`ProximaRecord`; compaction clustering stays off for `Churn`.
* TD-WLP-8a supplies the working-set gauge/soft ceiling.

== Retired proposal — do not implement

The original dedicated mutable AXIS index, its flush-coherence machinery, and a new ORION fusion
branch are superseded. Revisit an index only under a new evidence-backed TD if the bounded delta is
measured to dominate latency. Use the existing TD-045 fusion seam for graph expansion.

== TDD gate

Integration test `tests/storage_wlp_churn_freshness.rs` (storage-integration CI job):

* `test_churn_reembedded_symbol_immediately_visible`: insert a vector → query returns it; update
  (re-embed) the SAME `oid`; query BEFORE any flush returns the NEW embedding's neighbours
  (freshness); restart + WAL replay reconstructs identical state (authority invariant).
* `test_append_collection_unaffected_by_churn_path`: an `AppendBulk` collection in the same process
  still uses the durable path (mixed-read safety).

== Gating

Keyed on `workload_profile:churn`; `AppendBulk` remains unchanged. No new in-memory index or
durability authority is authorized by this resolved TD.
