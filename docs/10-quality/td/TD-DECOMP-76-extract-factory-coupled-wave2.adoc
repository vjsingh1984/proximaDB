== What moved (Phase 4 Step 4 — ~3.8K LOC)
Applying the proven TD-75 pattern (field/ctor `Arc<FilesystemFactory>` → `Arc<dyn
FilesystemPort>`, root coerces at construction):

* `columnar/nova_metadata.rs` (1,167 LOC, 3 tests) → engine-core. `extract_metadata` is a
  placeholder (never reads FS) → tests inject the no-op port.
* `columnar/parquet_metadata.rs` (1,006 LOC) → engine-core. **REAL reads** via
  `get_filesystem` — the port carries the full behavior (no test stub needed; 0 tests).
* `columnar/footer_cache.rs` (803 LOC, 3 tests) → engine-core as `columnar_footer_cache`
  (moka footer cache; tests only exercise construction/validity → no-op port).
* `columnar/utilities.rs` (661 LOC, 2 tests) → engine-core as `columnar_utilities`.
* Config-type cluster from `columnar/mod.rs` (122 LOC: ColumnarConfig + OptimizationThresholds
  + ColumnarFileMetadata + ColumnarColumnStatistics + Defaults + QuantizationConfig re-export)
  → `columnar_config_types.rs` — the shared types utilities/footer_cache were blocked on.

== Layering note
The 3 columnar files landed in ENGINE-CORE, not storage-common: storage-ports already depends
on storage-common, so storage-common cannot depend back on storage-ports (cycle). Engine-core
already sits above both. Root `columnar/mod.rs` keeps all paths via alias re-exports
(`as footer_cache`, `as utilities`, config-types list).

== Test-stub honesty (same caveat as TD-75)
nova/utilities/footer_cache tests inject no-op `FilesystemPort`s — each of those types'
filesystem reads are placeholder/unused-by-those-tests today. parquet_metadata is the ONLY
metadata serializer with a real read path, and it keeps real behavior through the port.
When placeholders gain real reads, swap stubs for real filesystems.
