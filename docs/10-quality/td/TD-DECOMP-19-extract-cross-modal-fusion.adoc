== Why

`src/core/search/cross_modal_fusion.rs` (563 LOC, **10 tests**) is the *modern*, non-deprecated
cross-modal fusion core: the modality-agnostic `Fuser` that calibrates + fuses + ranks `(oid, score)`
lists from every source. It is the cleanest leaf in `core/search/`:

* **zero `crate::` climb-out**, no `super::` (the one `super::` is the `#[cfg(test)]` block);
* **`std`-only** dependency (`HashMap`) — no serde, tracing, anyhow, or `proximadb_*`;
* fully self-contained: all 9 types it touches (`SourceId`, `SourceCandidates`, `Calibration`,
  `Operator`, `PoolCapMode`, `FusionPolicy`, `FusedItem`, `FusionStats`, `Fuser`) are defined in-file.

This contrasts with `hybrid/fusion.rs` (32 tests) which was the original target but is the *deprecated*
path — its `FusionStrategy` enum carries `#[deprecated]` variants pointing *to*
`cross_modal_fusion::Fuser`, so the migration direction is away from it. Extracting the live, modern
core is higher value and aligns with where the code is headed.

== What moved (behavior-neutral)

* Whole `src/core/search/cross_modal_fusion.rs` → `crates/horizontal/proximadb-cross-modal-fusion/src/`.
* Root `src/core/search/mod.rs`: `pub mod cross_modal_fusion;` →
  `pub use proximadb_cross_modal_fusion::cross_modal_fusion;` (8 callers across `src/services`,
  `src/network/{grpc,rest}`, `src/core/search` resolve unchanged via the shim).
* New crate is horizontal-tier with an empty `[dependencies]` (`std`-only).

== Follow-ups

* **Running total once merged: ~640 tests out of root** (630 + 10).
* The deprecated `hybrid/fusion.rs` (32 tests) remains a future extraction or a delete candidate once
  the migration to `cross_modal_fusion::Fuser` completes.
