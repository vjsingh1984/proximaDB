|===
| Field | Value
| Status | Landing

| Component | `crates/storage/proximadb-storage-ports`; `crates/control/proximadb-metrics`; `crates/control/proximadb-catalog`; `crates/modalities/proximadb-orion-engine`; `crates/storage/proximadb-storage-operations`; `src/network/shared_services.rs`; `scripts/check_workspace_boundaries.py`

== Problem
TD-DECOMP-63 closed the boundary checker's control-layer blind spot and grandfathered 4 known
violations. This TD resolves 3 of the 4, leaving only edge 1 (storage-common → catalog) for a
follow-up schema-type-extraction PR.

== Resolutions

=== Edge 3: orion-engine → metrics (modality → control)
**Was:** `proximadb_metrics::td066_metrics::record_recovery_checkpoint_observation()` — a sync free
function bumping Prometheus counters (1 call site, primitives only).
**Now:** Defined `OrionMetricsPort` trait + OnceLock global in `proximadb-storage-ports`. Concrete
impl `OrionMetricsAdapter` in `proximadb-metrics`. Registered at bootstrap in `shared_services.rs`.
Call site in orion-engine `lib.rs` uses `proximadb_storage_ports::orion_metrics()` (no-op when
unregistered). Removed `proximadb-metrics` dep from orion-engine Cargo.toml.

=== Edge 2: storage-operations → catalog (storage → control)
**Was:** `CorpusVersionRegistry::global().bump_collection_all_tenants()` — 2 call sites in
compaction manager (post minor/major compaction).
**Now:** Defined `CorpusVersionPort` trait + OnceLock global in `proximadb-storage-ports`. Concrete
impl on `CorpusVersionRegistry` in `proximadb-catalog`. Registered at bootstrap. Call sites use
`proximadb_storage_ports::corpus_version()`. Removed `proximadb-catalog` dep, added
`proximadb-storage-ports` dep to storage-operations Cargo.toml.

=== Edge 4: recall-bench → catalog (horizontal → control, dev-dep)
**Was:** Dev-dep for test-only `CatalogTableSchema` type construction in `tests/fp16_e2e.rs`.
**Now:** Updated `dependency_names()` in `check_workspace_boundaries.py` to exclude
`[dev-dependencies]` — dev-deps are test-only and don't form runtime coupling edges.

== Checker upgrades
- Removed edges 2, 3, 4 from `KNOWN_CONTROL_UP_EDGES` allowlist.
- Upgraded horizontal→control + modality→control rules from `"warning"` to `"error"` (their
  violations are fully resolved).
- storage→control rule remains `"warning"` with 1 grandfathered edge (storage-common → catalog)
  until PR B (schema-type extraction).

== Remaining (PR B)
Edge 1: `proximadb-storage-common → proximadb-catalog` — type-only re-exports of
`CatalogTableSchema`/`CatalogColumn`. Fix: extract types to a new foundation crate
`proximadb-schema-types`. Both catalog and storage-common depend on it; aliases re-point.
