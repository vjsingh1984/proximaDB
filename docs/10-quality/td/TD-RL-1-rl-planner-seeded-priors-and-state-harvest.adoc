= TD-RL-1: RL planner — bake seeded priors (not raw policies) + a state-harvest protocol for benchmark runs

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Proposed.** Filed from the TD-COMPACT-1 1M ratchet sessions (2026-07-23/24), where the question "can we bake the learned policy into code now?" was answered NO with evidence — and the evidence-collection gaps themselves are the debt.
| Priority | **P2** — the RL planner (`src/query/rl_planner/`, contextual bandit with Thompson sampling; persisted as `rl_policy.json` + `route_cost_cells.json` per data dir) currently cold-starts on every fresh deployment with uniform priors. | Evidence | 1M SIFT ratchet on the #1175-verified build: `rl_policy.json` after 1M inserts + ~400 queries holds arms at **α+β=10 (≈8 pulls each), near-uniform (6/4, 5/5)** — barely off the prior. Earlier same-night runs' state was (a) **destroyed** by the fresh-run `rm -rf` of the bench data dir, and (b) **poisoned**: collected inside the TD-COMPACT-2 phantom-column memory storm (40–52 GB RSS, swap, 500–1280 s compactions), i.e. rewards from a regime the #1175 fix removes; plus result-cache contamination (repeat query sets scored 0.4–0.6 ms cache hits, so route rewards measured caching, not routes). == The debt

1. **No harvest protocol.** Policy/cost state persists into the ephemeral bench data dir and dies with it. First harvest now exists manually at `~/proximadb-rl-harvest/` (with provenance README); the harness should snapshot `rl_policy.json` + `route_cost_cells.json` (plus git SHA, workload descriptor, regime notes) as a standard post-run step.
2. **No seeding mechanism.** There is no supported way to ship measured priors: (a) seed the bandit's Beta posteriors (informative α/β instead of uniform) or (b) pre-populate `route_cost_cells.json` defaults from measured traces. Cold-start exploration re-pays the learning cost on every deployment.
3. **No eval gate.** Per the evals mandate (rule 13), a learned routing surface needs an eval suite (output: recall/latency of chosen routes; trajectory: route choices sane per context) before any seeded prior ships — otherwise a bad seed is worse than a cold start.

== Direction

S1 — **Harvest step in the bench harness**: copy the two state files + provenance into a durable artifacts dir at the end of every benchmark run; never leave them only in the wiped data dir.

S2 — **Prior-seeding seam**: load optional seed priors at planner init (env/config path, default OFF; absent file ⇒ current uniform cold start). Mixed-safe: a seed is advisory, the bandit keeps learning online on top of it.

S3 — **Diverse-workload collection plan**: minimum matrix before any shipped seed — {SIFT-L2, a cosine workload, a filtered workload, ≥2 collection sizes}, all on a clean (post-#1175) memory regime, with cache-hit rewards either excluded or labeled.

S4 — **Eval gate**: a routing eval (fixed query/corpus matrix, asserts seeded-prior routes are ≥ cold-start on recall@k and latency) wired as a ratchet before a seed ships as default.

== Non-goals
Baking a raw learned policy file into the binary/repo. The measured *deterministic* facts (compaction profile, GET counts, latency tiers) belong in config defaults / cost-model constants (the #1164 pattern), not in bandit state.
