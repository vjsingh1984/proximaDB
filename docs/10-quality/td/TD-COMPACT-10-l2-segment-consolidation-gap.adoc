= TD-COMPACT-10: L2+ segment consolidation gap — GET/query 10× too high at 1M scale
:status: Open
:dim: D1
:pillar: PERF

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open.** Design decided (ADR-080). Root-caused + measured 2026-07-29.
| Priority | **P0** — GETs/query = 205 at 1M makes retrieval COGS ($141/M) exceed the rate-card price ($50/M) → negative margin. Blocks competitive pricing.
| Component | `src/storage/common/compaction_utils.rs:264-350` (level scaling); `src/core/config.rs` (`CompactionConfig.level_multiplier`).
| Evidence | 2026-07-29 SIFT1M end-to-end benchmark: 9 segments (3 L0 + 1 L1 + 5 L2), 205 GETs/query cold, recall 0.978, retrieval COGS $141.83/M queries at $0.0065/10K Azure reads.
|===

== The measured problem

At SIFT 1M scale on merged develop (async compaction + D2 fix), a cold query
pays **205 object-store GETs** — 10× the competitive threshold (~20). This makes
the retrieval COGS ($141.83/M queries) exceed the KRU rate-card price ($50/M) by
2.8× → **negative 183% margin**. At 33% margin the price would be $211/mo —
uncompetitive with Turbopuffer ($16) or S3 Vectors ($2.53).

== Root cause

**Segment count is the GET multiplier.** Each segment adds ~7-8 reads per cold
query (header + A0 + probed RaBitQ subset + footer + SQ8 ranges + OIDs). With 9
segments (3 L0 + 1 L1 + 5 L2): 9 × 8 × (1 − 0.22 cache hit) ≈ 56 base + 149
overhead = 205.

The compaction framework HAS a higher-level loop (`compaction_utils.rs:287-350`)
that checks L1+ thresholds. But `level_multiplier = 2.0` makes the L2 threshold
unreachable for a 1M collection:

[cols="3,2,3"]
|===
| Level | File threshold (`l0_file_threshold × level_multiplier^level`) | Actual files at 1M
| L0 | 5 × 2⁰ = 5 | 3 → no trigger (below threshold after compaction)
| L1 | 5 × 2¹ = 10 | 1 → no trigger
| L2 | 5 × 2² = **20** | **5** → **no trigger** ← the gap
|===

The 5 L2 segments (~1GB total, 183–226MB each) accumulate without merging.

The L0 early-return at line 264 also starves the higher-level loop during
sustained ingest — L0 always has ≥5 files, so the loop never runs until ingest
settles.

== Fix

. **`level_multiplier: 1.0`** (was 2.0) — every level compacts at the same file
  threshold (5). The 5 L2 files immediately trigger L2 compaction → merge into 1-2.
. **Post-ingest settle pass** — force the higher-level loop when no new L0 files
  appeared in the last tick (the auto-flush driver already ticks every 30s).
. **Production `flush_floor`** — the benchmark used `flush_floor=4MB` (test config),
  producing tiny 7.1MB L0 segments. Production uses 128MB.
