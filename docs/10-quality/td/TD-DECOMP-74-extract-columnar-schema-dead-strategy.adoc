== What moved (Phase 4 Step 2 — columnar leaves wave 2)
`columnar/schema.rs` (1,211 LOC, 2 tests, 62 pub items — schema creation/validation for the
columnar format, incl. ColumnarFilterableSpec + proto conversions) → storage-common as
`columnar_schema_full.rs`. Deps after rewrite: `proximadb-proto` (new dep; QuantizationConfig
comes from proto_v1), `proximadb-compression` (full crate alongside the existing -types),
`columnar_constants` (in-crate). Root shim: `pub use ...columnar_schema_full as schema;` —
all consumers (common.rs, streaming_writer, nova×2, viper) unchanged.

== Dead code removed
`columnar/strategy.rs` (709 LOC) — SerializationStrategyOptimizer etc. — had NO module
declaration anywhere (not in columnar/mod.rs, no `#[path]` include, no external import; the
`VectorizationStrategy` type consumers use is a DIFFERENT enum defined in serialization.rs).
Undeclared files aren't compiled, so this is a pure disk/LOC delete, zero behavior change.

== Wave-2 survey results (why only one move)
The other candidates' refs resolve to root-locked seams, not extracted crates:
- `common.rs`/`utilities.rs`/`footer_cache.rs`/`hybrid_writer.rs`/`nova_metadata.rs`/
  `parquet_metadata.rs` — all hold `Arc<FilesystemFactory>` params (root-coupled; the
  port-trait lift is the queued enabler).
- `serialization.rs` — uses the quantization ENGINE (modality tier) + compute_bridge glue.
- `toml_config.rs` — imports the config-builder cluster spread across sibling columnar files.
The filesystem port remains the single highest-leverage next extraction.
