== Settled constraints inherited from ADR-062

* Keep the coalesced RaBitQ region at the fixed header offset. It is the first,
  unconditional, self-sufficient query step; moving it behind the footer adds a
  serialized object-store GET.
* Clustering reduces GETs through survivor locality but does not compress SQ8 or
  RaBitQ codes by itself. Bytes move through a reversible statistical transform
  fitted to the clustered distribution, followed optionally by a lossless byte
  compressor. Decode must recover the input codes or f32 bit patterns exactly.
* Object-store-first remains the durable cost spine (`per_get` remains greater
  than `per_mib_read`). This phase must preserve the PR1 GET win.
* The survivor-fetch block is sized by `IopsBudget`; the cached RaBitQ region is
  sized by `dimension * file_rows`. They are independent controls.
* Storage-format additions are mixed-read-safe and default OFF. The reader never
  assumes that a new encoding is present.

== Audit: one codec engine, two physical layouts

ProximaBlocks and PAX are not the same block format. Reuse occurs below their
layout boundary.

[cols="1,2,2,2", options="header"]
|===
| Area | Already implemented | Reuse decision | Not reused as-is

| Shared codec (`proximadb-codec`)
| Stable `ProximaScheme` markers; SQ8 fitting/encode/decode; RaBitQ;
  bit-packing; frame-of-reference; PFor-delta; delta/RLE/dictionary and
  vector-base-XOR primitives
| Add a layout-neutral, lossless clustered-matrix transform here by composing
  frame-of-reference and bit-packing. Extend the existing bit-exact
  `vector_base_xor` pilot for f32. Expose deterministic parameter-bearing APIs
  plus realized-size profiles; do not depend on PAX or ProximaBlocks types.
| SQ8/RaBitQ remain quantizers/search projections. The new layer wraps their
  bytes losslessly; it is not another quantizer and must not receive a lossy
  `ProximaScheme` tag. Do not gate canonical writes with the current
  parameter-blind `ProximaScheme::is_lossless()`: conditional bit-width schemes
  require a type-aware fidelity check (`is_lossy(TypeId)` today, then one
  canonical checked API). Exclude Gorilla until its fidelity documentation,
  marker policy, and adversarial bit-round-trip behavior agree.

| ProximaBlocks (row/legacy layout)
| Row/block compression configuration; block and per-dimension compression;
  byte-compression algorithms and markers; metadata dictionary/delta/RLE prior
  art
| Reuse its Parquet-like composition policy: transform values first, then apply
  LZ4/Zstd only when the complete encoded chunk is smaller. Move reusable
  transposed/grouped vector logic into `proximadb-codec`; both layouts call the
  shared API while retaining independent envelopes and markers.
| Do not import ProximaBlocks wire markers or its whole-block compression into
  PAX. Whole-block decode would destroy PAX ranged-read granularity.

| PAX block format
| `ColumnMeta { column_id, role, data_type_id, encoding_id, min/max,
  distinct_hint, bloom offset/len }`; stable codec marker per stripe;
  `VectorParamBlock` for block-local vector parameters; optional footer-resident
  Bloom bytes; fixed-stride vector stripes
| Keep the existing quantization kind unchanged and add a lossless compression
  descriptor plus independently decodable micro-chunk directory. Lift existing
  `ColumnMeta` into the segment footer index instead of recomputing statistics.
| Do not store decode parameters only in the segment tail: a fetched block must
  remain independently decodable. Do not activate the currently inert global
  `BlockCompression` byte as a whole-block envelope.

| Foundation Bloom crate
| Sized Bloom strategies, serialization, approximately 10 bits/key defaults,
  and membership APIs
| Reuse its sizing/hash concepts after making the chosen durable Bloom payload
  deterministic and explicitly versioned.
| Current factory creation always selects `ByteAligned` regardless of requested
  strategy, and `BitPacked` chooses a random seed. Do not silently adopt either
  behavior as the PAX durable contract.

| Current PAX string Bloom
| Deterministic small footer Bloom and reader membership check
| Reuse the block-local `ColumnMeta` pointer seam and conservative no-false-
  negative behavior.
| Its fixed 32-byte payload saturates at useful OID block cardinalities; it is
  not the scalable OID Bloom specified by ADR-062 D5.
|===

Conclusion: the primitives already exist, but their composition is split across
layouts. The implementation extracts one lossless statistical codec into
`proximadb-codec`; PAX is the first measured consumer and ProximaBlocks can adopt
the same library API without sharing PAX bytes.

== Footer model: schema, encoding, statistics, and parameters have distinct roles

The segment remains four-layered:

[cols="1,3", options="header"]
|===
| Layer | Authority and contents

| Header prefix
| Offsets required to scan RaBitQ with zero metadata dependency. No schema,
  encoding parameters, or Bloom payloads.

| Segment footer-index
| Immutable physical snapshot for this file: schema snapshot, block extents,
  stripe encoding declarations, typed statistics descriptors, and auxiliary
  region references. It lets a reader plan reads without decoding every block.

| PAX block footer/side regions
| `ColumnMeta` and codec parameters required to decode that block, including
  micro-chunk boundaries, exact references/bases, bit widths, and lengths. A fetched block remains
  independently decodable.

| Catalog
| Logical schema and write authority. Defaults, comments, indexes, catalog
  object IDs, and mutable properties stay here; they are not copied into every
  segment.
|===

This follows Parquet's useful separation: file metadata plans physical access;
column/page-local metadata decodes bytes; optional indexes/Blooms may be ignored.
It does not copy Parquet Thrift structures into PAX.

=== Clean footer v2 with a v1 read fallback

PR1 footer v1 is an input compatibility case, not a byte-layout constraint on
this unreleased follow-on writer. Footer v2 removes the v1 summary fields that
the typed sections supersede:

```
[footer_version:u8 = 2]
[row_count:u64 | rabitq_off:u64 | rabitq_len:u64]
[embed_dim:u32 | embed_count:u32]
[block_count:u32 | required block entries]
[section_count:u16]
[repeated { section_tag:u8, section_version:u8, section_len:u32, bytes[] }]
```

Rules:

* No segment-magic or header-layout bump. Footer version changes because its
  byte layout changes; new value/transform/compression tags are not format
  magics.
* A new reader dispatches footer v1 to the PR1 parser and footer v2 to the typed
  parser. New-reader -> old-file readability is required.
* Old PR1 binaries are not required to read footer v2. Footer-v2 writes remain
  default OFF until the new reader is deployed.
* Footer v2 validates all lengths with checked arithmetic and skips unknown
  optional section tags/versions.
* A malformed recognized v2 section is an error, not a v1 fallback.
* Section order is deterministic on write; readers do not depend on order.

Initial section tags are `SchemaSnapshot`, `StripeEncodingMap`,
`BlockColumnStats`, and `AuxRegionDirectory`. Tags are stable; each section owns
its own version.

=== SchemaSnapshot section

The snapshot is the minimum physical schema needed to interpret the segment:

```
schema_fingerprint:u64
schema_version:u32
fields[] {
  field_id:i32, physical_column_id:i32, ordinal:u32,
  name:utf8, physical_type:u8, logical_type:versioned-bytes,
  nullable:bool, role:u8
}
```

`CatalogColumn.id` is the stable Parquet/PAX physical field identity and is the
reconciliation key across rename/reorder. `object_id` is a catalog surrogate and
must not be serialized as the PAX field ID. The footer excludes defaults,
comments, indexes, and arbitrary properties. Unknown logical-type annotations
do not change the physical decoder; unknown physical types fail closed.

RaBitQ, SQ8 rerank, and exact-f32 are physical tiers of one logical vector
field. Lossless transforms/compressors wrap one of those representations; they
are descriptor fields, not additional logical schema fields or precision tiers.
Full multi-version schema reconciliation remains TD-TBL-4/ADR-047.

=== StripeEncodingMap section

Replace the singular PR1 `embed_quant_tag` as the new reader's control plane;
retain that byte in the v1 core as the legacy/default summary.

```
entries[] {
  descriptor_id:u16,
  logical_field_id:i32,
  physical_column_id:i32,
  tier_role:u8,              // index | rerank | exact | metadata
  value_codec_tag:u8,        // raw-f32 | SQ8 | RaBitQ: semantic representation
  value_codec_version:u8,
  transform_tag:u8,          // none | clustered-FOR | vector-base-XOR
  transform_version:u8,
  compression_tag:u8,        // none | LZ4 | Zstd | Snappy
  compression_version:u8,
  compression_flags:u8,      // bit 0: lossless (required for durable data)
  parameter_scope:u8,        // none | segment | block | cluster-run | micro-chunk
  vector_transform:u8,       // none | l2-normalized | centered-rotated
  auxiliary_flags:u16,       // exact-norm-sq | correction-scale
  source_role:u8,            // canonical | index-projection | rerank-projection
  source_fidelity:u8,        // exact-bitwise | lossy
  rebuild_source_id:u16,     // 0 canonical; descriptor ID, or 0xffff external authority
  projection_generation:u16
}

block_tier_assignments[] {
  block_ordinal:u32,
  physical_column_id:i32,
  tier_role:u8,
  descriptor_id:u16
}
```

Multiple descriptors for the same logical field/tier are permitted because
write-time fallback can produce mixed raw/compressed SQ8 blocks in one segment. The
block assignment is the footer planning authority; the block-local `ColumnMeta`
and `VectorParamBlock` repeat the selected codec facts required for independent
decode. The reader rejects disagreement between them.

The three layers are intentionally separate, following Parquet's value
encoding-then-compression model while making vector precision explicit.
`value_codec_tag` declares the precision-bearing representation and may be lossy
only for an explicitly declared index/rerank projection with a canonical rebuild
source. `transform_tag` and `compression_tag` are always reversible: their
inverse must reproduce the exact input code bytes and parameter bytes before the
existing value decoder runs. A canonical descriptor that is not
`exact-bitwise`, or a durable transform/compressor marked non-lossless, is
malformed and fails closed.

Compatibility is asymmetric by design:

* Footer v1: use the PR1/block-local `VectorParamBlock` path; legacy SQ8 remains
  readable.
* Footer v2 with no encoding map: reject the malformed self-description.
* Known value/transform/compression tags: dispatch all declared layers and
  validate their versions/scopes.
* Explicit unknown value codec tag/version: never reinterpret its bytes as SQ8.
  Either use an independently declared exact tier when the caller permits that
  fallback, or return an unsupported-encoding error.
* Unknown compression tag on a required stripe also fails closed.

Optional metadata is skippable; an unknown data encoding is not. This is the
same compatibility distinction that keeps Parquet Bloom additions benign while
new encodings require reader support.

=== Vector metric and source-fidelity contract

Each logical vector field records the immutable physical contract under which
the segment was written:

```
vector_contracts[] {
  logical_field_id:i32,
  built_metric:u8,
  metric_epoch:u64,
  normalization_contract:u8, // none | enforced-unit-l2
  canonical_precision:u8     // f32-exact for current dense-vector contract
}
```

Runtime metric support comes from the registered value-codec implementation
keyed by `value_codec_tag` and version; the file does not assert an unaudited
supported-metric bitmap. Unit-normalized vectors may share one dot estimator
for L2/cosine/MIPS. General vectors require the candidate norm for direct
L2/cosine estimation, or full coordinate reconstruction. L1-family metrics
cannot use a dot-only TurboQuant/RaBitQ estimator as their candidate stage.

Every canonical PAX field is bitwise reconstructible. For the current dense
vector contract, every canonical live block decodes to the original f32 bit
patterns. A PAX object may omit canonical f32 only when the object is explicitly
cataloged as a rebuildable projection and `rebuild_source_id` names durable
canonical authority; such an object cannot serve record reconstruction,
compaction materialization, exact vector return, or exact queries by itself.
The reserved value `0xffff` means that authority is external to this immutable
segment (for example WAL/catalog lineage); it is never a physical stripe ID and
does not grant the file exact-read capability.

SQ8, RaBitQ, FP16, and future quantizers are projections. Quantization is the
sole permitted lossy boundary. Lossless transforms may reorder and recompress
their existing codes, but compaction must regenerate a different quantizer only
from canonical f32. Lossy-to-lossy transcoding is forbidden because it compounds
error. The weakest live block determines the collection guarantee; "any input
has f32" is never sufficient to mark a compacted output exact.

=== BlockColumnStats and optional Bloom payloads

The segment footer indexes existing block-local statistics by stable column ID:

```
stats[] {
  block_ordinal:u32,
  column_id:i32,
  stats_kind:u8,
  stats_version:u8,
  payload_ref:{ region_id:u16, offset:u32, len:u32 }
}
```

`ColumnMeta` remains the producer of min/max, null count, distinct hint, and
Bloom presence. The segment writer lifts these values; it does not run a second
statistics implementation.

Large Bloom/statistics bytes live in a contiguous auxiliary metadata region and
are addressed through `AuxRegionDirectory`, analogous to Parquet column-chunk
Bloom `offset + length`. Small fixed stats may be inline in a later section
version. The core footer stays bounded and cacheable.

The OID Bloom payload contract, when activated by TD-RDSTRAT-6 PR3, is
deterministic and self-describing:

```
bloom_version:u8 | hash_algorithm:u8 | hash_seed:u64 |
num_hashes:u8 | bit_count:u32 | inserted_count:u32 | bits[]
```

Target sizing starts near 10 bits/key (approximately 1% false-positive rate) and
is measured by block cardinality. A missing/unknown Bloom or a failed optional
Bloom decode means "may contain"; no point lookup may be skipped unless a known,
valid filter proves absence. Bloom activation is not required for the BYTES
headline, but the typed slot and auxiliary-region framing land now so PR3 does
not redesign the footer.

== Lossless clustered stripe encoding

=== Precision, transform, and compression are separate layers

The bytes lever does not add a new precision tier:

```
canonical f32 --lossless transform/compression--> identical f32 bits
       |
       +--quantize once--> SQ8 projection
                              |
                              +--lossless transform/compression--> identical SQ8 codes
```

RaBitQ and SQ8 remain explicitly lossy ANN projections. The new transform and
byte compressor invert exactly before the existing f32/SQ8 decoder runs.
Consequently normal rerank produces identical codes, distances, ranking, and
recall to flat SQ8; canonical reads recover identical IEEE-754 bits. There is no
residual-SQ4/SQ6 replacement and no second quantization error.

=== Producer and granularity

Refactor `cluster_order_pca_ivf` to expose the fitted plan instead of discarding
assignments after returning a permutation:

```
ClusterPlan { order, runs[] { cluster_id, ordered_start, row_count } }
```

The existing permutation-only function remains as a compatibility wrapper.
Writer and codec consume the same plan, so row order and micro-chunk boundaries
cannot drift.

Granularity is **one independently decodable micro-chunk per contiguous IVF
cluster-run fragment intersecting a PAX block**. A PAX block remains the
survivor-fetch/IopsBudget unit; a cluster supplies correlation; a micro-chunk
bounds decode amplification and carries its own offset/parameter directory. A
block may contain several run fragments, and a cluster may cross blocks. No
decoder depends on the segment tail after the block has been fetched.

=== Initial shared-codec contracts

The first query-path candidate is `ClusteredForBitpackU8/v1`, a reversible
transform over the already-produced SQ8 code matrix:

* accept fixed-dimension u8 rows plus explicit cluster-run boundaries;
* split each local run fragment into bounded micro-chunks;
* transpose each micro-chunk logically so values from the same dimension are
  adjacent;
* store the per-dimension minimum code and bit width, then bit-pack exact
  unsigned deltas `code - min`;
* optionally apply a registered lossless byte compressor to each complete
  transformed micro-chunk;
* invert to the byte-identical SQ8 code matrix before dequantization.

The canonical-f32 candidate is `ClusteredExactBaseXor/v1`. It extends the
existing bit-exact `vector_base_xor` pilot: use an exact per-run reference vector,
XOR IEEE-754 words per dimension, apply a reversible byte/bit-plane shuffle or
run coding, and optionally apply the same lossless byte compressor. Floating
point `x - centroid` is forbidden because subtraction/addition cannot guarantee
bitwise reconstruction.

Both APIs live in `proximadb-codec`, accept layout-neutral slices/boundaries, and
return encoded bytes, a micro-chunk directory, and a realized-size profile.
They validate dimensions, complete run coverage, checked lengths, and every
parameter with `Result`. PAX and ProximaBlocks retain their own envelopes but
call these shared APIs. Existing FOR/bitpack/base-XOR primitives are composed,
not forked.

The shared registry must expose one type-aware fidelity decision for durable
writes. The current zero-argument `ProximaScheme::is_lossless()` is insufficient
because it classifies conditional `BitPacked`, `FrameOfReference`, `PForDelta`,
and `Zigzag` variants without considering their bit width or value type. The
code PR either replaces that helper or prevents this path from calling it; tests
cover all conditional widths and types before any scheme may encode canonical
data.

The writer chooses transformed/compressed bytes only when the complete payload
(references, bases, widths, directory, checksums, and compressor framing) beats
the raw representation by a configured minimum. Otherwise that micro-chunk is
declared raw. Mixed raw/compressed chunks are permitted and explicit.

=== Equal-protocol codec bake-off — measured, no winner

The rejected lossy implementation does not earn a permanent format tag merely
by existing. Three isolated worktrees ran the same release-profile SIFT1M
N=100k, 100-query, single-file IVF-ON protocol:

* clustered SQ4/SQ6, including the explicitly declared exact-norm experiment;
* clustered TurboQuant-style 4-bit;
* clustered multi-bit RaBitQ 4-bit.

The result table records recall@10, range GETs/query, bytes read/query, query
latency percentiles, persisted bytes/row including parameters, and encode/flush
time. Total route cost is also reported under ADR-062's durable weights
`20 * GETs + 5 * MiB_read`. These prototypes are preserved as evidence only.
Under the corrected authority boundary, none is eligible for the durable BYTES
implementation regardless of recall because each introduces another lossy
transform after the selected projection.

Measured result: residual SQ6 + exact squared norm reached recall `0.981` but
only reduced bytes/query from `32,020,233` to `29,775,220` and increased mean
query latency from `11,756 us` to `39,688 us`. TurboQuant4 reached recall
`0.921`; multi-bit RaBitQ4 reached `0.917`. Both 4-bit arms read about
`25.12 MB/query`. All three are rejected.

At genuine N=1M, flat measured recall `0.968`, `61` GETs/query, and
`138,851,704` bytes/query; SQ6 measured `0.950`, `61`, and `128,722,140`.
The fixed pool is 1,000 candidates at both scales (1% of N=100k versus 0.1% of
N=1M), so the scale gate must be restored before another rerank codec is judged.

=== Prerequisites exposed by N=1M

* **Adaptive survivor M.** Replace the segment-size-independent 1,000-candidate
  contract with a measured recall/confidence rule and charge its survivor blocks
  to the GET/byte budget.
* **Wire the existing budget.** `IopsBudget` declares local 1 MiB and cloud
  4 MiB targets, but PAX still uses a 3 MiB threshold with a fixed 1 KiB/row
  proxy, yielding about 3,072 rows/block regardless of encoding or dimension.
* **Scale the producer.** N=1M IVF flushes took 44-48 minutes at d128; the sampled
  hot path was `kmeans_clustering_seeded`. Higher dimension requires scalable,
  deterministic fitting first.
* **Dimension sweep.** Measure real d128/384/768/1536/3072 L2, cosine, and dot
  workloads. Better estimator concentration is possible, but the mandatory
  RaBitQ region, rerank bytes, and fitting work all grow with dimension.

The lossless transforms are metric-independent because they reconstruct the
same f32 bits or SQ8 codes before scoring. L2/Euclidean, cosine, dot, L1 and
other generic kernels therefore remain available. Estimator-specific
RaBitQ/SQ8 projection limits still apply to the projection itself, not to this
storage compression layer.

=== Compaction and metric-change rules

. Read every block's footer assignment and source fidelity; do not infer a
  file-wide codec or exactness flag from block zero or from any one input.
. Canonical compaction materializes only exact canonical fields. Lossy
  projections never become record or compaction sources.
. Re-clustering may reorder canonical values and losslessly regenerate
  projections when canonical f32 exists for every row.
. If only an existing quantized projection is available, compaction may
  losslessly preserve/recompress its codes but may not fit a different
  quantizer. Otherwise pass through or defer; lossy-to-lossy transcode is
  forbidden.
. A collection metric change increments `metric_epoch`. Compatible generic
  reconstruction may continue approximately; estimator-specific tiers are
  rebuilt or bypassed. Until this reconciliation exists, metric changes must be
  rejected or executed as an explicit rebuild transaction.
. Exact queries and exact vector return require an exact authority for every
  relevant live block.

PR #1039 fixed the immediate exact-tier propagation seam: requested coalesced
f32 is emitted, compaction materializes it first, and output exactness requires
all input rows. Footer v2 generalizes that fact from `has_f32_tier` to an
authority-bearing canonical descriptor so a losslessly compressed f32 stripe is
equally exact.

Also normalize the score boundary before mixed files are compared: the
coalesced reranker currently produces squared L2 while the canonical distance
kernel returns Euclidean distance, and its internal negated-dot ordering value
must be converted back to the public positive-dot similarity exactly once.
Homogeneous ranking can hide both defects; mixed codecs/files cannot.

=== Opt-in and fallback

Writer gate: `PROXIMADB_PAX_LOSSLESS_CLUSTERED=1`, default OFF. It is effective
only when a supported stripe and cluster plan are present. Otherwise the writer
emits the existing raw f32/SQ8 representation and declares no transform or byte
compression in the encoding map.

Scalar all-null elision and post-codec LZ4 use the independent
`PROXIMADB_PAX_LOSSLESS_SCALAR=1` gate, also default OFF. This is the accepted
#1064 bytes arm. `ColumnMeta` declares LZ4 in-place; realized non-wins remain
flat, and all-null pages are declared by `null_count == row_count` with an empty
payload. No additional lossy boundary or nested format version is introduced.

Fallback is selected independently per micro-chunk for missing plans,
inconsistent dimensions, undersized runs, unsupported compressor, or
insufficient realized savings. Once a block explicitly declares a transform or
compressor, decode errors fail closed; the reader does not guess raw/SQ8 bytes.

Both encodings remain default OFF. The scalar arm has accepted bitwise and
end-to-end evidence; the clustered vector arm remains off pending evidence on a
layout where it is still load-bearing. Neither changes the coalesced-RaBitQ or
ADR-065 Region-B defaults.

== TDD implementation sequence

The code PR proceeds in this order; each production slice starts from a failing
test.

. Footer tests: legacy footer-v1 parse; footer-v2 full section round-trip;
  unknown optional v2 section skip; malformed/truncated v2 fail; explicit
  unknown required codec fail.
. Shared codec tests: deterministic encode; adversarial bitwise f32 and
  byte-identical u8 round-trip; dimension/run/chunk validation; bit-width edges;
  type-aware fidelity classification; realized total-size accounting; raw
  fallback; corrupt/unknown tag fail closed.
. PAX block tests: transform/compression parameter round-trip; independent
  micro-chunk decode; mixed raw/compressed chunks; ranged reader parity;
  canonical authority reconstruction; unknown required transform fail closed.
. Segment tests: schema/encoding/stats sections are emitted from actual block
  metadata; footer v1 reads through the PR1 path; gate OFF writes footer v1/SQ8;
  gate ON with IVF writes lossless chunks; legacy and new segments coexist in
  one query.
. SIFT eval: same N=100k, 100-query, single-file, IVF-ON protocol; compare OFF
  and ON in one run; assert recall floor `>= 0.98`, GET non-regression, and a
  ratcheted bytes/query ceiling materially below `31.7 MB`.

Bit-exact round-trip is a unit-test invariant. SIFT remains an end-to-end eval to
prove route parity and measure bytes/GETs/latency; recall must be identical to
the same SQ8/RaBitQ projection within deterministic harness tolerance, not merely
above a looser codec-error threshold.

== Scope boundaries and follow-ons

Included in the implementation PR:

* shared lossless clustered-FOR and exact base-XOR APIs plus stable transform
  tags, using the shared byte-compression registry;
* cluster-plan reuse;
* PAX writer/reader and block-local micro-chunk directories;
* clean footer-v2 sections for schema, encodings, stats descriptors, and aux
  region references, plus the footer-v1 read path;
* default-OFF mixed-read gate, tests, SIFT evidence, and ledger claim.

Not included:

* actual OID Bloom population/query routing (TD-RDSTRAT-6 PR3);
* metadata delta/RLE activation beyond registering the transform field;
* ProximaBlocks wire-format conversion (the shared APIs land now; adopting them
  in its independent envelope is a measured follow-on);
* GET-budget compaction and per-file RaBitQ region-cache feedback (PR2);
* full schema-evolution reconciliation (TD-TBL-4).

The per-file RaBitQ cache cap may later feed the compaction controller as the
upper bound on file size, while the query GET budget supplies the lower bound on
file size. This file-count/region-size band is real but orthogonal to the
survivor-block codec and is not tuned in the bytes PR.
