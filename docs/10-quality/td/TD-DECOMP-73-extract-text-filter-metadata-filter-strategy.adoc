== What moved (Phase 4 Step 1 — CI-shape continuation of TD-DECOMP-70's cluster)

* `columnar/text_filter.rs` (801 LOC, 13 tests) — n-gram bloom CONTAINS evaluator
  (TextColumnFilterEvaluator, TextFilterBuilder). Deps: regex + thiserror +
  `proximadb-bloom` (foundation; new storage-common dep).
* `columnar/mod.rs` filter-type cluster (161 LOC) → `text_search/metadata_filter_types.rs`:
  `ColumnarMetadataFilter` (+ `MetadataFilter` alias), `FilterLogic`, `FilterCondition`
  (+ `column()` helper), and the `FilterExpression` conversion impls
  (`proximadb-filter-expression`, already a storage-common dep).
* `columnar/metadata_filter_strategy.rs` (931 LOC, 12 tests) — MetadataFilterAnalyzer /
  MetadataFilterStrategy / FilterPerformanceMetrics. Deps: arrow-array, arrow-select
  (inline spec — root-package-only in the manifest sections), anyhow, records.

storage-common: 550 → **562 tests**. The filesystem survey that motivated this step found
the FilesystemFactory is deeply root-coupled (encryption wrapper, IoTrace recorder, 4 cloud
backends) — the port-trait lift is queued as the NEXT structural enabler; meanwhile these
zero-filesystem-coupling columnar files are the cheapest remaining wins.

nova) keeps resolving.
