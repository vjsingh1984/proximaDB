== Problem

`CatalogCache::maybe_evict` finds the LRU victim with
`cache.iter().min_by_key(|(_, v)| v.last_accessed)` — a full scan of the map on
EVERY insert once `len() >= max_entries` (default 10,000). A busy multi-tenant
server at capacity pays a 10k-entry scan per catalog-cache fill, under the
category's write lock (`RwLock<HashMap<…>>`), so the scan also extends lock
hold time for concurrent readers.

== Candidate fixes (pick one, measure first per co-design mandate)

1. **Proper O(1) LRU** — the `lru` crate (or an intrusive list + map). Gets
   are already write-shaped (they update `last_accessed`/`access_count`), so
   the lock pattern does not regress.
2. **Sampled eviction** (Redis-style): scan K random entries (K≈8), evict the
   oldest of the sample. O(K), one-line change, near-LRU quality.
3. **Shard the maps** (`DashMap` or N-way `RwLock<HashMap>`) — also fixes the
   whole-map write-lock contention noted in the review, independent of
   eviction cost.

Trace before tuning: emit `evictions` + insert latency at capacity in a bench
before choosing; if production caches never reach 10k entries, close as
won't-fix with the measurement attached.

== Follow-up: shared eviction ring defeated the capacity bound (fixed 2026-08-29)

An adversarial re-review of the #1735 implementation (option 2, sampled
eviction) found the single `eviction_ring` was shared across all four map
families (namespaces/tables/indexes/statistics). `maybe_evict::<T>` filters
ring entries by membership in *the one map being checked*, so a call for one
family silently dropped every other family's keys from the ring as "no
longer resident" — even though they were still resident in their own map.
Under interleaved multi-family traffic the ring got dominated by whichever
family wrote most recently; a starved family's `maybe_evict` then found zero
candidates while its `put_*` still inserted unconditionally, so that map grew
past `max_entries` until the next `evict_expired` TTL sweep caught it —
defeating the capacity bound TD-CAT-5 exists to guarantee. Fixed by giving
each family its own ring (`namespace_ring`/`table_ring`/`index_ring`/
`stats_ring`); regression test
`eviction_rings_are_independent_per_family_under_interleaved_traffic` in
`cache.rs` reproduces the cross-family starvation and fails pre-fix.
