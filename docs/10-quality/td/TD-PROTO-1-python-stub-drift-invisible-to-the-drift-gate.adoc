= TD-PROTO-1: The proto drift gate compares services, not schemas — so the Python stubs have silently fallen behind the wire

[cols="1,3",options="header"]
|===
| Field | Value
| Status | **Resolved — 2026-08-20.** Gate widened to compare serialized descriptors and wired into `make proto-check`; both stub trees regenerated; the two-trees-agree assertion added. Original filing follows. — **Open — filed 2026-08-20** from TD-CHUNK-5's wire retirement (#1679), where regenerating one stub picked up four unrelated fields nobody had noticed were missing. Measured across every proto in the tree; numbers below are from `origin/develop` at `b6b79b6f1`.
| Dim | D2 (network) — the wire contract itself; secondary D5 (governance: a merge-blocking gate that does not block what it claims to)
| Pillar | REL — secondary OE
| Blocks | Nothing today. It becomes a correctness problem the moment a caller needs one of the missing fields, and a *silent* one because the failure is an `AttributeError` in the SDK rather than a wire error.

== The finding

`clients/python/tests/unit/test_grpc_proto_drift.py` is the merge-blocking gate for proto↔stub drift.
Its own docstring is explicit about what it computes:

* `missing-stub:<proto>` — no matching `*_pb2_grpc.py` exists
* `missing-servicer:<proto>::<Service>` — servicer class not generated
* `missing-rpc:<proto>::<Service>.<Rpc>` — rpc not present on its servicer

Every one of those is about **services and rpcs**. A `.proto` change that adds a message, a field, or an
enum — and touches no service — moves nothing in that drift set, so the gate is green by construction.
`collection_types.proto`, where this was first noticed, declares **no service at all**, which is why a
field could sit unreflected in the checked-in stub indefinitely.

== Measured, and split by severity

Regenerated every `proto/proximadb/v{1,2}/*.proto` into both checked-in stub trees and compared the
**serialized `FileDescriptorProto`**, not the file text — protoc's formatting differs from the
committed copies and would otherwise dominate the diff. That distinction matters: of 26 files with a
textual diff, **12 have byte-identical descriptors** and are pure formatting churn.

[cols="1,1,3",options="header"]
|===
| Class | Files | What is actually missing
| **Shape drift** — messages/fields/enums the wire declares and the stub does not | 5
| `v2/record_pb2` (**15** names: the whole `PredicateShortfall` message, `VectorElementType` and its
  five members, `TypedSearchResponse.predicate_shortfall`, `TypedColumn.vector_dimension` /
  `.vector_element_type`); `v1/document_pb2` (**7**: the `LookupStage` message and its fields,
  `AggregationStage.lookup`, `DocumentCollectionConfig.use_jsonb`); `v2/fusion_pb2` (**3**:
  `FusionSearchRequest.text_query` / `.document_collection` / `.document_weight`)
| **Option drift** — `deprecated: true` markers absent from the stub | 9
| `v1/entity`, `v1/graph`, `v1/hybrid`, `v1/relations`, `v1/sql` (across both copies). Cosmetic for
  behaviour, but it means a deprecation the wire announces is invisible to SDK tooling.
| **Formatting only** — descriptors identical | 12 | Not drift. Listed so a future regen is not mistaken for one.

**This is user-visible, not bookkeeping.** Against the committed stubs on `develop`:

[source]
----
VectorElementType present:                    False
PredicateShortfall present:                   False
TypedSearchResponse.predicate_shortfall:      False
FusionSearchRequest.text_query:               False
----

while `proto/proximadb/v2/record.proto` and `fusion.proto` declare all four. A server can emit
predicate-shortfall telemetry — the *why did top-k under-return* signal — and the Python SDK has no
type to receive it. A caller wanting hybrid text fusion cannot set `text_query`. The failure mode is an
`AttributeError` inside the SDK, which reads as an SDK bug rather than as a stale artifact.

== A second finding: the two checked-in stub trees disagree

`clients/python/src/proximadb_sdk/v{1,2}/` and `clients/python/src/proximadb/v{1,2}/` are **both live** —
`unified_client_async.py`, `fusion_v2.py` and `document_v2.py` all import from the `proximadb.v2`
copy — and they are regenerated independently. 24 of 26 descriptors match; **`v1/document_pb2` and
`v1/hybrid_pb2` do not**. Two copies of one contract, drifting at different rates, with nothing
comparing them to each other.

== Co-design note

This is a **D2 (network)** defect, and the cost term is not bytes — it is the contract. The wire is one
of the four stable seams the co-design mandate says we expose (pgwire, Arrow Flight, Iceberg manifests,
REST v2, and the typed gRPC surface alongside them). "Vertical inside, standard outside" only holds if
the outside is *actually* what the schema says. A generated artifact that has silently diverged from its
source is the same failure class as a settable field that does nothing (TD-CHUNK-5) and an advertised
language whose parser returns nothing (TD-CG2): **the declared surface and the real one disagree, and
nothing in CI can tell.**

== What to do

Ordered so the gate lands before the cleanup, because otherwise the cleanup silently re-rots.

. **Widen the gate to compare schemas, not services.** For each `.proto`, generate a stub to a temp dir
  and compare the **serialized descriptor** against the committed one. Byte equality is the whole test —
  it needs no proto parsing, catches messages/fields/enums/options/rpcs together, and is immune to
  protoc's formatting. Fail on inequality with the regeneration command in the message.
. **Regenerate both stub trees and commit**, in one PR, with the shape drift called out per file so the
  three genuinely-new capabilities (`predicate_shortfall`, `LookupStage`, fusion `text_query`) are
  reviewed rather than absorbed.
. **Assert the two trees agree**, or collapse them. Two independently-generated copies of one contract
  is the duplication ADR-029 removed for code chunking, in a different medium. Collapsing is the real
  fix; asserting equality is the cheap one that stops the bleeding.
. **Then delete this TD's exception**, not before — a regenerate-only PR leaves the gate exactly as blind
  as it is today.

== Acceptance

* The drift gate fails when a field is added to any `.proto` without regenerating the stubs — proven by
  a deliberate one-field addition that must go red, then green after regeneration. A gate that has never
  been observed failing is not known to work.
* `git diff --exit-code` is empty after regenerating every proto into both trees.
* The two stub trees have identical descriptors for every shared file, or only one tree remains.

== Why this was not fixed in #1679

That PR removed a wire field and regenerated the one stub it touched. Fixing the gate is a change to a
merge-blocking check plus a regeneration of 26 files across two trees — a different blast radius, its
own review, and three capability additions that deserve to be looked at rather than ridden in on a
chunking PR. Recorded there and filed here rather than done silently.

== Executed 2026-08-20

All four steps, in the order this TD specified, because a regenerate-first PR would have left the gate
as blind as it was and the drift would simply have returned.

=== The gate, and the proof it works

`clients/python/tests/unit/test_proto_schema_drift.py` compares the serialized `FileDescriptorProto`
embedded in each committed `*_pb2.py` against one generated from its `.proto` at HEAD. Byte equality is
the whole test — no proto parsing to drift from the schema language, options caught alongside
messages, and immune to protoc's formatting.

Acceptance required the gate to be **observed failing**, and it was, against the exact shape the old
one is blind to: a single field added to `collection_types.proto`, which declares no service.

[cols="2,2,3",options="header"]
|===
| Gate | Result on the injected field | Reading
| `test_grpc_proto_drift` (services/rpcs) | **3 passed** | blind, as diagnosed
| `test_proto_schema_drift` (descriptors) | **2 failed** | catches it in both stub trees
|===

Run first against the unfixed tree, it failed on **14 files** — exactly the set this TD measured, which
is the same result arrived at twice by different means.

=== The regeneration

33 stub files regenerated across both trees, 27 with real content change. `make proto-check` now runs
schema drift alongside the service gate: **46 passed**.

The three capabilities the drift had been hiding are now reachable from the Python SDK —
`PredicateShortfall` and `VectorElementType` on `v2/record`, `LookupStage` on `v1/document`, and
`text_query`/`document_collection`/`document_weight` on `v2/fusion`. They were declared on the wire the
whole time; nothing but the stub stood between a caller and them.

=== Two guards on the guard

* **`test_there_is_something_to_compare`** — asserts the path convention still matches at least ten
  protos. A parametrised gate whose parameter list silently empties is a gate that passes forever, and
  this file derives its cases from a filesystem convention.
* **`test_the_two_stub_trees_agree`** — the cheap half of step 3. Collapsing the duplication remains the
  real fix; both trees are live (`unified_client_async`, `fusion_v2` and `document_v2` import
  `proximadb.v2`), and independent generation is precisely how they came to disagree on two files.

=== What is deliberately not done

The two stub trees are **not collapsed**. That is a wider change — every importer of one package has to
move — and it wants its own review rather than riding in on a gate fix. The equality assertion stops
the bleeding meanwhile, and will fail loudly if anyone regenerates one tree without the other.
