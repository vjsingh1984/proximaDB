== Why

The dominant cloud-OLAP cost term is bytes scanned. The biggest lever for star/snowflake
schemas — TPC-DS's dominant shape — is *runtime* filtering: at hash-join build time, push the
dimension-table keys down to prune fact-table partitions (DPP) and inject a bloom filter the
probe side tests before fetching rows (bloom semi-join). This is Databricks AQE + Snowflake
Search Optimization Service territory; it is where warehouse-class engines get 5–50× and
naive fixed-plan engines cannot follow. ProximaDB's bloom primitive
(`proximadb-block-format/src/stripe.rs`) and exact-vs-ANN pre-filter (ADR-011/028) are the
same idea on the vector side — converge, don't duplicate.

== Rollout (default-off, trace-gated)

. **Bloom semi-join:** at HashJoin build, construct a bloom filter over build-side keys;
  inject it into the probe-side scan (`LogicalNode::Scan` predicate) so non-matching stripes
  are pruned *before* fetch. Reuse `proximadb-bloom`. **Mechanism (pinned):** since the join
  executes inside DataFusion (ADR-052 invariant 1), the filter rides DataFusion's own
  dynamic/runtime-filter machinery where the pinned version supports it; otherwise a custom
  `ExecutionPlan` wrapper around the join captures the build-side keys and injects the bloom
  into the probe-side scan — the fallback is ours to ship, not blocked on upstream.
. **Dynamic Partition Pruning:** for partitioned/Iceberg tables, defer fact-scan partition
  selection until the dimension filter's runtime values are known; prune partitions from the
  manifest list at runtime.
. **AQE hook:** insert a re-optimization point at pipeline breaks (post-build) so the runtime
  filter + observed cardinality can adjust the probe plan (coalesce/repartition, join swap).
  (Full AQE is larger; this TD delivers the runtime-filter slice first.)
. **Trace + promotion:** instrument `bytes_scanned_before/after_filter` per query (TD-158 is
  **Resolved** — the trace substrate is available); promote only where the measured skip
  ratio justifies the bloom-construction cost.

== Verification

* TPC-DS star-join queries (e.g. Q72/Q95-class, store_sales ⋈ item/date_dim) show a measured
  bytes-scanned reduction in the TD-OLAP-4 ledger, conformance unchanged.
* The same bloom primitive serves ANN pre-filtering (ADR-011) and OLAP semi-join — one
  implementation, two consumers (converge, don't duplicate).
