== First principles

Three statements, each of which independently forces the deletion.

. **A generic vector-and-graph DB SDK has no business owning a code-domain AST parser.** This is
  ADR-029's boundary argument and it still holds: the SDK's job is to carry bytes to the store with
  tenant context and truthful offsets. Which node type in the Kotlin grammar names a function is
  application knowledge about a language ecosystem, and it belongs to the coding agent that owns a
  Code Property Graph, not to the database client.
. **Duplication is not the primary defect. "Dead AND advertised" is.** Measured in one environment on
  the pinned dependency: of the 23 registered languages, **12 raise `TypeError`, 10 are stubs returning
  `symbols=[]`, and exactly 1 works** (the regex-only XML parser). A duplicate that works is a
  maintenance cost; a duplicate that is broken while `__init__.py:11` advertises "AST-based parsing
  using tree-sitter for 20+ languages" and exports 21 parser classes is a correctness *trap*. Users
  select a supported language and receive nothing, or an exception.
. **Everything worth keeping has already been kept.** The richer taxonomy — 18 `CodeSymbolType` and 18
  `CodeRelationType` members — was ProximaDB's contribution to the shared package and is present there
  **verbatim, including identical integer values**. The `ProximaRecord` projection lives in victor's
  `adapter.py`. Deleting `code.py` therefore destroys no design, only a non-functional implementation
  of a design that already lives elsewhere.

The residual question is not *whether* to delete but *what the SDK owes a caller once it has*. That is
what the acceptance suite below defines, and it is why this TD is not a one-line `git rm`.

== Co-design: which dimensional cost term this moves

Per the co-design mandate, state the cost term and measure it — not a kernel benchmark.

Code chunking sits upstream of two meters, and its defects inflate both **before a single byte reaches
the store**:

[cols="2,3,2",options="header"]
|===
| Cost term | How the current path inflates it | Measured
| **KEU** (embedding) | `code.py` emits a class chunk *and* each of its methods again, so method bodies are embedded twice. It also never consults `chunk_size`/`max_chunk_size`, so oversized chunks are truncated or rejected by the provider — paid for, then discarded. | Sum of chunk characters = **2.0× the input** on a 4,311-char file (8,462 chars emitted). A 10.6× over-budget chunk (4,227 chars vs a 400 cap).
| **KSU** (storage GB-month) | Chunk count × dim sets the stored vector count, permanently. Double-emitted bodies are stored forever. | Same 2.0× multiplier, capitalised.
| **Recall** (the product, not a meter) | Duplicate chunks crowd real results out of top-k; imports, module constants and module-level statements land in **no** chunk, so they are unretrievable. | 61 of 4,311 chars covered by no chunk.
|===

The delegated path fixes the two multipliers — size capping verified with **zero over-budget chunks at
four budgets** (512/128/32/8 tokens), and no nested double-emission. So this deletion is not hygiene:
it is a **~2× KEU and KSU reduction per indexed repository**, which is the number to quote when
justifying the work.

What it does *not* move: compute. The delegated path runs the same tree-sitter parse. Anyone arguing
this change on CPU grounds is optimising the wrong layer.

**The boundary is the contract, and it is currently wrong.** `TextChunk.start_pos/end_pos` carries
UTF-8 **byte** offsets on the code path (`code.py:4338`, unchanged by the delegation, since victor also
publishes byte offsets) while `TextChunk` documents neither basis and every text strategy publishes
*character* offsets. One type, two incompatible units, no marker. A consumer slicing a Python `str`
with a byte offset silently corrupts any non-ASCII source. Fixing this at the seam is in scope here
because the deletion is the last moment at which the code path's contract can be set deliberately;
ADR-091 then inherits it for the document path.

== Working backwards: the tree when this is done

Written as the diff a reviewer should eventually see, so that every step below is justified by
reaching it and nothing else.

* `chunking_strategies/code.py` — **~200 lines**, not 4,427: the `CodeChunkingConfig`, the delegation,
  and re-exports of the neutral model from `victor_codegraph`. Zero `LanguageParser` subclasses, zero
  `tree_sitter` imports, zero `EXTENSION_TO_LANGUAGE`/`LANGUAGE_PARSERS` tables of its own.
* `chunking_strategies/__init__.py` — still exports `CodeSymbol`, `CodeSymbolType`, `CodeRelation`,
  `CodeRelationType`, `ParsedCode`, `SourceLocation` (re-exported, so downstream imports keep working),
  and **no longer exports 21 parser classes** or `register_language_parser`/`register_file_extension`.
* `tests/chunking/` — **green**, because it tests the delegated path. The 39 per-language parser tests
  either move upstream to `victor-codegraph` (where the parser now lives) or are deleted with the
  parsers they cover.
* `pyproject.toml` — `[chunking]` no longer implies tree-sitter symbol extraction. Installing
  `[chunking]` without `[codegraph]` and asking for code chunking **fails loudly** with an error naming
  the missing extra, rather than silently returning text windows. Fail-closed, matching the repo's
  posture everywhere else.
* `docs/SUPPORTED_SURFACE.adoc` — chunking has a support-tier row for the first time, listing the
  languages that genuinely extract symbols. Today the subsystem has **no tier at all**, which is why
  nobody had to decide whether "20+ languages" was a GA promise.
* ADR-029 — **Accepted**, its migration section marked done. (Proposed by this TD, not done by it: an
  ADR's status is the deciders' call, and it is currently Proposed here while Victor's companion
  ADR-014 has been Accepted since 2026-07-02.)

== TDD mechanism: the suite is the gate on the delete

The discipline that matters: **each acceptance test must fail today, for the stated reason, before any
deletion happens.** A test that cannot fail cannot authorise a 4,427-line removal. This is also the
direct lesson of the audit that produced this TD — the existing suite has 426 passing tests and caught
none of the defects, because it asserted execution rather than invariants.

Write these against the **delegated** path, parameterised over the language matrix:

[cols="1,4",options="header"]
|===
| Id | Assertion, and why it is red today
| **R1** | For every extension in the SDK's advertised map, chunking a minimal valid source yields **≥1 symbol**. *Red today:* fails for `.kt` (Kotlin functions are anonymous to victor's `_name_of` — `simple_identifier` is in the identifier table but absent from the hardcoded tuple actually checked), `.rb` (Ruby's `class`/`module`/`method` node types are missing from the walker's tables, so 0 symbols — a regression against `code.py`'s real 313-line parser), `.hs`/`.ex` (no grammar entry in victor at all), and `.sql` (0 symbols). This test is what forces step S3's choice: fix upstream or stop advertising.
| **R2** | `len(chunk.text) <= config.max_chunk_size` for every chunk. *Red today* on the non-delegated path (one 4,227-char chunk against a 400 cap); green on the delegated path — so R2 is the test that *proves* the delegation is the fix rather than assuming it.
| **R3** | No chunk's span is strictly contained in another chunk's span. *Red today:* every method body is emitted inside its class chunk and again alone. This is the KEU multiplier, expressed as an assertion.
| **R4** | The union of chunk spans covers every non-whitespace byte of the input. *Red today:* imports, module constants and module-level statements are covered by no chunk.
| **R5** | The offset basis is **declared and honoured**: `chunk.metadata["offset_basis"]` is present, and slicing the source by that basis reproduces `chunk.text` exactly. *Red today:* no such key exists, and byte offsets are published through a field whose sibling strategies fill with character offsets. Includes a non-ASCII case, which is the only case that can distinguish the two.
| **R6** | `include_tests=False` yields 0 chunks for `test_foo.py`. *Red today:* victor implements it, `code.py` never forwards it, so the SDK returns 1 chunk where a direct victor call returns 0.
| **R7** | `.tsx` yields ≥3 symbols. *Red today:* `code.py` maps `.tsx → "typescript"` and passes `language=` explicitly, overriding victor's own `.tsx → "tsx"` detection and costing **2 of 3 symbols** plus a syntax-error diagnostic. Deleting one argument fixes it.
| **R8** | A chunk produced by the text fallback is distinguishable from a symbol chunk. *Red today:* the delegated path labels everything `chunk_type="code"`, so a caller cannot tell a real symbol from a sliding window over 27 extensions victor does not know.
|===

R1 is deliberately the harshest: it converts "which languages do we support?" from a docstring claim
into a CI fact, and it is the assertion the whole ecosystem was missing — victor's own tests never
mention ruby, kotlin, csharp, php, swift, scala, lua or tsx, and ProximaDB's tests that do cover them
have been red the whole window. **Two suites, neither able to see the defect the other introduced.**

== Measured on 2026-08-19, executing S0–S3

The delegated path is materially better than the 2026-08-17 measurement of the LEGACY path suggested,
and three defects that measurement could not see were sitting inside it.

* **16 of 24 languages genuinely extract symbols** through delegation, not "1 of 23". The audit's
  "10/23 stubs" was the in-SDK parser figure and does not describe the shipping path.
* **R7 was costing half the symbols in every `.tsx` file.** This module maps `.tsx` to `typescript`
  and passed that down, overriding the shared package's own `.tsx -> tsx` detection: 2 symbols where
  detection yields 4. The fix is deleting one argument, exactly as this TD predicted.
* **Two defects were hidden by the red suite**, which is the argument for S0's sequencing. The
  delegation returned the shared package's *empty list* for unrecognised file types, silently
  discarding whole documents — a regression the delegation introduced, since the legacy path fell
  through to text chunking. And relations are not surfaced by the package's `chunk()` entry point at
  all, so `extract_relations` was accepted and ignored while `code_knowledge.py` builds graph EDGES
  from `metadata["relations"]`: the code knowledge graph had nodes and no edges.
* **`include_tests` (R6) was a third instance of the same class** — accepted and ignored. Fixing it
  then exposed a conflict with the new fallback, which had to be gated on *recognition* rather than
  emptiness: a package that recognises a file and returns nothing has made a decision, and overriding
  a decision is not the same as rescuing a document.

The pattern across all four: **a config field read by nobody is indistinguishable from one left
unset.** That is the same finding TD-CHUNK-5 records for the wire policy, and the same one that
forced deriving config forwarding from dataclass fields in the document path.

== R2–R5 landed 2026-08-19 — and what now gates S4

* **R2 passes everywhere.** The legacy path never consulted `max_chunk_size` (measured 10.6× over a
  400-character budget); the delegated path caps correctly. This is the assertion that *proves* the
  delegation is the fix rather than assuming it, and it is the strongest single argument for S4.
* **R5 was red and is fixed.** The code path publishes UTF-8 **byte** offsets while every text
  strategy fills the same field with **character** offsets. Confirmed by construction on a multi-byte
  source: byte-slicing reproduces the chunk text, character-slicing does not — which is why only a
  non-ASCII fixture can see it. The marker is additive, absence means legacy, no flag day.
* **R3 and R4 are red for UPSTREAM reasons**, and they are now the gate on S4:
+
[cols="1,4",options="header"]
|===
| Id | Upstream defect in `victor-codegraph` 0.9.0
| **R3** | `rust`: a window chunk for `impl Beta { … }` is emitted **alongside** a nested symbol chunk for the `fn` inside it, so the method body is embedded twice — paid once at ingest and stored forever. The KEU multiplier this TD quantified, still present in the delegated path.
| **R4** | `javascript`, `typescript`, `java`: a class yields a **header** chunk rather than a whole-class chunk, leaving the closing brace covered by nothing.
|===
+
Marked `xfail(strict=True)`, so they are a **bidirectional ratchet**: an upstream fix makes the test
xpass and *fail*, forcing the marker off. The exception cannot outlive its cause, and a fix cannot
land unnoticed. These two are the content of the upstream bug reports S3 asks for.

**Why S4 is not simply blocked on them.** The in-SDK parser does not satisfy R3 or R4 either — it is
strictly worse, since it raises outright on the pinned dependency. The question S4 must answer is not
"is the delegated path perfect" but "is it better on every axis", and R2/R5 say yes while R3/R4 say
"equally imperfect, for different reasons". That is a deliberate decision to record, not a blocker to
discover mid-deletion.

== Slices

Ordered so that each one is independently reviewable and none depends on a later one.

**S0 — stop the rot (do first, it is nearly free).** `tests/chunking/` is red on `develop` and no job
gates it. Do not "fix" it by repairing the `parse()` call signature in 23 parsers that step S4 deletes —
that is pure waste. Instead mark the per-language parser tests skipped with a reason string pointing at
this TD, and **add the delegated-path suite to the feat→develop lane** so this class of silent rot
cannot recur. A red suite outside the gate is strictly worse than a declared skip.

**S1 — write R1–R8. Land them red-and-marked**, with the failures recorded in this TD. This is the
baseline the deletion is measured against.

**S2 — fix the three seam defects** (R6, R7, R8): drop the `language=` argument and let victor detect,
forward `include_tests`, and label fallback chunks. All three live in `code.py`'s delegation, all three
are small, and all three are testable before any deletion.

**S3 — decide the advertised surface, then narrow it.** File the two upstream bugs against
`victor-codegraph` (Kotlin `_name_of`, Ruby node tables) with the failing cases from R1. For Haskell and
Elixir there is no upstream fix pending — remove them from the extension map rather than degrade
silently to text windows. R1 then goes green by construction, and the SUPPORTED_SURFACE row is
derivable from the test matrix instead of asserted.

**S4 — delete.** The 21 parser classes, the stubs, the registries, the `tree_sitter` imports. Keep the
neutral-model re-exports so downstream imports survive. Make `[chunking]`-without-`[codegraph]` fail
loudly. Expect the diff to be roughly −4,200 lines in `code.py` and −1,700 in tests.

**S5 — close the record.** SUPPORTED_SURFACE tier row; propose ADR-029 → Accepted with its migration
section marked done; note in ADR-029 that the document-chunker half is now tracked by ADR-091.

== S4 executed 2026-08-19

`code.py`: **4,589 -> 561 lines**. Removed: 21 parser classes, the `LanguageParser` ABC, the
`LANGUAGE_PARSERS` registry, this module's own extension table, and `register_language_parser` /
`register_file_extension`. Tests: −1,197 (`test_code_parsers.py`, entirely parser coverage) and −558
in the unit file, cut by a mechanical rule — drop any top-level def referencing a deleted symbol.
Total ≈ **−6,430 lines**, against the filing's estimate of −4,200 and −1,700.

Three decisions worth recording, because each went against the obvious reading:

* **The neutral model stays in-tree rather than being re-exported.** Re-exporting is the cleaner
  expression of "the shared package is the source of truth", and it would make `document_parsers.py`
  (23 references) fail whenever the optional extra is absent. Import-safety beats elegance for a model
  whose integer values are identical either way — verified 18/18, zero mismatches.
* **The extension map is derived, then deliberately re-widened by 13.** Derivation narrows 59
  extensions to 27, and the delta splits cleanly: 13 are *recoverable* (the package lacks the
  extension but parses the language — `.pyx`→python, `.hh`→cpp, `.zsh`→bash) and 19 are genuinely
  unsupported. The 13 return as an explicit alias overlay guarded by a test requiring every alias to
  resolve to a language the package actually supports, so the overlay cannot become a new overclaim.
  Final surface: **40 extensions, 18 languages.**
* **Surviving legacy tests were updated, not deleted, where they still describe something true.**
  `.tsx` now asserts `tsx` rather than `typescript` (the R7 fix, made permanent), and perl/yaml/json
  assert they are *no longer advertised* — which keeps the narrowing itself under test.

The S0 skip block is gone with the classes it named. `tests/chunking/` now needs **no skips at all**:
684 passed, 0 skipped, 0 failed — from 56 failed two days ago.

Absent extra now fails loudly. Previously it fell through to the broken in-SDK parsers; silently
returning text windows looks like working code chunking while extracting no symbols.

== Risks and the honest counter-argument

* **Deleting a real Ruby parser to adopt one that returns nothing is a regression on paper.** It is not
  one in practice *today* — the legacy parser raises `TypeError` on the pinned dependency, so nothing is
  lost right now. But S3 must not paper over it: either the upstream fix lands, or Ruby leaves the
  advertised set. Choosing silently is how the ecosystem got here.
* **Byte-versus-character offsets is a stored-contract change**, because `document_processor.py:437`
  and `:648` persist these values. Per the storage-migration mandate, R5's `offset_basis` marker is
  additive and readers must default to the legacy interpretation when it is absent. No flag day.
* **Someone will propose keeping `code.py` "just for the languages victor lacks."** That reproduces the
  duplication ADR-029 removed, and the languages in question (Haskell, Elixir) are stubs that return
  nothing anyway. There is no version of this argument that survives the measurement.

== S5 executed 2026-08-19 — closing the record

The slice was specified as documentation, and writing the SUPPORTED_SURFACE row is what exposed that
three claims in shipped code had not survived S4's deletion. A tier row is a promise; deriving one
from constants that are no longer true would have published the untruth rather than caught it.

**Three false claims removed from `code.py`.** The module docstring still promised a fallback to "the
legacy in-file implementation below" — deleted in S4. The package docstring still advertised a
"pluggable architecture for adding new language support" after the registries that made it pluggable
were removed. And the `DeprecationWarning` fired on every construction of the only supported
code-chunking entry point the SDK has. That warning was ADR-029's steer *off a duplicate parser*; the
duplicate is gone, so `CodeChunkingStrategy` now IS the consumption ADR-029 asked for. A
`DeprecationWarning` means "this will be removed", which is false, and a warning nobody can act on
trains callers to filter warnings. Retired, with the test inverted to hold it retired.

**`COVERED_WITHOUT_SYMBOLS` was conflating two states, and the one-directional partition assertion is
why nobody saw it.** S4 narrowed the extension map from 59 extensions to 40, which silently moved six
of that set's eight members out of the advertised map — leaving one name covering both "advertised but
symbol-less" (`ruby`, `sql`) and "not advertised at all" (`perl`, `haskell`, `elixir`, `json`, `xml`,
`yaml`). The assertion checked `advertised - accounted` only: it catches a language advertised without
classification, and cannot catch a claim about something no longer shipped. Now an **equality**, which
has no third state, plus `WITHDRAWN_LANGUAGES` as the standing record of S3's decision. Withdrawn is
not discarded — those files still chunk through the labelled fallback, and both coverage tests now run
over both sets.

The generalisation is worth carrying forward: **a ratchet that only tightens in one direction records
growth and misses retreat.** Every narrowing this program performed — the extension map, the
strategy surface, the parser set — is invisible to an assertion of that shape.

**The tier row itself.** Two rows, because the two halves have genuinely different support stories:
document chunking is **Supported** (0 violations against 70 of 70 clean cases, a golden oracle proving
neutrality and an eval suite scoring quality), code chunking is **Beta** (needs an optional extra and
carries two pinned upstream defects). The row states the 16-language symbol-extracting set explicitly
and instructs readers not to quote "20+ languages" — the claim this TD was filed to retire.

=== What remains, and it is not this TD's

* **ADR-029 → Accepted** is recommended in the ADR with its evidence, and deferred to the deciders.
* **Two upstream bug reports FILED 2026-08-19** against `victor-codegraph` 0.9.0 — **victor#916**
  (Rust `impl` overlap) and **victor#917** (class closing brace uncovered) — both pinned here as
  strict xfails so a fix cannot land unnoticed. Writing them re-measured both at **default** config
  rather than the tight budget the xfails use, and the defects are materially worse than the pins
  said: #916 emits **6,122 bytes for a 2,876-byte file (2.13x)** with 98% of bytes in more than one
  chunk, *and* leaves the struct's own field list in no chunk at all; #917 reproduces in
  javascript, typescript, tsx **and** java, at **any size** — a 62-byte class that fits the budget
  loses its brace too, so it is not large-symbol windowing.
+
Two fixture lessons, both caught before filing. A first Rust fixture carrying trailing `//` comments
produced **byte-identical duplicate chunks**, which would have been the headline — it was an artifact
of comment handling, a *different* behaviour, and the claim did not survive a cleaner fixture. The
same comments made the JS/Java coverage numbers read 891 uncovered bytes instead of 1. **A fixture
that introduces a second variable produces a confident wrong number**, which is the same failure as
filing victor#913 with a headline that had to be publicly corrected.
* **`ruby` symbol extraction** is an upstream node-table gap. It sits in `COVERED_WITHOUT_SYMBOLS`
  honestly rather than being claimed, which was the whole point.

== The version gap (2026-08-22) — this TD's evidence does not hold on any released package

Found by asking a question that should have been asked in S1: *does CI install the extra?* It does not.
Three facts compound from there, and the third invalidates the rest of this document's measurements.

. **No CI job installs `codegraph`**, so `tests/chunking/test_code_language_surface.py` — the R1–R8
  suite that authorised deleting 4,589 lines — has never run in CI.
. **It did not skip, it FAILED**: 50 of 52 in an environment without the extra, because the module had
  no guard. A red suite outside the gate is the precise defect **S0 of this TD** was filed to stop, and
  it was sitting in the suite written to close it.
. **Every measurement here was against 0.9.0 installed *editable* from a local, unpublished checkout.**
  Codegraph package tags stop at `victor-codegraph-v0.8.1`; PyPI agrees.

Run properly against the **published 0.8.1**, this TD's acceptance suite is **30 failed / 24 passed**:

[cols="3,1",options="header"]
|===
| Criterion | Failures on 0.8.1
| **R1** advertised languages extract symbols | **15 of 16 languages**
| symbol-less languages still covered | 8
| R4 full character coverage | 3
| R3 no nested chunks | 2
| R5 declared offset basis | 1
| R6 `include_tests` forwarded | 1
|===

So on the only version a user can install, the delegated chunker extracts essentially no symbols —
**the exact "dead but advertised" trap this TD deleted the in-SDK parsers to remove**, reintroduced
through a version gap. The language *surface* is identical across 0.8.1 and 0.9.0 (27 extensions, 18
languages, zero differences), so the derived constants are sound; the *behaviour* is not.

=== What was done about it

The honest half, landed immediately and independent of upstream: the extra now pins `>=0.9.0` — a floor
that is deliberately unsatisfiable from PyPI, because an install-time error naming the version is
better than a silent behavioural difference a caller meets as an empty result. `code.py` carries the
matching runtime guard for environments already holding an older copy, and the acceptance suite skips
(naming the installed version) instead of running against a package its claims were never measured on.
`SUPPORTED_SURFACE` is corrected and the code-chunking tier drops **Beta -> Experimental**, which is
what "requires an unreleased dependency" actually means.

The unblocker is upstream: **publish a codegraph release that passes this suite.** Until then the
delegated path stays unexercised in CI, and wiring the extra into the conformance job is pointless —
it would only make the gap loud in a place that blocks everyone rather than in the docs.

=== The lesson, which is not about versions

Both halves of the claim "measured, not advertised, and asserted per-language in CI" were false, and
each for a different reason: not in CI, and not measured on anything shippable. The measurement was
real — it was just taken in an environment only I had. **A capability claim inherits the trust level of
the environment it was measured in**, and a local editable checkout of an unreleased dependency is the
weakest such environment there is.
