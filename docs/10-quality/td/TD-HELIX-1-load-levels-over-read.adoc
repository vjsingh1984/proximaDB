= TD-HELIX-1: HELIX load_levels reads 953 MiB on cold-start (full block manifest, not compact footer)

== Symptom

HELIX's `load_levels()` (`helix/mod.rs:741`) reads every SST file's full "header" via
`read_helix_header_optimized` (2 ranged GETs per file). But the "header" in the ProximaDataBlock
format includes **per-block centroid, offset, and metadata for EVERY block** → ~953 MiB at 100K
vectors (18× the 51 MiB raw f32 vectors). This is the **full block manifest**, not a compact
spatial-pruning footer.

Measured cold-start (100K vectors, dim 128, `CountingFileSystem`):
```
HELIX: 108 GETs, 953 MiB, 271 ms cold-start latency
SST:     7 GETs, 7 KB,  24 ms  (lazy — manifest only)
VIPER:  27 GETs, 915 MiB, 133 ms
NOVA:   27 GETs, 914 MiB, 269 ms
```

== Root cause

`read_helix_header_optimized` (`helix/proxima.rs:636`) reads the file footer (16 bytes) to find the
header offset, then reads the **entire header** (which includes all block metadata). At 100K vectors
with ~100 blocks, each header entry carries centroid (128 dims × fp16 = 256 bytes) + offsets + stats
→ the header IS the block manifest → MiB-scale, not KB.

== Fix approach

**Isolate the spatial-pruning metadata** (Hilbert range + block centroids) into a **compact separate
footer/index** at the END of each HELIX file. `load_levels` reads ONLY that footer via ranged GET
(KB per file). The full block data is read only at query time, for the FEW targeted blocks:

```
AXIS (HNSW/HMGI) → returns matching vector IDs (TD-AXIS-1 fix)
    → SST has IDs sorted → target specific blocks by ID range
    → HELIX targets by centroid/Hilbert proximity → even fewer blocks
    → per-query reads = few ranged GETs (the production I/O cost)
```

This is the **index→ID→block-targeting flow**: the index narrows to a few block IDs → the engine
reads ONLY those blocks (not the whole file). HELIX's Hilbert sort makes the targeting tighter
(spatially adjacent IDs → contiguous blocks → fewer ranged GETs).

== Dependencies

- **Depends on**: TD-AXIS-1 (the block-targeting flow requires a working ANN index that returns IDs;
  without it, HELIX reads everything because there's no index to narrow the block set).
- Mixed-read-safe: the new compact footer must be version-gated (magic byte / version) so old files
  without the footer fall back to the full-header read.
