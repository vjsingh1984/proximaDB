= TD-DECOMP-55: Move morsel_scheduler into existing proximadb-storage-common crate

[cols="1,3", options="header"]
|===
| Field | Value
| Status | Landing
| Severity | Low — behavior-neutral re-export
| Component | `crates/storage/proximadb-storage-common`; root `src/storage/engines/sst/readers/mod.rs`

== What moved
`src/storage/engines/sst/readers/morsel_scheduler.rs` (5 tests: `MorselScheduler` cooperative
morsel-driven scan scheduler + `Morsel`/`MORSEL_SIZE`) → the EXISTING storage crate
`proximadb-storage-common`. Root `storage/engines/sst/readers/mod.rs` re-exports it
(`pub use proximadb_storage_common::morsel_scheduler;`), so the existing
`pub use morsel_scheduler::{MORSEL_SIZE, Morsel, MorselScheduler};` resolves unchanged.

== Why into an existing crate
morsel_scheduler's deps (anyhow / tokio / tracing / proximadb-records) are all already declared by
storage-common, and it has zero `proximadb_storage_common::` self-refs — so it drops in with no dep
adds and no self-import rewrite. NO new crate, NO root `Cargo.toml` wiring → no stacked-PR conflict.
Verified: standalone `cargo check --all-targets` + root `cargo check -p proximadb --lib` pass
(pre-existing storage-common clippy debt in test/bench code is unrelated and not CI-gated). SIFT
recall ratchet RUNS (storage_changes) under the 45m cap (#1555).
