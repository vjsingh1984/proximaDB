= TD-OLAP-5: Analytics surface parity — function/window/aggregate library, relational late-materialization, result cache

[cols="1,3", options="header"]
|===
| Field | Value
| Status | Open — the completeness gap; lower individual severity, high in aggregate (BI-tool usability)
| Severity | Medium — blocks real BI/pgwire workloads even after the execution engine is fast
| Component | `crates/foundation/proximadb-functions`, `proximadb-relational-executor`/DataFusion scan path, query result cache
| Governs | link:../../12-design/adr/ADR-052-analytics-execution-competitiveness-codesign.adoc[ADR-052] (invariant 3, completeness)
| Relates to | ADR-018 (pgwire/SQL parity roadmap — the driver), ADR-039 invariant 4 (one function definition, N bindings), TD-186 (expr-eval unification)
|===

== Why

Three gaps separate a fast engine from a *usable* warehouse surface, and each is table-stakes
vs Snowflake/Databricks:

. **Function library:** `proximadb-functions` ships ~8 scalars + one aggregate demonstrator
  (`register_builtin_scalars`/`register_builtin_aggregates`); window functions are absent.
  Mature systems ship 100+. Per ADR-039 invariant 4, each function is defined once as a
  `ProximaValue` kernel and bound to DataFusion — so coverage is additive, not a rewrite.
. **Relational late-materialization:** late materialization exists only for vector top-k
  (`columnar_query_reader.rs` "selection bitmap"); the relational scan fully materializes
  projected columns. For selective OLAP scans this wastes the bytes-scan budget ADR-052
  invariant 3 is trying to protect.
. **Result cache:** Snowflake's 24h→31d persisted result cache serves dashboard re-runs from
  the metadata layer with *no* compute charge. No competitor except the warehouses ships this;
  it is a large cloud-cost/UX lever for repetitive BI.

== Rollout (independent slices)

. **Functions:** grow `proximadb-functions` toward ANSI parity in tranches (date/time,
  conditional, casting, string, array/map, aggregate set); add window-function framing
  (`AggregateAccumulator` trait already exists — add partition/frame). Bind each through the
  DataFusion UDF wrapper; never redefine. Track ANSI-conformance coverage as a ratchet.
. **Late materialization (relational):** in the PAX-scan → Arrow path (TD-OLAP-1), defer
  wide-column decode for rows not surviving the filter/limit; reuse the vector-path selection
  bitmap idiom for the relational selection vector.
. **Result cache:** a query-result cache keyed on (canonical logical plan + LSN/bounded
  freshness watermark, per ADR-038/051), invalidated by write/DV; serve hits without
  warehouse compute. Default-off, flag-gated; promote on measured dashboard hit-rate.

== Verification

* ANSI function-coverage ratchet rises monotonically; pgwire BI-tool smoke tests (psql,
  Metabase/Superset-class) pass against a representative TPC-DS workload.
* Late-materialization: a measured bytes-decoded reduction on selective scans in the TD-OLAP-4
  ledger, conformance unchanged.
* Result cache: repeat-query latency drops to metadata-fetch on the second run; invalidated
  correctly on write (reuse the ADR-051 LSN-pinning invariant).
