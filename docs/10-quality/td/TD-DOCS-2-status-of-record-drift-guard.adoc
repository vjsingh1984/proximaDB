== Finding (2026-07-12)

An external architecture analysis of ProximaDB reproduced the Course Correction §4
audit table (a 2026-06-04 point-in-time snapshot) as *current* state — concluding
"DataFusion UNWIRED, test-only", "`ComputeProvider` DEAD STUB", "no Parquet/Iceberg
write". All three were false at the time of the analysis: `DataFusionLocal` routes
live on pgwire behind the default-on `datafusion-integration` feature (ADR-052), the
`LocalComputeProvider` scaffold was deleted the same day the audit was taken, and
`ALTER TABLE … MATERIALIZE` writes Parquet. `SYSTEM_MAP` — the doc that *claims* to be
the "active baseline tracking current HEAD" — also lagged (no mention of the landed
cost-model consult/override tiers), and stale module docs in
`src/query/compute_scheduler.rs` ("P0 ALWAYS returns Native") corroborated the wrong
story.

*Root cause (first principles, co-design P11 "measure, don't assert" applied to
docs):* the only doc guard (`docs-claim-check`) greps a handful of marketing phrases.
Nothing ties a status-of-record doc to a freshness contract, so the drift is invisible
until an external reader is misled. In a repo developed by many concurrent agent
sessions, docs ARE the harness — stale status docs poison every future session's
static context.

== Shipped in the filing PR

* `// status-as-of: YYYY-MM-DD` tag convention: the tag asserts the doc's
  status/current-state sections were re-verified against HEAD on that date. Bumped
  only after re-verifying — never mechanically.
* `scripts/check_status_as_of.py`: fails when an allowlisted doc is missing the tag or
  the tag exceeds `--max-age-days` (default 60). Exit 0/1/2 per repo guard convention.
* Makefile target `status-asof-check`, wired into `work-commit-check`.
* Tags: `SYSTEM_MAP` (2026-07-12, re-verified in the same PR) and `SUPPORTED_SURFACE`
  (2026-06-17 — its honest existing last-verified date; the guard forces a re-verify
  by mid-August rather than us stamping today's date on unverified content).
* Supersession NOTE on Course Correction §4 so the snapshot can no longer be cited as
  current state.

== Remaining scope

1. **Allowlist extension.** Graduate other docs that present current-state tables into
   the allowlist as they are re-verified (candidates: `docs/12-design/README.adoc`
   architecture index, capability-matrix source docs).
2. **Claim-level checking (stretch).** The tag is a freshness contract, not a truth
   contract. Consider tying specific greppable claims to code anchors (e.g. a claim
   registry mapping "DataFusionLocal routes live" → a grep that must hit
   `route_select_inner`), in the spirit of `capability-matrix-check`.
3. **Session hygiene.** When a PR materially changes routing/engine/format status,
   the same PR updates SYSTEM_MAP's status sections and bumps the tag (reviewers:
   treat a status-changing PR without a SYSTEM_MAP touch as suspect).

== Verify

* `python3 scripts/check_status_as_of.py` → exit 0 on a fresh tree.
* Backdate a tag beyond 60 days → exit 1 with the re-verify remedy message.
* Remove a tag → exit 1 naming the doc.
* `make work-commit-check` includes `status-asof-check`.
