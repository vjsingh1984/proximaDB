== Why

TD-183 was fixed across four code paths (PR #480/#486/#496 + open work) because
cast lowering, function resolution, and predicate evaluation are fragmented (see
ADR-043 Context). The load-bearing defect is a pushed-down `WHERE` predicate that
**silently drops every row** on an eval error — a wrong answer that presents as a
clean empty result, the exact class ADR-040 exists to catch.

== Rollout (each step gated by the ADR-040 document-accuracy ratchet)

. **Invariant 1 — fail-loud pushdown predicate.** Change the storage-scan row
  predicate from `Fn(&[ProximaValue]) -> bool` to
  `Fn(&[ProximaValue]) -> Result<bool, ExprError>`; thread it through
  `DmlService::scan_table_relational`; have `DmlTableReader::open`
  (`src/network/postgres/relational_pipeline.rs`) propagate `ReaderError::PredicateEval`
  like `FilterExec`. Subsumes the name-only pre-validation added in PR #496.
  Effect: d06 (and any cast/JSON predicate the native engine can't evaluate) fails
  loud → the OLAP binding serves it → accurate, never silent 0-rows. Ratchet 9 → 10.

. **Invariant 2 — one cast lowering in the frontend.** Add the `SqlExpr::Cast` arm
  to `proximadb-relational-frontend` `lower_expr` (one `sql_type → ProximaType`
  map); **delete** the cast-strip list in `src/network/postgres/translator.rs`; fill
  the native `cast_value` gaps (`proximadb-relational-types`, e.g. `String→Int32`).
  Effect: d06 native computes the correct row; d11 `::boolean` is preserved so the
  comparison is `cast(... AS Boolean) = true` (no `Utf8 = Boolean` clash). Ratchet
  → 11.

. **Invariant 3 — one function definition.** Move `json_extract` /
  `json_extract_text` / `json_extract_path_text` kernels from
  `src/datafusion/udf.rs` into `proximadb-functions` `register_builtins` (engine-
  neutral `ProximaValue` kernels accepting `ProximaValue::Json` and `String`); add
  them to `DATAFUSION_NATIVE_SCALARS` so the F2 adapter keeps the typed Arrow UDFs
  authoritative (avoids the untyped-shadow regression); tighten frontend scalar-name
  validation so unknown functions fail at planning, not row eval.

== Verification

Each step keeps `tests/document_json_pgwire_e2e.rs` green, removes the fixed ids from
`KNOWN_BAD_TD183`, and raises `DOC_ACCURACY_RATCHET`. Cross-engine differential +
anchored checks (ADR-040) confirm native ≡ DataFusion after each invariant lands.
