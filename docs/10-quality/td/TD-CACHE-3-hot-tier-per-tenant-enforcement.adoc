== The finding

The commercial hot tier is a *contract*: a paying tenant's working set stays
resident. Today all tenants share one elastic pool under one pseudo-tenant id,
so any tenant's churn can flush any other tenant's survivor ranges — including
a tenant paying for pinning. The multitenant cache underneath already has the
budget machinery; only the wiring is missing.

== Direction

S1 — **Thread the real `tenant_id`** from the search path into
`SurvivorRangeCache::get_or_fetch` (the `CacheKey` already carries a tenant
field). Per-tenant hit/miss/bytes fall out of the existing `tenant_stats()`
(and fix the TD-METRICS-1 gauges from sums to labeled per-tenant series when
cardinality allows).

S2 — **Pinned floors from entitlements** ✅ SHIPPED (see Status): the
hot-tier floor (`TierSpec.floor_frac` via the tiers.json entitlement) is now a
*reserved* pinned segment — never evictable by other tenants' pressure — while
unpinned tenants share the remaining elastic pool, work-conserving. Default-OFF
(`PROXIMADB_SURVIVOR_PIN_RESERVE_FRAC`), mandate #8.

S3 — **Enforcement metering** ✅ SHIPPED (2026-07-25):
`proximadb_survivor_cache_tenant_pinned_bytes` vs
`proximadb_survivor_cache_tenant_entitled_bytes` per-tenant gauges (top-50 by
resident bytes; entitlement via the new public `TenantCache::entitlement`).
Billing true-up charges what is entitled; a sustained pinned < entitled gap
under pressure = residency cannot be honored (capacity signal to move
B4ms → E-series, per the 2026-07-24 instance-family analysis). Cloud-latency two-tenant bed RUN 2026-07-26 (Azurite, scripts/bench/
two_tenant_bed.py): **residency contract PROVEN** — tenant A pinned 13.24 MB
= 98.7% of entitlement, byte-identical through tenant B's 9,162-admission
churn; B pinned 0; per-tenant pinned/entitled gauges correct. Latency
isolation inconclusive at emulator speeds (p95 3→10 ms = co-located CPU
contention, not eviction — gauges prove residency held); a real-cloud run
remains for the SLA number. BLOCKER found: TD-CACHE-6 (survivor cache
records zero hits on the probe-armed default path) must be fixed before the
hot tier is sold — pinned bytes that never serve hits are dead capital.

== Verification
- Two-tenant test: tenant A pinned (floor = its working set), tenant B churning
  a larger-than-pool set → A's hit rate stays 100%, B evicts only its own.
- Hot-tier QPS contract: A's measured latency stays in the hot regime
  (sub-ms, 0 GETs) throughout B's churn.
