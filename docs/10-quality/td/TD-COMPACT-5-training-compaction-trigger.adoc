= TD-COMPACT-5: training-compaction trigger — flush-floor beds never reach the L0-count gate, so IVF training never runs
:status: S1 shipped (2026-07-25, this PR)
:filed: 2026-07-25
:priority: P1 (4–9× cold-query cost)

== The finding

Compaction is where IVF/PCA training happens ("train-at-compaction,
assign-at-flush"): only `write_pax_segment_compacted` emits the trained
v3/A0 layout that arms the coarse probe; flush segments are untrained by
construction (sign-bit bootstrap). The compaction gate fires on **L0 file
count ≥ 5** — but the TD-FLUSH-3 predicted-bytes floor deliberately produces
2–3 large L0 segments at 1M vectors, so the count is structurally
unreachable and training never runs. Measured stake (rate-card eval
2026-07-25): untrained cold queries pay **179.7 GETs / 104.3 MB per query**
(whole-Region-A scans, scattered survivors) vs the trained band of **20–51
GETs / 24–30 MB** — a 4–9× cost difference on the billed dimension.

== S1 (shipped): untrained-segment arm on the flush-path gate

`SstEngine::should_trigger_compaction` (flush/mod.rs) now returns the
*effective threshold* with two arms:

- COUNT (unchanged): `l0_count ≥ per-collection threshold` → that threshold.
- TRAINING (new): any L0 `.pax` whose 72-byte header prefix shows
  `layout_version != 3 || a0_len == 0` (no A0 coarse directory) and whose
  size ≥ `PROXIMADB_TRAINING_COMPACTION_MIN_MB` (default 32) → threshold 1,
  so `run_due_compaction` compacts the few large untrained L0s instead of
  declining. The condition self-clears: the output segment is trained.

Cost of the check: one stat + one 72-byte ranged read per L0 candidate, only
when armed. Arming is UNCHANGED (default-OFF: `compaction:on` tag or
`PROXIMADB_L0_COMPACTION_ENABLED` — mandate #8); default-ON is the follow-up
flip once the trained path is baked against the recall ratchet.

== Rejected alternative

Telemetry-driven targeting via `proximadb_ivf_whole_region_fallback_total`:
the counter is process-global and unlabeled — it can say "fallbacks are
happening", not which segment is untrained. Per-segment attribution would
need the io_trace warehouse or a new label; the size-floor arm avoids the
coupling entirely and is strictly smaller.

== Measured (E2E, this PR, 2026-07-25)

1M ingest, production floor, `PROXIMADB_L0_COMPACTION_ENABLED=1
PROXIMADB_IVF2=1`: inline flush observable (55→110 s), training compaction
produced **v3/A0 segments** and the arm self-cleared (the second flush's L0
received its own pass; final bed = all-trained). Cold novel queries measured
MID-TRANSITION (one trained L1 + one untrained L0): **108.5 GETs / 88 MB per
query** (from 179.7/104.3 untrained), recall@10 **0.9840**, clean shutdown
with zero `__flush` stragglers. The fully-trained cold band (20–51 GETs) is
the follow-up evidence run on an all-trained bed with the read-side probe
armed. NOTE: the arm requires the A0 trainer (`PROXIMADB_IVF2`) — without it
compaction outputs stay v1 and the arm would loop, so the gate checks
`ivf_probe_enabled()` first.

== Verification

E2E (this PR's evidence run): 1M ingest with `PROXIMADB_L0_COMPACTION_ENABLED=1`
→ post-flush training compaction fires at threshold 1 → segments become
v3/A0 → cold sweep GETs/query drop from ~180 toward the trained 20–51 band,
recall ≥ 0.984.
