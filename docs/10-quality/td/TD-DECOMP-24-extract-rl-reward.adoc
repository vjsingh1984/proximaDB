== Why

`src/query/rl_planner/reward.rs` (**15 tests**) computes the reward signal for the RL query-route
planner (`RewardCalculator`, `OptimizationGoal`, `OptimizationTarget`). It is a truly self-contained
leaf (zero `crate::` climb-out, zero real `super::` — the one `super::` is the `#[cfg(test)]` block),
depending only on `serde` + `tracing`. Moves to a new tiny query-tier crate.

== What moved (behavior-neutral)

* `src/query/rl_planner/reward.rs` → `crates/query/proximadb-rl-reward/src/reward.rs`.
* Root `src/query/rl_planner/mod.rs`: `pub mod reward;` → `pub use proximadb_rl_reward::reward;`
  (the existing `pub use reward::{OptimizationGoal, OptimizationTarget, RewardCalculator};` re-export
  keeps working off the shimmed module).
* New query-tier crate, deps `serde` + `tracing` (workspace). No `CAPABILITY_MATRIX.toml` pointer.

== Follow-ups

* **Running total once merged: ~872 tests out of root** (857 + 15).
* Process: `reward.rs` declares only `use serde::...`, but uses `tracing::` fully-qualified (in tests) —
  the recurring "fully-qualified/test-only dep missed by the `use`-scan" lesson; compiling the standalone
  crate catches it. Compiled in ~4 min with `RUSTC_WRAPPER=sccache` (47 cached Rust hits reused) vs the
  ~30 min cold compile without it.
