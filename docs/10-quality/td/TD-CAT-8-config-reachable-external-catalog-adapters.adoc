|===
| Field | Value
| Status | In Progress — the two non-conforming adapters closed; federation wiring next
| Severity | Medium — build cost + an undecided public/wire surface, not a correctness bug
| Component | `crates/control/proximadb-catalog/src/{hive,iceberg,glue}.rs`, `manager.rs`

== 🔴 Correcting an earlier claim

An earlier catalog survey (recorded during the ADR-090 work) asserted these adapters had **"zero
non-test callers"** and could simply be gated or deleted. **That is wrong**, and the correction is
the point of this TD — acting on the original claim would have broken the build and silently
removed a configuration surface.

== Verified reachability map

[cols="2,3"]
|===
| Fact | Evidence

| The adapters ARE referenced by production code | `manager.rs:296` `use crate::iceberg::IcebergCatalogConfig`; `manager.rs:333` `use crate::glue::GlueCatalogConfig`; both construct the adapter and return `Arc<dyn Catalog>`
| They are re-exported as public API | `src/catalog/mod.rs:111` `pub use proximadb_catalog::glue::GlueCatalog`
| They have **wire** config variants | `proximadb.v1.rs`: `IcebergCatalogConfig`, `HiveCatalogConfig`, `GlueCatalogConfig` as `CatalogConfig` enum arms
| The manager entry points have ONLY test callers | `create_iceberg_catalog` / `create_glue_catalog` are called solely from `src/catalog/mod.rs` `#[cfg(test)]` (lines 371/432/438/461/619)
| `HiveCatalog` is used by a WAL test helper | `src/storage/persistence/write_ahead_log/mod.rs:4002`
| None are feature-gated | `proximadb-catalog/src/lib.rs:73-75` declares `pub mod glue; pub mod hive; pub mod iceberg;` unconditionally — they compile into EVERY build
|===

So the accurate statement is: **unreachable from the running server, but reachable by
configuration and part of the crate's public + proto surface.** That is a different category from
dead code, and it makes this a design decision rather than housekeeping.

== 🔴 Second correction: "config-reachable" was itself too generous

The reachability map above is right about the *Rust* surface and wrong about the
*configuration* surface. The one config path — `POST /api/v1/catalogs` — calls
`convert_proto_catalog_config` (`src/network/rest/canonical/catalog.rs:450`), whose parameter is
`_proto_config` and whose body is an unconditional
`Err(ApiError::NotImplemented("Catalog config conversion not yet implemented"))`. **Every**
`CatalogConfig` arm 501s, `Native` included. So the accurate statement is: reachable from Rust as
public API, **not** reachable by deployment configuration.

== ⭐ The finding that decides this: the target already exists

`ExternalCatalog` — the narrow, read-mostly, identity-free trait [[TD-CAT-7]] proposed *creating* —
is **already in the tree**: `federation/external/mod.rs:110`, 18 methods, string-keyed namespaces,
no identity, no minting. So is a `FederatedCatalog` struct with `register_external` /
`resolve_table` / `list_all_tables` / `get_constraint_support`
(`federation/federated_catalog.rs:213`).

[cols="2,1"]
|===
| Fact | Count
| Implementations of `ExternalCatalog` | **0**
| Construction sites of `FederatedCatalog` | **0**
| External adapters implementing the *internal* `Catalog` trait instead | **5**
|===

Two halves of a federation feature, neither connected to the other, neither reachable — under a
module header that said "PRODUCTION READY" (corrected). Building a new trait for these adapters
would have duplicated an existing primitive, the failure mode CLAUDE.md mandate #12 names
explicitly.

== Decision (2026-08-20): option 3 — keep and finish

Federated metastore support is wanted, so the adapters become `ExternalCatalog` implementations.
The work is *connecting two existing halves*, not designing anything:

. Implement `ExternalCatalog` for Hive/Glue/Unity/Polaris/Iceberg by **moving** their existing
  HTTP/thrift/SDK bodies across — they already perform exactly these operations.
. **Delete their `impl Catalog`.** This is the substance: identity obligations they cannot honour
  become *structurally absent* rather than silently defaulted. `Catalog` impls drop 9 → 4, which is
  also most of [[TD-CAT-7]] item 4's available win.
. Construct a `FederatedCatalog`, register adapters from config, and replace the blanket 501 with
  real dispatch — plus an **explicit** unsupported error for arms the build does not carry.
. Feature-gate behind `external-catalogs` (default-off) so five never-executed adapters stop
  compiling into every binary. Build cost is a dimension this repo pays (cold builds ~30 min,
  `CARGO_BUILD_JOBS` capped at 3 for OOM). **Measure the delta; do not assert it.**

== 🔴 Third correction: two of the five adapters were not what the plan assumed

The decision above ("move their existing HTTP/thrift/SDK bodies across — they already do exactly
these operations") was checked against the code before any was written. **It holds for three of
five and fails for two.**

[cols="1,3", options="header"]
|===
| Adapter | What it actually is

| `Unity` | **Real.** HTTP to the Unity REST API via `reqwest` (`unity.rs:272`, `:299`).
| `Polaris` | **Real.** HTTP with OAuth token + retry (`polaris.rs:247`, `:266`, `:299`).
| `Glue` | **Real** via `aws_sdk_glue` when a client is configured. Note: each operation is
  `if let Some(client) = &self.client { … }` with **no else**, so with no client (or the `aws`
  feature off) it no-ops and returns `Ok`.
| `Hive` | **A MOCK.** `thrift_uri` is stored at construction and never used to connect; every
  operation reads and writes `mock_databases` / `mock_tables` HashMaps. The code says so: "In
  production, this would be a proper Thrift client."
| `Iceberg` | **Real but LOCAL.** Persists metadata as JSON under `warehouse` via `tokio::fs` — not
  an external metastore at all.
|===

Registering the Hive mock as a federation adapter would have made "federation works"
indistinguishable from "we returned what we put in a HashMap" — the defect class this whole
program exists to close, reintroduced by the fix for it.

== Shipped: the two non-conforming adapters

=== `HiveCatalog` deleted

~780 lines that connected to nothing, plus its factory, its public surface, and the four tests that
asserted the mock behaved like a mock. A real Hive client would share no code with it, so nothing
reusable was lost.

The `hive` proto arm is retained for now but `convert_proto_catalog_config` no longer answers every
config with the same sentence — it names the reason per arm, and for `Hive` it says the backend was
removed. Retiring the wire arm is a follow-up (v1 serde is hand-maintained, with its own drift
gate).

One real dependency had to be replaced: `write_ahead_log`'s TD-FLUSH-8 fixture used `HiveCatalog`
for its *shape* — a catalog whose `list_namespaces` omits `default` while a table under it
resolves. That worked only as a side effect of someone else's mock, so the test's actual
requirement was invisible. It is now an explicit `UnlistedDefaultNamespaceCatalog` double that
implements the three methods the flush-side walk calls and errors by name on everything else.

=== `IcebergCatalog` now fails closed instead of lying

Two silent defects, both from configuration that was accepted, echoed back, and ignored:

. **`IcebergBackend` was never dispatched on.** It was derived from the URI scheme
  (`jdbc:` → `Jdbc`, `s3://` → `Hadoop`), stored, and reported by `health_check` — the only other
  use in the file. A JDBC URI got you local files while health reported "Jdbc".
. **A remote warehouse resolved to `std::env::temp_dir()`.** `parse_warehouse` mapped
  `s3://`/`gs://`/`az://` to a temp directory, so catalog metadata for a cloud warehouse was
  written to `/tmp` and did not survive a restart — the same failure the native catalog closed in
  TD-OBJSTORE-1 (#960), whose own comment says a clear error is "strictly safer than silently
  caching the catalog under /tmp".

The module's doc example configured **both** (`uri: "jdbc:postgresql://…"`,
`warehouse: "s3://my-bucket/warehouse"`), so the documented usage was the broken one.

`new` now rejects a `jdbc:` URI and any remote warehouse with an error saying what will not happen
and why. `Jdbc` stays on the enum (discriminant stability) documented as unconstructible.

**Teeth**: removing the guards makes both rejection tests fail while
`a_local_warehouse_still_constructs` keeps passing — a guard that rejected everything would look
correct without that positive control.

Iceberg stays on the internal `Catalog` trait: it is a local Iceberg-format store, not an external
metastore, so `ExternalCatalog` would misdescribe it.

== Still to do

Implement `ExternalCatalog` for **Unity, Polaris and Glue**, delete their `impl Catalog`, construct
a `FederatedCatalog`, and feature-gate them behind `external-catalogs`. That is the federation build
proper; this change cleared the two adapters that could not honestly take part in it.

== The decision that was to be made

. **Gate** behind a cargo feature (e.g. `external-catalogs`, default-off). Requires gating
  `manager.rs`'s `create_*` fns and the affected tests together, and answering what happens when a
  deployment sets a proto `CatalogConfig` arm the binary no longer supports — it must fail
  explicitly, never silently fall back.
. **Deprecate** the proto arms first (they are wire surface; per the pre-GA rules a clean break is
  allowed, but it must be *stated*), then gate or delete.
. **Keep and finish** — if federated metastore support is on the roadmap, these become
  `FederatedCatalog` implementations under [[TD-CAT-7]], where the narrower trait actually fits
  what an external metastore can honour.

Option 3 is the likely answer if federation is wanted, because the trait split reclassifies these
adapters from "impls that fake identity" to "impls with no identity obligation" — which is what
they honestly are.

== Do not

Do not gate or delete these on a "dead code" rationale without doing the reachability check above
first. The `test_create_glue_catalog_without_feature` test name suggests feature-gating was
considered once already; whatever was learned then is not recorded, which is part of why this
needs a decision rather than a sweep.
