== Problem

The v1 proto package is NOT generated: `build.rs` regenerates only the
self-contained `proximadb.v2` package, and `proximadb.v1.rs` is hand-maintained
(the comment in build.rs says this is deliberate, to protect hand-maintained
serde impls on v1 types). Nothing in CI compiles the v1 `.proto` files against
the Rust mirror:

* `make proto-check` = `cargo check -p proximadb-proto` + Python contract
  tests — it checks the mirror *compiles*, not that it *matches* the `.proto`.
* The descriptor-byte-equality drift gate pairs only protos that have
  committed generated stubs — v1 has none.

Consequence: a field added to a v1 `.proto` but not to the mirror decodes
(binary wire) to `None`/default silently; a field added to the mirror but not
the proto is dead code. Both directions are invisible to every gate.

== Live instance (found by the #1724 fresh-agent review)

`proto/proximadb/v1/catalog.proto` declares `OltpCatalogConfig oltp = 17` in
the `CatalogConfig` oneof (fields 10-16 + 17) — while the hand-maintained
mirror's oneof covers tags 10-16 only and has no `OltpCatalogConfig` struct at
all. A binary-wire catalog config carrying field 17 decodes to
`config: None` today. (The live REST ingest path is JSON/serde, where the
mirror's serde derives are the authority, so the practical blast radius is a
binary-gRPC future — but that is exactly the direction the v2 push is going.)

The same review also corrected a mechanism claim this family had been making:
removing an enum value does NOT make prost reject the value on binary decode
(the `catalog_type` field is a raw `i32`; unknown values pass through), and
reserving a oneof field does NOT error on decode (unknown tags are skipped and
retained). Rejection for the retired Hive arm happens at the JSON/serde
boundary (unknown-variant hard error) — comments in
`proximadb.v1.rs` now say so.

== Candidate fix (pick one, measure maintainability first)

1. **Round-trip conformance test**: a small test that, when `protoc` is
   available, parses `proto/proximadb/v1/*.proto` descriptors and asserts the
   mirror's `#[prost]` tags/field names per message match (mirror→proto
   direction catches invented fields; proto→mirror direction catches missing
   ones). Skipped gracefully when protoc is absent (mirrors the v2 regen
   gate's env pattern).
2. **Generate the structural half**: keep hand-maintained serde, but generate
   the prost structure from the `.proto` into a check-in file and diff it in
   CI against the mirror's prost-derive surface (heavier; only if (1)
   proves insufficient).

== Implementation (2026-09-02)

Candidate fix **1** landed — option 2 (generating the structural half) was not
needed: the source-scan approach proved sufficient and stays hand-maintained
alongside the mirrors it guards.

* **Guard**: `crates/foundation/proximadb-proto/src/proto/v1_conformance.rs`
  (`#[cfg(test)]`, runs under CI's unit-test job which installs
  `protobuf-compiler`; skips gracefully when `protoc` is absent). It compiles
  `proto/proximadb/v1/*.proto` + `proto/proximadb/explain.proto` with `protoc
  --include_imports`, decodes the `FileDescriptorSet`, parses ALL five v1
  mirrors (`proximadb.v1`, `.cluster.v1`, `.streaming.v1`, `.explain.v1`,
  `.v1.ranking`) for their `#[prost]` attributes / derives / enum discriminants
  / name tables, and compares both directions per message: field names, tags,
  kinds, cardinality, map-ness, oneof member tags, enum wire-name →
  discriminant maps. Unparseable mirror syntax is a fail-loud anomaly, never a
  silent skip. Wire-compatible leniencies (documented in the file): a proto
  oneof may be modeled as same-tagged plain fields; message/enum Rust-name
  renames (RbacAuditEvent vs RBACAuditEvent) are not wire drift.
* **Ratchet**: current findings are diffed against the checked-in ledger
  `src/proto/v1_conformance_known_drift.json` — new drift fails, fixed drift
  fails until the ledger is shrunk (regen:
  `UPDATE_V1_DRIFT_SNAPSHOT=1 cargo test -p proximadb-proto --lib
  v1_conformance`). The ledger doubles as the burn-down backlog.
* **Live instances fixed in the same change**:
  ** `OltpCatalogConfig` message + `CatalogConfig` oneof arm `oltp = 17` +
    `CatalogType::{OltpPostgres,OltpMysql,OltpSqlite}` (10/11/12) — the filed
    instance. The REST construction arm declines loudly (TD-CAT-10 retirement)
    instead of constructing: the wire shape exists so binary configs decode
    losslessly, not to resurrect the adapter.
  ** `SqlValue` oneof arm `jsonb_value = 9` (bytes) + the custom serde
    (`serde_impls.rs`) round-trip + the ~20 exhaustive-match fan-out sites,
    each extending its local `BytesValue` convention.
* **First-run census**: the guard found 49 pre-existing findings; 8 were fixed
  above and 41 remain in the ledger — mostly whole messages/enums that were
  never mirrored (security.proto's Byo*/MtlsCert, Pulsar*/Quasar* experimental
  engine surfaces, several List*Request types), 6 mirror-only messages
  (`assemble_context/document_*` — used by the REST surface, absent from the
  protos), `CollectionConfig.embedding_config` (tag 25), a
  `permitted_principals` kind disagreement (mirror `message` vs proto
  `string`), and `DocumentCollectionConfig.use_jsonb` (tag 8). Fixing each is a
  small, individually-reviewable follow-up; the ledger entry list is the work
  list and the count only goes down.
* The guard caught a variant-name typo (`Polar` vs `Polaris`) introduced in
  this very PR before review did — the class of mistake it exists for.

A fresh-context adversarial review (2026-09-02) hardened the change; its
findings and dispositions:

* **The ledger must be `git add -f`-tracked**: `.gitignore`'s `*.json` silently
  swallowed it (now a negation beside the other ratchet baselines). Untracked,
  the guard would have panicked on every fresh checkout — CI included.
* **Map kinds now compared for real**: the descriptor's synthetic map-entry
  message supplies the key/value kinds (the first cut hardcoded string keys and
  never compared values).
* **Enum name tables validated independently**: `as_str_name` and
  `from_str_name` are each checked against the descriptor and cross-checked
  against each other, so a corrupted serialize table can no longer hide behind
  a correct decode table.
* **`jsonb_value` handling canonicalized**: every ProximaValue-producing site
  decodes tag-9 bytes with the canonical MessagePack codec
  (`ProximaValue::from_jsonb_slice`, the v2 canon), with Binary fallback — the
  AQL sources follow their local JSON heuristic (matching their BytesValue
  arms) instead of silently nulling via the `_` wildcard; the Python SDK's
  `_convert_from_sql_value` gained the `jsonb_value` arm instead of silently
  returning `None`.
* **serde `jsonb_value` key no longer hijacks the generic-object fallback**:
  the branch commits only when the base64 payload decodes; otherwise the
  pre-existing MVP-friendly generic-object path applies.
* **protoc probe moved before any filesystem access**, so the graceful skip
  holds even without the repo tree; string literals and trailing comments are
  masked in the tokenizer's brace counting so `format!("{…}")`-style lines
  cannot desync it.
* **Round-trip gate extended** (`tests/sql_value_roundtrip.rs`): JsonbValue
  now covered on both the binary (prost) and REST (custom serde, `jsonb_value`
  base64 key pinned) paths — the format-change gate mandate #8 requires.

Known divergence deliberately left to the backlog: the JSONB *stringifying*
surfaces (REST row builders, Arrow/observability stringifiers) each follow
their local BytesValue convention (hex / per-byte arrays / placeholders); see
the ledger + follow-ups.

== Not in scope

The v2 package already has both generation (`PROXIMADB_PROTO_REGEN=1`) and the
descriptor drift gate; TD-PROTO-1 (Python stub drift) is the stub-side analog.
