== Why (and why deferred)

`Churn` reads Strong-merge the unflushed WAL/memtable delta (TD-WLP-5). That delta is already
**hard-bounded to ~2 MB per collection** (`MemtableConfig::flush_threshold_bytes`, default ~2 MB)
by the backpressure check in `wal_behavior.rs` (`current_usage >= threshold`). A brute-force merge
over ≤2 MB (≈ a few thousand vectors) is sub-millisecond — dwarfed by the ANN search itself. So a
`Churn`-*specific* tighter flush threshold (flush sooner so the delta is even smaller) buys, at
most, a sub-2 MB reduction of an already-cheap scan.

Against that marginal gain, the cost is real: the live flush trigger is **not profile-parameterized**
and is spread across three write-path serialization strategies (proto/avro/bincode), while the one
shared chokepoint (`wal_behavior.rs`) is *backpressure that rejects writes*, not a proactive flush.
A per-`Churn` override therefore means threading profile-awareness through the hot write path in all
three strategies — non-trivial risk for a marginal gain. Per the co-design **measure-don't-assert**
mandate, this is deferred, not built.

== Trigger to un-defer

A measured `Churn` per-query trace (bytes/latency, per the co-design tracing mandate) showing the
~2 MB Strong-merge delta is a material fraction of read latency **or** that freshness lag from the
flush cadence matters for the agent code-RAG loop. Absent that evidence, leave the shared bound.

== Sketch (if un-deferred)

* `storage_profile.rs`: `churn_flush_size_bytes()` reading `PROXIMADB_CHURN_FLUSH_MB` (unset ⇒ the
  shared default), mirroring `churn_working_set_ceiling_bytes()` (TD-WLP-8a).
* Resolve the effective per-collection flush threshold from the profile at the write path (which
  already holds `collection.config`/tags) and apply it at the proto (default) strategy's flush
  trigger — proto first; avro/bincode only if those strategies are in use.
* TDD: a `Churn`-tagged collection flushes at the tighter threshold; `AppendBulk` unchanged
  (asserted); WAL stays authority; reads stay correct across the flush.

== Gating

Opt-in `workload_profile:churn` + `PROXIMADB_CHURN_FLUSH_MB`. `AppendBulk` untouched. WAL is the
sole durable authority (ADR-061 D2).
