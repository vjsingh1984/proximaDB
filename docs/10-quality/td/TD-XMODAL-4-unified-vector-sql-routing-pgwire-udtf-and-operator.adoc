== Finding (the pieces exist — unify + route them, don't rebuild)

A pgwire/UDTF audit found the building blocks already present but **disconnected**:

* **The `vector_search(collection, query, k)` UDTF is live-backed and pgwire-reachable** — `VectorSearchTableFunction` → `VectorSearchTableProvider` carries a `VectorSearchExpr` and complete request identity to `VectorOpsPort::unified_search_native`; the pgwire DataFusion context registers the same function.
* **Before the 2026-08-15 slice, pgvector `<->`/`<=>`/`<#>` worked over pgwire via a hardcoded bypass**: regex-extract the vector literal + `LIMIT`, then call `unified_search_native()`. It skipped the relational pipeline and router — no typed plan, cost, or shape. That bypass is now deleted; router integration remains open.
* **Before the 2026-08-17 slice, the router had no vector access-path decision** — `QueryShape` described only the containing relational plan and `route_select_inner` selected only its `ComputeBackend`. The first draft proposed adding a vector boolean to that shape; implementation review rejected it because a `vector_search(...)` source can be nested inside a DataFusion join. Operator access-method selection and whole-plan engine selection are orthogonal axes.

The two SQL spellings now share one typed intent and runtime port. The scheduler observes explicit exact/approximate/adaptive intent and learns separate exact/ANN access-path cells from attributable executions. A bounded paired gate now makes those paths comparable at identical geometry, but live geometry-driven selection remains open until storage class and cache state prevent unlike deployments from poisoning one cell.

== Design: one canonical `VectorSearch` node

The load-bearing decision: **both syntaxes lower to the *same* logical node**, so the router costs one thing and the executor runs one thing.

[source]
----
VectorSearchExpr { collection, vector_column?, query_vector, top_k, threshold?,
                   metric, filter?, params(mode/ef_search/n_probes) }
----

* **UDTF** `SELECT * FROM vector_search('col', $q, 10)` → this node (reuse `VectorSearchTableFunction`).
* **pgvector operator** `SELECT id, … FROM col ORDER BY embedding <-> $q LIMIT 10` → the relational lowering pattern-matches `ORDER BY <distance> LIMIT k` (`<->`→L2, `<=>`→Cosine, `<#>`→neg-dot) → the **same** node (replacing the hardcoded bypass).
* **Result shape (decided):** ordinary SQL projection governs the output. `SELECT id` returns `id`; `SELECT id, payload` returns those two columns; a projected distance expression returns its alias; `SELECT *` expands to `id + distance + metadata`. `distance` is the operator value (L2, cosine distance, or negative inner product), never the normalized similarity score. `include_vectors` stays an opt-in arg.
* **Router:** the existing `ComputeScheduler` owns a sibling `VectorQueryShape` / `VectorRouteDecision` access-path method. The containing SQL plan still routes through `QueryShape` → one `ComputeBackend`; each vector source independently selects exact/approximate/adaptive inside the specialized native vector backend. This preserves cross-modal joins while keeping one policy owner. The decision will **cost-choose within** vector execution (exact brute-force vs RaBitQ ANN cascade; whole-vs-striped; centroid-prune `nprobe`) from comparable measured trace/geometry cells — this is where the RDSTRAT-4/5 knobs plug in.
* **REST SQL/UQL convergence:** the REST `/api/v2/query` SQL/UQL path routes through the **same** parse→lower→route seam (no parallel code path), so all surfaces share one definition of "what a vector search means" (`vertical inside, standard outside`).

== Reuse (do NOT duplicate)

`VectorSearchTableFunction` / `VectorSearchTableProvider` (`cross_modal.rs`), `register_udtf` (`datafusion/mod.rs`), `VectorOpsPort::unified_search_native`, `SstEngine::search_vectors_unified`, and the `ComputeScheduler`/`route_cost_model`/`QueryShape` router already exist — S1–S4 wire them behind one node, they do not rebuild them. Distance-metric mapping follows pgvector semantics for ecosystem compatibility.

== Implemented clean-break slice (2026-08-16)

The current implementation establishes one trustworthy boundary before adding router policy:

* deleted `protocol.rs::execute_vector_search` and the translator's regex operator rewrite;
* added PostgreSQL-AST lowering for `<->`, `<=>`, and `<#>`, including typed filters, positive `LIMIT`, and SQL projection; unsupported shapes fail with `0A000` rather than falling through or widening a filter;
* made vector dispatch AST-only: operator-looking text in literals/comments remains on the ordinary relational path, and oversized `LIMIT` values fail rather than truncating into the canonical `u32 top_k`;
* made extended-protocol `Describe` reuse the same projection lowerer as `Execute`;
* extended the existing `VectorSearchExpr` instead of adding a pgwire-only public plan: it now carries a named vector column and typed filter, and both pgvector lowering and the UDTF construct it. Shared validation rejects empty/non-finite vectors, zero top-k, and invalid thresholds. The UQL/multimodel executor now forwards metric/filter, applies its similarity threshold, and rejects unsupported non-default per-query tuning instead of silently dropping it;
* extended `VectorOpsPort::unified_search_native` with the requested metric and complete `PortIdentity`; its default implementation now errors instead of returning a false empty success. The canonical multimodel executor likewise propagates missing-service and backend failures, preserving the semantic distinction between "not executed" and a successful zero-match result;
* included metric in query-cache identity and threaded it through planner, WAL, storage, and delta merge;
* made `SearchMode::Exact` and metric/index incompatibility bypass AXIS, then enriched the bounded result set with metric-tagged semantic distances when an engine returned only a normalized score;
* established a single source-of-truth rule for SQL tables: pgvector search reads the catalog table's `TableRecordStore`, with tenant/ABAC enforcement and the typed predicate evaluated at that boundary. It never treats an empty legacy vector-WAL result as evidence that a SQL table is empty. Exact table scan is the correctness floor; an ANN/PAX structure may accelerate it only as a rebuildable projection of that same primary;
* bounded exact ranking to `O(top_k)` retained candidates with cooperative cancellation checks, no result-vector copies, projection-late metadata materialization, full composite-primary-key identity, named multi-vector-column selection, dimension validation, and route timing/cardinality telemetry. The current record-store API still materializes the filtered authority scan itself, so scan memory remains `O(matches)` until a streaming scan contract lands;
* preserved JSON/JSONB container paths (`payload.type`) through AST lowering and filter evaluation instead of flattening them into an ambiguous global metadata namespace;
* hardened the pgwire integration fixtures: metadata/catalog state is temp-directory scoped, setup errors are fatal, and both filtered and unfiltered searches assert exact non-empty ID sets. These gates exposed the previously false-green split-store behavior.

That S1 snapshot did **not** close TD-XMODAL-4: the UDTF and operator converged on the explicit `VectorSearchExpr` node and one native port, but had no vector access-path decision. Exact ranking was bounded; the underlying authoritative record scan was not streaming. The next section records the subsequent router-contract increment; cross-surface parity, full route-level I/O traces, projection freshness/rebuild tests, and measured geometry-driven exact/ANN selection remain acceptance gates for S2/S3.

== Implemented router-contract slice (2026-08-17)

The first S2 increment closes the policy-loss boundary without claiming an unmeasured route flip:

* added `ComputeScheduler::route_vector_search(VectorQueryShape)` returning an observable, typed `VectorRouteDecision` for exact/approximate/adaptive access inside `ComputeBackend::Native`; the relational `QueryShape` and its backend decisions are unchanged by construction;
* kept absent intent on the existing exact correctness floor. Approximate/adaptive access requires explicit typed intent until exact-vs-ANN cost observations are comparable and the recall ratchet admits a default change;
* replaced `VectorSearchParams { mode: String, ef_search, n_probes }` with the canonical typed `SearchMode`. The former shape accepted index-family-specific knobs before choosing an index family, and the runtime port dropped all three. `Approximate { nprobe }` is now one value that reaches storage unchanged; invalid zero ANN effort/adaptive cutoffs are rejected at shared validation;
* changed `VectorOpsPort::unified_search_native` to accept the complete `VectorSearchExpr` rather than six independently threaded arguments. Both pgvector lowering and the DataFusion UDTF now cross the same intent boundary, making field omission reviewable at one seam; shared validation and similarity-threshold semantics live on that expression;
* routed the production port and multimodel executor through the same scheduler decision and removed the hard-coded `SearchMode::Exact` overwrite for explicit caller intent.

This is deliberately **observe/static**, not a claimed completion of cost selection. The current route cost model ranks whole-plan `ComputeBackend` candidates and its one trace route slot cannot honestly compare nested vector access methods. The next S2 increment must add a distinct access-path trace dimension and warm comparable `(vector shape, exact|ANN)` cells before any default or live override can flip. Reusing the backend label for ANN would poison the existing engine cells; adding arbitrary dimension/top-k buckets before trace-density evidence would repeat ADR-058's warned failure mode.

== Implemented measured-access slice (2026-08-19)

The second S2 increment adds the evidence substrate without enabling an automatic route flip:

* added a repeated, typed `vector_accesses[]` dimension to `IoTraceSnapshot`, separate from the single containing-compute route. Each successful access retains physical engine, exact numeric dimensions/top-k, filter presence, requested mode, and the actual exact/ANN path; no vector, predicate, collection name, or user data is captured;
* projected those samples into normalized `trace_vector_access` warehouse rows keyed by the existing writer/sequence/query identity and access ordinal. Multi-vector SQL therefore remains queryable instead of being overwritten by a last-write-wins slot;
* reused the existing `RouteCostModel` EWMA/persistence store for `(vector engine + exact geometry, actual path)` cells. Exact dimensions/top-k are not Prometheus labels and are not forced into unmeasured buckets. Caller intent remains durable evidence but is intentionally not part of the cost key, because partitioning by intent would make exact-vs-ANN comparison impossible;
* made online attribution fail closed: only a trace with exactly one vector access can fold aggregate query I/O/compute into a cost cell. Multi-access traces stay durable but do not train the model until operator-local cost accounting exists;
* record ANN only after positive physical engagement proof (non-empty AXIS result, PAX cascade result, or file-centroid pruning). An Approximate/Adaptive request that falls back without such proof does not poison the ANN cell. Exact is recorded only after successful exact execution;
* rebind the owning `IoTrace` handle across SST's per-file `tokio::spawn` boundary, so multi-core PAX I/O and ANN engagement contribute to the same query sample instead of disappearing with the task-local context;
* fixed an exactness defect exposed by that attribution audit: `execute_exact_segment_scan` previously set only `block_prune.force_exact`, leaving Adaptive file pruning enabled, while every direct-scan implementation attempted the RaBitQ cascade before consulting that flag. The effective mode is now forced to `Exact`, and one shared cascade gate makes `force_exact` dominate sequential and multi-core PAX scans.

This snapshot remained observe-only. The scheduler's absent-intent default stayed Exact, persisted vector cells were not admitted to the whole-plan backend recommendation table, and no gate could flip vector access automatically. The next section records the paired-evidence increment and the correctness defects it exposed.

== Paired evidence and exact-authority correction (2026-08-21)

The third S2 increment attempted the required same-query exact/ANN comparison and
invalidated two earlier assumptions before admitting any live policy:

* Whole-object reads were absent from exact-path traces: ranged leaf reads were
  always attributed, while local full reads bypassed the filesystem port and
  full reads elsewhere depended on the optional counting wrapper. Physical leaf
  reads now own task-local attribution, and the staged object reader uses the
  port for local and remote URLs. The cost model prices total `get_ops`, not only
  `range_gets`; persisted cost cells use schema version 2 and relearn rather than
  interpreting version-1 range counts as total round trips.
* The first 100K paired run proved that exhaustive ranking of RaBitQ/SQ8 values
  is not `SearchMode::Exact`: one query returned only 9/10 brute-force neighbors.
  Explicit Exact now requires authoritative raw-f32 values in every PAX segment
  and fails with an actionable error otherwise. Exact per-file failures also
  propagate in serial and parallel scans instead of being warned away and
  returned as a partial success; approximate scans retain best-effort behavior.
* Coalesced PAX exposed a second authority bug: the footer and block-local exact
  tier existed, but canonical record materialization looked for it only while an
  `EMBED_BASE` stripe existed. Coalesced blocks intentionally omit that base, so
  SQ8 Region B was appended and ranked. The shared `FlatRow` materializer now
  discovers base or exact stripes, prefers raw f32, and uses SQ8 only for rows
  without an authoritative vector. The round-trip gate requires bit-exact values,
  not merely a non-empty embedding.

The bounded SIFT cohort alternates path order, uses explicit `Exact` and
`Approximate` intent, requires exactly one attributable vector access per query,
checks Exact top-10 set equality against brute force, retains the ANN recall
ratchet, and reports performance without making latency a flaky assertion. At
`N=100,000`, `dim=128`, `top_k=10`, three query pairs measured:

[cols="1,2,2", options="header"]
|===
| Measure | Exact raw-f32 scan | PAX ANN cascade
| Correctness | 10/10 oracle set on every query | recall@10 = 0.9667
| Latency p50 / p95 | 1,084,196 / 1,084,196 us | 61,269 / 61,269 us
| Physical GETs per query | 5.00 (whole reads) | 28.33 (ranged reads)
| Bytes per query | 77,192,428 | 35,642,387
| Attributed compute per query | 1,078.33 ms | 71.00 ms
|===

This evidence does **not** admit an automatic route flip. Local latency and
compute strongly favor ANN, total bytes also favor ANN, but object-store RTT
pricing favors the five whole GETs over roughly 28 ranged GETs. The current
vector cell key contains geometry and path but not storage class or cache state;
combining local/warm and remote/cold samples would train contradictory policies
into one cell. The next admission slice must add those dimensions (or an
equivalent deployment-scoped model boundary), require a minimum paired cohort,
and keep recall/correctness as hard gates. No new env gate or parallel router is
introduced here, and the default remains unchanged.

== Execution-regime evidence correction (2026-08-22)

The next measurement broke the initial cache-state implementation before any
route flip was enabled:

* Storage locality is derived from the storage URL actually used by the
  completed SST access (`local`, `remote`, or fail-closed `unknown`). It is not
  called an access tier: `ObjectAccessTier` is write-side policy metadata and is
  not observable on this read boundary. Claiming hot/cool/cold here would invent
  evidence.
* A feature-on SIFT run returned zero physical GETs for later ANN queries but no
  footer/L2 hits, so the first classifier reported `unknown`. The bytes had been
  served by the DRAM survivor-range cache, whose aggregate Prometheus counters
  were never represented in the query-local `IoTrace`. The cache foundation now
  returns the serving outcome (`MemoryHit`, `PersistentHit`, or `Loaded`); the
  SST wrapper records exactly one logical `survivor_l1_hits/misses` outcome per
  requested range. Exact-key and parent-key probes are implementation detail and
  cannot inflate the logical count.
* Cache regime uses physical I/O as authority: no GET plus any hit is `warm`; a
  GET plus a hit is `mixed`; a GET plus misses and no hits is `cold`; an
  instrumented GET with no cache consultation is `bypass`; insufficient evidence
  is `unknown`. `unknown` is durable for diagnosis but cannot enter an admission
  cohort. The CI ratchet therefore builds with `io-trace`; the feature-off
  negative control fails closed rather than silently treating missing counters
  as bypass.
* The paired exact/ANN gate uses an explicitly cache-free engine instance. Exact
  does not consult the survivor cache, so comparing it with warmed ANN would
  repeat the original pooled-regime defect. Cache benefit remains measured by
  the separate coalesced warm-tier test.
* The persisted JSON structure remains schema version 2. Only the vector shape
  key gained `storage` and `cache` dimensions; old keys cannot collide with the
  new identity, and this behavior has not shipped. Bumping the whole file would
  discard unrelated relational learning without a format change.

The controlled `N=1,000`, three-query validation then admitted all three pairs
into one `storage=local/cache=bypass` cohort. Exact matched the brute-force
top-10 set for every query, ANN recall@10 was 1.0, and the observed p50 values
were 1,516 us exact versus 531 us ANN. This is a wiring/correctness validation,
not representative performance evidence; the existing `N=100,000` cohort and
future remote/cold and warm cohorts remain the decision-grade measurements.

=== Decision-grade local/bypass replication (2026-08-23)

The regime-aware harness was then run three times from fresh test processes at
`N=100,000`, `dim=128`, `top_k=10`, with 30 paired queries per run. Because the
subset has no matching provided ground-truth file, every query's oracle was
brute-forced over the same 100,000 raw SIFT vectors. All 90 exact arms matched
the oracle top-10 set; all three ANN runs measured recall@10 = 0.9867 and
admitted all 30 pairs into the same
`vector/engine=sst/dim=128/k=10/filter=no/storage=local/cache=bypass` cohort.

[cols="1,2,2", options="header"]
|===
| Measure | Exact raw-f32 scan | PAX ANN cascade
| Latency p50 range across three runs | 179,833--199,654 us | 14,342--15,186 us
| Latency p95 range across three runs | 189,525--251,811 us | 15,701--20,053 us
| Physical GETs per query | 5.00 whole reads | 45.43 ranged reads
| Bytes per query | 77,192,428 | 58,901,320
| Attributed compute per query range | 177.73--210.70 ms | 13.47--15.83 ms
|===

This replicated local result makes ANN's compute advantage durable rather than
a three-query timing anecdote, but it also sharpens why automatic selection is
still closed. ANN saves about 24% of bytes while issuing about 9.1x as many
physical requests; a local bypass cohort cannot price remote request latency or
prove a route-time cache state. The older three-query and new 30-query I/O
counts also differ materially (28.33 versus 45.43 ANN GETs/query), so neither
sample may be generalized across query distributions. A paired remote/cold
cohort and an independently observable starting-cache regime remain admission
requirements.

This slice still does not authorize automatic exact/ANN selection. Cache outcome
is completed-execution evidence, not a route-time promise. A live decision needs
an independently observable starting regime or an admission policy whose
deployment scope guarantees it, plus paired remote/cold and warm measurements.

== Constraints

* **No new DSL** (ADR-053): SQL + table functions only.
* **Surface parity is the gate**: the same vector query on any surface (pgwire UDTF, pgwire operator, REST-SQL, UQL, gRPC) must return identical results — the whole point of the unification.
* **Default-safe**: the new lowering must not change relational routing; a query that isn't a vector search falls through unchanged (mixed-read-safe, like today's `try_run_select` returning `None`).
* **Recall is unaffected by surface** — all paths route to the same engine; the RDSTRAT recall gates (TD-RDSTRAT-5) still govern the *execution* knobs the router selects.
