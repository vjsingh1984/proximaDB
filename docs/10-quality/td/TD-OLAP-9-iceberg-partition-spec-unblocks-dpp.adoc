== Why

The TD-OLAP-3 rollout lists Dynamic Partition Pruning as item 2: defer fact-scan partition
selection until the dimension filter's runtime values are known, then prune partitions from the
Iceberg manifest list at runtime. This is the single cheapest runtime filter in a warehouse
engine — it avoids even opening the footers of skipped partitions.

It is **blocked today** because ProximaDB writes Iceberg tables *unpartitioned*:

* `crates/storage/proximadb-iceberg-engine/src/iceberg.rs:18` — "Tables are written
  **unpartitioned** for the first cut (partition spec id 0, empty struct)".
* The manifest Avro schema and `manifest_entry` are written with `partition_spec_id: 0` and an
  empty partition struct (same file, ~lines 30/127/141/203/286).

With an empty partition spec there is no partition list to prune — DPP has nothing to bind the
dimension filter's runtime values against. So DPP must wait on a real partition spec landing
first; this TD tracks that prerequisite and the DPP slice it unblocks.

== Rollout (sketch; details on picking up)

. **Partition spec on write:** extend the materializer / iceberg-engine write path to declare a
  partition spec (identity or transform — e.g. `date_dim` day, or a fact date/key column) and
  route rows to per-partition Parquet objects under the existing `DrPathBuilder` prefix. Keep it
  **mixed-read-safe** (spec id in the manifest; readers default to unpartitioned when spec id 0),
  default-OFF per-table until baked (mandate #8).
. **Manifest partition bounds:** populate per-`data_file` partition-value bounds in the manifest
  entry so the read leaf can prune manifests/files by partition predicate.
. **Runtime bind (DPP proper):** at HashJoin build, capture the dimension filter's realized key
  set and prune the fact partition list from the manifest before scheduling any row-group read —
  reusing the same build-side key material the bloom semi-join already captures.
. **Trace + promotion:** record `partitions_total`/`partitions_pruned` alongside the existing
  `splits_total`/`splits_pruned` io_trace counters; promote per the TD-OLAP-4 ledger skip ratio.

== Verification

* A partitioned TPC-DS `store_sales` (partitioned by `ss_sold_date_sk` or a date transform) shows
  a measured *partition*-level skip (manifests/files not opened) on a date-dimension-filtered
  star query, in the TD-OLAP-4 ledger, conformance unchanged.
* Unpartitioned tables (spec id 0) continue to read exactly as today (mixed-read-safe).
