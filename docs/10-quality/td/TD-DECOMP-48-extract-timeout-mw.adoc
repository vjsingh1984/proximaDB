= TD-DECOMP-48: Move timeout middleware into existing proximadb-network-middleware crate

[cols="1,3", options="header"]
|===
| Field | Value
| Status | Landing
| Severity | Low — behavior-neutral re-export (+1 tower-http feature)
| Component | `crates/platform/proximadb-network-middleware`; root `src/network/middleware/mod.rs`
|===

== What moved
`src/network/middleware/timeout.rs` (6 tests: `TimeoutConfig` + `create_timeout_layer` request-
timeout enforcement) → the EXISTING platform crate `proximadb-network-middleware` (TD-DECOMP-22),
joining `cors` + `rate_limit`. Root `network/middleware/mod.rs` re-exports it
(`pub use proximadb_network_middleware::timeout;`), so the existing
`pub use timeout::{TimeoutConfig, create_timeout_layer};` resolves unchanged.

== Why into an existing crate
All of timeout.rs's deps (axum / serde / tower-http / tracing) are already declared by
`proximadb-network-middleware` — so this needs NO new crate, NO root `Cargo.toml` workspace-member
or `[dependencies]` wiring (which also avoids the stacked-PR Cargo.toml conflict). The one change:
add the `timeout` feature to the crate-local `tower-http` dep
(`tower-http = { workspace = true, features = ["timeout"] }`) — the workspace default only enables
`cors`/`trace`. Verified: standalone + clippy -D warnings + root lib all pass. SIFT recall ratchet
SKIPS (network/** is not storage_changes).
