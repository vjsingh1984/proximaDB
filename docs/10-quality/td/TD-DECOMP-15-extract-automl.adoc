== Why

`src/automl/` is a cohesive subsystem (automated tuning, prediction, workload analysis,
**89 tests**) with only one climb-out: `service.rs` (0 tests) → `crate::metrics` (control-tier
types). The solution: move the 4 clean files + the mod.rs tests to a new `proximadb-automl`
crate (horizontal tier); keep `service.rs` at root; move `AutoMLConfig` (a pure config struct)
to the crate so optimization.rs can reference it.

== What moved (behavior-neutral)

* New `crates/horizontal/proximadb-automl/` (Cargo.toml + lib.rs).
* Moved: `prediction.rs` (31t), `tuning.rs` (51t), `workload.rs` (2t), `optimization.rs` (1t)
  + mod.rs test block (4t) = **89 tests**.
* `AutoMLConfig` struct + `Default` impl moved from `service.rs` → crate `lib.rs`; root
  `service.rs` now re-exports it (`pub use proximadb_automl::AutoMLConfig;`).
* `optimization.rs`: `super::service::AutoMLConfig` → `crate::AutoMLConfig`.
* Root `src/automl/mod.rs`: re-exports from crate + keeps `pub mod service;`.
* Deps: anyhow, chrono, rand, serde, serde_json, tokio, tracing (all workspace).

== Verification

* `cargo check -p proximadb` + `check_workspace_boundaries` + `check-layering` + server
build + automl-clippy + fmt + work-commit-check green.
