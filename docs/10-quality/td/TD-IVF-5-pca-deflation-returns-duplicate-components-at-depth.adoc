= TD-IVF-5: PCA deflation returns duplicate components at depth, bounding how far the projection width can be pushed
:status: Open
:dim: D1
:pillar: PERF

[cols="1,3", options="header"]
|===
| Field | Value
| Status | **Open — reproduced on a real corpus (128-d BIGANN) and by executing unit tests. Onset is far deeper than first estimated, so it does NOT bound the width the system wants.**
| Priority | **P3 — latent.** No live defect: the shipped width is 10–14, and the measured onset on real corpora is component 111 at worst. | Component | `crates/storage/proximadb-engine-core/src/proximablocks/spatial_clustering.rs` — `IncrementalPCA::finalize`, `power_iteration`, `deflate_matrix`. Guarded by `deep_component_conditioning_tests` in the same file.
| Evidence | Our extractor re-fit on the **real** corpora (20k sampled rows each: 128-d BIGANN, 384-d BGE, 768-d BGE) plus four deterministic synthetic spectra (dim=96, 4000 rows). Reproduced in-tree.
|===

== The defect

`IncrementalPCA::finalize` extracts components one at a time: `power_iteration`
finds the dominant eigenvector of the residual covariance, then `deflate_matrix`
subtracts `λvvᵀ` and the loop repeats. Two properties combine badly:

. `power_iteration` always starts from **the same fixed seed vector**
  (`(i+1).sin()`), and runs a fixed 20 iterations.
. Deflation is done in floating point with no re-orthogonalisation against the
  components already extracted, so residue accumulates along directions that were
  supposedly removed.

Past a spectrum-dependent depth the residual matrix is small enough that the
accumulated residue dominates it. Power iteration then converges to a direction
**already extracted**, and — because the seed never varies — does so repeatedly.

Measured onset. **Real corpora first** — our `IncrementalPCA`, 20,000 sampled
rows each, extracted to width 128:

[cols="1,1,1", options="header"]
|===
| corpus | worst \|dot\| within 32 | first near-duplicate
| 128-d BIGANN | 0.110 | components **(2, 111)**, \|dot\| 0.964
| 384-d BGE | 0.080 | none within 128
| 768-d BGE | 0.062 | none within 128
|===

And on deterministic synthetic spectra, `dim=96`:

[cols="1,1,1", options="header"]
|===
| spectrum | first near-duplicate pair | \|dot\|
| `0.90^j` (fast geometric) | components **(2, 42)** | 0.994
| `0.95^j` | components **(2, 59)** | 0.987
| `0.97^j` (mild) | none within 96 | —
| `1/sqrt(j+1)` (power law) | none within 96 | —
|===

[IMPORTANT]
====
**The synthetic spectra badly overstate the risk.** An initial reading of the
`0.90^j` result (onset at 42) was used to cap the TD-IVF-3 projection-width floor
at 32. Re-fitting on the actual corpora refuted that: the worst real case first
duplicates at component **111**, and two of three corpora show no duplicate at all
within 128. No real embedding spectrum measured decays anything like `0.90^j`.

The ceiling was therefore set back to the measured optimum of **64**, which
carries margin on every corpus this system has been measured against. The
conditioning bound is real but **corpus-dependent**, not a universal cap.
====

Note *which* component is duplicated: **component 2**, an early, high-variance
direction — not noise. That is the harmful case. A duplicated direction is
counted twice in the projected distance that ranks coarse cells, so the metric is
skewed toward whatever that direction encodes. It also consumes a coordinate in
every centroid comparison and `n_comp·dim + k_c·n_comp` f32s of A0 for no
information.

== Why nothing caught it

Recall cannot see it. The coarse projection only *selects cells*; survivors are
re-ranked by the SQ8 tier and then exactly. A skewed cell ranking costs extra
probes at the recall floor — it does not produce wrong results — so it surfaces as
a slightly worse GET/query curve, indistinguishable from ordinary geometry
variation. The entire 26-bed width study ran at widths where this never triggered
(the deepest production width is 14) except at the sweep's own `n_comp=128`
points, where it would have been present and unattributed.

This was initially proposed as an explanation for the one anomaly in the TD-IVF-3
table — width 64 was optimal at 384-d and 768-d but *lost* to 32 at 128-d. The
real-corpus measurement **weakens that**: 128-d BIGANN does condition worst of the
three (worst |dot| 0.110 within the first 32 components, against 0.080 and 0.062),
which is consistent with faster spectral decay, but its first true duplicate is at
component 111 — far beyond the widths where 64 lost to 32. Some milder
conditioning effect may still contribute; outright duplication does not. The
anomaly remains unexplained.

== Effect on TD-IVF-3

None, at the width TD-IVF-3 wants. `IVF_NCOMP_FLOOR_CEILING` ships at the measured
optimum of **64**: real-corpus onset is 111 at worst, so 64 has margin.

What this TD does contribute is a **bound on how far the floor could ever be
raised**, and a standing requirement: pushing the width materially past 64 — or
onto a corpus whose spectrum decays much faster than those measured — requires
re-running the conditioning check for that corpus first. The check is cheap and
needs no server, no object store and no bed: re-fit `IncrementalPCA` on the raw
corpus file and compute pairwise component dot products.

== Proposed resolution

. **Re-orthogonalise each new component** against all previously extracted ones
  (modified Gram-Schmidt) immediately after `power_iteration` returns, before
  deflation. This is the standard fix and is `O(n_comp·dim)` per component —
  negligible beside the `22·dim²·n_comp` the extraction already costs.
. **Stop early when the residual eigenvalue collapses.** If the Rayleigh quotient
  falls below a small fraction of the leading eigenvalue, the remaining
  directions carry no usable signal; returning fewer components is strictly
  better than returning duplicates, and the width is already self-describing
  per segment (A0 stores `n_comp`), so a short model is legal on the read path.
. **Vary the power-iteration seed per component** so a degenerate residual cannot
  funnel every component to the same vector. Cheapest of the three, and the least
  complete — do it in addition to (1), not instead.
. Then delete `deflation_degenerates_on_an_adversarially_fast_spectrum` (it
  exists to make this TD executable and should fail once fixed) and re-evaluate
  whether `IVF_NCOMP_FLOOR_CEILING` can rise above 64 — which is a question for
  TD-IVF-3's measurement, not for this one.

Any of these changes what gets written into A0, so it is a write-path change:
mixed-read-safe by construction (the width and components are persisted per
segment), but it must be measured against the recall baseline before the ceiling
moves.

== What is NOT established

* **Three corpora is not all corpora.** Onset is spectrum-dependent and only
  BIGANN and two BGE corpora were checked. A corpus with faster spectral decay
  would breach 64; nothing detects that automatically today.
* The probe sampled **20,000 rows**; production trains on up to 200,000. More
  samples give a better-conditioned covariance, so the real onset is plausibly
  *deeper* still — but that was not measured.
* Whether the mild non-orthogonality present at all depths (|dot| ≈ 0.02–0.11,
  from 20 fixed power iterations) costs anything. It is assumed benign; nothing
  measures it. Note 128-d BIGANN is the worst of the three here (0.110 vs 0.080
  and 0.062), consistent with its faster decay.
* Whether the 128-d anomaly in TD-IVF-3 is actually this. The mechanism now looks
  **less likely** than when first proposed: 128-d does condition worst of the
  three, but its first true duplicate is at 111, far beyond the widths where 64
  lost to 32. Recorded as weakened, not confirmed.
