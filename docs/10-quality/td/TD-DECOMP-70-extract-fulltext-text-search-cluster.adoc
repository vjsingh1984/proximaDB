| Field | Value

== What moved
Phase 3 Step 2 — the fulltext hub-and-dependents cluster (~4.4K LOC, 51 tests) into the
EXISTING storage crate `proximadb-storage-common`, as a new `text_search` module:

* `formats/columnar/fulltext_index.rs` (1,660 LOC, 12 tests) — the HUB: BM25 inverted index,
  tokenizer, posting lists. Zero `crate::` refs, deps `std::collections` + `thiserror` only.
* `formats/columnar/text_storage.rs` (1,818 LOC) — TEXT column storage strategies, chunker,
  reader/writer. 2 crate:: refs, both intra-cluster.
* `formats/columnar/text_storage_tests.rs` (749 LOC, 39 tests) — `#[path]`-included test module.
* `storage/document/sdp.rs` (200 LOC) — SDP chunking (SdpConfig/SdpChunk/SdpChunker), hermetic.

Carry-along: the `TextStorageStrategy` enum (+ `for_size`, size consts) moved from root
`core/types/mod.rs` into `text_search/mod.rs` — storage cannot depend upward on root types.

== Shims (behavior-neutral)
* `columnar/mod.rs`: `pub mod fulltext_index;` / `pub mod text_storage;` → `pub use
  proximadb_storage_common::text_search::{fulltext_index, text_storage};` (existing
  `pub use` re-export blocks in the parent unchanged — all 6 external consumers
  [hybrid_search, rank_backend, handlers, external_collection, fusion_service, columnar/mod]
  keep their import paths).
* `document/mod.rs`: `pub mod sdp;` → `pub use ...text_search::sdp;`.
* `core/types/mod.rs`: enum definition → `pub use ...text_search::TextStorageStrategy;`
  (consumers: text_validator, columnar/schema.rs, block_structures, sst/text_column_support).

== Known duplication (pre-existing, unchanged)
`columnar/schema.rs:211` carries its OWN `TextStorageStrategy` copy (sans serde derives).
It does not import either moved definition; deduplicating it is future work (needs schema.rs
extraction first — it is not part of this cluster).
