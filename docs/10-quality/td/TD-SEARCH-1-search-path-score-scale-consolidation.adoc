== The debt (observed while root-causing TD-RECALL-1)

1. **Implicit score-scale contract.** `OptimizedSearchRecord.score` must be "normalized similarity in [0,1], higher = better, computed on the collection's metric" for the cross-stage merges (`merge_delta_with_directory_results`, the two-stage dedup sort) to be meaningful — but nothing enforces it. Four independent producers (WAL delta scan, memtable two-stage Stage-1, AXIS, SST cascade/generic scan) each construct scores by hand; one hardcoded metric (the TD-RECALL-1 bug) silently broke ranking. *Direction:* make the merge inputs carry `(metric, canonical_distance)` and normalize at ONE boundary, or at minimum a debug-assert that merged record sets were scored under the same metric.
2. **Parallel memtable search implementations** (worse than first counted — SIX scoring sites): the live `write_ahead_log/mod.rs search_unflushed_vectors`; the dead chain `WALBatchStrategy::search_vectors_similarity` (trait default) → `WALBehaviorWrapper::search_unflushed_vectors` → `global_partitioned::search_vectors`; PLUS three per-strategy brute-force `search_vectors_similarity` impls (avro/bincode/proto serialization strategies, comment-admitted "for tests").
3. **Two `SimilarityResult` structs**: `proximadb-distance-kernel/src/engine.rs:363` (live) and `proximadb-vector/src/distance.rs:63` (duplicate) — workspace-decomposition residue, alongside a full duplicate distance engine (engine/impls/avx512/int8_simd, `BruteForceSearch`, `VectorServiceImpl`) with zero external users.
4. **Internal `_v1` DTO plumbing** in the live search chain (`unified_search_v1*`, `optimized_results_to_proto_v1`, proto `SearchVectorRecord`/`VectorOperationResponse`) even though the external v1 surfaces are sunset — this is the TD-V1SUNSET-2 scope; the search chain is a high-value slice because the DTO conversion is where the display-score bug (similarity=None → 0.0) lived.

== Progress

*Declutter PR 1 (this TD's first slice):*

* Deleted the dead memtable-search plumbing: `WALBatchStrategy::search_vectors_similarity` (trait default + avro/bincode/proto strategy impls), the `WriteAheadLogManager::search_vectors_similarity` wrapper, and `WALBehaviorWrapper::search_unflushed_vectors` — every one defaulted to Cosine when unset (the TD-RECALL-1 hazard class). `global_partitioned::search_vectors` is retained as the unit-test harness for partition MVCC/tombstone semantics (doc-marked; consolidation into the live path is the remaining direction).
* Pruned `proximadb-vector` to its externally-used surface (quantization, `IndexConfig`, transform-index, metric enum + proto conversions): deleted the duplicate distance engine (`engine.rs`/`impls.rs`/`avx512.rs`/`int8_simd.rs` — the latter had zero users even in-crate), the duplicate `SimilarityResult`, `search.rs` (`BruteForceSearch`), and `service.rs` (`VectorServiceImpl`). ~2,000 lines removed.
* Deleted the ORPHANED `write_ahead_log/tests/` module tree (~2,700 lines: avro/bincode serialization, batch-strategy, flush-coordinator, background-flush test files) — `tests/mod.rs` was never declared as a module, so none of it compiled ("TODO: Fix compilation errors" era); live serialization round-trip coverage is `serialization::{avro,bincode}::tests`. Dropped the mock-based `test_search_vectors_similarity` from the live `batch_strategy_tests.rs` (it asserted only that a mock errors or returns empty).

*Slice 2 (score-scale contract as executable assertions):* `proximadb-search-types` now carries `cross_stage_score_normalizations_agree_per_metric` (asserts `SimilarityResult::new(d, m).normalized_score` == `standardized_distance_to_similarity(d, m)` across Euclidean/Cosine/Manhattan sample distances — the two formulas every merge input flows through) and `normalized_score_is_monotonic_in_distance` (descending-score sort ⇔ ascending true distance, per metric domain). If either formula drifts, the contract test fails before a cross-scale merge can ship.

*Remaining:* the structural fix for item 1 (ONE shared normalization function instead of two asserted-equal copies), item 4 (`_v1` DTO sunset slice), and folding `global_partitioned` search + the live WAL search into one scoring core.

== Verification
* One memtable search entry point; the dead pair deleted or delegated.
* A test that constructs a Euclidean collection, plants records in memtable + storage, and asserts the merged top-k equals brute force (the exact TD-RECALL-1 reproducer, kept as a ratchet).
