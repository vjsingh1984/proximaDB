= TD-DECOMP-81: Extract the ops compression cluster → engine-core
:id: TD-DECOMP-81
:status: implemented
:date: 2026-08-16
:phase: root-crate decomposition — phase 6, PR B

== Problem

Root `src/storage/engines/core/ops/` still owns the compression stack:
`compression_common.rs` (2,026 LOC), `compression_adapter.rs` (1,123),
`proxima_tensor_encoding.rs` (676), `simd_config.rs` (365). The phase-6 survey
found `compression_common` — nominally the most "intra-ops-coupled" file (105
intra-ops refs) — has exactly **one outgoing root ref**:
`crate::metrics::compression::CompressionData`, a 5-variant fieldless enum
living in control-tier `proximadb-metrics`. Everything else it needs
(`CompressionAlgorithm`, `HardwareCapabilities`) is already horizontal/foundation.

== Change

1. **Hoist `CompressionData`** → `proximadb-compression` (horizontal; new
   `data_type.rs` module, re-exported at crate root) — semantically it belongs
   beside `CompressionAlgorithm`. `proximadb-metrics` keeps a `pub use`
   re-export so every existing `metrics::compression::CompressionData` path
   resolves unchanged. `proximadb-compression` added to
   `[workspace.dependencies]` (it was previously root-package-only — the
   manifest already listed it twice under root `[dependencies]`; one duplicate
   dropped). control→horizontal is layering-legal (boundary checker: no findings).
2. **`git mv` the four files** → `proximadb-engine-core/src/ops_compression/`
   (new module). Rewrites: `crate::metrics::compression::CompressionData` →
   `proximadb_compression::CompressionData`; compression_adapter's
   `crate::core::config::HardwareConfig` → `proximadb_config::HardwareConfig`
   (engine-core gains the `proximadb-config` dep — foundation, legal);
   proxima_tensor_encoding's `super::proximacodec` → `proximadb_codec` (the
   root module is itself a shim to that crate). `simd_decode.rs` stayed in root
   — it is already a re-export shim, not extractable code.
3. **Root `ops/mod.rs` shims**: `pub use
   proximadb_engine_core::ops_compression::{compression_adapter,
   compression_common, proxima_tensor_encoding, simd_config}` — the 8 external
   `ops::` consumers (sst/core, nova, swift, raptor ×2, columnar/search, …)
   resolve unchanged.
4. New engine-core deps: `proximadb-config` (workspace), `num_cpus` and `toml`
   (inline, matching root's specs — simd_config only).

== Deviation notes

- `SIMDConfiguration::init_with` return type boxed the error
  (`Result<(), Box<SIMDConfiguration>>`): the crate's clippy gate
  (`result_large_err`) fires where root's crate-level allows suppressed it.
  The API has **zero callers** anywhere in the workspace — signature change is
  consequence-free. This is the "root clippy allows don't travel" lesson
  (phase 3) applied at the lint level.
- `performance_optimization.rs` (828) + `zero_copy_reader_integration.rs` (416)
  deferred (filesystem-factory refs) — phase-7 candidates as planned.

== Verification

* `cargo check -p proximadb-engine-core --all-targets` clean
* `cargo check -p proximadb --lib` clean; workspace `--lib --bins --tests` clean
* `cargo clippy --lib --bins -p {engine-core, metrics, compression, root} -- -D warnings` clean
* `check_workspace_boundaries.py --strict` — no findings
* `nextest -p {engine-core, metrics, compression}`: 283/283 pass
  (93 tests moved with the cluster)
* `cargo fmt --check` clean; TD-unique guard pass

== Impact

~4,190 LOC out of the root crate. `ops/` is reduced to `mod.rs` +
`performance_optimization.rs` + `zero_copy_reader_integration.rs` (both phase-7
port-swap candidates). The `CompressionData` hoist also removes the last
storage→control naming dependency in the compression path.
