== Why

`src/storage/persistence/write_ahead_log/v2_segment_header.rs` (**14 tests**) is the WAL v2 segment
header (serialization + integrity), self-contained over `anyhow`/`proximadb-records`/`serde`. It is a
truly clean leaf (zero `crate::` climb-out, zero real `super::`), NOT feature-gated (lives in the
default root binary). NOTE: `smart_rowgroup_sizing` (22t) was skipped — raptor is
`#[cfg(feature="experimental-engines")]` (off by default), so its tests aren't in the default binary.

== What moved (behavior-neutral)

* `src/storage/persistence/write_ahead_log/v2_segment_header.rs` → `crates/storage/proximadb-wal-segment-header/src/`.
* Root `write_ahead_log/mod.rs`: `pub mod v2_segment_header;` → `pub use proximadb_wal_segment_header::v2_segment_header;`
  (3 consumers — `serialization/{bincode,mod}.rs` + the WAL `mod.rs` — resolve unchanged).
* New storage-tier crate, deps `anyhow`/`proximadb-records`/`serde` (workspace). No `CAPABILITY_MATRIX.toml` pointer.
