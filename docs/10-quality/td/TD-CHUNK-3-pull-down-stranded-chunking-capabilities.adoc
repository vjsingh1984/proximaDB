== The reframe: these are stranded, not missing

The obvious gap list for the SDK — header-path metadata, contextual retrieval, near-duplicate suppression
— reads as a research backlog. It is not. **Three of four already exist in the ecosystem, built and
unconsumed**, in the wrong layer. That makes this a consolidation problem, which is far cheaper than the
gap list implies, and it is the single highest-leverage finding in the ADR-091 census.

[cols="2,3,2",options="header"]
|===
| Capability | Where it already exists | State
| Heading-aware splitting **with hierarchy path** | anvaiops connector-sdk (implemented, used by Confluence/SharePoint/Google Drive); Rust SDP stage 1 | Works in anvaiops; ProximaDB's `semantic.py` detects headings then **discards them** and omits the heading line from every chunk
| **Context-conditioned enrichment** (i.e. contextual retrieval — prefixing a chunk with parent context) | Rust SDP stage 2, TD-043 | Implemented, **no product caller**
| **Topic-aware deduplication** | Rust SDP stage 4, TD-043 | Implemented, **no product caller**
| Abbreviation-aware sentence splitting | Victor `rust/…/chunking.rs`, compiled + shipped as `victor_native` 0.1.0 | **Never called** — its only Python front end has zero callers, while five Python regexes do the job worse
| Semantic boundary refinement | Rust SDP stage 3 | Implemented, no product caller
|===

Genuinely new work, and the reason this TD is not pure plumbing:

* **Parent-document / small-to-big retrieval** — index small precise child chunks, return the larger
  parent for generation. The biggest retrieval-quality lever in the list and entirely absent; no
  parent/child linkage exists on `TextChunk`. **ProximaDB is uniquely placed**: the parent edge is an
  ORION graph edge, not a duplicated metadata copy — which is a differentiator no pure vector store can
  offer, and the clearest case in this program for building rather than borrowing.

== Co-design framing

Each item names the cost term it moves, per the mandate — no item lands on "it would be nice":

* **Topic dedup → KEU and KSU directly.** A duplicated chunk is paid for once in embedding and forever in
  storage. This is the only item that *reduces* cost rather than trading it.
* **Heading paths → recall at constant cost.** Metadata on an existing chunk; no extra vectors, so no KSU
  or KEU delta. Strictly free quality.
* **Context enrichment → KEU up, recall up.** Prefixing lengthens the embedded text, so it must be
  measured, not assumed: gate on recall@k per KEU spent, not on recall alone.
* **Small-to-big → KSU up (two granularities), read cost *down*.** Fewer, more precise probes at query
  time. The trade must be measured on the ADR-091 corpus before it is defaulted on.
* **Rust splitter → compute down, quality up.** Replaces ProximaDB's two Python regexes, one of which is
  the quadratic path (518 KB → 17.5 s). Evaluate behind the TD-CHUNK-2 port, which is exactly the seam
  ADR-091 chose so a native segmenter is a backend swap and not a rewrite.

== Sequencing

Cheapest-and-free first, so value lands before the expensive measurement work:

. **Heading paths** — constant cost, immediate filtered-retrieval win, and half-built already in
  `semantic.py`'s detection.
. **Topic dedup** — the only cost *reduction*; gate on a recall ratchet so dedup can never silently drop
  a distinct chunk.
. **Rust splitter behind the port** — evaluate against the Python sentence source on the shared corpus.
. **Context enrichment** — requires the KEU-per-recall measurement to justify.
. **Small-to-big on ORION edges** — the largest piece of new design; sequence last so it lands on a port
  and an invariant suite that are already proven.

== Evals, not just tests

Boundary quality is a ranked surface, so per the evals mandate it needs a rubric rather than an
assertion. Gate on **output** (does retrieval return the span that answers the question) and
**trajectory** (was the boundary source appropriate to the document's shape), measured as recall@k
against the f32 baseline on the ADR-091 corpus, threshold-gated in CI, with suites versioned in the PR
that changes behaviour. Every item above ships default-OFF until its eval clears.
