== What moved (Phase 5 PR B, 2,228 LOC, 11 tests)
`columnar/parquet_write_engine/` (7 files: streaming_writer, batch_writer, schema_builder,
bloom_filter_builder, writer_config, writer_statistics, mod) → engine-core as a top-level
module. Deps resolved to extracted crates except two root seams, both dissolved via EXISTING
ports:

* **FilesystemPort** (storage-ports:198): `filesystem_factory` fields → `Arc<dyn
  FilesystemPort>`; the factory-CONSTRUCTING convenience `new` moved root-side (mod.rs helper
  + hybrid_writer's `root_quantization_engine` companion) — construction belongs to the
  composition root.
* **QuantizationEnginePort** (storage-ports:104): streaming_writer's inline
  `UnifiedQuantizationEngine::new(...)` construction (modality tier — storage→modality is a
  hard ERROR layering rule) became an injected `Option<Arc<dyn QuantizationEnginePort>>`.
  The port already exposed exactly the two level-specific encoders the writer calls
  (`quantize_to_binary`, `quantize_to_u8`); the kernel impls it downward (allowed direction).
  The `None` case errors only when quantization arrays are actually enabled.

== Scope corrections during execution (recorded for the next wave)
* `columnar/common.rs` was moved then REVERTED — it imports `super::serialization::*`
  (ColumnarSerializer etc.), and serialization.rs holds `Arc<StorageQuantizationEngine>`
  (modality). common+serialization are ONE unit; extracting them needs the wider
  `StorageQuantizationEnginePort` (batch/level surface) threaded through the serializer
  constructors — queued as its own step, not bundled here.
* streaming_writer's builder `build()` now REQUIRES the factory (the None-arm convenience
  was the root-locked default construction). All builders are root-driven.
