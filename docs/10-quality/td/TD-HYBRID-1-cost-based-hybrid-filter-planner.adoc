== 2. The reframe (this is the load-bearing correction)

The naïve draft treated "tenancy" as a predicate to weave into the ANN filter. The red-team showed that is **the wrong layer** for cross-tenant isolation and **unachievable** as a strong boundary in an ANN graph:

* **Cross-tenant isolation is physical, not a filter.** Tenants map to physically-scoped collections (ADR-032 tenant-prefixed catalog). The HNSW graph for collection `C` contains only `C`'s vectors. There is **no shared graph** across tenants to filter — so cross-tenant isolation is a property of *which graph you open*, enforced by `validate_tenant_collection_access`, not by a predicate inside the walk.
* **Inline filtering cannot be a strong isolation boundary anyway.** ACORN-style predicate search (`src/index/axis/indexes/hnsw_index.rs:465`) distance-scores **every visited neighbor** (`:492/:524`) and follows its edges (`:511–517`); the predicate only gates admission to results (`:495–497`). So a woven predicate prevents cross-something *results*, never cross-something *traversal/scoring*. That's fine **within** a graph you are authorized to read (RLS row-subsetting), and useless **as** the cross-tenant wall.

Therefore F7 splits cleanly:

[cols="1,3"]
|===
| Concern | Owner / mechanism
| **Cross-tenant isolation** | **Physical** — collection-scoping (existing, ADR-032). F7 does *not* re-implement it as a predicate. F7's contribution here is to **harden the three live gaps** in that path (§7).
| **Intra-collection RLS / ABAC** (a subject sees a *row-subset* of a collection it may open) | **The woven `CompiledGlobalFilter`** (§3). Inline filtering is the correct tool here — you are authorized to traverse the graph; the predicate subsets the rows returned.
| **The ABAC _policy_** (which rows) | **FA / TD-FOUNDATION-3** — fills the `access_predicate` slot; F7 provides the slot, not the policy.
|===

== 3. Design — the mechanism (sound; formalizes what exists)

=== D1 — Wire the existing selector fully; make it single-brained
Keep `AnnFilteringPolicy::routing_mode` + `UnifiedCostModel`. Fixes:

* **Always populate selectivity + policy on the canonical path.** Today the `IndexHybridQuery → AxisHybridQuery` conversion **drops** `ann_filtering_policy`/`estimated_selectivity`/`ann_filtering_mode` via `..default()` (`src/index/axis/contract.rs:113–116`), so the policy-driven route is unreachable on the canonical path (everything defaults to Inline). F7 threads them through.
* **Single-brain the mode.** `UnifiedQueryOptimizer` builds `AnnFilteringPolicy::default()` (not the collection policy) and feeds `filter_selectivity.unwrap_or(1.0)` — **unknown selectivity → 1.0 → PostFilter** (`query_optimizer.rs:1171–1183`), while AXIS recomputes from the structured policy (`manager.rs:1421`). Make one authoritative: the optimizer reads the *collection* policy and passes its chosen mode structurally; AXIS consumes rather than recomputes. Fix `unwrap_or(1.0)` → an exact/inline-safe default, since unknown-selectivity biasing to PostFilter is the worst case.

=== D2 — One `CompiledGlobalFilter`, two consumers (formalizes existing convergence)
Introduce `CompiledGlobalFilter` exposing `contains(doc_id) -> bool` (the existing Inline closure, `manager.rs:1925`) and a **lazy** enumerable view (PreFilter already streams+evaluates, `manager.rs:4381`). Both consumers already share the builder + evaluator (§1), so this is an **extraction**, not a reconciliation. Constraints from the review:

* **Scope to id + metadata predicate only.** `similarity_threshold` and `include_expired`/expiry are applied inline by PreFilter (`manager.rs:4413–4432`) and *not* by the Inline path — do **not** fold them into `CompiledGlobalFilter` (that would create a real, new divergence).
* **Layering:** contract in `proximadb-query-filter` (+ one workspace dep on `proximadb-filter-expression`); impl glue (`metadata_filters_to_expression`, `record_filter_metadata`) stays in `src/`. Resolve the duplicate `FilterOperator`/`FilterValue` enums the crate already carries (smell, not a blocker).

=== D3 — RLS/ABAC as an always-ANDed component of the woven filter (intra-collection only)
`CompiledGlobalFilter = user_predicate [AND access_predicate]`, where `access_predicate` is the **intra-collection** RLS/ABAC subset. It:

* is **always-ANDed** and, being intra-collection, is safe to apply Inline **or** PreFilter (both traverse a graph the subject may read) — so it does **not** need to "pin the mode." (The original "pin away from PostFilter" decision is withdrawn — see §8.)
* is **populated by FA** (empty-but-present until then). F7 wires the slot and the always-AND, not the policy.
* is the point at which the **dead RLS engine** (`security/rls/service.rs:194`, `filter_lattice.rs:281`) finally gets a caller — or is deleted in favor of FA. F7 must pick one; a second unwired predicate engine is not acceptable.

=== D4 — Fail-closed + explainable
Extend the trace (`search_plan_trace`, `route_explain`) to record which components were ANDed (user / access), the estimated selectivity, and the chosen mode. An **access-predicate that cannot be resolved fails closed** (empty result + a distinct trace state), never a wider scan.

== 4. Cross-tenant isolation review (carved out) — H2 VERIFIED not-a-leak; H1/H3 = cheap hardening
The tenancy-safety review flagged three suspected gaps in the existing physical-isolation path. A **follow-up verification (2026-07-28, agent-confirmed against the code)** downgraded all three: the alarming one (H2) is **not a live leak**, and H1/H3 are defense-in-depth hardening, not vulnerabilities. Recorded so the fear is not re-raised.

[cols="1,3"]
|===
| Gap | Verified status / evidence

| **H2 — cache hit skips the per-row scrub** — **VERIFIED NOT-A-LEAK**
| The cache key is `(collection_id, vector, k, filter)` with no `tenant_id` (`query_cache.rs:11–42`) and a hit (`legacy.rs:2285–2293`) skips the scrub at `:2343`. **But two tenants can never collide on the key:** `collection_id` is resolved to a **globally-unique** id *before* search (`record_ops_service.rs:395–410` → `collection.id`), minted from an allocator that is "globally unique, never reused across all tenants" (`manager.rs:2421–2440`); each collection is owned by **exactly one** tenant (`proximadb-tenant/src/lib.rs:50` single owner; `validate_tenant_collection_access` fail-closed, `manager.rs:436–450`). So the two tenants' id-sets are disjoint → keys cannot collide. Additionally, production callers reaching `:2187` pass `tenant_context = None` (the real tenant-scoped search routes through the *different* `unified_search_v1`), so no hit/miss scrub asymmetry is even reachable. The per-row scrub (`:2361`) is genuine belt-and-suspenders.
| **H2-fix (optional hardening)** — fold `tenant_id` into `QueryKey::new` (`query_cache.rs:19`) so the key is tenant-partitioned **by construction** rather than by the upstream resolve-first *contract*. Not required to close a leak; removes a standing assumption.

| **H1 — `Option<tenant_context>`** — hardening
| `legacy.rs:742` takes `tenant_context: Option<…>`; a `None` path skips the access check + scrub. Production paths pass `None` here by design (see H2), so this is not a live bypass — but making authenticated entry points fail-closed on `None` removes the footgun for a future caller.

| **H3 — second `AxisHybridQuery` build site** — hardening
| `src/services/external_collection/service.rs:528` builds an `AxisHybridQuery` outside the canonical builder. Not a current leak; any future tenancy/predicate wiring (D3) must cover it, tracked so it isn't missed.
|===

== 6. Test plan
* **H2 cache leak (do first):** two tenants, identical query shape → prove a tenant-A cache entry is never served to tenant-B (assert on cache key composition, not just rows).
* **H1 fail-closed:** `None` tenant context on an authenticated path → rejected, never a wide scan.
* **Intra-collection RLS subset:** within one collection, an `access_predicate` returns only the authorized row-subset under Inline *and* PreFilter (parity), and recall is measured within that subset.
* **Selectivity-absent safety:** no selectivity estimate → exact/inline default that still applies the filter, never plain unfiltered ANN (guards the `has_filters == false` fallthrough at `manager.rs:1480`).
* **No-regression:** flag off → ADR-011 byte-for-byte.
* **FA seam:** empty `access_predicate` is a no-op; a fixture-populated one ANDs correctly with no planner change.

== 7. Out of scope
* **Cross-tenant isolation as a predicate** — it is physical (ADR-032); F7 hardens the path (§4) but does not re-implement it in the filter.
* **A "never-traversed" cross-tenant guarantee inside a shared graph** — unachievable with ACORN inline filtering; would require per-tenant partitioned indexes (a separate architectural item, not F7).
* **ABAC policy resolution** (subject attributes, attribute-authority store) — FA / TD-FOUNDATION-3.
* **The graph/hybrid divergent evaluator** (`src/graph/hybrid/mod.rs:1147`, hand-rolled raw-JSON equality) and the other ~5 filter-eval sites (WAL parallel search, progressive pipeline, multi-tier dedup, per-engine block pruning) — F7 scopes to the **AxisManager ANN path**; routing those through `CompiledGlobalFilter` is budgeted follow-up, not F7.

== 8. Red-team log + what changed (rev 2, 2026-07-27; H2 verified rev 3, 2026-07-28)
Two adversarial agents attacked the draft against the code; a third verification pass closed out the suspected isolation gaps.

**Buildability review — the mechanism is sound (verdicts SOUND ×3):** Inline and PreFilter already share one builder + one evaluator (no divergence to fix — §1); `FilterExpression` is a foundation leaf crate so the layering has no inversion; PostFilter shortfall is disclosed on 4 channels. *Residual:* ~7 filter-eval sites exist and graph/hybrid is a true semantic divergence → scoped out (§7). Net: §7 of the draft (targets T3/T6) over-stated the risk; D2 simplified to an extraction.

**Tenancy-safety review — the naïve D3 is BROKEN/UNBUILDABLE:** `AxisHybridQuery` has no tenant field; ACORN inline filtering visits/scores every node regardless of predicate (so "never traversed/scored" is impossible at that layer); the "pin away from PostFilter" mechanism does not exist and `force_mode` short-circuits routing (`lib.rs:2273`); the RLS engine is dead code; and cross-tenant isolation is actually physical + a post-hoc scrub with **three live gaps** (§4).

**What changed:**
1. **Reframed the whole concern (§2):** cross-tenant = physical isolation (not a predicate); the woven filter is for intra-collection RLS/ABAC.
2. **Withdrew the "tenancy pins the mode" decision** — unnecessary once tenancy is not a predicate; intra-collection RLS is mode-agnostic.
3. **Carved out the three suspected isolation gaps (§4).** A rev-3 verification (2026-07-28) then found **H2 is NOT a live leak** — `collection_id` is globally-unique + single-owner, so cache keys cannot collide across tenants, and the `:2187` path passes `tenant_context = None` anyway. H1/H3 downgraded to optional defense-in-depth hardening. The scary "potential live cross-tenant leak" is retracted.
4. **Simplified D2** to an extraction of already-convergent code; confirmed the crate layering.
5. **Added the single-brain + `unwrap_or(1.0)` fix (D1)** from the two-brain finding.

**Re-scope:** the *planner* mechanism is **smaller than the 2w estimate** (much is extraction + wiring). The isolation concerns (§4) turned out to be **hardening, not a live vuln**. TD stays **Draft** until D3's RLS-reuse-vs-delete call is made with FA; there is no longer a blocking security item.

== 9. Build outcome + verified scope (rev 4, 2026-07-28)

D2 (the mechanism) was built and shipped as two PRs:

* **#1260 (WI-1a) — `CompiledGlobalFilter`** in `proximadb-search-types::compiled_filter`: the single
  id + metadata predicate, co-located with `evaluate_filter` (foundation leaf — no layering inversion,
  no operator-enum duplication). 6 parity unit tests. **Merged.**
* **#1264 (WI-1b) — rewire** the three `AxisManager` sites (Inline closure, residual re-filter, exact
  PreFilter) through it. Behaviour-preserving; verified by the 6 unit tests + the 2 direct parity tests
  (`test_predicate_search_all_pass_matches_unfiltered`, `test_bloom_filter_prefiltering`) + 364 axis
  lib tests.

**WI-2/WI-3 verification changed the remaining scope (this is the load-bearing rev-4 finding):**

* **WI-2 ("thread policy + selectivity") is ALREADY DONE.** The canonical path builds the query via
  `build_axis_hybrid_query_with_policy` (`services/operations/vectors/hybrid/axis_builder.rs`, called at
  `legacy.rs:3599`), which threads `estimated_selectivity` + `ann_filtering_mode` + a policy into AXIS;
  the policy-driven Pre/Inline/Post branches (`manager.rs:1448/1459/1474`) are reachable. The recon's
  "`contract.rs:113` drops the fields via `..default()`" was the **storage-DTO boundary**, not the
  service path — a conflation.
* **The real gap is a DORMANT feature, not missing wiring.** The per-collection `AnnFilteringPolicy`
  (`CollectionRecord.ann_filtering_policy`, catalog `lib.rs:674`; builder `with_ann_filtering_policy`
  `:940`) is **settable nowhere and read nowhere** — `legacy.rs:3610` hardcodes
  `AnnFilteringPolicy::default()`, and the builder has zero callers. Activating it (proto/config surface
  to *set* a policy + read-side resolution) is a **multi-layer feature = TD-073**, deferred. Wiring only
  the read side would be inert (every collection has the default).
* **WI-3 (two-brain) is live but deterministic.** `UnifiedQueryOptimizer` runs on the vector path
  (`legacy.rs:2580` et al.) and computes `plan.ann_filtering_mode`, but for filtered queries the catalog
  policy's `routing_mode` at `manager.rs:1421` **always overrides** it (a policy is always present via the
  hardcoded default). Per D15 the catalog policy is authoritative, so this is correct-by-design — the
  optimizer's mode is advisory/EXPLAIN for filtered ANN. No live bug; a clarity/dead-value cleanup at most.

**Decision (2026-07-28):** F7's shippable code = the D2 unification (#1260 + #1264). The per-collection
policy activation is folded into **TD-073** (dormant-feature, multi-layer). WI-4 (the `access_predicate`
FA seam) and WI-5 (EXPLAIN trace) remain available but are additive/speculative until FA unblocks. TD
stays **Draft**; no further F7 code is queued pending a TD-073 or FA decision.
