== Why

Once the mechanisms exist (WLP-1..5), a collection's profile should imply sensible prune defaults
and be observable in the query trace, and the ADR/TD set should be cross-linked and indexed.

== Scope

* Map `StorageProfile` → default `BlockPruneConfig`: `AppendBulk` applies the calibrated L2
  `radius_k` / nprobe; `Churn` leaves `radius_k=0.0` (irrelevant — memory-resident path).
* Emit the resolved `StorageProfile` into the io_trace so a query's projection strategy is
  observable per-tenant.
* Close-out docs: ADR-061 README row (added by the docs PR), TD-WLP cross-links, status bumps.

== TDD gate

* Unit `test_append_profile_applies_calibrated_prune_defaults`: `AppendBulk` yields the L2 `radius_k`
  default; `Churn` yields `0.0`.
* Behaviour ratchet: re-run the TD-WLP-3 sweep under the profile-default path — no recall regression
  vs explicit config.

== Gating

`AppendBulk` gets calibrated defaults; every other/untagged collection stays legacy. Ratchet-gated.
