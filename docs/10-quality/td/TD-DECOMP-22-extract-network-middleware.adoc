== Why

A broad clean-leaf scan of root `src/` (files with tests and zero `crate::` climb-out) surfaced the
`network/middleware` pair as a cohesive, high-value move:

* `cors.rs` (**24 tests**) — builds the CORS layer (`create_cors_layer`, `CorsConfig`, `CorsConfigError`);
* `rate_limit.rs` (**22 tests**) — per-client `RateLimitState` token bucket + `get_client_ip` helper.

Both are self-contained (no `super::` coupling beyond the `#[cfg(test)]` block; 16 types/fns in-file),
not feature-gated, and depend only on external crates — no `proximadb_*` deps — so they form a clean
platform-tier leaf. Moving them extracts **46 tests** from the root lib binary in one PR.

== What moved (behavior-neutral)

* `src/network/middleware/{cors,rate_limit}.rs` → `crates/platform/proximadb-network-middleware/src/`.
* Root `src/network/middleware/mod.rs`: `pub mod cors;` / `pub mod rate_limit;` →
  `pub use proximadb_network_middleware::{cors, rate_limit};` so all consumers — `multi_server`,
  `rest/server`, `postgres/{mod,protocol}`, `middleware/metrics` (using `RateLimitState`,
  `get_client_ip`, `CorsConfig`, `create_cors_layer`) — resolve unchanged.
* New platform crate, deps: `axum`/`serde`/`serde_json`/`tokio`/`thiserror`/`toml`/`tower-http`/`tracing`
  (all workspace). No `CAPABILITY_MATRIX.toml` pointer referenced these files.

== Follow-ups

* **Running total once merged: ~837 tests out of root** (791 + 46).
* Process note (recurring): a `use`-statement dep scan misses fully-qualified + test-only usage. Here
  `serde_json` (tests), `thiserror` (`#[derive(Error)]` on `CorsConfigError` — its absence also cascaded
  to a missing-`Display` E0599), and `toml` (rate-limit config test) were all only found by compiling.
  Compile early on the standalone crate to surface the real dep set before the full-tree check.
