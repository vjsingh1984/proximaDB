== Context

The 2026-07-30 boundary review confirmed the `OSS_ENTERPRISE_BOUNDARY_2026_06_17`
remediation ledger is complete: B4 externalized the commercial `src/{revenue,
sales_enablement, licensing, executive}` modules (#437), and B5's neutral baked
baseline + rename to `config/tier-config.json` are done. Two residuals were found
and fixed alongside ADR-084: the dead `src/api_handlers/sales_endpoints.rs`
(unreferenced since B4 removed the `sales_enablement` module it imported —
deleted) and the stale "still named pricing.json" migration comment in
`config/tier-config.json` (corrected; fingerprint regenerated).

One classification question remains open. `src/ai/executive_dashboard.rs` and
`src/ai/business_intelligence/` survived B4 because they live under `src/ai/`,
and they are compiled **ungated** into the OSS binary (both declared and
re-exported in `src/ai/mod.rs`; `src/lib.rs` declares `pub mod ai;` ungated). Their *content* is an AI-BI product feature
(NL querying + automated insight/report generation over the database) — under
`OPEN_CORE.md` ("features are free"), that is legitimately OSS. But their
*naming* ("executive dashboard", "business intelligence") is
commercial-flavored, sits adjacent to the externalized `executive` GTM surface,
and the `check_oss_boundary.py` denylist does not cover these terms — so the
guard passing is silence, not a verdict.

== Work

1. **Classify** each module: product feature (keep OSS) vs go-to-market surface
   (externalize per B4). Expected outcome given the content: feature → keep.
2. If kept, decide whether a **neutral rename** is warranted (e.g.
   `insight_dashboard` / `analytics_insights`) per the boundary spec's
   neutral-naming rule for public OSS surfaces, with serde/API aliases if any
   serialized names exist.
3. Assess whether the surface is **wired and supported** (routed endpoints,
   tests, `SUPPORTED_SURFACE.adoc` tier) or dormant scaffolding; dormant
   scaffolding should be removed rather than renamed (pre-GA, no back-compat).
4. If a rename or removal lands, consider adding the chosen resolution's terms
   to the `check_oss_boundary.py` denylist so the class of drift is guarded,
   not re-audited.

== Resolution (2026-07-30)

**Classification: dormant GTM-flavored scaffolding → removed** (Work item 3's
remove-if-dormant rule; pre-GA no-back-compat). The reachability audit found:

* The **only** consumers of `executive_dashboard` + `business_intelligence`
  were each other, the `src/ai/mod.rs` re-exports, and the
  `#[cfg(feature = "ai_endpoints")]` handler (default OFF, never in the CI
  feature matrix). No live code path reached them in a default build.
* The content was go-to-market shaped, not database-feature shaped:
  `FocusArea::Revenue/Customers/Growth/Risk`, "executive dashboards" — the
  sibling of the B4-externalized `src/executive` surface.
* The gated surface was **broken when enabled**: `create_router` binds `router`
  immutably while the gated block reassigned it, so
  `--features ai_endpoints` could not have compiled — invisible because the CI
  feature matrix never built that feature. Dead by construction.
* `tests/integration/release_1_enterprise_validation.rs` was not listed in
  `tests/integration/mod.rs` — a never-compiled test file referencing the same
  surface.

**Removed:** `src/ai/executive_dashboard.rs`, `src/ai/business_intelligence/`
(5 files), `src/api_handlers/ai_endpoints.rs`, the `ai_endpoints` feature flag,
its gated mount in `src/network/rest/canonical/handlers.rs`, the dead test
file, and the `feature_toggles.md` entry.

**Kept (classified as feature, not GTM):** `src/ai/insights.rs`,
`analytics.rs`, the NL-query stack (`natural_language*`, `llm*`, `nlp`) — these
are consumed by live paths (`src/query/nl/`, `database.rs`, REST `nl.rs`).
Incidental "business intelligence" *naming* inside retained feature content
(e.g. the NL prompt template `default_business_intelligence_template`, the
`NaturalLanguageBusinessIntelligenceAPI` type) is descriptive of the feature,
so **no `check_oss_boundary.py` denylist addition** (Work item 4): a denylist
on these phrases would false-positive on legitimate feature content.
