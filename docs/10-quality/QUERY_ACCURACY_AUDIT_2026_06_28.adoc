== Purpose

A repo-wide audit of query-accuracy testing across every modality (relational,
vector, graph, document, time-series) and the CI wiring that gates it. The goal is
to answer two questions per modality: (1) does a *value-accuracy* test exist (does
it check the answer is correct, not merely that the query ran), and (2) does that
test actually *gate* in CI.

== Two structural findings

=== Finding 1 — most "ratchets" count execution, not correctness

The TPC-H, TPC-DS, graph-LDBC, document, and events ratchets gate on "the query
ran without error", not "the query returned the right answer". `ADR-040` (accepted
2026-06-27) is the in-flight remedy: convert each ratchet to a value-accuracy gate
(dual-engine canonical equivalence + hand-anchored expected answers). Phase 1
(document, PR #476) already exposed *TD-183*: 7 of 11 JSON queries silently return
*0 rows on both engines* — the old execution ratchet counted all 11 as passing.

*Vector is the exception*: it is genuinely accuracy-based (recall@k vs an f32
brute-force baseline) across many engines and quantizers.

=== Finding 2 — the accuracy tests that exist mostly do not gate in CI

115 of 150 integration tests are *orphaned* (no CI tier runs them). An integration
test gates only if its filename matches an integration-job glob (`+*graph*+`,
`+*query*+`, `+*cache*+`, `+*storage*+`, `+*sst*+`, `+*wal*+`, `+*cluster*+`,
`+*distributed*+`) or is explicitly named in the qa-gate. The strong
value-correctness / recall suites that already exist run *nowhere* in CI:
`pgwire_relational_engine_e2e` (40+ join/subquery/set-op assertions),
`pgwire_olap_delta_merge_e2e` (incl. the JOIN value-accuracy test added in the
ADR-025 PR3 flip), `vector_ann_recall_e2e` / `raptor` / `helix` / `nova` /
`td112_postflush` recall, `document_json_pgwire_e2e`, `events_tsbs_pgwire_e2e`.

|===
| Tier | What runs

| *develop-tier* (feat→develop)

  (filename-globbed); `feature-matrix`; `rust-compile` (compile-only hard gate).

| `pgwire-recall-tests` = TPC-H + TPC-DS + `proximadb-block-format --lib recall`
  + `embedded_flush_recovery recall`; coverage ratchets.

| *full-tier* (qa→main)
| python, server-integration, docker, coverage.

== Prioritized program (TD-182)

=== P0 — gate the accuracy tests that already exist

Wire the orphaned accuracy/recall e2e suite into CI with `--test-threads=1` (they
toggle process env) and a Linux-sized run. Split by cost: a fast develop-tier
pgwire-accuracy job (`pgwire_relational_engine_e2e`, `pgwire_olap_delta_merge_e2e`,
`document_json_pgwire_e2e`, `events_tsbs_pgwire_e2e`) and the heavier vector recall
ratchets (`vector_ann_recall_e2e`, `raptor`, `helix`, `nova`, `td112_postflush`)
in the qa-tier alongside the existing recall ratchets. Verify each passes in CI
before declaring done. Cheapest high-value win — these tests are written and green
locally; they just run nowhere.

=== P1 — finish the ADR-040 execution→accuracy conversion

Graph LDBC (assert the recursive-CTE reachability set; value-check the 10 queries),
time-series (value-check windowed/ time-bucketed aggregates), and anchor more
TPC-H/DS queries than Q1/INTERSECT.

=== P2 — fill the modality accuracy gaps

* *Graph (HIGH):* no post-`MATERIALIZE` / deletion-vector accuracy test — mirror
  `pgwire_olap_delta_merge_e2e` for graph (create A→B→C, MATERIALIZE, DELETE B,
  assert C unreachable). A DV bug at the graph layer passes every current test.
* *Vector:* recall under deletes/updates/compaction (ADR-025 path); `sign_magnitude`
  + `turboquant`/PQ recall; un-`#[ignore]` filtered-ANN recall (TD-073);
  cross-engine recall parity.
* *Document:* fix TD-183 (JSON projection/filter 0-rows), then ratchet back to 11.
* *Time-series:* value-check windows/time-buckets/EXTRACT/HAVING; rate/delta;
  post-mutation.
* *Relational:* standalone UPDATE/DELETE value-correctness; window / ROLLUP /
  GROUPING SETS / recursive-CTE value checks.
