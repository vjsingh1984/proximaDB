== Security Overview

ProximaDB's security architecture is built on three foundational principles:

[cols="1,2", options="header"]
|===
| Security Principle | Implementation

| **Identity & Access Management**
| Multi-method authentication with granular role-based access control

| **Multi-Tenant Isolation** 
| Secure tenant boundaries with data segregation and resource isolation

| **Transport & Data Security**
| End-to-end encryption with mutual TLS and configurable data protection
|===

=== API Key Authentication

**Use Case:** Development, testing, and simple deployments

[source,python]
----
# Simple API key authentication
client = proximadb.connect(
    url="https://your-proximadb.com",
    api_key="your-api-key"
)
----

**Features:**
• Simple setup and configuration
• Suitable for development and testing
• Basic access control

=== JWT Token Authentication

**Use Case:** Production systems with session management

[source,python]
----
# JWT with automatic refresh
auth_config = AuthConfig(
    method=AuthMethod.JWT,
    jwt_token="your.jwt.token",
    refresh_token="refresh-token",
    auto_refresh=True
)

client = ProximaDBClient(
    url="https://your-proximadb.com",
    auth_config=auth_config
)
----

**Features:**
• Stateless authentication
• Automatic token refresh
• Role and permission encoding
• Session expiry control

=== OAuth2 Integration

**Use Case:** Enterprise SSO integration with identity providers

[source,python]
----
# OAuth2 with Google Workspace
auth_config = AuthConfig(
    method=AuthMethod.OAUTH2,
    oauth2_client_id="google-client-id",
    oauth2_client_secret="client-secret",
    oauth2_provider="google",
    oauth2_scopes=["openid", "profile", "email"]
)
----

**Supported Providers:**
• Google Workspace / Google Cloud Identity
• Microsoft Azure Active Directory
• Custom OAuth2 providers
• Enterprise identity systems

=== Mutual TLS (mTLS)

**Use Case:** High-security environments and zero-trust networks

[source,python]
----
# Client certificate authentication
auth_config = AuthConfig(
    method=AuthMethod.CLIENT_CERT,
    client_cert_file="/path/to/client.crt",
    client_key_file="/path/to/client.key",
    ca_cert_file="/path/to/ca.crt"
)
----

**Features:**
• Transport-level authentication
• Certificate-based identity verification
• Perfect for zero-trust architectures
• Hardware security module (HSM) support

| **Strict Isolation**
| Complete data and resource separation
| Physical separation per tenant

| Configurable per-tenant requirements
| Mixed physical/logical based on sensitivity

== Transport Security

=== TLS/SSL Configuration

**Default Security:**
• TLS 1.3 for all client-server communications
• Perfect Forward Secrecy (PFS)
• Strong cipher suites only
• Certificate validation enabled by default

[source,toml]
----
# Server TLS configuration
[server.tls]
cert_file = "/path/to/server.crt"
key_file = "/path/to/server.key"
ca_file = "/path/to/ca.crt"
min_tls_version = "1.3"
require_client_cert = false  # Set true for mTLS
----

=== Network Security

**gRPC Security (Port 5679):**
• HTTP/2 with TLS encryption
• Client certificate authentication support
• Compressed and encrypted payloads
• Connection multiplexing with security context

**REST Security (Port 5678):**
• HTTPS with configurable TLS versions
• Standard HTTP security headers
• CORS configuration for web applications
• Rate limiting and DDoS protection

== 🔧 Security Best Practices

=== Development Security

**Secure Development:**
• Use authenticated connections in all environments
• Store credentials in secure credential stores
• Implement proper error handling for auth failures
• Test with different permission levels
• Use least-privilege principle for application accounts

[source,python]
----
# Secure development pattern
import os
from proximadb import ProximaDBClient
from proximadb.auth import AuthConfig, AuthMethod

# Load credentials from secure environment
auth_config = AuthConfig(
    method=AuthMethod.JWT,
    jwt_token=os.environ.get('PROXIMADB_JWT_TOKEN'),
    refresh_token=os.environ.get('PROXIMADB_REFRESH_TOKEN')
)

# Use context manager for automatic cleanup
with ProximaDBClient(auth_config=auth_config) as client:
    # Perform operations with automatic session management
    result = client.search(collection_id="secure_data", vector=query_vector)
----

== Getting Started with Security

=== Quick Security Setup

[source,bash]
----
# 1. Generate secure configuration
proximadb init --secure

# 2. Configure authentication
proximadb auth setup --method jwt --provider your-idp

# 3. Create service account with minimal permissions
proximadb rbac create-role app-service \
  --permissions collections.read,vectors.search

# 4. Deploy with security enabled
proximadb deploy --config secure-config.toml
----
