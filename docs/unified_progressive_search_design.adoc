== Executive Summary

=== Overview
This document specifies the unified progressive search architecture for ProximaDB that provides intelligent routing between index-first search, progressive quantization search, and direct FP32 search based on collection configuration and cost analysis.

=== Key Requirements
* Use `search_vectors_unified` as the common entry point (trait-defined)
* Analyze collection configuration to detect quantization capabilities
* Integrate with existing AXIS indexes hydrated by flush/write operations
* Implement cost-based routing with real benchmarking data
* Provide comprehensive logging for each decision branch
* Avoid code proliferation through shared orchestrator pattern

=== Architecture Principles
* **Per-Search Orchestrator Pattern**: Each search operation gets its own orchestrator instance for optimal concurrency
* **Engine Component Access**: Orchestrator has full access to engine readers, writers, indexes, and cache without duplicating logic
* **Collection-Driven Configuration**: All search decisions based on collection's QuantizationConfig and IndexConfig
* **Progressive Refinement**: Multi-stage search using Binary → INT8 → PQ → FP32 refinement

=== Decision Tree Algorithm

==== Phase 1: Collection Configuration Analysis
[source,rust]
----
// 1. Check if quantization is enabled in collection
let quantization_enabled = collection.config
    .quantization_config
    .map(|q| q.enabled)
    .unwrap_or(false);

// 2. Determine available quantization levels based on strategy
let available_levels = if quantization_enabled {
    match collection.config.quantization_config.strategy {
        SmartDefaults => determine_smart_defaults(collection.config.dimension),
        CustomLevels => collection.config.quantization_config.custom_levels,
        Minimal => vec![QuantizationLevel::Int8],
        Aggressive => vec![QuantizationLevel::Binary, QuantizationLevel::Pq4, QuantizationLevel::Pq8],
    }
} else {
    vec![] // No quantization available
};

// 3. Check progressive search enablement
let progressive_enabled = collection.config
    .quantization_config
    .map(|q| q.enable_progressive_search)
    .unwrap_or(false);

    (_, p, d) if p <= d => SearchStrategy::ProgressiveQuantization { /* ... */ },

fn determine_smart_defaults(dimension: u32) -> Vec<QuantizationLevel> {
    match dimension {
        d if d < 64 => vec![QuantizationLevel::Int8],
        d if d < 128 => vec![QuantizationLevel::Binary, QuantizationLevel::Int8],
        d if d < 512 => vec![QuantizationLevel::Binary, QuantizationLevel::Int8, QuantizationLevel::Pq8],
        _ => vec![QuantizationLevel::Binary, QuantizationLevel::Pq4, QuantizationLevel::Pq8],
    }
}

==== Progressive Search Execution
Multi-stage refinement using collection's quantization levels:

[source,rust]
----
async fn execute_progressive_search(
    &self,
    ctx: &SearchContext,
    available_levels: &[QuantizationLevel],
) -> Result<Vec<SearchResult>> {
    let mut candidates = vec![];
    let mut stage = 1;
    
    // Stage 1: Binary filtering (if available)
    if available_levels.contains(&QuantizationLevel::Binary) {
        tracing::info!("🔍 Stage {}: Binary filtering", stage);
        candidates = self.binary_filter_search(ctx).await?;
        stage += 1;
    }
    
    // Stage 2: INT8 refinement (if available)
    if available_levels.contains(&QuantizationLevel::Int8) && !candidates.is_empty() {
        tracing::info!("🔍 Stage {}: INT8 refinement on {} candidates", stage, candidates.len());
        candidates = self.int8_refine_search(ctx, candidates).await?;
        stage += 1;
    }
    
    // Stage 3: PQ refinement (if available)
    if available_levels.iter().any(|l| matches!(l, QuantizationLevel::Pq4 | QuantizationLevel::Pq8)) {
        tracing::info!("🔍 Stage {}: PQ refinement on {} candidates", stage, candidates.len());
        candidates = self.pq_refine_search(ctx, candidates).await?;
        stage += 1;
    }
    
    // Stage 4: Full precision reranking
    tracing::info!("🔍 Stage {}: Full precision reranking of {} candidates", stage, candidates.len());
    let final_results = self.fp32_rerank_search(ctx, candidates).await?;
    
    tracing::info!("✅ Progressive search completed in {} stages", stage);
    Ok(final_results)
}
----

=== Cost Factors

==== Index Search Cost Factors
* Index type and size
* Query vector complexity
* Hardware capabilities (SIMD, GPU availability)
* Memory hierarchy (L1/L2 cache, RAM, storage)

==== Progressive Search Cost Factors
* Number of quantization stages
* Candidate reduction ratio at each stage
* Quantization/dequantization overhead
* Memory access patterns

==== Direct Search Cost Factors
* Dataset size and storage layout
* Filter selectivity and complexity
* I/O bandwidth and latency
* Parallel processing capabilities
