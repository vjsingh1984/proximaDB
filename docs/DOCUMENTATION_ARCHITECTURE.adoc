== Overview

This document defines the modular, streamlined documentation architecture for ProximaDB, eliminating duplication and establishing clear content boundaries.

== Core Principles

. **Single Source of Truth**: Each concept documented in exactly one canonical location
. **Reference, Don't Duplicate**: High-level docs reference detailed implementation docs
. **Modular Structure**: Documentation organized by audience and purpose
. **Proximity to Code**: Implementation details live with the code they document

== Content Boundaries

=== docs/ (High-Level)

**Purpose**: User-facing documentation answering "what" and "why"

**Content**:
- Feature overviews and capabilities
- Usage guides and tutorials
- Configuration examples
- Architecture diagrams (system-level)
- Performance characteristics (benchmarks)
- Operations procedures

**Audience**: Users, operators, decision-makers

**Examples**:
- "How to choose between storage engines" (docs/02-guides/engine-selection.adoc)
- "SST vs VIPER: When to use each" (docs/07-architecture/storage-layer.adoc)
- "Performance tuning guide" (docs/05-performance/optimization-guide.adoc)

=== src/*/README.adoc (Implementation Details)

**Purpose**: Developer documentation answering "how"

**Content**:
- Implementation architecture
- Data structures and algorithms
- Code organization and modules
- Internal APIs and interfaces
- Development guidelines for the module

**Audience**: Contributors, developers modifying code

**Examples**:
- "SST ProximaBlocks internal format" (src/storage/engines/impls/sst/README.adoc)
- "VIPER Parquet schema design" (src/storage/engines/impls/viper/README.adoc)
- "AXIS EventLog coordination protocol" (src/index/axis/README.adoc)

== Migration Strategy

=== Phase 1: Consolidate Storage Engine Docs

**Action**: Merge duplicate docs

. **Keep**: `src/storage/engines/impls/*/README.adoc` (implementation details)
. **Transform**: `docs/storage/*-engine-deep-dive.adoc` → `docs/07-architecture/storage-layer.adoc` (overview)
. **Delete**: Duplicate deep-dive files after consolidation

**Result**: Single source of truth per engine

=== Phase 2: Merge Implementation Directories

**Action**: Consolidate scattered implementation docs

. **Merge**: `docs/implementation/` → `docs/09-roadmap/implementation/`
. **Update**: All cross-references

**Result**: Single location for implementation planning

=== Phase 3: Consolidate Performance Docs

**Action**: Merge performance and benchmarks

. **Merge**: `docs/benchmarks/` → `docs/05-performance/`
. **Structure**:
   - `overview.adoc` - Performance summary
   - `benchmark-suite.adoc` - Benchmark methodology and results
   - `optimization-guide.adoc` - Tuning recommendations
   - `hardware-tuning.adoc` - Hardware-specific optimizations

**Result**: Unified performance documentation

=== Phase 4: Restructure Technical/Architecture

**Action**: Clarify architecture vs implementation

. **Consolidate**: `docs/technical/` + `docs/architecture/` → `docs/07-architecture/`
. **Split**: Keep overviews in docs/, details in src/
. **Pattern**: Each architecture doc references corresponding src/ modules

**Result**: Clear layered documentation

== Documentation Workflow

=== For Feature Development

. **Implementation**: Document in `src/MODULE/README.adoc`
. **User Guide**: Add usage guide to `docs/02-guides/`
. **Architecture**: Update `docs/07-architecture/` if system-level changes
. **API Reference**: Update `docs/03-reference/` if API changes

=== For Documentation Updates

. **Identify**: Which tier does this content belong to?
. **Check**: Does canonical documentation already exist?
. **Update**: Modify canonical source, update cross-references
. **Validate**: Run `scripts/validate_docs.sh`

== Validation

The validation script checks:

. **No Broken Links**: All cross-references resolve
. **No Duplicates**: Content exists in single canonical location
. **Structure**: Files in correct tier directories
. **Cross-References**: docs/ ↔ src/ links are bidirectional

Run validation:

[source,bash]
----
./scripts/validate_docs.sh
----

== Benefits

. **Reduced Maintenance**: Update once, reference everywhere
. **Clear Ownership**: Each doc has clear purpose and audience
. **Better Discovery**: Logical structure, clear navigation
. **Faster Updates**: Know exactly where to update content
. **No Drift**: Implementation docs live with code
