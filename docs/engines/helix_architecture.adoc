== Overview

HELIX (High-Efficiency Locality-Indexed eXecution) is a sophisticated disk-only LSM storage engine that leverages PCA dimensionality reduction and Hilbert curve clustering to physically co-locate similar vectors on disk, enabling aggressive pruning during query execution.

== Core Architecture Components

=== 1. PCA Dimensionality Reduction

The PCA module reduces high-dimensional vectors to a lower-dimensional space while preserving the most important variance:

[source,asciiart]
----
    Original Space (1536D)           PCA Transform              Reduced Space (16D)
    
    ┌─────────────────┐            ┌──────────────┐          ┌──────────────┐
    │  v₁ v₂ ... v₁₅₃₆│  ────────> │ Eigenvectors │ ──────>  │ p₁ p₂ ... p₁₆│
    └─────────────────┘            └──────────────┘          └──────────────┘
           1536D                      Top 16 components              16D
    
    Variance Preserved: ~95%
    Memory Reduction: 96x
    Projection Time: ~45μs
----

=== 2. Hilbert Curve Mapping

The Hilbert curve maps the reduced multi-dimensional space to a single dimension while preserving locality:

[source,mermaid]
----
graph LR
    subgraph "2D Hilbert Curve Example"
        A[0,0] --> B[0,1]
        B --> C[1,1]
        C --> D[1,0]
        D --> E[2,0]
        E --> F[2,1]
        F --> G[3,1]
        G --> H[3,0]
    end
    
    subgraph "Linearization"
        SEQ[0 → 1 → 2 → 3 → 4 → 5 → 6 → 7]
    end
    
    A -.->|Maps to| SEQ
----

**16D Hilbert Properties:**
- Bits per dimension: 16 (configurable)
- Total key space: 2^256
- Locality preservation: ~85%
- Encoding time: 3.2μs

=== 3. LSM Tree Structure

HELIX uses a leveled LSM tree with Hilbert-sorted SSTables:

[source,asciiart]

    │ (Not in      │ ───────────────>  │  │SST₁ │ │SST₂ │ │SST₃ │   │
    │  HELIX)      │                   │  └─────┘ └─────┘ └─────┘   │
    └──────────────┘                   └──────────────────────────────┘

=== 6. Zone Maps

Zone maps provide dimension-level statistics for fine-grained pruning:

[source,asciiart]
----
    Block 1 Zone Map              Block 2 Zone Map
    ┌─────────────────┐          ┌─────────────────┐
    │ Dim 0: [-1, 1]  │          │ Dim 0: [0, 2]   │
    │ Dim 1: [-2, 0]  │          │ Dim 1: [1, 3]   │
    │ Dim 2: [0, 3]   │          │ Dim 2: [-1, 1]  │
    │ ...             │          │ ...             │
    │ Dim 15: [-1, 2] │          │ Dim 15: [0, 4]  │
    └─────────────────┘          └─────────────────┘
            │                             │
            └─────────────┬───────────────┘
                          ↓
                   Query Vector
                  q = [0.5, 2, 0, ...]
                          │
                    Pruning Decision
                          ↓
                 Block 1: ✗ (Dim 1 out of range)
                 Block 2: ✓ (All dims overlap)
----

    EventLog->>HELIX: Process Flush

    HELIX->>HELIX: Compute Hilbert Key
    HELIX->>Disk: Write SSTable (L0)
    
    EventLog->>AXIS: Index Update Event
    AXIS->>AXIS: Update Indexes
    
    Note over HELIX: Compaction Triggered
    HELIX->>HELIX: Merge & Sort by Hilbert
    HELIX->>HELIX: Apply Liquid Clustering
    HELIX->>Disk: Write Compacted SSTable
----

    HELIX-->>Client: Search Results

== Best Practices

=== 1. Initial Setup
- Train PCA model on representative sample (10-20% of data)
- Start with default 16 PCA dimensions and 16 Hilbert bits
- Enable liquid clustering for dynamic workloads

=== 2. Performance Tuning
- Monitor pruning ratio - if <70%, increase PCA dimensions
- Watch PCA drift - retrain if >0.3
- Adjust cache size based on working set

=== 3. Maintenance
- Schedule PCA retraining during low traffic
- Monitor compaction frequency and adjust triggers
- Track hot regions and consider partitioning

== Summary

HELIX provides a sophisticated disk-optimized storage engine that:

1. **Reduces dimensions** via PCA (96% space savings)
2. **Preserves locality** via Hilbert curves (85% correlation)
3. **Prunes aggressively** (80-95% blocks skipped)
4. **Adapts dynamically** via liquid clustering
5. **Searches progressively** (5-stage refinement)
6. **Scales efficiently** (millions of vectors)

The combination of these techniques delivers **5-10x query performance** improvement over naive full scans while maintaining excellent compression and disk utilization.
