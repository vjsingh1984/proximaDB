RAPTOR is an **enhanced IVF (Inverted File) index** that achieves superior performance through:

1. **IVF Clustering**: k-means partitioning into k clusters
2. **Component Boosting**: 5-component distance formula for better recall
3. **Row-Aligned Storage**: Sequential I/O optimized for cloud storage
4. **Bloom Filters**: O(1) ID lookups with 1% false positive rate
5. **Hardware Optimization**: L3 cache-aware row group sizing

== Component Boosting Formula

[source]
----
┌─────────────────────────────────────────────────────────────────────┐
│                  5-Component Distance Calculation                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  D(v, q) = α₁·d₁ + α₂·d₂ + α₃·d₃ + β₁·d₄ + β₂·d₅                 │
│                                                                     │
│  Where:                                                             │
│  ┌─────────────────────────────────────────────────────────┐      │
│  │ d₁ = ||v - c_own||    : Distance to assigned centroid   │      │
│  │ d₂ = ||c_own - c_q||  : Inter-centroid distance         │      │
│  │ d₃ = σ(c_own)         : Cluster variance                │      │
│  │ d₄ = min(||c_i - c_j||): Minimum centroid separation    │      │
│  │ d₅ = max(||c_i - c_j||): Maximum centroid separation    │      │
│  └─────────────────────────────────────────────────────────┘      │
│                                                                     │
│  Default Weights:                                                   │
│  • α₁ = 0.5  (intra-cluster cohesion)                             │
│  • α₂ = 1.0  (boundary penalty)                                   │
│  • α₃ = 0.3  (compactness measure)                                │
│  • β₁ = 1.0  (cluster separation)                                 │
│  • β₂ = 1.0  (global structure)                                   │
└─────────────────────────────────────────────────────────────────────┘
----

            BF->>RAPTOR: Filter candidates

            RG->>Cache: Utilize L3 cache (45%)

        RAPTOR->>RAPTOR: Apply 5-component formula
        RAPTOR->>RAPTOR: Sort by boosted distance
    end
    
    RAPTOR->>User: Return top-k results

== Parameter Selection Algorithm

[source]
----
┌─────────────────────────────────────────────────────────────────────┐
│              RAPTOR Parameter Selection Algorithm                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Input: n vectors, d dimensions, L3 cache size                     │
│                                                                     │
│  Step 1: Calculate Optimal k (number of clusters)                  │
│  ┌────────────────────────────────────────────────┐               │
│  │ k_math = √n                    // Mathematical │               │
│  │ k_memory = L3_size / (d × 4)   // Memory bound │               │
│  │ k_io = max(32, n/10000)        // I/O bound    │               │
│  │ k = median(k_math, k_memory, k_io)             │               │
│  └────────────────────────────────────────────────┘               │
│                                                                     │
│  Step 2: Calculate Optimal p (row group size)                      │
│  ┌────────────────────────────────────────────────┐               │
│  │ p_cache = 0.45 × L3_size / (d × 4)             │               │
│  │ p_io = 1024                    // Min I/O block│               │
│  │ p_math = √n                    // Mathematical │               │
│  │ p = max(p_cache, p_io, min(p_math, 4096))     │               │
│  └────────────────────────────────────────────────┘               │
│                                                                     │
│  Step 3: Verify Complexity                                         │
│  ┌────────────────────────────────────────────────┐               │
│  │ complexity = k² + k×p                          │               │
│  │ optimal = 2×n                                  │               │
│  │ if complexity > 3×optimal:                     │               │
│  │     adjust k and p proportionally              │               │
│  └────────────────────────────────────────────────┘               │
│                                                                     │
│  Output: k clusters, p vectors per row group                       │
└─────────────────────────────────────────────────────────────────────┘

== Key Innovations

=== 1. IVF with Component Boosting
Unlike standard IVF that uses single centroid distance, RAPTOR computes 5 distance components for intelligent routing.

=== 2. Row-Aligned Storage
Sequential I/O pattern optimized for cloud storage (S3, GCS) with 4KB-64MB reads.

=== 3. Bloom Filter Integration
O(1) ID lookups with 180KB bloom filter handling 1M vectors at 1% false positive rate.

=== 4. Hardware-Aware Sizing
Dynamic row group sizing based on detected L3 cache for optimal memory utilization.

=== 5. Parallel-Friendly Design
Embarrassingly parallel clustering and search, unlike graph-based methods.

== Conclusion

RAPTOR is an **enhanced IVF implementation** that achieves superior performance through:

1. **Correct Classification**: IVF-based, not HNSW
2. **Mathematical Optimality**: O(√n) complexity with k=p=√n
3. **Hardware Awareness**: L3 cache optimization
4. **Cloud Optimized**: Sequential I/O patterns
5. **Production Ready**: Comprehensive testing and validation

The k²+p×(k+p) formula with component boosting provides both theoretical elegance and practical efficiency, making RAPTOR ideal for large-scale similarity search workloads.
