= ProximaDB Configuration Reference
:toc: left
:toclevels: 2
:imagesdir: ../diagrams/images

**Complete configuration guide for ProximaDB deployments.**

[IMPORTANT]
====
ProximaDB auto-configures optimal defaults. Most deployments only need to set 5-10 parameters.
====

== Quick Start Configurations

image::configuration-hierarchy.svg[Configuration Hierarchy, width=900, align=center]

=== Minimal Configuration
[source,toml]
----
# ProximaDB auto-detects and optimizes
[server]
bind_address = "0.0.0.0"

[api]
rest_port = 5678
grpc_port = 5679
----

=== Production Configuration
[source,toml]
----
[server]
bind_address = "0.0.0.0"
node_id = "proximadb-prod-1"
data_dir = "/data/proximadb"

[api]
rest_port = 5678
grpc_port = 5679
max_request_size_mb = 100
enable_tls = true

[storage]
metadata_url = "file:///data/proximadb/metadata"
[[storage.storage_locations]]
url = "file:///nvme/proximadb/hot"
weight = 10
[[storage.storage_locations]]
url = "s3://bucket/proximadb/cold"
weight = 1

[memory]
cache_size_mb = 4096
write_buffer_size_mb = 256

[performance]
num_threads = 0  # Auto-detect
enable_simd = true
enable_gpu = true
----

=== High-Performance Configuration
[source,toml]
----
[api]
grpc_port = 5679
grpc_compression = false  # Disable for lowest latency

[sst]
block_size_kb = 3072  # 3MB optimized for cloud
compression_algorithm = "lz4"  # Fastest
enable_bloom_filter = true

[viper]
compression_algorithm = "zstd"
compression_level = 6
enable_quantization = true

[memory]
cache_size_mb = 16384  # 16GB cache
memtable_size_mb = 1024  # 1GB write buffer

[performance]
read_threads = 32
write_threads = 16
compaction_threads = 8
----

== Core Configuration Sections

=== [server] - Server Settings

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| bind_address | "127.0.0.1" | Network interface ("0.0.0.0" for all)
| node_id | "proximadb-node-1" | Unique node identifier
| data_dir | "./data" | Primary data directory
|===

=== [api] - API Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| rest_port | 5678 | REST API port
| grpc_port | 5679 | gRPC port (3x faster)
| max_request_size_mb | 64 | Maximum request size
| timeout_seconds | 30 | Request timeout
| enable_tls | false | Enable TLS encryption
| rest_compression | false | REST compression (disable for debugging)
| grpc_compression | false | gRPC compression
|===

=== [storage] - Storage Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| metadata_url | "file://./metadata" | Metadata storage location
| storage_locations | [] | Array of storage tiers
| wal_dir | "./wal" | Write-ahead log directory
| enable_mmap | true | Memory-mapped I/O
|===

**Multi-Tier Storage Example:**
[source,toml]
----
[[storage.storage_locations]]
url = "file:///nvme/proximadb"  # Fast tier
weight = 10  # Higher weight = preferred

[[storage.storage_locations]]
url = "s3://bucket/proximadb"  # Cold tier
weight = 1
region = "us-east-1"
storage_class = "STANDARD_IA"
----

=== [memory] - Memory Management

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| cache_size_mb | 512 | Total cache size
| memtable_size_mb | 256 | Write buffer size
| block_cache_mb | 256 | SST block cache
| query_cache_mb | 128 | Query result cache
| filter_cache_mb | 64 | Bloom filter cache
|===

=== [performance] - Performance Tuning

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| num_threads | 0 | Worker threads (0=auto)
| read_threads | 16 | Read operation threads
| write_threads | 8 | Write operation threads
| compaction_threads | 4 | Background compaction
| enable_simd | true | SIMD acceleration
| enable_gpu | false | GPU acceleration
|===

== Storage Engine Configuration

=== [sst] - SST Engine (Row-Based)

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| block_size_kb | 3072 | SST block size (3MB)
| compression_algorithm | "lz4" | Compression (lz4, zstd, snappy, none)
| compression_level | 1 | Compression level (1-9)
| enable_bloom_filter | true | Bloom filters for fast lookups
| bloom_bits_per_key | 10 | Bloom filter precision
| compaction_style | "leveled" | Compaction strategy
|===

=== [viper] - VIPER Engine (Columnar)

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| compression_algorithm | "zstd" | Column compression
| compression_level | 6 | Compression level
| enable_quantization | false | Vector quantization
| quantization_type | "int8" | Quantization type (int8, pq8, pq4)
| row_group_size | 100000 | Parquet row group size
|===

=== [compaction] - Compaction Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| l0_file_threshold | 5 | Files in L0 before compaction
| l0_size_threshold_mb | 256 | MB in L0 before compaction
| level_multiplier | 2.0 | Threshold multiplier per level
| max_levels | 7 | Maximum compaction levels
| strategy | "hybrid" | Compaction strategy (count, size, hybrid)
| target_file_size_mb | 128 | Target output file size in MB
|===

**Compaction Strategy Details:**

* **count**: Triggers when file count exceeds threshold
* **size**: Triggers when total size exceeds threshold
* **hybrid**: Triggers when either count OR size exceeds threshold (recommended)

**Example Compaction Configuration:**
[source,toml]
----
[storage.compaction_config]
l0_file_threshold = 5          # Compact when 5+ files in L0
l0_size_threshold_mb = 256     # Or when L0 exceeds 256MB
level_multiplier = 2.0          # L1: 10 files/512MB, L2: 20 files/1GB
max_levels = 7                  # Support up to 7 levels
strategy = "hybrid"             # Use both count and size thresholds
target_file_size_mb = 128       # Create 128MB output files

# Engine-specific overrides (optional)
[storage.sst_config.compaction_config]
l0_file_threshold = 10          # SST can handle more small files
target_file_size_mb = 64        # Smaller files for faster reads

[storage.viper_config.compaction_config]
l0_size_threshold_mb = 512     # VIPER prefers batching more data
target_file_size_mb = 256       # Larger files for analytics
|===

== Advanced Configuration

=== [tiering] - AXIS Tiering

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_auto_tiering | true | Automatic data tiering
| hot_threshold_hours | 24 | Time before warm tier
| warm_threshold_days | 7 | Time before cold tier
| memory_pressure_threshold | 0.7 | Trigger emergency demotion
|===

=== [monitoring] - Observability

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_metrics | true | Prometheus metrics
| metrics_port | 9090 | Metrics endpoint
| log_level | "info" | Log level (debug, info, warn, error)
| enable_tracing | false | OpenTelemetry tracing
|===

=== [security] - Security Settings

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_auth | false | Authentication required
| auth_type | "token" | Auth type (token, oauth, ldap)
| encryption_at_rest | false | Encrypt stored data
| audit_logging | false | Audit all operations
|===

== Cloud-Specific Configuration

=== AWS S3 Storage
[source,toml]
----
[[storage.storage_locations]]
url = "s3://my-bucket/proximadb"
region = "us-east-1"
storage_class = "STANDARD_IA"
access_key_id = "${AWS_ACCESS_KEY_ID}"
secret_access_key = "${AWS_SECRET_ACCESS_KEY}"
----

=== Azure Blob Storage
[source,toml]
----
[[storage.storage_locations]]
url = "azblob://myaccount/proximadb"
access_tier = "Cool"
account_name = "${AZURE_STORAGE_ACCOUNT}"
account_key = "${AZURE_STORAGE_KEY}"
----

=== Google Cloud Storage
[source,toml]
----
[[storage.storage_locations]]
url = "gcs://my-bucket/proximadb"
storage_class = "NEARLINE"
credentials_path = "/path/to/service-account.json"
----

== Environment Variables

All configuration values can be overridden with environment variables:

```bash
PROXIMADB_SERVER_BIND_ADDRESS=0.0.0.0
PROXIMADB_API_REST_PORT=8080
PROXIMADB_API_GRPC_PORT=8081
PROXIMADB_MEMORY_CACHE_SIZE_MB=8192
```

== Configuration Best Practices

1. **Start Simple**: Use minimal config, add as needed
2. **Monitor First**: Enable metrics before tuning
3. **Test Changes**: One parameter at a time
4. **Document Custom**: Comment why you changed defaults
5. **Version Control**: Track config changes
