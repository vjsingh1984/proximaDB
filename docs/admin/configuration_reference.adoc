= ProximaDB Configuration Reference
:toc: left
:toclevels: 3
:imagesdir: ../diagrams/images

**Complete configuration guide for ProximaDB deployments.**

[IMPORTANT]
====
ProximaDB auto-configures optimal defaults. Most deployments only need to set 5-10 parameters.
====

== Quick Start Configurations

image::configuration-hierarchy.svg[Configuration Hierarchy, width=900, align=center]

=== Minimal Configuration
[source,toml]
----
# ProximaDB auto-detects and optimizes
[server]
bind_address = "0.0.0.0"

[api]
rest_port = 5678
grpc_port = 5679
----

=== Production Configuration
[source,toml]
----
[server]
bind_address = "0.0.0.0"
node_id = "proximadb-prod-1"
data_dir = "/data/proximadb"

[api]
rest_port = 5678
grpc_port = 5679
max_request_size_mb = 100
enable_tls = true

[storage]
metadata_url = "file:///data/proximadb/metadata"
[[storage.storage_locations]]
url = "file:///nvme/proximadb/hot"
weight = 10
[[storage.storage_locations]]
url = "s3://bucket/proximadb/cold"
weight = 1

[memory]
cache_size_mb = 4096
write_buffer_size_mb = 256

[compute]
enable_simd = true
enable_gpu = true

[performance]
num_threads = 0  # Auto-detect
----

=== High-Performance Configuration
[source,toml]
----
[api]
grpc_port = 5679
grpc_compression = false  # Disable for lowest latency

[storage]
[storage.sst_config]
block_size_kb = 3072  # 3MB optimized for cloud
compression = "lz4"  # Fastest
enable_bloom_filter = true

[storage.viper_config]
compression = "zstd"
compression_level = 6
enable_quantization = true

[memory]
cache_size_mb = 16384  # 16GB cache
memtable_size_mb = 1024  # 1GB write buffer

[performance]
read_threads = 32
write_threads = 16
compaction_threads = 8
----

== Core Configuration Sections

=== [server] - Server Settings

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| bind_address
| "127.0.0.1"
| Network interface to bind to. Use "0.0.0.0" to listen on all interfaces.

| node_id
| "proximadb-node-1"
| A unique identifier for this node.

| data_dir
| "./data"
| The primary directory for storing data.
|===

=== [api] - API Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| rest_port
| 5678
| The port for the REST API.

| grpc_port
| 5679
| The port for the gRPC API. gRPC is typically 3x faster than REST.

| max_request_size_mb
| 64
| The maximum size of a request body in megabytes.

| timeout_seconds
| 30
| The timeout for API requests in seconds.

| enable_tls
| false
| Enable TLS encryption for the API.

| rest_compression
| false
| Enable compression for REST responses. Disable for debugging.

| grpc_compression
| false
| Enable compression for gRPC responses.
|===

=== [storage] - Storage Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| metadata_url
| "file://./metadata"
| The URL for the metadata store. This can be a local file path or a cloud storage URL.

| storage_locations
| `[]`
| An array of storage tiers. Each tier has a URL and a weight.

| wal_dir
| "./wal"
| The directory for the Write-Ahead Log.

| enable_mmap
| true
| Enable memory-mapped I/O for faster file access.
|===

==== Multi-Tier Storage Example
[source,toml]
----
[[storage.storage_locations]]
url = "file:///nvme/proximadb"  # Fast tier
weight = 10  # Higher weight means it's preferred

[[storage.storage_locations]]
url = "s3://bucket/proximadb"  # Cold tier
weight = 1
region = "us-east-1"
storage_class = "STANDARD_IA"
----

=== [memory] - Memory Management

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| cache_size_mb
| 512
| The total size of the cache in megabytes.

| memtable_size_mb
| 256
| The size of the write buffer in megabytes.

| block_cache_mb
| 256
| The size of the SST block cache in megabytes.

| query_cache_mb
| 128
| The size of the query result cache in megabytes.

| filter_cache_mb
| 64
| The size of the bloom filter cache in megabytes.
|===

=== [performance] - Performance Tuning

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| num_threads
| 0
| The number of worker threads. 0 means auto-detect based on the number of CPU cores.

| read_threads
| 16
| The number of threads for read operations.

| write_threads
| 8
| The number of threads for write operations.

| compaction_threads
| 4
| The number of threads for background compaction.
|===

=== [compute] - Compute Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_simd
| true
| Enable SIMD acceleration for distance calculations.

| enable_gpu
| false
| Enable GPU acceleration for distance calculations.
|===

== Storage Engine Configuration

=== [storage.sst_config] - SST Engine (Row-Based)

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| block_size_kb
| 3072
| The size of the SST blocks in kilobytes. 3MB is optimized for cloud storage.

| compression
| "lz4"
| The compression algorithm to use. Options are "lz4", "zstd", "snappy", and "none".

| compression_level
| 1
| The compression level to use (1-9).

| enable_bloom_filter
| true
| Enable bloom filters for faster key lookups.

| bloom_bits_per_key
| 10
| The number of bits per key in the bloom filter.
|===

=== [storage.viper_config] - VIPER Engine (Columnar)

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| compression
| "zstd"
| The compression algorithm to use for columns.

| compression_level
| 6
| The compression level to use.

| enable_quantization
| false
| Enable vector quantization.

| quantization_type
| "int8"
| The type of quantization to use ("int8", "pq8", "pq4").

| row_group_size
| 100000
| The size of the row groups in Parquet files.
|===

=== [storage.compaction_config] - Compaction Configuration

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| l0_file_threshold
| 5
| The number of files in L0 before compaction is triggered.

| l0_size_threshold_mb
| 256
| The size of L0 in megabytes before compaction is triggered.

| level_multiplier
| 2.0
| The multiplier for the threshold for each level.

| max_levels
| 7
| The maximum number of compaction levels.

| strategy
| "hybrid"
| The compaction strategy to use ("count", "size", "hybrid").

| target_file_size_mb
| 128
| The target size of the output files in megabytes.
|===

==== Compaction Strategy Details

* *count*: Triggers when the number of files exceeds the threshold.
* *size*: Triggers when the total size of the files exceeds the threshold.
* *hybrid*: Triggers when either the count or the size exceeds the threshold (recommended).

==== Example Compaction Configuration
[source,toml]
----
[storage.compaction_config]
l0_file_threshold = 5          # Compact when 5+ files in L0
l0_size_threshold_mb = 256     # Or when L0 exceeds 256MB
level_multiplier = 2.0          # L1: 10 files/512MB, L2: 20 files/1GB
max_levels = 7                  # Support up to 7 levels
strategy = "hybrid"             # Use both count and size thresholds
target_file_size_mb = 128       # Create 128MB output files

# Engine-specific overrides (optional)
[storage.sst_config.compaction_config]
l0_file_threshold = 10          # SST can handle more small files
target_file_size_mb = 64        # Smaller files for faster reads

[storage.viper_config.compaction_config]
l0_size_threshold_mb = 512     # VIPER prefers batching more data
target_file_size_mb = 256       # Larger files for analytics
----

== Advanced Configuration

=== [tiering] - AXIS Tiering

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_auto_tiering
| true
| Enable automatic data tiering.

| hot_threshold_hours
| 24
| The time in hours before data is moved to the warm tier.

| warm_threshold_days
| 7
| The time in days before data is moved to the cold tier.

| memory_pressure_threshold
| 0.7
| The memory pressure threshold that triggers emergency demotion of data.
|===

=== [monitoring] - Observability

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_metrics
| true
| Enable Prometheus metrics.

| metrics_port
| 9090
| The port for the metrics endpoint.

| log_level
| "info"
| The log level ("debug", "info", "warn", "error").

| enable_tracing
| false
| Enable OpenTelemetry tracing.
|===

=== [security] - Security Settings

[cols="1,1,3", options="header"]
|===
| Parameter | Default | Description

| enable_auth
| false
| Require authentication for all requests.

| auth_type
| "token"
| The authentication type to use ("token", "oauth", "ldap").

| encryption_at_rest
| false
| Encrypt data at rest.

| audit_logging
| false
| Log all operations for auditing purposes.
|===

== Cloud-Specific Configuration

=== AWS S3 Storage
[source,toml]
----
[[storage.storage_locations]]
url = "s3://my-bucket/proximadb"
region = "us-east-1"
storage_class = "STANDARD_IA"
access_key_id = "${AWS_ACCESS_KEY_ID}"
secret_access_key = "${AWS_SECRET_ACCESS_KEY}"
----

access_tier = "Cool"
account_name = "${AZURE_STORAGE_ACCOUNT}"
account_key = "${AZURE_STORAGE_KEY}"
----

[source,toml]
----
[[storage.storage_locations]]
url = "gcs://my-bucket/proximadb"
storage_class = "NEARLINE"
credentials_path = "/path/to/service-account.json"
----

== Environment Variables

All configuration values can be overridden with environment variables. The environment variable name is the uppercase, underscore-separated path to the configuration value, prefixed with `PROXIMADB_`.

For example:
[source,bash]
----
PROXIMADB_SERVER_BIND_ADDRESS=0.0.0.0
PROXIMADB_API_REST_PORT=8080
PROXIMADB_API_GRPC_PORT=8081
PROXIMADB_MEMORY_CACHE_SIZE_MB=8192
----

== Configuration Best Practices

. *Start Simple*: Use the minimal configuration and add parameters as needed.
. *Monitor First*: Enable metrics before you start tuning performance.
. *Test Changes*: Change one parameter at a time and test the impact.
. *Document Customizations*: Add comments to your configuration file to explain why you have changed the default values.
. *Version Control*: Keep your configuration files in version control.
