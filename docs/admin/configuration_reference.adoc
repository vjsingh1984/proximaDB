= ProximaDB Complete Configuration Reference
:toc: left
:toclevels: 3
:icons: font
:imagesdir: ../diagrams/images

**Comprehensive guide to all ProximaDB configuration options with behavior, performance impact, and deployment recommendations.**

[IMPORTANT]
====
This document covers ALL available configuration options. Most deployments only need to set 5-10 key parameters. ProximaDB auto-configures optimal defaults based on your environment.
====

== Quick Configuration Guide

=== Minimal Configuration (Auto-Optimized)
[source,toml]
----
# Minimal config - ProximaDB auto-detects and optimizes
[server]
bind_address = "0.0.0.0"

[api]
rest_port = 5678
grpc_port = 5679
----

=== Typical Production Configuration
[source,toml]
----
[server]
bind_address = "0.0.0.0"
node_id = "proximadb-prod-1"
data_dir = "/data/proximadb"

[api]
rest_port = 5678
grpc_port = 5679
max_request_size_mb = 100
enable_tls = true

[sst]
block_size_kb = 2048        # 2MB default, adjust for your storage
compression_algorithm = "zstd"
compression_level = 3

[memory]
memtable_size_mb = 256
cache_size_mb = 4096

[performance]
read_threads = 16
write_threads = 8
----

== Configuration Best Practices

=== By Workload Type

==== OLTP (Transactional)
* Small block sizes (256-512 KB)
* More write threads
* Smaller memtables
* Fast compression (LZ4)
* SST engine

==== OLAP (Analytical)
* Large block sizes (2-8 MB)
* More read threads
* Large caches
* High compression (ZSTD-6+)
* VIPER engine

==== Mixed Workload
* Medium block sizes (1-2 MB)
* Balanced thread allocation
* Multi-engine deployment
* Adaptive caching
* AXIS tiering

=== By Deployment Size

==== Small (< 10M vectors)
* Conservative memory settings
* Default thread counts
* Single engine
* Basic monitoring

==== Medium (10-100M vectors)
* Increased cache sizes
* More threads
* Consider multi-engine
* Full monitoring

==== Large (> 100M vectors)
* Maximum cache allocation
* High thread counts
* Multi-engine + tiering
* Distributed deployment

== Troubleshooting Guide

=== Common Issues and Solutions

[cols="3,3,2", options="header"]
|===
| Symptom | Likely Cause | Solution

| High latency
| Insufficient cache
| Increase `cache_size_mb`

| Write stalls
| Small memtables
| Increase `memtable_size_mb`

| OOM errors
| Over-allocation
| Reduce cache/memtable sizes

| Slow compaction
| Few threads
| Increase `compaction_threads`

| High CPU usage
| Heavy compression
| Reduce `compression_level`

| Disk full
| No tiering
| Enable AXIS tiering

| Network timeouts
| Small timeouts
| Increase timeout values

| Poor throughput
| Few threads
| Increase thread counts
|===
