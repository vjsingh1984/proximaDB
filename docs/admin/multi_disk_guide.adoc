ProximaDB's multi-disk persistence system for enhanced performance, scalability, and fault tolerance.

== Architecture Benefits

* **Parallel I/O Operations**: Concurrent read/write across multiple disks
* **Load Distribution**: Weighted collection assignment across storage locations
* **Fault Tolerance**: Disk failure isolation with automatic recovery
* **Multi-Cloud Support**: AWS S3, Azure Blob, Google Cloud Storage
* **Hybrid Deployments**: Local high-performance with cloud backup

== Storage Assignment Model

=== Collection-Level Assignment
Each collection is assigned to a single storage location at creation time:

1. **Automatic Assignment**: System selects location based on configured strategy
2. **User-Specified**: Collection can request specific location via `storage_location` parameter
3. **Unified Storage**: All collection data (WAL, data, indexes) stored together

=== Directory Structure
Once assigned, a collection's data is organized as:
```
{base_url}/{collection_id}/
├── wal/          # Write-ahead logs
├── data/         # SSTable or Parquet files
└── indexes/      # Index structures
```

Example for collection `abc123` on disk1:
```
file:///data/disk1/proximadb/abc123/
├── wal/
├── data/
└── indexes/
```

=== Assignment Strategies

* **Random**: Equal probability selection
* **Weighted**: Selection based on configured weights
* **Hash**: Consistent hashing of collection ID
* **RoundRobin**: Sequential assignment
* **Tagged**: Match collection requirements to storage tags

== Core Configuration

=== Basic Multi-Disk Setup

[source,toml]
----
[storage]
# Single metadata URL for consistency (on fastest disk)
metadata_url = "file:///data/disk1/metadata"

# Multiple storage locations for collections
# Each collection gets assigned one location at creation time
# The location hosts: {base_url}/{collection_id}/{wal,data,indexes}/
[[storage.storage_locations]]
url = "file:///data/disk1/proximadb"  # Fast NVMe disk
weight = 3  # Higher weight = higher probability of selection
tags = ["fast", "nvme", "primary"]

[[storage.storage_locations]]
url = "file:///data/disk2/proximadb"  # Secondary SSD
weight = 2  # Medium weight
tags = ["ssd", "secondary"]

[[storage.storage_locations]]
url = "file:///data/disk3/proximadb"  # Capacity HDD
weight = 1  # Lower weight
tags = ["hdd", "capacity", "archive"]

# Assignment configuration
[storage.assignment_config]
strategy = "weighted"  # Options: "random", "weighted", "hash", "roundrobin"
affinity = true       # Keep WAL/data/indexes together per collection

# WAL configuration (applies to all collections)
[storage.wal_config]
memory_flush_size_bytes = 16777216  # 16MB
global_flush_threshold = 536870912  # 512MB
write_buffer_size_mb = 8192         # 8GB global write buffer
sync_mode = "sync"                  # Options: "sync", "async", "none"

# Storage engine settings
mmap_enabled = true
cache_size_mb = 512
bloom_filter_bits = 10
----

=== Configuration Options

**Disk Types:**
* `NvmeSsd`: Highest performance (max_iops = 100000)
* `SataSsd`: High performance (max_iops = 50000)  
* `Hdd`: High capacity (max_iops = 1000)
* `NetworkStorage`: Cloud storage (latency_ms = 5.0)

=== Supported Providers

**AWS S3:**
* URL: `s3://bucket-name/prefix`
* Authentication: IAM roles, use_iam_role = true

**Azure Blob:**
* URL: `adls://account.dfs.core.windows.net/container/prefix`  
* Authentication: Managed Identity, use_managed_identity = true

**Google Cloud:**
* URL: `gcs://bucket-name/prefix`
* Authentication: Workload Identity, use_workload_identity = true

== Deployment Scenarios

=== Development Environment
```toml
[storage]
metadata_url = "file:///tmp/proximadb/metadata"

[[storage.storage_locations]]
url = "file:///tmp/proximadb/storage"
weight = 1
tags = ["dev", "local"]
```

=== Production On-Premises
```toml
[storage]
metadata_url = "file:///mnt/nvme1/proximadb/metadata"

[[storage.storage_locations]]
url = "file:///mnt/nvme1/proximadb"
weight = 3
tags = ["nvme", "fast", "primary"]

[[storage.storage_locations]]
url = "file:///mnt/nvme2/proximadb"
weight = 3
tags = ["nvme", "fast", "secondary"]

[[storage.storage_locations]]
url = "file:///mnt/sata1/proximadb"
weight = 1
tags = ["sata", "capacity", "archive"]
```

=== Hybrid Cloud Deployment  
```toml
[storage]
metadata_url = "file:///mnt/nvme1/metadata"

[[storage.storage_locations]]
url = "file:///mnt/nvme1/proximadb"
weight = 5  # Prefer local for hot data
tags = ["local", "nvme", "hot"]

[[storage.storage_locations]]
url = "s3://proximadb-storage/collections"
weight = 1  # Use cloud for cold data
tags = ["cloud", "s3", "cold"]

# Cloud authentication
[storage.cloud_auth]
aws_use_iam_role = true
aws_region = "us-west-2"
```

== Performance Tuning

* **NVMe Optimization**: Use max_iops = 1000000 for high-performance disks
* **Network Storage**: Use latency_ms = 5.0, conservative capacity settings
* **Capacity Management**: Adjust warning_threshold_percent based on disk type (95% for NVMe, 80% for network)

== Monitoring and Maintenance

=== Health Check Commands
```bash
# Server health and storage usage
curl http://localhost:5678/health
curl http://localhost:5678/admin/storage/usage

# Check disk usage across all configured disks  
for disk in /data/disk1 /data/disk2 /data/disk3; do
  echo "=== $disk ==="
  df -h $disk
done
```

== Troubleshooting

=== Common Issues

* **Permission Problems**: Verify directory permissions with `ls -la /data/disk*/storage`
* **URL Configuration Errors**: Use correct format `file:///data/disk1/storage` (not `file://data/disk1/storage`)
* **Disk Failure Recovery**: Replace disk at same mount point, service auto-discovers new layout
* **Performance Issues**: Use `iostat`, `iotop` to identify I/O bottlenecks

== Best Practices

* **Configuration**: Use consistent path conventions, separate configs for environments, version control
* **Operations**: Regular SMART checks, capacity planning, recovery testing, performance baselines
* **Security**: Enable disk/cloud encryption, proper file system permissions, audit logging
