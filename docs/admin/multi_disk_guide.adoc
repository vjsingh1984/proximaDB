**Multi-disk persistence for performance, scalability, and fault tolerance.**

image::multi-disk-deployment-detail-modular.svg[Multi-Disk Architecture, width=800]

== Key Benefits

* **Parallel I/O**: Concurrent operations across disks
* **Load Distribution**: Weighted collection assignment
* **Fault Tolerance**: Disk failure isolation
* **Multi-Cloud**: AWS S3, Azure Blob, GCS support
* **Hybrid Deployment**: Local + cloud backup

== Storage Assignment

=== Collection-Level Assignment
Each collection assigned to one storage location at creation:
* **Automatic**: System selects based on strategy
* **User-Specified**: Via `storage_location` parameter
* **Unified**: WAL, data, indexes stored together

=== Directory Structure
```
Collection Assignment Flow:
┌──────────────────────────────────────────────────────┐
│              New Collection Created                   │
│                 "my_collection"                       │
└───────────────────┬──────────────────────────────────┘
                    ▼
┌──────────────────────────────────────────────────────┐
│          Assignment Strategy (Weighted)               │
│  ┌────────────┬────────────┬────────────┐          │
│  │  Disk1: 3  │  Disk2: 2  │  Disk3: 1  │          │
│  │   (50%)    │   (33%)    │   (17%)    │          │
│  └────────────┴────────────┴────────────┘          │
└───────────────────┬──────────────────────────────────┘
                    ▼
              [Selected: Disk1]
                    ▼
┌──────────────────────────────────────────────────────┐
│              Final Storage Layout                     │
│                                                       │
│  /data/disk1/proximadb/my_collection/                │
│  ├── wal/          # Write-ahead logs                │
│  ├── data/         # SSTable or Parquet files        │
│  └── indexes/      # Index structures                │
└──────────────────────────────────────────────────────┘
```

== Configuration

=== Basic Multi-Disk Setup
```toml
[storage]
metadata_url = "file:///data/disk1/metadata"

[[storage.storage_locations]]
url = "file:///data/disk1/proximadb"  # NVMe
weight = 3  # Higher = more likely
tags = ["fast", "nvme"]

[[storage.storage_locations]]
url = "file:///data/disk2/proximadb"  # SSD
weight = 2
tags = ["ssd"]

[[storage.storage_locations]]
url = "file:///data/disk3/proximadb"  # HDD
weight = 1
tags = ["capacity"]

[storage.assignment_config]
strategy = "weighted"  # random|weighted|hash|roundrobin
affinity = true       # Keep collection data together
```

=== Cloud Storage
```toml
# AWS S3
[[storage.storage_locations]]
url = "s3://bucket/prefix"
weight = 1
aws_use_iam_role = true

# Azure Blob
[[storage.storage_locations]]
url = "adls://account.dfs.core.windows.net/container"
use_managed_identity = true

# Google Cloud
[[storage.storage_locations]]
url = "gcs://bucket/prefix"
use_workload_identity = true
```

== Deployment Scenarios

=== Development
```toml
[[storage.storage_locations]]
url = "file:///tmp/proximadb/storage"
weight = 1
```

=== Production On-Premises
```toml
[[storage.storage_locations]]
url = "file:///mnt/nvme1/proximadb"
weight = 3
tags = ["nvme", "primary"]

[[storage.storage_locations]]
url = "file:///mnt/sata1/proximadb"
weight = 1
tags = ["capacity", "archive"]
```

=== Hybrid Cloud
```toml
[[storage.storage_locations]]
url = "file:///mnt/nvme1/proximadb"
weight = 5  # Prefer local
tags = ["local", "hot"]

[[storage.storage_locations]]
url = "s3://proximadb-storage/collections"
weight = 1  # Cloud for cold
tags = ["cloud", "cold"]
```

== Performance Tuning

=== Disk Types
* **NvmeSsd**: 100K IOPS max
* **SataSsd**: 50K IOPS max
* **Hdd**: 1K IOPS max
* **NetworkStorage**: 5ms latency

=== Optimization Tips
* NVMe: Set max_iops = 1000000
* Network: Use conservative capacity
* Thresholds: 95% NVMe, 80% network

== Monitoring

```bash
# Health check
curl http://localhost:5678/health
curl http://localhost:5678/admin/storage/usage

# Disk usage
for disk in /data/disk1 /data/disk2; do
  df -h $disk
done

# I/O statistics
iostat -x 1
```

== Troubleshooting

=== Common Issues
* **Permissions**: Check with `ls -la`
* **URL Format**: Use `file:///` (three slashes)
* **Disk Failure**: Replace at same mount point
* **Performance**: Use `iostat`, `iotop`

== Best Practices

* Use consistent path conventions
* Separate configs per environment
* Regular SMART checks
* Capacity planning (80% max)
* Enable encryption
* Test recovery procedures

== URL Schemes

* **Local**: `file:///path/to/directory`
* **AWS S3**: `s3://bucket/prefix`
* **Azure**: `adls://account.dfs.core.windows.net/container`
* **GCS**: `gcs://bucket/prefix`
