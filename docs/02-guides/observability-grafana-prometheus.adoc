**Comprehensive observability platform design for ProximaDB with Prometheus scraping and Grafana dashboards**

---

## Overview

ProximaDB can serve as both a **producer** and **consumer** of observability data:

1. **ProximaDB exposes its own metrics** via Prometheus endpoint for Grafana
2. **ProximaDB ingests external observability events** (logs, metrics, traces)
3. **Grafana queries ProximaDB** as a datasource for dashboards

This document outlines the architecture, implementation plan, and configuration for making ProximaDB a comprehensive observability platform.

### Data Flow

1. **External Sources → ProximaDB Ingestion**:
   - OpenTelemetry SDKs → OTLP adapter (gRPC/HTTP)
   - Prometheus → remote_write protocol
   - Syslog servers → Syslog adapter

2. **ProximaDB Storage**:
   - Metrics → Time-series rollups (1m/5m/1h/1d aggregates)
   - Logs → Tantivy full-text index
   - Traces → Span graph with parent-child relationships

3. **Grafana Queries**:
   - Prometheus scraping → `/metrics` endpoint
   - Datasource queries → JSON API with PromQL support

**Deliverable - OTLP Adapter**:
```rust
// src/observability/ingestion/adapters/otlp.rs

use tonic::transport::Server;
use crate::proto::opentelemetry::proto::collector::logs::v1::logs_service_server::LogsServiceServer;

pub struct OtlpAdapter {
    logs_rx: mpsc::Receiver<LogEntry>,
    metrics_rx: mpsc::Receiver<MetricData>,
    traces_rx: mpsc::Receiver<SpanData>,
}

impl OtlpAdapter {
    pub async fn start(&self) -> Result<()> {
        // Start gRPC server on :4317
        let grpc_server = Server::builder()
            .add_service(LogsServiceServer::new(self.clone()))
            .serve("[::]:4317".parse()?);

        // Start HTTP server on :4318
        let http_server = axum::Server::bind(&"[::]:4318".parse()?)
            .serve(otlp_http_router().into_make_service());

        tokio::select! {
            _ = grpc_server => {}
            _ = http_server => {}
        }

        Ok(())
    }
}
```

**Deliverable - Query API**:
```rust
// src/network/rest/v1/observability.rs

#[derive(Deserialize)]
pub struct GrafanaQueryRequest {
    pub from: i64,
    pub to: i64,
    pub queries: Vec<TimeSeriesQuery>,
}

#[derive(Deserialize)]
pub struct TimeSeriesQuery {
    pub ref_id: String,
    pub query: String,  // PromQL
    pub step_ms: Option<u64>,
}

#[derive(Serialize)]
pub struct GrafanaQueryResponse {
    pub data: Vec<TimeSeriesData>,
}

pub async fn query_promql(
    State(db): State<Arc<ProximaDB>>,
    Json(req): Json<GrafanaQueryRequest>,
) -> Json<GrafanaQueryResponse> {
    // Parse PromQL
    let parsed = parse_promql(&req.queries[0].query)?;

    // Execute query
    let results = db.observability.query_time_series(
        parsed,
        req.from,
        req.to,
        req.queries[0].step_ms,
    ).await?;

    // Format for Grafana
    Json(GrafanaQueryResponse { data: results })
}
```

**Grafana Plugin Structure**:
```typescript
// src/plugin/datasource-proximadb/src/datasource.ts

export class ProximaDBDatasource extends DataSourceApi<GrafanaQuery, MyDataSourceOptions> {

  async query(options: DataQueryRequest<GrafanaQuery>): Promise<DataQueryResponse> {
    const queries = options.targets.map(target => ({
      refId: target.refId,
      query: target.expr,  // PromQL
      stepMs: target.stepMs,
    }));

    const response = await fetch(`/api/datasources/proximadb/query`, {
      method: 'POST',
      body: JSON.stringify({
        from: options.range.from.valueOf(),
        to: options.range.to.valueOf(),
        queries,
      }),
    });

    return { data: response.data };
  }

  async testDatasource() {
    const response = await fetch(`/api/datasources/proximadb/health`);
    return { status: response.data.status === 'ok' };
  }
}
```

**Deliverable - Query Examples**:

## Performance Considerations

### Metrics Collection Overhead

| Metric | Value |
|--------|-------|
| CPU overhead | < 0.1% |
| Memory overhead | 512MB (configurable) |
| Storage overhead | < 1% of data size |
| Query latency | < 10ms for recent data |

### Ingestion Throughput

| Protocol | Max Throughput |
|----------|---------------|
| OTLP gRPC | 100K events/sec |
| OTLP HTTP | 50K events/sec |
| Prometheus remote_write | 1M samples/sec |
| HTTP API | 10K events/sec |

### Storage Sizing

For 30 days retention with 100 services:
- **Logs**: ~100GB/day (varies by log volume)
- **Metrics**: ~10GB/day (1 metric/sec × 100 services)
- **Traces**: ~50GB/day (varies by sampling rate)

## Migration Path

### From Prometheus to ProximaDB

1. **Phase 1**: Run ProximaDB alongside Prometheus
   - Prometheus scrapes applications
   - Prometheus forwards to ProximaDB via remote_write
   - Grafana queries both datasources

2. **Phase 2**: Migrate applications to OTLP
   - Install OpenTelemetry SDK
   - Configure OTLP exporter to ProximaDB
   - Verify data in ProximaDB

3. **Phase 3**: Retire Prometheus
   - Switch Grafana datasources to ProximaDB
   - Disable Prometheus scraping
   - Decommission Prometheus servers

### From ELK to ProximaDB

1. **Phase 1**: Dual-write to both systems
   - Applications send logs to both Filebeat and OTLP
   - Verify data consistency

2. **Phase 2**: Migrate dashboards
   - Recreate Grafana dashboards with ProximaDB queries
   - Test query performance

3. **Phase 3**: Retire ELK
   - Switch to ProximaDB datasource
   - Decommission Elasticsearch

## Troubleshooting

### Common Issues

**Issue**: Prometheus scrape fails
```
Solution:
1. Check /metrics endpoint: curl http://localhost:5678/metrics
2. Verify Prometheus configuration: targets section
3. Check firewall rules: ensure port 5678 is accessible
```

**Issue**: OTLP ingestion rejected
```
Solution:
1. Check OTLP adapter status: logs show "OTLP adapter started on :4317"
2. Verify port availability: netstat -tuln | grep 4317
3. Check max request size: increase observability.ingestion.max_request_size_mb
```

**Issue**: Grafana query timeout
```
Solution:
1. Increase timeout: observability.grafana.query_timeout
2. Reduce time range: max_time_range_hours
3. Optimize query: add label selectors
```
