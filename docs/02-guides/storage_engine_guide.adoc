= Storage Engine Guide

ProximaDB offers multiple storage engines, each optimized for different workloads. This guide explains the available engines and how to configure them.

== Available Engines

* **SST (Sorted String Table):** Optimized for real-time OLTP applications with high write throughput. link:../storage/sst-engine-deep-dive.adoc[Deep Dive]
* **VIPER (Vector-Indexed Parquet Extended Rows):** Optimized for analytics and business intelligence workloads. link:../storage/viper-engine-deep-dive.adoc[Deep Dive]
* **NOVA:** A general-purpose engine for mixed workloads. link:../storage/nova-engine-deep-dive.adoc[Deep Dive]
* **SWIFT:** Optimized for ultra-low latency requirements with three-tier hierarchy. link:../storage/swift-engine-deep-dive.adoc[Deep Dive]
* **RAPTOR:** A dynamic, adaptive engine with Matrix Trinity architecture. link:../storage/raptor-engine-deep-dive.adoc[Deep Dive]
* **HELIX:** Optimized for spatial locality using Hilbert curves. link:../storage/helix-engine-deep-dive.adoc[Deep Dive]

== Graph Engines

ProximaDB also provides specialized graph database engines:

* **ORION:** In-memory CSR format for high-performance traversal
* **PULSAR:** Distributed sharded storage for horizontal scaling
* **QUASAR:** Hot/cold tiering for cost optimization

For comprehensive graph engine documentation, see link:../graph/graph-engines-deep-dive.adoc[Graph Engines Deep Dive].

== Configuration

You can configure the storage engines in your `config.toml` file.

=== SST Configuration

The `[storage.sst_config]` section controls the SST engine.

[source,toml]
----
[storage.sst_config]
level_count = 7
compaction_threshold = 10
block_size_kb = 4096
compaction_strategy = "leveled"
compression = "zstd"
compression_enabled = true
compression_level = 6
cache_size_mb = 2048
max_files_per_level = 20
level_size_multiplier = 10.0
max_levels = 7
background_thread_count = 8
data_directory = "/var/lib/proximadb/sst_data"
mmap_enabled = true
prefetch_enabled = true
prefetch_size_kb = 128
----

=== VIPER Configuration

The `[storage.viper_config]` section controls the VIPER engine.

[source,toml]
----
[storage.viper_config]
row_group_size = 250000
compression = "zstd"
compression_enabled = true
compression_level = 6
enable_statistics = true
data_directory = "/var/lib/proximadb/viper_data"
cache_size_mb = 4096
----

=== Other Engines

Configuration for the NOVA, SWIFT, RAPTOR, and HELIX engines follows a similar pattern. You can add sections like `[storage.nova_config]`, `[storage.swift_config]`, etc. to your configuration file.
