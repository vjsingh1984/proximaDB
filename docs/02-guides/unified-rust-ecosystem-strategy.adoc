## Executive Summary

### Vision

Create a **unified Rust ecosystem** where:

1. **ProximaDB** serves as the foundational storage infrastructure (open-source)
2. **Victor** provides intelligent AI agent capabilities (open-source)
3. **ibkrtrading** demonstrates real-world trading applications (proprietary)

### Key Insight

> **ProximaDB is the infrastructure layer; Victor is the intelligence layer; ibkrtrading is the application layer.**

This creates a **full-stack solution** where developers can use ProximaDB for storage and Victor for AI, while ibkrtrading serves as a proof-of-concept for what's possible.

## Low-Latency Embedded Architecture

### In-Process Database Design

The key innovation for trading applications is **embedded ProximaDB** with **zero-copy intra-process communication**:

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%
flowchart TB
    subgraph Process["Single Rust Process"]
        subgraph App["Application Layer"]
            TRADING["ibkrtrading<br/>Trading Logic"]
            AGENTS["Victor Agents<br/>AI Analysis"]
        end

        subgraph DB["ProximaDB Embedded"]
            MEM["Memtable<br/>Hot Data (Memory)"]
            WAL["Write-Ahead Log<br/>LSM Tree"]
            CACHE["Block Cache<br/>Configurable Size"]
        end

        subgraph Storage["Persistent Storage"]
            SST["SST Files<br/>Cold Data"]
        end

        TRADING <-->|"zero-copy<br/>no serialization"| MEM
        AGENTS <-->|"zero-copy<br/>no serialization"| MEM
        MEM --> WAL
        MEM <-->|"LRU eviction"| CACHE
        WAL --> SST
        CACHE <--> SST
    end

**Architecture**:

│         │                  │                  │             │
│         └──────────────────┼──────────────────┘             │
│                            │                                │
│                   ┌────────▼────────┐                       │

### Memory Management for Trading Apps

**Configuration Options** (`config/config.toml`):

```toml
[storage.memtable]
# Size of memtable before flush (per collection)
# Trading apps: 256-512MB for high-throughput
size_mb = 256

# Flush strategy: "auto", "manual", "interval"
flush_strategy = "interval"
flush_interval_seconds = 10  # Flush every 10s for guaranteed durability

[storage.wal]
# WAL buffer size
# Trading apps: 16-32MB for low-latency writes
buffer_size_mb = 16

# Sync mode: "none" (fastest), "data" (safe), "full" (safest)
# Trading apps: "data" for durability without blocking
sync_mode = "data"

[storage.cache]
# Block cache size (shared across collections)
# Trading apps: 1-2GB for hot data
size_mb = 1024

# Eviction policy: "lru", "lfu", "adaptive"
# Trading apps: "adaptive" for automatic tuning
eviction_policy = "adaptive"

# Enable zero-copy memory mapping
enable_mmap = true

[performance]
# Enable SIMD acceleration
simd_enabled = true

# Number of background flush threads
flush_threads = 4

# Compression for SST files
compression = "lz4"  # Fast compression for trading
```

### Intra-Process Communication Benefits

**Traditional (Network I/O)**:
```
Trading App → Serialize → TCP → Network Stack → TCP → Deserialize → ProximaDB
Latency: ~100-500μs
```

**Embedded (In-Process)**:
```
Trading App → Zero-Copy Pointer → ProximaDB
Latency: ~1-5μs (100x faster!)
```

**Performance Comparison**:

| Operation | Network Mode | Embedded Mode | Speedup |
|-----------|--------------|---------------|---------|
| Single write | 100μs | 2μs | **50x** |
| Vector search | 500μs | 10μs | **50x** |
| Graph traversal | 1ms | 20μs | **50x** |
| Batch insert (1000) | 50ms | 1ms | **50x** |

**One Database, All Use Cases**:

```rust
// All in the same embedded database instance:

// 1. Vector Search - RAG for Victor agents
db.create_collection("agent_knowledge", dimension=1536)
    .with_engine(StorageEngine::Sst);  // Fast writes

db.create_edges("market_graph", [/* ... */]);

// 3. Documents - SEC filings, reports
db.create_document_collection("sec_filings")
    .with_full_text_search();

// 4. RDBMS - Trade history, positions
db.execute("CREATE TABLE trades (
    id SERIAL PRIMARY KEY,
    symbol VARCHAR(10),
    quantity INT,
    price DECIMAL,
    timestamp TIMESTAMP
)");

// 5. Time Series - OHLCV bars
db.create_time_series("ohlcv")
    .with_retention(Retention::Days(30))
    .with_rollup_interval(RollupInterval::Minute);

// 6. Observability - Trading metrics
db.observability()
    .enable_metrics_export("/metrics")
    .enable_otlp_ingestion(4317);
```

### Cross-Model Queries (The Power Play)

**Example: AI-Powered Trading Strategy**

```sql
-- Find similar historical patterns + correlated stocks + recent news
WITH similar_patterns AS (
    SELECT vector_search('price_history', current_market_vector, 10)
),
correlated_stocks AS (
    SELECT target_id, weight
    FROM GRAPH_QUERY('market_graph', 'MATCH (a:Stock)-[:CORRELATES]-(b:Stock)')
    WHERE a.symbol = 'AAPL' AND weight > 0.7
),
recent_news AS (
    SELECT document_id, text, published_at
    FROM DOCUMENT_QUERY('sec_filings', 'symbol = "AAPL"')
    WHERE published_at > NOW() - INTERVAL '7 days'
)
SELECT
    sp.pattern_id,
    sp.similarity_score,
    cs.target_id AS correlated_symbol,
    cs.weight AS correlation_weight,
    rn.text AS news_headline
FROM similar_patterns sp
JOIN LATERAL GRAPH_QUERY('market_graph', sp.pattern_id) cs ON true
JOIN LATERAL DOCUMENT_QUERY('sec_filings', sp.pattern_id) rn ON true
WHERE sp.similarity_score > 0.85
ORDER BY sp.similarity_score DESC;
```

**This single query combines**:
- Vector similarity search (price patterns)
- Graph traversal (correlated stocks)
- Full-text search (SEC filings)
- Time-series filtering (last 7 days)

### Demo 1: AI-Powered Trading System (Full Stack)

**Scenario**: Victor agents analyze market data and ibkrtrading executes trades

**Flow**:

```mermaid
%%{init: {"theme": "neutral"}}%%
sequenceDiagram
    participant Market as Market Data Feed
    participant IBKR as ibkrtrading
    participant Prox as ProximaDB (Embedded)
    participant Victor as Victor Agents
    participant Grafana as Grafana Dashboard

    Market->>IBKR: Real-time OHLCV data
    IBKR->>Prox: Store bars (time-series)
    IBKR->>Victor: Trigger analysis (AAPL)

    Victor->>Prox: Query historical patterns (vector)
    Victor->>Prox: Query correlated stocks (graph)
    Victor->>Prox: Query SEC filings (documents)
    Prox-->>Victor: Query results

    Victor->>Victor: SEC Agent analyzes
    Victor->>Victor: Technical Agent analyzes
    Victor->>Victor: Fundamental Agent analyzes
    Victor->>Victor: Synthesis Agent combines

    Victor->>IBKR: Trading signal (BUY, 100 shares)
    IBKR->>IBKR: Risk check
    IBKR->>Market: Submit order

    IBKR->>Prox: Log trade (RDBMS)
    IBKR->>Prox: Emit metrics (observability)
    Prox->>Grafana: /metrics scrape
```

**Code Example**:

```rust
// In ibkrtrading main process
let db = ProximaDB::embedded()
    .data_path("/tmp/trading_db")
    .memtable_size_mb(512)  // Large memtable for trading
    .wal_buffer_size_mb(32)
    .start()?;

// Victor agents use same embedded instance
let victor = Victor::builder()
    .database(db.clone())  // Zero-copy access
    .build();

// Trading loop
for bar in market_data_feed {
    // Store in ProximaDB (embedded, zero-copy)
    db.insert_time_series("ohlcv", bar).await?;

    // Check if analysis needed
    if should_analyze(bar.symbol) {
        // Victor agents use ProximaDB for queries
        let signal = victor.analyze_symbol(bar.symbol).await?;

        // Execute trade based on signal
        if signal.confidence > 0.8 {
            execute_trade(signal)?;
        }

        // Store analysis in ProximaDB for learning
        db.insert_vector("agent_memories", signal.embedding, metadata).await?;
    }
}
```

// Build correlation graph
db.create_graph("market_correlations");

// Add nodes (stocks)
for stock in stocks {
    db.create_node("market_correlations", stock.symbol)
        .with_property("sector", stock.sector)
        .with_property("market_cap", stock.market_cap);

// Add edges (correlations)
for (stock1, stock2, correlation) in calculate_correlations() {
    if correlation.abs() > 0.7 {
        db.create_edge("market_correlations", stock1, stock2, "CORRELATES")
            .with_property("coefficient", correlation)
            .with_property("calculated_at", Utc::now());
    }
}

// Find connected components (highly correlated groups)
let components = db.find_connected_components("market_correlations");
