== Documentation Principles

=== Single Source of Truth

Each concept documented in **exactly one canonical location**:

- **Duplicates eliminated**: Content exists once, referenced elsewhere
- **Clear ownership**: Each doc has single purpose and audience
- **Easier maintenance**: Update once, consistent everywhere

=== Reference, Don't Duplicate

**Pattern**: High-level docs reference detailed docs

**Example**:
```asciidoc
= Storage Layer Architecture

SST engine uses hybrid columnar format for write-heavy workloads.

For implementation details, see link:../../src/storage/engines/impls/sst/README.adoc[SST Implementation].
```

=== Proximity to Code

**Principle**: Implementation docs live with the code

**Benefits**:
- Docs updated when code changes
- Easy to find relevant documentation
- Lower risk of doc drift
- Natural organization

== Contributing to Documentation

### Documentation Workflow

1. **Identify tier**: Which tier does this content belong to?
2. **Check existing**: Does canonical documentation already exist?
3. **Update canonical source**: Modify source, update cross-references
4. **Validate**: Run `scripts/validate_docs.sh`

### Documentation Standards

- **Format**: AsciiDoc (`.adoc`) for all docs
- **Diagrams**: Mermaid only, using ProximaDB color scheme
- **Style**: Follow link:08-development/style-guide.adoc[Style Guide]
- **Cross-references**: Use `link:` for internal references

### Validation

Run documentation validation:

[source,bash]
----
./scripts/validate_docs.sh
----

**Checks**:
- No broken links
- No duplicate content
- Proper structure
- Bidirectional cross-references
