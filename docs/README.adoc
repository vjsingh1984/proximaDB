== Config Examples

- Example TOML: `docs/config/example-config.toml`
  - Includes `[server]`, `[api]`, `[cache]`, `[storage]`, `[sks]`, `[tls]`, `[hardware]`
  - The `[cache].total_memory_mb` sets the Cross‑Cache Orchestrator budget; if omitted, falls back to `storage.cache_size_mb`.

== Running with a Config File

- CLI (example): `proximadb-server --config /path/to/config.toml`
- Env var (example): `PROXIMADB_CONFIG=/path/to/config.toml proximadb-server`
- Programmatic (Rust): use `core::config_loader::ConfigLoader::load_with_defaults("/path/to/config.toml")` and pass into `ProximaDB::new(config).await?`.

Notes
- Relative paths in the config are resolved to file URLs where applicable (see `core/config_loader.rs`).
- The server reads `[cache]` (if present) to configure the unified Cross‑Cache Orchestrator and registers it globally for vector, SKS, and graph.

== Cache Configuration

Add a dedicated `[cache]` section in your TOML to control the unified Cross‑Cache Orchestrator budget (shared by vector, SKS, and graph caches).

Example
----
[cache]
total_memory_mb = 512  # global budget for orchestrator‑managed caches
----

Fallback
- If `[cache]` is omitted, the system falls back to `storage.cache_size_mb`.
