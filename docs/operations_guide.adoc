**5-Minute Production Setup:**

[source,bash]
----
# 1. Pull ProximaDB image
docker pull proximadb/proximadb:latest

# 2. Create configuration
cat > proximadb.toml << EOF
[server]
rest_port = 5678
grpc_port = 5679

[storage]
default_engine = "sst"
data_path = "/data/proximadb"

[cache]
total_memory_mb = 8192

[hardware]
enable_simd = true
enable_gpu = true
EOF

# 3. Start container
docker run -d \
  --name proximadb \
  -p 5678:5678 -p 5679:5679 \
  -v $(pwd)/proximadb.toml:/etc/proximadb/config.toml \
  -v proximadb-data:/data/proximadb \
  proximadb/proximadb:latest

# 4. Verify deployment
curl http://localhost:5678/health
----

=== Production Configuration

[IMPORTANT]
====
**Resource Planning**: Allocate sufficient memory and storage for your workload

**Performance Tuning**: Configure engines based on access patterns

**Monitoring Setup**: Enable metrics collection from day one

**Backup Strategy**: Plan data protection and recovery procedures
====

[source,toml]
----
[server]
rest_port = 5678
grpc_port = 5679
max_connections = 1000
request_timeout_seconds = 30

[storage]
default_engine = "sst"
data_path = "s3://your-bucket/proximadb-data"

[storage.metadata]
backend = "rocksdb"
path = "/var/lib/proximadb/metadata"

[engines.sst]
memtable_size_mb = 2048
bloom_filter_bits_per_key = 10
compaction_strategy = "level"
max_background_jobs = 4

[engines.viper]
batch_size = 10000
compression = "zstd"
quantization = "pq8"
enable_statistics = true

[cache]
total_memory_mb = 16384
result_cache_ttl_seconds = 3600
metadata_cache_size_mb = 1024

[hardware]
enable_simd = true
enable_gpu = true
gpu_memory_limit_mb = 8192

[monitoring]
enable_prometheus = true
metrics_port = 9090
log_level = "info"

[security]
enable_tls = true
cert_path = "/etc/ssl/certs/proximadb.crt"
key_path = "/etc/ssl/private/proximadb.key"
----

**Backup Commands:**
[source,bash]
----
# Create full backup
proximadb-cli backup create --type full --destination s3://backups/proximadb/

# Incremental backup
proximadb-cli backup create --type incremental --destination s3://backups/proximadb/

# Point-in-time recovery
proximadb-cli restore --timestamp "2025-09-11T10:00:00Z" --source s3://backups/proximadb/

# Verify backup integrity
proximadb-cli backup verify --source s3://backups/proximadb/backup-20250911.tar.gz
----

=== Troubleshooting Guide

**Common Issues and Solutions:**

[cols="2,2,3"]
|===
|Issue |Symptoms |Resolution

|**High Query Latency**
|P95 > 50ms
|Check index usage, optimize query patterns, review engine selection

|**Memory Pressure**
|>90% memory usage
|Increase memory allocation, optimize cache settings, review quantization

|**Storage Growth**
|Rapid disk usage increase
|Enable compression, configure compaction, archive old data

|**Connection Issues**
|Client timeouts
|Check network connectivity, review connection limits, verify firewall rules

|**Performance Degradation**
|Gradual slowdown
|Analyze query patterns, update statistics, consider index rebuilds
|===

== 🎯 Best Practices Summary

=== Deployment Best Practices

[NOTE]
====
**Resource Planning**: Start with 2x expected resource needs for headroom

**Monitoring First**: Set up monitoring before production traffic

**Gradual Rollout**: Deploy to staging environment first, then production

**Backup Strategy**: Implement automated backups from day one
====

=== Operational Excellence

1. **Proactive Monitoring**: Set up alerts for key metrics
2. **Performance Baselines**: Establish normal operating parameters  
3. **Capacity Planning**: Monitor growth trends and plan scaling
4. **Incident Response**: Define clear escalation procedures
5. **Documentation**: Maintain operational runbooks and procedures
