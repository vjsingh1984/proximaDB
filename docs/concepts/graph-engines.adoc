== Use Case Recommendations

=== Real-Time Recommendations

**Recommended: ORION Engine**

Best for:

* Friend-of-friend suggestions
* Real-time product recommendations
* Knowledge graph traversal
* Session-based personalization

[source,python]
----
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient("http://localhost:5678")

# ORION is the default engine for graph operations
client.create_graph(
    name="recommendations",
    engine="orion",
    engine_config={
        "enable_wal": True,  # Durability via WAL
        "memory_pool_size_mb": 512
    }
)

# Create nodes for users and products
client.create_nodes("recommendations", [
    {"id": "user_alice", "label": "User", "properties": {"name": "Alice"}},
    {"id": "product_1", "label": "Product", "properties": {"name": "Widget"}}
])

# Create relationship edges
client.create_edges("recommendations", [
    {"source": "user_alice", "target": "product_1", "type": "PURCHASED", "weight": 1.0}
])

# Traverse to find recommendations
results = client.traverse(
    "recommendations",
    start_node="user_alice",
    edge_types=["PURCHASED", "SIMILAR_TO"],
    max_depth=2,
    limit=10
)
----

=== Large-Scale Social Graphs

**Recommended: PULSAR Engine**

Best for:

* Social networks (millions of users)
* Multi-hop relationship queries
* Cross-shard analytics
* High availability requirements

[source,python]
----
client.create_graph(
    name="social_network",
    engine="pulsar",
    engine_config={
        "shard_count": 16,           # Distribute across 16 shards
        "replication_factor": 2,     # 2x replication for HA
        "consistency_level": "quorum",
        "cross_shard_optimization": True,
        "max_concurrent_queries": 100
    }
)
----

=== Cost-Optimized Knowledge Graphs

**Recommended: QUASAR Engine**

Best for:

* Large but sparse graphs
* Infrequently accessed historical data
* Budget-constrained deployments
* Mixed hot/cold access patterns

[source,python]
----
client.create_graph(
    name="knowledge_base",
    engine="quasar",
    engine_config={
        "hot_tier_max_nodes": 100000,        # 100K nodes in memory
        "hot_tier_max_memory_mb": 1024,      # 1GB hot tier
        "cold_tier_path": "/data/quasar",
        "cold_migration_threshold_hours": 1, # Move to cold after 1hr idle
        "hot_promotion_threshold_min": 5,    # Promote after 5min of access
        "cold_storage_backend": "sst"        # SST or Parquet
    }
)
----

== Engine Architecture

=== ORION: In-Memory CSR

ORION uses Compressed Sparse Row (CSR) format for cache-efficient traversal:

[source,text]
----
+------------------------------------------+
|              ORION Engine                 |
+------------------------------------------+
|  Nodes: DashMap<NodeId, Arc<Node>>       |
+------------------------------------------+
|  CSR Outgoing Edges:                     |
|  +-----------+-----------+               |
|  |  Offsets  |  Targets  |               |
|  | [0,2,5..] | [1,3,2..] |               |
|  +-----------+-----------+               |
+------------------------------------------+
|  CSR Incoming Edges:                     |
|  +-----------+-----------+               |
|  |  Offsets  |  Sources  |               |
|  | [0,1,3..] | [0,2,1..] |               |
|  +-----------+-----------+               |
+------------------------------------------+
----

**Performance Characteristics:**

* Traversal speed: 1M+ edges/second
* Node lookup: <1us (O(1) DashMap access)
* Edge traversal: O(degree) with sequential access
* Memory overhead: <100 bytes/node

**Key Features:**

* Zero-copy Arc-based memory sharing
* WAL-backed persistence for durability
* SIMD-optimized edge array operations
* Parallel traversal support via Rayon

=== PULSAR: Distributed Sharding

PULSAR distributes graph data across multiple ORION shards:

[source,text]
----
+------------------------------------------+
|            PULSAR Engine                  |
+------------------------------------------+
|              Coordinator                  |
|  +------------------------------------+  |
|  |     Query Router & Distributor      |  |
|  +------------------------------------+  |
+------------------------------------------+
|               Sharding                    |
|  +--------+--------+--------+            |
|  |Shard 0 |Shard 1 |Shard N |            |
|  |(ORION) |(ORION) |(ORION) |            |
|  +--------+--------+--------+            |
+------------------------------------------+
|             Replication                   |
|  +------------------------------------+  |
|  |    Master-Slave Replication        |  |
|  |    Configurable Factor (1-3)       |  |
|  +------------------------------------+  |
+------------------------------------------+
----

**Key Features:**

* Consistent hashing with SHA-256 hash ring
* Configurable 1-3x replication factor
* Cross-shard BFS/DFS traversal
* 2PC transaction support
* Hot shard detection and load balancing

=== QUASAR: Tiered Storage

QUASAR automatically tiers data between memory and disk:

[source,text]
----
+------------------------------------------+
|            QUASAR Engine                  |
+------------------------------------------+
|              Hot Tier                     |
|  +------------------------------------+  |
|  |        ORION Engine                |  |
|  |       (In-Memory CSR)              |  |
|  +------------------------------------+  |
+------------------------------------------+
|             Tiering Logic                 |
|  +------------------------------------+  |
|  |      LRU Cache Manager             |  |
|  |    Access Pattern Tracker          |  |
|  |   Background Migration Worker      |  |
|  +------------------------------------+  |
+------------------------------------------+
|              Cold Tier                    |
|  +------------------------------------+  |
|  |      Disk Storage Backend          |  |
|  |       (SST/Parquet Files)          |  |
|  +------------------------------------+  |
+------------------------------------------+
----

**Key Features:**

* Automatic hot/cold tiering based on access patterns
* LRU eviction policy
* Transparent cross-tier access
* Background async migration
* 80-90% storage cost savings for sparse graphs

== Hybrid Vector+Graph Queries

ProximaDB supports combining vector similarity with graph traversal:

[source,python]
----
# Find products similar to user's interests via graph + vector
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient("http://localhost:5678")

# Step 1: Traverse graph to find user's purchased products
purchased = client.traverse(
    "recommendations",
    start_node="user_alice",
    edge_types=["PURCHASED"],
    max_depth=1
)

# Step 2: Get embeddings and find similar products
product_ids = [r["node"]["id"] for r in purchased]
for pid in product_ids:
    similar = client.search(
        "product_embeddings",
        vector=client.get_vector("product_embeddings", pid),
        top_k=5,
        filter={"not_in": product_ids}  # Exclude already purchased
    )
    print(f"Similar to {pid}: {similar}")

# Or use unified query for combined graph+vector search
results = client.unified_query("""
    SELECT p.id, p.name, VECTOR_DISTANCE(p.embedding, ?)
    FROM products p
    WHERE GRAPH_CONNECTED('recommendations', 'user_alice', p.id, 'SIMILAR_TO', 2)
    ORDER BY VECTOR_DISTANCE(p.embedding, ?) ASC
    LIMIT 10
""", vector=[0.1, 0.2, ...])
----

== Graph Query Language

ProximaDB supports a SQL-like graph query syntax:

[source,sql]
----
-- Find 2-hop connections
SELECT target FROM GRAPH social
WHERE GRAPH_TRAVERSE(source='user_1', edge_type='FOLLOWS', max_depth=2);

-- Filter by node properties
SELECT * FROM GRAPH knowledge
WHERE GRAPH_CONNECTED(source='concept_ai', target_label='Paper')
  AND target.$.year > 2020;

-- Combine with vector similarity
SELECT g.target, v.score
FROM GRAPH knowledge g
JOIN vectors.papers v ON g.target = v.id
WHERE GRAPH_TRAVERSE(source='concept_ml', edge_type='RELATED_TO', max_depth=1)
  AND VECTOR_SIMILAR(v.embedding, ?, 0.8);
----

== Graph Algorithms

ORION supports common graph algorithms:

[source,python]
----
# PageRank for node importance
pagerank = client.graph_algorithm(
    "social_network",
    algorithm="pagerank",
    config={"iterations": 20, "damping": 0.85}
)

# Community detection
communities = client.graph_algorithm(
    "social_network",
    algorithm="louvain",
    config={"resolution": 1.0}
)

# Shortest path
path = client.shortest_path(
    "social_network",
    source="user_1",
    target="user_100",
    edge_types=["FOLLOWS", "FRIENDS"]
)
----

== Migration Between Engines

Graph engines cannot be changed in-place. To migrate:

1. Export graph data from source engine
2. Create new graph with target engine
3. Import nodes and edges
4. Update application to use new graph
5. Delete old graph

[source,python]
----
# Export from ORION
nodes = client.get_all_nodes("old_graph")
edges = client.get_all_edges("old_graph")

# Create new PULSAR graph
client.create_graph("new_graph", engine="pulsar", engine_config={...})

# Import data
client.create_nodes("new_graph", nodes)
client.create_edges("new_graph", edges)

# Verify
stats = client.graph_stats("new_graph")
assert stats["node_count"] == len(nodes)
----
