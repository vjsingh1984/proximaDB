== Context

First principle: an agent is **context-bounded** — it acts on the minimal sufficient statistic *without seeing the data* (ADR-037 D1). Freshness is therefore not a footnote, it is **the trust contract**: a statistic whose `as_of` the agent cannot trust is *confidently wrong* — worse than absent, because the agent will act on it.

The frozen v1 envelope (ADR-037) carries **one** top-level `freshness`. TD-174 maintains the whole envelope at the **SST vector-flush** boundary and stamps that single watermark (`flush/mod.rs:692`). This is coherent **only while a single write boundary feeds the envelope.**

ADR-037 Decision 3 + TD-175 break that assumption. The envelope is **modality-neutral**, and its blocks are fed from **independent write boundaries** — document/BM25 at the tantivy index commit, graph at the graph mutation/commit, traces/time-series at their ingest — each advancing at its **own cadence**. The instant the second boundary feeds a block, one top-level `freshness` either **over-promises** (claims the whole envelope is as fresh as the latest flush, so the agent trusts a stale graph stat as current) or is **meaningless**. Caught now, before TD-175 feeds the second boundary, while the fix is still additive.

== Decision

=== D1 — Freshness is per-source; the top-level field is the conservative FLOOR

Redefine the top-level `freshness` as `min(as_of)` across all contributing sources. A consumer reading only the top level then **can never over-trust** — it degrades to "at least this stale." Backward-compatible: a single-source envelope's floor is its only watermark, so v1.0 producers (TD-174) remain correct unchanged.

=== D2 — Optional per-block freshness (additive → v1.1)

Add an optional `freshness` (the same `Freshness` shape) **embedded in each modality block**. Each modality stamps its own `as_of`/`source` at its own write boundary. Embedded — not a side table — so the freshness travels *with* the statistics it describes (the agent reading the graph block sees the graph block's freshness inline). Additive (blocks are `additionalProperties: true`; consumers pin the **major**) ⇒ a **minor** bump to `1.1.0`, no break. A producer that doesn't populate a block's freshness is valid; the consumer falls back to the floor.

=== D3 — Composition rule: freshness composes by MIN, never average

For a block-specific stat, use that block's freshness; for any whole-envelope decision, use the floor (D1). Like a database snapshot bounded by its **oldest** read. The consumer (AnvaiOps ADR-0021) MUST NOT average per-block freshness — averaging manufactures a freshness the data never had. This is the "measure vs. bill" discipline applied to **time**: the engine reports per-source as-of *facts*; the consumer composes the *trust envelope*.

=== D4 — Maintenance architecture: N write-boundaries, one resident summary

ADR-030's "one seam, N readers" **inverted**. Each modality engine calls the **same** process-global `StatisticsRegistry` (TD-174) with its block **and its own freshness stamp**, at **its** commit boundary:

[cols="1,2,1", options="header"]
|===
| Block | Write boundary it rides | Status
| vector | SST flush | done (TD-174)
| document / BM25 | tantivy index commit | TD-175
| graph | graph mutation/commit (`GetGraphStats` snapshot) | TD-175
| trace / time-series | their ingest flush | TD-175
|===

The registry is the convergence point; per-block freshness (D2) is what makes the convergence **honest**. All mechanism, all OSS.

=== D5 — Open-core: the engine emits MARGINALS; the consumer composes JOINTS

TD-175 forces a boundary call ADR-037 left implicit. **Marginal** per-modality statistics (cardinalities, distributions) are cheap and mechanical ⇒ **engine / OSS** (the envelope blocks). **Joint / conditional** cross-modal statistics ("incidents tagged X correlate with graph nodes Y") require *correlating* modalities + semantic interpretation ⇒ expensive and meaning-laden ⇒ **AnvaiOps** (computed by reading the marginals + sampling via the query API). The engine never computes cross-modal joints. Same open-core line as ADR-037/027/030, one altitude deeper.

== v1.1 contract change (additive — the exact diff)

* `x-envelope-version` (schema) and `ENVELOPE_VERSION` (const): `1.0.0` → `1.1.0`. The schema **file name stays `statistics-envelope.v1.*`** — it is the v1 line; the minor is tracked in `x-envelope-version`.
* Top-level `freshness` description: redefined as the conservative floor (min across sources, D1).
* Each modality `$def` / block struct (`Document`/`Vector`/`Graph`/`Trace`/`Timeseries`Statistics): add optional `freshness` of the existing `Freshness` shape (D2).
* Consumer (AnvaiOps `apps/api/src/models/statistics.py`): `SUPPORTED_ENVELOPE_MAJOR` stays `1` (accepts `1.1`); add the optional per-block `freshness` field + implement the floor / MIN composition rule (D3) when reading the live envelope (ADR-0021 B1).
* Golden example: bump to `1.1.0` and populate per-block freshness on ≥2 blocks at different `as_of` so the top-level floor = the older one (demonstrates D1+D3).

== Implementation sequencing (why v1.1 lands *with* TD-175, not before)

The additive field is **not free on the producer side**: Rust struct literals require every construction site to name the new field, so adding `freshness: Option<Freshness>` to the block structs forces `freshness: None` (or a real stamp) at every place `summary.rs` builds a block. The schema/type change and the per-boundary stamping are therefore **coupled at the construction sites** and must land together — as the first slice of TD-175 — rather than as a separate contract-only commit that would either break the build or leave a broken intermediate state on an open PR. This ADR records the decision and the exact change so TD-175 executes it mechanically; the contract code (schema + `mod.rs` block structs + example + the Python consumer) and the producer wiring move in one PR.

== Consequences

* **Honest multi-boundary freshness:** an agent never trusts a stale block as fresh; the trust contract holds as the envelope fans across boundaries.
* **Fail-safe by construction:** the floor (D1) means a regression in per-block stamping degrades to "more stale than reality," never "fresher than reality" — the same defense-in-depth posture as ADR-0021's belt-and-suspenders tenant filter (under-trust, never over-trust).
* **Forward-compatible:** v1.0 consumers ignore per-block freshness; v1.1 consumers read it; producers populate per-boundary as TD-175 lands. Consumers pin the major, so nothing breaks.
* **Vindicates frozen-but-versioned:** the contract evolves one minor immediately after the freeze — exactly what the versioned (not locked) design intended. Catching it before the second write boundary avoids baking wrong semantics into the agent trust contract.
* **Cost/risk:** TD-175 now owns a contract bump in addition to extractor wiring; the coupling note above keeps it a single coherent PR.
