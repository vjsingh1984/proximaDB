= ADR-024: Single Canonical Data Type (`ProximaType`) and Schema
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge
:last-updated: 2026-06-04

== Status

Accepted (phased rollout in progress)

Scope: convergence of the three parallel data-type enums and two schema structs onto a single canonical logical type + schema. Tracker: CONVERGENCE_AUDIT seam *S8*; TD-111 (to be filed in `docs/10-quality/TECHNICAL_DEBT.adoc`). Supersedes the implicit "three-parallel-type" tolerance noted in `roadmap/MULTIMODAL_OVERHAUL_SPEC_2026_05_08.adoc` §4.2.

== Context

The codebase carries three parallel "data type" enums plus bridges between them — the duplicate-abstraction class the Convergence Gate (CLAUDE.md; `CONVERGENCE_AUDIT_2026_05_30.adoc`) treats as a regression:

* `ProximaType` — `crates/foundation/proximadb-data-model` (~42 variants; the richest). CLAUDE.md mandates it as the canonical durable/wire/storage type ("New internal/durable contracts use `ProximaRecord` + `ProximaType`/`ProximaValue`"); MULTIMODAL spec §4.2 calls it "the single source of truth for catalog, wire, and storage types." Already carries `pgwire_oid()`.
* `ProximaDataType` — `crates/storage/proximadb-storage-common` (~28 variants). Used by `ProximaSchema`/`ProximaColumn`. Holds the Arrow bridges *and* three quantized-vector variants carrying *physical encoding* parameters (`scale_factor`, `zero_point`, PQ `segments`/`bits`) plus a `BFloat16` element. Persisted only via the in-memory `ProximaSchema`.
* `CatalogDataType` — `crates/control/proximadb-catalog` (~19 variants; the poorest). Used by `CatalogColumn`/`CatalogTableSchema`; **durably persisted** to catalog backends; carries proto-v1 wire codes.

There is no `ProximaType`↔`ProximaDataType` bridge, and no `CatalogTableSchema`↔`ProximaSchema` converter — so each new schema-aware path was tempted to add *another* bridge. `proximadb-relational-types::ColumnInfo` already carries `ProximaType` directly, proving the target works.

A key distinction surfaced during analysis: `ProximaDataType`'s quantized variants encode **physical storage detail** (quantization parameters), which the **logical** `ProximaType` deliberately omits. Folding those parameters into the logical type would conflate logical type with physical encoding.

== Decision

. **One canonical logical type: `ProximaType`.** It is the single authority for column/field types across catalog, storage, query, and protocol layers. `ProximaDataType` and `CatalogDataType` are deprecated and collapsed into it.
. **Logical vs physical separation.** `ProximaType` describes the *logical* type only (e.g. `DenseVector { element, dim }`). Physical encoding — quantization (int8 scale/zero-point, PQ segments/bits), compression, layout — is an **orthogonal storage attribute**, not a logical-type variant. The quantized `ProximaDataType` variants therefore do **not** become `ProximaType` variants; on collapse they map to their logical type (`DenseVector`/`BinaryVector`) plus a separate encoding descriptor on the storage column. `VectorElement` gains `BFloat16` to match the prior element set.
. **One bridge per concern, hosted on `ProximaType`.** The Arrow projection (`ProximaType::to_arrow_type`/`from_arrow_type`), pgwire OIDs (`pgwire_oid`), and proto wire-code mapping live on (or key off) `ProximaType`. The previously scattered converters (`CatalogDataType::to_arrow_datatype`, `ProximaDataType::to_arrow_type`) delegate to it, then are removed with their enums. Dense vectors project to `FixedSizeBinary(dim * element_width)` little-endian; this is the canonical, lossy *physical projection* (the logical type stays authoritative).
. **One canonical schema struct.** `CatalogTableSchema` (durable authority: columns, primary key, indexes, storage layouts, projections, relational capabilities, workload/specialization/policy) and `ProximaSchema` (in-memory Arrow + evolution: schema_id/version/parent/fingerprint) merge into a single schema type whose columns carry `ProximaType`.
. **Proto enums remain versioned wire edges.** Proto v1 `DataType`/`SqlValue`/`SqlObject` and v2 `ColumnDataType`/`TypedValue` are NOT deleted (that would break the wire); each gets exactly one bridge ⇄ `ProximaType`/`ProximaValue`. Variant wire codes are never renumbered.
. **REST/gRPC funnel through `ProximaType`.** REST v2's stringly-typed `data_type` parses via the one canonical `ProximaType` parser; gRPC conversions route through the single bridge.

== Rollout (phased; durable-safe; hot-branch aware)

[cols="1,3,1"]
|===
| Step | Change | Risk

| 1 (this ADR) | `ProximaType` becomes the proven logical superset: `VectorElement::BFloat16`; canonical `to_arrow_type`/`from_arrow_type`; extended `pgwire_oid`. Additive to the foundation crate. | Low — additive, no deletions, no deprecation noise.
| 2 | Collapse `ProximaDataType` → `ProximaType` (storage). `ProximaColumn.data_type: ProximaType`; quantization moves to a storage encoding attribute. | Med — `ProximaSchema` is in-memory.
| 3 | Collapse `CatalogDataType` → `ProximaType` (catalog). Durable: serde deserialize-compat shim accepts legacy tags. | High — persisted catalog schemas.
| 4 | Merge `CatalogTableSchema` + `ProximaSchema` into one canonical schema struct. Durable: `#[serde(default)]` for added fields. | High — durable authority.
| 5 | REST v2 string → `ProximaType` parser; proto v1/v2 ⇄ `ProximaType`/`ProximaValue` single bridge. | Low — wire-stable; advances seam S3 / TD-106.
|===

Each step compiles and lands independently; persisted-shape changes (3, 4) ship with a deserialize-compat shim + a legacy-form round-trip test; proto wire codes are never renumbered.

== Consequences

* Positive: one logical type and one schema struct; the bridge web collapses to a single Arrow/pgwire/proto mapping; new code stops minting parallel types; logical/physical separation makes the type model honest about quantization.
* Negative / cost: a durable migration for persisted catalog schemas (mitigated by serde compat shims); a multi-step rollout that temporarily keeps deprecated aliases; coordination with in-flight catalog (TD-061/TD-110) and storage (F-series) work.
* The Convergence Gate is satisfied: this ADR is the cited justification for the type/schema seam change; seam S8 in `CONVERGENCE_AUDIT_2026_05_30.adoc` tracks it to closure.
