= ADR-023: F2 Cold-Load Ordering — Binary-First Tiered Index Serving

:toclevels: 3
:icons: font

:last-updated: 2026-05-30

== Status

Proposed

Scope: TD-087 / Phase 8 F2 (`docs/12-design/PHASE8_CONTINUOUS_LOOP_HLD_LLD_2026_05_28.adoc` §F2). Closes F2 success criterion #1 (and #4); criteria #2/#3 are already met (recall envelope via the `RecallProbeGate`; degraded-route disclosure shipped as the `QUANTIZED_ROUTE_DOWNGRADED` EXPLAIN hint, 2026-05-30).

== Context

Phase 8 F2 ("scale-to-zero cold path") promises that when compute scales from zero, the *first* query loads a compact 1-bit representation (~1/32 of the full index) and begins serving a coarse two-stage search *before* the full-fidelity tier is pulled from object storage. The recall envelope is gated and disclosed.

As of 2026-05-30 the *serving* half is live but the *loading* half is not:

* **Binary two-stage search is implemented, tested, and now reachable.** `UnifiedIvfIndex::search_with_binary_acceleration` (`src/index/axis/indexes/dual_store_ivf.rs`) does Stage-1 Hamming coarse filtering over the 1-bit `binary_codes` tier within IVF-pruned clusters, then Stage-2 fp32 rerank of the survivors. It was dead until commit `d0f67c42c` activated the tier via `PROXIMADB_IVF_BINARY_TIER` (the route is gated by `RecallProbeGate` and discloses downgrades in EXPLAIN).

* **But the cold *load* still pulls the full index.** `UnifiedIvfIndex::export_state` / `restore_state` (`dual_store_ivf.rs:2142,2181`) serialize centroids + *every fp32 vector*, and restore *replays `add_vector` for each vector* — reconstructing `binary_codes` from fp32 on the way. Correct for warm restart (proven by `serialize_roundtrip_preserves_search_topk`), but it loads 100% of the index bytes before the first query can be served. **Success criterion #1 ("≤ ~1/30 of full-index bytes before serving begins") is therefore unmet** — the compact tier is reconstructed *from* the full tier rather than loaded *instead of* it.

* **The generic storage tier-mover does not model tiers-within-an-index.** `UniversalIndexStorage` (`src/index/axis/storage/universal_index_storage.rs`) moves whole bincode blobs across `StorageLocation::{Memory, NvmeSsd, HardDisk, S3Express}` keyed by item id. It has no notion of "the binary sub-tier of index X is cheap and should load before X's fp32 sub-tier." Cold-load ordering must live *inside* the index serialization + a load policy, not in the generic mover.

Two structural facts make the binary-first design natural:

. **Centroids are already inelastic / always-resident.** `CentroidStore::restore` (`dual_store_ivf.rs:2106`) marks the centroid store trained-and-resident; the F2 LLD calls it "ideal for cold start." Centroids + the binary tier together form a self-contained Stage-1-searchable structure.
. **`BinaryCode` is ~1/32 of fp32.** One sign bit per dimension = `ceil(dim/8)` bytes vs `4·dim` bytes for fp32 — a 32× ratio (the spec's "~1/30"). For 1M × 768-dim: binary tier ≈ 96 MB, fp32 tier ≈ 3 GB; centroids (1000 × 768 × 4) ≈ 3 MB.

== Decision

Serialize the IVF index as **two independently loadable tiers** and add a **`ColdPathLoadPolicy`** that loads the cold tier first, serves Stage-1-only, then lazily upgrades to full two-stage when the warm tier arrives. Reuse the existing gate + EXPLAIN + diagnostics surfaces for the recall-envelope disclosure. No new on-disk format crate; no second physical copy.

=== 1. Two-tier serialization

Split `SerializableIvfState` (`dual_store_ivf.rs:~2090`) into two blobs behind a versioned container (bump `IVF_STATE_VERSION` → 2; v1 stays loadable as a single warm blob):

[cols="1,3", options="header"]
|===
| Tier | Contents

| **COLD** (load first, ~1/32)
| `SerializableIvfConfig` (already carries `use_binary`), centroids, and `Vec<(id, BinaryCode, cluster_id)>` — the per-vector 1-bit code plus its posting-list membership. Self-contained: enough to run Stage-1 Hamming over IVF-pruned clusters with **no fp32**.

| **WARM** (lazy, ~31/32)
| `Vec<(id, Vec<f32>)>` — the fp32 vectors for Stage-2 rerank. Streamed/range-fetched after serving has begun.
|===

Record a **cold-path profile** on `AxisSerializedIndexMetadata` (`src/index/axis/storage/serialization.rs:107`): `has_binary_tier: bool`, `cold_tier_bytes: u64`, `warm_tier_bytes: u64`, and the byte offset/length of each tier blob so the loader can range-read the cold tier alone (the S3 path already supports object reads — see `promote_from_s3`).

=== 2. Serving-state machine

Add a per-index serving state (atomic enum on `UnifiedIvfIndex`):

[source]
----
ColdBinaryOnly  -- cold tier loaded; fp32 absent; Stage-1-only serving
   │  (warm tier load completes)
   ▼
FullTwoStage    -- both tiers present; Stage-1 → Stage-2 rerank (today's behavior)
----

`Warming` is implicit (a background/triggered load is in flight). Restore from a v1 (single) blob lands directly in `FullTwoStage`.

=== 3. `ColdPathLoadPolicy` and load ordering

On cold start the index manager loads the **cold tier blob first** (range-read), constructs a `UnifiedIvfIndex` in `ColdBinaryOnly`, and registers it as the served index immediately — serving begins after ~1/32 of the bytes. The warm tier is then loaded (a) eagerly in the background, or (b) on first query, governed by `ColdPathLoadPolicy { BinaryFirstThenRerank, FullEager }`. `FullEager` is the v1 path (back-compat / small indexes); `BinaryFirstThenRerank` is the scale-to-zero path, default for object-store-backed collections.

=== 4. Stage-1-only serving

When `state == ColdBinaryOnly`, `search_with_binary_acceleration` returns the Hamming-ranked top-k of the IVF-pruned candidates **without the fp32 rerank** (the rerank loop at `dual_store_ivf.rs:1784` is skipped; `binary_codes` and centroids suffice). This is lower-recall but immediately available. The existing empty-tier guard already degrades gracefully; this adds the symmetric "fp32 absent" branch.

=== 5. Recall-envelope disclosure (reuse, do not rebuild)

The gate + EXPLAIN surfaces already exist:

* `RecallProbeGate` stays **conservative** in `ColdBinaryOnly`: do not open the "quantized-verified" gate on Stage-1-only probes (Stage-1 recall ≠ two-stage recall). The `RecallObserver` (`src/services/recall_observer.rs`) only opens the gate once the warm tier is present and two-stage recall passes.
* Disclose the coarse mode via a new `route_explain` hint `COLD_STAGE1_ONLY` + a Plan-section line ("serving Stage-1-only: rerank tier loading, recall envelope reduced"), mirroring the `QUANTIZED_ROUTE_DOWNGRADED` hint added 2026-05-30 (`src/observability/route_explain.rs`). Carry the flag up the existing per-request `predicate_diagnostics` task-local bus (taken *inside* the search scope), exactly as the downgrade flag does.

== Reuse map

[cols="1,3", options="header"]
|===
| Concern | Reuse

| Cold tier structure | `CentroidStore` (already inelastic/resident, `dual_store_ivf.rs:2106`) + `BinaryCode` (`from_f32` / `hamming`) + `TieredPostingList.vector_ids` for membership.
| Two-blob container | Extend `SerializableIvfState` + `IVF_STATE_VERSION` bump; `IndexSerializer::{serialize,deserialize}_ivf` in `src/index/axis/storage/serialization.rs`.
| Object range-read | `UniversalIndexStorage::promote_from_s3` / the `S3Express` tier already read objects; add a byte-range cold-tier read.
| Stage-1 route | `search_with_binary_acceleration` — add the fp32-absent branch; `search_with_quantized_acceleration` already prefers it when `binary_codes` is non-empty.
| Gate + observer | `RecallProbeGate` / `RecallObserver` — unchanged; add conservatism in `ColdBinaryOnly`.
| Envelope disclosure | `route_explain` hints + `predicate_diagnostics` task-local bus (the `QUANTIZED_ROUTE_DOWNGRADED` pattern).
| Metadata profile | `AxisSerializedIndexMetadata` (`serialization.rs:107`) — add the cold-path profile fields.
|===

== Alternatives considered

. **Keep single-blob + replay (status quo).** Rejected: loads 100% of bytes before serving; fails criterion #1 by construction.
. **Serialize `binary_codes` directly but keep one blob.** Rejected: removes the reconstruction cost but still loads fp32 in the same blob — no binary-*first* ordering, no Stage-1-only serving, no upgrade path.
. **Adopt Vortex / a new columnar format for the tiers.** Rejected here (consistent with F3's scope-narrowing): duplicates the `proximadb-block-format` investment and violates the reuse-first mandate. Two bincode blobs + a metadata profile is sufficient; revisit only if benchmarks (T-F) miss the byte/latency target.
. **Push tier ordering into `UniversalIndexStorage`.** Rejected: it is a whole-blob mover with no intra-index tier model; encoding "binary sub-tier first" there would leak index internals into the generic cache. Ordering belongs in the index serialization + `ColdPathLoadPolicy`.

== Consequences

* **Positive:** first cold query serves after ~1/32 of index bytes (criterion #1); scale-to-zero between F1 loop turns becomes economical; the binary route, gate, observer, and EXPLAIN disclosure shipped this session all compose into one coherent cold path.
* **Negative / managed:** Stage-1-only recall is lower than two-stage — *disclosed* (criterion #2) and *bounded in time* (warm tier loads behind it). Two-blob serialization adds format complexity (mitigated by the version bump + v1 back-compat). Warm-tier memory pressure reuses the existing `UniversalIndexStorage` demotion (Memory→NVMe→HDD→S3) — no new eviction logic.
* **Neutral:** one logical copy preserved (criterion #3) — the two tiers are projections of the same index, not a second store.

== Success-criteria mapping (Phase 8 F2)

. *≤ ~1/30 bytes before serving* → T-A/T-B/T-C/T-F.
. *Two-stage recall meets floor, envelope disclosed* → T-D/T-E (Stage-1-only disclosed; two-stage resumes after warm load); the gate + `QUANTIZED_ROUTE_DOWNGRADED` disclosure already shipped.
. *Gate FAIL → non-quantized fallback + EXPLAIN reason* → already shipped (2026-05-30).
. *Cold-start latency seconds-class* → T-F.

== Risks

* **Stage-1-only recall floor unknown.** Hamming-only recall@k over a real corpus is not yet measured; T-F must quantify it so the disclosed envelope is honest. If it is too low to be useful, fall back to `FullEager` for that collection (policy already provides the switch).
* **Warm-tier load latency dominates.** If the fp32 tier load is slow, queries spend a long time in `ColdBinaryOnly`. Mitigation: per-cluster lazy load (load only the fp32 of probed clusters first) — a T-E refinement, not a blocker.
* **Calibration coupling with F1.** The `RecallObserver` interval (default 300s) gates when two-stage becomes "verified"; a freshly warmed index may serve Stage-1-only longer than necessary. Trigger an immediate probe on warm-tier completion.

== Literature review (2026-05-31) — revisions from the arxive corpus

A design review against six recent ANN papers (full text read via `pdftotext`; arXiv ids in brackets) validated the two-tier / load-cold-first architecture but surfaced three places the *current* implementation is suboptimal. None require abandoning the two-blob / IVF / reuse-first commitments above.

**External validation of the thesis.** *Onyx* [2604.20401] independently arrives at our exact structure — a "compact intermediate representation that proactively prunes the majority of bandwidth-intensive full-precision accesses," with a layout that co-locates the coarse hints (fetched first) and stores full-precision separately (fetched only for survivors). It reports **5× ANN bandwidth reduction at ≤15% more accesses**. *d-HNSW* [2505.11783] keeps a ~0.4 MB representative index resident and fetches the bulk on demand — confirming our centroids+COLD-resident / WARM-fetched split (our COLD at ~1/32 is generous, not tight).

=== R1 — COLD codes: codebook-free *rotated-residual* 1-bit, not naive sign (HIGHEST LEVERAGE)

Our `BinaryCode` is a raw per-dimension sign bit: no random rotation, no renormalization, no distortion bound. *Block-Sphere VQ* [2605.19972] Table 1 shows rotation-based 1-bit quantizers (EDEN / RabitQ / TurboQuant) achieve bounded **MSE ≈ 0.363** and **inner-product distortion ≈ 0.571/(d−1)**; naive sign has *no* such bound and is the dominated corner. *IVF-TQ* [2605.17415] quantizes the **residual to the IVF centroid** (which we already keep resident) with a fixed rotation + a data-independent Lloyd–Max quantizer and measures **+17.9pp recall** over IVF-PQ on streaming SIFT-10M at matched memory. Same ~1/32 byte budget; directly raises the Stage-1-only recall floor flagged below. **It also resolves the F1↔F2 coupling**: codebook-free codes need *no re-encode* when F1 reclusters the coarse partition, and IVF-TQ proves per-batch retraining does not even recover the streaming gap (paired-t p>0.28; ~0.15pp for 309s compute). IVF-RaBitQ already ships in Milvus / cuVS / LanceDB / Weaviate. **Action:** make the COLD tier the rotated-residual 1-bit code from the in-repo TurboQuant work (ADR-021), not naive sign — a new task **T-G** (COLD-tier quantizer upgrade), sequenced before T-F so the benchmark measures the real representation.

=== R2 — adaptive Stage-1 candidate count + early-termination, not fixed `candidate_k = 4·k`

*AQR-HNSW* [2602.21600] uses a multi-stage rerank that runs fp32 distance "only when necessary," with a per-target-recall candidate schedule and a gap/ratio **early-termination gate** that skips the exact stage when the top-k is already well-separated (it cites pure 1-bit FAISS binary at ~75–80% recall — our Stage-1-only prior). **Action (folds into T-D/T-E):** replace the fixed `BINARY_RERANK_EXPANSION = 4` with a recall-targeted candidate count, and use the separation gap as a *per-query* confidence signal for when `ColdBinaryOnly` is trustworthy enough to skip/defer fp32 rerank — sharpening the T-E upgrade decision and the recall-envelope disclosure.

=== R3 — WARM loading: per-cluster, survivor-aware, de-duplicated, I/O-overlapped — not whole-tier eager

Onyx fetches full-precision **only for query survivors**; d-HNSW fetches each partition's fp32 **once per batch** with a contiguous per-partition layout (single range-read). *LIOS* [2605.19335] harvests the >40% of ANN CPU time spent stalled on I/O to run background work via `io_uring`, under a single user-facing latency-degradation bound θ. **Action (refines T-C/T-E):** (a) lay WARM out **per-IVF-cluster contiguously** (also answers the T-C open question — COLD blob first, then per-cluster WARM extents), (b) fetch a cluster's fp32 on first probe and share it across concurrent cold-path queries, (c) overlap that fetch with Stage-1 serving via stall-harvesting bounded by θ, rather than an eager whole-tier loader competing for bandwidth.

=== R4 — optional 3-tier ladder (measured fallback)

Onyx argues a *coarse* hint alone barely reduces bandwidth and a *medium*-precision hint does the pruning work; Block-Sphere shows 2-bit codes cut MSE ~3× at 1/16 of fp32. **Action:** keep a 2-bit (or asymmetric reconstructed-distance) MID tier as a *measured* fallback gated on T-F — only if R1's rotated 1-bit Stage-1 recall is still too low to disclose honestly. Not a v1 commitment (reuse-first).

== Risks

* **Stage-1-only recall floor unknown.** Hamming-only recall@k over a real corpus is not yet measured; T-F must quantify it so the disclosed envelope is honest. AQR-HNSW's ~75–80% figure for naive 1-bit binary is the prior; R1 (rotated-residual codes) is expected to lift it materially. If still too low, fall back to `FullEager` (policy switch) or the R4 MID tier.
* **Warm-tier load latency dominates.** If the fp32 tier load is slow, queries spend a long time in `ColdBinaryOnly`. Mitigation: R3 — per-cluster survivor-aware lazy load with stall-overlapped I/O under a bounded degradation budget.
* **Calibration coupling with F1.** The `RecallObserver` interval (default 300s) gates when two-stage becomes "verified"; a freshly warmed index may serve Stage-1-only longer than necessary. Trigger an immediate probe on warm-tier completion. R1 (codebook-free codes) removes the re-encode-on-recluster half of this coupling entirely.
