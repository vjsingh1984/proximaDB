== 1. Context — first principles

A query trace is, from first principles, **the per-query bill of materials for the five co-design
dimensions** (ADR-052): the object-storage I/O, the network egress, the local-disk/cache hits, the
per-modality compute, and the governance context (tenant, route) that one query consumed. ProximaDB
already *captures* this in-process — `IoTraceSnapshot`
(`crates/modalities/proximadb-observability-engine/src/io_trace.rs`) is stamped at every I/O boundary
and read at `instrument()` exit by three observers: the cost model (route), the cache stats, and the
always-on **billing** observer (ADR-027). ADR-064 Decision 3 / TD-TRACE-1 added the *structured*
content (routing reasons, lowering declines, and — Slice 2 — the per-operator `exec[]` vector).

Before #1084/#1087 the trace was **ephemeral and shapeless**:

[listing]
----
  per-query:  I/O boundaries ──stamp──▶ IoTraceSnapshot ──instrument() exit──▶ observers ──▶ {cost model, cache, BILLING}
                                              │                                                         │
                                              └── optional tracing::info!(target=io_trace) ─────────────┴─▶ ./log/proximadb.log  (MIXED w/ app log,
                                                     (io-trace feature, default OFF; formatted text)                              text, io-trace-gated)
       ▲                                                                                                    ▲
       │ no DURABLE, QUERYABLE history                                                                       │ not ETL-native: parse log lines back out
----

S1/S2 now provide an external flat JSONL+zstd stream, but two target-model
problems remain:

1. **External history exists and sealed batches are restart-safe, but ingress is intentionally
   best-effort.** The old formatted-log-only path was fragile and not ETL-native; #1084/#1087 now
   emit structured JSONL+zstd, and #1093 seals immutable pending files, conditionally creates the
   object, verifies digest collisions, and retries pending files at startup. Records may still be
   dropped from the bounded memory queue before sealing. The billing observer ships aggregates per
   tenant, not a per-query durable ledger.

2. **The snapshot is one wide, sparse, ever-widening struct.** `IoTraceSnapshot` is a flat superset:
   object-store counters, footer hits, `compute_ms`, wall spans, egress, route, the plan-geometry
   vector, and now `exec_ops`. Every modality that wants to be observable (vector prune ratios, graph
   frontier, embedding KEU) adds *more flat fields that are null for every other modality*. This is a
   sparse-superset anti-pattern: it widens forever, and it columnar-compresses badly (a `trace_exec`
   column is null for every vector query, and vice-versa).

The decision below separates the three concerns a durable trace conflates — the **data model** (what a
trace *is*), the **transport** (how it *durably lands*), and the **consumption** (billing vs cost-model
vs analytics) — and co-designs each against its dominant cost term.

== 2. Decision

=== D1 — Data model: an **envelope**, not one wide struct

A trace record is a homogeneous **header** + a modality-discriminated **payload** (a tagged union), not
a flat superset.

[listing]
----
  TraceRecord = Header  ⊕  Payload
  ─────────────────────────────────────────────────────────────────────────────
  Header   (EVERY modality emits it — the homogeneous co-design cost spine):
    query_id, tenant, ts, route(shape_class,backend),
    get_ops/put_ops/list_ops, bytes_read, range_gets, footer_hits/misses,
    compute_ms{engine→ms}, setup_ms/open_ms/emit_ms, egress_bytes(KOU), storage_profile
  Payload  (tagged by modality — internally HOMOGENEOUS):
    Relational { plan geometry (depth/nodes/fanout/blocking), exec:[{op,rows_in,rows_out,ms_self,bytes,spill}] }
    VectorAnn  { prune ratios, candidates, stripe gets, quant tier }
    Graph      { hops, frontier sizes }
    Document   { shred stats }        Embedding { KEU input/output tokens }
----

**First principle:** a trace has a *homogeneous cost spine* every query pays (I/O round-trips, compute,
egress — the co-design dimensions) and a *modality-specific tail*. Forcing the tail into the spine
makes the record a sparse superset. The envelope keeps the spine stable (billing reads *only* the
header — a stable seam) and makes each payload internally homogeneous, which is exactly what columnar
storage rewards (D3). The current flat `IoTraceSnapshot` is the **migration source**, not the target;
the header↔payload split lands at a stable seam so **billing is never broken** (it already reads only
header-class fields — `compute_ms`, `egress_bytes`).

=== D2 — Two buses and two durability classes, never conflated

The cost/I-O trace is intended to be **per-query**, but this sink is
**best-effort observability evidence**, not billing authority. Quality/eval signals —
recall@k, hybrid/RRF ranking, semantic relevance — are **sampled, eval-grade**, and already ride the
`predicate_diagnostics` bus; TD-TRACE-1 named recall an explicit non-goal. Merging them would
(a) tax the hot path with sampling/scoring logic it must not carry, and (b) mix cost-accounting fields
with sampled quality data in one schema. **They stay two buses.** This ADR governs only the cost/I-O
trace.

Billing remains the fail-closed aggregate path in ADR-027. A future per-query billing/audit ledger
would require a separate durable outbox with explicit acknowledgement, replay, and retention—not a
flag that silently upgrades this drop-capable sink. Therefore no ADR, UI, or downstream reconciliation
may call the current stream “billing-grade.”

=== D3 — Format: two formats, two tiers, config-selected

[listing]
----
  HOT write path  ──▶  LANDING = JSONL + zstd           ──async compaction──▶  WAREHOUSE = Iceberg + star-schema Parquet
                       (append-native, one record/line)                        trace_header  +  satellites:
                       additive-compatible (serde #[default])                  trace_exec / trace_vector / trace_graph …
                       modality heterogeneity for free                          joined on query_id
                       debuggable (zcat | jq)                                   each satellite internally HOMOGENEOUS
----

* **Landing format = JSONL + zstd.** One record per line avoids schema-bound encoding on the query
  path; `#[serde(default)]` supports additive reader compatibility but does not eliminate the need
  for an explicit envelope `schema_version`.
  It carries modality heterogeneity cheaply and remains directly debuggable (`zcat | jq`).
* **Warehouse = Iceberg-managed star-schema Parquet**, produced by async compaction:
  a `trace_header` fact table + **one satellite per modality** (`trace_exec`, `trace_vector`,
  `trace_graph`, …), joined on full event identity, with `query_id` retained as the analytical query
  join key. Each satellite is internally homogeneous → columnar
  compression and projection/predicate pushdown *win* (the exact benefit the flat sparse struct
  forfeits). Flattening the relational `exec[]` LIST into one `trace_exec` **row per operator**
  sidesteps the nested-LIST concern and makes "which operator is slowest across the fleet" a trivial
  DataFusion scan. Parquet files alone are not discovery/commit authority; the standard-outside
  warehouse surface is an Iceberg table/manifest commit.
* **Reject Avro.** Avro is row-oriented with no predicate/projection pushdown; it earns its keep only
  as a Kafka/schema-registry wire format, which is out of scope (D2 non-goal). In a warehouse read
  through DataFusion it would be transcoded to Parquet anyway — so we produce Parquet directly.

=== D4 — Transport: object-store dispatch, co-designed against the dominant cost term

The dominant cost term for a cloud trace stream is **object-store request count + GB-month at rest**,
*not* CPU. The transport is co-designed to that:

* **No query-path I/O.** The observer at `instrument()` exit currently serializes one JSON record and
  enqueues it to a bounded **in-memory ingress queue**. Serialization is real hot-path CPU; measure
  and bound it rather than calling the path “enqueue only.” A background task seals on size OR
  interval, compresses, and PUTs. The query path never compresses or performs filesystem/network I/O.
  `segment_bytes` means **uncompressed JSONL bytes**. Compressed size is observed; 4 MiB is not called
  a multipart part size (this is a single PUT, and backend multipart minimums differ).
* **Crash-aware delivery state.** Seal locally as an immutable pending file, upload with conditional
  create, and retire the pending file only after success or content verification. Startup inventories
  and retries pending files. A direct PUT failure that writes a file nobody retries is not a durable
  spool. Drops, seal failures, upload failures, pending bytes, and last-success timestamps are metrics
  and health—not warnings alone.
* **Collision-free identity and idempotency.** Every record carries
  `{schema_version, writer_incarnation_uuid, sequence, query_id, event_time}`. Keys use
  `{date}/{writer_uuid}-{first_seq}-{last_seq}-{content_digest}.jsonl.zst`; conditional create plus
  digest verification makes retry idempotent. Wall-clock nanoseconds alone are not unique across pods.
* **Keys via `DrPathBuilder`.** The default cross-tenant stream lives under `_operator/io_trace/` and
  requires operator-only ACLs/encryption. Tenant-isolated mode writes one tenant per object beneath
  that tenant's structural data root; a `tenant_id=` partition under one shared operator object is
  partitioning, not isolation.
* **Access tier is the at-rest lever (ADR-036).** PUT these objects **Cool/Cold** via the canonical,
  cloud-neutral `ObjectAccessTier` / `FileOptions.storage_class` (never per-cloud strings) — GB-month is
  the cost term, moved by the tier, not the scheme.
* **Ingress overflow → drop-oldest.** The in-memory queue is bounded (`spool_max_bytes`); on overflow
  it drops the oldest record. Best-effort observability must never block or OOM the database, and the
  exact dropped records/bytes are surfaced.

=== D5 — Consumption: a separate, gated observer; billing untouched

A new `set_trace_observer` seam, **distinct from the billing observer**. Billing stays always-on and
**never gated** (ADR-027, enforced by `scripts/check_billing_never_gated.py`) — the trace sink is
default-**OFF**, env/TOML-gated, and reads the same snapshot without touching the billing input set
(`compute_ms`/`egress_bytes`), so it is provably **zero-double-count** and cannot regress a meter.

=== D6 — Configuration: TOML-first, env-override (12-factor)

[source,toml]
----
[observability.io_trace_sink]
enabled          = false          # default OFF; env: PROXIMADB_IO_TRACE_SINK=1
local_dir        = "./log/io_trace"
segment_bytes    = 4194304        # uncompressed JSONL threshold
flush_interval_s = 60             # ...or this, whichever first (bounds latency-to-warehouse)
compression      = "zstd"
format           = "jsonl"        # current landing format; warehouse compaction is separate
object_store_uri = "az://…/io_trace"   # or reuse the data object-store
access_tier      = "cool"         # Cool/Cold — GB-month lever (ADR-036)
partition_by     = "date"         # date | tenant | host
retention_days   = 30
spool_max_bytes  = 268435456      # bounded spool; drop-oldest on overflow
pending_max_bytes = 1073741824    # hard cap; never evict already-sealed pending files
----

**Current code contact.** `enabled`, `local_dir`, `segment_bytes`, `flush_interval_s`,
`spool_max_bytes`, `pending_max_bytes`, `compression`, `format`, `object_store_uri`, and
`access_tier` resolve today. Only JSONL+zstd is implemented; strict runtime resolution rejects
unsupported `format`, `compression`, and access-tier values. `partition_by` and `retention_days` deserialize but are not
carried into `ResolvedIoTraceSinkConfig` and have no runtime effect. They are reserved until their
implementation and tests land; documentation must not advertise them as active controls.
Once `pending_max_bytes` is full, the worker preserves existing pending files and
stops draining memory ingress, causing measured ingress drops; it never deletes sealed pending data
to make room.

Config remains default-OFF. Every active field gets a documented env override; startup emits the
resolved delivery class and rejects contradictory settings.

== 3. Co-design dimensional analysis (ADR-052 spine)

Each of the five physical dimensions, and the dominant cost term this ADR moves on it:

[cols="1,3",options="header"]
|===
| Dimension | Decision & dominant cost term
| **Object storage** | *Requests + GB-month + commit/discovery.* Batch records, zstd, Cool/Cold access tier, immutable idempotent keys via `DrPathBuilder`; Iceberg manifests commit warehouse outputs. Measure compressed object size and PUT count rather than asserting a codec ratio.
| **Network** | *Egress round-trips.* Traces flow app→warehouse in-region, batched — few large requests, not per-query chatter. No cross-region egress on the hot path.
| **Local disk / cache** | *Backpressure + crash gap.* The bounded memory ingress protects the DB; immutable pending files protect sealed batches across restart. Pending-byte caps and retry policy are separate from ingress drop policy.
| **Compute-per-modality** | *Bounded serialization on query completion; compression/transcode off-path.* Measure serialization p95 and allocation. Envelope+typed payload keeps downstream satellites homogeneous.
| **Governance / security** | *Structural isolation, least privilege, retention ordering.* Operator stream ACL/encryption is mandatory; tenant mode uses tenant roots. The trace excludes row/vector/raw-query payloads, but route/operator strings are still treated as potentially sensitive. Lifecycle may delete source JSONL only after the warehouse commit/watermark covers it.
|===

== 4. Alternatives considered — and rejected

* **A1 — Keep one wide `IoTraceSnapshot` forever.** Rejected: the sparse-superset widens with every
  modality and columnar-compresses badly (D1). Envelope+typed-payload is the target end-state.
* **A2 — Log-routing only (a `tracing` Layer to a dedicated file).** A `fmt::Layer::json()` filtered to
  `target=proximadb::io_trace` would separate the stream cheaply, but it rides the `io-trace` feature
  gate, re-serializes from a formatted event, and still needs log-line parsing for ETL. Useful as a
  *stopgap*, not the architecture. The observer→structured-sink (D5) is the durable path.
* **A3 — Avro / Kafka streaming bus.** Rejected: row-oriented, no pushdown, and it earns its keep only
  with a schema registry + streaming consumer (out of scope, D2). It would transcode to Parquet in the
  warehouse anyway (D3).
* **A4 — Fold the trace sink into the billing observer.** Rejected: entangles observability with
  billing, violating ADR-027 (billing never gated); a separate observer keeps billing provably
  unaffected (D5).
* **A5 — Synchronous upload at query time.** Rejected: puts compress + PUT round-trips on the hot path
  (D4). Serialize+enqueue with background seal is the current split; a future zero-copy handoff may
  reduce serialization CPU if measurement justifies the ownership complexity.
* **A6 — Parquet on the hot write path.** Rejected: Parquet's schema rigidity fights modality
  heterogeneity and forces buffering/rewrite (write amplification) vs a JSONL append. Parquet is the
  *warehouse* format, produced by async compaction (D3).

== 5. Consequences & migration

* **Incremental, safe rollout.** The sink first serializes the **existing flat snapshot** as JSONL
  (S1–S2 in TD-TRACE-2), so no data-model refactor blocks the durable stream. The **envelope refactor**
  (D1) lands later at a stable seam (billing reads header-class fields throughout) as a separate slice.
* **`query_id`.** A stable per-query id is needed to join header↔satellites; mint it at
  `instrument()` entry if one does not already exist. It does not replace writer UUID + sequence as
  the ingestion/dedup identity.
* **Warehouse producer.** Async compaction maps immutable input object identities to Iceberg commits.
  Retry either observes the committed input set or produces the same deterministic output; source
  JSONL is retained until the manifest commit and watermark are durable. Satellite rows carry the
  source event identity, preventing duplicate operators after retry.
* **Retention.** Prefer object-store lifecycle, but only after its minimum age exceeds worst-case
  upload/compaction lag and the warehouse watermark covers the source. `retention_days` is currently
  inert and cannot imply policy installation.
* **Gate.** Observe-only, no served-result change; default-OFF and billing guard remain necessary but
  are insufficient. The acceptance conditions below close the data-loss and governance surfaces.

== 6. Acceptance conditions from the first-principles pressure test

. **S2 delivery hardening:** pending-file state machine, startup retry, collision-free writer
  identity, conditional-create idempotency, and metrics/health for drop/seal/upload/pending state.
. **Lifecycle:** duplicate installation is rejected or gracefully drains the prior worker; it never
  aborts a live worker and loses its queue. Shutdown timeout/drop state is observable.
. **Hot-path budget:** representative p50/p95 serialization+enqueue overhead and allocation are
  recorded with sink OFF/ON; no query-path filesystem/network/compression work.
. **S3 envelope (shipped #1133):** explicit schema version and event identity; unknown payload variants remain
  readable/skippable; billing observer input/output is byte-identical and separately tested.
. **Governance:** operator-stream ACL/encryption contract and tenant-root mode are integration-tested;
  no raw query, row, vector, secret, or unbounded user value enters the trace.
. **S4 warehouse core (shipped #1136):** JSONL→Parquet round-trip under an Iceberg manifest,
  crash/retry dedup, schema evolution, and a source-retirement watermark. **S4b:** background
  scheduling plus small-file compaction policy/tests.
. **Honest delivery label:** until a fail-closed outbox is separately designed, the sink stays
  best-effort observability and cannot be used as billing/audit authority.

**Flip verdict:** ADR-066 remains Proposed. S1–S4 validate the landing, delivery, envelope, and
warehouse-commit shape, but acceptance still requires the lifecycle/hot-path and governance conditions
above plus the S4b background trigger. Shipped slices do not upgrade best-effort observability into
billing-grade durability.
