== Context

The canonical spine (`trait TableRecordStore` + `trait TableWalAppender`, `TenantContext` in every
signature) already exists but is adopted on a **gradient**: relational rides it fully, vector for
durability only, document is mid-migration, and graph/observability/timeseries/ledger/queue each carry
**their own WAL and re-implement their own tier storage + tenancy plumbing** (RFC-0002 §map). Two
costs: **code proliferation** (the queue re-rolls memory/disk/object tiers; N private WALs) and
**inconsistent correctness/security** (an off-contract modality does not inherit fail-closed tenant
isolation, tiering, or the CDC feed). Independently, the just-shipped ledger and the relational OLTP
insert path want the **same atomic primitive** — insert-if-absent on a composite key — which the store
lacks, so relational fakes it with a coarse table op-lock. The minimum bar (serverless, low-cost,
composite natural keys) forces the atomic primitive into the storage layer.

== Decision

**D1 — Consolidate the CONTRACT surface, not the implementations.** A small family of narrow,
tenancy-carrying contracts (record store, WAL/durability, `ConditionalKeyStore`, read IR, tiering,
tenancy, and the **catalog**) is the single foundation every modality stacks on. The **catalog is the
governance seam**: one metamodel — `Container → Entity → Attribute → Identity/Uniqueness → Index →
Constraint/Policy` — governs *all* modality data (schema, RBAC, tenancy, constraints, indexes), with
only the *vocabulary and index shapes* differing per modality (relational `database/table/column`,
btree/bitmap; vector `namespace/collection/field`, ANN/axis-index; document `collection/field·path`,
path/fulltext/array/geo; graph `graph/node·edge/property`, CSR-adjacency; observability
`namespace/stream/field`, Tantivy/PromQL). DDL, RBAC, schema evolution, and constraint/index
enforcement are written **once** against the metamodel — which is precisely why the `ConditionalKeyStore`
(D3) is modality-agnostic ("uniqueness on the entity's identity key" is a metamodel concept). This
formalizes the existing `proximadb-storage-ports` family; it does **not** introduce one god-trait.
_(Refined P3 — D12: the identity slot is **not** uniform across modalities and Index/Constraint likely
split from the logical core; graph edges become a first-class relationship type. Grounded in U-Schema
<<biblio-uschema>>.)_

**D2 — One contract, many implementations; divergent access keeps its own impl *behind* the contract.**
A modality may not invent an off-contract WAL or re-roll tiers/tenancy. Where its access pattern truly
diverges (ledger hot counters, queue offsets, timeseries ingest), it ships its **own implementation of
the shared contract** — ratifying ADR-071's ledger WAL and the queue's dedicated log as *contract
impls*, not silos. Forcing everyone onto one shared WAL is rejected (the map + ADR-071 + the queue
precedent prove access patterns legitimately diverge).

**D3 — New `ConditionalKeyStore` contract = the atomic OLTP primitive, _fenced_.** (Amended P2.) The
primitive is a *generation-fenced* conditional write, **not** a bare existence check:
`put_if_absent(tenant, keyspace, key: &[u8], oid, fence: Generation) -> Result<Committed, Conflict>`,
plus `get` and a *fenced* `delete`/tombstone. It is extracted from the ledger's proven **version-CAS**
core, whose `compare_and_swap` returns a `Version` — the fencing token a bare object-store
`PutMode::Create` drops, and without which a writer cannot distinguish "my own idempotent retry" from a
"real conflict" (the ABA gap; see the P2 revision). For a composite natural `PRIMARY KEY` the guarantee
needs **no separate index write**: the row's `oid` already *is* its primary-key encoding
(`to_proxima_record` → `primary_key_string`), so PK uniqueness is a **single row-keyed-by-PK** fenced
write — not a two-write index→oid→row sequence. Secondary `UNIQUE` (a genuine second durable write) and
FK (a `get`) stay **inside the existing op-lock critical section** for the MVP. **The op-lock is
retained, not demoted** (revised — it also orders `ON DELETE CASCADE`; see D-note in the P2 revision).
_(Refined P3 — D11: the fence becomes **append-only MVCC + tombstone**, not slot-reclaim; the conflict
result **returns the current holder**; the contract is **capability-typed** (each impl declares its
atomic scope). Non-unique secondary indexes are **blind-writes**, only `UNIQUE` needs coordination.
Grounded in Aurora DSQL <<biblio-dsql>>, cMVBT <<biblio-cmvbt>>, Cornus <<biblio-cornus>>, ScalarDB
<<biblio-scalardb>>.)_

**D4 — Storage ⊥ compute, decoupled + swappable behind contracts.** Compute (insert executor; Volcano/
DataFusion/DuckDB readers) depends only on the contracts, never a storage impl; storage impls (canonical
WAL, dedicated WAL, object-store) and compute engines (ADR-039) swap independently. Dispatch is
**coarse-grained** (per batch / per query), so swappability bears **zero per-row cost** — the balance
between flexibility and speed.

**D5 — Default = the generation-fenced local path; object-store `put_if_absent` is the scale-to-zero
_escape hatch_, not the OLTP hot path.** (Amended P2 — reverses the original "object-store default".)
The correctness authority already in the codebase is the **object-store generation fence** / per-partition
lease (`src/cluster/partition_lease.rs`), which achieves atomicity by claiming *fresh
monotonically-versioned successor slots* (`v{n}.manifest`) — an **append-only** pattern that does **not**
transfer to a *reclaimable fixed PK slot* (delete + re-insert of the same key). A bare fixed-key
`put_if_absent` over S3/GCS/Azure is therefore neither reclaim-linearizable nor cost-viable at OLTP
insert rates (tens-of-ms RTT + a per-op charge per key, times each unique constraint). The hot,
correctness-carrying default is the **generation-fenced local-WAL** path (the ledger core, generalized
`bytes→oid`); the object-store impl is the availability / serverless escape hatch behind the same
contract. _(Refined P3 — the two impls realize the **fence-placement fork**: local-WAL = fence-in-storage
(CAS); serverless = fence in a per-key coordinating step + a **batched successor-slot log append**, per
Aurora DSQL's adjudicator+journal <<biblio-dsql>> and BatchWeave's batch-manifest <<biblio-batchweave>>.
One contract, two placements.)_

**D6 — Tenancy in every contract signature; enterprise security is structural.** `TenantContext`
(fail-closed), `DrPathBuilder` per-tenant paths, and `ObjectAccessTier` are foundation facilities every
modality inherits at the contract boundary — never re-implemented per silo. Neutral units only.

**D7 — Compile-time modality composition.** Every modality + its contract impls are `#[cfg]`-gated
features, so a deployment links only what it runs (lean profiles) — per the modality-composition
handoff. Reduced binary/RAM/attack surface, lower cost to operate.

**D8 — Additive, incremental, evidence-gated migration.** Widen contract adoption modality-by-modality,
leaf-first; each step additive + feature-gated, with reclaimed-footprint / latency evidence filed to
`BENCHMARK_EVIDENCE.toml` (ADR-052 measure-don't-assert). `default` unchanged until opt-in.

== Design-gate revision (P2 · 2026-07-24) — three-model review reconciliation

Before acceptance, the design was pressure-tested by three independent adversarial reviews (Kimi, GLM-5.2,
DeepSeek), each grounding its critique in the actual code. Their load-bearing findings were re-verified
against the source. The findings below are **confirmed against code** and drive the D3/D5 amendments
above plus D9/D10.

**Confirmed findings (unanimous → binding).**

* *A bare `put_if_absent` is not an atomic row insert, and it drops the fence.* The ledger's real
  primitive is `compare_and_swap(expected: Option<Version>) -> Result<Version, CasError>`
  (`proximadb-ledger/src/lib.rs:77`) — **version-fenced**; the object-store primitive is
  `PutMode::Create` returning `()` (`proximadb-object-store/src/lib.rs:247`) — a bare existence check
  with no token. Generalizing the former to the latter silently loses ABA/retry disambiguation. → D3
  carries an explicit fence.
* *The existing "object-store `put_if_absent` is proven" citation does not transfer.* Every existing
  consumer (Iceberg manifests `manifest.rs`, partition leases `partition_lease.rs`) claims a **fresh
  monotonically-versioned successor slot**, never a reclaimable fixed key. A PK slot must be reclaimed on
  `DELETE`/PK-`UPDATE`; `delete` is unconditional (`lib.rs:372`) and `put` is create-only, so the
  reclaim path races (torn insert / orphaned-slot / natural-key-mutability leak). → D5 demotes
  object-store to escape hatch; delete becomes fenced/tombstoned.
* *The op-lock must not be demoted.* `TableOpLockRegistry` (`proximadb-catalog/src/manager.rs`) is
  in-process, and its own docstring says it exists to order `ON DELETE CASCADE` (child-scan → child-mutation
  → parent-tombstone) — demoting it re-opens the cascade-orphan race. FK cascades acquire it sorted
  (`dml/mod.rs:3332`). → D3 retains it; secondary `UNIQUE`/FK stay in its critical section for the MVP.
* *`oid == primary_key_string` (`relational.rs:282`).* The row is keyed by its own PK, so the reviewers'
  shared "a row insert is two durable writes (index + row)" premise is **false for the primary key** —
  PK uniqueness is one row-keyed-by-PK write. It stays true for secondary `UNIQUE` (a real second write).
  → D3 splits the two cases.
* *The composite-key codec is provably defective.* `encode_primary_key_tuple` (`relational.rs:864`)
  stringifies columns and joins on `\u{1f}`; its own docstring admits the separator is **unescaped**
  (values containing it collide), and the string form is neither order-preserving (`"10" < "9"`) nor
  type-tagged. → D9.

**D9 — Typed composite `Identity` key codec (the one foundational change taken now).** Replace the
stringly-typed `oid: String` + `encode_primary_key_tuple` string-join with a typed, **length-delimited,
order-preserving, NULL-explicit, per-column type-tagged, tenant-scoped** key codec. `oid`/`local_id`
derive from it. This is the seam `ConditionalKeyStore` keys on and the direct fix for the R4 codec
defect; it is small and self-contained (an ADR-worthy sub-change tracked in TD-FOUNDATION-1). Scope
chosen at the design gate: **typed identity now, record-composition refactor deferred (D10).**

**D10 — `ProximaRecord` is already the multi-modal meta-record; keep it, defer the composition refactor.**
Code finding: `ProximaRecord` (`proximadb-records/src/lib.rs:776`) already carries `props: ProximaTree`
(NF² arbitrary-metadata tree = relational + document), `edge: Option<EdgeShape>` (graph, first-class),
`embeddings: Vec<EmbeddingCell>` (vector), `sequence: Option<TokenSequence>` (event/TS), `refs`
(cross-modal), plus identity/tenancy+RLS/bitemporal/provenance/branch headers. The record-shape
consolidation is therefore **already banked** — no `MultiModalMetaRecord` overhaul is needed, and this
also softens the metamodel-fidelity critique (the *record* models edges/sequences first-class; only the
catalog metamodel doc flattened them — a doc fix, not a record fix). The genuine tension is that
`ProximaRecord` is a **fat union** (every modality carries every other's fields; the `branch_id` serde
regression documented in the struct is a scar of that coupling). The *composed-record* alternative
(thin `RecordCore` + `#[cfg]`-gated modality extension payloads) is real but has wire/WAL/proto/all-modality
blast radius and is **routed to the compile-time modality-composition track (#1180)**, not this OLTP MVP.

**Verdict reconciliation.** Kimi (b, proceed-with-changes) and GLM/DeepSeek (c, rethink the MVP mechanism)
converge once separated: all three keep the **contract-consolidation thesis** (D1/D2) and reject the
original **MVP mechanism** ("one bare `put_if_absent`, object-store default, op-lock demoted"). Reconciled
outcome: **proceed with the amended (fenced, local-default, op-lock-retained, typed-identity) MVP.**

== Design-gate revision (P3 · 2026-07-24) — research calibration

The P2 design was calibrated against 10 systems/DB research papers (full-text, not abstracts) plus
Google's Spanner columnar-engine disclosure. See the _Research bibliography_ below and RFC-0002
§_Research calibration_ for the per-paper briefs. Net: the papers **confirm the consolidation thesis and
the P2 reversals**, and drive two new decisions (D11, D12) plus refinements to D3/D5/D1.

**Consensus that binds the design (multi-paper agreement):**

* **Uniqueness is the one operation that cannot be blind-written / made commutative** — it always needs
  coordination. Aurora DSQL's blind-write optimization skips the conflict check for *non-unique* indexes
  but **explicitly excludes unique indexes** <<biblio-dsql>>. This is the load-bearing justification for
  `ConditionalKeyStore` existing at all.
* **CAS + a version token is the universal uniqueness substrate**, and it is cleanly separable from each
  modality's storage engine (Cornus <<biblio-cornus>>, ScalarDB <<biblio-scalardb>>, CCaaS
  <<biblio-ccaas>>, BatchWeave <<biblio-batchweave>>, DSQL <<biblio-dsql>>).
* **Never reuse/overwrite a durable key slot; append + version-order + tombstone + reclaim behind an
  oldest-active-reader watermark** — unanimous across cMVBT <<biblio-cmvbt>>, BatchWeave
  <<biblio-batchweave>>, DSQL <<biblio-dsql>>. cMVBT flags that in-place slot reuse "requires more
  sophisticated synchronization" and defers it — a direct caution against our P2 fenced-reclaim delete.
* **Keep divergent implementations** — native per-modality storage is worth up to 188× vs non-native
  layouts (M2 <<biblio-m2>>); polystore keeps N *semantics* and pays with no cross-engine transactions
  (BigDAWG <<biblio-bigdawg>>). Unify the *contract*, not the engines.

**D11 — Reclaim is append-only MVCC, not slot-reclaim; the contract is capability-typed.** (Supersedes
the P2 "fenced tombstone delete" mechanism.) A PK `UPDATE`/`DELETE` does **not** delete-then-reinsert a
durable slot (the race the reviews found). It **appends a tombstone + a new version** under the key,
resolved by `version ≤ snapshot`; physical reclamation is gated by an oldest-active-reader watermark
(cMVBT <<biblio-cmvbt>>). This dissolves the reclaim race by construction and largely **subsumes the
explicit generation fence** into MVCC version-ordering. Two contract refinements follow: (a) the
conditional op **returns the current holder on conflict** (not just failure), so a loser resolves
retry-vs-conflict — Cornus `LogOnce` returns the settled state <<biblio-cornus>>; (b) the contract is
**capability-typed** — each impl **declares its atomic scope/granularity** (ScalarDB's *Atomicity Unit*
<<biblio-scalardb>>; CCaaS's row-vs-txn granularity leak <<biblio-ccaas>>), not a boolean `supports_cas`.
Non-unique secondary indexes are **blind-writes keyed by the PK** (no conflict check); only `UNIQUE`
takes the coordinated path (DSQL <<biblio-dsql>>).

**D12 — Metamodel: identity is family-parameterized, graph edges are first-class, logical splits from
physical.** (Refines D1.) U-Schema <<biblio-uschema>> — the most complete unified metamodel in the
literature (relational + document + graph + key-value + columnar) — establishes three things our D1 must
absorb: (1) **a graph edge is a first-class `RelationshipType` (peer of `EntityType`) + a `Reference`**,
with its own attributes/variations/direction/multigraph — **not** an identity key; modeling edges through
the `Identity/Uniqueness` slot is exactly what the leading prior art refuses. (2) **The identity slot is
not uniform** — graph omits it, key-value detaches it from attributes; by extension time-series is
*ordering-not-uniqueness*. Make `Identity/Uniqueness` a **family-parameterized slot** with a per-modality
"completeness-gap" list (U-Schema's own discipline), not one uniform semantics. (3) U-Schema
**deliberately split physical (Index) and Constraint into separate metamodels**, judging they don't
generalize alongside Entity/Attribute — so D1's single `…→Index→Constraint/Policy` chain is the
least-supported part of the claim and should **split governance-logical from physical-index**.
**Caveat (open risk):** no unified-metamodel paper covers **time-series or vector** identity — these
remain the highest-risk element of D1 and are flagged for pressure-testing before finalizing.

**Fence-placement fork (D5 refinement).** Aurora DSQL <<biblio-dsql>> — the closest production system
(serverless multi-region OLTP over disaggregated storage) — locates the uniqueness fence in a **separate
per-key coordinating tier** ("adjudicator"), makes **atomicity a single ordered-log append** ("not atomic
commitment, just atomic voting on candidacy"), and keeps **storage a coordination-free, fsync-free
deterministic applier**. This is a valid alternative to fence-in-storage; the two map onto our two impls
(D5). DSQL cautions folded in: prefer **snapshot isolation** (write-write conflicts only) to keep abort
rates sane; **monotonic composite keys hot-shard** under range partitioning (mitigate with hybrid
range/hash); bounded transaction runtime/size are *consequences* of coordination-free serverless.

== Consequences

* **Positive:** reduced code proliferation (siloed modalities stop re-inventing tiers/tenancy/WAL-framing
  and inherit CDC + tiering + fail-closed isolation); foundational consistency; storage and compute swap
  at ease; enterprise security structural; serverless + low-cost by default; modalities build on each
  other (fusion is the proof — pure compose-over-contracts).
* **Cost:** an abstraction tax (mitigated by coarse-grained, map-derived contracts); a multi-crate
  migration (mitigated by additive, feature-gated, one-modality-per-step); the object-store
  `ConditionalKeyStore` trades latency for serverless operation (the hot impl is the escape hatch).
* **Boundary preserved:** neutral units; tenancy fail-closed; the measure-vs-price line untouched; no
  modality's semantics change.

== Alternatives considered

* *One shared WAL for all modalities* — rejected (D2): divergent access patterns (ledger/queue/TS)
  make it wrong; ADR-071 already ratified the ledger's own WAL.
* *A single god storage-engine trait* — rejected: too coarse; the narrow-port family is the right grain.
* *Status quo (per-modality silos)* — the code-proliferation + inconsistent-security cost this ADR
  exists to stop.
