== Context

ProximaDB exposes four protocol surfaces: PostgreSQL wire (pgwire), Arrow Flight,
Iceberg REST, and REST/gRPC. Each protocol has its own type system. The canonical
`ProximaType`/`ProximaValue` type system is richer than any single protocol surface.

When data is read from or written to a protocol surface, type conversions occur. Some
conversions are lossless; others lose information. Without an explicit coercion matrix:

* External engines (Spark, Trino, DuckDB via Iceberg REST) receive opaque binary for
  `props` map and cannot push predicates into document fields.
* Arrow Flight clients receive `FixedSizeList<float32>[dim]` for embeddings but do not
  know the dimension without schema introspection.
* pgwire clients cannot receive graph edge structures as a native type.
* `ProximaValue::Variant` (union type) has no representation in Iceberg.

This ADR catalogs all known lossless and lossy conversions and mandates that planners
surface coercion warnings in EXPLAIN when a query uses a lossy path.

The `ProtocolTypeCoercionNote` struct is implemented in
`crates/control/proximadb-catalog/src/lib.rs::ProtocolTypeCoercionNote::standard_notes()`.

=== Protocol-Level Type Precedence

When a `ProximaType` cannot be losslessly represented in a target protocol, the following
precedence rules apply:

. If the conversion is lossless: use the mapped type.
. If the conversion is lossy and `STRICT` protocol mode is set: reject the query / DDL
  with an error listing the lossy columns.
. If the conversion is lossy and `PERMISSIVE` protocol mode is set (default): use the
  fallback type, emit a warning in query response metadata, and record
  `CatalogStorageLayout.lossy_type_mappings` for the affected columns.
. External compute engines (Spark, Trino) that read via Iceberg REST always operate in
  permissive mode. ProximaDB MUST NOT block external reads based on type coercion warnings.

=== EXPLAIN Surface for Coercion Warnings

When a query plan involves a protocol-level type coercion, the `ExplainOperator` (ADR-004)
MUST include a `coercion_warnings` field:

[source,json]
----
{
  "operator_type": "IcebergScan",
  "coercion_warnings": [
    {
      "column": "props",
      "proxima_type": "ProximaValue::Map",
      "wire_type": "map<string,binary>",
      "lossless": false,
      "note": "Predicate on props.category cannot be pushed into Iceberg scan. Enable props auto-promotion."
    }
  ]
}
----

=== TimestampTz Precision Alignment

Iceberg uses microsecond-precision timestamps. ProximaDB WAL and PAX blocks use nanosecond
precision (`valid_from_ns`, `valid_to_ns`, `created_at_ns`).

The Iceberg export (ADR-007) divides nanosecond values by 1000 for the Iceberg
`timestamptz` columns. On import, the microsecond value is multiplied by 1000.

Applications that require nanosecond MVCC precision AND Iceberg federation MUST add a
separate user-defined column of type `Int64` to store the nanosecond timestamp alongside
the Iceberg `timestamptz` column.

=== Vector ANN Operations Through Protocol Surfaces

ProximaDB ANN distance operations (`<->`, `<#>`, `<=>`  in pgwire; `VECTOR_SEARCH()` in
SQL) are NOT available through Iceberg REST or raw Arrow Flight. External engines that
connect via these surfaces can:

. Read embeddings as `list<float>` / `FixedSizeList<float32>`.
. Perform distance operations client-side using numpy/PyArrow.
. Delegate ANN search to ProximaDB via SQL (`VECTOR_SEARCH()`) through pgwire or REST/gRPC.

External engines that need server-side ANN MUST connect via pgwire or REST/gRPC, not
Iceberg REST. This is a known limitation of the Iceberg REST protocol and is documented in
`OPEN_FORMAT_CATALOG_2026_05_17.adoc`.

== Consequences

=== Positive

* Developers and operators know in advance which types will degrade through which protocol.
* `ProtocolTypeCoercionNote::standard_notes()` can be used by the Iceberg REST handler to
  auto-populate table metadata with coercion warnings.
* EXPLAIN output can surface actionable warnings ("enable props auto-promotion") rather
  than silent degradation.

=== Implementation Obligations

. The Iceberg REST table response (ADR-007) MUST include coercion notes for `props`,
  `embedding_*`, and any Variant or BinaryVector columns in the table properties.
. Arrow Flight `GetSchema` response MUST include metadata fields for Vector dimension.
. pgwire `RowDescription` MUST map `DenseVector` to pgvector OID (16384) when the
  `pgvector` extension compatibility mode is active.
. The `ALTER TABLE ... PROMOTE PROPS KEY(name TYPE type)` DDL MUST be implemented to allow
  manual promotion of `props` keys to typed columns (prerequisite for Iceberg predicate pushdown).
