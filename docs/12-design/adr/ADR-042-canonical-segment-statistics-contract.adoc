= ADR-042: Canonical SegmentStatistics Contract (aggregate the zone maps once; one stats view across ProximaBlocks + PAX)

[cols="1,3"]
|===
|Status|Proposed
|Date|2026-06-28
|Deciders|Vijaykumar Singh
|Relates to|ADR-037 (Statistics Substrate — this ADR fulfills its Decision 1 "measured once at the write boundary, read many" by *aggregating* per-segment stats instead of re-observing records), ADR-038 (envelope freshness coherence — per-segment watermarks fold into the conservative-floor envelope freshness), ADR-027 (PAX zone maps + coalesced writer + small→large compaction), ADR-030 ("one seam, N readers" co-design), the `SegmentFormat::detect` mixed-read seam (`src/storage/engines/sst/segment_format.rs`)
|Supersedes|—
|Tracked under|TD-180 (this contract). Relates to TD-177/178/179 (the block-stats spine consumers — int-id bloom / f64 decoders / adaptive bloom sizing) and TD-162a (typed `user_columns` stripe — the prerequisite for per-user-field stats). Builds on TD-174 (the statistics envelope producer).
|===

== Context

ADR-037 Decision 1 mandates that the statistics envelope is *"measured once at the
write boundary, read many"* — aggregate the per-segment zone maps + merge
segment-level sketches at flush/compaction, **never a scan-to-answer `ANALYZE`**.

The TD-174 producer shipped a pragmatic approximation: it **re-observes the records
in hand at flush** (`observe_flush_into_statistics`) and feeds streaming sketches.
This is correct and format-uniform *at the envelope level* (it runs above the
storage-format layer), but it has two gaps against the ADR-037 intent:

1. **It re-derives instead of aggregating.** It pays per-record CPU on the flush
   path and only ever sees the *flushed batch*, not the full set of segments — so a
   collection's envelope reflects the last flush, not the merged state across all
   live segments (which compaction already coalesces for records and meters).
2. **The on-disk per-segment stats are not uniform across the stacked formats.**
   PAX (`proximadb-block-format` `BlockStats`) carries rich per-column statistics —
   `null_counts`, `distinct_counts`, `lower/upper_bounds`, `hash_*_bounds`,
   `bloom_filter_bytes`, zone maps — keyed by `col_id`. Legacy row-based
   ProximaBlocks (`ProximaDataBlock`) carries far less. If we switched the envelope
   to *aggregate from disk* (the ADR-037 design), **envelope quality would fork by
   format**: rich for PAX segments, sparse for legacy ones.

The two formats already coexist mixed-read-safe, disambiguated by magic bytes via
`SegmentFormat::detect`. What is missing is a **single per-segment statistics view
both formats produce**, so the aggregation reads one shape regardless of format.

== Decision 1 — The boundary object is a per-segment `SegmentStatistics`, conforming to the envelope vocabulary

Define a **canonical, format-neutral per-segment statistics view** — the
lower-level dual of the TD-174 envelope: same field/modality vocabulary, at
*segment* granularity, and **mergeable**.

[cols="1,2", options="header"]
|===
| Level | Carries
| Segment | `row_count`, `byte_size`, freshness watermark (`source` ∈ flush\|compaction, `as_of`, `segment_id`), `format` tag, `partial: bool` (true when the producing format could not supply rich stats)
| Per column (`col_id`/name) | `null_count`, typed `min`/`max` (zone-map bounds), **distinct sketch (HLL, serialized)**, optional **quantile sketch (t-digest, serialized)**, optional reservoir of examples
| Per modality | the per-modality hints (vector centroid/spread, document term sketches, graph counts) at segment granularity
|===

Critically, the per-column **distinct** is an **HLL sketch, not the exact per-block
`distinct_counts`** that `BlockStats` carries today: exact per-block counts **cannot
be merged across blocks/segments** (distinct is not additive), which is exactly why
ADR-037 specifies HLL. `SegmentStatistics` carries the *mergeable* sketch;
`BlockStats`'s exact per-block counts remain for in-block pruning.

== Decision 2 — Both formats produce it at flush; legacy emits a partial view (never blocks)

Every segment writer **emits `SegmentStatistics` at flush**, a sibling of the bytes
it is already writing (ADR-030 "one seam, N readers" applied to the write boundary).

[cols="1,2", options="header"]
|===
| Format | Producer
| **PAX** | Maps `BlockStats` (null/bounds) in directly and **builds the mergeable HLL/t-digest during the columnar write** — the write already visits every value, so the sketch rides that pass at no extra scan. Rich, `partial = false`.
| **Legacy ProximaBlocks** | Emits what it has — `row_count`, timestamp `min/max`, available column bounds — with `partial = true` and the envelope's `approximate: true` labels. It never blocks aggregation; a legacy segment contributes a coarser view.
|===

=== Constraint (the P2 reality): PAX types canonical + vector columns only; user fields live in an opaque `PROPS` msgpack blob

The PAX block writer (`PaxBlockWriter`, `proximadb-block-format`) holds a **fixed
canonical column set** keyed by `col_id` (OID, TENANT_ID, CREATED_AT/UPDATED_AT,
VALID_FROM/TO, ACTOR, ORIGIN, EDGE_*, EMBED_BASE+i) plus `PROPS` — and **user scalar
fields are serialized into the opaque `PROPS` column as msgpack**
(`rmp_serde::to_vec_named`, `record.rs`), *not* per-field typed stripes. So PAX zone
maps / `BlockStats` cover the **canonical + vector/temporal** columns only; the
**per-user-field** statistics the envelope's `fields[]` describes are **not**
available from PAX block stats.

Consequence: the PAX producer contributes the **vector modality** (centroid/spread
from `EMBED_*`), temporal ranges, and canonical-id cardinality; **per-user-field**
column stats stay **record-sourced** (the TD-174 observe-at-flush path), and the
`SegmentStatistics` merge composes both sources (`partial` + per-source merge exist
for exactly this). Making user-field zone maps (and user int-id **bloom**, TD-177)
available *from the format* requires promoting filterable columns to typed PAX
stripes — tracked as **TD-162a** (typed `user_columns` stripe), the shared
prerequisite for the rich PAX user-field producer.

== Decision 3 — The aggregator merges per-segment views, format-agnostically, with no rescan

The registry/compaction path **merges per-segment `SegmentStatistics` → the
collection `StatisticsSummary` → the envelope**, detecting each segment's format by
magic via the existing `SegmentFormat::detect` seam and **merging the HLL/t-digest**
across segments (HLL register-max; t-digest weighted-centroid merge). This is the
small→large coalescing ADR-027 already runs for records and meters — one more reader
on the same compaction pass.

This **replaces the TD-174 per-record re-observe shortcut**: the envelope is
assembled by folding the tiny per-segment summaries, never by re-scanning or
re-tokenizing records. Re-observation remains only as the *legacy-segment fallback*.

== Decision 4 — Relocate the mergeable sketches to a foundation crate (the load-bearing structural change)

Today the sketches (`HyperLogLog`/`TDigest`/`Reservoir`/`FrequentItems`) live in the
**root crate** at `src/core/statistics/sketches/`, but the PAX producer lives in the
**foundation crate** `proximadb-block-format`, which (correctly) cannot depend on the
root crate. For both the **producer** (block-format) and the **aggregator** (root
crate) to share *one* sketch implementation, the sketches MUST move down.

* **Decision:** relocate the mergeable sketches into a foundation crate — a new
  `proximadb-statistics-sketches` (preferred: single-purpose) or into
  `proximadb-block-format`. The root crate re-exports them for source compatibility
  (the TD-174 call sites keep compiling).
* The **envelope DTO types** stay in the root crate — they are the consumer-facing
  wire contract, not a storage primitive. `SegmentStatistics` itself lives **with the
  sketches** (foundation), since both formats' writers must construct it.

== Mixed-read-safety and phasing (mandate #8 — never a flag-day)

`SegmentStatistics` is **versioned**. Readers default to the legacy/partial path when
rich stats are absent; aggregation **never assumes** rich stats. Ship **default-OFF**
until baked, gated by round-trip + recall/quality-parity tests.

. **P1 — Relocate + contract.** Move sketches to the foundation crate; define
  `SegmentStatistics` + its merge; unit-test the merge. No behavior change.
. **P2 — PAX producer.** Emit `SegmentStatistics` from the PAX columnar writer
  (sketches ride the existing value pass) — canonical + vector first; the rich
  user-field producer waits on TD-162a.
. **P3 — Aggregator.** Registry/compaction merges per-segment views; switch the
  envelope source from re-observe → aggregate (behind the gate).
. **P4 — Legacy partial producer.** ProximaBlocks emits its partial view; keep
  re-observe as the fallback.
. **P5 — Spine reuse.** Feed TD-177 (int-id bloom), TD-178 (f64 decoders), TD-179
  (adaptive bloom sizing) off the *same* per-column `SegmentStatistics`.

== Co-design framing (mandate)

This moves the **dominant I/O cost term** — bytes scanned / block round-trips — not
CPU: the per-column stats let the planner skip blocks (zone maps + bloom) and choose
codecs, and the same view feeds envelope, EXPLAIN selectivity (ADR-004), pruning, and
codec/bloom selection. The ADR-030 "one seam, N readers" economy extended to a
**single block-stats spine**: measure cardinality once at the write boundary → choose
encoding + bloom + prune + answer the agent.

== Authority and route declaration

[cols="1,3", options="header"]
|===
| Field | Value
| `authority_mode` | `projection` / `facade` — `SegmentStatistics` is a derived summary over segment bytes; segments + xCatalog remain authoritative. No new durable authority beyond a small per-segment stats sidecar/footer.
| `policy_boundary` | Per-tenant via `TenantContext`/RLS — a tenant aggregates only its own segments' stats.
| `workload_profile` | `read_mostly` — produced on the existing flush/compaction write pass; reads are tiny merged-summary fetches.
| `freshness_sla` | Per-segment watermark (`eventual`, advanced at flush/compaction); folds into the ADR-038 conservative-floor envelope freshness. A FACT, never an SLA.
| `compute_route` | Reuses the flush/compaction write path (sketch build) + the introspection read path (merged fetch). No new route.
|===

== Consequences

* **Fulfills ADR-037 Decision 1 as written** — aggregate-don't-rescan, across *all*
  live segments (not just the last batch), at lower flush CPU.
* **Format-uniform statistics** — one `SegmentStatistics` view across ProximaBlocks +
  PAX; envelope quality no longer forks by on-disk format.
* **One block-stats spine** — the same per-column stats drive pruning, codec/bloom
  selection (TD-177/178/179), envelope, and EXPLAIN selectivity.
* **Cost/risk:** the sketch relocation is a cross-crate refactor (root → foundation,
  re-export for compatibility); `SegmentStatistics` is a new persisted/derived
  surface, so it must be versioned + mixed-read-safe + parity-tested. Sketch state
  adds bounded per-segment bytes (acceptable — it rides an existing pass).

== Rejected alternatives

* **Keep re-observing records at flush (TD-174 status quo).** Works and is
  format-uniform, but re-derives instead of aggregating, only sees the flushed batch,
  and pays per-record CPU. Kept only as the legacy-segment fallback.
* **Duplicate the sketches in both crates.** Drift risk — two HLL-merge impls that
  must stay bit-compatible. Rejected: one shared foundation copy.
* **Push the envelope DTO types down into `proximadb-block-format`.** Over-couples the
  consumer-facing wire contract to a storage primitive. Only `SegmentStatistics` +
  the sketches move down.
* **A scan-to-answer `ANALYZE` over segments.** Rejected by ADR-037 Decision 1 — it
  charges KRU to produce the artifact whose purpose is to avoid scanning.
