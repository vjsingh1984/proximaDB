= How to File a TD or ADR — the canonical, collision-free convention
:toc: macro
:icons: font

**This is the single source of truth for filing Technical Debt (TD) items and
Architecture Decision Records (ADRs).** It lives in the repo, so it is identical
on every developer machine. The per-agent rule files (`CLAUDE.md`, `GEMINI.md`,
`AGENTS.md`) — which vary by developer preference and machine — only *point* here;
they do not duplicate these rules. Read this; do not re-derive the convention from
the per-agent files.

toc::[]

== Why this exists

This repo is worked on by many concurrent agent sessions. Sequential numbering in
a shared space has no atomic allocator, so two sessions branched off the same base
both pick the same "next" number — `ADR-031`, `ADR-032`, `ADR-033`, `TD-167` were
each claimed twice in a single week, surfacing only at merge (or coexisting
silently). And a single monolithic registry file makes every concurrent filing a
textual merge conflict. The convention below removes both failure modes.

== The rules (do this)

1. **One file per entry.**
   * ADRs: `docs/12-design/adr/ADR-<NNN>-<slug>.adoc` (already the norm).
   * TDs: `docs/10-quality/td/TD-<id>-<slug>.adoc` — the per-file directory.
   Two sessions adding *different* entries touch *different* files, so there is no
   textual conflict.

2. **Declare the id in the title heading**, not just the filename. The first
   AsciiDoc heading is authoritative:
   `= TD-167: short title` / `= ADR-037: short title`. The uniqueness guard reads
   the id from this heading (the filename slug uses hyphens too, so it is
   ambiguous; the heading delimits the id with `:`/space).

3. **Prefer a topic-scoped id for any multi-step effort** —
   `TD-<TOPIC>-N` (e.g. `TD-CAT-1`, `TD-SC-2`, `TD-CG3`). One initiative owns its
   prefix, so parallel sessions on *different* initiatives never collide. This is
   the collision-free path and is already proven in this repo. Reserve global
   sequential `TD-NNN` for genuinely standalone one-offs.

4. **For a global number, claim the next free one by scanning the directory**
   (the highest existing `ADR-NNN` / `TD-NNN`, +1). Never reuse a number already on
   `develop`, even if your branch was cut before it landed — rebase first
   (mandated within 48h) and re-check.

5. **The `td-adr-unique` CI guard is the backstop.** `scripts/check_td_adr_unique.py`
   fails any PR that introduces a duplicate ADR number or a duplicate TD id (across
   both the legacy table and the per-file directory). Because a rebased PR re-runs
   CI, your `ADR-037` colliding with a freshly-merged `ADR-037` is caught *before*
   merge — you renumber then. It is a backstop, not a lock; rule 4 is how you avoid
   needing it.

6. **Index new ADRs** in `docs/12-design/adr/README.adoc`. (The guard *warns* on an
   unindexed ADR; keeping the index current is expected hygiene.)

== Legacy entries (do NOT migrate ad hoc)

The ~100 existing TDs in `docs/10-quality/TECHNICAL_DEBT.adoc` stay in that table —
they are referenced ~900× across code and docs, and rewriting the file would
conflict with every open PR. The guard treats those table rows as declarations, so
a new per-file TD cannot reuse a legacy id. Migrating the legacy table to per-file
is a separate, batched, post-merge effort — not something to do incidentally.

== Quick reference

[cols="1,3", options="header"]
|===
| Want to… | Do this

| File a TD for an initiative | `docs/10-quality/td/TD-<TOPIC>-N-<slug>.adoc`, heading `= TD-<TOPIC>-N: …` (topic-scoped → collision-free)
| File a standalone numbered TD | scan `docs/10-quality/td/` + the legacy table for the highest `TD-NNN`, use +1, heading `= TD-NNN: …`
| File an ADR | scan `docs/12-design/adr/` for the highest `ADR-NNN`, use +1; `ADR-NNN-<slug>.adoc`, heading `= ADR-NNN: …`; add a row to `adr/README.adoc`
| Check before pushing | `python3 scripts/check_td_adr_unique.py` (exit 0 = unique)
|===

== Verification

`python3 scripts/check_td_adr_unique.py` — exits 0 when all ADR numbers and TD ids
are unique; exits 1 (with a specific message) on a duplicate. Add `--strict` to
also fail on the unindexed-ADR warnings. The CI **Docs Validation** job runs it on
every PR.
