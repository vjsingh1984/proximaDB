[.lead]
This is the **single pane of glass** for ProximaDB. It exists to answer one question fast — "where does
a thing live, and what does it converge on?" — across 57 workspace crates and 48 `src/` modules. It is
navigation-first: it does not duplicate the per-module detail in the feeder docs, it indexes and ties
them together so they stop diverging.

[IMPORTANT]
====
**Why this doc exists.** The codebase grew three partially-overlapping whole-system maps
(`ARCHITECTURE_ATLAS_2026_05_22`, `MODULE_COMPONENT_LLD_2026_05_22`, `docs/05-concepts/architecture.adoc`).
Each is correct but none is canonical, so they drift. This doc is declared the apex; the three become
subordinate feeders. New whole-system diagrams belong here or in a feeder linked from here — **not in a
fourth competing map**. That rule is itself a convergence gate (see
link:CONVERGENCE_AUDIT_2026_05_30.adoc[CONVERGENCE_AUDIT_2026_05_30]).
====

== How to use this map

* Need the *system shape and ownership boundaries*? Start at <<workspace>> then <<feeders>>.
* Need *where a `src/` module lives and what it does*? <<srcmap>>.
* Need *how a write or read flows end to end*? <<writepath>> / <<readpath>>.
* Need *why four protocols don't mean four truths*? <<convergence>>.
* Need *where the known divergent seams are*? <<seams>>.

[#workspace]
== Layer 1 — Workspace (57 crates, layered)

The workspace follows the stable map from `CLAUDE.md`:
`Foundation -> Contracts -> Control -> Horizontal -> Modality -> Storage -> Query/Cross-Model -> Platform -> Apps/Bindings`.
Crates are added only for real dependency or ownership payoff.

[source,mermaid]
----

[#convergence]
== Layer 4 — Protocol-facade → canonical-authority convergence

Four wire protocols are *facades*, not authorities. They lower into the same canonical record + WAL +
catalog chain. This is the load-bearing invariant the whole architecture rests on: proliferation is
allowed at the edge, never in the durable core.

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%
flowchart TB
  classDef edge fill:#cfe2f7,stroke:#2e5c8a,color:#000;
  classDef core fill:#4a90e2,stroke:#2e5c8a,color:#000;

  R1[REST v1]:::edge --> SVC
  R2[REST v2]:::edge --> SVC
  GR[gRPC]:::edge --> SVC
  AF[Arrow Flight]:::edge --> SVC
  PG["pgwire 5433<br/>(pgvector compat)"]:::edge --> SVC

  SVC["services/ (shared)"]:::core --> REC["ProximaRecord<br/>ProximaType / ProximaValue"]:::core
  REC --> WAL["canonical WAL"]:::core
  WAL --> XC["xCatalog (durable authority)"]:::core
----

[#seams]
== Where the seams are

This map is the apex; it points at the live divergent seams rather than hiding them. The authoritative
catalog with reconcile directions and queued TD items is
link:CONVERGENCE_AUDIT_2026_05_30.adoc[CONVERGENCE_AUDIT_2026_05_30]. Summary:

[cols="2,3", options="header"]
|===
| Seam | One-line status

| Phase 9 handler/service extraction
| Real impl in `src/api_handlers/request_handlers.rs`; `proximadb-runtime/src/handlers.rs` is a stub. Migration in progress.

| Deprecated gRPC shims
| `src/network/grpc/*_service.rs` deprecation shims; real impls migrated. Removal targeted for v0.2 (pulls forward from the code's `0.3.0` markers).

| Proto-v1 internal mirrors
| `VectorRecord`/`SqlValue`/`SqlObject` still used internally; canonical is `ProximaRecord`/`ProximaValue`.

| Scattered configs
| CDC + cluster config structs not yet under `crates/foundation/proximadb-config`.

| PlanCache B/C/D
| Four impls; A consolidated, B/C/D intentionally separate (documented as by-design).
|===

== Agent-memory note

ProximaDB's positioning as a memory substrate for AI agents and its mapping to the mem0 / agentmemory
orchestration libraries are specified in
link:adr/ADR-022-agent-memory-layer.adoc[ADR-022] +
link:AGENT_MEMORY_LAYER_HLD_2026_05_30.adoc[AGENT_MEMORY_LAYER_HLD_2026_05_30]. The short version: the
agent-memory layer is a *consumer* of the surfaces mapped above (AQL, Graph RAG, RERANK, hybrid fusion,
`ProximaRecord.memory_type`, pgvector wire), not a new storage stack.
