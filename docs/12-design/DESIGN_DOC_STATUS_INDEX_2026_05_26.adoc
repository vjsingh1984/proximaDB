== How to read this index

* **Status** values: Accepted (ADRs), Active (live design), Active-Memo (short-lived follow-up), Reference (convention/index), Pending (no code yet), Archived (moved to `docs/_archive/`).
* **Wired** values:
** **WIRED** — distinctive symbol from the doc has hits in workspace code outside docs/tests.
** **PARTIAL** — some referenced symbols/paths exist, others don't (typically phase-gated work).
** **NOT_WIRED** — no code traces; either pending implementation OR external/SaaS-only.
** **N/A** — convention/index doc, no code expected.
* **Cluster** — semantic grouping for consolidation review (see <<consolidation-clusters>>).

== Maintenance cadence

This index should be refreshed whenever:

* a new file lands in `docs/12-design/` (top-level or `adr/`),
* an ADR's status changes from Accepted to Superseded (currently none),
* a top-level design doc moves from PARTIAL → WIRED or vice versa,
* a consolidation batch from `DOCUMENTATION_CONSOLIDATION_AND_ARCHIVE_PLAN_2026_05_22.adoc` is executed.

Suggested refresh interval otherwise: every 4-6 weeks. The audit format is intentionally cheap to re-run (3 parallel grep-based passes, ~5 minutes of human time).
