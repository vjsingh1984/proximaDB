* Rust 1.75+ (latest stable)
* Protobuf compiler (protoc)
* Git

== Quick Start Commands

=== Docker (Fastest)
[source,bash]
----
# Pull and run ProximaDB
docker run -d \
  --name proximadb \
  -p 5678:5678 -p 5679:5679 \
  -v proximadb_data:/data \
  proximadb/proximadb:latest

# Verify it's running
curl http://localhost:5678/health
----

=== From Source

[source,bash]
----
# Clone and build
git clone https://github.com/vjsingh1984/proximaDB.git
cd proximadb
cargo build --release

# Run server
./target/release/proximadb-server

# Verify
curl http://localhost:5678/health
----

=== Python Client

[source,bash]
----
# Install client
pip install proximadb

# Test connection
python -c "from proximadb import ProximaDBClient; \
           client = ProximaDBClient('http://localhost:5678'); \
           print(client.health())"
----

= Collections Management
:toc:
:toclevels: 3
:icons: font
:source-highlighter: rouge

== Overview

Collections are the fundamental storage unit in ProximaDB. Each collection stores vectors of the same dimension along with their metadata.

== Creating Collections

=== Basic Collection

[source,python]
----
from proximadb import Client

client = Client("localhost:5678")

# Create a simple collection
collection = client.create_collection(
    name="my_vectors",
    dimension=1536,  # OpenAI embedding dimension
    metric="cosine"
)
----

=== Advanced Configuration

[source,python]
----
collection = client.create_collection(
    name="products",
    dimension=512,
    metric="euclidean",
    config={
        "storage_engine": "VIPER",     # Columnar for analytics
        "compression": "zstd",          # Compression algorithm
        "compression_level": 3,         # 1-9 scale
        "enable_mmap": True,           # Memory-mapped files
        "quantization": {
            "enabled": True,
            "type": "PQ",              # Product Quantization
            "num_subvectors": 64,
            "bits_per_code": 8
        },
        "index": {
            "type": "HNSW",            # Hierarchical NSW
            "M": 16,                   # Number of connections
            "ef_construction": 200,     # Construction quality
            "ef_search": 100           # Search quality
        }
    }
)
----

== Storage Engine Selection

=== Engine Comparison

[cols="1,2,2,2", options="header"]
|===
| Engine | Best For | Pros | Cons

| *VIPER*
| Analytics, batch operations
| Columnar compression, fast scans
| Slower single-record access

| *SST*
| High write throughput
| LSM-tree, write-optimized
| Requires compaction

| *RAPTOR*
| Graph-based search
| HNSW integration, high recall
| Higher memory usage

| *NOVA*
| Zone-based queries
| Efficient pruning, zone maps
| Beta status

| *SWIFT*
| Mixed workloads
| Adaptive blocks, balanced
| Beta status

| *PRISM*
| Large-scale search
| Progressive refinement
| Beta status
|===

=== Choosing the Right Engine

[source,python]
----
# For real-time search
collection = client.create_collection(
    name="realtime",
    dimension=128,
    storage_engine="RAPTOR"  # Fast graph-based search
)

# For analytics workloads
collection = client.create_collection(
    name="analytics",
    dimension=768,
    storage_engine="VIPER"   # Columnar storage
)

# For streaming data
collection = client.create_collection(
    name="streaming",
    dimension=256,
    storage_engine="SST"     # Write-optimized
)
----

== Collection Operations

=== List Collections

[source,python]
----
# List all collections
collections = client.list_collections()
for col in collections:
    print(f"Name: {col.name}")
    print(f"Dimension: {col.dimension}")
    print(f"Vector count: {col.count}")
    print(f"Storage engine: {col.storage_engine}")
----

=== Get Collection Info

[source,python]
----
# Get detailed collection information
info = client.get_collection_info("products")
print(f"Total vectors: {info.vector_count}")
print(f"Index type: {info.index_type}")
print(f"Memory usage: {info.memory_bytes / 1024 / 1024:.2f} MB")
print(f"Disk usage: {info.disk_bytes / 1024 / 1024:.2f} MB")
----

=== Update Collection Configuration

[source,python]
----
# Update index parameters
client.update_collection(
    name="products",
    index_params={
        "ef_search": 200  # Increase search quality
    }
)

# Enable quantization
client.update_collection(
    name="products",
    quantization={
        "enabled": True,
        "type": "INT8"
    }
)
----

=== Delete Collection

[source,python]
----
# Delete a collection (WARNING: irreversible)
client.delete_collection("old_collection")

# Delete with confirmation
if client.collection_exists("temp_collection"):
    client.delete_collection("temp_collection")
----

== Distance Metrics

=== Available Metrics

[cols="1,2,2,2", options="header"]
|===
| Metric | Description | Range | Use Case

| *cosine*
| Cosine similarity
| [0, 2]
| Text embeddings, normalized vectors

| *euclidean*
| L2 distance
| [0, ∞)
| General purpose, spatial data

| *dot_product*
| Inner product
| (-∞, ∞)
| Recommendation systems

| *manhattan*
| L1 distance
| [0, ∞)
| Sparse vectors, grid-based

| *hamming*
| Bit differences
| [0, n]
| Binary vectors, hashes
|===

== Collection Schema

=== Defining Metadata Schema

[source,python]
----
# Define metadata schema for validation
schema = {
    "fields": [
        {"name": "title", "type": "string", "required": True},
        {"name": "price", "type": "float", "required": True},
        {"name": "category", "type": "string", "required": False},
        {"name": "tags", "type": "array", "required": False},
        {"name": "created_at", "type": "timestamp", "required": True}
    ]
}

collection = client.create_collection(
    name="products_with_schema",
    dimension=512,
    metadata_schema=schema
)
----

=== Schema Validation

[source,python]
----
# Vectors with invalid metadata will be rejected
try:
    collection.insert(
        vectors=[[0.1] * 512],
        metadata=[{"title": "Product"}]  # Missing required 'price'
    )
except ValidationError as e:
    print(f"Validation failed: {e}")
----

== Partitioning

=== Creating Partitioned Collections

[source,python]
----
# Partition by category for better performance
collection = client.create_collection(
    name="partitioned_products",
    dimension=512,
    partitions={
        "key": "category",
        "num_partitions": 10
    }
)

# Time-based partitioning
collection = client.create_collection(
    name="timeseries",
    dimension=128,
    partitions={
        "key": "timestamp",
        "type": "range",
        "interval": "daily"
    }
)
----

== Collection Lifecycle

=== Collection States

[plantuml, collection-lifecycle, svg]
----
@startuml
[*] --> Creating
Creating --> Active : Success
Creating --> Failed : Error
Active --> Indexing : Reindex
Indexing --> Active : Complete
Active --> Optimizing : Optimize
Optimizing --> Active : Complete
Active --> Deleting : Delete
Deleting --> [*]
Failed --> [*]
@enduml
----

=== Managing Collection State

[source,python]
----
# Check collection state
state = client.get_collection_state("products")
print(f"State: {state}")  # 'active', 'indexing', 'optimizing'

# Trigger optimization
client.optimize_collection("products")

# Wait for collection to be ready
client.wait_for_collection("products", timeout=60)
----

== Best Practices

=== Naming Conventions

* Use lowercase with underscores: `user_embeddings`
* Include version if needed: `products_v2`
* Be descriptive: `customer_reviews_2024`

=== Dimension Guidelines

[cols="1,2,2", options="header"]
|===
| Dimension | Model Examples | Considerations

| 128-256
| Small models, custom embeddings
| Fast, low memory

| 384-768
| BERT, sentence transformers
| Balanced performance

| 1536-2048
| OpenAI, large language models
| High quality, more memory
|===

=== Performance Tips

. Choose appropriate storage engine for workload
. Enable quantization for large collections
. Use proper indexing parameters
. Partition large collections
. Monitor and optimize regularly

== Troubleshooting

=== Common Issues

[cols="2,3", options="header"]
|===
| Issue | Solution

| Collection creation fails
| Check dimension limits, name conflicts

| Slow search performance
| Adjust index parameters, enable caching

| High memory usage
| Enable quantization, use VIPER engine

| Write throughput low
| Use SST engine, batch operations
|===

== Overview

ProximaDB uses TOML configuration files. Example configs are in `config/` (e.g., `config/config.toml`, `config/simple-config.toml`). The server binds REST on port 5678 by default; gRPC listens on 5679 (multi-server).

== Top-Level Structure (maps to src/core/config.rs)

[source,toml]
----
[server]         # ServerConfig
[storage]        # StorageConfig
[consensus]      # ConsensusConfig (reserved)
[api]            # ApiConfig
[monitoring]     # MonitoringConfig
# Optional blocks
[network]        # NetworkConfig
[tls]            # TlsConfig
[hardware]       # HardwareConfig
----

== Server

[source,toml]
----
[server]
node_id = "node-1"
bind_address = "127.0.0.1"   # REST bind address
port = 5678                  # REST port (gRPC fixed at 5679)
data_dir = "./data"
grpc_port = 5679             # Optional convenience; ApiConfig takes precedence
----

TLS (same REST port, optional):

[source,toml]
----
[tls]
enabled = false
cert_file = "/path/to/cert.pem"
key_file  = "/path/to/key.pem"
bind_interface = "0.0.0.0"   # optional
----

== Storage

[source,toml]
----
[storage]
mmap_enabled = true
metadata_url = "file://./metadata"
cache_size_mb = <cache_size_mb>

[[storage.storage_locations]]
url = "file://./data"   # or s3://bucket/path
weight = 1
tags = ["local"]

# Write-ahead log and engine configs (selected fields)
# See code for full fields: SstConfig, ViperConfig, CompactionConfig, FilesystemOptimizationConfig
sst_config = { block_size_kb = <block_size_kb>, compression = "zstd", data_directory = "./data/sst" }
viper_config = { row_group_size = <row_group_size>, compression = "zstd", data_directory = "./data/viper" }
----

== Environment Overrides

All keys can be overridden via environment variables using your loader. Common examples:

[source,bash]
----
export PROXIMADB_SERVER_PORT=8080
export PROXIMADB_STORAGE_METADATA_URL=file:///var/lib/proximadb/meta
export PROXIMADB_TLS_ENABLED=true
----

== Notes
- REST port is `server.port`; gRPC is started by the multi-server on 5679.
- Index-specific tuning (HNSW/IVF/etc.) is configured per engine or service layer, not in this file.
- For concrete examples, see `config/config.toml` and `config/simple-config.toml`.

=== Memory Constrained Profile

[source,toml]
----

[performance]
vector_cache_size_mb = <vector_cache_size_mb>

[quantization]

== Hardware-Specific Configuration

=== CPU-Only Systems

[source,toml]
----
[performance]
enable_gpu = false
enable_simd = true
num_search_threads = 0  # Use all cores
----

=== GPU-Accelerated Systems

[source,toml]
----
[performance]
enable_gpu = true
gpu_memory_fraction = 0.9
# Larger batches for GPU
prefetch_size = 256
----

=== ARM/NEON Systems

[source,toml]
----
[performance]
enable_simd = true  # Will use NEON
enable_gpu = false
----

  proximadb:
    image: proximadb/proximadb:latest
    ports:
      - "5678:5678"
      - "5679:5679"
    volumes:
      - ./config:/config
      - ./data:/data
    environment:
      - PROXIMADB_CONFIG=/config/server.toml
