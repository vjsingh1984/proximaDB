== Overview

ProximaDB's **DirectVectorService-powered REST API** delivers **40-60% insert latency reduction**, **zero double serialization** with automatic JSON ↔ Proto conversion, **85% code reduction** through unified handlers, and **64MB batch support** for high-throughput operations.

=== Proto-First Advantages

[horizontal]
**Zero Double Serialization**:: Direct protobuf types with automatic JSON mapping
**Unified Handlers**:: 85% code reduction - single business logic for REST/gRPC  
**Type Safety**:: Proto-generated types ensure consistency across all protocols
**Batch Optimization**:: 64MB message support for high-throughput operations
**Hardware Integration**:: Native quantization hints and search optimization
**Storage-Aware**:: Automatic VIPER/SST engine selection through API hints

=== Core Design Principles

[horizontal]
Proto-Native:: All request/response types generated from protobuf definitions
Handler Consolidation:: Single UnifiedHandlers implementation for all protocols
Storage-Aware:: Optimization hints enable automatic engine selection
Quantization-Ready:: Native support for hardware-accelerated compression
Production-Scale:: 64MB batch limits with streaming capabilities

==== Operations

[cols="1,3"]
|===
| Operation | Description

| `create`
| Create a new collection with specified configuration

| `get`
| Retrieve collection details by ID or name

| `list`
| List all collections with optional pagination

| `update`
| Update collection metadata (description, tags, owner)

| `delete`
| Delete a collection and all its data
|===

==== Vector Search

Search for similar vectors with optional metadata filtering.

[cols="1,4"]
|===
| Method | `POST`
| Path | `/api/v1/vector/search`
| Content-Type | `application/json`
| Response | `200 OK`
|===

.Request Schema
[source,json]
----
{
  "collection_id": "string",                // Required
  "queries": [                              // Required: batch queries
    {
      "vector": [0.1, 0.2, ...],           // Required: query vector
      "id": "string",                       // Optional: search by ID
      "metadata_filter": {                  // Optional: filters
        "conditions": [
          {
            "field_name": "category",
            "operation": "equals",          // equals|greater_than|less_than|in|contains|starts_with
            "value": "electronics"
          }
        ],
        "operator": "and"                   // and|or|not
      }
    }
  ],
  "top_k": 10,                             // Required: results per query
  "distance_metric_override": "cosine",     // Optional: override metric
  "search_parameters": {                    // Optional: algorithm params
    "ef_search": 50,                        // HNSW parameter
    "n_probe": 10,                          // IVF parameter
    "enable_reranking": true,
    "accuracy_threshold": 0.95
  },
  "include_fields": {                       // Optional: response fields
    "vector": false,
    "metadata": true,
    "score": true,
    "rank": true
  },
  "search_optimization": {                  // Optional: optimization hints
    "enable_two_stage": true,
    "quantization_hint": {
      "hint_type": "scalar",
      "parameters": {"bits": 8}
    },
    "enable_clustering_hint": true,
    "timeout_ms": 5000
  }
}

== Search Architecture

=== Polymorphic Storage-Aware Search

ProximaDB implements a sophisticated polymorphic search architecture that automatically routes queries to the optimal storage engine based on data location and characteristics.

==== Search Flow

[source]
----
Query → SearchEngineFactory → Multi-Tier Search → Deduplication → Results
         ↓                    ↓
         Storage Detection    ├─ WriteBuffer (Unflushed data)
         ↓                    ├─ SST (Recent data)
         Optimization Hints   └─ VIPER (Compacted data)
----

==== Key Features

* **Automatic Routing**: Queries are automatically routed to the appropriate storage engine
* **Deduplication**: When the same vector exists in multiple tiers, the newest version is returned
* **Quantization Support**: Dynamic quantization for performance optimization
* **Two-Stage Search**: Optional coarse-to-fine search for improved performance
* **Metadata Filtering**: Efficient predicate pushdown to storage engines

==== Search Optimization Hints

The `search_optimization` parameter allows fine-tuning of search behavior:

[cols="2,1,3"]
|===
| Field | Type | Description

| enable_two_stage
| bool
| Enable two-stage search (coarse + reranking)

| quantization_hint
| object
| Quantization level for search optimization

| enable_clustering_hint
| bool
| Enable ML-based cluster selection (VIPER)

| enable_metadata_filtering_hint
| bool
| Optimize for metadata-heavy queries

| timeout_ms
| i64
| Maximum search time in milliseconds

| accuracy_threshold
| f32
| Minimum accuracy (0.0-1.0) for early termination

| custom_hints
| object
| Storage-engine specific hints
|===

==== Quantization Levels

Supported quantization hints for search optimization:

[cols="1,2,3"]
|===
| Type | Parameters | Description

| none
| -
| Full precision FP32 (no quantization)

| scalar
| bits: 8
| INT8 scalar quantization

| product
| bits_per_code: 8, num_subvectors: 8
| Product quantization (PQ8)

| binary
| -
| Binary quantization (1-bit per dimension)

| uniform
| scale: 1.0, offset: 0.0
| Uniform quantization with scale/offset
|===

== Performance Considerations

=== Batch Operations

* Optimal batch size: 100-1000 vectors per request
* Use `batch_timeout_ms` to control latency vs throughput
* Larger batches improve throughput but increase latency

=== Search Optimization

* Use `search_optimization.quantization_hint` for faster approximate search
* Enable `two_stage_search` for large datasets
* Set appropriate `timeout_ms` to prevent long-running queries

=== Network Optimization

* Keep connections alive with HTTP/1.1 keep-alive
* Consider using HTTP/2 for multiplexing
* Compress large payloads with gzip encoding

=== Python Client Example

[source,python]
----
from proximadb import ProximaDBRestClient
import numpy as np

# Initialize client
client = ProximaDBRestClient(url="http://localhost:5678")

# Create collection with advanced features
collection = client.create_collection(
    name="products",
    dimension=384,
    distance_metric="cosine",
    storage_engine="viper",
    filterable_columns=[
        {"name": "category", "data_type": "string", "indexed": True},
        {"name": "price", "data_type": "float", "indexed": True, "supports_range": True}
    ],
    quantization_config={
        "enabled": True,
        "search_quantization": {
            "enabled": True,
            "default_level": {"level_type": "scalar", "bits": 8}
        }
    }
)

# Insert vectors
vectors = np.random.rand(100, 384).astype(np.float32)
metadata = [{"category": "electronics", "price": 100 + i*10} for i in range(100)]

result = client.insert_vectors(
    collection_id=collection.id,
    vectors=vectors,
    ids=[f"vec_{i}" for i in range(100)],
    metadata=metadata
)

# Search with optimization
query_vector = np.random.rand(384).astype(np.float32)
results = client.search(
    collection_id=collection.id,
    query=query_vector,
    k=10,
    filter={"category": "electronics", "price": {"$lt": 500}},
    optimization_hints={
        "enable_two_stage_search": True,
        "quantization_hint": "PQ8",
        "candidate_multiplier": 3.0
    }
)

for result in results:
    print(f"ID: {result.id}, Score: {result.score}, Metadata: {result.metadata}")
----
