= REST API Reference
:toc: left
:toclevels: 2
:icons: font

[.lead]
Developer‑first REST API reference. Base URL: `http://localhost:5678`.

== Status Notes

* Vector APIs are stable.
* Document, graph, and observability APIs are beta.
* **Unified multi-model query is stable** - Cross-model SQL with VECTOR_SEARCH, GRAPH_QUERY, DOCUMENT_QUERY extensions.

=== Key Differentiator

ProximaDB's multi-model query engine enables cross-model joins that are impossible with single-model databases (Pinecone, Weaviate, Milvus). Use `POST /api/v1/unified/federated` for SQL with extensions.

== Unified Multi‑Model Query (Stable)

ProximaDB's multi-model query engine is the key differentiator vs single-model databases (Pinecone, Weaviate, Milvus). It enables cross-model joins in a single SQL query.

=== POST /api/v1/unified/federated

**Federated SQL query with multi-model extensions.** This is the primary endpoint for cross-model queries.

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/unified/federated \
  -H "Content-Type: application/json" \
  -d '{"query": "SELECT * FROM VECTOR_SEARCH('products', '[0.1, 0.2, 0.3]', 10)"}'
----

==== SQL Extensions

|===
| Extension | Syntax | Example

| Vector Search | `VECTOR_SEARCH(collection, vector, top_k)` | `SELECT * FROM VECTOR_SEARCH('products', '[0.1,0.2]', 10)`
| pgvector Distance | `embedding <-> '[...]'::vector` | `SELECT * FROM products ORDER BY embedding <-> '[0.1,0.2]'::vector LIMIT 10`
| Graph Query | `GRAPH_QUERY('cypher')` | `SELECT * FROM GRAPH_QUERY('MATCH (a)-[:KNOWS]->(b) RETURN b.name')`
| Document Query | `DOCUMENT_QUERY(collection, filter)` | `SELECT * FROM DOCUMENT_QUERY('orders', 'status = "pending"')`
| Log Query | `LOGS(namespace)` | `SELECT * FROM LOGS('production') WHERE timestamp > now() - interval '1h'`
| Metric Query | `METRICS(namespace)` | `SELECT * FROM METRICS('cpu') WHERE value > 90`
|===

==== Cross-Model Join Examples

**Vector + Document: Find similar products and their reviews**
[source,sql]
----
SELECT v.product_id, v.score, d.review_text
FROM VECTOR_SEARCH('products', '[0.1,0.2,0.3]', 10) v
JOIN LATERAL DOCUMENT_QUERY('reviews', 'product_id = "' || v.product_id || '"') d ON true;
----

**Vector + Graph: Filter by category relationships**
[source,sql]
----
SELECT * FROM VECTOR_SEARCH('products', '[0.1,0.2]', 100)
WHERE id IN (
  SELECT target FROM GRAPH_QUERY('MATCH (:Category {name:"Electronics"})-[:CONTAINS]->(p) RETURN p.id')
);
----

**Logs + Graph: Errors with service dependency context**
[source,sql]
----
SELECT l.timestamp, l.message, g.dependency
FROM LOGS('errors') l
JOIN LATERAL GRAPH_QUERY('MATCH (s:Service {name: "' || l.service || '"})-[:DEPENDS_ON]->(d) RETURN d.name as dependency') g ON true
WHERE l.timestamp > now() - interval '5m';
----

=== POST /api/v1/unified/execute

**Auto-routing unified query.** Automatically detects multi-model extensions and routes to federated engine.

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/unified/execute \
  -H "Content-Type: application/json" \
  -d '{
    "query": "SELECT * FROM products WHERE $.category = 'electronics' AND VECTOR_SIMILAR(embedding, ?, 0.8)",
    "query_vector": [0.1, 0.2, 0.3],
    "fusion_strategy": "intersection",
    "limit": 100
  }'
----

==== Fusion Strategies

|===
| Strategy | Description

| `intersection` | Records must match all sub-queries (AND)
| `union` | Records from any sub-query (OR)
| `rrf` | Reciprocal Rank Fusion - weighted rank combination
| `ranked` | Custom weights per model
|===

=== POST /api/v1/unified/multi-model

**Programmatic multi-model query.** Use when you need explicit control over each model's parameters.

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/unified/multi-model \
  -H "Content-Type: application/json" \
  -d '{
    "components": [
      {
        "component_type": "vector",
        "config": {
          "collection": "products",
          "query_vector": [0.1, 0.2, 0.3],
          "top_k": 10,
          "threshold": 0.8
        }
      },
      {
        "component_type": "document",
        "config": {
          "collection": "products",
          "filter": "$.category = 'electronics'"
        }
      },
      {
        "component_type": "graph",
        "config": {
          "graph": "product_categories",
          "start_node": "electronics",
          "edge_type": "CONTAINS",
          "max_depth": 2
        }
      }
    ],
    "fusion_strategy": "rrf",
    "limit": 100
  }'
----

=== POST /api/v1/unified/explain

**Explain query execution plan.** Shows how a query will be decomposed and executed.

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/unified/explain \
  -H "Content-Type: application/json" \
  -d '{"query": "SELECT * FROM VECTOR_SEARCH('products', '[0.1,0.2]', 10) v JOIN GRAPH_QUERY('...') g ON v.id = g.id"}'
----

Response:
[source,json]
----
{
  "components": [
    {"model": "Vector", "estimated_cost": 1.0, "parallelizable": true},
    {"model": "Graph", "estimated_cost": 3.0, "parallelizable": true}
  ],
  "fusion_strategy": "Intersection",
  "estimated_total_cost": 3.0
}
----
