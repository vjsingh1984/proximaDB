== Overview

This document provides visual representations of ProximaDB's architecture using Mermaid diagrams that can be rendered inline.

== System Architecture

The complete current system architecture with accurate component relationships:

image::current-architecture-accurate.png[Current ProximaDB Architecture, width=100%, align=center]

_Diagram source: link:diagrams/current-architecture-accurate.mmd[View Mermaid source]_

This diagram shows the actual implementation with:

* **MultiServer**: Concurrent REST and gRPC servers on separate ports
* **SharedServices**: Business logic hub coordinating all services
* **DirectVectorService**: Core service providing 40-60% latency reduction
* **Dual Storage Strategy**: VIPER (default) and SST (alternative) engines
* **AXIS Integration**: Fully implemented adaptive indexing system

Detailed sequence showing how requests flow through the actual system:

image::service-interactions.png[Service Interaction Sequence, width=100%, align=center]

This sequence diagram illustrates:

* **Request Routing**: MultiServer to UnifiedHandlers to DirectVectorService

* **Write Buffer Integration**: Atomic persistence with cloud storage

== Storage Engine Class Structure

Actual class relationships and dependencies in the storage layer:

image::storage-engine-classes.png[Storage Engine Classes, width=100%, align=center]

_Diagram source: link:diagrams/storage-engine-classes.mmd[View Mermaid source]_

Key architectural elements:

* **StorageEngine**: Central coordinator using DashMap for concurrent access
* **DirectVectorService**: Optimized service with direct memtable access
* **Dual Storage Engines**: ViperEngine (default) and SstStorage (alternative)
* **WriteBufferManager**: Handles persistence with multiple serialization strategies
* **AxisManager**: Fully implemented adaptive indexing system
