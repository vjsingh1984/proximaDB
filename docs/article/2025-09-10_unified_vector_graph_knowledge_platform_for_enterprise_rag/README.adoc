[.lead]
ProximaDB unifies vector search, graph traversal, and a semantic knowledge store (SKS) in one accelerated, serverless, multicloud database—so teams ship accurate, explainable AI features without stitching multiple systems.

image::enterprise_rag_flow.svg[Enterprise RAG Flow,align="center",width=960]

== Why ProximaDB
- Unified intelligence: vector similarity + graph traversal + SKS in one engine.
- SQL-first: query vectors, metadata, and relationships using familiar SQL with extensions for hybrid intelligence.
- Accelerated performance: progressive search, SIMD optimizations, and smart pruning reduce latency and cost.
- Operationally simple: serverless deployment patterns, multicloud portability, and built‑in observability.

== Key Capabilities
- Vector search at scale with advanced filtering and hybrid fusion (e.g., Reciprocal Rank Fusion).
- Native graph analytics: paths, neighborhoods, constraints, and streaming traversals.
- Semantic Knowledge Store: entities, provenance, and temporal context for trustworthy answers.
- One API surface: REST and gRPC (SqlService/ExecuteSql) with typed results.

== Spotlight Use Case: Enterprise RAG You Can Trust
Challenge: A global services company must answer internal questions from 100k+ documents across product, support, and policy repositories. Pure vector search returns plausible but incomplete answers; classic knowledge graphs are accurate but too slow to maintain and query at scale.

Solution with ProximaDB:
. Ingest documents as entities (SKS) with embeddings and rich metadata (department, version, effective dates).
. Capture relationships (dependencies, ownership, policy lineage) in the native graph engine.
. Serve questions via a single SQL query that:
.. Finds semantically similar passages (vector similarity),
.. Follows graph edges to authoritative sources and owners,
.. Applies temporal/provenance filters to ensure currency,
.. Fuses results and returns a compact, cited context window.

Outcome:
- Higher answer accuracy and explainability (answers cite sources and owners).
- Lower latency and cost versus multi‑system stacks.
- One data plane to operate and secure across clouds.

== Example (Conceptual SQL)
[source,sql]
----
SELECT passage, source_url, owner
FROM docs
WHERE SIMILAR(embedding, $query_vec, 'cosine')
  AND FOLLOW(doc_id, 'references', 2)
  AND temporal.valid_from <= NOW()
ORDER BY _similarity DESC
LIMIT 8;
----
