== Overview

ProximaDB's Unified Strategy Pattern provides a consistent, intelligent way to optimize read operations across all storage engines. This guide demonstrates how to use the strategy pattern effectively for different workloads.

[NOTE]
====
**Performance Baseline**: All performance metrics in this guide are based on benchmarks conducted on **Apple M4 Pro** (14 cores, 48 GB memory) running macOS 15.6.1. Actual performance varies by hardware.
====

== Architecture Benefits

[cols="1,3"]
|===
|Benefit |Description

|**Consistent API**
|All engines use the same `ReadAccessStrategy` enum and `StrategyAwareReader` trait

|**Intelligent Caching**
|Automatic selection between cached and direct reads based on access patterns

|**Performance Optimization**
|**98.2% faster compaction** (VIPER: 255.71ns), **5.1M ops/sec** on 768D BERT

|**Cache Pollution Avoidance**
|Direct reads for full scans prevent cache pollution

|**Engine-Specific Optimization**
|Each engine maps strategies to its optimal internal implementations
|===

== Core Strategy Types

=== DirectStream Strategy

Use for full sequential scans where caching provides no benefit:

[source,rust]
----
use proximadb::storage::engines::core::read_strategy::ReadAccessStrategy;
use proximadb::storage::engines::impls::nova::UnifiedNOVAReader;

// Optimal for compaction operations
let reader = UnifiedNOVAReader::for_compaction(
    filesystem_factory.clone(),
    "my_collection".to_string(),
)?;

// Or explicitly
let reader = UnifiedNOVAReader::new(
    filesystem_factory,
    "my_collection".to_string(),
    ReadAccessStrategy::DirectStream,
)?;
----

**Best for:**

* Compaction operations
* AXIS indexing (full table scans)
* Data migration and batch processing
* Sequential reads of entire files

=== CachedSearch Strategy

Use for search operations with repeated metadata access:

[source,rust]
----
use proximadb::storage::engines::impls::swift::UnifiedSWIFTReader;

// Optimal for search workloads
let reader = UnifiedSWIFTReader::for_search(
    filesystem_factory.clone(),
    "my_collection".to_string(),
)?;

// Or explicitly with options
let reader = UnifiedSWIFTReader::new(
    filesystem_factory,
    "my_collection".to_string(),
    ReadAccessStrategy::CachedSearch { prefetch_metadata: true },
    config,
)?;
----

**Best for:**

* Vector similarity searches
* Repeated queries on same data
* Operations requiring bloom filter access
* Search with metadata filtering

=== CachedSelective Strategy

Use for point queries and filtered scans:

[source,rust]
----
use proximadb::core::search::FilterExpression;
use proximadb::storage::engines::impls::helix::UnifiedHELIXReader;

// With filter expression
let filter = Some(FilterExpression::Equals {
    field: "category".to_string(),
    value: "documents".into(),
});

let reader = UnifiedHELIXReader::for_time_series_query(
    filesystem_factory,
    "my_collection".to_string(),
    filter,
)?;
----

**Best for:**

* Point lookups by ID
* Range queries with filters
* Time-series queries with temporal bounds
* Selective data access patterns

=== Adaptive Strategy

Use for workloads with changing access patterns:

[source,rust]
----
use proximadb::storage::engines::impls::viper::UnifiedVIPERReader;

let adaptive_strategy = ReadAccessStrategy::Adaptive {
    initial_strategy: Box::new(
        ReadAccessStrategy::CachedSearch { prefetch_metadata: true }
    ),
    fallback_threshold: 5, // Switch after 5 cache misses
};

let reader = UnifiedVIPERReader::new(
    filesystem_factory,
    "my_collection".to_string(),
    adaptive_strategy,
)?;
----

**Best for:**

* Mixed workloads (search + batch operations)
* Applications with variable access patterns
* Development and testing environments
* Workloads requiring runtime optimization

== Engine-Specific Usage Examples

=== SST Engine (Row-based, High-frequency Updates)

[source,rust]
----
use proximadb::storage::engines::impls::sst::readers::UnifiedSstableReader;

// For real-time queries
let sst_reader = UnifiedSstableReader::new(
    filesystem_factory.clone(),
    unified_fs,
    collection_id,
);

// Strategy determines internal SST behavior:
// DirectStream -> CompactionDirect (no bloom filter cache)
// CachedSearch -> SearchOptimized (cache bloom filters and indexes)
----

=== SWIFT Engine (FastLanes Columnar)

[source,rust]
----
use proximadb::storage::engines::impls::swift::{UnifiedSWIFTReader, SwiftReaderConfig};

// Configure for high-throughput search
let config = SwiftReaderConfig {
    enable_prefetch: false,        // Disable for random access
    max_concurrent_reads: 8,       // Higher concurrency for search
    coalesce_threshold_bytes: 64 * 1024,
    cache_metadata: true,          // Cache superblock metadata
    use_streaming: false,          // Not streaming for search
};

let reader = UnifiedSWIFTReader::for_search(
    filesystem_factory,
    collection_id,
)?;
----

=== NOVA Engine (Advanced Analytics)

[source,rust]
----
use proximadb::storage::engines::impls::nova::UnifiedNOVAReader;

// For complex analytics queries
let reader = UnifiedNOVAReader::for_search(
    filesystem_factory,
    collection_id,
)?;

// NOVA maps strategies to zone map pruning:
// DirectStream -> NoPruning (read all data)
// CachedSearch -> Hierarchical(3) (3-tier statistics hierarchy)
// CachedSelective -> BasicZoneMap (simple min/max pruning)
----

=== VIPER Engine (Production Columnar)

[source,rust]
----
use proximadb::storage::engines::impls::viper::UnifiedVIPERReader;

// For Parquet-optimized analytics
let reader = UnifiedVIPERReader::for_search(
    filesystem_factory,
    collection_id,

// VIPER optimizes for Parquet:
// DirectStream -> Direct arrow-rs streaming
// CachedSearch -> Cached Parquet footer and metadata

=== HELIX Engine (Time-series Optimized)

[source,rust]
----
use proximadb::storage::engines::impls::helix::UnifiedHELIXReader;

// For time-series queries with temporal locality
let reader = UnifiedHELIXReader::for_time_series_query(
    filesystem_factory,
    collection_id,

// HELIX specializes in temporal patterns:
// DirectStream -> NoPruning (full temporal scan)

== Strategy Switching at Runtime

All unified readers support dynamic strategy switching:

[source,rust]
----
use proximadb::storage::engines::core::read_strategy::StrategyAwareReader;

let mut reader = UnifiedNOVAReader::for_compaction(
    filesystem_factory,
    collection_id,
)?;

// Initially optimized for compaction (DirectStream)
assert_eq!(reader.strategy(), &ReadAccessStrategy::DirectStream);

// Switch to search optimization
reader.set_strategy(ReadAccessStrategy::CachedSearch { prefetch_metadata: true });

// Reader automatically reconfigures internal optimizations
assert!(matches!(reader.strategy(), ReadAccessStrategy::CachedSearch { .. }));
----

== Best Practices

=== 1. Choose Strategy Based on Access Pattern

[source,rust]
----
// ✅ Good: Direct reads for compaction
let compaction_reader = UnifiedNOVAReader::for_compaction(fs, collection_id)?;

// ✅ Good: Cached reads for search
let search_reader = UnifiedNOVAReader::for_search(fs, collection_id)?;

// ❌ Bad: Cached reads for full scans (cache pollution)
// let bad_reader = UnifiedNOVAReader::for_search(fs, collection_id)?;
// bad_reader.read_entire_collection().await?; // Don't do this
----

=== 2. Use Factory Methods for Common Patterns

[source,rust]
----
// ✅ Preferred: Use factory methods
let reader = UnifiedSWIFTReader::for_search(fs, collection_id)?;

// ✅ Alternative: Explicit strategy when needed
let reader = UnifiedSWIFTReader::new(
    fs,
    collection_id,
    ReadAccessStrategy::CachedSelective { filter: Some(filter) },
    custom_config,
)?;
----

=== 3. Switch Strategies Based on Workload Changes

[source,rust]
----
// Start with search optimization
let mut reader = UnifiedHELIXReader::for_search(fs, collection_id)?;

// Process search queries...
search_results = reader.search(query_vector, top_k).await?;

// Switch to compaction when needed
reader.set_strategy(ReadAccessStrategy::DirectStream);
compaction_data = reader.read_for_compaction().await?;
----

=== 4. Monitor and Tune Adaptive Thresholds

[source,rust]
----
// Tune fallback threshold based on workload
let adaptive_strategy = ReadAccessStrategy::Adaptive {
    initial_strategy: Box::new(ReadAccessStrategy::CachedSearch { prefetch_metadata: true }),
    fallback_threshold: if high_cache_hit_rate { 10 } else { 3 },
};
----

== Troubleshooting

=== Common Issues

**Cache Not Working**::
Ensure you're using a caching strategy (`CachedSearch`, `CachedSelective`, not `DirectStream`)

**Poor Performance on Full Scans**::
Use `DirectStream` strategy or `for_compaction()` factory method for sequential reads

**Memory Usage Too High**::
Switch from caching strategies to `DirectStream` for large data operations

**Inconsistent Behavior Across Engines**::
Verify all engines are using the same `ReadAccessStrategy` enum values

== Conclusion

The Unified Strategy Pattern provides a powerful, consistent way to optimize read operations across all ProximaDB storage engines. By choosing the right strategy for your workload, you can achieve significant performance improvements while maintaining code clarity and consistency.

Key takeaways:

* Use `DirectStream` for full scans and compaction
* Use `CachedSearch` for search workloads
* Use `CachedSelective` for point queries and filtered access
* Use `Adaptive` for variable workloads
* All engines support the same strategy interface
* Strategy switching is supported at runtime
* Factory methods provide convenient defaults for common patterns
