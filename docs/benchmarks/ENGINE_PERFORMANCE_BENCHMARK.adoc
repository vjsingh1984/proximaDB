== Detailed Results by Engine

=== SST Engine (Write-Optimized)

SST uses LSM-tree architecture optimized for real-time writes with integrated AXIS indexing.

[cols="1,1,1,1,1,1", options="header"]
|===
| Vectors | Insert (vec/s) | Flush (ms) | Search Avg (ms) | Search P99 (ms) | Recall
| 1,000 | 4,024 | 2.3 | 9.22 | 11.58 | 90.8%
| 5,000 | 3,188 | 12.1 | 27.43 | 39.02 | 100%
| 10,000 | 2,867 | 27.5 | 43.82 | 58.41 | 100%
|===

*Analysis*: 90.8% recall at 1K vectors is due to cold-start HNSW index building. At 5K+ vectors, SST achieves perfect recall with AXIS integration.

=== HELIX Engine (Locality-Optimized)

HELIX uses Hilbert curve ordering for spatial locality with zone map pruning.

[cols="1,1,1,1,1,1", options="header"]
|===
| Vectors | Insert (vec/s) | Flush (ms) | Search Avg (ms) | Search P99 (ms) | Recall
| 1,000 | 5,128 | 3.1 | 15.67 | 19.23 | 100%
| 5,000 | 3,892 | 18.4 | 39.21 | 52.18 | 100%
| 10,000 | 2,509 | 41.2 | 68.76 | 89.45 | 100%
|===

*Analysis*: HELIX maintains 100% recall across all scales. Hilbert-based zone map pruning eliminates unnecessary file scans. PCA uses real SVD via nalgebra.

=== VIPER Engine (Analytics-Optimized)

== Key Bug Fixes Applied

=== SST HNSW Recall at 50K (Phase 10.1)

*Root Cause*: IVF trained too early with only 100 vectors, creating 20 clusters.

*Fix*: Added `train_ivf_for_batch()` in `manager.rs` with optimal cluster sizing:
[source,rust]
----
// n_clusters = clamp(sqrt(N) * 2, 16, 256)
let n_clusters = ((batch_size as f32).sqrt() as usize * 2).clamp(16, 256);
----

=== RAPTOR 210-Second Flush (Phase 10.2)

*Root Cause*: Duplicate IVF clustering running twice during flush.

*Status*: Already fixed in prior commits.

=== SWIFT Fallback Path (Phase 10.5)

*Root Cause*: Search fell back to direct scan without block pruning.

*Fix*: Updated `swift/engine.rs` to use `search_without_index` for block-pruned search.

== Architecture Improvements

=== AXIS Manager Integration

All 6 engines now implement the AXIS index search path:

[source,rust]
----
// Phase 0: Try AXIS index first
if self.axis_manager.is_some() {
    if let Some(manager) = &self.axis_manager {
        let axis_filter = self.convert_filter_to_axis(&filter);
        match manager.search(&collection_id, query_vector, k * 2, axis_filter).await {
            Ok(candidates) if !candidates.is_empty() => {
                // Refine with exact distances
            }
        }
    }
}
// Fallback: Engine-specific search
----

=== Progressive Search Stages (ISP Compliant)

All engines implement the `ProgressiveSearchStage` trait:

* `BinaryStage` - Hamming distance pre-filtering (32x compression)
* `INT8Stage` - Quantized distance calculation (4x compression)
* `FP32Stage` - Full precision final ranking

== Recommendations

=== Engine Selection Guide

[cols="1,2,1", options="header"]
|===
| Workload | Recommended Engine | Reason
| Real-time streaming | SST | LSM-tree, 5ms latency target
| High-dimensional (>512d) | HELIX | Hilbert locality, PCA reduction
| Analytics/batch | VIPER | Columnar Parquet, row group pruning
| Small datasets (<5K) | SWIFT | In-memory, simple architecture
| Mixed workloads | NOVA | Progressive search, zone maps
| Dynamic scaling | RAPTOR | Adaptive multi-tier
|===
