== Configuration Presets

=== Optimal (Recommended for M4 Pro) ⭐

[source,rust]
----
BlockCompressionConfig {
    vector_layout: VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector,
    algorithm: CompressionAlgorithm::Lz4,
    compression_level: 3,
    enable_vector_compression: true,
    enable_metadata_compression: true,
    compression_threshold_bytes: 256,
    dictionary_compression: false,  // For batches <50k
}

EngineProfile::Swift  // Best SIMD performance
----

**Use when**: Default configuration for most workloads
**Performance**: 227 Kelem/s encoding, balanced compression
**Memory**: ~150 MB for 100k vectors

=== Large-Scale (100k+ vectors)

[source,rust]
----
BlockCompressionConfig {
    vector_layout: VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector,
    algorithm: CompressionAlgorithm::Zstd,  // Better for large batches
    compression_level: 3,
    enable_vector_compression: true,
    enable_metadata_compression: true,
    compression_threshold_bytes: 1024,
    dictionary_compression: true,  // Critical for >50k vectors
}

EngineProfile::Swift
----

**Use when**: Processing >50k vectors per batch
**Performance**: 454 MiB/s peak at 100k × 384d
**Memory**: ~1.5 GB for 1M vectors

=== Real-Time (Low Latency)

[source,rust]
----
BlockCompressionConfig {
    vector_layout: VectorEncodingLayout::FullVector,  // No encoding overhead
    algorithm: CompressionAlgorithm::Lz4,
    compression_level: 1,  // Minimal compression
    enable_vector_compression: false,
    enable_metadata_compression: true,
    compression_threshold_bytes: 512,
    dictionary_compression: false,

----

**Use when**: Latency-critical applications (<1ms encoding)
**Performance**: 638 Kelem/s (no encoding overhead)
**Memory**: Higher (no compression)

=== Adaptive Selection Example

[source,rust]
----
pub fn select_encoding(vectors: &[Vec<f32>]) -> VectorEncodingLayout {
    let profile = analyze_pattern(vectors);

    match profile {
        p if p.constant_ratio > 0.6 => {
            // Use RLE for constant patterns
            VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector
        }
        p if p.zero_ratio > 0.8 => {
            // TODO: Use sparse bitmap when implemented
            VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector
        }
        _ => {
            // Default grouped encoding
            VectorEncodingLayout::GroupedFieldEncodedAndCompressedVector
        }
    }
}
----

== Troubleshooting

[cols="2,3,2"]
|===
|Symptom |Cause |Solution

|Encoding <180 Kelem/s
|Suboptimal layout or batch size
|Use Grouped encoding, batch 100k

|Large-scale <350 MiB/s
|Cache pressure or small batches
|Increase batch to 100k-200k

|SIMD bandwidth <1.2 GiB/s
|Cache thrashing at high dimensions
|Reduce dimension or use multi-threaded transpose

|Sparse data slow
|Current implementation overhead
|Wait for sparse bitmap implementation

|High outlier rates
|Workload variance
|Enable adaptive encoding selection

|Memory pressure
|Batch size too large
|Reduce to 100k-200k vectors
|===

== Quick Tuning Guide

=== Step 1: Profile Your Data

[source,bash]
----
# Analyze actual production vectors
cargo run --bin proximadb-bench -- analyze-vectors \
  --input vectors.bin \
  --output pattern_report.json

# Check pattern distribution
{
  "constant_ratio": 0.15,
  "clustered_ratio": 0.30,
  "random_ratio": 0.40,
  "sparse_ratio": 0.15
}
----

=== Step 2: Select Configuration

```
If constant_ratio > 0.6:
  → Use Grouped + RLE (+17% performance)

If sparse_ratio > 0.8:
  → Wait for sparse bitmap (current: -4%)

Otherwise:
  → Use default Grouped encoding (227 Kelem/s)
```

=== Step 3: Optimize Batch Size

```
Data size < 10k vectors:
  → Batch: 1k-10k
  → Compression: LZ4 level 3
  → Expected: ~200 Kelem/s

Data size 10k-100k vectors:
  → Batch: 100k (OPTIMAL)
  → Compression: Zstd level 3 + dictionary
  → Expected: ~450 MiB/s

Data size > 100k vectors:
  → Batch: 100k-200k
  → Compression: Zstd + dictionary
  → Expected: ~400 MiB/s
```

=== Step 4: Monitor and Tune

== Normalization Calculator

Use these formulas to estimate performance on your hardware:

[source,rust]
----
// SIMD throughput adjustment
let simd_factor = (target_simd_width / 128.0) * (target_clock_ghz / 3.75);
let adjusted_throughput = 227_000 * simd_factor;  // elem/s

// Example: Intel AVX512 @ 2.5 GHz
// simd_factor = (512/128) * (2.5/3.75) = 4.0 * 0.67 = 2.67
// adjusted = 227k * 2.67 = 606 Kelem/s

// Cache size adjustment
let cache_factor = target_cache_mb / 32.0;
let optimal_batch = 100_000 * cache_factor;

// Example: Intel Xeon 64MB L3
// optimal_batch = 100k * (64/32) = 200k vectors

// Memory bandwidth adjustment
let bandwidth_factor = target_bandwidth_gbps / 300.0;
let large_scale_throughput = 454.0 * bandwidth_factor;  // MiB/s

// Example: DDR4-3200 (100 GB/s)
// large_scale = 454 * (100/300) = 151 MiB/s
----
