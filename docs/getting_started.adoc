== Quick Installation

=== Docker (Recommended)

[source,bash]
----
# Complete production-ready setup
git clone https://github.com/vjsingh1984/proximadb.git
cd proximadb/demo && docker compose up -d

# Verify both REST and gRPC endpoints
curl http://localhost:5678/health
grpcurl -plaintext localhost:5679 list

=== From Source (Production Build)

[source,bash]
----
# Prerequisites: Rust 1.75+, gcc-14, Protocol Buffers compiler
git clone https://github.com/vjsingh1984/proximadb.git
cd proximadb

# Build with production optimizations
cargo build --release
./target/release/proximadb-server

# Dual protocol servers
# REST API: http://localhost:5678
# gRPC API: grpc://localhost:5679
----

=== Proto-First Client Workflow

[source,python]
----
from proximadb import UnifiedClient
from sentence_transformers import SentenceTransformer

# 1. Connect to ProximaDB (unified client supports both REST and gRPC)
client = UnifiedClient("http://localhost:5678")  # REST
# client = UnifiedClient("grpc://localhost:5679")  # gRPC (for performance)

# 2. Create a collection with quantization support
collection_config = {
    "collection_id": "ai_documents",
    "dimension": 384,
    "distance_metric": "cosine",
    "quantization_config": {
        "quantization_level": "pq8",  # Product quantization (8-bit)
        "enable_two_stage_search": True
    }
}
collection = client.create_collection(collection_config)

# 3. Generate embeddings with modern model
model = SentenceTransformer('all-MiniLM-L6-v2')
texts = [
    "ProximaDB delivers optimized search performance",
    "Proto-first architecture eliminates double serialization",
    "Storage-aware search automatically selects optimal engines",
    "Unified quantization provides hardware acceleration"
]
embeddings = model.encode(texts)

# 4. Batch insert with proto-native operations
vectors = []
for i, (text, embedding) in enumerate(zip(texts, embeddings)):
    vectors.append({
        "id": f"doc_{i}",
        "vector": embedding.tolist(),
        "metadata": {
            "text": text,
            "category": "architecture",
            "timestamp": "2025-01-12"
        }
    })

# Insert batch (optimized for 64MB gRPC limit)
client.insert_vectors_batch(collection_id="ai_documents", vectors=vectors)

# 5. Search with optimization hints
query_embedding = model.encode(["vector database performance optimization"])
search_request = {
    "collection_id": "ai_documents",
    "query_vector": query_embedding[0].tolist(),
    "k": 3,
    "search_optimization_hints": {
        "enable_two_stage_search": True,
        "candidate_multiplier": 3,
        "quantization_hint": "pq8"
    },
    "metadata_filter": {
        "category": "architecture"
    }
}

results = client.search_vectors(search_request)

# 6. View results with performance metrics
print(f"Search completed in {results.latency_ms}ms")
for result in results.vectors:
    print(f"Score: {result.distance:.4f} - {result.metadata['text']}")
    
# 7. Check collection stats
stats = client.get_collection_stats("ai_documents")
print(f"Total vectors: {stats.vector_count}")
print(f"Storage engine: {stats.storage_engine}")
print(f"Quantization: {stats.quantization_level}")
----

== Production Performance Tips

=== Optimal Batch Sizes (64MB gRPC Limit)

[cols="2,2,2,3"]
|===
|**Vector Dim** |**Batch Size** |**Throughput** |**Use Case**

|128 |30,000 |50,000 vec/s |Small embeddings
|384 |10,000 |18,000 vec/s |Sentence transformers
|768 |5,000 |10,000 vec/s |Large language models
|1536 |2,500 |5,000 vec/s |GPT embeddings
|===

=== Quantization Selection Guide

[source,python]
----
# High accuracy (>95% recall)
quantization_config = {"quantization_level": "int8"}

# Balanced (90% recall, 4x compression)
quantization_config = {"quantization_level": "pq8"}

# Maximum compression (85% recall, 32x compression)
quantization_config = {"quantization_level": "binary"}
----

=== Hardware Optimization

- **x86 with AVX2**: 40% faster distance calculations
- **ARM with NEON**: 25% improvement on compatible hardware  
- **GPU acceleration**: Use gRPC for large batch operations
- **Multi-disk setup**: Configure hot/warm/cold storage tiers

== Troubleshooting

[cols="2,3,3"]
|===
|**Issue** |**Cause** |**Solution**

|Connection refused |Server not running |Check `cargo run --bin proximadb-server`
|Dimension mismatch |Vector size mismatch |Verify collection dimension=384
|Slow search (>100ms) |No quantization |Enable `two_stage_search: True`
|High memory usage |Large vectors in memory |Configure WriteBuffer flush thresholds
|Proto parse errors |Mismatched schemas |Update to latest Python SDK
|===

== Advanced Features Preview

=== Multi-Engine Storage Strategy

[source,python]
----
# VIPER engine for analytics workloads
collection_config = {
    "storage_engine": "viper",
    "enable_ml_clustering": True,
    "parquet_compression": "zstd"
}

# SST engine for high-write workloads  
collection_config = {
    "storage_engine": "lsm",
    "enable_bloom_filters": True,
    "compaction_style": "leveled"
}
----

=== Storage-Aware Search

ProximaDB automatically selects the optimal search strategy:

- **WriteBuffer search**: Latest unflushed vectors
- **VIPER search**: Columnar Parquet with predicate pushdown
- **SST search**: Row-based SSTable with bloom filters
