= Agent Tools — GraphWalk
:toc: auto

ProximaDB exposes graph traversal as agent-callable tools so an LLM can
walk a graph step by step without the database materializing a subgraph
that won't fit in the agent's context window. The patterns follow
arXiv:2604.01610 (Ghandi/Mahyar/Klaiman 2026, GraphWalk).

== Tool catalog

|===
| Tool | When to choose | REST endpoint

| `graph_walk`
| You can predict roughly how many nodes you want, and BFS depth is a
useful budget.
| `POST /api/v1/graph/graphs/:graph_id/walk`

| `graph_step`
| You need to inspect each neighbor before deciding where to go. Call
in a loop.
| `POST /api/v1/graph/graphs/:graph_id/step`
|===

== Machine-readable schema

The canonical schema for both tools lives in the Python SDK at
`clients/python/src/proximadb_sdk/integrations/mcp_tools.py`. It is
the single source of truth — every other surface (this doc, agent
runtime registrations, future TypeScript SDK) renders from it.

[source,python]
----
from proximadb_sdk.integrations.mcp_tools import list_tools, render_invocation

# 1. Hand the schema to your agent runtime (Anthropic / OpenAI / MCP).
tools = list_tools()
# Example: tools[0]["name"] == "graph_walk"

# 2. When the agent emits a tool call, translate it to a request.
method, path, body = render_invocation("graph_walk", {
    "graph_id": "ontology",
    "start_node_id": "n1",
    "max_depth": 2,
    "limit": 50,
})
# method = "POST"
# path   = "/api/v1/graph/graphs/ontology/walk"
# body   = {"start_node_id": "n1", "max_depth": 2, "limit": 50}
----

`render_invocation` is the *guardrail layer*: it drops any keys the
agent hallucinated that aren't in the schema, raises a clear `ValueError`
on missing required arguments, and lifts `graph_id` to the URL path so
the body matches what the server expects.

== Tool specifications (for reference)

=== `graph_walk`

[source,json]
----
{
  "name": "graph_walk",
  "description": "Bounded breadth-first exploration of a ProximaDB graph from a starting node. Returns up to `limit` nodes within `max_depth` hops.",
  "input_schema": {
    "type": "object",
    "properties": {
      "graph_id":      {"type": "string"},
      "start_node_id": {"type": "string"},
      "max_depth":     {"type": "integer", "minimum": 0},
      "limit":         {"type": "integer", "minimum": 1}
    },
    "required": ["graph_id", "start_node_id"]
  }
}
----

=== `graph_step`

[source,json]
----
{
  "name": "graph_step",
  "description": "Single-step graph navigation: return the immediate neighbors of one node, optionally filtered by edge type. Call in a loop when the agent needs to drive traversal step by step.",
  "input_schema": {
    "type": "object",
    "properties": {
      "graph_id":  {"type": "string"},
      "node_id":   {"type": "string"},
      "edge_type": {"type": "string"},
      "limit":     {"type": "integer", "minimum": 1}
    },
    "required": ["graph_id", "node_id"]
  }
}
----

== Anthropic example

[source,python]
----
import anthropic
from proximadb_sdk.integrations.mcp_tools import list_tools, render_invocation

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    tools=list_tools(),
    messages=[{"role": "user", "content": "What is connected to node n1 in graph ontology?"}],
)

for block in response.content:
    if block.type == "tool_use":
        method, path, body = render_invocation(block.name, block.input)
        # ... fire the request, feed the result back to the model
----

== Higher-level: GraphWalkClient

If you want the schema validation + HTTP turn in one object,
`graph_walk_client.GraphWalkClient` composes the renderer with an
injected HTTP transport. The transport callable is the seam that lets
the SDK stay backend-agnostic — plug in `httpx`, `requests`,
`aiohttp`, or anything else.

[source,python]
----
import httpx
from proximadb_sdk.integrations.graph_walk_client import GraphWalkClient

def httpx_transport(method: str, url: str, json: dict) -> dict:
    return httpx.request(method, url, json=json).json()

client = GraphWalkClient("http://localhost:5678", transport=httpx_transport)

# Convenience methods with typed signatures.
result = client.walk(graph_id="ontology", start_node_id="n1", max_depth=2, limit=50)
result = client.step(graph_id="ontology", node_id="n1", edge_type="REFERS_TO", limit=10)

# Or generic dispatch when the agent emits a name+args pair.
result = client.invoke("graph_walk", {"graph_id": "ontology", "start_node_id": "n1"})
----

`GraphWalkClient` validates argument shape via `mcp_tools.render_invocation`
(missing required args → `ValueError`), normalizes trailing slashes
on the base URL, and wraps transport errors in `GraphWalkError` so
callers don't have to import every backend's exception type.

(proto messages plus generated tonic handlers) is the remaining
