== Quick ROI Estimator

=== Your Current Setup

[source,javascript]
----
// Input your metrics
const currentMetrics = {
  vectors: 10_000_000,        // Number of vectors
  dimensions: 1536,            // Vector dimensions
  qps: 100,                    // Queries per second
  storageGB: 600,              // Current storage used
  monthlyInfraCost: 2000,      // Infrastructure cost
  monthlyStorageCost: 150      // Storage cost
};

// ProximaDB savings calculation
const savings = {
  storage: currentMetrics.storageGB * 0.65,           // 65% reduction
  infraCost: currentMetrics.monthlyInfraCost * 0.70,  // 70% reduction
  performance: currentMetrics.qps * 3.5                // 3.5x improvement
};

const annualSavings = (savings.infraCost + 
                       currentMetrics.monthlyStorageCost * 0.65) * 12;

console.log(`Annual Savings: $${annualSavings.toLocaleString()}`);
console.log(`New QPS Capacity: ${savings.performance}`);
console.log(`Storage Saved: ${savings.storage} GB`);
----

== Decision Framework

=== When ProximaDB Delivers Maximum ROI

✅ **Ideal Scenarios**:
* Vector datasets > 1M vectors
* Need for real-time search (<10ms)
* Storage costs > $1,000/month
* Multi-modal search requirements
* High ingestion rates (>1K vectors/sec)

⚠️ **Consider Alternatives If**:
* < 100K vectors
* Batch processing only
* No latency requirements
* Existing vendor lock-in with high switching costs
