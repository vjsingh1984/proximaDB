== Structural Improvements

=== Before: Scattered and Duplicated

**Problems**:
- Engine docs duplicated between `docs/storage/` and `src/storage/engines/impls/`
- Performance docs split between `benchmarks/` and `performance/`
- Implementation plans in two directories
- No clear content boundaries
- ~3,800 lines of duplicate storage engine documentation

**Example of duplication**:
```
docs/storage/sst-engine-deep-dive.adoc:
  - SST architecture overview
  - ProximaBlocks format details
  - Implementation specifics
  - Usage guide
  - Configuration examples

src/storage/engines/impls/sst/README.adoc:
  - SST architecture overview (DUPLICATE)
  - ProximaBlocks format details (DUPLICATE)
  - Implementation specifics (OVERLAPPING)
```

=== After: Modular and Clear

**Solutions**:
- Single storage layer overview doc references individual engine implementations
- Unified performance directory with clear hub
- Single implementation directory
- Clear tier-based boundaries
- Zero duplication with cross-references

**Example of modular structure**:
```
docs/07-architecture/storage-layer.adoc:
  - High-level SST overview
  - When to use SST
  - Performance characteristics
  - Configuration examples
  - → References src/storage/engines/impls/sst/README.adoc

src/storage/engines/impls/sst/README.adoc:
  - ProximaBlocks internal format (CANONICAL)
  - Implementation architecture
  - Code organization
  - Development guidelines
  - → References docs/07-architecture/ for usage
```

## Documentation Principles

=== 1. Single Source of Truth

Each concept documented **exactly once** in canonical location:

[cols="2,3,3", options="header"]
|===
| Concept | Canonical Location | References From

| SST Architecture Overview | `docs/07-architecture/storage-layer.adoc` | Various guides
| SST Implementation Details | `src/storage/engines/impls/sst/README.adoc` | Architecture doc
| Performance Benchmarks | `docs/05-performance/benchmark-results.adoc` | Optimization guides
| AXIS Index System | `src/index/axis/README.adoc` | Architecture docs
|===

=== 2. Reference, Don't Duplicate

**Pattern**: High-level docs link to detailed docs

**Benefits**:
- Update once, consistent everywhere
- Clear documentation hierarchy
- No drift between duplicates
- Easier maintenance

=== 3. Proximity to Code

**Pattern**: Implementation docs live with code

**Benefits**:
- Docs updated with code changes
- Easy to find relevant documentation
- Natural organization
- Lower risk of doc drift

## Cross-Reference System

=== Bidirectional Linking

**From docs/ to src/**:
```asciidoc
= Storage Layer Architecture

For SST implementation details, see
link:../../src/storage/engines/impls/sst/README.adoc[SST Implementation Guide].
```

**From src/ to docs/**:
```asciidoc
= SST Engine Implementation

For user-facing documentation, see
link:02-guides/engine_selection_optimization_guide.adoc[Engine Selection Guide].
```
