**Complete guide to ProximaDB's unified quantization system for vector compression and accelerated search**

== Overview

ProximaDB's quantization system provides efficient vector compression with configurable quality/performance tradeoffs. The system is **fully implemented** and production-ready across all 6 storage engines.

**Key Features:**
* **Multiple Quantization Levels**: Binary, INT8, PQ4/8/16/32
* **Hardware Acceleration**: SIMD-optimized operations
* **Progressive Search**: Multi-level cascade for speed
* **Codebook Management**: Training, caching, persistence
* **Storage-Agnostic**: Works across all engines

[cols="2,1,1,1,1", options="header"]
|===
| Quantization Level | Compression | Recall | Speed | Use Case
| Binary (1-bit) | 32x | 70% | 50x | Fast filtering
| INT8 (8-bit) | 4x | 95% | 10x | Balanced
| PQ4 (4-bit) | 8x | 85% | 8x | High compression
| PQ8 (8-bit) | 4-32x | 90% | 6x | Production default
| PQ16 (16-bit) | 2-16x | 95% | 4x | High accuracy
| PQ32 (32-bit) | 1-8x | 98% | 2x | Maximum accuracy
| FP32 (original) | 1x | 100% | 1x | Baseline
|===

=== Core Components

**UnifiedQuantizationEngine** (`unified.rs`):
* Main entry point for all quantization operations
* Manages codebooks and training
* Coordinates hardware acceleration
* Provides distance computation on quantized vectors

**CodebookStore** (trait):
* Persistence layer for PQ codebooks
* Implementations: InMemory, File-based, Distributed
* Thread-safe with DashMap caching

**AcceleratedQuantization** (`hardware_accelerated.rs`):
* SIMD-optimized batch operations
* AVX2/AVX512/NEON support
* Automatic hardware detection

**QuantizationSelector** (`selection.rs`):
* Intelligent level selection based on:
  - Vector dimensionality
  - Dataset size
  - Query patterns
  - Hardware capabilities

== Quantization Levels

=== Binary Quantization

**Compression**: 32x (1 bit vs 32 bits per dimension)

**Algorithm**: Sign-based thresholding
[source,rust]
----
// Quantize FP32 to binary
for value in vector {
    bit = if value >= threshold { 1 } else { 0 }
}
----

**Distance Metric**: Hamming distance
[source,rust]
----
let distance = (a XOR b).count_ones();
----

**Use Cases**:
* First-stage filtering in cascade search
* Bloom filter-style existence checks
* Ultra-fast approximate search

**Configuration**:
[source,rust]
----
let config = BinaryQuantization {
    threshold: Some(0.0),  // Default: 0.0 (sign-based)
    sign_based: true,
};
----

**Example**:
[source,rust]
----
let engine = UnifiedQuantizationEngine::new(/* ... */);
let binary = engine.quantize_to_binary(&vector)?;
// binary.len() = ceil(vector.len() / 8) bytes
----

**Performance**:
* Quantization: ~0.1µs per vector
* Distance: ~0.05µs per pair (Hamming)
* Memory: 3% of FP32 (768d → 96 bytes)

=== INT8 Quantization

**Compression**: 4x (8 bits vs 32 bits per dimension)

**Algorithm**: Min-max normalization
[source,rust]
----
let min = vector.iter().min();
let max = vector.iter().max();
let scale = 255.0 / (max - min);

for value in vector {
    quantized = ((value - min) * scale).round() as u8
}
----

**Distance Metric**: L2 distance on quantized values
[source,rust]
----
let distance: i32 = quantized_a.iter()
    .zip(quantized_b.iter())
    .map(|(a, b)| {
        let diff = (*a as i32) - (*b as i32);
        diff * diff
    })
    .sum();
----

**Use Cases**:
* Production default for most workloads
* Good balance of compression and accuracy
* Second-stage refinement in cascade

**Configuration**:
[source,rust]
----
let config = ScalarQuantization {
    bits: 8,
    scale: 1.0,      // Auto-calculated
    offset: 0.0,     // Auto-calculated
    clamp_values: true,
};
----

**Example**:
[source,rust]
----
let (quantized, min, max) = engine.quantize_to_u8(&vector)?;
// quantized.len() = vector.len() bytes
let reconstructed = engine.dequantize_u8(&quantized, min, max);
----

**Performance**:
* Quantization: ~0.5µs per vector (768d)
* Distance: ~2µs per pair
* Memory: 25% of FP32 (768d → 768 bytes + 8 bytes overhead)
* Recall: 95%+ with proper calibration

=== Product Quantization (PQ)

**Compression**: 4-32x depending on configuration

**Algorithm**: Subspace quantization with k-means
[source,text]
----
1. Divide vector into M subvectors
2. Train codebook for each subspace (k-means)
3. Replace each subvector with nearest centroid index
4. Store only indices (8-32 bits each)
----

**Subspace Division**:
[source,text]
----
Vector (768d) → 8 subvectors (96d each)
Each subvector → 256 centroids (8-bit index)
Result: 768 × 32 bits → 8 × 8 bits = 32x compression
----

**Distance Computation**:
[source,rust]
----
// Asymmetric distance (query is FP32, vectors are PQ)
let mut distance = 0.0;
for (subvector_query, pq_code) in query.chunks(dim/M).zip(pq_codes) {
    let centroid = codebook[subspace][pq_code];
    distance += euclidean(subvector_query, centroid);
}
----

**Quantization Levels**:
[cols="1,1,1,2"]
|===
| Level | Bits/Code | Centroids | Compression
| PQ4 | 4 | 16 | 8x
| PQ8 | 8 | 256 | 4x
| PQ16 | 16 | 65536 | 2x
| PQ32 | 32 | 2^32 | 1x
|===

**Configuration**:
[source,rust]
----
let config = ProductQuantization {
    bits_per_code: 8,         // 4, 8, 16, or 32
    num_subvectors: 8,        // M subspaces
    codebook_id: None,        // Auto-generated
    adaptive_subvectors: false,  // Fixed subspace sizes
};
----

**Training**:
[source,rust]
----
// Train PQ codebook on sample data
let engine = UnifiedQuantizationEngine::new(/* ... */);
let codebook = engine.train_pq_codebook(
    &training_vectors,  // 10K-100K samples
    8,                  // num_subvectors
    256,                // centroids_per_subvector
    20,                 // max_iterations
).await?;
----

**Example**:
[source,rust]
----
// Quantize with trained codebook
let pq_codes = engine.quantize_to_pq(
    &vector,
    &codebook,
    num_subvectors,
)?;

// pq_codes.len() = num_subvectors bytes (for PQ8)
----

**Performance**:
* Training: 5-30 seconds for 100K vectors
* Quantization: ~5µs per vector
* Distance: ~10µs per pair (asymmetric)
* Memory: PQ8(8 subvectors) = 8 bytes per vector
* Recall: 90%+ with proper training

=== Uniform Quantization

**Compression**: Configurable (2-16 bits per dimension)

**Algorithm**: Linear quantization with scale and offset
[source,rust]
----
let quantized = ((value - offset) / scale).round();
let clamped = quantized.clamp(0, (1 << bits) - 1);
----

**Use Cases**:
* Custom compression ratios
* Domain-specific optimizations
* Research and experimentation

**Configuration**:
[source,rust]
----
let config = UniformQuantization {
    bits: 4,          // 2-16 bits
    scale: None,      // Auto-calculated
    offset: None,     // Auto-calculated
};
----

== Progressive Cascade Search

The quantization system enables multi-level cascade search for optimal speed/accuracy tradeoff:

[source,mermaid]
----

    B -->|Top 10%| C{Stage 2<br/>INT8}
    C -->|Top 1%| D{Stage 3<br/>PQ8}
    D -->|Top k×2| E[Stage 4<br/>FP32 Rerank]
    E --> F[Final Top-K]

    B -.->|Filtered 90%| X[Eliminated]
    C -.->|Filtered 9%| X
    D -.->|Filtered 0.9%| X

let result = engine.calculate_progressive_distance(

----

**Stage Configuration**:
[cols="1,2,1,1,2"]
|===
| Stage | Level | Candidates In | Candidates Out | Cost per Vector
| 1 | Binary | 1,000,000 | 100,000 | 0.05µs
| 2 | INT8 | 100,000 | 10,000 | 2µs
| 3 | PQ8 | 10,000 | 20 | 10µs
| 4 | FP32 | 20 | 10 | 50µs
|===

**Total Cost**: ~0.05µs × 1M + 2µs × 100K + 10µs × 10K + 50µs × 20 = 351ms

**vs. Brute Force FP32**: 50µs × 1M = 50,000ms

**Speedup**: 142x with 95%+ recall

== Codebook Management

=== Training

**K-means++ Algorithm**:
[source,rust]
----
// 1. Select first centroid randomly
let first = sample_random(&training_data);
centroids.push(first);

// 2. Select remaining centroids with D² weighting
for _ in 1..k {
    let distances = compute_distances(&training_data, &centroids);
    let probabilities = distances.map(|d| d * d); // D²
    let next = sample_weighted(&training_data, &probabilities);
    centroids.push(next);
}

// 3. Lloyd's iterations
for iteration in 0..max_iterations {
    // Assign points to nearest centroid
    let assignments = assign_to_nearest(&training_data, &centroids);

    // Recompute centroids
    centroids = compute_cluster_means(&training_data, &assignments);

    // Check convergence
    if !has_changed(&old_centroids, &centroids, epsilon) {
        break;
    }
}
----

**Training Configuration**:
[source,rust]
----
pub struct TrainingConfig {
    pub sample_size: usize,        // 10K-100K
    pub max_iterations: usize,     // 20-50
    pub convergence_threshold: f32,  // 1e-4
    pub initialization: InitMethod,  // KMeansPlusPlus, Random
    pub num_attempts: usize,       // Try N times, keep best
}
----

**Example**:
[source,rust]
----
let codebook = engine.train_pq_codebook(
    &training_vectors,
    num_subvectors,
    centroids_per_subvector,
    max_iterations,
).await?;

// Codebook structure:

----

**Global Codebook Cache**:

* LRU with size limit
* Per-collection TTL
* Manual invalidation on codebook retrain

== Usage Examples

=== Basic Quantization

[source,rust]
----
use proximadb::compute::quantization::unified::UnifiedQuantizationEngine;
use proximadb::compute::quantization::types::*;

// Create engine
let engine = UnifiedQuantizationEngine::new(
    distance_compute,
    codebook_store,
);

// Quantize to INT8
let (quantized_int8, min, max) = engine.quantize_to_u8(&vector)?;

// Quantize to Binary
let binary = engine.quantize_to_binary(&vector)?;

// Quantize to PQ8 (requires trained codebook)
let pq_codes = engine.quantize_to_pq(&vector, &codebook, 8)?;
----

=== Training and Using PQ

[source,rust]
----
// 1. Train codebook on sample data
let training_vectors: Vec<Vec<f32>> = load_training_data();
let codebook = engine.train_pq_codebook(
    &training_vectors,
    8,    // num_subvectors
    256,  // centroids per subvector
    20,   // max iterations
).await?;

// 2. Save codebook
codebook_store.save("my_collection_pq8", &codebook).await?;

// 3. Quantize vectors
for vector in &vectors {
    let pq_codes = engine.quantize_to_pq(vector, &codebook, 8)?;
    // Store pq_codes with vector
}

// 4. Search with PQ distance
let distances = engine.calculate_pq_distance(
    &query_vector,
    &pq_codes_batch,
    &codebook,
).await?;
----

== Integration with Storage Engines

=== VIPER Engine

**Columnar Quantization**:
* Each quantization level stored as separate Parquet column
* Column: `vector_binary`, `vector_int8`, `vector_pq8`
* Enables column pruning during queries

**Configuration**:
[source,toml]
----
[collection.my_collection]
storage_engine = "viper"
quantization.enabled = true
quantization.levels = ["int8", "pq8"]
quantization.store_columnar = true
----

=== SST/SWIFT/HELIX Engines

**Inline Quantization**:
* Quantized vectors stored alongside FP32 in ProximaBlocks
* Configurable encoding layout (TransposeFieldEncoded, GroupedFieldEncoded)
* Block-level quantization metadata

**Configuration**:
[source,toml]
----
[collection.my_collection]
storage_engine = "sst"
quantization.enabled = true
quantization.level = "int8"
quantization.inline_storage = true
----

=== NOVA Engine

**Progressive Columnar**:
* Multiple quantization levels for progressive search
* Automatic level selection based on query patterns
* Zone maps accelerate quantized search

== Best Practices

=== Training

✅ **DO**:
* Use 10K-100K representative samples
* Retrain periodically (weekly/monthly)
* Validate reconstruction error
* Test recall on holdout set

❌ **DON'T**:
* Train on biased samples
* Use too few samples (<1K)
* Skip validation
* Ignore convergence warnings

=== Production Deployment

✅ **DO**:
* Start with INT8 for balanced performance
* Monitor recall metrics
* Use cascade for large datasets
* Cache codebooks in memory

❌ **DON'T**:
* Use binary for final results
* Skip codebook persistence
* Ignore memory limits
* Over-quantize (PQ4 unless necessary)

=== Debugging

**Common Issues**:

1. **Low Recall**: Retrain codebook with more samples
2. **High Latency**: Check SIMD acceleration enabled
3. **Memory Issues**: Reduce quantization levels stored
4. **Cache Misses**: Increase cache size or persistence
