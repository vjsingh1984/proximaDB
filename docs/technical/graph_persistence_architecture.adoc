== FilesystemFactory Integration

The FilesystemFactory automatically selects the appropriate storage backend based on URL schemes:

[source,rust]
----
// Example: Creating a graph with automatic backend selection
pub async fn create_graph_with_persistence(
    graph_id: String,
    storage_url: String,  // e.g., "s3://bucket/graphs" or "file:///data"
) -> Result<GraphEngine> {
    // FilesystemFactory automatically detects and creates the right backend
    let filesystem = FilesystemFactory::get_filesystem(&storage_url)?;

    // Build graph-specific path
    let graph_path = format!("{}/graphs/{}/data",
                            storage_url.trim_end_matches('/'),
                            graph_id);

    // Initialize persistence layer
    let persistence = OrionPersistence::new(
        graph_id,
        graph_path,
        true  // Enable WAL
    ).await?;

    // Create engine with persistence
    OrionGraphEngine::with_persistence(persistence).await
}
----

== Write-Ahead Logging (WAL)

=== WAL Architecture

[source,mermaid]
----
%%{init: {"theme": "neutral"}}}%%
sequenceDiagram
    participant Client
    participant GraphEngine
    participant WAL
    participant Snapshot
    participant Storage

    Client->>GraphEngine: Graph Operation
    GraphEngine->>WAL: Write to WAL
    WAL->>Storage: Persist WAL entry
    Storage-->>WAL: Acknowledged
    WAL-->>GraphEngine: WAL written
    GraphEngine->>GraphEngine: Apply in-memory
    GraphEngine-->>Client: Operation complete

    Note over GraphEngine,Snapshot: Periodic snapshot
    GraphEngine->>Snapshot: Create snapshot
    Snapshot->>Storage: Save snapshot
    Storage-->>Snapshot: Saved
    Snapshot->>WAL: Truncate old WAL
----

=== Consistency Guarantees

**ACID Properties:**
* **Atomicity**: All operations in a transaction succeed or fail together
* **Consistency**: Graph invariants are maintained (no dangling edges)
* **Isolation**: Concurrent operations are serialized
* **Durability**: WAL ensures persistence before acknowledgment

**Consistency Levels:**
[cols="2,3,2"]
|===
|Level |Description |Performance Impact

|**Synchronous**
|WAL flush before acknowledgment
|Higher latency, maximum durability

|**Asynchronous**
|Batched WAL writes
|Lower latency, bounded data loss

|**Snapshot-Only**
|Periodic snapshots only
|Minimum latency, snapshot interval data loss
|===

=== Batch Operations

Optimize write throughput with batching:

[source,rust]
----
// Batch multiple graph operations for efficient persistence
pub async fn batch_graph_operations(
    engine: &GraphEngine,
    operations: Vec<GraphOperation>,
) -> Result<()> {
    // Group operations by type for optimization
    let mut node_creates = Vec::new();
    let mut edge_creates = Vec::new();

    for op in operations {
        match op {
            GraphOperation::CreateNode(node) => node_creates.push(node),
            GraphOperation::CreateEdge(edge) => edge_creates.push(edge),
            // ... other operations
        }
    }

    // Execute in optimal order
    engine.batch_create_nodes(node_creates).await?;
    engine.batch_create_edges(edge_creates).await?;

    // Single WAL flush for entire batch
    engine.flush_wal().await?;

    Ok(())
}

== Best Practices

=== Storage Layout

[TIP]
====
**Organize by Environment**: Separate production, staging, and development graphs

**Use Consistent Naming**: `{environment}/{application}/{graph_id}`

**Plan for Growth**: Design storage hierarchy for scalability

**Regular Maintenance**: Schedule snapshot cleanup and WAL rotation
====

=== Performance Tuning

**Snapshot Frequency:**
* High-write workloads: Every 15-30 minutes
* Read-heavy workloads: Every 1-4 hours
* Archive graphs: Daily or weekly

**Compression Selection:**
* Real-time queries: LZ4 or Snappy
* Balanced workloads: Zstd with level 3-6
* Long-term storage: Brotli or XZ

**Cache Configuration:**
* Working set should fit in L2 cache
* Monitor cache hit ratios (target >80%)
* Use SSD cache for overflow

=== Disaster Recovery

[IMPORTANT]
====
**RPO (Recovery Point Objective)**: Maximum data loss = WAL flush interval

**RTO (Recovery Time Objective)**: Recovery time = Snapshot load + WAL replay

**Backup Strategy**:
- Continuous WAL archival
- Regular snapshot backups
- Cross-region replication
- Test recovery procedures monthly
====

=== Cross-Graph Operations

[source,rust]
----
// Query across multiple graphs
pub async fn federated_graph_query(
    graphs: Vec<GraphEngine>,
    query: GraphQuery,
) -> Result<FederatedResults> {
    let mut results = FederatedResults::new();

    // Parallel query execution
    let futures = graphs.iter().map(|graph| {
        graph.execute_query(query.clone())
    });

    let graph_results = futures::future::join_all(futures).await;

    // Merge results with graph provenance
    for (graph_id, result) in graph_results {
        results.add_graph_result(graph_id, result?);
    }

    Ok(results)
}
