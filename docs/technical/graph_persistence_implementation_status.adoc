== Executive Summary

ProximaDB's graph persistence is being implemented following a unified architecture that reuses existing WAL and memtable infrastructure. This approach ensures consistency, reduces complexity, and enables atomic hybrid vector-graph transactions.

pub enum UnifiedWALOperation {
    /// Vector operation (existing)
    VectorOp(VectorOperation),

    /// Graph operation (new)
    GraphOp(GraphOperation),

    /// Hybrid operation combining both
    HybridOp {
        vector_ops: Vec<VectorOperation>,
        graph_ops: Vec<GraphOperation>,
        transaction_id: String,
    },

    /// Batch operation
    BatchOp {
        operations: Vec<UnifiedWALOperation>,
        batch_id: Option<String>,
    },

    /// Checkpoint for recovery
    Checkpoint {
        sequence_number: u64,
        timestamp: SystemTime,
        collections: Vec<String>,
        graphs: Vec<String>,
    },
}

=== Current Compilation Issues ⚠️

**API Migration Required:**
The GraphService API was partially migrated from singleton to multi-graph pattern:
- ✅ **Architecture**: Correct multi-graph engine registry
- ❌ **API Methods**: ~20 methods still reference non-existent `self.engine`
- ❌ **Method Signatures**: Need `graph_id` parameter added to all public methods

**Specific Issues:**
[source,bash]
----
// Current broken calls (examples)
self.engine.insert_node(node)           // engine field doesn't exist
self.engine.get_node(id)                // engine field doesn't exist

// Should be
let engine = self.get_or_create_graph_engine(graph_id)?;
engine.insert_node(node)
----

=== Migration Plan

**Phase 1: API Signature Updates**
All GraphService public methods need graph_id parameter:
```rust
// Old signature
pub fn create_node(&self, node: Node) -> Result<Arc<Node>>

// New signature
pub async fn create_node(&self, graph_id: &str, node: Node) -> Result<Arc<Node>>
```

**Phase 2: Method Implementation Updates**
Replace all `self.engine.method()` calls with:
```rust
let engine = self.get_or_create_graph_engine(graph_id).await?;
engine.method()
```

**Phase 3: Protocol Buffer API Updates**
Update gRPC/REST handlers to include graph_id in requests

== Performance Considerations

=== Memory Overhead

[cols="2,2,2"]
|===
|Component |Memory Usage |Notes

|**GraphMemtable**
|~100 bytes per node/edge
|Plus index overhead

|**CSR Structure**
|8 bytes × (nodes + edges)
|Compact representation

|**Indexes**
|Variable
|Depends on label/type cardinality
|===

=== Write Performance

- **WAL Write**: ~1-2ms per operation with fsync
- **Memtable Apply**: <0.1ms for most operations
- **CSR Update**: O(1) for edge insertion with incremental update

=== Recovery Time

- **Snapshot Load**: O(nodes + edges) - typically seconds for millions
- **WAL Replay**: ~1000 ops/second with verification
