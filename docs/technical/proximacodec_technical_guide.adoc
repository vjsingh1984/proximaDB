Comprehensive technical reference for ProximaCodec encoding schemes, implementation coverage, lossless guarantees, and hardware acceleration.

== Overview

ProximaCodec is ProximaDB's unified encoding/decoding framework with hardware-aware routing across Baseline (scalar), SIMD, and GPU implementations.

**Key Features**:

* 15 encoding schemes for different data patterns
* Hardware acceleration: AVX2/NEON (SIMD) and CUDA/Metal/ROCm/OpenCL (GPU)
* Automatic scheme selection based on pattern analysis
* Lossless guarantees for f32/f64 embeddings
* Wire format compatibility across all implementations

== Encoding Schemes Reference

=== Always Lossless Schemes (10)

These schemes guarantee perfect round-trip for all data types:

==== 1. Delta

**Description**: Stores differences from base value

[source,rust]
----
ProximaScheme::Delta { base: i64 }
----

**Lossless Guarantee**: Uses IEEE 754 bit pattern preservation (`to_bits()`/`from_bits()`)

**Example**:
[source,rust]
----
let original = 3.14159265359f32;
let base = 0;
let encoded = codec.encode(&[original], ProximaScheme::Delta { base })?;
let decoded: Vec<f32> = codec.decode(&encoded)?;
assert_eq!(original, decoded[0]); // ✅ Perfect recovery
----

**Best For**: Smooth sequences, monotonic data

**Compression**: 35-45%

==== 2. DoubleDelta

**Description**: Delta of deltas (second-order differences)

[source,rust]
----
ProximaScheme::DoubleDelta {
    first_value: i64,
    first_delta: i64,
}
----

**Lossless Guarantee**: Uses IEEE 754 bit pattern preservation

**Best For**: Linear sequences, time-series data

**Compression**: 50-60%

**Benchmark Evidence**: 52.7% compression on time-series, 34.0% on sinusoidal

==== 3. PForDoubleDelta

**Description**: Patched double delta for linear data with outliers

[source,rust]
----
ProximaScheme::PForDoubleDelta {
    base: i64,
    first_delta: i64,
}
----

**Lossless Guarantee**: Uses IEEE 754 bit pattern preservation, handles outliers without loss

**Best For**: Linear sequences with occasional spikes

**Compression**: 45-55%

==== 4. Simple8b

**Description**: Variable-length integer packing

[source,rust]
----
ProximaScheme::Simple8b
----

**Lossless Guarantee**: Stores full values in 64-bit words

**Best For**: Small integers (0-2^60)

**Compression**: 20-30%

**Warning**: Causes 66-133% expansion on normalized f32 embeddings!

==== 5. VByte

**Description**: Variable-byte encoding (LEB128)

[source,rust]
----
ProximaScheme::VByte
----

**Lossless Guarantee**: Stores full values with variable bytes

**Best For**: Variable-sized integers

**Compression**: 30-40%

==== 6. SparseBitmap

**Description**: Bitmap + non-zero values

[source,rust]
----
ProximaScheme::SparseBitmap
----

**Lossless Guarantee**: Stores complete index and value

**Best For**: 70-95% sparse data

**Compression**: 70-80%

==== 7. SparseCOO

**Description**: Coordinate format (index, value) pairs

[source,rust]
----
ProximaScheme::SparseCOO
----

**Lossless Guarantee**: Stores complete coordinates

**Best For**: >95% sparse data

**Compression**: 97.6% (benchmark evidence)

==== 8. Dictionary

**Description**: Value → integer code mapping

[source,rust]
----
ProximaScheme::Dictionary
----

**Lossless Guarantee**: Maintains complete dictionary

**Best For**: Low-cardinality data (clustered patterns)

**Compression**: 7-8%

==== 9. RunLength

**Description**: (value, count) pairs

[source,rust]
----
ProximaScheme::RunLength
----

**Lossless Guarantee**: Stores exact values and counts

**Best For**: Constant/repeated data

**Compression**: 99.6% (benchmark evidence)

==== 10. Raw

**Description**: Identity encoding (no transformation)

[source,rust]
----
ProximaScheme::Raw
----

**Lossless Guarantee**: Direct storage without transformation

**Best For**: Normalized ML embeddings ([-1, 1])

**Compression**: 0% (no expansion)

**Critical**: Only scheme that doesn't expand normalized f32 data!

=== Conditionally Lossy Schemes (4)

These schemes are lossy ONLY when `bits < type_size`:

==== 1. BitPacked

[source,rust]
----
ProximaScheme::BitPacked { bits: u8 }
----

**Lossy When**: `bits < 32` for f32, `bits < 64` for f64

**Example (LOSSY)**:
[source,rust]
----
// ❌ LOSSY: 8 bits for f32 (32 bits needed)
let scheme = ProximaScheme::BitPacked { bits: 8 };
let original = 3.14159265359f32;
let encoded = codec.encode(&[original], scheme)?;
let decoded: Vec<f32> = codec.decode(&encoded)?;
assert_ne!(original, decoded[0]); // Lost 24 bits!
----

**Example (LOSSLESS)**:
[source,rust]
----
// ✅ LOSSLESS: 32 bits for f32
let scheme = ProximaScheme::BitPacked { bits: 32 };
let original = 3.14159265359f32;
let encoded = codec.encode(&[original], scheme)?;
let decoded: Vec<f32> = codec.decode(&encoded)?;
assert_eq!(original, decoded[0]); // Perfect recovery
----

**Guidelines**:

* f32: Use `bits: 32`
* f64: Use `bits: 64`
* i32/u32: Use `bits: 32`
* i64/u64: Use `bits: 64`

==== 2. Zigzag

[source,rust]
----
ProximaScheme::Zigzag { bits: u8 }
----

**Lossy When**: `bits < type_size`

**Lossless Guarantee**: When `bits` matches type size

==== 3. FrameOfReference

[source,rust]
----
ProximaScheme::FrameOfReference {
    reference: i64,
    bits: u8,
}
----

**Lossy When**: `bits < type_size`

**Lossless Guarantee**: When `bits` matches type size

==== 4. PForDelta

[source,rust]
----
ProximaScheme::PForDelta {
    majority_bits: u8,
    base: i64,
}
----

**Lossy For**: f32 (stores deltas as integers)

**Lossless Alternative**: Use `PForDoubleDelta` which preserves IEEE 754 bit patterns

**Automatic Upgrade**: Analysis module upgrades PForDelta → PForDoubleDelta for f32

== Lossless Verification

=== Using is_lossy() Method

[source,rust]
----
use proximadb::storage::engines::core::ops::proximacodec::{ProximaScheme, TypeId};

let scheme = ProximaScheme::BitPacked { bits: 16 };

// Check if lossy for f32
if scheme.is_lossy(TypeId::F32) {
    println!("⚠ Lossy for f32! Use bits: 32");
}

// Check if lossy for i32
if scheme.is_lossy(TypeId::I32) {
    println!("⚠ Lossy for i32! Use bits: 32");
}
----

=== Automatic Upgrade Logic

The analysis module automatically upgrades lossy schemes to lossless variants:

[source,rust]
----
// In encoding strategy implementations
let detected_scheme = analysis::analyze_and_choose_scheme_f32(&values);

let scheme = if detected_scheme.is_lossy(TypeId::F32) {
    match &detected_scheme {
        ProximaScheme::PForDelta { .. } => {
            // Upgrade to lossless PForDoubleDelta
            if let Some(base) = values.first() {
                let base_bits = base.to_bits() as i64;
                let first_delta = if values.len() > 1 {
                    (values[1].to_bits() as i64) - base_bits
                } else { 0 };
                ProximaScheme::PForDoubleDelta { base: base_bits, first_delta }
            } else {
                ProximaScheme::Raw // Fallback to identity
            }
        },
        _ => ProximaScheme::Raw // Safe fallback
    }
} else {
    detected_scheme // Already lossless
};
----

== Architecture Quality

=== Strengths ✅

1. **Proper Abstraction**
   * SIMD uses intrinsics (not software emulation)
   * GPU uses real kernels (CUDA C, Metal shaders)
   * Baseline is pure scalar (no conditional compilation)

2. **Graceful Fallback**
   * GPU → SIMD → Baseline cascade
   * Automatic hardware detection
   * Transparent to caller

3. **Memory Pooling**
   * Zero-allocation hot paths
   * Pre-allocated GPU buffers
   * Configurable pool sizes

4. **Platform-Specific**
   * Proper conditional compilation
   * Feature gates for GPU backends
   * Runtime CPU feature detection

5. **Wire Compatibility**
   * All implementations produce identical bytes
   * Cross-implementation decoding works
   * Comprehensive compatibility tests

=== Improvement Opportunities ⚠

1. **Limited Coverage**
   * Only 40% SIMD implementation (6/15 schemes)
   * Only 33% GPU implementation (5/15 schemes)
   * Missing high-value schemes (simple8b, vbyte)

2. **DoubleDelta GPU Gap**
   * Has SIMD but no GPU
   * Important for time-series workloads
   * 52.7% compression on time-series data

3. **Missing SIMD Directories**
   * `simd/functions/{avx2,avx512,neon}/` exist but empty
   * Code currently in `simd.rs` (less organized)
   * Should migrate to structured directories

== Recommendations

=== Priority 1: Extend GPU to DoubleDelta

**Impact**: Enable GPU acceleration for time-series workloads

**Implementation**:
[source,cuda]
----
// CUDA kernel for DoubleDelta
__global__ void double_delta_encode_kernel(
    const float* input,
    int64_t* output,
    int64_t first_value,
    int64_t first_delta,
    int n
) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= n - 2) return;

    // Compute second-order differences on GPU
    int64_t v0 = __float_as_int(input[idx]);
    int64_t v1 = __float_as_int(input[idx + 1]);
    int64_t v2 = __float_as_int(input[idx + 2]);

    int64_t d1 = v1 - v0;
    int64_t d2 = v2 - v1;
    output[idx] = d2 - d1;
}
----

**Timeline**: 1-2 weeks

**Impact**: Accelerate common workloads (mixed ranges, small integers)

**SIMD Opportunity**:

**Timeline**: 2-3 weeks

== Best Practices

=== Scheme Selection for ML Embeddings

[discrete]
==== Normalized Embeddings ([-1, 1])

Use `Raw` encoding to avoid expansion:

[source,rust]
----
// ✅ CORRECT: No expansion
let scheme = ProximaScheme::Raw;
let encoded = codec.encode(&embeddings, scheme)?;
// Size: 4 bytes per f32 (same as uncompressed)
----

[discrete]
==== Avoid Integer-Based Schemes

[source,rust]
----
// ❌ WRONG: Causes 66-133% expansion!
let scheme = ProximaScheme::Simple8b;
let encoded = codec.encode(&normalized_embeddings, scheme)?;
// Size: 8+ bytes per f32 (expansion!)
----

=== Choosing Between Schemes

**Use the analysis module** for automatic selection:

[source,rust]
----
use proximadb::storage::engines::core::ops::proximacodec::analysis;

let values: Vec<f32> = /* your data */;
let scheme = analysis::analyze_and_choose_scheme_f32(&values);
let encoded = codec.encode(&values, scheme)?;
----

The analysis module considers:

* Sparsity (zero ratio)
* Linearity (second-order differences)
* Smoothness (delta variance)
* Jaggedness (random patterns)
* Value range (min/max/clustering)
* Data type (f32 embedding detection)

See `src/storage/engines/core/ops/proximacodec/analysis.rs:1-30` for benchmark evidence.

=== Testing Losslessness

[source,rust]
----
#[test]
fn test_lossless_roundtrip() {
    let codec = ProximaCodec::global();
    let original = vec![3.14159265359f32, 2.71828182846f32];

    // Test all lossless schemes
    for scheme in lossless_schemes() {
        let encoded = codec.encode(&original, scheme).unwrap();
        let decoded: Vec<f32> = codec.decode(&encoded).unwrap();

        for (i, (&orig, &dec)) in original.iter().zip(&decoded).enumerate() {
            assert_eq!(
                orig.to_bits(),
                dec.to_bits(),
                "Scheme {:?} lost data at index {}: {} != {}",
                scheme, i, orig, dec
            );
        }
    }
}
----

== Troubleshooting

=== Scheme Causes Data Loss

**Symptom**: Decoded values != original values

**Diagnosis**:
[source,rust]
----
if scheme.is_lossy(TypeId::F32) {
    println!("⚠ Scheme {:?} is lossy for f32!", scheme);
}
----

**Solution**: Use lossless variant or upgrade scheme

=== Expansion Instead of Compression

**Symptom**: Encoded size > original size

**Common Causes**:

1. **Normalized embeddings + Simple8b**: Use `Raw` instead
2. **High-entropy data + Delta**: Use `Raw` or `BitPacked`
3. **No external compression**: Enable Zstd/LZ4

**Solution**:
[source,rust]
----
// Check if data is normalized
let (min, max) = (values.iter().fold(f32::INFINITY, |a, &b| a.min(b)),
                  values.iter().fold(f32::NEG_INFINITY, |a, &b| a.max(b)));

if min >= -1.5 && max <= 1.5 {
    // Use Raw for normalized embeddings
    let scheme = ProximaScheme::Raw;
}
----

=== SIMD/GPU Not Used

**Verification**:
[source,bash]
----
RUST_LOG=debug cargo test --lib proximacodec -- --nocapture

# Should see:
# "Using AVX2 encoder for delta"
# or "Using NEON encoder for delta"
# or "Using GPU encoder for delta"
----

**Common Issues**:

* GPU feature not enabled: `cargo build --features gpu`
* SIMD not available: Automatic fallback to baseline
* Batch too small for GPU: Use SIMD instead (<10K values)
