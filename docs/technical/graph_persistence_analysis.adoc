== Gap Analysis

=== Critical Gaps

==== 1. Graph Operations Not in WAL

The existing WAL system (`src/storage/persistence/write_ahead_log/`) only handles `VectorRecord` operations. Graph operations (Node/Edge CRUD) are not represented.

**Current WAL Operations:**
[source,rust]
----
pub enum WALOperation {
    AddVector(VectorRecord),
    UpdateVector(VectorRecord),
    DeleteVector(String),
    // Missing: Graph operations
}
----

**Required Graph Operations:**
[source,rust]
----
pub enum GraphWALOperation {
    CreateNode(Node),
    UpdateNode(NodeId, NodeUpdate),
    DeleteNode(NodeId),
    CreateEdge(Edge),
    UpdateEdge(EdgeId, EdgeUpdate),
    DeleteEdge(EdgeId),
    BatchGraphOp(Vec<GraphWALOperation>),
}
----

==== 2. No Graph Memtable

The memtable system is designed for vectors. Graph data needs a different in-memory structure optimized for CSR format and graph traversals.

**Current:** `GlobalPartitionedMemtable` for vectors
**Needed:** `GraphMemtable` for graph operations

==== 3. Persistence Not Connected

The `OrionPersistence` module was created but:
- Not integrated with `OrionGraphEngine`
- Not using the existing WAL infrastructure
- Compilation errors due to missing error types

==== 4. Single Graph Assumption

The `GraphService` assumes a single graph instance. Multi-graph support is designed but not implemented.

== Reconciliation Strategy

=== Design Principles

[IMPORTANT]
====
**Key Decision**: Reuse existing WAL and memtable infrastructure rather than creating parallel systems.

**Rationale**:
1. WAL already handles durability, recovery, serialization
2. Memtable manager provides memory management
3. Unified approach reduces complexity
4. Enables hybrid vector-graph transactions
====

// src/storage/memtable/implementations/graph_memtable.rs
pub struct GraphMemtable {
    graph_id: String,

    // CSR format for fast traversal
    node_offsets: Vec<usize>,
    edge_targets: Vec<NodeId>,

    // Node and edge data
    nodes: DashMap<NodeId, Arc<Node>>,
    edges: DashMap<EdgeId, Arc<Edge>>,

    // Indexes for queries
    label_index: DashMap<String, HashSet<NodeId>>,
    edge_type_index: DashMap<String, HashSet<EdgeId>>,

    // Memory tracking
    memory_usage: AtomicUsize,
}

impl GraphMemtable {
    pub fn apply_operation(&self, op: GraphOperation) -> Result<()> {
        match op {
            GraphOperation::CreateNode { node, .. } => {
                self.insert_node(node)?;
                self.update_csr_structure()?;
            }
            GraphOperation::CreateEdge { edge, .. } => {
                self.insert_edge(edge)?;
                self.update_csr_structure()?;
            }
            // ... other operations
        }
        Ok(())
    }

    pub fn flush_to_storage(&self) -> Result<GraphSnapshot> {
        // Create CSR snapshot for persistence
        GraphSnapshot {
            graph_id: self.graph_id.clone(),
            nodes: self.nodes.iter().map(|e| e.value().clone()).collect(),
            edges: self.edges.iter().map(|e| e.value().clone()).collect(),
            csr_offsets: self.node_offsets.clone(),
            csr_targets: self.edge_targets.clone(),
        }
    }
}

=== Phase 4: Integrate with ORION Engine

==== Modified ORION Engine
[source,rust]
----
// src/graph/engines/orion/mod.rs
pub struct OrionGraphEngine {
    graph_id: String,
    storage: Arc<RwLock<CsrStorage>>,

    // Persistence components
    memtable: Arc<GraphMemtable>,
    wal_writer: Option<Arc<WALWriter>>,

    // Snapshot management
    snapshot_manager: Option<Arc<SnapshotManager>>,
    last_snapshot: Option<Instant>,
}

impl OrionGraphEngine {
    pub async fn with_persistence(
        graph_id: String,
        storage_url: String,
    ) -> Result<Self> {
        // Initialize WAL
        let wal_writer = WALWriter::new(&format!("{}/wal", storage_url))?;

        // Initialize or recover from snapshot
        let storage = Self::recover_or_init(&storage_url).await?;

        // Create memtable
        let memtable = Arc::new(GraphMemtable::new(graph_id.clone()));

        Ok(Self {
            graph_id,
            storage,
            memtable,
            wal_writer: Some(Arc::new(wal_writer)),
            snapshot_manager: Some(Arc::new(SnapshotManager::new(storage_url))),
            last_snapshot: Some(Instant::now()),
        })
    }

    pub async fn create_node(&self, node: Node) -> Result<NodeId> {
        // Write to WAL first
        if let Some(wal) = &self.wal_writer {
            wal.append(UnifiedWALOperation::GraphOp(
                GraphOperation::CreateNode {
                    graph_id: self.graph_id.clone(),
                    node: node.clone(),
                }
            )).await?;
        }

        // Apply to memtable
        self.memtable.apply_operation(
            GraphOperation::CreateNode {
                graph_id: self.graph_id.clone(),
                node: node.clone(),
            }
        )?;

        // Apply to in-memory storage
        let mut storage = self.storage.write().await;
        storage.insert_node(node.clone())?;

        // Check if snapshot needed
        self.maybe_snapshot().await?;

        Ok(node.id)
    }
}

=== Phase 5: Multi-Graph Support

==== Enhanced GraphService
[source,rust]
----
// src/graph/service.rs
pub struct GraphService {
    // Graph registry
    graphs: Arc<DashMap<String, Arc<OrionGraphEngine>>>,

    // Configuration
    default_storage_url: String,

    // Metrics
    metrics: Arc<dyn MetricsUpdater>,
}

impl GraphService {
    pub async fn create_graph(
        &self,
        graph_id: String,
        storage_url: Option<String>,
    ) -> Result<()> {
        let url = storage_url.unwrap_or_else(||
            format!("{}/graphs/{}/data", self.default_storage_url, graph_id)
        );

        let engine = OrionGraphEngine::with_persistence(
            graph_id.clone(),
            url
        ).await?;

        self.graphs.insert(graph_id, Arc::new(engine));
        Ok(())
    }

    pub async fn get_or_create_graph(&self, graph_id: &str) -> Result<Arc<OrionGraphEngine>> {
        if let Some(engine) = self.graphs.get(graph_id) {
            return Ok(engine.clone());
        }

        self.create_graph(graph_id.to_string(), None).await?;
        Ok(self.graphs.get(graph_id).unwrap().clone())
    }

    pub async fn create_node(&self, graph_id: &str, node: Node) -> Result<NodeId> {
        let engine = self.get_or_create_graph(graph_id).await?;
        engine.create_node(node).await
    }
}

== Rationale for Design Decisions

=== Why Reuse Existing WAL?

[cols="2,3"]
|===
|Reason |Explanation

|**Proven Reliability**
|WAL system already handles crash recovery, fsync, serialization

|**Unified Transactions**
|Enables atomic vector + graph operations in hybrid mode

|**Code Reuse**
|Avoids duplicating complex durability logic

|**Operational Simplicity**
|Single WAL to monitor, backup, and manage
|===

=== Why Separate Graph Memtable?

[cols="2,3"]
|===
|Reason |Explanation

|**Different Access Patterns**
|Graphs need CSR format for traversal, vectors need arrays

|**Specialized Indexes**
|Label and edge-type indexes specific to graphs

|**Memory Optimization**
|CSR is more memory-efficient for sparse graphs

|**Query Performance**
|Dedicated structure optimizes graph algorithms
|===

=== Why Multi-Graph Architecture?

[cols="2,3"]
|===
|Reason |Explanation

|**Isolation**
|Different applications/tenants get separate graphs

|**Scalability**
|Can shard graphs across nodes in future

|**Flexibility**
|Different graphs can use different engines (ORION/PULSAR/QUASAR)

|**Consistency with Vectors**
|Mirrors collection model for vectors
|===

== Conclusion

The graph persistence architecture should leverage existing ProximaDB infrastructure:

1. **Extend WAL** to handle graph operations alongside vector operations
2. **Create GraphMemtable** optimized for CSR format and graph queries
3. **Integrate with ORION** by adding persistence hooks to the engine
4. **Enable Multi-Graph** support in GraphService with graph_id routing
5. **Maintain Compatibility** with existing REST/gRPC APIs

This approach ensures:
- **Consistency**: Single durability mechanism for all data
- **Efficiency**: Reuse proven components
- **Flexibility**: Support multiple concurrent graphs
- **Reliability**: Leverage existing recovery mechanisms

The existing GraphService and APIs will continue to work, with persistence added transparently behind the scenes.
