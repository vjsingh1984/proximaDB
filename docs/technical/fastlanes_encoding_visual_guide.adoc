FastLanes provides three vector encoding strategies, each optimized for different access patterns and data characteristics, with advanced field-level compression for maximum efficiency.

== Block-Level Structure

=== Core Block Format

[source,text]
----
┌─────────────────────────────────── FASTLANES BLOCK ──────────────────────────────────┐
│                                                                                       │
│  ┌──────────────────────────── HEADER (10 bytes) ─────────────────────────────┐      │
│  │ [0x01] Format Version (1 byte)                                             │      │
│  │ [0xXX] Encoding Marker (1 byte) - Determines encoding scheme               │      │
│  │ [u32]  Record Count (4 bytes) - Number of vectors                          │      │
│  │ [u32]  Dimension (4 bytes) - Vector dimension                              │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
│  ┌──────────────────────── VECTOR DATA (Variable) ────────────────────────────┐      │
│  │ Strategy-specific encoding (see detailed sections below)                   │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
│  ┌────────────────────── ID DICTIONARY (Variable) ────────────────────────────┐      │
│  │ [u32] Dictionary Size                                                      │      │
│  │ For each unique ID:                                                        │      │
│  │   [u32] ID Length                                                          │      │
│  │   [bytes] ID String                                                        │      │
│  │ [u32] Encoded Indices Length                                               │      │
│  │ [bytes] Delta-encoded ID indices                                           │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
│  ┌───────────────── SPARSE METADATA COLUMNS (Variable) ───────────────────────┐      │
│  │ [u32] Number of Metadata Keys                                              │      │
│  │ For each key:                                                              │      │
│  │   [u32] Key Name Length                                                    │      │
│  │   [bytes] Key Name                                                         │      │
│  │   [u32] Presence Bitmap Length                                             │      │
│  │   [bytes] Bitmap (1 bit per record)                                        │      │
│  │   [u32] Compressed Values Length                                           │      │
│  │   [bytes] Compressed Values                                                │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
│  ┌─────────────────────── TIMESTAMPS (Variable) ──────────────────────────────┐      │
│  │ [u32] Timestamp Data Length                                                │      │
│  │ [bytes] Delta-encoded timestamps                                           │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
│  ┌────────────────── BLOCK METADATA (Variable) ───────────────────────────────┐      │
│  │ [u32] Metadata Length                                                      │      │
│  │ [bytes] Bincode-serialized FastLanesBlockMetadata                          │      │
│  └─────────────────────────────────────────────────────────────────────────────┘      │
│                                                                                       │
└───────────────────────────────────────────────────────────────────────────────────────┘
----

== Vector Encoding Strategies

=== FullVector Strategy (Row-wise Storage)

[TIP]
====
**Best For**: Sequential access of complete vectors, real-time queries, low-dimensional data (≤128D).

**Key Advantage**: Zero reconstruction overhead - vectors stored contiguously in memory.
====

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%

    subgraph "FullVector Layout"

        B[FastLanes Delta Encoding<br/>First vector raw: [1.1, 1.2, 1.3, 1.4]<br/>Deltas: Δ[1.0, 1.0, 1.0, 1.0]<br/>Deltas: Δ[1.0, 1.0, 1.0, 1.0]]
        C[Field Compression<br/>Zstd/LZ4 applied<br/>to encoded vectors]
    end

    A --> B
    B --> C

[horizontal]
**Advantages**:: Excellent compression ratios (1.43x with Zstd, 1.25x with LZ4)
**Performance**:: Sequential access optimized for complete vectors
**Encoding**:: FastLanes delta encoding eliminates redundancy
**Flexibility**:: Field-level compression allows per-field optimization

=== TransposeVector Strategy (Columnar Storage)

[TIP]
====
**Best For**: Dimension-wise operations, analytical workloads, SIMD processing, partial dimension loading.

**Key Advantage**: Each dimension compressed independently for optimal efficiency.
====

----

    Transpose->>Compress: D0:[1.1,2.1,3.1]<br/>D1:[1.2,2.2,3.2]<br/>D2:[1.3,2.3,3.3]<br/>D3:[1.4,2.4,3.4]
    Compress->>Storage: Each dimension<br/>compressed independently<br/>FastLanes + Zstd/LZ4
----

**Best For**: High-dimensional vectors (>128D), cache efficiency, memory bandwidth optimization.

=== Compression Configuration

[horizontal]
**Configurable Metadata Compression**:: `metadata_algorithm` field in `BlockCompressionConfig`
**Smart Fallback**:: Uses main algorithm if metadata algorithm not specified
**No Hardcoded Algorithms**:: Eliminates hardcoded Zstd for metadata
**Performance First**:: Layouts optimized for both compression ratio and decode speed

== Implementation Recommendations

=== Automatic Strategy Selection

[source,rust]
----
fn select_encoding_strategy(dimension: usize, access_pattern: AccessPattern) -> EncodingStrategy {
    match (dimension, access_pattern) {
        (d, _) if d <= 64 => EncodingStrategy::FullVector,
        (d, AccessPattern::Sequential) if d <= 128 => EncodingStrategy::FullVector,
        (d, AccessPattern::Analytical) if d <= 128 => EncodingStrategy::TransposeVector,
        (d, _) if d > 1024 => EncodingStrategy::GroupedVector,
        (d, AccessPattern::Analytical) if d > 512 => EncodingStrategy::TransposeVector,
        _ => EncodingStrategy::GroupedVector,
    }
}

== Conclusion

FastLanes block encoding provides three complementary strategies optimized for different use cases:

[horizontal]
**FullVector**:: Optimal for low-dimensional data and sequential access patterns
**TransposeVector**:: Perfect for analytical workloads requiring dimension-wise operations
**GroupedVector**:: Best overall performance for high-dimensional vectors with cache optimization

The field-level compression architecture ensures maximum efficiency while maintaining flexibility for diverse workload requirements.
