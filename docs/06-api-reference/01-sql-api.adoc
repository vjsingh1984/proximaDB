== Overview

SQL endpoints provide a SQL-first interface over REST, plus EXPLAIN for orchestration plans and vector/graph hints.

Base URL: `http://localhost:5678`

== Execute

- REST: `POST /api/v1/sql/execute`

Seeding strategy controls for hybrid graph→vector:

- SQL hint (inline): `-- SEEDING: AVERAGE | PER_SEED | NONE` (or `SEED USING AVERAGE`)
- REST body field: `"seeding": "average" | "per_seed" | "none"`

Request
----
{
  "query": "-- SEEDING: PER_SEED\nSELECT id FROM my_collection ORDER BY COSINE_DISTANCE(vector, $1) LIMIT 5",
  "parameters": [[0.1,0.2,0.3, ...]],
  "collection": "my_collection",
  "seeding": "per_seed"
}
----

Response (truncated)
----
{
  "success": true,
  "data": {
    "rows": [ { "id": "vec_1", "score": 0.92, ... }, ... ],
    "row_count": 5
  },
  "error": null
}
----

== EXPLAIN

- REST: `POST /api/v1/sql/explain`

Request
----
{
  "query": "SELECT * FROM my_collection ORDER BY COSINE_DISTANCE(vector, $1) LIMIT 10",
  "analyze": false
}
----

Response (fields abridged)
----
{
  "success": true,
  "data": {
    "plan": {
      "orchestration_steps": ["Parse", "Orchestrate", ...],
      "vector_hints": { "pruned_files": 12, "ef_search": 64, ... },
      "graph_hints": { "traversal_algorithm": "BFS", ... }
    },
    "request_id": "..."
  }
}
----

== Graph Constructs in SQL

SQL can express graph operations using functions/clauses that the SqlService lowers to GraphService calls internally. Examples:

- FOLLOW/TRAVERSE semantics (illustrative):
----
SELECT id
FROM FOLLOW(start => 'user_123', rel => 'FOLLOWS', depth => 2)
WHERE label = 'User';
----

- Hybrid vector + graph (illustrative):
----
SELECT n.id
FROM SIMILAR(table => 'docs', vec => $1, top_k => 10) AS s
JOIN FOLLOW(start => s.id, rel => 'CITES', depth => 1) AS n
WHERE n.label = 'Paper'
LIMIT 20;
----

Note: The above are examples of SQL surface syntax; actual lowering uses the existing planner to call GraphService and VectorService as needed.
