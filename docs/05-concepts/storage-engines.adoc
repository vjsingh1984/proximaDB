== Use Case Recommendations

=== Real-Time Applications

**Recommended: SST Engine**

Best for:

* Chat applications with embedding-based search
* Real-time recommendation systems
* Streaming data ingestion (IoT, logs)
* High-concurrency workloads

[source,python]
----
from proximadb_sdk import ProximaDBClient

client = ProximaDBClient("http://localhost:5678")

# SST is the default engine for write-heavy workloads
client.create_collection(
    name="chat_embeddings",
    dimension=1536,
    engine="sst",
    engine_config={
        "compression": "lz4",  # Fast compression for real-time
        "flush_threshold_mb": 64,
        "bloom_filter_fpp": 0.01
    }
)
----

=== Semantic Search Applications

**Recommended: HELIX Engine**

Best for:

* Document similarity search
* Image/video embedding search
* Knowledge base retrieval
* RAG (Retrieval Augmented Generation)

[source,python]
----
client.create_collection(
    name="knowledge_base",
    dimension=768,
    engine="helix",
    engine_config={
        "pca_dimensions": 64,  # Reduce dimensions for faster search
        "hilbert_bits": 16,    # Locality-preserving encoding
        "cluster_size": 256    # Vectors per cluster
    }
)
----

=== Analytics and Batch Processing

**Recommended: VIPER Engine**

Best for:

* Data warehouse integration
* Parquet file ingestion
* Large-scale batch analytics
* Columnar query patterns

[source,python]
----
client.create_collection(
    name="analytics_vectors",
    dimension=512,
    engine="viper",
    engine_config={
        "compression": "zstd",  # High compression ratio
        "row_group_size": 100000,
        "enable_statistics": True
    }
)
----

=== Small Dataset, Maximum Speed

**Recommended: SWIFT Engine**

Best for:

* Prototyping and development
* Small reference datasets (<10K vectors)
* Exact nearest neighbor (no approximation)
* Multi-tenant with isolated small collections

[source,python]
----
client.create_collection(
    name="product_catalog",
    dimension=384,
    engine="swift",
    engine_config={
        "in_memory": True,
        "exact_search": True
    }
)
----

=== Dynamic/Evolving Workloads

**Recommended: RAPTOR Engine**

Best for:

* A/B testing with changing data patterns
* Adaptive caching based on access patterns
* Workloads with unpredictable query distribution

[source,python]
----
client.create_collection(
    name="adaptive_embeddings",
    dimension=768,
    engine="raptor",
    engine_config={
        "adaptive_pruning": True,
        "cache_hot_blocks": True
    }
)
----

== Engine Configuration Reference

=== SST Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `compression`
| string
| Compression algorithm: `none`, `lz4`, `zstd`, `snappy`
| `lz4`

| `flush_threshold_mb`
| int
| MemTable size before flush to disk
| 64

| `bloom_filter_fpp`
| float
| Bloom filter false positive probability
| 0.01

| `block_size`
| int
| SSTable block size in bytes
| 65536

| `compaction_style`
| string
| `leveled` or `tiered`
| `leveled`
|===

=== HELIX Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `pca_dimensions`
| int
| Target dimensions after PCA (0 = disable)
| 64

| `hilbert_bits`
| int
| Hilbert curve precision (higher = more locality)
| 16

| `cluster_size`
| int
| Vectors per locality cluster
| 256

| `enable_quantization`
| bool
| Enable PQ quantization for memory reduction
| false
|===

=== VIPER Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `compression`
| string
| `zstd`, `lz4`, `snappy`, `gzip`
| `zstd`

| `row_group_size`
| int
| Parquet row group size
| 100000

| `enable_statistics`
| bool
| Column statistics for predicate pushdown
| true

| `parquet_version`
| string
| `1.0` or `2.0`
| `2.0`
|===

=== SWIFT Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `in_memory`
| bool
| Keep all data in memory
| true

| `exact_search`
| bool
| Disable approximate search (brute force)
| true

| `superblock_size`
| int
| Vectors per superblock
| 1024
|===

=== NOVA Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `zone_map_granularity`
| int
| Rows per zone map entry
| 1000

| `progressive_search`
| bool
| Enable progressive refinement
| true

| `cache_size_mb`
| int
| Block cache size
| 128
|===

=== RAPTOR Engine Options

[cols="2,1,3,2", options="header"]
|===
| Option | Type | Description | Default

| `adaptive_pruning`
| bool
| Enable adaptive block pruning
| true

| `cache_hot_blocks`
| bool
| Cache frequently accessed blocks
| true

| `rebalance_threshold`
| float
| Trigger rebalancing at this skew ratio
| 0.3
|===

== Changing Engines

=== Migration Strategy

Engines cannot be changed in-place. To migrate:

1. Create a new collection with the target engine
2. Export vectors from the source collection
3. Import vectors to the target collection
4. Update application to use the new collection
5. Delete the old collection

[source,python]
----
# Export from SST collection
vectors = client.get_all_vectors("old_collection")

# Create new HELIX collection
client.create_collection("new_collection", dimension=768, engine="helix")

# Import through the canonical record API
client.insert_records("new_collection", vectors)

# Verify and switch
assert client.get_collection_stats("new_collection")["vector_count"] == len(vectors)
----
