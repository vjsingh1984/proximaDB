== 🔑 Key Features

=== Storage Architecture
ProximaDB uses **magic bytes** for automatic format detection:

[cols="1,1,2", options="header"]
|===
| Engine | Magic Bytes | Purpose

| **SST Engine**
| `SST1` (header)
| Row-based storage for OLTP workloads

| **VIPER Engine**
| `PAR1` (footer)
| Columnar storage for analytics
|===

=== Performance Metrics
[cols="2,1,1", options="header"]
|===
| Operation | Performance | vs Competition

| **Bulk Insert**
| 17,484 vec/s
| 3x faster

| **Search Latency**
| 0.9ms (p99)
| 65% lower

| **Storage**
| 50-80% reduction
| Best in class
|===

=== Compression Options
**SDK-Driven** - No server defaults, full client control:

* **Algorithms**: ZSTD (2-10x), LZ4 (1.5-3x), Snappy (1.5-2x)
* **Adaptive**: Automatic selection based on data characteristics
* **Cache**: LRU decompression cache with auto-invalidation
