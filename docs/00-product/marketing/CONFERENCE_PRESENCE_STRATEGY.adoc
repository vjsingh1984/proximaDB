== Talk Proposals

### Proposal #1: "Building a Production-Grade Vector Database from Scratch"

**Target Conferences**: Strange Loop, MLConf, VDB
**Length**: 40 minutes
**Level**: Advanced
**Speaker**: CTO or Lead Engineer

**Abstract**:
----
Vector databases are the backbone of modern AI applications, powering everything from semantic search to recommendation systems. But what does it take to build one that scales to billions of vectors while maintaining sub-100ms query latency?

In this talk, we'll dive deep into the architecture of ProximaDB, an open-source vector database built from scratch in Rust. We'll explore:

* **Storage Engines**: How we combined LSM-trees (SST), Columnar stores (HELIX), and hybrid approaches (VIPER) to optimize for different workloads
* **Query Optimization**: Our cost-based query planner with runtime statistics feedback and adaptive indexing
* **Multi-Model Architecture**: Native graph database integration with vector search for knowledge graphs and entity resolution
* **Performance at Scale**: How we achieve 99.9% availability with sub-100ms p95 latency across 6 storage engines

Attendees will walk away with a deep understanding of vector database internals, practical lessons from building distributed systems in Rust, and insights into the future of AI infrastructure.

**Takeaways**:
- Architecture patterns for building scalable vector databases
- Real-world performance optimization techniques
- Lessons learned from 190+ commits of production code
- How to evaluate and choose the right vector database for your use case
----

**Technical Depth**: High (code examples, architecture diagrams)
**Demo**: Yes (live query performance comparison)

### Proposal #3: "Graph Meets Vectors: The Future of Knowledge Graphs"

**Target Conferences**: VDB, Strange Loop, Graph Connect
**Length**: 40 minutes
**Level**: Advanced
**Speaker**: Graph Database Lead

**Abstract**:
----
Vector databases excel at similarity search, while graph databases shine at traversing relationships. But what if you could combine both?

Enter ProximaDB's native integration of graph operations with vector search, enabling powerful queries like:

* "Find entities similar to this one, connected to these nodes, within 3 hops"
* "Traverse the knowledge graph and rank results by semantic similarity"
* "Perform entity resolution using both structural and semantic features"

In this talk, we'll introduce our novel approach to hybrid graph-vector queries:

* **Unified Query Engine**: Single query engine optimizing both graph and vector operations
* **Native Graph Storage**: CSR-based graph storage with WAL for durability
* **Adaptive Indexing**: Automatic selection between HNSW, IVF, and exact search
* **Real-World Use Cases**: Fraud detection, recommendation engines, knowledge graph completion

We'll demonstrate how hybrid graph-vector queries enable new classes of applications impossible with either technology alone.

**Takeaways**:
- Understand the limitations of pure vector or pure graph approaches
- Learn hybrid query patterns for graph-vector workloads
- See real-world applications in fraud, recommendations, and knowledge graphs
- Get hands-on with ProximaDB's unified query interface

**Technical Depth**: High (graph theory + vector math)
**Demo**: Yes (fraud detection example)

**Demo Scenarios**:

**Scenario 1: Semantic Document Search (5 min)**
```python
from proximadb_sdk import connect
client = connect("http://localhost:5678")

# Load Wikipedia articles
collection = client.create_collection("wiki", dimension=768)

# Insert with BERT embeddings
for article in wikipedia_articles:
    embedding = bert_model.encode(article['text'])
    client.insert_vectors("wiki", [{
        "id": article['id'],
        "vector": embedding.tolist(),
        "metadata": {"title": article['title'], "category": article['category']}
    }])

# Semantic search
query = "machine learning algorithms for image classification"
query_emb = bert_model.encode(query)
results = client.search("wiki", vector=query_emb.tolist(), top_k=5)

# Live demo: Search for different queries, show semantic understanding
```

**Scenario 2: Graph + Vector Hybrid (5 min)**
```python
# Create knowledge graph
client.create_graph("company_kg")

# Add entities and relationships
client.add_entities([
    {"id": "acme_corp", "type": "Company", "vector": company_emb},
    {"id": "john_doe", "type": "Person", "vector": person_emb}
])

client.add_edges([
    {"source": "john_doe", "target": "acme_corp", "type": "WORKS_AT"}
])

# Hybrid query: Find similar entities connected to Acme Corp
results = client.hybrid_search(
    collection="company_kg",
    vector=query_emb,
    graph_query="MATCH (e)-[:WORKS_AT]->(c:Company {id: 'acme_corp'})"
)
```

**Scenario 3: Performance Comparison (3 min)**
```python
import time

# Benchmark: 1M vectors, 1536 dimensions
start = time.time()
results = client.search("large_collection", vector=query, top_k=100)
latency = (time.time() - start) * 1000

print(f"Query latency: {latency:.2f}ms")
print(f"Throughput: {1_000_000 / latency:.0f} queries/second")

# Live demo: Show sub-100ms p95 latency
```
