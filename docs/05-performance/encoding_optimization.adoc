== Problem Statement

=== Original Issues

**Issue 1: Hardcoded Lossy Blocklists**

Encoding strategies used hardcoded scheme blocklists that blocked *lossless* schemes:

* `Simple8b` - Actually lossless for integers
* `RunLength` - Actually lossless
* `VByte` - Actually lossless for integers
* `Zigzag` - Can be lossless with proper bits
* `PForDelta` - Should upgrade to `PForDoubleDelta` (lossless for f32)

**Impact**: Forced unnecessary fallback to Delta encoding, reducing compression by 50-60%.

**Issue 2: Sample-Based Analysis**

TransposeBlockCompressed and GroupedField used tiny samples:

* TransposeBlock: 100 vectors × 50 dims = 5,000 floats (0.4-0.8% coverage)
* GroupedField: 10 vectors × 32 dims = 320 floats (0.04% coverage)

**Impact**: Inaccurate scheme selection, missed optimal compression opportunities.

**Issue 3: Sequential Processing**

All dimensions analyzed sequentially:

* 768 dimensions processed one by one
* No parallelization despite independent analysis
* Significant CPU underutilization

**Impact**: 5x slower than necessary on multi-core systems.

== Solutions Implemented

=== Fix 1: Dynamic Lossy Detection

**Files Modified**:

* `src/storage/engines/core/formats/proximablocks/block_structures.rs:2913-2936` (TransposeFieldEncoded)
* `src/storage/engines/core/formats/proximablocks/block_structures.rs:2805-2826` (TransposeBlockCompressed)
* `src/storage/engines/core/formats/proximablocks/block_structures.rs:2600-2621` (GroupedFieldEncoded)
* `src/storage/engines/core/formats/proximablocks/block_structures.rs:2685-2706` (GroupedBlockCompressed)

[source,rust]
----
// BEFORE (hardcoded blocklist)
let scheme = match &detected_scheme {
    ProximaScheme::Simple8b | ProximaScheme::RunLength |
    ProximaScheme::VByte | ProximaScheme::Zigzag { .. } |
    ProximaScheme::PForDelta { .. } => {
        ProximaScheme::Delta { base: 0 }  // Fallback
    },
    _ => detected_scheme.clone(),
};

// AFTER (dynamic is_lossy() method)
use crate::storage::engines::core::ops::proximacodec::TypeId;

let scheme = if detected_scheme.is_lossy(TypeId::F32) {
    match &detected_scheme {
        CodecScheme::PForDelta { .. } => {
            // Upgrade to PForDoubleDelta (lossless)
            if let Some(base) = dimension_values.first() {
                let base_bits = base.to_bits() as i64;
                let first_delta = if dimension_values.len() > 1 {
                    (dimension_values[1].to_bits() as i64) - base_bits
                } else { 0 };
                CodecScheme::PForDoubleDelta { base: base_bits, first_delta }
            } else {
                CodecScheme::Delta { base: 0 }
            }
        },
        _ => CodecScheme::Delta { base: 0 }
    }
} else {
    detected_scheme.clone()  // Use lossless scheme as-is
};
----

/// SIMD-accelerated min/max detection for f32 slices
pub fn simd_min_max_f32(data: &[f32]) -> (f32, f32) {
    #[cfg(target_arch = "x86_64")]
    {
        if is_x86_feature_detected!("avx2") {
            unsafe { simd_min_max_f32_avx2(data) }
        } else {
            scalar_min_max_f32(data)
        }
    }

    #[cfg(target_arch = "aarch64")]
    {
        if std::arch::is_aarch64_feature_detected!("neon") {
            unsafe { simd_min_max_f32_neon(data) }
        } else {
            scalar_min_max_f32(data)
        }
    }

    #[cfg(not(any(target_arch = "x86_64", target_arch = "aarch64")))]
    {
        scalar_min_max_f32(data)
    }
}

== Best Practices

=== Encoding Strategy Selection

[discrete]
==== Use TransposeFieldEncoded When

* Real-time encoding performance critical
* Each dimension has unique patterns
* Parallel encoding + parallel analysis desired

[discrete]
==== Use TransposeBlockCompressed When

* Block-level compression important
* Sequential encoding order required
* Slightly slower encoding acceptable

[discrete]
==== Use GroupedFieldEncoded When

* 32D groups have similar patterns
* Moderate compression needed
* Good balance of speed and size

[discrete]
==== Use GroupedBlockCompressed When

* Maximum compression desired
* Encoding speed less critical
* Block-level compression beneficial

=== Fallback Behavior

All SIMD functions automatically fall back to scalar implementations:

* No SIMD available: Uses optimized scalar code
* Partial SIMD: Uses SIMD for bulk, scalar for remainder
* Runtime detection: No compile-time flags required

== Troubleshooting

=== Encoding Slower After Update

**Symptom**: Encoding takes 10-12x longer than before

**Cause**: Full analysis (100% coverage) instead of tiny sample (0.04-0.8%)

**Resolution**: This is expected and correct:

* Before: Fast but inaccurate (wrong schemes selected)
* After: Slower but optimal (2-3x better compression)
* Trade-off: 10-12x slower encoding for 2-3x better compression

=== Size "Expansion" with None Compression

**Symptom**: "Compression" shows -37.6% (expansion)

**Cause**: ProximaCodec metadata overhead without external compression

**Resolution**: Use external compression (Zstd, LZ4):

[source,rust]
----
// Enable external compression
let strategy = EncodingStrategy::TransposeBlockCompressed {
    compression: CompressionType::Zstd(3),  // Level 3
};
----

=== SIMD Not Detected

**Symptom**: Performance not improved despite SIMD support

**Verification**:

[source,bash]
----
# Check CPU features (Linux)
cat /proc/cpuinfo | grep flags

# Check CPU features (macOS)
sysctl -a | grep cpu.features
----

**Resolution**: SIMD detection is automatic - if unavailable, scalar fallback is used.
