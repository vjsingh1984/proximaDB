== Executive Summary

**CRITICAL ISSUE IDENTIFIED**: TransposeFieldEncoded and TransposeBlockCompressed strategies have the same fundamental flaw as GroupedField strategies - they use different encoding analysis approaches, resulting in inconsistent compression ratios even with "None" compression.

**Impact**:
- 768D: TransposeField 2.76MB vs TransposeBlock 2.55MB (8% size difference)
- 1536D: TransposeField 5.57MB vs TransposeBlock 6.04MB (8% size difference, REVERSED!)
- Makes "None" compression benchmarks unreliable
- Confuses users about which strategy actually compresses better

=== Root Cause: Different Analysis Strategies

==== TransposeFieldEncoded Approach

Location: `src/storage/engines/core/formats/proximablocks/block_structures.rs:2869-2940`

[source,rust]
----
// ===== PER-DIMENSION FIELD COMPRESSION =====
// Transpose RxD → DxR: each dimension becomes a separate field
for dim_idx in 0..dimension {
    // Extract all values for this dimension across all vectors
    let mut dimension_values = Vec::with_capacity(vectors.len());
    for vector in vectors {
        dimension_values.push(vector[dim_idx]);
    }

    // ANALYZE EACH DIMENSION SEPARATELY
    let detected_scheme = analysis::analyze_and_choose_scheme_f32(&dimension_values);

    // Override lossy/problematic schemes
    let scheme = match &detected_scheme {
        ProximaScheme::Simple8b | ProximaScheme::RunLength |
        ProximaScheme::VByte | ProximaScheme::Zigzag { .. } |
        ProximaScheme::PForDelta { .. } => {
            ProximaScheme::Delta { base: 0 }  // Fallback
        },
        _ => detected_scheme.clone(),
    };

    let encoded_dimension = codec.encode(&dimension_values, scheme)?;
    // ... write encoded data
}
----

**Analysis Coverage**:
- **768D**: 768 separate analyses, each analyzing 1024 values
- **1536D**: 1536 separate analyses, each analyzing 1024 values
- **Total analyses**: Equal to dimension count
- **Pattern detection**: Per-dimension optimal encoding

**Analysis Coverage**:
- **768D**: 1 analysis of 100 vectors × 50 dims = 5,000 floats (0.8% of data)
- **1536D**: 1 analysis of 100 vectors × 50 dims = 5,000 floats (0.4% of data)
- **Total analyses**: 1 (same scheme for all dimensions)
- **Pattern detection**: Global average encoding

=== Why This Causes Size Differences

==== Scenario 1: 768 Dimensions

**TransposeFieldEncoded**:
- Analyzes each dimension separately (768 analyses)
- Dimension 0: Detects DoubleDelta pattern → uses DoubleDelta (50-60% compression)
- Dimension 1: Detects FrameOfReference → uses FOR (40-45% compression)
- Dimension 2: Detects SparseBitmap → uses SparseBitmap (70% compression)
- ... 765 more dimension-specific schemes
- **Result**: Optimal encoding per dimension, better overall compression

**TransposeBlockCompressed**:
- Analyzes sample of 5,000 floats ONCE
- Sample detects "average" pattern (e.g., Delta)
- ALL 768 dimensions forced to use Delta encoding
- Dimension 0: Delta instead of DoubleDelta (worse compression)
- Dimension 1: Delta instead of FOR (worse compression)
- Dimension 2: Delta instead of SparseBitmap (MUCH worse compression)
- **Result**: Suboptimal encoding, worse overall compression

**Size Impact**: TransposeBlock 2.55MB vs TransposeField 2.76MB (Field is WORSE by 8%)

**Why Field is worse**: Even though per-dimension analysis is more accurate, the HARDCODED lossy blocklist is too aggressive:

[source,rust]
----
ProximaScheme::Simple8b |      // BLOCKED (but lossless!)
ProximaScheme::RunLength |     // BLOCKED (but lossless!)
ProximaScheme::VByte |         // BLOCKED (but lossless!)
ProximaScheme::Zigzag { .. } | // BLOCKED (but could be lossless with proper bits)
ProximaScheme::PForDelta { .. } => {  // BLOCKED (but should upgrade to PForDoubleDelta)
    ProximaScheme::Delta { base: 0 }  // Fallback to Delta
}
----

This forces MANY dimensions to fall back to Delta even when better lossless schemes exist!

==== Scenario 2: 1536 Dimensions

**TransposeFieldEncoded**:
- Analyzes each dimension (1536 analyses)
- Same aggressive lossy blocklist
- MORE dimensions forced to Delta fallback
- **Result**: Worse compression due to excessive fallbacks (5.57MB)

**TransposeBlockCompressed**:
- Analyzes sample ONCE
- Sample might not trigger lossy schemes
- Uses detected scheme (e.g., DoubleDelta) for ALL dimensions
- **Result**: Better compression because fewer fallbacks (6.04MB)

**Size Impact**: REVERSED! TransposeField 5.57MB vs TransposeBlock 6.04MB (Block is WORSE by 8%)

== Recommended Solutions

=== Solution 1: Use `is_lossy()` Method (CRITICAL)

**Problem**: Both strategies use hardcoded lossy blocklists that are TOO AGGRESSIVE.

**Current Code** (TransposeFieldEncoded, line 2915):
[source,rust]
----
let scheme = match &detected_scheme {
    ProximaScheme::Simple8b |      // WRONG! Simple8b is lossless for integers
    ProximaScheme::RunLength |     // WRONG! RunLength is lossless
    ProximaScheme::VByte |         // WRONG! VByte is lossless for integers
    ProximaScheme::Zigzag { .. } | // WRONG! Zigzag can be lossless
    ProximaScheme::PForDelta { .. } => {  // WRONG! Should upgrade to PForDoubleDelta
        ProximaScheme::Delta { base: 0 }
    },
    _ => detected_scheme.clone(),
};
----

**Fixed Code** (like GroupedField):
[source,rust]
----
use crate::storage::engines::core::ops::proximacodec::TypeId;

let scheme = if detected_scheme.is_lossy(TypeId::F32) {
    // Upgrade PForDelta to PForDoubleDelta (lossless for f32)
    match &detected_scheme {
        CodecScheme::PForDelta { .. } => {
            if let Some(base) = dimension_values.first() {
                let base_bits = base.to_bits() as i64;
                let first_delta = if dimension_values.len() > 1 {
                    (dimension_values[1].to_bits() as i64) - base_bits
                } else {
                    0
                };
                CodecScheme::PForDoubleDelta { base: base_bits, first_delta }
            } else {
                CodecScheme::Delta { base: 0 }
            }
        },
        _ => CodecScheme::Delta { base: 0 }
    }
} else {
    detected_scheme.clone()  // Use lossless scheme as-is
};
----

**Impact**: Enables DoubleDelta, PForDoubleDelta, and other lossless schemes for better compression.

// New utility function
pub fn get_safe_scheme_for_f32(detected: ProximaScheme) -> ProximaScheme {
    use crate::storage::engines::core::ops::proximacodec::TypeId;

    if detected.is_lossy(TypeId::F32) {
        // Upgrade PForDelta to PForDoubleDelta
        match detected {
            ProximaScheme::PForDelta { base, .. } => {
                ProximaScheme::PForDoubleDelta { base, first_delta: 0 }
            },
            _ => ProximaScheme::Delta { base: 0 }
        }
    } else {
        detected  // Use as-is
    }
}
