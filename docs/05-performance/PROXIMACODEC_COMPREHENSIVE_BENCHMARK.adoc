== Overview

This benchmark provides **comprehensive analysis** of ProximaCodec encoding schemes across:
- **15 Encoding Algorithms**: Delta, DoubleDelta, BitPacked, FrameOfRef, Zigzag, PForDelta, Simple8b, VByte, Gorilla, SparseBitmap, SparseCOO, Dictionary, RunLength, and more
- **8 Data Patterns**: Normalized embeddings, Sinusoidal, Time-Series, Sequential, Random, Sparse, Constant, and Clustered data
- **Auto-Accelerated Execution**: Automatically selects GPU → SIMD → Baseline via ProximaCodec registry
- **Complete Metrics**: Encode time, decode time, and compression ratio for every combination

The benchmark uses `ProximaCodec::global()` which automatically routes to the fastest available implementation (Metal GPU on macOS, CUDA on Linux, SIMD fallback, or Baseline).

== Platform Auto-Detection

The benchmark automatically detects the platform and runs appropriate acceleration variants:

* **macOS ARM64 (M4)**: Baseline, NEON SIMD, Metal GPU
* **Linux x86_64**: Baseline, AVX2/AVX-512 SIMD, CUDA GPU
* **Other platforms**: Baseline, SIMD (architecture-specific), CPU fallback

== Encoding Schemes Benchmarked

=== 1. Raw (Identity Encoding) ⭐ NEW

* **Use case**: Normalized ML embeddings in [-1, 1] range
* **Why critical**: ONLY scheme that doesn't expand f32 embeddings
* **Performance**: 1.25-1.57 Gelem/s (FASTEST encode/decode)
* **Compression**: -0.1% (essentially unchanged)
* **⚠️ Comparison**:
** Simple8b: -66% to -100% (SEVERE expansion)
** VByte: -25% (expansion)
** Delta: -0.3% (slight expansion)
* **Variants tested**:
** Baseline: Pure Rust (identity transformation, direct byte copy)

=== 2. DoubleDelta

* **Use case**: Time-series data, sequential IDs
* **Variants tested**:
** Baseline: Pure Rust implementation
** SIMD: NEON-accelerated (Apple Silicon) or AVX2/AVX-512 (x86)
** Metal GPU: 3-phase parallel algorithm (macOS)
** CUDA GPU: 3-phase parallel algorithm (Linux NVIDIA)

=== 3. Delta

* **Use case**: Monotonic sequences, trending data
* **Variants tested**:
** Baseline: Pure Rust
** SIMD: NEON (ARM) or AVX2/AVX-512 (x86)
** GPU: Parallel subtraction

=== 4. Frame-of-Reference

* **Use case**: Values clustered around reference point
* **Variants tested**:
** Baseline: Pure Rust
** SIMD: Platform-specific SIMD
** GPU: Two-stage (delta + pack)

=== 5. Zigzag

* **Use case**: Signed integers, negative values
* **Variants tested**:
** Baseline: Pure Rust
** SIMD: Platform-specific SIMD
** GPU: Bit manipulation kernels

== Test Data Patterns

The benchmark tests 8 different data patterns to comprehensively evaluate encoding performance:

=== 1. Normalized Embeddings

[source,rust]
----
values in range [-1.0, 1.0]
----

**Characteristics**: Simulates ML embeddings (BERT, OpenAI, etc.)
**Use Case**: Vector similarity search, RAG systems

=== 2. Sinusoidal / Periodic

[source,rust]
----
100.0 + sin(i * 0.1) * 50 + cos(i * 0.05) * 30 + sin(i * 0.02) * 20
----

**Characteristics**: Multiple frequency components
**Use Case**: Sensor data, waveforms, periodic signals

=== 3. Time-Series

[source,rust]
----
baseline + trend + noise
100.0 + (i * 0.05) + sin(i * 0.1) * 2.0
----

**Characteristics**: Trending data with noise
**Use Case**: IoT metrics, stock prices, monitoring data

=== 4. Sequential

[source,rust]
----
i * 0.1
----

**Characteristics**: Monotonic increase (best-case compression)
**Use Case**: Auto-increment IDs, timestamps

=== 5. Random

[source,rust]
----
random values (high entropy)
----

**Characteristics**: Worst-case compression scenario
**Use Case**: Testing compression limits, cryptographic data

=== 6. Sparse

[source,rust]
----
mostly zeros with occasional non-zero values (1% density)
----

**Characteristics**: 99% zeros
**Use Case**: Sparse vectors, feature vectors, recommender systems

=== 7. Constant

[source,rust]
----
all values = 42.0
----

**Characteristics**: No variation (optimal for RLE)
**Use Case**: Testing run-length encoding, constant fields

=== 8. Clustered

[source,rust]
----
values grouped in 5 distinct clusters
----

**Characteristics**: Distinct value clusters with small variations
**Use Case**: Categorical embeddings, quantized data

== Compression Analysis

The benchmark includes a compression analysis phase that compares encoding efficiency:

=== Compression Metrics

* **Original Size**: Uncompressed data size in bytes
* **Encoded Size**: Compressed data size after encoding
* **Compression Ratio**: Percentage of space saved (higher is better)
* **Scheme Comparison**: Delta vs DoubleDelta trade-offs

=== Key Findings

**Raw (Identity Encoding) - Critical for Normalized ML Embeddings:**
* Baseline: -0.1% compression (essentially unchanged, ONLY scheme that doesn't expand f32)
* Performance: 1.25-1.57 Gelem/s throughput (FASTEST encode/decode)
* Best for: Normalized embeddings where ALL other schemes cause expansion
* ⚠️ **Why it matters**: Simple8b causes 66-100% expansion, VByte 25%, Delta 0.3%
* **Use when**: ML embeddings in [-1, 1] range that don't match structured patterns

**DoubleDelta:**
* Baseline: 52-53% compression on time-series data
* SIMD/GPU: 75% compression (vectorized encoding format)
* Column-level (1024 f32): 34% (sinusoidal), 52.7% (time-series), 12.2% (random)
* Best for: Sequential/trending data where storage is critical
* Performance: 30-35 Melem/s baseline, 435-455 Melem/s SIMD (14x speedup)

**Delta:**
* Baseline: 0-1% compression (minimal savings on normalized data, -0.3% expansion)
* SIMD/GPU: 75% compression (identical to DoubleDelta with SIMD/GPU)
* Performance: 27-28 Melem/s baseline, 1.3 Gelem/s SIMD (47x speedup)
* Best for: Speed-critical applications (10-30x faster than DoubleDelta)

**Recommendation:**
* **For ML embeddings (normalized f32)**: Use Raw (ONLY scheme that doesn't expand)
* **For structured data with SIMD/GPU**: Use Delta (identical 75% compression, 10-30x faster)
* **For time-series without SIMD/GPU**: Use DoubleDelta Baseline (52% compression)
* **Exception**: Use DoubleDelta Baseline only if: (1) No SIMD/GPU available AND (2) Storage cost > CPU cost

== Benchmark Output Interpretation

=== Criterion Output Format

----
Benchmarking double_delta_comprehensive/baseline/10000
                        time:   [500.00 µs 510.00 µs 520.00 µs]
                        thrpt:  [19.23 Melem/s 19.61 Melem/s 20.00 Melem/s]
----

* **time**: Mean execution time [lower bound, estimate, upper bound]
* **thrpt**: Throughput in millions of elements per second
* **change**: Performance change vs previous run (if available)

=== Key Metrics

**Speedup Calculation:**
----
Speedup = Baseline time / Variant time
----

**GPU Efficiency:**
----
GPU Efficiency = (GPU speedup / Theoretical max) * 100%
----

For M4: Theoretical max ~32x (SIMD width 128-bit, GPU 4096 cores) +
Practical GPU speedup: 6-10x (memory-bound operations)

== Interpreting Results

=== When to Use Each Variant

**Baseline (Pure Rust):**

* Small batches (<500 vectors)
* Portability required
* Predictable performance
* No hardware acceleration available

**SIMD:**

* Medium batches (500-5,000 vectors)
* Low latency critical
* CPU-only environment
* Predictable performance required

**GPU (Metal/CUDA):**

* Large batches (>5,000 vectors)
* Throughput maximization
* Batch processing workloads
* GPU hardware available

=== Performance Patterns

**Small Batches (1K):**

* GPU slower due to kernel launch overhead
* SIMD 2-14x faster than baseline
* **Recommendation**: Use SIMD for best performance

**Medium Batches (10K):**

* GPU starts winning (5-8x vs baseline)
* SIMD still competitive (2-3x vs baseline)
* **Crossover point**: GPU becomes optimal

**Large Batches (100K+):**

* GPU dominates (8-12x vs baseline)
* Memory bandwidth becomes bottleneck
* GPU efficiency plateaus
* **Recommendation**: Use GPU for maximum throughput

== Notes and Best Practices

[NOTE]
====
1. **First run slower**: JIT compilation and cache warming affect initial results
2. **Variance**: Metal GPU may show higher variance due to thermal throttling
3. **Background processes**: Close other applications for accurate results
4. **Power mode**: Ensure system is in high-performance mode (not battery saver)
5. **Thermal state**: Run when machine is cool for consistent results
====

== Troubleshooting

=== Compilation Errors

[source,bash]
----
cargo clean
cargo build --features metal
cargo bench --bench bench_16_proximacodec_comprehensive --features metal
----

=== Metal Not Detected

* Ensure running on macOS with Apple Silicon
* Check `metal` feature is enabled in build command
* Verify Metal framework is available

=== CUDA Not Detected

* Ensure running on Linux with NVIDIA GPU
* Check `gpu` feature is enabled
* Verify CUDA toolkit is installed

=== Benchmark Crashes

* Reduce sample size: `--sample-size 10`
* Skip warmup: `--warm-up-time 0`
* Run single test: filter by name
