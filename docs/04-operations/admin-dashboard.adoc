= Embedded Admin Dashboard (read-only)
:toc: macro
:icons: font

toc::[]

ProximaDB ships a built-in, **read-only** admin dashboard for local standalone and
embedded operation. It is served by the REST listener itself — no separate process,
no node/npm toolchain, no build step, no external network — so it works in offline
and air-gapped deployments.

== Enabling it (off by default)

The dashboard is **disabled by default** — Kubernetes pods and embedded deployments
do not get it unless an operator explicitly opts in. Enable it in the TOML config for
a **standalone** instance:

[source,toml]
----
[server.admin_ui]
enabled = true        # mount the read-only /admin route (default: false)
----

[NOTE]
====
Intended for standalone local instances. Leave it off for Kubernetes pods (each pod
does not need it). In embedded / UDS mode (`[api].transport = "uds"`) the HTTP surface
is a local Unix-domain socket, not a browser-reachable TCP port — even if you set
`enabled = true` there it is only reachable via `curl --unix-socket`, so it is meant
for TCP standalone deployments. The legacy multi-port server never serves it.
====

== Accessing it

With `[server.admin_ui] enabled = true`, start the server and open `/admin` on the
REST port (default `5678`):

[source,console]
----
$ cargo run --release --bin proximadb-server
# then browse to:
#   http://localhost:5678/admin
----

`GET /dashboard` is kept as a back-compat alias for the same page. On startup the
server logs `🖥️  Read-only admin dashboard enabled at /admin` when the toggle is on;
when off, the `/admin` route does not exist (404).

== What it shows

[cols="1,3", options="header"]
|===
| Panel | Source (read-only GET)
| Server health | `GET /health`, `GET /health/ready`
| Build & capabilities | `GET /api/v2/_meta/capabilities`
| Metrics | `GET /metrics/json` (when the metrics collector is enabled)
| Collections | `GET /api/v2/collections`; click a row → `GET /api/v2/collections/{id}`
|===

The page auto-refreshes every 10s (toggleable) and degrades gracefully — a panel
shows `n/a` if its endpoint is disabled, unauthorized, or unavailable in that
deployment.

== Read-only by design

The dashboard issues **only `GET`** requests and renders **no** create/update/delete
controls — it cannot mutate data. For writes and administration use the SDKs, REST
`/api/v2`, gRPC, or pgwire. A crate-level test enforces both invariants (no external
URLs, no write verbs in the page).

[NOTE]
====
This is the lightweight, dependency-free counterpart to the full operator console
(the `ui/` React app). It is intended for local/embedded visibility; it is not a
multi-tenant SaaS admin surface. If you expose the REST port beyond localhost,
front it with your normal auth/network controls — the page inherits whatever
auth the underlying `/api/v2` endpoints enforce.
====

== Implementation

Self-contained HTML embedded into the binary via `include_str!`, served by the
`crates/platform/proximadb-admin-ui` crate's `admin_router()`, merged into the REST
router in `src/network/rest/server.rs`. See the crate README for details.
