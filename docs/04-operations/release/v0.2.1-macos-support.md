# ProximaDB v0.2.1 - macOS aarch64 Support Plan

## Overview

This document outlines the changes needed to add macOS aarch64 (Apple Silicon) support with Metal Performance Shaders (MPS) for ProximaDB v0.2.1.

## Technical Details

### Why macOS Only Needs aarch64

Since November 2020, Apple has exclusively shipped Macs with ARM64 (Apple Silicon) processors:
- **M1, M1 Pro, M1 Max, M1 Ultra** (2020-2022)
- **M2, M2 Pro, M2 Max, M2 Ultra** (2022-2023)
- **M3, M3 Pro, M3 Max** (2023-2024)
- **M4 series** (2024-2025)

Intel Macs are no longer manufactured, and GitHub Actions `macos-latest` is now ARM64-only.

### Metal Feature Support

The `metal` feature enables:
- **Metal Performance Shaders (MPS)** for GPU-accelerated vector operations
- Native Apple Silicon GPU acceleration
- Zero-copy memory operations with Unified Memory Architecture

**Requirements**:
- macOS 11.0+ (Big Sur) or later
- Xcode Command Line Tools (pre-installed on GitHub Actions)
- No additional dependencies needed

### Build Configuration

```toml
# Cargo.toml
[dependencies]
metal = { version = "0.27", optional = true }

[features]
metal = ["dep:metal"]
gpu = ["metal"]
```

### Runtime GPU Detection

The codebase already has conditional compilation for Metal:

```rust
#[cfg(all(target_os = "macos", feature = "metal"))]
{
    // Metal/MPS GPU code path
}
```

| Platform | Build Time |
|----------|------------|
| Linux x86_64 | ~20 min |
| Windows x86_64 | ~25 min |
| macOS aarch64 | ~15 min (native build, no cross-compilation) |
| DMG creation | ~1 min |

## Implementation Order

1. Create feature branch: `git checkout -b feature/macos-aarch64-support`
2. Apply changes to prerelease-ci.yml
3. Apply changes to release.yml
4. Test with workflow dispatch on development branch
5. Fix any issues that arise
6. Update version to 0.2.1
7. Create PR and merge to main
8. Tag and release v0.2.1

## Rollback Plan

If macOS build fails:
1. Disable the target again (comment out aarch64-apple-darwin)
2. Update validation back to 2 binaries
3. Disable DMG build with `if: false`
4. Investigate failure logs
5. Fix and retry in v0.2.2
