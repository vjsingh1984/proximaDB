= Refined Graph Database Specification for AI Agent Implementation

:toc:
:icons: font
:source-highlighter: rouge
:status: in-progress

This document provides a refined, phased, and actionable implementation plan for ProximaDB's native graph database capabilities. It is designed to be used by AI coding agents to implement the features in a step-by-step manner.

== Status Snapshot (Reviewed: 2025-09-09)

- Implemented: Proto schemas (`proto/proximadb/v1/graph.proto`), GraphService (`src/graph/service.rs`), ORION engine CSR storage and indexes (`src/graph/engines/orion/{storage.rs,index.rs}`), traversal (BFS/DFS/Dijkstra; PageRank), REST and gRPC endpoints (`src/network/rest/v1/graph.rs`, `src/network/grpc/graph_service.rs`).
- In Progress: Parallel BFS (falls back to BFS), pattern-matching execution path (planner exists; executor wiring pending), documentation polish and tutorials.
- Next: Harden hybrid graph+vector execution path and add EXPLAIN/metrics surfaces for graph queries.

== Phase 1: Core Data Structures and Storage

*Goal:* Establish the fundamental data structures for nodes and edges and integrate them with the existing storage engine.

*Tasks:*

1.  **Define Protobuf Schema:**
    *   **File:** `proto/proximadb/v1/graph.proto`
    *   **Messages:**
        *   `Node`:
            *   `id`: `bytes` (UUID)
            *   `labels`: `repeated string`
            *   `properties`: `map<string, Value>`
        *   `Edge`:
            *   `id`: `bytes` (UUID)
            *   `source_id`: `bytes` (UUID)
            *   `target_id`: `bytes` (UUID)
            *   `label`: `string`
            *   `properties`: `map<string, Value>`
        *   `Value`: `oneof` for `string`, `int64`, `float64`, `bool`, `bytes`.
    *   **Verification:** The protobuf file should be compilable by `build.rs`.

2.  **Implement Rust Structs:**
    *   **File:** `src/graph/models.rs`
    *   **Structs:**
        *   `Node`
        *   `Edge`
    *   **Implementation:**
        *   Derive `serde::Serialize`, `serde::Deserialize`, `Clone`, `Debug`, `PartialEq`.
        *   Implement `From<proto::Node> for Node` and `From<Node> for proto::Node`.
        *   Implement `From<proto::Edge> for Edge` and `From<Edge> for proto::Edge`.
    *   **Verification:** Unit tests for conversions between protobuf and Rust structs.

3.  **Integrate with Storage Engine:**
    *   **File:** `src/storage/graph.rs`
    *   **Key-Value Mapping:**
        *   Nodes: `graph/nodes/{node_id}` -> `proto::Node` bytes
        *   Edges: `graph/edges/{edge_id}` -> `proto::Edge` bytes
        *   Outgoing Edges Index: `graph/node_edges/out/{source_id}/{label}/{target_id}` -> `edge_id`
        *   Incoming Edges Index: `graph/node_edges/in/{target_id}/{label}/{source_id}` -> `edge_id`
    *   **Functions:**
        *   `put_node(node: &Node) -> Result<()>`
        *   `get_node(node_id: &[u8]) -> Result<Option<Node>>`
        *   `delete_node(node_id: &[u8]) -> Result<()>`
        *   `put_edge(edge: &Edge) -> Result<()>`
        *   `get_edge(edge_id: &[u8]) -> Result<Option<Edge>>`
        *   `delete_edge(edge_id: &[u8]) -> Result<()>`
        *   `get_outgoing_edges(node_id: &[u8], label: Option<&str>) -> Result<Vec<Edge>>`
        *   `get_incoming_edges(node_id: &[u8], label: Option<&str>) -> Result<Vec<Edge>>`
    *   **Verification:** Unit tests for all storage functions.

== Phase 2: Graph Service and API

*Goal:* Expose graph functionality through a new `GraphService` and REST/gRPC APIs.

*Tasks:*

1.  **Create `GraphService`:**
    *   **File:** `src/graph/service.rs`
    *   **Struct:** `GraphService`
    *   **Implementation:**
        *   The service will hold a reference to the `Storage` engine.
        *   Implement methods that call the storage functions from Phase 1.
        *   Add validation logic (e.g., check if nodes exist before creating an edge).
    *   **Verification:** Unit tests for the `GraphService` methods.

2.  **Integrate into `SharedServices`:**
    *   **File:** `src/services/shared_services.rs`
    *   **Implementation:** Add `GraphService` to the `SharedServices` struct.
    *   **Verification:** The project should compile successfully.

3.  **Expose via REST API:**
    *   **File:** `src/network/rest/v1/graph.rs`
    *   **Endpoints:**
        *   `POST /v1/graph/nodes`
        *   `GET /v1/graph/nodes/{id}`
        *   `DELETE /v1/graph/nodes/{id}`
        *   `POST /v1/graph/edges`
        *   `GET /v1/graph/edges/{id}`
        *   `DELETE /v1/graph/edges/{id}`
        *   `GET /v1/graph/nodes/{id}/edges/outgoing`
        *   `GET /v1/graph/nodes/{id}/edges/incoming`
    *   **Verification:** Integration tests for all REST endpoints.

4.  **Expose via gRPC API:**
    *   **File:** `proto/proximadb/v1/graph_service.proto`
    *   **Service:** `GraphService`
    *   **RPCs:**
        *   `CreateNode`, `GetNode`, `DeleteNode`
        *   `CreateEdge`, `GetEdge`, `DeleteEdge`
        *   `GetOutgoingEdges`, `GetIncomingEdges`
    *   **File:** `src/network/grpc/graph_service.rs`
    *   **Implementation:** Implement the gRPC service.
    *   **Verification:** Integration tests for all gRPC RPCs.

== Phase 3: In-Memory Engine (ORION) and Traversal

*Goal:* Implement the ORION in-memory engine using CSR for high-performance traversal.

*Tasks:*

1.  **ORION Engine Structure:**
    *   **File:** `src/graph/engines/orion/mod.rs`
    *   **Struct:** `OrionGraphEngine`
    *   **Data Structures:**
        *   `nodes: Arc<DashMap<NodeId, Node>>`
        *   `edge_offsets: Vec<usize>`
        *   `edge_targets: Vec<NodeId>`
        *   `edge_data: Vec<Arc<Edge>>`
        *   `reverse_offsets: Vec<usize>`
        *   `reverse_sources: Vec<NodeId>`
    *   **Verification:** The engine should be able to load graph data from the storage layer.

2.  **Traversal Algorithms:**
    *   **File:** `src/graph/engines/orion/traversal.rs`
    *   **Functions:**
        *   `bfs(start_node: NodeId, max_depth: usize) -> Vec<NodeId>`
        *   `dfs(start_node: NodeId, max_depth: usize) -> Vec<NodeId>`
    *   **Implementation:**
        *   Use the CSR data structures for efficient traversal.
        *   Implement iterative versions to avoid stack overflow.
    *   **Verification:** Unit tests for BFS and DFS on various graph structures.

3.  **Expose Traversal via API:**
    *   **File:** `src/network/rest/v1/graph.rs`
    *   **Endpoints:**
        *   `GET /v1/graph/nodes/{id}/traverse/bfs`
        *   `GET /v1/graph/nodes/{id}/traverse/dfs`
    *   **File:** `src/network/grpc/graph_service.rs`
    *   **RPCs:**
        *   `Bfs`
        *   `Dfs`
    *   **Verification:** Integration tests for traversal APIs.

== Phase 4: Indexing and Querying

*Goal:* Implement property and label indexes for faster queries.

*Tasks:*

1.  **Property Indexes:**
    *   **File:** `src/graph/engines/orion/index.rs`
    *   **Data Structure:** `node_indexes: HashMap<String, BTreeMap<Value, HashSet<NodeId>>>`
    *   **Implementation:**
        *   When a node is created or updated, update the corresponding indexes.
        *   Implement a `find_nodes_by_property` function that uses the indexes.
    *   **Verification:** Unit tests for property indexing and querying.

2.  **Label Indexes:**
    *   **File:** `src/graph/engines/orion/index.rs`
    *   **Data Structure:** `label_index: HashMap<String, HashSet<NodeId>>`
    *   **Implementation:**
        *   When a node is created or updated, update the label index.
        *   Implement a `find_nodes_by_label` function that uses the index.
    *   **Verification:** Unit tests for label indexing and querying.

3.  **Expose Querying via API:**
    *   **File:** `src/network/rest/v1/graph.rs`
    *   **Endpoints:**
        *   `GET /v1/graph/nodes?label={label}`
        *   `GET /v1/graph/nodes?property_key={key}&property_value={value}`
    *   **File:** `src/network/grpc/graph_service.rs`
    *   **RPCs:**
        *   `FindNodesByLabel`
        *   `FindNodesByProperty`
    *   **Verification:** Integration tests for querying APIs.
