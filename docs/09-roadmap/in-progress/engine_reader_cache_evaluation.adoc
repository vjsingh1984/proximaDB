 = Engine Reader Cache Evaluation — Orchestrator Integration
 :toc:
 :status: in-progress

== Purpose
Evaluate reader paths across engines for unified cache opportunities (file metadata, bloom/filter, index structures) and safe prefetch via Cross‑Cache Orchestrator.

== Summary by Engine

- NOVA (Columnar/Parquet)
  - Reader: Shared columnar `UnifiedParquetReader` and Parquet I/O layer.
  - Current: Uses footer cache and I/O layer; no explicit orchestrator threading yet.
  - Opportunities: Wire `SharedContext` → `UnifiedParquetReader`; track `Metadata` and `IndexStructure`; bounded adjacent row‑group prefetch.
  - Next: Add `with_context(..)` to reader; pass from NOVA constructors; register footer cache provider.

- VIPER (Columnar/Parquet)
  - Reader: `UnifiedParquetReader` with strategy selection.
  - Current: Footer cache implemented; VIPER exposes `with_context(..)`; explicit reader tracking pending.
  - Opportunities: Track `Metadata` (footers, row‑group stats) and `IndexStructure`; safe prefetch of neighboring row groups.
  - Next: Emit `track_access_async` at metadata/row‑group reads; register footer cache provider.

- SST (Row/Block, FastLanes)
  - Reader: UnifiedSstableReader + decompression cache; bloom filters at block/manifest.
  - Current: Engine holds orchestrator; hooks identified; no provider registration.
  - Opportunities: Track `Metadata` (manifest, headers) and `FilterBitmap` (blooms); prefetch next block window; register decompression cache provider.
  - Next: Emit tracking at decompression cache hits/misses and manifest reads; register providers.

- HELIX (LSM‑like, FastLanes + zone maps)
  - Reader: Helix readers with zone maps and clustering.
  - Current: Orchestrator field present; no tracking calls.
  - Opportunities: Track `Metadata` (zone map headers), `IndexStructure` (cluster/centroid trees); prefetch adjacent clusters.
  - Next: Wire orchestrator into readers; register zone‑map/index providers; guard prefetch.

- RAPTOR (RowGroup + custom metadata)
  - Reader: Consolidated reader with custom file metadata.
  - Current: Tracks `Metadata` via orchestrator pattern tracker; zero‑copy caching.
  - Opportunities: Add `FilterBitmap` tracking when checking rowgroup blooms; register metadata/bloom providers; bounded prefetch of next rowgroups.
  - Next: Add tracking at bloom checks; implement providers.

- SWIFT (Hierarchical SuperBlocks/DataBlocks)
  - Reader: UnifiedSwiftReader + SuperBlock cache; batch ops prefetch + LRU block cache.
  - Current: Local caches and prefetch; no orchestrator integration.
  - Opportunities: Track `Metadata` (SuperBlock headers), `FilterBitmap` (hierarchical blooms), `VectorData` (hot blocks); expose cache stats to orchestrator; bounded superblock adjacency prefetch.
  - Next: Wire orchestrator handle; register superblock/datablock/bloom providers; emit tracking on cache hits/misses and metadata loads.

== Acceptance
- Engines report cache stats via `register_cache_provider`; orchestrator rebalances budgets.
- Metadata/filter/index tracking emits through orchestrator; bounded prefetch only.
- Parquet engines thread `SharedContext` into readers; FastLanes engines expose cache providers and tracking at key touchpoints.
