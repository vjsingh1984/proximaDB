= SKS Coupling v1 — Next Steps (P0)
 :toc:
 :status: in-progress

 == Objective
 Evolve SKS from in-memory scaffolding to an engine-backed, coherent store that enables low-latency hybrid queries with bidirectional seeding.

 == Deliverables
 - Engine-backed EntityStore (headers persisted; embeddings cataloged)
 - EntityID↔VectorID index and embedding catalog API
 - Graph→Vector seed handoff in Hybrid Orchestrator
 - Minimal EXPLAIN additions for hybrid plans

 == Design Notes
 - Persistence: reuse `UnifiedStorageEngine` to store serialized EntityHeader and embeddings; keep Arc headers for zero-copy.
 - Indexes: maintain per-collection maps for entity→embedding keys and embedding→entity reverse lookup.
 - Seeding: given a set of node ids, retrieve associated embeddings or vector ids to run SIMILAR.

 == File Scope
 - `src/storage/entity_store.rs` — add engine-backed put/get, entity↔vector index
 - `src/query/execution/executor.rs` — add graph→vector seeding path
 - `src/api_handlers/unified_handlers.rs` — optional EXPLAIN enrichments

== Acceptance Criteria
 - Upsert/get/list entities persisted beyond process lifetime (behind feature flag if needed)
 - Graph→Vector seeding returns top‑K fused results deterministically
 - Unit tests for persistence + seeding; integration test for SIMILAR→FOLLOW and FOLLOW→SIMILAR
