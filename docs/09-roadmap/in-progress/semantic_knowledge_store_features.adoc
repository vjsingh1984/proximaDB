== Architecture Choice: Federated Hybrid vs Storage-Coupled SKS

**✅ CHOSEN ARCHITECTURE: HYBRID APPROACH (IMPLEMENTED)**

**Current Implementation (Production)**:
- **ProximaEntityStore** serves as central entity catalog with engine-backed persistence
- **Federated Execution**: Vector and graph operations remain in specialized engines for performance
- **Unified Query Layer**: ExecutionOperation::{VectorSearch, GraphTraversal, Fusion} orchestrates hybrid intelligence
- **Entity-Vector Mapping**: ProximaEntityStore maintains bidirectional index (entity_to_vectors, vector_to_entity)
- **Cross-Engine Optimization**: HashMap metadata filtering, progressive search, cache orchestration

**Performance Benefits Achieved**:
- **Zero Marshaling Overhead**: Direct VectorRecord flow through engines
- **O(1) Entity Lookups**: HashMap-based entity↔vector resolution
- **Coherent Provenance**: Centralized entity headers with distributed embedding storage
- **Optimal Hybrid Latency**: Parallel execution with intelligent seeding strategies

```rust
    pub flexible_metadata: Option<FlexibleMetadata>, // Dynamic JSON metadata  
    pub provenance: Option<Provenance>,            // Source tracking

```

**EmbeddingVersion (Multi-modal support)**:
```rust
pub struct EmbeddingVersion {
    pub model_id: String,           // "bert-base-uncased", "clip-vit-b32"
    pub model_version: String,      // "v1", "2023-12-01" 
    pub vector: Vec<f32>,          // Dense embedding values
    pub dimension: u32,            // Vector dimensionality
    pub modality: Modality,        // Text, Image, Audio, Video
    pub created_at: Option<Timestamp>,
    pub model_params: HashMap<String, String>, // Training parameters
}
```

**Relations (CSR Format for O(1) traversal)**:
```rust
pub struct CsrRelationsStore {
    offsets: Vec<usize>,    // Node offset into dst array
    dst: Vec<u32>,         // Destination node IDs
    edge_type: Vec<u8>,    // Edge type enumeration
    // Per collection: "users" -> CSR, "products" -> CSR
}
```

**Entity Storage Keys (Hierarchical)**:
- Entity: `{collection_id}/entity/{entity_id}`
- Embedding: `{collection_id}/{entity_id}/{model_id}/{modality}`
- Relation: `{collection_id}/relations/{from_id}/{edge_type}/{to_id}`

== Execution Flow (PRODUCTION ARCHITECTURE)

**1. SQL Parsing & Lowering**:
```sql
-- Example hybrid query
SELECT * FROM entities e 
WHERE SIMILAR(e.content, $1, 'cosine', 10)
  AND FOLLOW(e.id, 'related', 2) 
ORDER BY similarity_score DESC;
```
→ Parsed to AST with `Expr::SksSimilar` and `Expr::SksFollow`

**2. Cost-Based Planning (ExecutionPlanner)**:
```rust
// Strategy detection based on query analysis
let strategy = match (has_vector_functions, has_graph_patterns, has_sks_functions) {
    (true, true, _) | (_, _, true) => ExecutionStrategy::Hybrid,
    (true, false, false) => ExecutionStrategy::VectorOnly,
    (false, true, false) => ExecutionStrategy::GraphOnly,
    _ => ExecutionStrategy::Relational,
};
```

**3. Parallel Hybrid Execution**:
```rust
// Concurrent execution with tokio::join!
let vector_fut = execute_vector_operation(&vector_ops);
let graph_fut = execute_graph_operation(&graph_ops);
let (vector_results, graph_results) = tokio::join!(vector_fut, graph_fut);

// Bidirectional seeding
if graph_needs_seeds {
    let seeds = vector_results.iter().map(|r| extract_id(r)).take(100).collect();
    graph_results.extend(execute_graph_traversal(&seeds).await?);
}

// Graph → Vector seeding with strategies
match seeding_strategy {
    SeedingStrategy::Average => /* average 32 embeddings */,
    SeedingStrategy::PerSeed => /* individual SIMILAR queries */,
    SeedingStrategy::None => /* catalog-only derivation */,
}
```

**4. Advanced Fusion & Results**:
```rust
// Reciprocal Rank Fusion algorithm
let fused_results = apply_reciprocal_rank_fusion(&vector_results, &graph_results, k)?;
fused_results.sort_by(|a, b| b.similarity_score.partial_cmp(&a.similarity_score));

// Apply pagination and return
Self::apply_limit_offset(&mut fused_results, plan.offset, plan.limit);
```
