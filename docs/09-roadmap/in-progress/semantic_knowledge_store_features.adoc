== Implementation Status (Updated: 2025-09-10)

Overall: In progress

Implemented:
- gRPC EntityService and REST handlers present (see `src/network/grpc/entity_service.rs`, `src/network/rest/v1/entities.rs`)
- Graph service and hybrid fusion strategies (RRF, adaptive) available
- SQL frontend integrated; SKS functions (SIMILAR/FOLLOW) are lowered and mapped to `VectorSearch`/`GraphTraversal` operations.
- In-memory SKS v1: `ProximaEntityStore` stores headers/embeddings; `CsrRelationsStore` and `InMemoryProvenanceRegistry` implemented; REST entity routes mounted.

Gaps:
- Persistent engine-backed EntityStore and embedding catalog; Graph→Vector seed handoff
- No text→embedding conversion; temporal filters not implemented
- Limited tests for SKS flows; pagination/streaming not wired

== Architecture Choice: Federated Hybrid vs Storage-Coupled SKS

Option A — Federated Hybrid (today, faster to finish):
- Keep vector and graph in their engines; orchestrate hybrid via `ExecutionOperation::{VectorSearch, GraphTraversal, Fusion}` in `src/query/execution/*`.
- Pros: Minimal storage change, incremental; uses existing VectorOperationsService and GraphService.
- Cons: Extra marshaling; weaker locality; harder provenance/temporal cohesion.

Option B — Storage-Coupled SKS (recommended path):
- Use `ProximaEntityStore` with shared headers (typed/flexible metadata, provenance, temporal) and per-entity embedding pointers; relations in CSR.
- Pros: Zero-copy headers, coherent semantics, better hybrid latency; enables unified indexes and caching.
- Plan: Deliver both—keep A as fallback, implement B v1 and flip via feature flag.

  - P0: Hybrid Orchestrator path:
    - Parallel vector + graph execution [DONE], configurable Fusion (RRF default)

    - Pagination/streaming on fused results [DEFERRED]

== Data Model (v1)

- EntityHeader: `TypedMetadata`, `FlexibleMetadata`, `Provenance`, `TemporalInfo` (Arc shared)
- EmbeddingVersion: `{model_id, modality, values, created_at, metadata}`
- Relations (CSR): `Vec<usize> offsets`, `Vec<u32> dst`, `Vec<u8> edge_type` per collection

== Execution Flow (Hybrid)

1. Parse SQL with SIMILAR/FOLLOW → lower to internal AST
2. Planner emits parallel `VectorSearch` and/or `GraphTraversal` and a `Fusion` op
3. Executor:
   - Runs vector and graph parts in parallel
   - Applies seed handoff if both present
   - Applies RRF fusion → paginate/stream

== Acceptance Criteria

- SKS v1: Upsert/get/list entities; store embeddings; add/get relations; provenance add/remove
- Hybrid: SIMILAR, FOLLOW, SIMILAR→FOLLOW pipeline with RRF; consistent pagination
- Performance: Zero-copy headers observed; O(1) metadata lookups on vector path
