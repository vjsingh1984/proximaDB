== Layered Architecture

- Frontend (SQL/AST): Parse SQL via `sqlparser-rs` into a canonical AST (`src/query/ast/*`, `sql_frontend/*`).
- Orchestration (Query): Lower AST to engine requests, manage hybrid sequences, enforce limits, shape results (`src/query/*`).
- Engines:
  - Vector: VectorOperationsService (VOS) plans+executes search, caching+pruning, progressive quantization.
  - Graph: GraphService/ORION plans+executes traversal/index use; future PULSAR/QUASAR for scale.
- Hybrid: Orchestrate VOS → Graph (or vice versa) using shared limits/metrics and zero-copy data sharing.

== Delegation Boundaries

- Vector planning/caching: delegated to VOS. Query passes normalized filters, vectors, and config and consumes VOS hints for EXPLAIN.
- Graph planning/caching: in GraphService per graph spec; Query orchestrates hybrid only.
- SQL joins/aggregations: planned by Query; vector costs supplied as hints from VOS; graph subtree costs from graph stats.

== Common Capabilities (Shared)

- Parameters: unified binding (`utils::params`).
- Limits/Timeouts: `utils::limits` honored by both stacks; propagated to VOS/Graph.
- Metrics/Tracing: unified metrics + OpenTelemetry spans; EXPLAIN exposes orchestration and engine hints.
- Caching: Query keeps plan/prepared/result caches; vector caches live in VOS; graph keeps traversal/stats caches. No duplication.
- Security/Multi-tenancy: consistent authZ across SQL/graph endpoints; tenant-scoped resources.

Limits propagation:
- RequestLimits carries `timeout_ms`, `work_budget`, `max_frontier`, `max_results`; propagate to VOS/Graph.
- Enforce server-side defaults and clamp unsafe client-provided values.

EXPLAIN/ANALYZE semantics:
- EXPLAIN shows orchestration steps (e.g., VectorSearch→GraphTraversal) with VOS/Graph hints.
- ANALYZE includes measured latencies, rows, cache hits, pruned files, progressive stages.

- gRPC: `ExecuteSql` RPC; graph service RPCs.

Error semantics:
