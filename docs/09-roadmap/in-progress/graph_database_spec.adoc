== Architecture Overview

- Service layer: `GraphService` encapsulates graph operations and orchestrates engine access.
- Engines: ORION (in-memory CSR) is primary; QUASAR/PULSAR scaffolding exists for tiered/distributed modes.
- Handlers: REST and gRPC use UnifiedHandlers to route to `GraphService`.
- Zero-copy: Arc-based sharing used across traversal and results.

== Data Model (Proto Summary)

Node and Edge are defined with typed properties.

[source,protobuf]
----
message Node { bytes id = 1; repeated string labels = 2; map<string, Value> properties = 3; }
message Edge { bytes id = 1; bytes source_id = 2; bytes target_id = 3; string label = 4; map<string, Value> properties = 5; }
----

== Storage Mapping (Key Layout)

Canonical key layout (applies in storage layers and engine caching):

- Nodes: `graph/nodes/{node_id}` → serialized proto Node
- Edges: `graph/edges/{edge_id}` → serialized proto Edge
- Outgoing index: `graph/node_edges/out/{source_id}/{label}/{target_id}` → edge_id
- Incoming index: `graph/node_edges/in/{target_id}/{label}/{source_id}` → edge_id

Essential store functions (by service/engine):
- `put_node/get_node/delete_node`
- `put_edge/get_edge/delete_edge`
- `get_outgoing_edges/get_incoming_edges`

== Public APIs

REST (mounted under `/api/v1/graph` in `src/network/rest/v1/handlers.rs`):
- Nodes: `POST /nodes`, `GET /nodes/{id}`, `PUT /nodes/{id}`, `DELETE /nodes/{id}`
- Edges: `POST /edges`, `GET /edges/{id}`, `PUT /edges/{id}`, `DELETE /edges/{id}`
- Neighbors: `GET /nodes/{id}/neighbors`
- Batch: `POST /nodes/batch`, `POST /edges/batch`
- Query: `POST /query/nodes`, `POST /query/edges`
- Traversal & analysis: `POST /traverse`, `POST /shortest_path`, `GET /components`, `GET /cycles`, `GET /stats`

gRPC (service `proximadb.v1.GraphService`):
- CRUD RPCs for Node/Edge, `GetNeighbors`, `TraverseGraph`/`StreamTraverse`, `ShortestPath`, `GetConnectedComponents`, `HasCycle`, batch ops, and query RPCs.

== Traversal & Algorithms

- BFS/DFS: Iterative traversal over CSR; supports property/label filtering.
- Shortest Path: Dijkstra; A* skeleton present.
- PageRank: Power iteration with damping.
- Parallel BFS: design present; currently falls back to sequential BFS.

== Indexing & Querying

- Property indexes: BTreeMap per property → NodeId sets; supports range/prefix.
- Label index: label → NodeId sets; supports AND/OR.
- Query surfaces: node/edge query RPCs and REST endpoints; planner surfaces selectivity hints.

=== Executor Mapping & Conventions (Precise)

[cols="2,2,3,3", options="header"]
|===
| PlanStepType | Required Params | Service Call | Output Row Shape
| `NodeScan { labels, property_filters }` | none | `GraphService::query_nodes(NodeQuery)` (map filters to proto ops) | `{ node }`
| `IndexSeek { index_name, key_value }` | none | `query_nodes` with label or equality filter (see index conventions) | `{ node }`
| `Traverse { algorithm, max_depth, edge_filters }` | `parameters["start_node_id"]: string` | `GraphService::traverse(TraversalRequest)` | `{ node, depth }` (extendable to `{ path }`)
| `Filter { condition }` | none | in‑memory predicate over row JSON | unchanged
| `Project { fields }` | none | in‑memory projection (support dotted paths like `node.id`) | reduced keys
| `Sort { fields }` | none | in‑memory stable sort | unchanged
| `Limit { count, offset }` | none | in‑memory slice | truncated
|===

Index name conventions
- Label index: `label_index_<label>` → build `NodeQuery { labels: [<label>] }`.
- Property index: `node_prop_<key>` → build `NodeQuery` with equality filter on `<key>` using `key_value`.

Parameter formats
- `start_node_id`: string NodeId (internal form). Do not parse/hex‑decode in executor; delegate representation concerns to `GraphService`.

Row shaping conventions
- `node`: full Node serialized to JSON (`serde_json::to_value(&Node)`), consistent with existing test expectations.
- `depth`: integer depth from traversal (root = 0).
- Future: a `path` array of NodeIds can be added without breaking existing rows.

=== Error Handling & Edge Cases
- Missing `start_node_id` for `Traverse` → return invalid‑argument error (do not panic).
- Unknown `index_name` prefix in `IndexSeek` → return not‑implemented with structured message.
- Empty results are valid; always return `[]` rather than error.
- Sorting mixed types: compare like‑types only; if types differ, coerce to string for comparison.
- Large result sets: apply `Limit` early when present to minimize allocations.

=== Logging & Debugging
- Log at debug level when selecting path for `IndexSeek` (label vs property).
- Log traversal entry with `start_node_id`, `algorithm`, `max_depth`.
- Attach a `request_id` in higher layers; executor should not generate IDs.
