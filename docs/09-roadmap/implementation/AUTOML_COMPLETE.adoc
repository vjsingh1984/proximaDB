- Coordinates optimization cycles
- Manages component lifecycle
- Tracks metrics and status

**Pattern Detection Rules:**

[cols="2,3,2"]
|===
| Pattern | Characteristics | Optimization Focus

| **ReadHeavy**
| Read/write ratio > 10:1
| Minimize latency, maximize cache

| **WriteHeavy**
| Write/read ratio > 10:1
| Maximize throughput, optimize flush

| **Balanced**
| Read/write ratio 1:2 to 2:1
| Balance all metrics

| **BatchProcessing**
| High variance (burstiness > 100)
| Optimize for bursts

| **Streaming**
| Stable throughput, low variance
| Consistent performance

| **Analytics**
| High latency (p99 > 1000ms), low QPS
| Maximize accuracy

| **Mixed**
| No clear pattern
| Adaptive strategy
|===

=== 6. Hyperparameter Tuner (`src/automl/tuning.rs`)

Advanced algorithms for parameter optimization.

**Supported Algorithms:**
- **TPE (Tree-structured Parzen Estimator)** - Default algorithm, balances exploration/exploitation
- **Hyperband** - Multi-armed bandit approach for resource allocation
- **Grid** - Exhaustive search for small parameter spaces
- **Random** - Baseline random sampling

== Usage Examples

=== Basic Setup

[source,rust]
----
use proximadb::automl::{AutoMLCoordinator, AutoMLConfig};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Create configuration
    let config = AutoMLConfig::default();

    // Initialize coordinator
    let automl = AutoMLCoordinator::new(config).await?;

    // Start AutoML (runs in background)
    automl.start().await?;

    // AutoML now automatically:
    // - Monitors workload patterns
    // - Predicts performance bottlenecks
    // - Optimizes configurations
    // - Tunes hyperparameters

    Ok(())
}
----

=== Manual Optimization

[source,rust]
----
use proximadb::automl::{
    OptimizationGoal,
    OptimizationStrategy,
    WorkloadPattern
};

// Trigger manual optimization
let best_config = automl.optimization_pipeline.optimize(
    "my_collection",
    OptimizationGoal::MinimizeLatency,
    OptimizationStrategy::BayesianOptimization {
        n_iterations: 50
    },
    WorkloadPattern::ReadHeavy,
).await?;

// Apply configuration
println!("Optimal settings:");
println!("  Index: {}", best_config.index.algorithm);
println!("  Quantization: {}", best_config.quantization.level);
println!("  Engine: {}", best_config.engine.engine_type);
println!("  Cache: {} MB", best_config.cache.cache_size_mb);

=== Hyperparameter Tuning

[source,rust]
----
use proximadb::automl::{
    HyperparameterTuner,
    TuningConfig,
    TuningAlgorithm,
    ProximaDBHyperparameters
};

// Configure tuner
let config = TuningConfig {
    max_trials: 50,
    early_stopping_patience: 10,
    parallel_trials: true,
    max_parallel_trials: 4,
    ..Default::default()
};

let tuner = HyperparameterTuner::new(config).await?;

// Add parameters to tune
for param in ProximaDBHyperparameters::hnsw_params() {
    tuner.add_parameter(param).await?;
}

// Define objective
let objective = |params| async move {
    // Evaluate configuration
    let score = evaluate_config(params).await?;
    Ok(score)
};

// Run tuning
let best = tuner
    .with_algorithm(TuningAlgorithm::TPE)
    .tune(objective)
    .await?;

println!("Best parameters: {:?}", best);
----

== Troubleshooting

=== Common Issues

**AutoML not triggering optimizations:**
- Check `automl.enabled = true` in config
- Verify minimum data points met (`min_data_points`)
- Check optimization interval timing
- Review logs for errors: `RUST_LOG=proximadb::automl=debug`

**Poor prediction accuracy:**
- Ensure sufficient training data (>1000 samples)
- Check feature normalization
- Verify appropriate model selection
- Consider retraining models

**Optimization timeouts:**
- Increase `timeout_per_trial` in configuration
- Reduce search space complexity
- Use faster evaluation functions
- Consider parallel trials

**High memory usage:**
- Reduce `max_data_points` for workload history
- Limit concurrent optimizations
- Adjust model complexity
- Clear old optimization history
