==== Storage Format Groups (All Columnar!)
1. **Parquet-Based (Native Columnar)**: VIPER, NOVA
   - Natural fit for separate quantization columns
   - Can add FIELD_VECTOR_BINARY, FIELD_VECTOR_INT8, FIELD_VECTOR_PQ columns

2. **ProximaDataBlock-Based (Columnar with Encoding)**: SST, SWIFT, HELIX
   - Uses columnar encoding strategies (TransposeFieldEncoded, GroupedFieldEncoded)
   - Already has QuantizedSection support in block structure!
   - Quantized vectors use SAME columnar encoding as main vectors

3. **Custom ProximaEncoder (Columnar Schemes)**: RAPTOR
   - Uses ProximaEncoder with columnar schemes (FrameOfReference, BitPacking, etc.)
   - Apply same columnar encoding to quantized vectors
   - Integrate with Matrix Trinity architecture

=== New Minimal Implementation

[source,rust]
----
// src/compute/quantization/precompute.rs
pub struct QuantizationPrecomputeService {
    storage_engine: Arc<StorageQuantizationEngine>,
    memory_pool: Arc<VectorMemoryPool>,
    cache: Arc<GlobalQuantizationCache>,
}

impl QuantizationPrecomputeService {
    pub async fn quantize_for_flush(
        &self,
        records: Vec<VectorRecord>,
        config: &QuantizationConfig,
    ) -> Result<QuantizedBatch> {
        // 1. Get memory buffer from pool
        let mut buffer = self.memory_pool.vector_buffers.take().await;

        // 2. Use StorageQuantizationEngine for actual quantization
        let storage_config = StorageQuantizationConfig::from(config);
        let quantized = self.storage_engine
            .quantize_batch_with_pool(&records, &storage_config, &mut buffer)
            .await?;

        // 3. Return buffer to pool
        self.memory_pool.vector_buffers.put(buffer).await;

        // 4. Return paired batch
        Ok(QuantizedBatch {
            records,
            quantized,
        })
    }
}
----
