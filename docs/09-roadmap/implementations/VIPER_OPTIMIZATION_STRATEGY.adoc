== Metadata Filtering Strategy

=== Overview

VIPER implements a dual-path metadata filtering strategy to optimize query performance while maintaining correctness:

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%
flowchart LR
    A[Query with Filters] --> B{Analyze Filters}
    B -->|All Filterable| C[Fast Path]
    B -->|Some Non-Filterable| D[Mixed Path]
    B -->|All Non-Filterable| E[Slow Path]

    C --> F[Column Projection]
    F --> G[Parquet Pushdown]
    G --> H[Direct Read]

    D --> I[Pushdown Filterable]
    I --> J[Post-filter Rest]

    E --> K[Full Scan]
    K --> L[extra_meta Filtering]

=== Filterable vs Non-Filterable Columns

==== Filterable Columns (Fast Path)
Columns explicitly defined in `CollectionConfig.filterable_columns`:

* Have dedicated Parquet columns
* Support statistics-based pruning
* Enable predicate pushdown
* Allow column projection
* Examples: `user_id`, `timestamp`, `category`

==== Non-Filterable Columns (Slow Path)
Columns stored in `extra_meta` Map field:

* Require full row reading
* No statistics available
* Post-processing required
* Cannot use column projection
* Examples: Dynamic metadata fields

=== Critical Issue: Quantization-Aware Compaction

[WARNING]
====
When quantization is enabled, compaction CANNOT use simple row-group merging!

* **Binary**: Thresholds change with merged data distribution
* **INT8**: Min/max values change requiring full recalculation
* **PQ**: Codebooks must be retrained on combined dataset
* **Impact**: Compaction becomes O(n×d) memory and O(n×k×iterations) compute
====

== Conclusion

The VIPER engine has most optimization infrastructure built but not connected. By following this phased implementation plan:

1. **Phase 1-2**: Enable quantization (5 days) - Immediate 10-15x search speedup
2. **Phase 3-4**: Connect filters and bloom filters (3 days) - 10-1000x query improvement
3. **Phase 5**: Integration and optimization (2 days) - Production readiness

Total effort: **10 days** for full optimization implementation.

The most critical insight is that quantization requires recalculation during compaction, fundamentally changing the compaction strategy from simple row-group merging to full vector processing.
