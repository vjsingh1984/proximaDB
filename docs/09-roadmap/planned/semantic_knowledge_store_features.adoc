== Section 2: Storage Engine Selection Rationale

=== Available Storage Engines Analysis

ProximaDB has 5 production-ready storage engines with distinct characteristics:

[cols="2,2,3,3", options="header"]
|===
| Engine | Type | Best For | SKS Suitability

| **SST**
| Row-based (LSM-tree)
| - High write throughput (200K/sec)
- OLTP workloads
- Frequent updates
| **Primary for Entity Headers**: 
- Fast point lookups (< 5ms)
- Efficient updates
- Bloom filters for existence checks

| **VIPER**
| Columnar (Parquet)
| - Analytics queries
- Batch operations (500K/sec)
- Maximum compression (5-10x)
| **Primary for Embeddings**:
- Columnar storage for vectors
- Advanced quantization pipeline
- Cloud-optimized with footer cache

| **NOVA**
| Enhanced columnar
| - Extended statistics
- Zone maps
- Aggressive pruning
| Alternative for embeddings
(85% complete)

| **SWIFT**
| High-perf row-based
| - Adaptive block sizes
- Fast traversal
| Alternative for relations
(75% complete)

| **PRISM**
| Metadata-first
| - Progressive quantization
- Metadata-heavy workloads
| Future option for metadata
(70% complete)
|===

=== Recommended Storage Architecture for SKS

**Decision**: Use hybrid storage with multiple engines optimized for each data type:

1. **Entity Headers (Metadata + Provenance)**: **SST Engine**
   - Rationale: Frequent updates, fast point lookups, efficient bloom filters
   - Key format: `(collection_id, entity_id)` 
   - Performance: < 1ms reads with decompression cache

2. **Embeddings Storage**: **VIPER Engine**
   - Rationale: Best compression (5-10x), columnar benefits, quantization support
   - Key format: `(collection_id, entity_id, model_id, modality)`
   - Performance: 10-50ms for batch retrieval

3. **Relations Storage**: **SST Engine**
   - Rationale: Fast adjacency list lookups, bloom filters for edge existence
   - Key format: `(collection_id, entity_id, relation_type, target_id)`
   - Performance: < 5ms for degree-bounded traversal

4. **Provenance Registry**: **SST Engine**
   - Rationale: Small dataset, fast lookups, good compression
   - Key format: `(source_id)` for sources, `(source_id, chunk_id)` for chunks

=== Quantization Strategy for SKS

Based on ProximaDB's quantization infrastructure:

```rust
// Use SMART_DEFAULTS strategy for automatic configuration
QuantizationConfig {
    enabled: true,
    strategy: Strategy::SMART_DEFAULTS,
    enable_progressive_search: true,
    // Automatic selection based on dimension:
    // - d < 128: Binary + INT8
    // - d >= 128 && d < 512: Binary + INT8 + PQ8
    // - d >= 512: Binary + PQ4 + PQ8 + INT8
}
```

**Rationale**:
- Progressive search reduces search space by 95% with bloom filters
- Quantization provides 5-10x storage reduction
- SIMD acceleration available (13.5M - 20.8M ops/sec for 128D)

=== Metadata Storage Decision

**TypedMetadata vs FlexibleMetadata**:

1. **TypedMetadata** (Parquet columnar in VIPER):
   - For declared fields with known types
   - 2-5x faster access with columnar projection
   - Automatic indexing and statistics

2. **FlexibleMetadata** (JSON in SST):
   - For ad-hoc fields
   - Auto-promotion to typed when query frequency > 100/day
   - Compressed with ZSTD for 3x reduction

/// Entity storage trait for SKS operations
#[async_trait]
pub trait EntityStore: Send + Sync {
    /// Upsert an entity (insert or update)
    async fn upsert_entity(
        &self,
        collection_id: &str,
        entity: Entity,
    ) -> Result<String>;
    
    /// Get entity by ID
    async fn get_entity(
        &self,
        collection_id: &str,
        entity_id: &str,
        include_embeddings: bool,
        include_relations: bool,
    ) -> Result<Option<Entity>>;
    
    /// Delete entity (soft or hard delete)
    async fn delete_entity(
        &self,
        collection_id: &str,
        entity_id: &str,
        hard_delete: bool,
    ) -> Result<bool>;
    
    /// Search entities with filters
    async fn search_entities(
        &self,
        collection_id: &str,
        query_vector: Option<Vec<f32>>,
        metadata_filter: Option<MetadataFilter>,
        temporal_filter: Option<TemporalFilter>,
        top_k: usize,
    ) -> Result<Vec<(Entity, f32)>>;
}

/// Concrete implementation using existing storage engines
pub struct ProximaEntityStore {
    /// Vector storage engine - VIPER for best compression and columnar benefits
    /// Chosen for: 5-10x compression, predicate pushdown, cloud optimization
    vector_engine: Arc<dyn StorageEngine>,  // Use VIPER
    
    /// Metadata storage - SST for fast updates and point lookups
    /// Chosen for: < 1ms lookups, bloom filters, efficient updates
    metadata_store: Arc<dyn StorageEngine>,  // Use SST
    
    /// Relations storage
    relations_store: Arc<RelationsStore>,
    
    /// Provenance registry
    provenance_registry: Arc<ProvenanceRegistry>,
}

impl ProximaEntityStore {
    pub fn new(
        vector_engine: Arc<dyn StorageEngine>,  // Should be VIPER
        metadata_store: Arc<dyn StorageEngine>,  // Should be SST
    ) -> Self {
        // Validate engine types for optimal performance
        assert_eq!(vector_engine.engine_name(), "VIPER", 
                   "Vector engine should be VIPER for optimal compression");
        assert_eq!(metadata_store.engine_name(), "SST",
                   "Metadata store should be SST for fast lookups");
        Self {
            vector_engine,
            metadata_store,
            relations_store: Arc::new(RelationsStore::new()),
            provenance_registry: Arc::new(ProvenanceRegistry::new()),
        }
    }
    
    /// Generate storage key for entity
    fn entity_key(collection_id: &str, entity_id: &str) -> String {
        format!("{}/{}", collection_id, entity_id)
    }
    
    /// Generate embedding key
    fn embedding_key(
        collection_id: &str,
        entity_id: &str,
        model_id: &str,
        modality: &str,
    ) -> String {
        format!("{}/{}/{}/{}", collection_id, entity_id, model_id, modality)
    }
}

#[async_trait]
impl EntityStore for ProximaEntityStore {
    async fn upsert_entity(
        &self,
        collection_id: &str,
        mut entity: Entity,
    ) -> Result<String> {
        // Validate entity
        if entity.id.is_empty() {
            entity.id = uuid::Uuid::new_v4().to_string();
        }
        
        // Store embeddings in vector engine
        for embedding in &entity.embeddings {
            let key = Self::embedding_key(
                collection_id,
                &entity.id,
                &embedding.model_id,
                &format!("{:?}", embedding.modality),
            );
            
            // Store vector using existing engine
            self.vector_engine
                .store_vector(&key, &embedding.vector)
                .await?;
        }
        
        // Store entity header (metadata, provenance, temporal)
        let header_key = Self::entity_key(collection_id, &entity.id);
        let header = EntityHeader {
            typed_metadata: entity.typed_metadata.clone(),
            flexible_metadata: entity.flexible_metadata.clone(),
            provenance: entity.provenance.clone(),
            temporal: entity.temporal.clone(),
        };
        
        self.metadata_store
            .store_entity_header(&header_key, &header)
            .await?;
        
        // Store relations
        for relation in &entity.relations {
            self.relations_store
                .add_relation(collection_id, relation.clone())
                .await?;
        }
        
        // Track provenance
        if let Some(ref provenance) = entity.provenance {
            self.provenance_registry
                .register_provenance(&entity.id, provenance.clone())
                .await?;
        }
        
        Ok(entity.id)
    }
    
    async fn get_entity(
        &self,
        collection_id: &str,
        entity_id: &str,
        include_embeddings: bool,
        include_relations: bool,
    ) -> Result<Option<Entity>> {
        let header_key = Self::entity_key(collection_id, entity_id);
        
        // Fetch entity header
        let header = match self.metadata_store
            .get_entity_header(&header_key)
            .await? 
        {
            Some(h) => h,
            None => return Ok(None),
        };
        
        let mut entity = Entity {
            id: entity_id.to_string(),
            typed_metadata: header.typed_metadata,
            flexible_metadata: header.flexible_metadata,
            provenance: header.provenance,
            temporal: header.temporal,
            collection_id: collection_id.to_string(),
            embeddings: vec![],
            relations: vec![],
        };
        
        // Optionally fetch embeddings
        if include_embeddings {
            entity.embeddings = self
                .fetch_embeddings(collection_id, entity_id)
                .await?;
        }
        
        // Optionally fetch relations
        if include_relations {
            entity.relations = self.relations_store
                .get_relations(collection_id, entity_id)
                .await?;
        }
        
        Ok(Some(entity))
    }
    
    async fn delete_entity(
        &self,
        collection_id: &str,
        entity_id: &str,
        hard_delete: bool,
    ) -> Result<bool> {
        let header_key = Self::entity_key(collection_id, entity_id);
        
        if hard_delete {
            // Remove all data
            self.metadata_store.delete(&header_key).await?;
            self.vector_engine
                .delete_entity_vectors(collection_id, entity_id)
                .await?;
            self.relations_store
                .delete_all_relations(collection_id, entity_id)
                .await?;
            self.provenance_registry
                .remove_provenance(entity_id)
                .await?;
        } else {
            // Soft delete: mark as deleted
            self.metadata_store
                .mark_deleted(&header_key)
                .await?;
        }
        
        Ok(true)
    }
    
    async fn search_entities(
        &self,
        collection_id: &str,
        query_vector: Option<Vec<f32>>,
        metadata_filter: Option<MetadataFilter>,
        temporal_filter: Option<TemporalFilter>,
        top_k: usize,
    ) -> Result<Vec<(Entity, f32)>> {
        // Use existing progressive search infrastructure
        let mut results = Vec::new();
        
        if let Some(vector) = query_vector {
            // Vector similarity search
            let search_results = self.vector_engine
                .search(collection_id, &vector, top_k)
                .await?;
            
            for (entity_id, score) in search_results {
                if let Some(entity) = self
                    .get_entity(collection_id, &entity_id, true, false)
                    .await?
                {
                    // Apply metadata filters
                    if Self::matches_filters(&entity, &metadata_filter, &temporal_filter) {
                        results.push((entity, score));
                    }
                }
            }
        } else {
            // Metadata-only search
            let entities = self.metadata_store
                .scan_with_filters(collection_id, metadata_filter, temporal_filter)
                .await?;
            
            for entity in entities.into_iter().take(top_k) {
                results.push((entity, 1.0));
            }
        }
        
        Ok(results)
    }
}

==== 1.1 Entity Data Model

*Requirement*: Transform from vector-centric to entity-centric storage model.

*Design*:
[source,protobuf]
----
message Entity {
  string id = 1;
  repeated EmbeddingVersion embeddings = 2;
  TypedMetadata typed_metadata = 3;
  google.protobuf.Struct flexible_metadata = 4;
  Provenance provenance = 5;
  repeated Relation relations = 6;
  TemporalInfo temporal = 7;
}

message EmbeddingVersion {
  string model_id = 1;
  string model_version = 2;
  repeated float vector = 3;
  uint32 dimension = 4;
  uint32 created_at = 5;
  map<string, string> model_params = 6;
}

message Provenance {
  string source_id = 1;          // Original document/source
  string chunk_id = 2;           // Specific chunk within source
  uint32 chunk_position = 3;     // Position in source
  string extraction_method = 4;   // How it was extracted
  uint32 extracted_at = 5;       // When extracted
  map<string, string> metadata = 6; // Additional provenance data
}
----

*Use Cases*:
- Track multiple embedding versions as models evolve
- Maintain full audit trail of data lineage
- Enable filtering by source or extraction method

*Integration Notes*:
- Protos: add `proximadb.v1.entity` in `proto/proximadb/v1/entity.proto` and import from existing `collection.proto` and `search.proto`.
- Storage: persist `Entity` as the logical record; store vectors in existing engines keyed by `(collection_id, entity_id, model_id, modality)`; keep a thin row-store for the `Entity` header (typed/flexible metadata, temporal, provenance) in SST.
- Indexing: extend `IndexConfig` to allow `name` and `selector` (e.g., `model_id`, `modality`) to map embeddings to indices; maintain one primary index per modality with optional auxiliaries.
- Keys: canonical primary key `entity_id` (string), with partitioning by `source_id` and/or time where configured.
- MVCC: reuse existing MVCC; add `tombstone` at `EmbeddingVersion` granularity for soft-deletes and re-embeds.

#[tonic::async_trait]
impl EntityService for EntityServiceImpl {
    async fn upsert_entity(
        &self,
        request: Request<UpsertEntityRequest>,
    ) -> Result<Response<UpsertEntityResponse>, Status> {
        let req = request.into_inner();
        
        // Validate request
        if req.collection_id.is_empty() {
            return Err(Status::invalid_argument("collection_id is required"));
        }
        
        let entity = req.entity.ok_or_else(|| {
            Status::invalid_argument("entity is required")
        })?;
        
        // Store entity
        match self.store.upsert_entity(&req.collection_id, entity).await {
            Ok(entity_id) => {
                Ok(Response::new(UpsertEntityResponse {
                    success: true,
                    entity_id,
                    message: "Entity upserted successfully".to_string(),
                }))
            }
            Err(e) => {
                Err(Status::internal(format!("Failed to upsert entity: {}", e)))
            }
        }
    }
    
    async fn get_entity(
        &self,
        request: Request<GetEntityRequest>,
    ) -> Result<Response<GetEntityResponse>, Status> {
        let req = request.into_inner();
        
        // Validate
        if req.collection_id.is_empty() || req.entity_id.is_empty() {
            return Err(Status::invalid_argument(
                "collection_id and entity_id are required"
            ));
        }
        
        // Fetch entity
        match self.store.get_entity(
            &req.collection_id,
            &req.entity_id,
            req.include_embeddings,
            req.include_relations,
        ).await {
            Ok(Some(entity)) => {
                Ok(Response::new(GetEntityResponse {
                    entity: Some(entity),
                }))
            }
            Ok(None) => {
                Err(Status::not_found(format!(
                    "Entity {} not found in collection {}",
                    req.entity_id, req.collection_id
                )))
            }
            Err(e) => {
                Err(Status::internal(format!("Failed to get entity: {}", e)))
            }
        }
    }
    
    async fn delete_entity(
        &self,
        request: Request<DeleteEntityRequest>,
    ) -> Result<Response<DeleteEntityResponse>, Status> {
        let req = request.into_inner();
        
        // Validate
        if req.collection_id.is_empty() || req.entity_id.is_empty() {
            return Err(Status::invalid_argument(
                "collection_id and entity_id are required"
            ));
        }
        
        // Delete entity
        match self.store.delete_entity(
            &req.collection_id,
            &req.entity_id,
            req.hard_delete,
        ).await {
            Ok(success) => {
                Ok(Response::new(DeleteEntityResponse {
                    success,
                    message: if success {
                        "Entity deleted successfully".to_string()
                    } else {
                        "Entity not found".to_string()
                    },
                }))
            }
            Err(e) => {
                Err(Status::internal(format!("Failed to delete entity: {}", e)))
            }
        }
    }
    
    async fn search_entities(
        &self,
        request: Request<SearchEntitiesRequest>,
    ) -> Result<Response<SearchEntitiesResponse>, Status> {
        let req = request.into_inner();
        
        // Validate
        if req.collection_id.is_empty() {
            return Err(Status::invalid_argument("collection_id is required"));
        }
        
        // Extract query vector
        let query_vector = if let Some(similar) = req.similar {
            match similar.query {
                Some(query) => {
                    // Process query based on type
                    Some(self.process_query(query).await?)
                }
                None => None,
            }
        } else {
            None
        };
        
        // Search
        let results = self.store.search_entities(
            &req.collection_id,
            query_vector,
            req.filters.map(|f| f.into()),
            req.temporal.map(|t| t.into()),
            req.top_k as usize,
        ).await.map_err(|e| {
            Status::internal(format!("Search failed: {}", e))
        })?;
        
        // Convert results
        let entity_results: Vec<EntityResult> = results
            .into_iter()
            .map(|(entity, score)| EntityResult {
                entity: Some(entity),
                score,
                debug_info: Default::default(),
            })
            .collect();
        
        Ok(Response::new(SearchEntitiesResponse {
            results: entity_results,
            total: 0, // Will be populated with actual count
            page_info: None,
            progress: None,
        }))
    }
}

/// POST /api/v1/entities/{collection_id}
pub async fn upsert_entity(
    Path(collection_id): Path<String>,
    State(state): State<EntityState>,
    Json(entity): Json<Entity>,

    // Validate
    if collection_id.is_empty() {
        return Err(ApiError::InvalidArgument(
            "collection_id is required".to_string()
        ));
    }
    
    // Upsert
    let entity_id = state.store

        .await
        .map_err(|e| ApiError::Internal(e.to_string()))?;

        "success": true,
        "entity_id": entity_id,
    })))

/// GET /api/v1/entities/{collection_id}/{entity_id}
pub async fn get_entity(
    Path((collection_id, entity_id)): Path<(String, String)>,
    Query(params): Query<SearchQuery>,
    State(state): State<EntityState>,
) -> ApiResult<Json<EntityResponse>> {
    // Validate
    if collection_id.is_empty() || entity_id.is_empty() {
        return Err(ApiError::InvalidArgument(
            "collection_id and entity_id are required".to_string()
        ));
    }
    
    // Fetch
    let entity = state.store
        .get_entity(
            &collection_id,
            &entity_id,
            params.include_embeddings.unwrap_or(false),
            false, // include_relations
        )
        .await
        .map_err(|e| ApiError::Internal(e.to_string()))?;
    
    match entity {
        Some(e) => Ok(Json(EntityResponse {
            entity: e,
            score: None,
        })),
        None => Err(ApiError::CollectionNotFound(format!(
            "Entity {} not found", entity_id
        ))),
    }
}

/// DELETE /api/v1/entities/{collection_id}/{entity_id}
pub async fn delete_entity(
    Path((collection_id, entity_id)): Path<(String, String)>,
    Query(params): Query<DeleteQuery>,
    State(state): State<EntityState>,
) -> ApiResult<StatusCode> {
    // Validate
    if collection_id.is_empty() || entity_id.is_empty() {
        return Err(ApiError::InvalidArgument(
            "collection_id and entity_id are required".to_string()
        ));
    }
    
    // Delete
    let success = state.store
        .delete_entity(
            &collection_id,
            &entity_id,
            params.hard_delete.unwrap_or(false),
        )
        .await
        .map_err(|e| ApiError::Internal(e.to_string()))?;
    
    if success {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(ApiError::CollectionNotFound(format!(
            "Entity {} not found", entity_id
        )))
    }
}

/// POST /api/v1/search/{collection_id}
pub async fn search_entities(
    Path(collection_id): Path<String>,
    State(state): State<EntityState>,
    Json(request): Json<SearchRequest>,
) -> ApiResult<Json<SearchResponse>> {
    // Validate
    if collection_id.is_empty() {
        return Err(ApiError::InvalidArgument(
            "collection_id is required".to_string()
        ));
    }
    
    // Process query
    let query_vector = if let Some(text) = request.query_text {
        // Generate embedding from text (placeholder)
        Some(vec![0.0; 768]) // Replace with actual embedding
    } else {
        request.query_vector
    };
    
    // Search
    let results = state.store
        .search_entities(
            &collection_id,
            query_vector,
            None, // metadata_filter
            None, // temporal_filter
            request.top_k.unwrap_or(10) as usize,
        )
        .await
        .map_err(|e| ApiError::Internal(e.to_string()))?;
    
    // Convert results
    let items: Vec<EntityResponse> = results
        .into_iter()
        .map(|(entity, score)| EntityResponse {
            entity,
            score: Some(score),
        })
        .collect();
    
    Ok(Json(SearchResponse {
        items,
        total: items.len() as u32,
    }))
}

== Validation and Limits

- Max entity size: 1 MB for header (typed+flexible metadata, provenance); embeddings unbounded but recommend <8 models x 4096 dims.
- Max relations per entity: default 10k; hard cap 1M with paging and degree limiting in traversals.
- Max modalities: 4 (TEXT, IMAGE, AUDIO, VIDEO); extensible via enum but indices required per modality.
- Query limits: `top_k` default 10, max 1000; traversal depth default 2, max 5.
- Write batch: up to 10k entities per request; WAL entry size capped at 16 MB.

== Error Model

- Error envelope contains `code`, `message`, `details`, and `retryable` boolean.
- Common codes: `INVALID_ARGUMENT`, `FAILED_PRECONDITION` (schema/ACL), `NOT_FOUND`, `ALREADY_EXISTS`, `RESOURCE_EXHAUSTED`, `UNAVAILABLE` (retryable), `INTERNAL`.
- Partial success semantics for batch upserts with per-item status; include `failed_indices` for index-level failures.

HTTP mapping:
- 400 → `INVALID_ARGUMENT`, 401 → `UNAUTHENTICATED`, 403 → `PERMISSION_DENIED`, 404 → `NOT_FOUND`, 409 → `ALREADY_EXISTS`, 429 → `RESOURCE_EXHAUSTED`, 503 → `UNAVAILABLE`, 500 → `INTERNAL`.

== Default Configuration

- Progressive search stages: `[candidate_k=200, rerank_k=50]` then `[candidate_k=1000, rerank_k=100]`.
- Typed metadata: no fields by default; recommended to declare high-selectivity fields (author, year).
- Retention: keep last 2 embedding versions per (model, modality); relations TTL none (infinite) unless configured.
- Quantization: enabled by default for embeddings dimension > 2048 with PQ m=64.

=== Storage Layer Changes

[source,mermaid]
----
graph TD
    A[Entity Store] --> B[Vector Storage]
    A --> C[Metadata Store]
    A --> D[Graph Store]
    A --> E[Provenance Store]

*Data Layout*:
- Entity header table (SST): key `(collection_id, entity_id)` → value `{typed_metadata, flexible_metadata, temporal, provenance_summary}`.
- Embeddings table (vector engines): key `(collection_id, entity_id, model_id, modality, version)` → vector payload + small header.
- Relations table (SST): key `(collection_id, entity_id, relation_type, target_id)` → `{weight, created_at, properties}` and reverse index.
- Provenance registry (SST): `source_id` → source attributes; chunk index keyed by `(source_id, chunk_id)`.

=== Query Processing Pipeline

[source,mermaid]
----
sequenceDiagram
    participant Client
    participant Parser
    participant Planner
    participant Executor
    participant Storage
    
    Client->>Parser: SQL Query
    Parser->>Parser: Parse SIMILAR, FOLLOW, ASSEMBLE
    Parser->>Planner: AST
    Planner->>Planner: Optimize query plan
    Planner->>Executor: Execution plan
    Executor->>Storage: Vector search
    Executor->>Storage: Graph traversal
    Executor->>Storage: Context assembly
    Storage-->>Executor: Results
    Executor-->>Client: Assembled response
----

*Planner Steps*:
- Parse SQL-like query → AST; normalize to a canonical template for caching.
- Apply temporal pruning and metadata predicate pushdown using typed/flexible indexes.
- Choose index set by modality/model; if progressive, define stages with `candidate_k` and `rerank_k` per stage.
- Execute vector search → candidate set; expand via `FOLLOW` when present with bounded depth; deduplicate by `entity_id`.
- Assemble context when requested; compute final scores and envelope response.

=== Search Semantics

- Determinism: results are stable under identical inputs; ordering ties resolved by `(score DESC, entity_id ASC)`.
- Scoring: base score is distance similarity; optional re-rankers (e.g., metadata priors) apply linear combination with documented weights.
- Pagination: opaque `cursor` encodes query hash, last entity_id, and last score; server verifies hash to prevent drift.
- Consistency: read-your-writes within a session (best-effort) via same-node affinity; eventual consistency across nodes.

== Consistency and Transactions

- Write path: append to WAL with a composite record `{entity, embeddings[], relations[]}`; perform storage updates; mark commit when all sub-stores ack or schedule repair.
- Idempotency: deduplicate by `(collection_id, entity_id, client_op_id)` when provided.
- Repairer: background task reconciles mismatches across stores using WAL.

== Security and Access Control

- Multi-tenant isolation via `tenant_id` carried in collection and all keys.
- ACLs: collection-level roles (admin, writer, reader) and optional row-level filters expressed as metadata predicates.
- Audit: provenance changes and relation mutations are audited with actor and timestamp.

== Observability

- Metrics: `sks_search_latency_ms`, `sks_traversal_nodes_visited`, `sks_context_segments`, `sks_index_hit_ratio`, `sks_compactions_total`.
- Tracing: spans for `parse`, `plan`, `vector_search`, `graph_traverse`, `assemble`, `commit` with entity_id tags (hashed).
- Logs: structured JSON with op ids; sampling for high-volume search paths.

== Data Lifecycle

- Retention: per-collection policies for embeddings history, relations TTL, provenance retention.
- Compaction windows: daily for metadata/relations, weekly for embeddings if cold.
- Export: snapshot APIs to materialize entities and relations for offline analysis.

== Configuration Keys

- `sks.enabled` (bool, default false): enable SKS features per collection.
- `sks.progressive.default_stages` (array): e.g., `[{candidate_k:200, rerank_k:50}, {candidate_k:1000, rerank_k:100}]`.
- `sks.relations.max_degree` (int, default 10000): hard cap per relation type.
- `sks.temporal.partition_granularity` (enum day|hour, default day).
- `sks.metadata.auto_index.threshold` (int, default 100) and `miss_ratio` (float, default 0.95).
- `sks.embeddings.retention.versions` (int, default 2) or `ttl_days`.
- `sks.quantization.auto` (bool, default true) with overrides under `collection.index_configs`.

== Performance Considerations

=== Storage Overhead

* **Entity Model**: ~15% overhead for provenance and relations
* **Multi-Embeddings**: Linear with number of models (mitigated by compression)
* **Graph Index**: O(E) space for E edges (use sparse representation)

=== Query Performance

* **SIMILAR**: Maintain existing sub-millisecond latency
* **FOLLOW**: Graph traversal in O(k*d) for depth d, degree k
* **ASSEMBLE**: Document reconstruction in O(n log n) for n chunks
* **Temporal**: Time-range index for O(log t) lookup

=== Optimization Strategies

1. **Hierarchical Caching**: Entity → Embedding → Index
2. **Lazy Loading**: Load relations/provenance on demand
3. **Partition Pruning**: Time-based and source-based partitions
4. **Adaptive Compression**: Compress cold embeddings more aggressively

=== Common Pitfalls to Avoid

1. **Don't create backward compatibility layers** - This is Release 1
2. **Don't use mocks** - Use real storage engines (SST + VIPER)
3. **Don't forget hardware initialization** in tests
4. **Don't use release builds** during development (slow)
5. **Don't create new filter types** - Reuse existing `protocol_conversions`
6. **Don't use wrong storage engine** - SST for metadata, VIPER for vectors
7. **Don't skip quantization** - Use SMART_DEFAULTS for automatic config
8. **Don't ignore bloom filters** - They reduce search space by 95%
9. **Don't hardcode dimensions** - Support variable dimensions per model
10. **Don't mix storage engines** - Keep consistent engine per data type
