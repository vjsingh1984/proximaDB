== Overview

This guide covers ProximaDB's multi-disk persistence system configuration for enhanced performance, scalability, and fault tolerance through intelligent data distribution across multiple storage devices.

image::multi_disk_architecture.svg[Multi-Disk Architecture,800,600]

== Architecture Benefits

=== Performance & Reliability
* **Parallel I/O Operations**: Concurrent read/write across multiple disks
* **Load Distribution**: Round-robin collection assignment
* **Fault Tolerance**: Disk failure isolation with automatic recovery
* **Scalable Throughput**: Linear performance scaling with additional disks

=== Cloud Integration
* **Multi-Cloud Support**: AWS S3, Azure Blob, Google Cloud Storage
* **Hybrid Deployments**: Local high-performance with cloud backup
* **Elastic Scaling**: Dynamic storage resource addition

== Core Configuration

=== Basic Multi-Disk Setup

[source,toml]
----
# Multi-disk WriteBuffer configuration
[storage.wal_config]
wal_urls = [
"file:///data/disk1/wal",
"file:///data/disk2/wal",
"file:///data/disk3/wal"
]
distribution_strategy = "LoadBalanced"
collection_affinity = true
memory_flush_size_bytes = 1048576 # 1MB
global_flush_threshold = 536870912 # 512MB

# Storage layout per disk
[[storage.storage_layout.base_paths]]
base_dir = "/data/disk1/storage"
instance_id = 1
mount_point = "/mnt/disk1"
disk_type = { NvmeSsd = { max_iops = 100000 } }
capacity_config = { max_wal_size_mb = 2048, metadata_reserved_mb = 512, warning_threshold_percent = 85.0 }

[[storage.storage_layout.base_paths]]
base_dir = "/data/disk2/storage"
instance_id = 2
mount_point = "/mnt/disk2"
disk_type = { NvmeSsd = { max_iops = 100000 } }
capacity_config = { max_wal_size_mb = 2048, metadata_reserved_mb = 512, warning_threshold_percent = 85.0 }

# Metadata backend (on fastest disk)
[storage.metadata_backend]
backend_type = "filestore"
storage_url = "file:///data/disk1/metadata"
cache_size_mb = 128
flush_interval_secs = 30
----

=== Distribution Strategies

[source,toml]
----
[storage.wal_config]
# Available strategies
distribution_strategy = "LoadBalanced" # Round-robin (default)
distribution_strategy = "HashBased" # Consistent hashing
distribution_strategy = "PerformanceBased" # Fastest disk first

# Collection affinity
collection_affinity = true # Same collection → same disk
collection_affinity = false # Maximum distribution
----

=== Disk Type Configuration

[source,toml]
----
# Performance tiers
disk_type = { NvmeSsd = { max_iops = 100000 } } # Highest performance
disk_type = { SataSsd = { max_iops = 50000 } } # High performance
disk_type = { Hdd = { max_iops = 1000 } } # High capacity
disk_type = { NetworkStorage = { latency_ms = 5.0 } } # Cloud storage
----

== Cloud Storage Configuration

=== Multi-Cloud Setup

[source,toml]
----
[storage.wal_config]
wal_urls = [
"file:///mnt/nvme1/wal", # Local NVMe
"s3://proximadb-wal/cluster1", # AWS S3
"adls://storage.dfs.core.windows.net/wal", # Azure Data Lake
"gcs://proximadb-gcs/wal" # Google Cloud
]
distribution_strategy = "LoadBalanced"
----

== Performance Tuning

=== WriteBuffer Optimization
[source,toml]
----
[storage.wal_config]
# Flush threshold tuning
memory_flush_size_bytes = 1048576 # 1MB - frequent small flushes
memory_flush_size_bytes = 16777216 # 16MB - balanced performance
memory_flush_size_bytes = 67108864 # 64MB - maximum batch size

# Memory management
global_flush_threshold = 536870912 # 512MB - conservative
global_flush_threshold = 2147483648 # 2GB - aggressive
----

=== Disk-Specific Optimization
[source,toml]
----
# NVMe optimization
[[storage.storage_layout.base_paths]]
disk_type = { NvmeSsd = { max_iops = 1000000 } }

max_wal_size_mb = 20480, # 20GB WriteBuffer

max_wal_size_mb = 1024, # 1GB WriteBuffer
warning_threshold_percent = 80.0 # Conservative on network
}
----

== Monitoring and Maintenance

=== Health Check Commands
[source,bash]
----
# Assignment service status
curl http://localhost:5678/health/assignment

# Assignment statistics
curl http://localhost:5678/admin/assignment/stats

# Storage usage
curl http://localhost:5678/admin/storage/usage

# Check distribution balance
curl http://localhost:5678/admin/assignment/stats | jq '.wal.directory_distribution'
----

=== Log Monitoring
[source,bash]
----
# Assignment service logs
tail -f /var/log/proximadb/server.log | grep "assignment"

# Multi-disk operations
tail -f /var/log/proximadb/server.log | grep "multi-disk\|round-robin"

# WriteBuffer operations
tail -f /var/log/proximadb/server.log | grep "flush\|WriteBuffer"
----

=== Disk Usage Monitoring
[source,bash]
----
# Check all configured disks
for disk in /data/disk1 /data/disk2 /data/disk3; do
echo "=== $disk ==="
df -h $disk
du -sh $disk/wal $disk/storage $disk/metadata 2>/dev/null
done
----

== Troubleshooting

=== Common Issues

==== Assignment Service Problems
[source,bash]
----
# Check service initialization
grep "RoundRobinAssignmentService" /var/log/proximadb/server.log

# Verify permissions
ls -la /data/disk*/wal /data/disk*/storage

# Test directory creation
sudo -u proximadb mkdir -p /data/disk1/wal/test_collection
----

==== URL Configuration Errors
[source,bash]
----
# Check for parsing errors
grep "No such file or directory" /var/log/proximadb/server.log

# Verify URL format
# Correct: file:///data/disk1/wal
# Incorrect: file://data/disk1/wal (missing slash)
----

==== Distribution Problems
[source,bash]
----
# Check assignment distribution
curl http://localhost:5678/admin/assignment/stats | jq '.wal.directory_distribution'

# Good distribution example across 3 disks:
# {"0": 5, "1": 4, "2": 4} # Even distribution
# {"0": 13, "1": 0, "2": 0} # Investigate poor distribution
----

=== Recovery Procedures

==== Disk Failure Recovery
1. **Identify Failed Disk**: Monitor alerts and check disk health
2. **Replace Disk**: Install new disk at same mount point
3. **Restore Data**: From backups or replicas if available
4. **Verify Recovery**: Assignment service auto-discovers new layout

==== Performance Issues
* **Disk I/O Bottlenecks**: Use `iostat`, `iotop` to identify issues
* **Memory Pressure**: Adjust `memory_flush_size_bytes` and `global_flush_threshold`
* **Network Latency**: Increase timeout values, use regional storage

== Best Practices

=== Configuration
1. **Consistent Naming**: Use consistent path conventions across environments
2. **Environment Separation**: Different configs for dev/staging/prod
3. **Version Control**: Keep configurations in source control
4. **Documentation**: Maintain disk assignment documentation

=== Operations
1. **Health Monitoring**: Regular SMART checks and disk health monitoring
2. **Capacity Planning**: Monitor usage trends and plan for growth
3. **Recovery Testing**: Regular backup and recovery procedure validation
4. **Performance Baselines**: Establish monitoring baselines

=== Security
1. **Encryption**: Enable disk encryption or cloud provider encryption
2. **Network Security**: Use VPCs/VNETs for cloud deployments
3. **Access Control**: Proper file system permissions
4. **Audit Logging**: Enable for compliance requirements

== URL Schemes Reference

* **Local Filesystem**: `file:///path/to/directory`
* **AWS S3**: `s3://bucket-name/prefix`
* **Azure Blob**: `adls://account.dfs.core.windows.net/container/prefix`
* **Google Cloud**: `gcs://bucket-name/prefix`
* **HDFS**: `hdfs://namenode:port/path` (future support)
