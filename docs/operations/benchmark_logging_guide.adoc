:toc-placement: preamble

[.lead]
Guidelines for proper logging in ProximaDB benchmarks to maintain clean console output while preserving detailed debugging information.

== Logging Principles

=== Console Output (eprintln!)
Use `eprintln!` for information users need to see during benchmark execution:

[horizontal]
**Test Progress**:: Test names, completion status, overall progress
**Important Metrics**:: Final results, compression ratios, performance summaries
**Warnings/Errors**:: Critical issues that affect benchmark validity
**System Info**:: Hardware details, configuration settings

.Example: Keep these as eprintln!
[source,rust]
----
eprintln!("    ✅ FOUND: Pure search returned {} results in {}ms", count, time_ms);
eprintln!("    ⚠️  WARNING: Expected <= 10 results, got {}", results.len());
eprintln!("=== Compression Ratio Test: {}x{} ===", vectors, dimensions);
----

=== Debug Tracing (tracing::debug!)
Use `tracing::debug!` for detailed information that clutters console output:

[horizontal]
**Search Result Details**:: Individual vector IDs, distances, similarities
**Metadata Content**:: Key-value pairs from result metadata
**Internal State**:: Validation details, intermediate calculations
**Verbose Success Messages**:: Detailed confirmation messages

.Example: Convert these to debug!
[source,rust]
----
// Before (clutters console)
eprintln!("       Result {}: ID={}, score={:.6}, similarity={:.6}",
         i, result.id, result.score, result.similarity);

// After (clean console, available in debug logs)
debug!("Result {}: ID={}, distance={:.6}, similarity={:.6}",
       i, result.id, result.score, result.similarity);
----

== Search Results Interpretation

=== Understanding Metrics

[IMPORTANT]
====
**ProximaDB Search Metrics**:

* **Score** = Distance (0.0 = perfect match, higher = less similar)
* **Similarity** = Computed similarity measure (higher = more similar)
* **Distance 0.0** means exact vector match
* **Distance > 0** means vectors differ by that amount
====

This explains the counter-intuitive results:
- `score=1.000000, similarity=0.000000` → Perfect match (distance=0)
- `score=0.044359, similarity=21.543369` → Different vectors

=== Console Output Standards

[horizontal]
**Keep as eprintln!**::
- Test progress indicators
- Final benchmark results
- Warning and error messages
- System configuration info

**Convert to debug!**::
- Individual search result details
- Metadata content display
- Internal validation messages
- Verbose success confirmations

== Usage Examples

=== Running with Debug Logs
[source,bash]
----
# Console output only (clean)
cargo bench --bench bench_04_storage_unified

# Console + debug logs
RUST_LOG=debug cargo bench --bench bench_04_storage_unified

# Specific module debugging
RUST_LOG=proximadb::benches=debug cargo bench --bench bench_04_storage_unified
----

=== Expected Output Reduction

[horizontal]
**Before**:: 50+ lines of search result details per test
**After**:: 3-5 lines of summary per test
**Debug Mode**:: Full details available via RUST_LOG=debug

== Benefits

[horizontal]
**Clean Console**:: Focus on metrics and progress, not verbose details
**Better Performance**:: Reduced I/O overhead during benchmarking
**Selective Debugging**:: Enable detailed logs only when needed
**Professional Output**:: Production-ready benchmark reporting
