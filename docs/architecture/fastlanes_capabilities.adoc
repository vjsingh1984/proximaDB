FastLanes provides unified, high-performance block storage infrastructure with automatic optimization capabilities for ProximaDB storage engines. This guide demonstrates how to leverage FastLanes' built-in features instead of implementing them manually in SST, SWIFT, and other storage engines.

**Key Benefits:** 50-90% code reduction, consistent optimization, automatic hardware acceleration, zero-copy operations, and integrated cloud caching through UnifiedCachingFilesystem.
****

== Overview

=== What is FastLanes?

FastLanes is ProximaDB's **unified storage block architecture** that provides automatic optimization capabilities across all storage engines (SST, SWIFT, HELIX). It eliminates the need for manual implementation of common storage engine features and integrates seamlessly with UnifiedCachingFilesystem for cloud storage optimization.

== Automatic Features Reference

=== 🔍 Automatic Bloom Filter Generation

FastLanes automatically creates optimized bloom filters for existence checks, eliminating manual bloom filter implementation.

==== What FastLanes Provides Automatically
* **Optimal sizing** based on record count
* **False positive rate optimization** for your data characteristics
* **Memory-efficient storage** (<1% of block size)
* **Dual bloom filters** for both IDs and metadata

==== Usage Example
[source,rust]
----
// ✅ FastLanes automatically generates bloom filters
let block = FastLanesDataBlock::new(records, compression_config);

// ✅ Use built-in existence checking (O(1) operation)
if block.contains_id("vector_123") {
    // Block likely contains this ID
    let record = block.find_record_by_id("vector_123");
} else {
    // Block definitely doesn't contain this ID - skip I/O!
}

// ✅ Access auto-generated bloom filters directly
let id_bloom = &block.bloom_filter;         // For ID existence
let metadata_bloom = &block.block_bloom_filter; // For metadata filtering
----

==== Performance Impact
* **95%+ query speedup** for non-existent IDs
* **Reduced I/O** by skipping irrelevant blocks
* **Memory efficient** bloom filter sizing

==== What FastLanes Provides Automatically
* **Min/max values** for every metadata column
* **Null count tracking** for data quality insights
* **Record count and size estimates**
* **Compression ratio calculations**
* **Column cardinality statistics**

==== Usage Example

=== 📝 Automatic Range Tracking

FastLanes automatically tracks ID and timestamp ranges for efficient query pruning.

==== What FastLanes Provides Automatically
* **Sorted ID ranges** (min_id, max_id) for pruning
* **Timestamp ranges** (min_ts, max_ts) for temporal queries
* **O(1) range checking** without scanning block contents
* **Automatic sorting** and boundary detection

==== Usage Example
[source,rust]
----
// ✅ FastLanes automatically calculates ranges during construction
let block = FastLanesDataBlock::new(records, compression_config);

// ✅ Use auto-generated ranges for query pruning
let (min_id, max_id) = &block.id_range;
let (min_ts, max_ts) = &block.timestamp_range;

// ✅ Efficient query pruning without scanning block
if query_id >= min_id && query_id <= max_id {
    // Block might contain the ID - proceed with search
    search_block(&block, query_id);
} else {
    // Block definitely doesn't contain ID - skip entirely
    skip_block();
}

// ✅ Temporal query optimization
if query_timestamp >= min_ts && query_timestamp <= max_ts {
    // Block contains records in time range
    process_temporal_query(&block, query_timestamp);
}
----

=== 🧠 Automatic Delete Detection

FastLanes automatically identifies tombstone records and sets optimization flags.

==== What FastLanes Provides Automatically
* **Tombstone detection** by scanning for `"_deleted": "true"` metadata
* **has_deletes flag** for compaction optimization
* **Skip-ahead capabilities** during queries when no deletes present

==== Usage Example
[source,rust]
----
// ✅ FastLanes automatically detects deletes during construction
let block = FastLanesDataBlock::new(records, compression_config);

// ✅ Use auto-detected delete information for optimization
if !block.has_deletes {
    // No tombstones in this block - use fast path
    fast_query_path(&block);
} else {
    // Block contains deletes - use filtered query path
    filtered_query_path(&block);
}

// ✅ Compaction optimization
if block.has_deletes && block.metadata.record_count < threshold {
    // Block is sparse due to deletes - schedule for compaction
    schedule_compaction(&block);
}
----

=== ⚡ Automatic SIMD Encoding Selection

FastLanes automatically analyzes data characteristics and chooses optimal SIMD encoding.

==== What FastLanes Provides Automatically
* **Data characteristic analysis** (range, distribution, patterns)
* **Optimal encoding selection** (BitPacked, Delta, FrameOfReference)
* **SIMD optimization** for hardware acceleration
* **Encoding metadata generation** for decoder configuration

==== Usage Example
[source,rust]
----
// ✅ FastLanes automatically chooses optimal encoding
let block = FastLanesDataBlock::new(records, compression_config);

// ✅ Inspect auto-selected encoding
match block.encoding_marker {
    0x10 => println!("Auto-selected: BitPacked encoding for SIMD"),
    0x20 => println!("Auto-selected: Delta encoding for sequential data"),
    0x30 => println!("Auto-selected: Frame-of-Reference for small ranges"),
    _ => println!("Auto-selected: Raw encoding for complex data"),
}

// ✅ Access encoding metadata for performance insights
if let Some(ref metadata) = block.encoding_metadata {
    println!("Compression ratio: {:.2}", metadata.compression_ratio);
    println!("SIMD optimization: {} bits per value", metadata.range_bits);
}

=== Caching Strategy for FastLanes Blocks

==== Metadata Cache (Always Hot)
* **Bloom Filters**: 4KB per file, always cached
* **Block Index**: 60KB per file, frequently accessed
* **Statistics**: Column min/max, ranges, always available
* **TTL**: 3600 seconds default, configurable per workload

==== Disk Cache (Local Mirror)
* **Hot Blocks**: Frequently accessed FastLanes blocks
* **Cloud Files**: Local copies of S3/Azure/GCS objects
* **Compression**: Maintains FastLanes compression on disk
* **Eviction**: LRU with frequency tracking

==== Prefetch Strategy
* **Sequential Detection**: Identifies sequential block access
* **Pattern Learning**: Learns query patterns per collection
* **Predictive Loading**: Prefetches likely next blocks
* **Bandwidth Optimization**: Batches cloud requests

=== Usage Examples

// Configure for cloud workload

== Conclusion

FastLanes provides comprehensive automatic capabilities that eliminate the need for manual implementation in storage engines. Combined with UnifiedCachingFilesystem, it delivers:

1. **Automatic Optimization**: Bloom filters, statistics, and encoding selection without manual code
2. **Unified Caching**: Single cache layer for all storage backends with intelligent prefetching
3. **Cloud Optimization**: Local disk caching and bandwidth optimization for S3/Azure/GCS
4. **Zero-Copy Operations**: Memory-mapped access and direct buffer processing
5. **Engine Composition**: Clean integration pattern that preserves engine-specific optimizations

By following the composition pattern demonstrated by HELIX and leveraging UnifiedCachingFilesystem, storage engines achieve significant code reduction while gaining consistent optimization and performance benefits across local and cloud storage.

The key is to **leverage FastLanes capabilities** rather than **reimplementing them manually**, and to **utilize UnifiedCachingFilesystem** for all I/O operations to benefit from automatic caching and optimization.
