ProximaDB's unified bloom filter architecture provides a polymorphic, strategy-based design that eliminates code duplication and enables efficient filtering across all storage engines.

== Overview

The bloom filter architecture was completely redesigned to address multiple implementations that had emerged organically throughout the codebase. The new unified design provides:

* **Single trait interface** for all bloom filter operations
* **Strategy pattern** for different implementation needs
* **Factory pattern** for consistent creation
* **Type-safe serialization** with version control
* **Zero code duplication** across storage engines

== Architecture

=== Core Trait Design

[source,rust]
----
pub trait BloomFilterStrategy: Send + Sync {
    fn insert(&mut self, key: &[u8]);
    fn might_contain(&self, key: &[u8]) -> bool;
    fn clear(&mut self);
    fn false_positive_rate(&self) -> f64;
    fn serialize(&self) -> Result<Vec<u8>>;
    fn approximate_memory_usage(&self) -> usize;
}

=== Strategy Implementations

==== ByteAligned Strategy

Optimized for disk persistence in SSTable files:

[source,rust]
----
pub struct ByteAlignedBloomFilter {
    bits: Vec<u8>,
    num_bits: u32,
    num_hashes: u32,
}
----

* **Use Case**: SST SSTable storage
* **Benefits**: Efficient disk I/O, byte-aligned access
* **Memory**: ~10 bits per key for 1% false positive rate

==== BitPacked Strategy

Memory-efficient implementation for in-memory structures:

[source,rust]
----
pub struct BitPackedBloomFilter {
    bits: Vec<u64>,
    num_bits: usize,
    num_hashes: u32,
    items_added: u32,
}
----

* **Use Case**: Memtable filtering
* **Benefits**: 64-bit word operations, cache-friendly
* **Memory**: Minimal overhead with bit packing

==== Simple Strategy

Fast implementation for small datasets:

[source,rust]
----
pub struct SimpleBloomFilter {
    bits: Vec<bool>,
    size: usize,
}
----

* **Use Case**: Small collections, testing
* **Benefits**: Simple logic, fast for <1000 items
* **Trade-offs**: Higher memory usage

==== Composite Strategy

Metadata-aware filtering with multiple sub-filters:

[source,rust]
----
pub struct CompositeBloomFilter {
    key_filter: Box<dyn BloomFilterStrategy>,
    metadata_filters: HashMap<String, Box<dyn BloomFilterStrategy>>,
}
----

* **Use Case**: VIPER engine metadata filtering
* **Benefits**: Column-specific filtering, predicate pushdown
* **Features**: Dynamic metadata column tracking

==== NoOp Strategy

Edge case handling for disabled or empty filters:

[source,rust]
----
pub struct NoOpBloomFilter;

impl BloomFilterStrategy for NoOpBloomFilter {
    fn might_contain(&self, _key: &[u8]) -> bool {
        true  // Always check actual data
    }
}
----

* **Use Case**: Disabled filters, empty collections
* **Benefits**: Zero memory usage, consistent API
* **Behavior**: Conservative (always returns true)

== Factory Pattern

=== BloomFilterFactory

[source,rust]
----
pub struct BloomFilterFactory;

impl BloomFilterFactory {
    pub fn create(config: &BloomFilterConfig) -> Box<dyn BloomFilterStrategy> {
        // Handle edge cases first
        if !config.enabled || config.expected_items == 0 {
            return Box::new(NoOpBloomFilter);
        }
        
        match config.strategy {
            BloomStrategy::ByteAligned => {
                Box::new(ByteAlignedBloomFilter::new_with_config(config))
            }
            BloomStrategy::BitPacked => {
                Box::new(BitPackedBloomFilter::new(
                    config.expected_items,
                    config.false_positive_rate.unwrap_or(0.01)
                ))
            }
            BloomStrategy::Simple => {
                Box::new(SimpleBloomFilter::new(config.expected_items))
            }
            BloomStrategy::Composite => {
                Box::new(CompositeBloomFilter::new_with_config(config))
            }
        }
    }
}
----

            data: filter.serialize()?,

            BloomStrategy::ByteAligned => {
                ByteAlignedBloomFilter::deserialize(&self.data)?
            }
            // ... other strategies
        };
        Ok(filter)
    }
}

== Hash Functions

=== MurmurHash3 Implementation

[source,rust]
----
pub fn murmur_hash(key: &[u8], seed: u32) -> u32 {
    let mut h = seed;
    
    for chunk in key.chunks(4) {
        let mut k = 0u32;
        for (i, &byte) in chunk.iter().enumerate() {
            k |= (byte as u32) << (i * 8);
        }
        
        k = k.wrapping_mul(0xcc9e2d51);
        k = k.rotate_left(15);
        k = k.wrapping_mul(0x1b873593);
        
        h ^= k;
        h = h.rotate_left(13);
        h = h.wrapping_mul(5).wrapping_add(0xe6546b64);
    }
    
    h ^= key.len() as u32;
    h = h.wrapping_mul(0x85ebca6b);
    h ^= h >> 13;
    h = h.wrapping_mul(0xc2b2ae35);
    h ^= h >> 16;
    
    h
}
----

=== Double Hashing

[source,rust]
----
fn get_hash_indices(&self, key: &[u8], num_bits: usize) -> Vec<usize> {
    let h1 = murmur_hash(key, 0);
    let h2 = murmur_hash(key, h1);
    
    (0..self.num_hashes)
        .map(|i| {
            let hash = h1.wrapping_add(i.wrapping_mul(h2));
            (hash as usize) % num_bits
        })
        .collect()
}

== Edge Cases and Error Handling

=== Division by Zero Protection

[source,rust]
----
impl ByteAlignedBloomFilter {
    pub fn new(mut num_bits: u32, num_hashes: u32) -> Self {
        // Ensure minimum size to prevent division by zero
        if num_bits == 0 {
            num_bits = 64;  // Minimum viable size
        }
        
        // Round up to byte boundary
        let num_bytes = ((num_bits + 7) / 8) as usize;
        
        Self {
            bits: vec![0; num_bytes],
            num_bits,
            num_hashes: num_hashes.max(1),  // At least one hash
        }
    }
}

== Best Practices

1. **Choose the Right Strategy**:
   - Use ByteAligned for disk storage
   - Use BitPacked for in-memory structures
   - Use Composite for metadata filtering
   - Use Simple only for very small datasets

2. **Configure Appropriately**:
   - Set realistic expected_items counts
   - Use 10 bits per key for 1% false positive rate
   - Enable only when beneficial (>100 items)

3. **Handle Edge Cases**:
   - Always check filter.enabled before creating
   - Use NoOpBloomFilter for disabled/empty cases
   - Validate configuration before use

4. **Monitor Performance**:
   - Track false positive rates in production
   - Monitor memory usage
   - Adjust parameters based on workload

== Conclusion

The unified bloom filter architecture successfully consolidates multiple implementations into a single, extensible design. The strategy pattern provides flexibility while maintaining type safety, and the factory pattern ensures consistent usage across all storage engines. This design eliminates code duplication, improves maintainability, and provides better performance through specialized implementations.
