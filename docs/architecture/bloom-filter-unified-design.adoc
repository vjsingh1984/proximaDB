= Bloom Filter Unified Design
:toc: left
:imagesdir: ../diagrams/images

ProximaDB's unified bloom filter architecture provides a polymorphic, strategy-based design for efficient filtering across all storage engines.

== Overview

Unified design providing:
* Single trait interface for all bloom filter operations
* Strategy pattern for different storage engines
* Factory pattern for consistent creation
* Type-safe serialization with version control

image::bloom-filter-architecture.svg[Bloom Filter Architecture]

== Core Architecture

=== Trait Interface

[source,rust]
----
pub trait BloomFilterStrategy: Send + Sync {
fn insert(&mut self, key: &[u8]);
fn might_contain(&self, key: &[u8]) -> bool;
fn clear(&mut self);
fn false_positive_rate(&self) -> f64;
fn serialize(&self) -> Result<Vec<u8>>;
fn approximate_memory_usage(&self) -> usize;
}
----

=== Strategy Implementations

==== ByteAligned Strategy
* **Use Case**: SST storage (disk persistence)
* **Benefits**: Efficient disk I/O, byte-aligned access
* **Memory**: ~10 bits per key for 1% false positive rate

==== BitPacked Strategy  
* **Use Case**: Memtable filtering (in-memory)
* **Benefits**: 64-bit word operations, cache-friendly
* **Memory**: Minimal overhead with bit packing

==== Composite Strategy
* **Use Case**: VIPER engine metadata filtering
* **Benefits**: Column-specific filtering, predicate pushdown
* **Features**: Dynamic metadata column tracking

==== NoOp Strategy
* **Use Case**: Disabled filters, empty collections
* **Benefits**: Zero memory usage, consistent API

== Factory Pattern

=== BloomFilterFactory

[source,rust]
----
impl BloomFilterFactory {
    pub fn create(config: &BloomFilterConfig) -> Box<dyn BloomFilterStrategy> {
        if !config.enabled || config.expected_items == 0 {
            return Box::new(NoOpBloomFilter);
        }
        
        match config.strategy {
            BloomStrategy::ByteAligned => Box::new(ByteAlignedBloomFilter::new_with_config(config)),
            BloomStrategy::BitPacked => Box::new(BitPackedBloomFilter::new(/* ... */)),
            BloomStrategy::Composite => Box::new(CompositeBloomFilter::new_with_config(config)),
        }
    }
}
----

=== Configuration

Strategies: `ByteAligned`, `BitPacked`, `Composite`
Settings: `enabled`, `expected_items`, `false_positive_rate`, `bits_per_key`

== Storage Engine Integration

=== SST Engine
Uses ByteAligned filters for SSTable files with ~10 bits per key.

=== VIPER Engine  
Uses Composite filters for metadata-aware filtering and predicate pushdown.

=== Memtable Integration
Uses BitPacked filters for memory efficiency with configurable false positive rates.

== Serialization

Type-safe serialization format with versioning support:
* Version tracking for backward compatibility
* Strategy-specific deserialization
* Optional metadata storage

== Hash Functions

Uses MurmurHash3 with double hashing strategy for uniform distribution across all bit positions.

== Error Handling

* **Division by Zero Protection**: Minimum viable sizes enforced
* **Empty Filter Handling**: NoOpBloomFilter for disabled/empty cases  
* **Configuration Validation**: Checks before filter creation

== Best Practices

* **Strategy Selection**: ByteAligned for disk, BitPacked for memory, Composite for metadata
* **Configuration**: Set realistic expected_items, use 10 bits/key for 1% FPR, enable only when beneficial (>100 items)
* **Edge Cases**: Check enabled before creating, use NoOpBloomFilter for disabled/empty cases
* **Monitoring**: Track false positive rates and memory usage in production
