== Usage Patterns

=== Basic Operations
[source,rust]
----
// Create filter
let filter = BloomFilterFactory::create(&BloomFilterConfig {
    enabled: true,
    strategy: BloomStrategy::ByteAligned,
    bits_per_key: Some(10),
    expected_items: records.len(),
    ..Default::default()
});

// Insert and check
bloom_filter.insert(&record.key);
if bloom_filter.might_contain(&search_key) {
    // Check actual data only if bloom filter says maybe
    if let Some(value) = sstable.get(&search_key) {
        // Found it
    }
}
----

=== Serialization
[source,rust]
----
// Serialize
let serialized = bloom_filter.serialize()?;
metadata.bloom_filter = Some(serialized);

// Deserialize  
if let Some(filter_data) = metadata.bloom_filter {
    let filter = BloomFilterFactory::deserialize(&filter_data, strategy)?;
}
----

== Strategy Selection Guide

[cols="2,3,2,2"]
|===
| Strategy | Use When | Memory/Key | Example

| **ByteAligned**
| Storing in SSTable files
| 10 bits
| `bits_per_key = 10`

| **BitPacked**
| In-memory filtering
| 8-12 bits
| `false_positive_rate = 0.01`

| **Simple**
| < 1000 items
| 8 bytes
| Testing, small collections

| **Composite**
| Metadata queries
| Variable
| VIPER predicate pushdown

| **NoOp**
| Disabled/empty
| 0 bytes
| `enabled = false`
|===

== Configuration Examples

[source,rust]
----
// SSTable storage (1% FPR)
BloomFilterConfig {
    enabled: true,
    strategy: BloomStrategy::ByteAligned,
    bits_per_key: Some(10),
    expected_items: 100_000,
}

// Memory-optimized (2% FPR)
BloomFilterConfig {
    enabled: true,
    strategy: BloomStrategy::BitPacked,
    false_positive_rate: Some(0.02),
    expected_items: 50_000,
}
----

== Performance Notes

* Check bloom filter before expensive disk I/O operations
* Use appropriate strategy for dataset size and memory constraints
* Enable bloom filters for SSTable files with >1000 records
* Monitor false positive rates in production

== Common Pitfalls

* **Wrong Strategy**: Use Simple only for <1000 items, BitPacked for memory, ByteAligned for storage
* **Disabled Filters**: Always check `config.enabled` before operations
* **Tiny Datasets**: Direct HashMap lookup faster for <100 records
* **Memory Overuse**: Monitor memory usage with large datasets

== Debugging

=== Monitor Effectiveness
[source,rust]
----
// Track performance metrics
let effectiveness = bloom_misses as f64 / (bloom_hits + bloom_misses) as f64;
info!("Bloom filter prevented {:.1}% of disk reads", effectiveness * 100.0);

// Log configuration
info!("Bloom filter: strategy={:?}, memory={} bytes, fpr={:.4}",
    config.strategy, filter.approximate_memory_usage(), filter.false_positive_rate());
----

== Migration Checklist

* Choose appropriate strategy for each use case
* Update configuration files with new settings
* Replace old instantiation with factory calls
* Test false positive rates and memory usage
* Remove old implementations
