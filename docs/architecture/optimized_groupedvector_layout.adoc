=== Current Inefficiencies

[horizontal]
**Excessive Metadata**:: 16 bytes per group metadata vs 256 bytes group data (6% overhead)
**Redundant Compression**:: All groups use same algorithm but store it separately
**Memory Fragmentation**:: Metadata scattered throughout the data stream
**Cache Inefficiency**:: Poor spatial locality for metadata access

== Proposed Optimized Layout

=== Option 1: Header-Based Group Compression

[TIP]
====
**Best for**: Uniform compression across all groups (most common case)

Reduces metadata overhead by 75% while maintaining flexibility.
====

[source,text]
----
┌─────────────────────────────────────────────────────────────────────┐
│ HEADER (Unified Compression):                                      │
│   [0x47] 'G' marker                                                │
│   [0x56] 'V' marker  → "GV" = GroupedVector                       │
│   [0x02] Version (optimized)                                       │
│   [u32]  Dimension = 256                                          │
│   [u32]  Count = 16                                               │
│   [u32]  Num Groups = 4                                           │
│   [0x10] Group Compression Algorithm (shared by all groups)        │
│        └─ 0x00=None, 0x10=LZ4, 0x11=Zstd, 0x12=Snappy           │
├─────────────────────────────────────────────────────────────────────┤
│ GROUP 0 (dims 0-63):                                              │
│   [u32] Start Dim = 0                                             │
│   [u32] Group Dims = 64                                           │
│   [u32] Data Size (final size after compression)                   │
│   [bytes] Data (FastLanes encoded, then compressed per header)     │
├─────────────────────────────────────────────────────────────────────┤
│ GROUP 1-3: Similar structure without compression markers...        │
└─────────────────────────────────────────────────────────────────────┘
----

=== Option 2: Bitmap-Based Selective Compression

[TIP]
====
**Best for**: Mixed compression scenarios where some groups benefit more from compression than others.
====

[source,text]
----
┌─────────────────────────────────────────────────────────────────────┐
│ HEADER (Selective Compression):                                    │
│   [0x47] 'G' marker                                                │
│   [0x56] 'V' marker                                                │
│   [0x03] Version (bitmap-based)                                    │
│   [u32]  Dimension = 256                                          │
│   [u32]  Count = 16                                               │
│   [u32]  Num Groups = 4                                           │
│   [0x10] Default Compression Algorithm                             │
│   [0x0C] Compression Bitmap = 1100b (groups 0,1 compressed)       │
│        └─ Bit N set = Group N uses compression                    │
├─────────────────────────────────────────────────────────────────────┤
│ GROUPS: Metadata varies based on bitmap                            │
│   Compressed groups: include original_size                         │
│   Uncompressed groups: omit original_size                          │
└─────────────────────────────────────────────────────────────────────┘
----

== Implementation Strategy

=== Automatic Layout Selection

[source,rust]
----
impl GroupedVectorEncoder {
    fn select_optimal_layout(&self, groups: &[GroupData]) -> LayoutStrategy {
        let compression_ratios: Vec<f32> = groups.iter()
            .map(|group| estimate_compression_ratio(group))
            .collect();

        let variance = calculate_variance(&compression_ratios);
        let avg_ratio = compression_ratios.iter().sum::<f32>() / groups.len() as f32;

        if variance < 0.2 && avg_ratio > 1.5 {
            // Low variance, good compression -> Header-based
            LayoutStrategy::HeaderBased
        } else if variance > 0.5 {
            // High variance -> Bitmap-based
            LayoutStrategy::BitmapBased
        } else {
            // Default to simpler approach
            LayoutStrategy::HeaderBased
        }
    }
}
----
