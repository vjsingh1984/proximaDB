== [0.1.0] - 2025-07-31

=== Major Architecture Achievements

==== Core Vector Database Engine
- *Performance*: 49,000 vectors/second (gRPC), 48 QPS search performance
- *Architecture*: Complete dual-engine system
  * SST Engine: Write-optimized storage with atomic operations
  * VIPER Engine: Analytics-optimized columnar storage
  * DirectVectorService: Direct memtable access for optimal performance
  * UnifiedAtomicCoordinator: ACID transactions across all operations
- *Hardware Acceleration*: Automatic SIMD/AVX-512 and GPU support with fallback

==== AXIS Indexing System ✅
- *Adaptive Selection*: Automatically chooses optimal algorithm (HNSW, IVF, LSH, Annoy)
- *Multi-Algorithm Support*: 4 index types with seamless switching
- *Performance Optimization*: Algorithm selection based on data characteristics
- *Zero-Downtime Migration*: Index type changes without service interruption

==== Comprehensive Distance Metrics
- *13 Hardware-Accelerated Metrics*: Cosine, Euclidean, Manhattan, Hamming, Jaccard, and 8 more
- *SIMD Performance*: 1.3 billion elements/sec (Euclidean), 671M/sec (Cosine)
- *Unified Interface*: Single API for all distance computations
- *Automatic Optimization*: Hardware-specific implementations with fallback

==== Dual Storage Engine System
- *SST Engine*: Directory-based SSTable storage for write-heavy workloads
- *VIPER Engine*: Columnar Parquet storage for analytics and complex queries
- *Engine Routing*: Automatic or manual engine selection per collection
- *Unified Interface*: Common API across both engines
- *Atomic Operations*: Cross-engine transaction support

==== SQL Query Engine
- *Full SQL Support*: Collection name resolution and metadata filtering
- *JSON Operators*: Advanced JSON path queries (`metadata->>'category'`)
- *Vector Similarity*: SQL integration with vector search (`VECTOR_SIMILARITY`)
- *Complex Queries*: AND/OR/NOT operators with proper precedence

== Release Notes

=== Version 0.1.0 Highlights

This initial release establishes ProximaDB as a production-ready, enterprise-grade vector database with comprehensive features and exceptional performance:

==== Dual-Engine Architecture
ProximaDB introduces a unique dual-engine approach:
- **SST Engine**: Optimized for write-heavy workloads with atomic operations
- **VIPER Engine**: Columnar storage for analytics and complex queries
- **Unified Interface**: Single API across both engines with automatic routing

==== AXIS Adaptive Indexing
Revolutionary indexing system that automatically selects the optimal algorithm:
- **HNSW**: High-precision hierarchical graph search
- **IVF**: Large-scale clustering-based search
- **LSH**: Binary and hamming distance optimization
- **Annoy**: Fast tree-based approximate search

==== Hardware Acceleration
Full CPU and GPU acceleration with automatic detection:
- **SIMD Optimization**: AVX-512, ARM NEON support
- **GPU Processing**: CUDA acceleration with CPU fallback
- **Performance**: 1.3 billion elements/sec distance computation

==== Production Features
- **100% Test Success**: 982 tests across Rust and Python
- **ACID Transactions**: Full atomicity with UnifiedAtomicCoordinator
- **Multi-Cloud Support**: AWS S3, Azure Blob, Google Cloud Storage
- **Enterprise Security**: Apache 2.0 license, secure authentication

==== Getting Started
ProximaDB is designed for immediate productivity:

[source,bash]
----
# Quick start with Docker
git clone https://github.com/vjsingh1984/proximadb.git
cd proximadb && docker compose up -d

# Connect with Python client
pip install proximadb
----

[source,python]
----
from proximadb import connect_rest

client = connect_rest("http://localhost:5678")
collection = client.create_collection("my_app", dimension=384)
----
