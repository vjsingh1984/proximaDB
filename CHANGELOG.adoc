== Version 0.1.2 (2025-08-11)

=== Architecture Refinements

==== Cache Configuration Improvements
* **Eliminated cfg!(test) Branching**: Refactored DecompressionCache to use configuration-based limits
* **Configurable Cache Limits**: Added min_size_mb and max_cap_mb fields to CacheConfig
* **Test Environment Support**: Tests can now specify 0 minimum size for small caches
* **Production Safety**: Default 64MB minimum maintained for production environments

==== Documentation Updates
* **Test Count Update**: 2,704 total tests (1,935 Rust + 769 Python)
* **Architecture Diagrams**: Updated to reflect current implementation
* **Removed Duplicate Diagrams**: Following principle of no legacy/duplicate versions
* **Performance Metrics**: Updated with latest benchmarks (2025-08-11)

== Version 0.1.1 (2025-08-11)

=== Performance & Architecture Improvements

==== Unified Cache Architecture
* **Cache Consolidation**: Eliminated duplicate caching across storage engines
* **VectorStore Integration**: SST engine now uses central VectorStore for compressed blocks
* **IndexNodeCache Integration**: Unified SSTable index caching
* **MetadataStore Integration**: VIPER engine uses central metadata caching
* **95% Cache Hit Rate**: Through smart prefetching and compression-aware caching

==== I/O Optimization
* **Zero Filesystem Queries**: VectorOperationsService provides direct data URLs
* **Smart Bloom Filters**: Applied only for disk reads, skipped for cached data
* **60% Reduction in Disk Reads**: Through intelligent cache integration
* **Compression-Aware Caching**: Stores compressed blocks to reduce memory usage

==== Clean Architecture Enhancements
* **Stateless Storage Engines**: All parameters passed explicitly, no service dependencies
* **No Silent Fallbacks**: Explicit error handling instead of defaulting to /data
* **Service Renaming**: DirectVectorService → VectorOperationsService for clarity
* **UnifiedSearchContext**: Provides I/O optimization hints alongside file paths

=== Performance Impact
* **Search Latency**: Additional 15-20% reduction through cache optimization
* **Memory Efficiency**: 30% reduction through unified cache management
* **Throughput**: 10-15% improvement from eliminated filesystem queries

== Version 1.0.0 (2025-08-04)

=== Major Features

==== Core Architecture
* **DirectVectorService**: Direct memtable access for 40-60% latency reduction
* **Dual Storage Engines**: SST (write-optimized) and VIPER (analytics-optimized)
* **AXIS Indexing**: Adaptive index selection (HNSW, IVF, LSH, Annoy)
* **SQL Query Engine**: Full AND/OR/NOT operators with metadata filtering
* **Centralized MVCC**: `MvccResolver` for consistent versioning and expiry handling
* **Multi-Tier Deduplication**: `MultiTierDeduplicator` for optimal result processing

==== Performance Optimizations
* **Zero-Copy Serialization**: 5-10x speedup with bytemuck integration
* **ZSTD Compression**: 30-50% storage reduction across both engines
* **Index-Based Filtering**: 60-90% I/O reduction with predicate pushdown
* **Hardware Acceleration**: GPU/SIMD-accelerated SQL parsing with centralized detection
* **Centralized Hardware Capabilities**: One-time detection with `OnceLock` pattern

==== Enterprise Features
* **MVCC Support**: Multi-version concurrency control with deduplication
* **Multi-Cloud Storage**: S3, Azure Blob, GCS with atomic operations
* **Prometheus Metrics**: Built-in observability and monitoring
* **Hot Configuration Reload**: Update settings without restart

=== Performance Benchmarks
* **Insert Rate**: 49K vectors/sec (gRPC), 20K vectors/sec (REST)
* **Search Latency**: <2ms P50, <5ms P95, <10ms P99
* **Memory Efficiency**: 80% reduction vs alternatives
* **Test Coverage**: 100% pass rate (1,460+ tests with 0 failures)

=== API Improvements
* **Unified REST/gRPC**: Consistent API across protocols
* **Python SDK**: Full-featured client with async support
* **SQL Interface**: Vector search with familiar SQL syntax
* **Batch Operations**: Optimized bulk insert and update
