== 🎯 Executive Summary

=== 📊 Performance at a Glance

[source,python]
----
# Using Python SDK (recommended)
from proximadb import ProximaDBClient
client = ProximaDBClient("http://localhost:5678")

# Or use REST API directly from any language
# POST http://localhost:5678/v1/collections
# POST http://localhost:5678/v1/vectors/insert

# Create a VIPER collection with compression
from proximadb.models import (
    CollectionConfig, CompressionConfig, 
    CompressionAlgorithm, StorageEngine
)

config = CollectionConfig(
    name="products",
    dimension=1536,  # OpenAI embedding size
    storage_engine=StorageEngine.VIPER,  # Columnar analytics engine
    compression=CompressionConfig(
        algorithm=CompressionAlgorithm.ZSTD,
        level=6,  # Balanced compression (1-22)
        enable_quantization=True  # VIPER dual columns (FP32 + quantized)
    )
)
collection = client.create_collection("products", config)

# Insert with 17,000+ vectors/sec throughput
vectors = [{"id": f"p_{i}", "vector": [...], "metadata": {...}} 
           for i in range(10000)]
client.insert_vectors("products", vectors)

# Sub-millisecond semantic search
results = client.search("products", query_vector, top_k=10)
# Returns in <1ms with metadata filtering
----

== 🚀 Technical Excellence

=== Architecture Advantages

**Dual Storage Engine Architecture**
- **VIPER Engine**: Columnar storage optimized for analytics (Parquet-based, PAR1 magic bytes)
- **SST Engine**: Row-based storage optimized for OLTP (SST1 magic bytes, clean format)
- **Automatic Routing**: Queries automatically routed to optimal engine

**Proto-First Design**
- Zero double serialization overhead
- 40-60% latency reduction vs JSON/REST
- Native gRPC streaming support

**Hardware Acceleration**
- Automatic GPU detection and utilization
- SIMD vectorization for all distance metrics
- Cache-aware data structures

=== Supported Capabilities

**13 Distance Metrics** (All hardware accelerated)
- Core: `cosine`, `euclidean`, `dot_product`
- Extended: `manhattan`, `hamming`, `jaccard`, `chebyshev`, `canberra`, `minkowski`
- Specialized: `angular`, `bray_curtis`, `hellinger`, `custom`

**6 Indexing Algorithms**
- `HNSW` - Hierarchical Navigable Small World (best for recall)
- `IVF` - Inverted File Index (balanced performance)
- `PQ` - Product Quantization (memory efficient)
- `FLAT` - Brute force (100% recall)
- `ANNOY` - Approximate Nearest Neighbors (tree-based)
- `LSH` - Locality Sensitive Hashing (sublinear search)

**Storage Formats**
- SST1: Modern SSTable format with intelligent compression
- Parquet: Industry-standard columnar format
- Automatic format detection via magic bytes

== 📊 SQL + Vector Hybrid Queries

ProximaDB uniquely combines SQL with vector operations:

[source,sql]
----
-- Find similar products in a price range
SELECT 
    id, 
    metadata->>'name' as product_name,
    metadata->>'price' as price,
    VECTOR_SIMILARITY(embedding, [0.1, 0.2, ...], 'cosine') as similarity
FROM products
WHERE 
    metadata->>'category' = 'electronics' 
    AND CAST(metadata->>'price' AS DECIMAL) BETWEEN 100 AND 500
ORDER BY similarity DESC
LIMIT 10;
----
