== 🎯 Why ProximaDB?

=== The Vector Database Challenge

Modern AI applications demand vector databases that balance *performance*, *scalability*, and *operational simplicity*. Existing solutions force compromises:

- **Vendor Lock-in**: Cloud providers trap you with proprietary APIs
- **Memory Inefficiency**: Separate memtable implementations waste resources  
- **Search Bottlenecks**: Monolithic engines can't optimize for data location
- **Operational Complexity**: Complex deployments with limited monitoring

=== ProximaDB's Solution

ProximaDB eliminates these trade-offs through revolutionary architectural innovations:

**⚡ 6.10x Performance Breakthrough**:: Storage-aware polymorphic search automatically adapts to data location, delivering 317ms → 52ms search latency with 100% accuracy retention.

**🧠 Unified Memtable Architecture**:: Single memtable system with behavior wrappers eliminates 40% of code duplication while supporting diverse storage backends.

**☁️ True Multi-Cloud Freedom**:: URL-based abstraction (`file://`, `s3://`, `adls://`, `gcs://`) enables zero-downtime cloud migration via configuration changes.

**🤖 ML-Driven Optimization**:: Intelligent K-means++ clustering provides 3-5x storage efficiency for collections >1M vectors with 20% growth threshold retraining.

== 🚀 What is ProximaDB?

ProximaDB is a production-ready, cloud-native vector database built in Rust featuring:

=== Core Innovations

**Unified Memtable System** (link:docs/lld.adoc#unified-memtable-architecture[Details])::
- Single interface supporting SkipList, BTree, HashMap, DashMap backends
- Behavior wrappers for WAL and LSM specialization
- VIPER engine uses pure WAL delegation (no memtable overhead)

**Storage-Aware Polymorphic Search** (link:docs/lld.adoc#storage-aware-polymorphic-search[Details])::
- Automatic engine selection based on data location
- Three-tier search: WAL → VIPER → LSM with result aggregation
- Proven 6.10x performance improvement in production

**Dual Storage Engine Strategy** (link:docs/lld.adoc#storage-engines[Details])::
- *VIPER*: Vector-optimized Parquet with ML clustering
- *LSM*: Row-based SSTable with bloom filters
- Both engines support granular ID-based retrieval

image::Unified_Memtable_Architecture.png[Unified Memtable Architecture,700,align=center]

=== Production-Ready Features

**Multi-Protocol API**:: Simultaneous REST (port 5678) and gRPC (port 5679) with identical feature parity

**Advanced Indexing**:: AXIS+HNSW integration with configurable update modes (Synchronous/Asynchronous/Hybrid)

**Vector Quantization**:: Product, Scalar, and Binary quantization with 4x memory reduction

**Text Processing**:: Built-in chunking with 6 strategies (sentence, paragraph, sliding window, semantic, fixed-size, recursive)

**Enterprise Security**:: TLS 1.3, API key authentication, role-based access control, audit logging

=== Python SDK Example

[source,python]
----
from proximadb import connect_rest, CollectionConfig, DistanceMetric
from sentence_transformers import SentenceTransformer

# Connect to ProximaDB
client = connect_rest("http://localhost:5678")

# Create collection with quantization
config = CollectionConfig(
    dimension=768,
    distance_metric=DistanceMetric.COSINE,
    storage_config={
        "quantization": {"enabled": True, "method": "product", "compression_ratio": 4.0}
    }
)
collection = client.create_collection("documents", config)

# Generate embeddings and insert
model = SentenceTransformer('all-mpnet-base-v2')
texts = ["ProximaDB delivers 6.10x faster search performance"]
embeddings = model.encode(texts).tolist()

client.insert_vectors("documents", embeddings, metadata=[{"category": "performance"}])

# Advanced search with metadata filtering
results = client.search("documents", embeddings[0], k=10)
----

=== Multi-Cloud Configuration

ProximaDB's URL-based storage abstraction enables seamless multi-cloud deployment:

[source,toml]
----
[storage.wal_config]
wal_urls = [
    "file:///mnt/nvme1/wal",               # Local NVMe
    "s3://proximadb-wal/cluster1",         # AWS S3
    "adls://storage.dfs.core.windows.net", # Azure
    "gcs://proximadb-backup/wal"           # Google Cloud
]
----

== 📊 Architecture Deep Dive

=== System Overview

ProximaDB implements a sophisticated three-tier architecture:

image::ProximaDB_Complete_System_Architecture.png[ProximaDB Complete System Architecture,800,align=center]

**Hot Tier (WAL)**:: Immediate vector availability with configurable flush thresholds
**Warm Tier (VIPER)**:: Parquet-based storage with ML clustering optimization  
**Cold Tier (Cloud)**:: Multi-cloud support with automatic tiering

=== WAL Strategy Pattern

The Write-Ahead Log system uses pluggable serialization strategies:

image::ProximaDB_Data_Flow.png[ProximaDB Data Flow,700,align=center]

**Avro Strategy**:: Cross-language compatibility with 35-50% payload reduction vs JSON
**Bincode Strategy**:: Native Rust performance with 8-21% faster batch operations
