== Quick Start

=== Installation

[source,bash]
----
# Docker (Recommended)
docker run -d -p 5678:5678 -p 5679:5679 proximadb/proximadb:latest

# From Source
git clone https://github.com/vjsingh1984/proximaDB
cd proximaDB
cargo run --release --bin proximadb-server
----

=== Basic Usage

[source,bash]
----
# Create collection
curl -X POST http://localhost:5678/v1/collections \
  -H "Content-Type: application/json" \
  -d '{"name": "documents", "dimension": 1536}'

# Insert vectors
curl -X POST http://localhost:5678/v1/collections/documents/vectors \
  -H "Content-Type: application/json" \
  -d '{"vectors": [{"id": "doc1", "values": [0.1, 0.2, ...]}]}'

# Search vectors
curl -X POST http://localhost:5678/v1/collections/documents/search \
  -H "Content-Type: application/json" \
  -d '{"query_vector": [0.1, 0.2, ...], "top_k": 10}'
----

== Why ProximaDB?

ProximaDB is designed for developers building AI applications who need:

* **Automatic Optimization** - No manual tuning required. ProximaDB selects the best storage engine for your workload
* **Real Performance** - Hardware-accelerated vector operations using SIMD (AVX2, AVX512, NEON)
* **Flexible Deployment** - Single binary, Docker, or cloud-native with S3/Azure/GCS support
* **Cost Efficiency** - Advanced quantization reduces storage by 4-32x while maintaining accuracy

== Core Features

=== 6 Auto-Optimized Storage Engines

[cols="2,3,2", options="header"]
|===
|Engine |Optimized For |Characteristics

|**SST**
|Real-time queries, frequent updates
|Row-based LSM tree, write-optimized

|**VIPER**
|Analytics, batch operations
|Columnar Parquet format, high compression

|**NOVA**
|Mixed read/write workloads
|Progressive columnar with zone maps

|**SWIFT**
|Ultra-low latency reads
|ProximaBlocks encoding, cache-optimized

|**RAPTOR**
|Dynamic access patterns
|Adaptive row-group management

|**HELIX**
|Spatial locality queries
|Hilbert curve clustering, PCA reduction
|===

=== Performance Highlights

**Vector Operations** (actual benchmarks on Intel Xeon):

* **128D Cosine**: 20.8M ops/sec with AVX2
* **512D Euclidean**: 3.8M ops/sec with AVX2
* **1536D Dot Product**: 1.2M ops/sec with AVX2

**Storage Performance**:

* Insert throughput: 100K+ vectors/sec
* Search latency: <1ms for cached queries
* Compression: 4-32x with quantization

=== Advanced Features

**Quantization**: Binary, INT8, Product Quantization (PQ4-32) +
**Distance Metrics**: Cosine, Euclidean, Dot, Manhattan, Hamming, Jaccard +
**APIs**: REST (port 5678) and gRPC (port 5679) +
**Metadata Filtering**: SQL-like predicates on vector metadata +
**Cloud Storage**: Native S3, Azure Blob, Google Cloud Storage support

=== Configuration

[source,toml]
----
# config/config.toml
[server]
http_port = 5678
grpc_port = 5679

[storage]
data_dir = "./data"
engine_selection = "auto"

[performance]
enable_simd = true
max_batch_size = 10000
----

== Python SDK

[source,bash]
----
pip install proximadb
----

[source,python]
----
from proximadb import ProximaDB

client = ProximaDB(url="http://localhost:5678")

# Create collection
collection = client.create_collection(
    name="documents",
    dimension=1536,
    engine="auto"  # Let ProximaDB choose
)

# Insert vectors with metadata
collection.insert([
    {
        "id": "doc1",
        "vector": [0.1, 0.2, ...],
        "metadata": {"category": "tech", "date": "2024-01"}
    }
])

# Search with filtering
results = collection.search(
    query_vector=[0.15, 0.25, ...],
    top_k=10,
    filter={"category": "tech"}
)
----

== Production Deployment

=== Docker Compose

[source,yaml]
----
version: '3.8'
services:
  proximadb:
    image: proximadb/proximadb:latest
    ports:
      - "5678:5678"
      - "5679:5679"
    volumes:
      - proximadb_data:/data
      - ./config:/app/config
    environment:
      - RUST_LOG=info

volumes:
  proximadb_data:
----

=== Kubernetes

[source,yaml]
----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: proximadb
spec:
  replicas: 3

    matchLabels:
      app: proximadb

    spec:

            cpu: "1"
