**Unified Vector + Graph Database for AI Applications**

ProximaDB combines semantic vector search with native graph traversal in a single database, eliminating the need to glue together separate systems for RAG, knowledge graphs, and recommendation engines.

== Why ProximaDB?

=== The Problem

Building AI applications today requires multiple databases:

[source,mermaid]
----
%%{init: {"theme": "neutral"}}%%
graph LR
    subgraph TRADITIONAL["Traditional Approach"]
        A[Vector DB] -->|ETL| B[Graph DB]
        B -->|Sync| C[Metadata Store]
        C -->|Join| A
    end

    subgraph PROXIMADB["ProximaDB"]
        D[Unified Engine]
    end

    style TRADITIONAL fill:#ffe6e6,stroke:#e06666
    style PROXIMADB fill:#e6ffe6,stroke:#93c47d
----

* **Vector databases** find similar items but lose relationship context
* **Graph databases** capture relationships but lack semantic understanding
* **Gluing them together** adds latency, complexity, and consistency issues

=== The Solution

ProximaDB provides **hybrid queries** that combine vector similarity with graph traversal:

[source,python]
----
# Find similar papers AND their citation network in one query
results = db.hybrid_search(
    vector=query_embedding,      # Semantic similarity
    graph_traversal="2-hop",     # Relationship context
    filters={"year": ">2020"}    # Metadata constraints
)
# Returns: Similar papers + their citations + shared authors
----

**Result**: Sub-3ms hybrid queries instead of 50-100ms with separate systems.

[source,mermaid]
----

=== Data Flow

1. **Ingest**: Vectors + metadata + relationships stored atomically
2. **Index**: Auto-selected engine builds optimized indexes
3. **Query**: Hybrid search combines similarity + traversal + filters
4. **Return**: Unified results with provenance and relationships

== Quick Start

=== 1. Run ProximaDB

[source,bash]
----
# From source (Rust 1.88+)
git clone https://github.com/vjsingh1984/proximaDB
cd proximaDB && cargo run --release --bin proximadb-server
----

=== 2. Create a Collection

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/collections \
  -H "Content-Type: application/json" \
  -d '{
    "name": "documents",
    "dimension": 768,
    "filterable_columns": [
      {"name": "category", "data_type": "STRING"},
      {"name": "date", "data_type": "INT64"}
    ]
  }'
----

=== 3. Search with Filters

[source,bash]
----
curl -X POST http://localhost:5678/api/v1/search \
  -H "Content-Type: application/json" \
  -d '{
    "collection_id": "documents",
    "query_vector": [0.1, 0.2, ...],
    "top_k": 10,
    "filter_expression": {
      "field": "category", "operator": "EQUALS", "value": "technical"
    }
  }'
----

== Multi-Model Architecture

ProximaDB is a **unified multi-model database** that integrates:

* **Vector Store**: 6 specialized engines for semantic search
* **Graph Store**: ORION/PULSAR/QUASAR for relationship traversal
* **Document Store**: MongoDB-like JSON document storage
* **Observability Store**: Cloud SIEM-like log/metric/trace ingestion
* **PostgreSQL Wire Protocol**: pgvector migration path (psql compatible)

=== Unified Query Engine

All stores can be queried together through a single SQL-like interface:

[source,sql]
----
-- Hybrid query: vector search + graph traversal + document filter
SELECT d.id, d.title, v.similarity, g.path
FROM documents d
JOIN vectors v ON d.embedding_id = v.id
FOLLOW GRAPH knowledge ON d.entity_id = knowledge.start_node
WHERE SIMILAR(v.embedding, ?, 0.8)
  AND d.category = 'technical'
  AND g.depth <= 2
LIMIT 10;
----

=== PostgreSQL/pgvector Compatibility

Connect with any PostgreSQL client:

[source,bash]
----
# Connect via psql
psql -h localhost -p 5433 -U proximadb

# Create table (creates ProximaDB collection)
CREATE TABLE embeddings (id TEXT, embedding vector(768));

# Insert vectors
INSERT INTO embeddings VALUES ('doc1', '[0.1, 0.2, ...]');

# pgvector-style similarity search
SELECT * FROM embeddings ORDER BY embedding <-> '[0.1, ...]' LIMIT 10;
----

== API Examples

=== REST API

[source,bash]
----
# Vector Search
curl -X POST http://localhost:5678/api/v1/search \
  -d '{"collection_id": "docs", "query_vector": [...], "top_k": 10}'

# Document Store
curl -X POST http://localhost:5678/v1/documents/products \
  -d '{"id": "prod1", "document": {"name": "Widget", "price": 99.99}}'

# Graph Operations
curl -X POST http://localhost:5678/v1/graphs/knowledge/nodes \
  -d '{"id": "entity1", "labels": ["Person"], "properties": {"name": "Alice"}}'

# Observability Ingestion
curl -X POST http://localhost:5678/v1/observability/logs/_bulk \
  -d '{"logs": [{"message": "User login", "service": "auth", "level": "info"}]}'
----

=== Python SDK

[source,python]
----
from proximadb_sdk import ProximaDBClient
from proximadb_sdk.embedded import EmbeddedProximaDB

# Server mode
client = ProximaDBClient("http://localhost:5678")
client.create_collection("docs", dimension=768)
client.insert_vectors("docs", vectors=[...], ids=["v1", "v2"])
results = client.search("docs", query_vector=[...], top_k=10)

# Embedded mode (no server needed)
db = EmbeddedProximaDB(data_path="/data/proximadb")

# Vector operations
db.create_collection("embeddings", dimension=768, engine="sst")
db.insert("embeddings", ids=["e1"], vectors=[[0.1] * 768])
results = db.search("embeddings", query=[0.1] * 768, top_k=5)

# Graph operations
db.create_graph("knowledge")
db.create_nodes("knowledge", [
    GraphNode("alice").with_label("Person").with_property("name", "Alice")
])
db.create_edges("knowledge", [
    GraphEdge("alice", "bob", "KNOWS").with_weight(0.9)
])
neighbors = db.get_neighbors("knowledge", "alice")

# Document operations
db.create_document_collection("products")
db.insert_document("products", "p1", {"name": "Widget", "price": 99.99})
docs = db.query_documents("products", filter="$.price > 50")
----

=== Embedded Mode Features

* **Search Modes**: `exact` (100% recall), `approximate` (faster), `adaptive` (auto-tuned)
* **Graph Traversal**: BFS, DFS, shortest path, PageRank
* **Document Queries**: JSON path filtering, full-text search, array operations
* **Multi-Language Bindings**: Python, Java (JNI), Node.js (NAPI-RS), C FFI
