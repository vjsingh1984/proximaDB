== Quick Start

=== Run with Docker

[source,bash]
----
# Start ProximaDB server
docker run -d -p 5678:5678 -p 5679:5679 proximadb/proximadb:latest

# Verify server is running
curl http://localhost:5678/health

# Create your first collection
curl -X POST http://localhost:5678/v1/collections \
  -H "Content-Type: application/json" \
  -d '{"name": "my_vectors", "dimension": 768}'
----

=== Build from Source

[source,bash]
----
# Requirements: Rust 1.88+
git clone https://github.com/vjsingh1984/proximaDB
cd proximaDB
cargo build --release
./target/release/proximadb-server
----

**Server endpoints:**

* REST API: http://localhost:5678
* gRPC API: localhost:5679

== What is ProximaDB?

ProximaDB is a vector database designed for production AI applications. Built from the ground up in Rust, it provides:

* **6 specialized storage engines** that automatically optimize for different workload patterns
* **Hardware acceleration** with SIMD (AVX2, AVX512, NEON) for vector operations
* **Advanced compression** (Binary, INT8, Product Quantization) reducing storage by 4-32x
* **Real-time performance** with write-optimized and read-optimized engines
* **Single binary deployment** - no external dependencies

=== Core Capabilities

**Adaptive Storage Architecture**

ProximaDB automatically selects the optimal storage engine based on your data and access patterns:

[cols="1,2,2"]
|===
|Engine |Optimized For |Use When

|*SST*
|Write-heavy, real-time updates
|Frequent insertions, point queries

|*VIPER*
|Analytics, batch operations
|Large scans, high compression needs

|*NOVA*
|Balanced read/write
|Mixed workloads, progressive search

|*SWIFT*
|Ultra-low latency
|Cache-friendly, small datasets

|*RAPTOR*
|Adaptive workloads
|Unpredictable access patterns

|*HELIX*
|Spatial locality
|Image embeddings, spatial data
|===

**Hardware Acceleration**

Built-in SIMD acceleration across all operations:

* **Distance Computation**: 20.8M ops/sec (128D), 3.8M ops/sec (512D), 1.2M ops/sec (1536D)
* **Encoding Analysis**: 9.6x speedup with AVX2/NEON
* **Automatic Detection**: AVX2, AVX512 (x86_64), NEON (ARM64)
* **Graceful Fallback**: Scalar implementations when SIMD unavailable

**Compression & Quantization**

Multiple quantization levels for storage/performance trade-offs:

* **Binary**: 32x compression, 100x faster filtering
* **INT8**: 4x compression, 10x faster search
* **PQ8/16/32**: Variable compression with accuracy control
* **Lossless modes**: Preserve full f32 precision when needed

== Usage Examples

=== Python SDK

[source,python]
----
from proximadb import ProximaDB

# Connect to ProximaDB
client = ProximaDB(url="http://localhost:5678")

# Create collection with automatic engine selection
collection = client.create_collection(
    name="documents",
    dimension=768,
    engine="auto"  # ProximaDB selects optimal engine
)

# Insert vectors with metadata
collection.insert([
    {
        "id": "doc_1",
        "vector": [0.1, 0.2, ...],  # 768D embedding
        "metadata": {
            "title": "Introduction to Vector Databases",
            "category": "technology",
            "timestamp": "2024-01-15"
        }
    }
])

# Search with metadata filtering
results = collection.search(
    query_vector=[0.15, 0.25, ...],
    top_k=10,
    filter={"category": "technology"}
)

for result in results:
    print(f"ID: {result.id}, Distance: {result.distance}")
----

=== REST API

[source,bash]
----
# Create collection
curl -X POST http://localhost:5678/v1/collections \
  -H "Content-Type: application/json" \
  -d '{
    "name": "products",
    "dimension": 1536,
    "engine": "auto"
  }'

# Insert vectors
curl -X POST http://localhost:5678/v1/collections/products/vectors \
  -H "Content-Type: application/json" \
  -d '{
    "vectors": [
      {
        "id": "product_123",
        "values": [0.1, 0.2, ...],
        "metadata": {"category": "electronics", "price": 299}
      }
    ]
  }'

# Search vectors
curl -X POST http://localhost:5678/v1/collections/products/search \
  -H "Content-Type: application/json" \
  -d '{
    "query_vector": [0.15, 0.25, ...],
    "top_k": 5,
    "filter": {"category": "electronics"}
  }'
----

== Production Deployment

=== Docker Compose

[source,yaml]
----
version: '3.8'
services:
  proximadb:
    image: proximadb/proximadb:latest
    ports:
      - "5678:5678"  # REST API
      - "5679:5679"  # gRPC API
    volumes:
      - proximadb_data:/data
    environment:
      - RUST_LOG=info
    restart: unless-stopped
    deploy:
      resources:
        limits:
          memory: 4G
          cpus: '2'

volumes:
  proximadb_data:
    driver: local
----

=== Configuration

Basic configuration in `config/config.toml`:

[source,toml]
----
[server]
http_port = 5678
grpc_port = 5679
data_dir = "/data"

[storage]
# Auto-select best engine (SST, VIPER, NOVA, SWIFT, RAPTOR, HELIX)
default_engine = "auto"

[storage.write_buffer]
flush_threshold_mb = 256
flush_interval_secs = 300

[compute.quantization]
default_level = "INT8"  # Binary, INT8, PQ8, None

[compute.distance]
simd_enabled = true  # Auto-detects AVX2/NEON
----

See link:config/config.toml[config.toml] for all options.

== Key Features

=== Compression & Quantization

**Multiple Quantization Levels:**

* **Binary (1-bit)**: 32x compression, fastest filtering
* **INT8 (8-bit)**: 4x compression, balanced performance
* **PQ4/8/16/32**: Product quantization with tunable accuracy
* **Full Precision**: Lossless f32 storage when needed

**Lossless Guarantees:**

ProximaDB ensures lossless encoding for f32 embeddings:

* IEEE 754 bit pattern preservation
* Automatic scheme upgrade (PForDelta → PForDoubleDelta)
* Dynamic lossy detection and fallback
* 15 encoding schemes optimized per data pattern

See link:docs/technical/proximacodec_technical_guide.adoc[ProximaCodec Technical Guide]

=== Metadata Filtering

Combine vector similarity with business logic:

[source,python]
----
# SQL-like filtering
results = collection.search(
    query_vector=embedding,
    top_k=10,
    filter={
        "category": "electronics",
        "price": {"$lt": 500},
        "in_stock": True,
        "tags": {"$contains": "wireless"}
    }
)
----

**Supported Operators:**

* Equality: `category = "tech"`
* Comparison: `price < 100`, `rating >= 4.5`
* Range: `timestamp BETWEEN start AND end`
* Arrays: `tags CONTAINS "featured"`
* Boolean: `in_stock = true`

=== Graph Integration

Native graph database capabilities:

* Store relationships alongside vectors
* Graph traversal with vector filtering
* Hybrid graph-vector queries
* PageRank, BFS, DFS algorithms

[source,python]
----
# Create nodes with embeddings
collection.insert_node({
    "id": "person_1",
    "vector": embedding,
    "properties": {"name": "Alice", "age": 30}
})

# Create relationships
collection.create_edge(
    from_id="person_1",
    to_id="person_2",
    edge_type="knows",
    properties={"since": "2020"}
)

# Hybrid graph-vector query
results = collection.graph_search(
    query_vector=embedding,
    traversal="BFS",
    max_depth=3,
    filter={"age": {"$gte": 25}}
)
----
