== Overview

The ProximaDB Python SDK provides a comprehensive interface for interacting with ProximaDB's vector database, offering both REST and gRPC protocols with automatic protocol selection and advanced features.

== Installation

[source,bash]
----
pip install proximadb-client
----

== Quick Start

[source,python]
----
from proximadb import ProximaDBClient

# Connect to ProximaDB
client = ProximaDBClient("http://localhost:5678")

# Create a collection
collection = client.create_collection(
    name="my_vectors",
    dimension=1536,
    storage_engine="sst",  # or "viper"
    distance_metric="cosine"
)

# Insert vectors
vectors = [
    {"id": "vec1", "vector": [0.1, 0.2, ...], "metadata": {"category": "A"}},
    {"id": "vec2", "vector": [0.3, 0.4, ...], "metadata": {"category": "B"}}
]
client.insert_vectors("my_vectors", vectors)

# Search
results = client.search_vectors(
    collection_id="my_vectors",
    query_vector=[0.1, 0.2, ...],
    top_k=10
)
----

== Core Features

=== Protocol Support

The SDK supports both REST and gRPC protocols with automatic selection:

[source,python]
----
from proximadb import ProximaDBClient, Protocol

# Automatic protocol selection (default)
client = ProximaDBClient("http://localhost:5678")

# Force specific protocol
rest_client = ProximaDBClient("http://localhost:5678", protocol=Protocol.REST)
grpc_client = ProximaDBClient("localhost:5679", protocol=Protocol.GRPC)

# Intelligent protocol selection
smart_client = ProximaDBClient(
    "http://localhost:5678",
    protocol_selector=IntelligentProtocolSelector()
)
----

=== Compression Configuration

SDK-driven compression without server defaults:

[source,python]
----
from proximadb.models import (
    CompressionConfig,
    CompressionAlgorithm,
    StorageEngine
)

# Configure compression
compression = CompressionConfig(
    # SST compression settings
    sst_compression_algorithm=CompressionAlgorithm.ZSTD,
    sst_compression_level=6,
    sst_block_size=32768,
    
    # VIPER compression settings
    viper_compression_algorithm=CompressionAlgorithm.SNAPPY,
    viper_enable_dual_columns=True,
    
    # Adaptive settings
    adaptive_compression=True,
    compression_threshold_kb=100
)

# Create collection with compression
collection = client.create_collection(
    name="compressed_vectors",
    dimension=768,
    storage_engine=StorageEngine.SST,
    compression_config=compression
)
----

== Advanced Features

=== Chunking and Embedding

Built-in text chunking with embedding support:

[source,python]
----
from proximadb.chunking import TextChunker, ChunkingStrategy
from proximadb.embedding_providers import OpenAIProvider

# Configure chunker
chunker = TextChunker(
    strategy=ChunkingStrategy.SEMANTIC,
    chunk_size=512,
    chunk_overlap=50,
    embedding_provider=OpenAIProvider(api_key="...")
)

# Process text
text = "Large document content..."
chunks = chunker.chunk_text(text)

# Insert chunks as vectors
for chunk in chunks:
    client.insert_vector(
        collection_id="documents",
        vector_id=chunk.id,
        vector=chunk.embedding,
        metadata={"text": chunk.text, "position": chunk.position}
    )
----

=== Batching and Streaming

Efficient batch operations:

[source,python]
----
from proximadb.batching import RequestBatcher

# Configure batcher
batcher = RequestBatcher(
    batch_size=1000,
    batch_timeout_ms=100,
    max_concurrent_batches=5
)

# Batch insertion
async with batcher.batch_context() as batch:
    for vector in large_dataset:
        await batch.add_vector(vector)
    # Automatically flushes when batch is full or timeout

# Streaming search
async for result in client.stream_search(
    collection_id="my_vectors",
    query_vector=query_vector,
    batch_size=100
):
    process_result(result)
----

=== Response Caching

Client-side caching for improved performance:

[source,python]
----
from proximadb.cache import ResponseCache

# Configure cache
cache = ResponseCache(
    max_size=1000,
    ttl_seconds=300,
    cache_searches=True,
    cache_metadata=True
)

# Client with caching
cached_client = ProximaDBClient(
    "http://localhost:5678",
    cache=cache
)

# Cached operations
results = cached_client.search_vectors(...)  # First call
results = cached_client.search_vectors(...)  # Cached response
----

== SQL Integration

Execute SQL queries with vector operations:

[source,python]
----
# SQL with vector similarity
sql = """
    SELECT id, metadata->>'name' as name,
           VECTOR_SIMILARITY(vector, %s, 'cosine') as similarity
    FROM products
    WHERE metadata->>'category' = 'electronics'
      AND metadata->>'price'::float < 1000
    ORDER BY similarity DESC
    LIMIT 10
"""

results = client.execute_sql(sql, [query_vector])
----

== Error Handling

Comprehensive error handling:

[source,python]
----
from proximadb.exceptions import (
    ProximaDBError,
    CollectionNotFoundError,
    VectorDimensionError,
    CompressionError,
    NetworkError
)

try:
    results = client.search_vectors(...)
except CollectionNotFoundError:
    # Handle missing collection
    client.create_collection(...)
except VectorDimensionError as e:
    # Handle dimension mismatch
    print(f"Expected {e.expected}, got {e.actual}")
except NetworkError:
    # Handle network issues with retry
    retry_with_backoff()
----

== Performance Best Practices

=== 1. Use gRPC for Bulk Operations

[source,python]
----
# gRPC is 3x faster for bulk inserts
grpc_client = ProximaDBClient("localhost:5679", protocol=Protocol.GRPC)
grpc_client.insert_vectors(collection_id, large_batch)
----

=== 2. Enable Compression for Large Datasets

[source,python]
----
# Reduce storage by 50-80%
compression = CompressionConfig(
    sst_compression_algorithm=CompressionAlgorithm.ZSTD,
    adaptive_compression=True
)
----

=== 3. Use Connection Pooling

[source,python]
----
# Reuse connections for better performance
client = ProximaDBClient(
    "http://localhost:5678",
    connection_pool_size=10
)
----

=== 4. Batch Operations

[source,python]
----
# Batch for efficiency
with client.batch_context(size=1000) as batch:
    for vector in vectors:
        batch.add(vector)
----

=== 5. Cache Repeated Queries

[source,python]
----
# Cache for repeated queries
client = ProximaDBClient(
    "http://localhost:5678",
    enable_cache=True,
    cache_ttl=300
)
----

== Migration Guide

=== From v0.x to v1.0

[source,python]
----
# Old API (v0.x)
client.insert(collection, vector_data)

# New API (v1.0)
client.insert_vectors(
    collection_id=collection,
    records=[VectorRecord(
        id=v["id"],
        vector=v["vector"],
        metadata=v.get("metadata")
    ) for v in vector_data]
)
----

=== Protocol Migration

[source,python]
----
# Migrate from REST to gRPC
old_client = ProximaDBClient("http://localhost:5678")  # REST
new_client = ProximaDBClient("localhost:5679", protocol=Protocol.GRPC)

# Export and import
data = old_client.export_collection("my_collection")
new_client.import_collection("my_collection", data)
----

== Troubleshooting

=== Common Issues

**Connection Refused**
[source,python]
----
# Check server is running
# Verify correct port (5678 for REST, 5679 for gRPC)
----

**Dimension Mismatch**
[source,python]
----
# Ensure all vectors have same dimension as collection
# Check collection.config.dimension
----

**Compression Not Working**
[source,python]
----
# Compression is SDK-driven, must be configured on collection creation
# Cannot change compression after creation
----

**Slow Performance**
[source,python]
----
# Use gRPC instead of REST
# Enable connection pooling
# Use batch operations
# Enable caching for repeated queries
----
