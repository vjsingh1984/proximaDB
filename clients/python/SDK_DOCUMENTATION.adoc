= ProximaDB Python SDK
:toc:
:toclevels: 2

[.lead]
Developer-first SDK for vector search with optional document, graph, and observability helpers.

== Install

[source,bash]
----
pip install proximadb-client
----

== Quick Start (Vectors)

[source,python]
----
from proximadb import ProximaDBClient

client = ProximaDBClient("http://localhost:5678")

client.create_collection(
    name="docs",
    dimension=768,
    storage_engine="sst",
    distance_metric="cosine",
)

client.insert_vectors("docs", [
    {"id": "doc_1", "vector": [0.1, 0.2], "metadata": {"category": "tech"}}
])

results = client.search_vectors(
    collection_id="docs",
    query_vector=[0.1, 0.2],
    top_k=5,
)
print(results)
----

== Document Operations (Beta)

[source,python]
----
client.create_document_collection("events")
client.insert_document("events", {"service": "api", "status": "warn"})
----

== Graph Operations (Beta)

[source,python]
----
client.create_graph("topology")
client.create_node("topology", {"id": "service-api", "labels": ["Service"]})
----

== Observability (Beta)

[source,python]
----
client.create_observability_namespace("prod")
client.ingest_logs("prod", [{"message": "error", "severity": "error"}])
----

== Protocols

The SDK supports REST and gRPC. REST is the default for local development.

[source,python]
----
from proximadb import ProximaDBClient, Protocol
client = ProximaDBClient("http://localhost:5678", protocol=Protocol.REST)
----

== Notes

* Vector operations are the most mature API surface.
* Document, graph, and observability helpers are evolving.
* For production, prefer explicit configuration and retries.
