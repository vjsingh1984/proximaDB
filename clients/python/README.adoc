= ProximaDB Python Client SDK
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: pygments

The official Python client for ProximaDB — gRPC‑first, aligned with current proto.

== Features

* High Performance: **High Performance**: Optimized for ML workloads with numpy integration
* **Async/Sync APIs**: Both synchronous and asynchronous gRPC client support
* **Type Safe**: Full typing support with dataclasses
* **Batching**: Efficient batch operations for bulk inserts and searches
* **Rich Filtering**: Advanced metadata filtering with complex queries
* **Multi-Protocol**: gRPC and REST API support
* **Observability**: Built-in metrics and logging
* **Security**: TLS encryption and authentication support

== Quick Start (gRPC, v1)

[source,python]
----
import numpy as np
from proximadb.protocols.grpc_sync import ProximaDBSyncGrpcClient
from proximadb import proximadb_pb2 as pb2  # Messages

# Initialize sync gRPC client (5679). Server exposes proximadb.v1.VectorService.
client = ProximaDBSyncGrpcClient("localhost:5679")

# Create a collection with primary HNSW index
ic = pb2.IndexConfig(index_name="documents_primary", algorithm=pb2.IndexingAlgorithm.HNSW, is_primary=True)
qcfg = pb2.QuantizationConfig(enabled=False)
client.create_collection(
    name="documents",
    dimension=768,
    distance_metric=pb2.DistanceMetric.COSINE,
    storage_engine=pb2.StorageEngine.VIPER,
    index_configs=[ic],
    quantization_config=qcfg,
)

# Insert vectors via VectorBatch (build pb2.VectorBatchRequest in higher-level helpers)
# See unified_client or batching helpers for convenience wrappers.
----

// REST client references are being refactored; prefer gRPC for v1.

NOTE: The v1 gRPC service is `proximadb.v1.VectorService`. Python stubs are generated from
`proto/proximadb/v1/vector.proto` and exposed as `proximadb.v1.vector_pb2_grpc.VectorServiceStub`.
Legacy `ProximaDBStub` is no longer supported in v1 SDKs.

=== SKS Compatibility (Experimental)

- The Python SDK automatically probes and uses SKS endpoints when available:
  - Search: `POST /api/v1/search/{collection_id}` (envelope response)
  - Entities: `POST/GET/DELETE /api/v1/entities/{collection_id}[/{entity_id}]`
- When SKS is not available, the SDK falls back to legacy endpoints:
  - Search: `POST /api/v1/vector/search`
  - Batch write: `POST /api/v1/vector/batch`
  - Delete: `DELETE /api/v1/vectors/{collection_id}`

You can pre‑probe SKS support for a collection to avoid first‑call probing:

[source,python]
----
from proximadb.protocols.rest_sync import ProximaDBClient as RestClient

client = RestClient(url="http://localhost:5678")
support = client.warmup_sks_capabilities("my_collection")
print(support)  # {'search': True/False, 'entities': True/False}
----

Search returns a consistent list of SearchResult regardless of protocol. When SKS is active, results are parsed from the envelope (`items[*].entity_id`, `score`, `typed_metadata`).

== Advanced Usage

=== Batch Operations

[source,python]
----
# Efficient batch insert
batch_size = 1000
for i in range(0, len(all_vectors), batch_size):
batch = all_vectors[i:i+batch_size]
await client.insert_vectors(
collection_id="documents",
vectors=batch,
upsert_mode=True
)
----

=== Metadata Filtering

[source,python]
----
# Search with filters
results = await client.search_vectors(
collection_id="documents",
query_vectors=[query_vector],
top_k=10,
metadata_filter={
"category": "science",
"year": {"$gte": 2020}
}
)
----

=== Collection Management

[source,python]
----
# List all collections
collections = await client.list_collections()

# Get collection info
info = await client.get_collection("documents")

# Delete collection
await client.delete_collection("documents")
----

=== Running Tests

Unit tests (no mocks) focus on local model/utility behavior:

[source,bash]
----
cd clients/python
pytest -q clients/python/tests/test_models_and_utils.py
----

Integration tests (no mocks) require a running server:

- REST server at PROXIMADB_URL (default http://localhost:5678)
- gRPC server at PROXIMADB_GRPC (default localhost:5679) for gRPC-specific tests

[source,bash]
----
# Start ProximaDB in another terminal (from repo root):
# cargo run --bin proximadb-server

cd clients/python
export PROXIMADB_URL=http://localhost:5678
pytest -q clients/python/tests/integration_sks -m integration
----

CI note: mark integration jobs to run only when a ProximaDB service is available. The tests skip gracefully if the server is not reachable.

== API Reference

=== GrpcClient

[cols="2,3,2"]
|===
|Method |Description |Returns

|`connect()`
|Establish connection to server
|None

|`disconnect()`
|Close connection to server
|None

|`create_collection(...)`
|Create new collection
|CollectionResponse

|`insert_vectors(...)`
|Insert vectors into collection
|VectorOperationResponse

|`search_vectors(...)`
|Search for similar vectors
|VectorOperationResponse

|`delete_collection(...)`
|Delete a collection
|CollectionResponse
|===

=== RestClient

[cols="2,3,2"]
|===
|Method |Description |Returns

|`create_collection(...)`
|Create new collection via REST
|dict

|`insert_vectors(...)`
|Insert vectors via REST
|dict

|`search(...)`
|Search vectors via REST
|dict

|`health_check()`
|Check server health
|dict
|===

== Error Handling

[source,python]
----
from proximadb.exceptions import ProximaDBError, ConnectionError, CollectionNotFoundError

try:
await client.search_vectors(...)
except CollectionNotFoundError:
print("Collection doesn't exist")
except ConnectionError:
print("Failed to connect to server")
except ProximaDBError as e:
print(f"Operation failed: {e}")
----
