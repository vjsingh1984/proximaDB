== Overview

ProximaCodec is a hardware-aware encoding/decoding framework for ProximaDB that provides automatic acceleration through hardware-specific implementations.

== Core Architectural Principles

[IMPORTANT]
====
**Separation of Implementations**

ProximaCodec maintains **strict separation** between implementation layers:

* **Baseline**: Pure scalar Rust code (NO SIMD, NO GPU)
* **SIMD**: SIMD intrinsics only (AVX512/AVX2/SSE2/NEON)
* **GPU**: GPU kernels only (CUDA/ROCm/Metal/OpenCL)

**Never mix implementations!** Each layer must remain independent.
====

=== 2. Implementation Purity Requirements

==== Baseline Implementation

[cols="2,3"]
|===
| Location | `src/storage/engines/core/ops/proximacodec/impls/baseline/`
| Language | Pure Rust (stable)
| Restrictions | *NO* SIMD intrinsics, *NO* unsafe code for SIMD, *NO* `#[cfg(target_arch)]`
| Purpose | Portable fallback, reference implementation, platform independence
| Performance | Baseline (1x)
|===

**Example (CORRECT Baseline)**:
[source,rust]
----
// ✅ CORRECT: Pure scalar code
pub fn encode_f32(values: &[f32], base: i64) -> Result<Vec<u8>> {
    let base_i32 = base as i32;
    let deltas: Vec<i32> = values
        .iter()
        .map(|&v| {
            let v_bits = v.to_bits() as i32;
            v_bits.wrapping_sub(base_i32)
        })
        .collect();
    // ... bitpack deltas ...
}
----

**Example (INCORRECT Baseline)**:
[source,rust]
----
// ❌ WRONG: SIMD intrinsics in baseline!
#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

unsafe fn compute_deltas_avx2(...) { // ❌ NO SIMD in baseline!
    _mm256_loadu_ps(...)
}
----

==== SIMD Implementation

[cols="2,3"]
|===
| Location | `src/storage/engines/core/ops/proximacodec/simd.rs` or `impls/simd/`
| Language | Rust with SIMD intrinsics
| Allowed | `std::arch::x86_64::*`, `std::arch::aarch64::*`, `unsafe`, `#[cfg(target_arch)]`
| Purpose | Hardware-accelerated encoding/decoding
| Performance | 4-16x faster than baseline
|===

**Example (CORRECT SIMD)**:
[source,rust]
----
// ✅ CORRECT: SIMD intrinsics in SIMD module
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
unsafe fn compute_deltas_avx2(values: &[f32], base_i32: i32) -> Vec<i32> {
    let base_vec = _mm256_set1_epi32(base_i32);
    // ... SIMD operations ...
}

pub fn simd_delta_encode_f32(values: &[f32], base: i64) -> Result<Vec<u8>> {
    #[cfg(target_arch = "x86_64")]
    {
        if is_x86_feature_detected!("avx2") {
            return unsafe { /* use AVX2 */ };
        }
    }
    // Fallback to scalar (within SIMD module, NOT calling baseline)
    let deltas: Vec<i32> = values.iter().map(|&v| v.to_bits() as i32).collect();
    // ... continue encoding ...
}
----

**Example (INCORRECT SIMD)**:
[source,rust]
----
// ❌ WRONG: Delegating to baseline!
pub fn simd_delta_encode_f32(values: &[f32], base: i64) -> Result<Vec<u8>> {
    // ❌ NO! SIMD should have its own implementation
    use super::impls::baseline::functions::delta;
    delta::encode_f32(values, base)
}
----

=== 3. Wire Format Compatibility

[IMPORTANT]
====
**All implementations MUST produce identical byte-level output**

* Baseline encoded data → SIMD decoder ✅
* SIMD encoded data → Baseline decoder ✅
* GPU encoded data → Baseline decoder ✅
* Any combination must work ✅
====

==== Wire Format Guarantee

All encoders for the same scheme must:

1. **Produce identical bytes** - Exact byte-for-byte match
2. **Follow same algorithm** - Delta, BitPacked, FrameOfReference, etc.
3. **Use same bit layout** - No implementation-specific optimizations that change format

**Testing**:
[source,rust]
----
// Wire compatibility test
let values = vec![1.0f32, 2.0, 3.0];

let baseline_bytes = baseline_encoder.encode(&values, scheme)?;
let simd_bytes = simd_encoder.encode(&values, scheme)?;
let gpu_bytes = gpu_encoder.encode(&values, scheme)?;

// MUST be identical
assert_eq!(baseline_bytes, simd_bytes);
assert_eq!(baseline_bytes, gpu_bytes);

// Cross-decoding MUST work
let b_to_b = baseline_decoder.decode(&baseline_bytes)?;
let b_to_s = simd_decoder.decode(&baseline_bytes)?;
let s_to_b = baseline_decoder.decode(&simd_bytes)?;
assert_eq!(values, b_to_b);
assert_eq!(values, b_to_s);
assert_eq!(values, s_to_b);
----

=== 4. No Delegation Between Implementations

[WARNING]
====
**Each implementation must be self-contained**

* Baseline ≠→ SIMD
* SIMD ≠→ Baseline
* SIMD ≠→ GPU
* GPU ≠→ Baseline

Each must have its own complete encoding/decoding logic.
====

**Rationale**:

1. **Performance Benchmarking** - Can't measure SIMD speedup if it calls baseline
2. **Testing Independence** - Each implementation tested separately
3. **Debugging** - Clear which code path is executing
4. **Maintenance** - Changes to one implementation don't affect others

**Exception**: Scalar fallback within SIMD module is allowed:
[source,rust]
----
// ✅ OK: Scalar fallback WITHIN SIMD module
pub fn simd_delta_encode_f32(values: &[f32], base: i64) -> Result<Vec<u8>> {
    #[cfg(target_arch = "x86_64")]
    {
        if is_x86_feature_detected!("avx2") {
            return unsafe { encode_with_avx2(values, base) };
        }
    }

    // Fallback to scalar implementation (within this file)
    encode_scalar_fallback(values, base)
}

fn encode_scalar_fallback(values: &[f32], base: i64) -> Result<Vec<u8>> {
    // Pure scalar implementation (duplicated from baseline, but local)
    // ...
}
----

=== 5. Router Logic (ProximaCodec)

ProximaCodec selects implementation based on:

[source,rust]
----
pub fn encode(&self, values: &[f32], scheme: ProximaScheme) -> Result<Vec<u8>> {
    // Priority: GPU > SIMD > Baseline

    #[cfg(feature = "gpu")]
    if self.gpu_available && self.gpu_encoder.supports(&scheme) {
        return self.gpu_encoder.encode(values, &scheme);
    }

    #[cfg(any(target_arch = "x86_64", target_arch = "aarch64"))]
    if self.simd_available && self.simd_encoder.supports(&scheme) {
        return self.simd_encoder.encode(values, &scheme);
    }

    // Always fallback to baseline
    self.baseline_encoder.encode(values, &scheme)
}
----

== Implementation Checklist

When implementing a new encoding scheme:

=== Baseline Implementation

☐ Pure Rust code (no SIMD intrinsics)
☐ No `#[cfg(target_arch)]` for SIMD
☐ No `std::arch::*` imports
☐ Works on all platforms
☐ Well-documented algorithm
☐ Unit tests with expected values

=== SIMD Implementation

☐ SIMD intrinsics for target platforms
☐ Runtime feature detection
☐ Scalar fallback within SIMD module
☐ Produces **identical bytes** to baseline
☐ Performance benchmarks vs baseline
☐ Cross-compatibility tests

=== GPU Implementation (Optional)

☐ GPU kernels for target platforms
☐ Host/device memory management
☐ Batch size optimization
☐ Produces **identical bytes** to baseline
☐ Performance benchmarks vs SIMD
☐ Fallback to SIMD/baseline for small batches

=== Integration

☐ Register with ProximaCodec
☐ Wire format compatibility tests
☐ Cross-implementation decode tests
☐ Update documentation

== Anti-Patterns to Avoid

[cols="2,3"]
|===
| ❌ Anti-Pattern | ✅ Correct Pattern

| SIMD intrinsics in baseline
| SIMD intrinsics only in SIMD module

| SIMD delegates to baseline
| SIMD has own implementation

| Baseline calls SIMD "if available"
| ProximaCodec chooses implementation

| Different wire formats per implementation
| All implementations produce identical bytes

| GPU code in SIMD module
| GPU code only in GPU module

| Conditional compilation in baseline
| Conditional compilation only in SIMD/GPU
|===

== Benefits of This Architecture

1. **Clear Separation**: Easy to understand which code runs where
2. **Independent Testing**: Test each implementation separately
3. **Performance Benchmarking**: Measure actual speedup of SIMD/GPU
4. **Platform Independence**: Baseline works everywhere
5. **Wire Compatibility**: Data portable across implementations
6. **Maintenance**: Changes isolated to specific implementations
7. **Debugging**: Clear execution path
8. **Future-Proof**: Easy to add new implementations (WebGPU, etc.)

== Common Questions

=== Q: Why not optimize baseline with SIMD?

**A**: Baseline must remain pure scalar for:

* Platform independence
* Reference implementation
* Benchmarking baseline
* Debugging without SIMD complexity

=== Q: Can SIMD use scalar code as fallback?

**A**: Yes, but the scalar fallback should be **within the SIMD module**, not calling baseline.

[source,rust]
----
// ✅ CORRECT: Local scalar fallback
pub fn simd_encode(values: &[f32]) -> Result<Vec<u8>> {
    if is_x86_feature_detected!("avx2") {
        return unsafe { avx2_encode(values) };
    }
    // Local scalar implementation (not calling baseline)
    scalar_fallback_encode(values)
}

// ❌ WRONG: Calling baseline
pub fn simd_encode(values: &[f32]) -> Result<Vec<u8>> {
    if !has_simd() {
        return baseline::encode(values); // ❌ NO!
    }
    // ...
}
----

=== Q: What if implementations produce different bytes?

**A**: This is a **bug** that must be fixed. All implementations must be wire-compatible.

Use comprehensive cross-compatibility tests:
[source,rust]
----
#[test]
fn test_wire_compatibility() {
    let baseline_encoder = BaselineEncoder;
    let simd_encoder = SimdEncoder;

    let values = vec![1.0f32, 2.0, 3.0];
    let scheme = ProximaScheme::Delta { base: 0 };

    let baseline_bytes = baseline_encoder.encode_f32(&values, &scheme).unwrap();
    let simd_bytes = simd_encoder.encode_f32(&values, &scheme).unwrap();

    assert_eq!(baseline_bytes, simd_bytes, "WIRE FORMAT MISMATCH!");
}
----

== Summary

[IMPORTANT]
====
**Golden Rules**

1. Baseline = Pure scalar (NO SIMD)
2. SIMD = SIMD intrinsics (NO delegation to baseline)
3. GPU = GPU kernels (NO delegation to SIMD/baseline)
4. All produce **identical bytes**
5. ProximaCodec chooses implementation
6. Test wire compatibility rigorously
====
