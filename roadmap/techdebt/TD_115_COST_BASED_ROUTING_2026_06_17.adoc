== Context

The design doc `docs/12-design/PROXIMADB_AS_LAKEHOUSE_NATIVE_PG_ENGINE_2026_06_17.md` §3.4/5.3 adopts
the TiDB lesson: per-query row-vs-column dispatch should be a **cost-based** decision with a
selectivity crossover, plus manual hints as an escape hatch (even TiDB's cost model is "still rough").
Today every SELECT is forced onto the row-oriented Volcano executor, capping analytical-scan
throughput over Parquet base tables — the mismatch the data-warehouse course correction targets.

== Current State (grounded)

* `ComputeScheduler::route_select()` (`src/query/compute_scheduler.rs:202`) hardcodes
  `ComputeBackend::Native`.
* Flip scaffolding present: `QueryShape.parquet_backed` / `engages_relational`, `routed_read_plan`,
  `explain_line()` — but `parquet_backed` is never set and no cost is compared.
* `UnifiedCostModel` / `UnifiedCostWeights` (`src/query/query_optimizer.rs:49`) exists but is used only
  by the ANN/search optimizer.
* Session `SET` parser exists (`src/network/postgres/protocol.rs:895`).

== Target Design

A cost calculator that compares Native (Volcano) vs DataFusionLocal per query using a selectivity
crossover, fed by lightweight catalog statistics, with a session-level override.

== Deliverables

1. Enrich `QueryShape` with `estimated_cardinality`, `partition_count`, `is_point_lookup`,
   `filter_selectivity`, populated at the planner boundary from catalog metadata + Parquet row-group
   split counts.
2. New `src/query/cost_model.rs` `cost_for_backend(shape, backend)` reusing `UnifiedCostWeights`:
   point/high-selectivity → Native; large-scan/low-selectivity/aggregate/join over parquet_backed →
   DataFusionLocal.
3. Set `parquet_backed=true` once all referenced tables are Parquet-materialized.
4. `SET compute_engine TO {auto/native/datafusion}` session override via the existing SET parser.
5. Extend `explain_line()` with a per-backend cost breakdown.

== Acceptance

* A scan-heavy query routes to DataFusionLocal and a point lookup to Native, both visible in EXPLAIN.
* The session override forces a backend regardless of cost.

== Dependencies & Sequencing

Depends on the live DataFusion execution path (data-warehouse course correction /
`DATAFUSION_BALLISTA_DISTRIBUTED_EXECUTION_2026_06_05.adoc`).
