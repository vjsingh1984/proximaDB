= TD-114 Storage Spine: L0→Base Compactor + Merge-on-Read Deletion Vectors
:toc:
:toclevels: 3
:sectnums:

Status: Open / proposed +
Date: 2026-06-17 +
Owner: Storage, query/runtime

== Context

ProximaDB already has both ends of the canonical LSM hot→cold pattern but never names or
closes the middle. The design doc
`docs/12-design/PROXIMADB_AS_LAKEHOUSE_NATIVE_PG_ENGINE_2026_06_17.md` §4–5.1 establishes that no
single physical layout can serve both fast OLTP read-after-write and efficient columnar scans, so the
spine must be **delta (hot, row/append) → compactor → base (cold, columnar)**. Without a background
compactor the system accrues the small-file problem (slow scans, bloated manifests); without deletion
vectors a delete cannot be reflected in immutable Parquet without a full rewrite.

== Current State (grounded)

* Hot/delta tier: `DirectWalTableRecordStore` (`src/services/record_store.rs:1168`) + memtable; flush
  via `SstEngine::flush_implementation` (`src/storage/engines/sst/flush/mod.rs:92`) produces PAX
  segments (vector) / Parquet (relational) and updates `GlobalManifestEntry` Active→Flushed.
* Compactor: `CompactionOrchestrator` (`src/storage/common/compaction_orchestrator.rs`,
  thresholds level0=5 / level=10 / max=7) is **defined but never called from the flush path**.
* Deletes: WAL tombstones (`CanonicalOperation::RecordDelete`). `enable_deletion_vectors` is an
  **unused field** (`src/storage/formats/open/delta.rs:107`).
* Read-time merge happens implicitly per partition (`scan_records_filtered`,
  `src/services/record_store.rs:458`); there is no explicit L0/base distinction.

== Target Design

Name the spine and wire the dormant orchestrator. Compaction is the Delta `OPTIMIZE` / Hudi
async-compaction analog; deletion vectors are merge-on-read deletes so Parquet is never rewritten per
delete. Compaction is `dataChange=false`-equivalent so it is invisible to snapshot isolation.

== Deliverables

1. Post-flush trigger in `sst/flush/mod.rs` after `index_flushed_into_axis()`: when L0 segment count
   ≥ `level0_threshold`, enqueue an async compaction task via the existing orchestrator.
2. `SstEngine::execute_compaction()` merging L0 → one L1 base file via `PaxSegmentWriter` / Parquet
   encoder, registering a new `GlobalManifestEntry` (Active, level 1).
3. Deletion-vector overlay applied at the read-time merge (`scan_records_filtered`) and consumed by
   the compactor to drop tombstoned rows — wire the dormant `enable_deletion_vectors` / `deleted_at`.
4. Mark compaction `dataChange=false`-equivalent (snapshot reads unaffected).
5. Per-collection eager/lazy compaction knob (write-amp vs read-amp).

== Acceptance

* An e2e that forces ≥2 flush+compaction cycles asserts: (a) L0 count collapses to ≤1 base file;
  (b) a deleted row is absent from post-compaction scans; (c) scan latency / manifest size improves.

== Dependencies & Sequencing

Independent. Shares the flush seam with TD-112 (post-flush ANN index population) — coordinate edits to
`sst/flush/mod.rs`.
