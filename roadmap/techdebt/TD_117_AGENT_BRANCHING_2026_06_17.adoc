== Context

The design doc `docs/12-design/PROXIMADB_AS_LAKEHOUSE_NATIVE_PG_ENGINE_2026_06_17.md` §6 makes
git-style, copy-on-write branching the headline agent capability: an agent forks the database state
instantly, gets an isolated read-write branch, and fork cost is independent of data size. This is the
capability Neon/Lakebase have and Supabase (ephemeral-instance branching) lacks. ProximaDB already has
the two CoW substrates — the WAL/LSN history (TD-116) and the immutable versioned manifest — and needs
only a branch ref over them plus an ancestor-fall-through read path and a writer fence.

== Current State (grounded)

* `SnapshotPin` (`src/services/snapshot/coordinator.rs:18`) captures `(from_lsn,to_lsn,checkpoint_id)`
  with **no parent/ancestor pointer**.
* `ManifestCommitter` (`crates/storage/proximadb-iceberg-engine/src/manifest.rs`) writes immutable
  versioned `v{N}.manifest` under optimistic CAS — but **no ref/branch layer** and **no
  generation/epoch writer fence**.
* `DrPathBuilder` (`src/storage/trait_components/path_resolver.rs`) isolates paths
  (`data/{tenant}/{ns}/{coll}/`) but does not fence concurrent writers.
* The graph branch/merge APIs are unrelated knowledge-graph features.

== Target Design

A `BranchRef` is one small immutable object pinning `(catalog snapshot, per-collection fork LSN,
per-table manifest version)`. Reads of unmodified data fall through to the parent; only post-branch
writes create new layers. A generation number fences stale writers (Neon's `index_part.json` model).

== Deliverables

1. `BranchRef` (new `src/services/snapshot/branch_ref.rs`):
   `{branch_id, parent, collections:{coll→fork_lsn}, tables:{tbl→manifest_version},
   catalog_snapshot_id, generation, created_at_ns}` persisted as `_branches/{id}.json` under a new
   `DrPathBuilder::branches_subprefix()` (~`path_resolver.rs:474`) and indexed in a new catalog
   `branches`/`snapshots` table (reuse the drop+create projection pattern).
2. Ancestor fall-through — `SnapshotPublishCoordinator::create_branch()` +
   `resolve_snapshot_lineage()`; the scoped read path recurses to the parent when the branch has no
   entry ≤ the requested version.
3. Generation-number writer fence on the `ManifestCommitter` CAS per `(tenant, branch)`.
4. Branch GC by reference-counting WAL layers/data files (Iceberg `expire_snapshots` semantics —
   safer than Delta shallow clone, which breaks on source VACUUM).

== Acceptance

* O(1) branch create off a populated collection (no data copy).
* Divergent writes leave the parent unchanged; unmodified reads fall through to the parent.
* A stale writer is fenced by generation.

== Dependencies & Sequencing

Depends on **TD-116** (LSN-addressable history) and **TD-119** (manifest snapshot refs to point at).
