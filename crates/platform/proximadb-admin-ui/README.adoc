= proximadb-admin-ui

A self-contained, **read-only** admin dashboard for ProximaDB, served by the REST
listener of standalone `proximadb-server` (or any embedded mode that boots the HTTP
server).

== What it is

* One static HTML page (`assets/admin.html`) — vanilla JS, no CDN, no build step —
  embedded into the binary via `include_str!`. Safe for offline / air-gapped /
  embedded deployments.
* An axum router factory, `admin_router::<S>()`, that serves the page at
  `GET /admin` (with `GET /dashboard` kept as a back-compat alias).

== Why a crate

`apps/` holds the binaries, the root crate is the lib, and functionality lives in
`crates/`. The dashboard previously lived as ~1k lines of inline HTML inside
`src/network/rest/server.rs`; factoring it here keeps the server lib thin (it only
mounts the router) and gives the UI its own home + tests.

== Read-only by construction

The page issues **only `GET`** requests (the `fetch` default), against existing
diagnostic endpoints:

* `GET /health`, `GET /health/ready` — liveness / readiness
* `GET /api/v2/_meta/capabilities` — build + capability summary
* `GET /api/v2/collections` and `GET /api/v2/collections/{id}` — collections + detail
* `GET /metrics/json` — numeric metrics (when the metrics collector is enabled)

It renders no create/update/delete controls, so it cannot mutate state. A crate
test (`html_is_embedded_and_self_contained`) enforces both invariants: no external
URLs, and no write verbs in the page.

== Mounting

[source,rust]
----
// in the REST router assembly:
base_router = base_router.merge(proximadb_admin_ui::admin_router());
----

== Enabling (off by default)

Disabled by default. Opt in via TOML, for **standalone** instances only (keep it off
for Kubernetes pods and embedded/UDS mode):

[source,toml]
----
[server.admin_ui]
enabled = true
----

The router-build path always merges `admin_router_if(enabled)`; the toggle decides
whether `/admin` actually exists. The flag flows
`[server.admin_ui] enabled` → `ServerConfig` → `MultiServerBuilder::with_admin_ui_enabled`
→ `MultiServerConfig::admin_ui_enabled` → `build_router_for_unified(.., admin_ui_enabled)`.

== Accessing

With the toggle on, start the server and open `/admin` on the REST port (default 5678):

[source,console]
----
$ cargo run --release --bin proximadb-server
# then browse to:
#   http://localhost:5678/admin
----

For production multi-tenant SaaS, the full operator console is the separate `ui/`
app; this crate is the lightweight, dependency-free counterpart for local /
embedded operation.
